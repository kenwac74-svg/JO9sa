# JO9 작업 인계

한 인계에는 목표 하나만 넣는다. 기획 Chat의 전체 대화를 다시 분석하기보다 확정 사항과 대상 파일을 전달한다.

```text
작업번호: 기존 원장/JO9_IMAGE_JOB 번호 유지, 해당 없으면 없음
목표: 한 문장
기준SHA: 원격 main 전체 SHA / 확인시각
상태·승인규칙: 제안|승인|구현|검증|배포|보류|취소 / 사용자 결정 근거와 허용 행동
수정범위: 파일·location·함수 / 보존할 부분 / local-pending 포함 여부
입력파일: 실제 경로·해시·출처 / 채택 이미지·기존 JO9_IMAGE_JOB 첨부
테스트: 필요한 파일검사·회귀검사·사용자 플레이 확인과 완료 조건
결과: 변경·산출물·검사결과·남은 항목 / 출력 해시 / commit·공개 상태
```

이미지 채택은 생성 완료와 구분한다. 채택 기록 없는 시안은 반영 대상으로 바꾸지 않는다. JO9_IMAGE_JOB 필드와 이미지 원장 번호를 새로 만들거나 바꾸지 않는다.

## 운영 문서 배포 인계

- 목표: 승인된 팀 구조와 각 담당 역할을 문서로 배포하고 연결 가능한 JO9 실행 세션에 알린다.
- 기준SHA: `653d674de4b08893c606003afc92b1062ec6ac83`, 2026-10-11 08:40 UTC 원격 main 직접 확인.
- 상태·승인규칙: 사용자 승인. 문서 전용 별도 브랜치·초안 PR 게시와 역할 인지 전달을 수행한다. main 병합·게임 기능 변경·빌드·공개 게임 배포는 별도 작업이다.
- 수정범위: docs/team/README.md, HANDOFF.md, BASELINE.md 신규 3개만. 기존 지침과 로컬 미커밋 변경은 포함하지 않는다.
- 입력파일: BASELINE.md의 고정 SHA 원격 지침과 앞선 홈컴 조사. 게임·이미지 전체를 입력으로 읽지 않는다.
- 테스트: 담당 링크·기준 SHA·상태 구분·원격/로컬 표시, 게시된 변경 파일 3개를 확인한다.
- 결과: 게시 commit SHA·브랜치·PR URL을 배포 보고에 기록한다. 대상별 메시지 전송 결과와 실제 수신 확인을 구분한다. 메시지 전송 성공만으로 수신·인지 완료를 주장하지 않는다.
