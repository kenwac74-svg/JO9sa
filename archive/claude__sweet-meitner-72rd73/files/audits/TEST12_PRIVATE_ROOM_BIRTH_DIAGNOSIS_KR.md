# TEST12 개인실 출산 호출 점검

2026-09-28. 사용자 보고: 개인실 인물이 임신 150일에 출산 이벤트를 시작하지 않는다.

## 확인 범위

G:/somi/JO9/game/jack.qsp를 읽어 실제 설치된 main_screen, next_day, interaction, snk_room_bridge, snk_room_menu_screen, slave_private_room1~4의 본문이 TEST12 배포 패치와 동일함을 확인했다. 세이브의 실제 임신 수치 및 실행 중 화면은 확인하지 않았다. 코드/게임/세이브 수정이나 빌드는 하지 않았다.

## 확인된 원인

1. 원작 main_screen.qsrc:895–940에 출산 검사가 집중되어 있다. 개인실 room1~4의 pregnant >= 150이면 각각 interaction 9914~9917을 호출한다. 임신 값을 0으로 초기화하고 아기 수를 1 증가시킨 뒤 interaction으로 이동한다. 조건은 게임 경과일이 아니라 인물별 임신 경과일이며, 150을 넘겨도 검사 대상이다.
2. 원작 및 현재 개인실 기본 화면에는 이 출산 호출이 없다. 현재 생성기 build/private_room.py의 room_body에도 출산 검사 연결이 없다.
3. 현재 main_screen의 첫 부분은 snk_room_target > 0일 때 snk_room_menu_screen을 출력하고 exit한다. 따라서 개인실 보상 등 하위 메뉴에서는 원작 main_screen 뒤쪽 출산 검사에 도달하지 않는다. snk_room_menu_screen에도 대체 검사가 없다.
4. 임신 일수 갱신 자체에서 개인실이 빠진 것은 아니다. #static_base.qsrc:335–338의 $main_screen_slave_characters에 room1~4가 포함되어 있고, next_day.qsrc:1779–1845의 임신 갱신을 1878에서 이 목록에 적용한다. 일반 임신 조건에서 pregnant가 매일 증가한다. 출산 이벤트 호출과 일수 갱신은 별개다.
5. 원작 interaction.qsrc:9628–9731에 개인실 4곳의 출산 처리가 존재한다. 개인실 출산 기능 자체가 없는 것이 아니라 화면에서 그 기능을 시작하는 검사 연결이 부족하다.

## 영향 및 구분

- 개인실 기본 화면의 검사 누락은 참조 원작에도 존재한다.
- 이번 UI 통합의 개인실 하위 메뉴 조기 종료는 원작 메인 화면 검사를 우회한다. 통합 과정에서 이 전역 이벤트 처리를 별도로 보존하지 못한 부분이다.
- 원래 방 슬롯에 pregnant >= 150 값이 남아 있고 정상 메인 화면 검사까지 도달하면, 개인실 배정을 유지한 상태에서도 해당 방의 출산 검사가 실행될 수 있다. 1층에서까지 발생하지 않는 사례는 실제 세이브 수치와 앞선 이벤트 분기를 추가 점검해야 한다.

## 수정 방향

개인실 기본 화면과 하위 메뉴에서도 기존 150일 조건 및 방별 출산 이벤트를 검사하도록 연결한다. 하위 메뉴에서 인물을 임시 교환한 상태라면 먼저 원래 방 슬롯으로 복구한 뒤 검사해야 하며, 중복 출산·아기 수 중복 증가·다른 인물 대상으로 실행되는 것을 방지해야 한다. 기존 출산 내용과 비용/효과를 새로 만들거나 변경할 필요는 없다. 검사 연결 변경은 아직 적용하지 않았다.

후속 검증: 4개 방 각각 149/150/151일, 일반 화면/하위 메뉴, 여러 방 동시 만기, 중복 호출 방지, 메인 노예 데이터 보존, 이벤트 종료 후 화면 경로.

## 추가 점검: 의료시설 자동 방문 후 같은 방으로 복귀

사용자가 1층 메인 화면으로 돌아가면 이벤트가 발생함을 확인했다. 자동 의료시설 이벤트와 원래 개인실 복귀는 기존 구조로 구현 가능하다. 아래 내용은 정적 코드 검토 결과이며 아직 구현하지 않았다.

- interaction 9914~9917은 이미 `$interaction_type = 'special_talk'`, `$place = 'hospital'`, `$npc_id = 'doctor'`로 의료시설 출산 장면을 구성한다. interaction_screen은 `$place`에 해당하는 배경과 의사를 표시한다. 별도로 도시 병원 자유행동 메뉴를 열 필요가 없다.
- 각 이벤트는 room1~4 데이터를 직접 변경한다. 다른 슬롯으로 이동시키거나 방을 비우는 코드는 없다. 개인실 배정을 그대로 유지하면서 의료시설 장면을 진행하고 같은 개인실 화면으로 돌아오는 것이 최소 변경이다.
- 현재 해당 출산 블록에는 방별 반환 목적지 설정이 없다. 이벤트 시작 때 출산 대상 방을 보관하고 `$return_lock`을 전용 종료 처리 또는 해당 개인실로 지정할 수 있다. 원작 `$objsel.qsrc:31–55`의 다음 버튼은 마지막 페이지 이후 `$return_lock`으로 이동한다.
- 개인실 하위 메뉴의 임시 대상 교환은 출산 전에 해제해야 한다. 방 번호를 먼저 보관한 뒤 복구하고 원래 roomN 대상 이벤트를 실행한다. 종료 경로는 원래 개인실 기본 화면으로 고정하고 남은 이벤트 표시/임시 상태를 정리한다.
- 임신 일수 증가 직후 일일 처리 중간을 끊기보다, 일일 처리 완료 후 안전한 화면 전환 지점에서 출산을 시작하도록 연결해야 한다. 이미 150일 이상인 기존 세이브는 개인실 진입/행동 메뉴 갱신 때도 확인한다. 여러 방이 만기이면 한 번에 한 명씩 처리한다.
- 의료비 정책은 별도 결정 사항이다. 원작은 500 스파크 이상일 때 500을 차감하는 정상 의료 분기, 부족할 때 비용 차감 없이 부정적 결과를 적용하는 분기가 있다. 항상 정상 의료시설 처치를 보장하려면 잔액 부족 시에도 허용할지 정책을 정해야 하며 무료/빚 처리를 임의로 추가하지 않는다.

구현 검증에는 정상 다음 버튼과 ESC/기타 종료 경로, 이벤트 중 저장·불러오기, 비용 중복 차감 및 출산 수 중복 증가 방지도 포함한다. 현재 검토만 수행했으며 새 빌드는 없다.
