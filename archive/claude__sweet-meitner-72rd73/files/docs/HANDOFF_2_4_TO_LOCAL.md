## 2. 확정된 결정 (결정 18·19)
- UI 패치를 끝내고 **잭오나 2.4.0**으로 간다.
- 배포물
  - **2.4 패치**: 2.3 원본 대비 변경·추가 파일만 담은 덮어쓰기 ZIP. 설치기 없음. 카일이 빌드한다.
  - **통압축**: 2.3 원본 + 2.4 패치 완성본. 사용자가 로컬에서 만들고 Google Drive에 직접 올린다.
- 모딩(QSP 내용 변경)은 계속 집컴·노트북이 `mods/*.json`으로 기록해 main에 올린다.
- SNKmod 폴더 폐지. 세이브는 2.3과 호환. 버전 2.4.0, 게임 타이틀도 변경.
- 출처: 잭오나는 오픈소스, 출처만 밝히면 된다. 2.4 작업자 **SAnk**, 올걸팩은 **smsfbatalovehandle** 님 작업.

## 3. 로컬 세션이 결정하거나 할 일
1. **창 제목**: 게임 창 위의 "Jack-o-nine-tails 2.3.2.5 & Kor Ver"는 jack.qsp에 없다. 엔진을 빌드하는 로컬에서 바꾼다.
2. **재도색 엔진**: 수정본 `engine/jack.exe`를 2.4 패치 ZIP에 넣을지. 0.14는 순정 엔진이고 Qt5Widgets.dll이 맞을 때만 교체했다.
3. **기존 배포물**: UI 패치 0.14와 이미지 교체 패치(비비, newimgadd)를 2.4에 흡수하고 종료할지. 흡수한다면 비비의 원본 덮어쓰기 이미지를 2.4 패치에 넣을지.
   - 이미지 교체 패치가 원본 경로에 덮어쓴 대체 이미지(예: 112·121·212 등)를 원래 그림으로 되돌릴지도 함께 정한다. QSP가 새 이미지를 직접 부르게 되면 덮어쓰기가 필요 없어질 수 있다.
4. **개발자 크레딧**: 게임 안 크레딧 화면(`credits` location)에 2.4 변경 내역과 출처(SAnk, smsfbatalovehandle 님)를 넣는다. 게임 문구라 로컬이 mods로 한다.
5. **mods의 SNKmod 경로**: 고치지 않아도 된다. 카일 빌드가 `SNKmod\`를 일괄로 지운다(아래 4). 새 mods는 처음부터 SNKmod 없이 써도 되고, 써도 빌드가 정리한다.
6. **통압축 만드는 방법**: "2.3 원본 폴더(`G:\somi\JO9O` 등) 복사 → 2.4 패치 ZIP 덮어쓰기 → 압축"을 로컬 스크립트로 만들지 정한다.

## 4. 카일이 할 일 (사용자 "진행해" 이후)
- 빌드 변경: SNKmod 이전(덮어쓰기 56, 새 파일 67, trash 30 제외), QSP·CSS·JSON의 `SNKmod\` 경로 일괄 정리, 버전 표기 9곳 2.4.0(`$code_rev` 2곳 + 화면 구석 표기 8곳… 상세는 PLAN).
- 2.4 패치 ZIP 구성: `game/jack.qsp`, `css/base.css`, `json/menu_icon.json`, 변경·추가 이미지, README(설치법·호환 불가 안내·출처). 설치기 없음.
- 검사 후 사용자 게임 점검 → 승인 → 패키징.
- 로컬의 결정(위 3의 1~3)은 빌드와 겹치지 않는다. 결정되면 카일이 PLAN과 빌드에 반영한다.

## 5. 세이브 호환 원칙 (로컬 mods에도 적용)
- 기존 변수의 이름·의미·형식을 바꾸지 않는다.
- 새 변수는 2.3 세이브에 없으므로, 값이 없을 때(0 또는 빈 문자열) 기본 동작이 되도록 쓴다.
- 버전 값이 바뀌면 2.3 세이브를 불러올 때 게임의 기존 업데이트 처리(`$addon`)가 "2.3.2.5에서 2.4.0으로 업데이트" 메시지를 한 번 보여 준다. 이 처리에 새 초기화가 필요하면 그 안에 넣는다.
