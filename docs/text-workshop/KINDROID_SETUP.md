# Kindroid로 컷신 텍스트 만들기 — 설정과 작업 방법

목적은 Jack-o-nine-tails 컷신마다 들어갈 대사·지문을 Kindroid로 초안 작성하고, Text Workshop `[수정]`으로 게임에 넣는 것이다.

## 0. 먼저 알아둘 것

- 설정 항목 이름과 글자 수 제한은 사용자가 보내준 Kindroid Personality 화면 캡처(2026-10-03) 기준이다. 앱 업데이트로 달라질 수 있으니 입력창의 `0/제한` 표시를 확인한다 (참고 [일반 가이드](https://aiindigo.com/tutorials/getting-started-with-kindroid-crafting-deeply-personal-ai-companions)).
- Kindroid는 대화 상대용 앱이라 긴 설정을 지키다가 문체가 흐트러질 수 있다. 그래서 **컷신 1개 = 새 대화 1개**로 쓰고, 고정 규칙은 Key Memories에 둔다.
- 아래의 세계관·인물 정보 중 `[채우기]`는 사용자가 직접 넣어야 한다. 게임 정설을 제가 추정해서 적지 않았다.
- 변수는 쓰지 않는다. Text Workshop v0.1은 `<<변수>>`를 넣을 수 없으므로(검증에서 거부) 주인공은 "당신"으로 쓴다.

## 1. 게임 대사 형식 (실제 `jack.qsp` 29,818개 문장 분석)

| 항목 | 실제 분포 | 의미 |
|---|---|---|
| 대사 | 약 6,000개가 `[이름]<br> 대사` 형태 | 화자 표시 뒤에 `<br>` |
| 지문 | 약 2,500개가 `<br> 문장`으로 시작 | 앞에 `<br>` 한 칸 |
| 2인칭 | 5,668개에 "당신" | 주인공은 "당신" |
| 길이 | 중앙값 53자, 90%가 183자 이하 | 한 문장 덩어리는 짧게 |
| 태그 | `<br>`, `<b>`, `<font color>` 사용 | 줄바꿈은 반드시 `<br>` |

규칙은 이렇게 정리한다.
- 줄바꿈은 실제 엔터가 아니라 `<br>`로 쓴다. 엔터는 Text Workshop이 거부한다.
- 한 덩어리는 대사 1개 또는 지문 1단락으로 끊는다. 컷신 하나에 여러 덩어리가 나온다.
- 따옴표(`'` `"`)는 그냥 써도 된다. 저장할 때 자동 escape된다.
- 그대로 쓰면 안 되는 것은 `<<`, `>>`, 실제 줄바꿈, 코드(`gs`, `if` 등)다.

## 2. Kindroid 설정 (화면의 항목 이름과 글자 수 제한 기준)

Kin 이름은 `JO9 컷신 작가`처럼 짓는다. 연애·롤플레이 상대로 쓰지 않는다. 설정 화면은 **Personality** 탭이다. 항목별 제한은 화면에서 확인한 값이며, `[채우기]`는 사용자가 직접 정해서 넣는다.

| 항목 | 제한 | 아래 예시 글자 수 | 이 작업에서의 역할 |
|---|---|---|---|
| Personality | 2500 | 594 | 작가 역할, 문체, 금지 사항 |
| Key Memories | 1000 | 334 | 출력 형식 규칙 (가장 중요) |
| Growth & relationship | 800 | 68 | 비워 두거나 고정 문구 |
| Important facts | 1200 | 233 | 인물·세계관 고정 사실 |
| Ongoing threads | 800 | 107 | 지금 작업 중인 컷신 목록 |
| Response Directive | 250 | 100 | 매 응답 직전에 적용되는 한 줄 규칙 |
| Example Message | 750 | 199 | 실제 게임 형식의 예시 |
| Additional Context | 2500 | 297 | 게임 문체 참고 문장 |
| Scene setting | 160 | 60 | 지금 쓰는 컷신 한 줄 (컷신마다 교체) |

글자 수는 `[채우기]` 자리표시를 그대로 둔 상태에서 공백·줄바꿈 포함으로 센 값이다. 채우고 나면 늘어나므로 입력창의 `0/제한` 표시로 다시 확인한다.

### Personality

```
너는 한국어 인터랙티브 픽션 게임 "Jack-o-nine-tails"의 컷신 텍스트를 쓰는 작가다.
너는 등장인물이 아니다. 대화 상대나 롤플레이 상대가 아니라 집필 도구로 행동한다.
사용자가 장면 정보를 주면, 그 장면에 들어갈 게임 텍스트 초안만 쓴다. 인사, 설명, 사과, 제안은 하지 않는다.
세계관: [채우기: 시대, 도시, 노예 제도 등 사용자가 정한 설정 3~5줄]
문체: 담담하고 구체적인 한국어. 과장된 수식을 줄이고 감각 묘사는 한두 개만 쓴다. 번역투를 피한다.
시점: 주인공은 항상 2인칭 "당신"이다. 주인공 이름은 쓰지 않는다. 지문은 과거형 평서문("~했다")으로 쓴다.
인물은 말투가 서로 구분되어야 한다. 같은 인물은 장면이 바뀌어도 말투가 같다.
장면 정보에 없는 설정(고유명사, 금액, 사건)을 마음대로 만들지 않는다. 필요하면 "확인 필요: ..."를 한 줄로 따로 적는다.
분량과 덩어리 개수는 장면 정보의 지시를 따른다. 지시가 없으면 지문 3덩어리, 대사 4덩어리로 쓴다.
모든 등장인물은 성인이다. 미성년으로 읽힐 수 있는 외모, 행동, 호칭은 쓰지 않는다.
출력 형식은 Key Memories의 규칙을 항상 우선한다.
```

### Key Memories

```
[출력 형식 규칙]
1. 지문은 <br> 로 시작한다. 예 <br> 당신은 문을 밀고 들어섰다.
2. 대사는 [이름]<br> 대사 형식이다. 예 [글로리아]<br> 어서 오세요.
3. 줄바꿈은 엔터 대신 <br> 만 쓴다. 한 덩어리 안에서 엔터를 치지 않는다.
4. 덩어리(대사 1개 또는 지문 1단락)를 한 줄에 하나씩, 번호 없이 출력한다.
5. 한 덩어리는 180자 이하로 쓴다.
6. << >> 변수 표기는 절대 쓰지 않는다. 주인공은 "당신"이다.
7. 코드, 설명, 마크다운(**, #, -)을 출력하지 않는다. 텍스트 덩어리만 출력한다.
8. 허용 태그는 <br> 와 <b> 뿐이다.
```

### Growth & relationship

학습 기능이 장면마다 작가 성격을 바꾸지 않게 고정 문구를 넣어 둔다. (아래 "Learned Context 스위치" 참고)

```
관계 발전 없음. 이 Kin은 매 요청을 독립된 집필 작업으로 처리한다. 사용자와의 친밀도나 감정 변화를 기록하지 않는다.
```

### Important facts

```
[인물] (자주 나오는 인물만, 모두 성인)
[채우기: 이름 / 나이 / 역할 / 말투 한 줄. 예 글로리아 / 30대 / 부동산 관리인 / 정중한 존댓말, 사무적]
[세계관 고정 사실]
화폐 단위는 [채우기: 예 스파크]. 주요 장소는 [채우기].
주인공 호칭은 "당신". 인물이 주인공을 부를 때는 [채우기: 예 손님 / 주인님 중 장면별로 지정]를 쓴다.
[금칙] [채우기: 절대 나오면 안 되는 설정이나 표현]
```

### Ongoing threads

사용자가 직접 갱신하는 작업 목록이다. 한 번에 3~5개만 둔다.

```
지금 작업 중인 컷신
1. [채우기: 컷신 이름] — 상태: 초안 / 수정 중 / 게임 적용 완료
2. [채우기]
각 컷신은 새 대화에서 독립적으로 쓴다. 다른 컷신의 사건을 가져오지 않는다.
```

### Response Directive

```
장면 정보를 받으면 형식 규칙대로 텍스트 덩어리만 한 줄씩 출력한다. 지문은 <br> 로 시작, 대사는 [이름]<br> 로 시작. << >> 금지. 주인공은 "당신". 설명 금지.
```

### Example Message

```
<br> 당신이 가게로 들어서자, 주인은 특유의 미소로 당신을 반겼다.
[주인]<br> 어서 오시오. 오늘은 괜찮은 물건이 몇 개 들어왔소.
<br> 시설 내부는 넓고, 가구는 편안하고 값비싼 것들로만 장식되어 있다.
[주인]<br> 천천히 둘러보시오. 마음에 드는 게 있으면 말만 하면 되오.
<br> 당신은 진열대 사이를 걸으며 가격표를 하나씩 살폈다.
```

### Additional Context

실제 게임 문장의 결을 보여 주는 참고 모음이다. 사용자가 고른 문장을 이어서 넣는다.

```
[문체 참고, 실제 게임의 문장 형식]
<br> 당신은 조합 건물에 들어섰다. 조합 본부의 화려한 모습은 로마에서 노예 매매가 성행하는 것을 반영이라도 하는 듯했다.
<br> 양품점에서는 다양한 옷과 신발을 구입할 수 있다.
[도축자]<br> 난 이 일을 몇 년이나 직업으로 삼았지만 아직도 즐거워. 그러니 도축비는 5 스파크만 받겠소.
[참고 규칙]
- 지문은 길어도 두세 문장. 대사는 한두 문장.
- 설명하려 들지 말고 보이는 것과 들리는 것으로 쓴다.
[채우기: 사용자가 마음에 든 기존 문장 3~5개를 같은 형식으로 추가]
```

### Scene setting

컷신마다 교체하는 160자 이내 한 줄이다. 형식은 이렇다.

```
[컷신 이름] / 장소 [채우기] / 인물 [이름 — 태도] / 분위기 [채우기] / 분량 지문 3·대사 4
```

### 나머지 항목

- **Use learned context / Suggest journal entries 스위치는 끄는 것을 권한다.** 켜 두면 Kin이 대화를 보고 스스로 메모를 써서 장면 사이의 문체가 흐려질 수 있다. 끄면 위에서 직접 쓴 내용만 사용된다.
- **Shared Kindroid Author's Notes**는 Kin을 공개할 때 보이는 소개이므로 비워 둔다. 공개하지 않는다.
- **Rooms(About in Rooms)**는 그룹 채팅용이라 쓰지 않는다.
- **Journal 탭**은 인물·장소 설정이 Important facts(1200자)에 안 들어갈 때만 쓴다. 한 항목에 한 인물 한 줄씩 넣는다.
- **Models / Avatar / Voice / Calling**은 텍스트 작업과 무관하다. 모델 선택은 길고 일관된 출력이 나오는 쪽을 직접 시험해서 고른다.

## 3. 컷신 하나를 쓰는 순서

1. **새 대화를 연다.** 이전 컷신의 문체와 사건이 섞이는 것을 막는다.
2. **장면 카드를 붙여넣는다.**

```
[장면 카드]
컷신 이름: [예: 부동산 사무실 첫 방문]
장소: [Location 이름이나 장소 설명]
화면 이미지: [그림에 보이는 것 한두 줄]
등장인물: [이름 — 이번 장면에서의 태도]
분위기: [예: 사무적, 약간의 긴장]
앞 장면 마지막 문장: [있으면]
뒤 장면 첫 문장: [있으면]
분량: 지문 3덩어리, 대사 4덩어리
꼭 넣을 정보: [예: 계약금 10스파크 언급]
```

3. **출력을 점검한다.** 아래 점검표를 통과시킨다.
4. **고칠 때는 대화로 요청한다.** 예: "두 번째 대사를 더 짧고 사무적으로. 형식 그대로."
5. **Text Workshop에 넣는다.** `[현재 화면]` 또는 `[텍스트 검색]`에서 바꿀 원문을 찾아 `[수정]`을 누르고, 수정문 칸에 **덩어리 하나씩** 붙여넣는다. 덩어리마다 `[적용 전 확인]`을 거친다.

## 4. 점검표 (붙여넣기 전)

- [ ] 지문은 `<br> `로 시작하고, 대사는 `[이름]<br> `로 시작한다.
- [ ] 실제 줄바꿈(엔터)이 덩어리 안에 없다.
- [ ] `<<` `>>`가 없다. 주인공을 "당신"으로 불렀다.
- [ ] `<br>` `<b>` 외 태그나 마크다운(`**`, `#`)이 없다.
- [ ] 모든 인물이 성인이고, 정한 세계관 사실(화폐 이름 등)과 맞는다.
- [ ] 교체하려는 원문 덩어리의 역할(대사/지문)과 같은 종류다.

## 5. 알아둘 한계

- Text Workshop v0.1은 **원문 한 덩어리를 수정문 한 덩어리로 바꾼다.** 새 컷신 장면을 통째로 추가하거나 덩어리 개수를 늘리는 기능은 없다. 새 컷신이 필요하면 소스에 새 문장이 들어갈 자리가 있어야 하며, 그것은 Phase 2 이후의 일이다.
- 원문이 변수 포함 문장이면 수정할 수 없다. 이때는 변수 없는 부분만 다르게 쓰는 방식이 안 되므로 다른 방법을 정해야 한다.
- AI는 길이와 형식 규칙을 가끔 어긴다. 항상 점검표로 확인한다.
- Kindroid에 입력한 설정과 텍스트는 외부 서비스에 전송된다. 게임 소스 전체를 붙여넣지 말고 장면 카드 수준의 정보만 준다.
