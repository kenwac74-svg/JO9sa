# JO9 Text Workshop 개발 핸드오프 기획서
버전: Planning Handoff v0.1  
대상: Claude 개발 AI  
프로젝트: Jack-o-nine-tails Modding / JO9 Workshop  
목적: 기존 JO9 Image Workshop과 유사한 사용감의 텍스트 편집 도구를 개발하기 위한 요구사항 전달

---

# 0. 핵심 요약

JO9 Text Workshop은 **치트 프로그램이 아니라 인게임 연동형 모딩 편집기**다.

첫 개발 버전(v0.1)은 기능을 크게 벌리지 않는다.

**v0.1 핵심 목표는 오직 다음 한 가지다.**

> 게임을 플레이하다 화면에 보이는 “변수가 없는 순수 대사와 지문”을 발견하면,  
> 엔진 메뉴에서 Text Workshop을 열어 해당 문장의 실제 QSP/QSRC 사용처를 찾아 목록으로 보고,  
> 사용자가 원하는 항목만 선택해 수정하고, 안전하게 백업·적용·롤백할 수 있게 한다.

처음부터 QGen 대체 IDE를 만들지 않는다.  
처음부터 변수/조건/이벤트 로직까지 편집하지 않는다.  
먼저 단순 텍스트 편집 사이클을 실제 게임에서 안정적으로 검증한다.

---

# 1. 기존 JO9 Image Workshop과의 관계

Text Workshop은 기존 Image Workshop의 UX와 철학을 최대한 계승한다.

기존 Image Workshop의 주요 철학:

- 게임 플레이 중 현재 장면을 보고 편집 시작
- 엔진 메뉴에서 실행
- HTML 기반 UI
- Python 사용하지 않음
- 로컬 보조 서버 사용 가능
- 파일/리소스의 사용처 목록을 찾아 보여줌
- 사용자가 직접 적용 대상을 선택
- 백업 후 적용
- 해시 검증
- 적용 실패 시 가능한 경우 자동 롤백
- History / Restore 제공
- 원본을 가능한 한 보호
- 별도 개발도구를 직접 다루지 않는 UX

Text Workshop도 같은 계열의 도구처럼 느껴져야 한다.

개념적으로:

```text
JO9 Workshop
├─ Image Workshop
└─ Text Workshop
```

초기 버전에서는 내부 구현이 완전히 통합되지 않아도 된다.
기존 Image Workshop의 안정성을 깨뜨리지 않는 것이 우선이다.

# 2. 제품 성격

## 2.1 모딩 도구이지 치트 메뉴가 아니다

별도 편의 기능으로 다음을 제공하지 않는다.

- 돈 증가
- 활동력 무한
- 스탯 최대
- 경험치 증가
- 호감도 즉시 증가
- 아이템 자동 지급
- 기타 노골적인 Cheat Menu

그러나 이 도구는 소스 편집기이므로 사용자가 일반 모딩 범위에서 다음을 수정하는 것까지 막지는 않는다.

예:

- 초기 소지금 변경
- 이벤트 보상 금액 수정
- 게임 시작값 변경
- 특정 이벤트의 수치 변경
- 가격 변경
- 조건 변경

즉:

> 치트 기능을 메뉴로 제공하지 않는다.  
> 하지만 범용 편집 기능의 결과를 사용자가 어떻게 활용할지는 제한하지 않는다.

v0.1에서는 애초에 이런 변수/수치 편집을 구현하지 않는다.

# 3. 전체 개발 순서

## Phase 1 — Text Workshop v0.1

지원:

- 순수 대사
- 순수 지문/서술
- 현재 장면 기준 탐색
- 동일 문자열 사용처 목록
- 사용자 선택 편집
- 백업
- 적용
- History
- 롤백

지원하지 않음:

- 변수 포함 텍스트
- 문자열 조립
- 변수 값
- 조건문
- Location 호출
- Key 분리
- Preset
- 고급 코드 수정

---

## Phase 2 — Text Workshop 확장

v0.1 안정화 이후 순차 구현 후보:

- 변수 포함 문장 표시
- 변수 토큰 보호
- 텍스트 참조 Key 추적
- 공용 텍스트 → 전용 텍스트 분리
- 새로운 텍스트 Key 생성
- 참조명 교체
- 반복 소스 편집용 Preset
- 고급 소스 보기
- 일부 안전한 구조 수정

한 번에 모두 구현하지 않는다.

---

## Phase 3 — Image Workshop 소스 참조 확장

기존 Image Workshop의 “동일 파일명 교체”를 넘어 다음 기능 확장:

- 현재 이벤트에서 참조하는 이미지 파일명 변경
- 원래 이미지가 없는 장면에 이미지 참조 추가
- 공용 이미지 → 특정 이벤트 전용 이미지 분리
- 새 이미지 경로 생성
- 소스 이미지명 교체 Preset

이 기능은 Text Workshop과 동일한 Patch Recipe 개념을 공유할 수 있다.

---

## Phase 4 — Asset Registry / 모딩 자산 관리

Text Workshop 이후의 **별도 개발 스펙**이다.

이번 Text Workshop v0.1 구현에 넣지 않는다.

목표:

- 인물(Entity) 등록
- Alias 등록
- 실제 게임 자산과 인물 연결
- 사용자가 수동으로 자산 연결
- 제작 중인 신규 자산 등록
- 나중에 인물 이름 검색 시 연결된 모든 자산 조회
- 향후 NPC/Character/Slave Modding Tool의 공통 자산 DB로 활용

예:

```text
Gloria
├─ Alias
│  ├─ 글로리아
│  ├─ realtor
│  └─ 부동산 관리인
├─ 게임 자산
│  ├─ realtor.png
│  ├─ 관련 이벤트 이미지
│  ├─ 관련 Location
│  └─ 관련 텍스트
└─ 제작 중 자산
   ├─ 신규 portrait
   └─ 신규 event CG
```

# 4. Text Workshop v0.1 범위

## 4.1 지원 대상

다음처럼 화면에 직접 출력되는 순수 문자열.

### NPC 대사

```text
Gloria:
"Welcome. What can I do for you?"
```

### 주인공 대사

```text
"I came to ask about the property."
```

### 지문 / 서술

```text
The realtor looks through several documents.
```

### 일반 장면 설명

```text
You enter the office and find the realtor waiting inside.
```

조건:

- QSP/QSRC 원본에서 문자열을 명확하게 식별 가능
- 변수 삽입이 없는 직접 문자열
- 자동 추적 신뢰도가 충분하거나 사용자가 후보를 선택 가능

# 5. v0.1 비지원 대상

다음은 편집 대상으로 취급하지 않는다.

## 5.1 변수 포함 텍스트

```qsp
'<<$npc_name>> gives you <<reward>> gold.'
```

화면:

```text
Gloria gives you 100 gold.
```

이 경우 v0.1에서는:

```text
[변수 포함 텍스트]
현재 버전에서는 수정할 수 없습니다.
```

라고 표시한다.

---

## 5.2 문자열 조립

```qsp
$text = $prefix + $npc_name + $suffix
```

제외.

---

## 5.3 변수 값

```qsp
$npc_name = 'Gloria'
reward = 100
```

제외.

---

## 5.4 조건 및 실행 코드

```qsp
if relation > 50:
gs 'interaction_result'
goto 'estate'
dynamic $code
```

제외.

---

## 5.5 Key 구조 변경

```qsp
$txt['generic_greeting']
```

을 다른 Key로 분리하거나 새 Key를 생성하는 기능은 v0.1에서 제외.

# 9. Source Resolver — v0.1 범위

Resolver의 역할:

> 현재 화면에 보이는 문장이 실제 어느 QSRC/Location에서 사용되는지 후보를 찾는다.

v0.1 탐색 우선순위:

```text
1. 현재 Location
2. 현재 Location 내부 완전 일치 문자열
3. 현재 Location이 직접 참조하는 텍스트
4. 관련 텍스트 DB의 직접 문자열
5. 전체 QSRC 문자열 검색
```

v0.1에서는 다음과 같은 복잡한 분석을 하지 않는다.

- 변수 흐름 추적
- 동적 문자열 조립
- 복잡한 실행 경로 해석
- 조건 분기 정밀 해석
- 동적 배열 값 추적

# 10. Context는 힌트이지 확정 소스가 아니다

게임에서 다음을 넘길 수 있다.

```json
{
  "currentLocation": "interaction_city",
  "visibleTexts": [
    "Welcome. What can I do for you?"
  ]
}
```

하지만 `currentLocation`만 보고 바로 수정하지 않는다.

반드시 실제 QSRC를 다시 확인한다.

흐름:

```text
Context
 ↓
Source 후보 검색
 ↓
실제 문자열 확인
 ↓
사용 위치 확인
 ↓
후보 표시
 ↓
사용자 선택
```

# 15. 주변 문맥 표시

같은 짧은 문장이 여러 곳에 있을 수 있으므로 각 사용처에 앞뒤 문맥을 보여준다.

예:

```text
Location: guild

Before:
The clerk looks up.

Target:
"Welcome."

After:
"What business brings you here?"
```

짧은 공통 문장을 사용자가 구분할 수 있어야 한다.

# 18. QSP 문자열 안전 처리

사용자는 QSP escaping 규칙을 몰라도 되어야 한다.

예:

사용자 입력:

```text
"Don't worry," Gloria says.
```

Workshop이 필요한 문자열 escaping을 처리해야 한다.

적용 전 최소한 다음을 확인한다.

- 문자열 delimiter 손상 여부
- 대상 문자열 블록 식별 가능 여부
- 수정 후 파일을 정상적으로 다시 읽을 수 있는지
- 기존 코드 구조를 침범하지 않는지

v0.1에서는 파서가 확신할 수 없는 문자열은 편집 불가로 처리하는 것이 낫다.

---

# 19. 백업 — v0.1 필수

백업은 후속 기능이 아니다.

첫 버전부터 반드시 포함한다.

처리 순서:

```text
현재 원본 읽기
 ↓
원본 SHA-256 기록
 ↓
백업 생성
 ↓
적용 직전 원본 해시 재확인
 ↓
텍스트 수정
 ↓
수정본 재읽기
 ↓
저장 결과 검증
 ↓
History 기록
```

---

# 20. 수정 중 원본 변경 감지

Workshop을 연 후 다른 패치/도구가 파일을 변경했을 수 있다.

적용 직전 원본이 탐색 당시와 다르면 중단한다.

UI:

```text
원본 소스가 Workshop을 연 이후 변경되었습니다.

안전을 위해 적용을 중단했습니다.

[다시 검색]
[취소]
```

강제 덮어쓰기 금지.

---

# 21. 실패 자동 롤백

적용 도중 오류 발생:

```text
수정 실패

원본 상태로 자동 복구:
성공

게임 파일은 수정 전 상태입니다.
```

백업/복원 방식은 기존 Image Workshop의 검증된 트랜잭션 철학을 최대한 재사용한다.

---

# 22. History

예:

```text
09:30
interaction_city

"Welcome."
→
"Welcome back."

[상세]
[되돌리기]
```

한 번의 적용에서 여러 문장을 수정했다면 하나의 작업 단위로 묶는다.

```text
09:38
Gloria office scene

텍스트 4개 수정

[상세]
[전체 되돌리기]
```

v0.1에서는 개별 줄 롤백보다 **작업 단위 롤백을 우선**해도 된다.

---

# 23. 롤백 충돌

해당 작업 이후 같은 파일에 다른 수정이 존재하면 자동 롤백을 중단한다.

예:

```text
이 파일에는 이후 다른 변경이 있습니다.

자동 복구를 중단했습니다.

[현재 내용 확인]
[취소]
```

v0.1에서 강제 복구는 필수가 아니다.

후보 목록을 보여준다.

# 26. 편집 불가 항목도 숨기지 않는다

```text
Gloria gives you 100 gold.

[변수 포함 텍스트]

현재 버전에서는 직접 수정할 수 없습니다.

[소스 정보]
```

라고 표시한다.

사용자가 “왜 이 문장만 안 보이는가”라고 혼란스러워하지 않도록 한다.

v0.1에서 실제 QSP 전체 코드 편집기는 만들지 않는다.

# 28. v0.1에서 Preset 미구현

Preset의 개념:

> 특정 버그 이름이 아니라 자주 반복되는 소스 수정 방법을 정의하는 Recipe.

예:

- 소스 이미지명 교체
- 공용 이미지 → 전용 이미지 분리
- 텍스트 참조명 교체
- 공용 텍스트 → 전용 텍스트 분리
- 누락 변수 할당 삽입

하지만 v0.1에서 구현하지 않는다.

v0.1은 먼저:

```text
발견
→ 사용처 선택
→ 수정
→ 백업
→ 적용
→ 롤백
```

사이클을 검증한다.

---

# 29. 향후 Preset 철학

추후 Preset은 특정 패치와 구분한다.

잘못된 예:

```text
Preset:
Amaranth Salon Fix
```

올바른 개념:

```text
Preset:
특정 분기의 누락된 값 할당 추가
```

`Amaranth Salon Fix`는 이 Preset을 실제 소스에 적용해 만든 **Patch**다.

또한 Image Workshop에서는:

```text
Preset:
소스 이미지명 교체
```

등을 만들 수 있다.

# 30. 등장인물 분류 — 현재 개발에서의 의미

향후 Asset Registry를 위해 등장인물은 다음으로 분류한다.

```text
1. 노예 캐릭터
2. 일반 캐릭터
3. 몹
4. 고유 NPC
5. 일반 NPC
6. 엑스트라
```

그러나 **Text Workshop v0.1에서 이 전체 캐릭터 자산 편집 기능을 구현하지 않는다.**

분류 정의:

## 노예 캐릭터

- `girls` 계열에 본인 전용 이미지셋 존재
- Isabella 같은 케이스

## 일반 캐릭터

- `character` 폴더에 본인 전용 캐릭터 이미지 존재
- mob 폴더에도 이미지가 있더라도 Character 조건을 만족하면 Character로 우선 분류

## 몹

- mob 폴더에 본인 Portrait 존재
- 관련 이벤트 존재
- Character 조건을 만족하지 않는 경우

## 고유 NPC

- 고유 이름
- 고유 이벤트 Scene
- 고유 이미지
- Character/Mob 구조는 아님

## 일반 NPC

- 장면/배경에 등장
- 텍스트에서는 역할명/대명사로 불리는 경우
- 예: 여직원, 점원, 경비병
- 같은 역할명이 다른 장면에 있다고 같은 인물로 묶으면 안 됨

## 엑스트라

- 별도 이미지 없음
- 스토리 텍스트에서만 언급

# 31. Character / Slave 전체 편집은 별도 툴

특히 노예 캐릭터는:

- 대량 이미지셋
- 포즈별 이미지
- 장면별 이미지
- 행위별 매핑
- 상태별 리소스

가 필요하므로 Text Workshop 범위가 아니다.

향후 별도:

```text
Character / Slave Modding Tool
```

로 개발한다.

# 32. Asset Registry — 다음 개발 스펙

이번 Text Workshop 개발이 끝난 뒤 별도로 개발.

목표:

> 사용자가 한 인물과 관련된 자산을 직접 연결해두면, 다음부터 그 인물 이름을 검색했을 때 자동 발견 자산 + 수동 연결 자산 + 제작 중 자산을 모두 보여준다.

중요 사례: Gloria

게임에서는:

```text
표시 이름:
Gloria

역할:
부동산 관리인

이미지 파일:
realtor.png
```

이므로 단순 파일명 검색으로는 연결 불가.

따라서 사용자가:

```text
realtor.png → Gloria
```

를 직접 등록할 수 있어야 한다.

이 관계는 영구 저장.

---

# 33. Asset Registry의 제작 중 자산

아직 게임에 사용되지 않은 신규 자산도 인물에 등록 가능해야 한다.

예:

```text
Gloria

게임 사용:
- realtor.png

제작 중:
- gloria_new_portrait.png
- gloria_event_new.png
```

나중에 다른 모딩 툴에서 `Gloria`를 입력하면 이 자산들이 모두 보여야 한다.

이 기능은 **Text Workshop이 아니라 독립적인 모딩 자산 관리 기능**으로 개발.

# 39. 개발 시 중요한 원칙

## 39.1 단순한 성공 경로부터

먼저:

```text
현재 장면의 직접 문자열
→ 정확한 소스 위치
→ 수정
→ 백업
→ 검증
```

을 완성한다.

복잡한 Resolver를 먼저 만들지 않는다.

---

## 39.2 완전 일치 우선

v0.1은 문자열 완전 일치를 가장 높은 신뢰도로 사용한다.

부분 일치는 후보로만 보여준다.

---

## 39.3 확신 없으면 수정하지 않는다

Resolver가 정확한 위치를 확정하지 못하면 사용자에게 후보를 보여준다.

자동 추측 수정 금지.

---

## 39.4 전역 치환보다 선택 목록

항상:

```text
검색
→ 사용처 목록
→ 사용자 선택
→ 변경
```

흐름을 우선한다.

---

## 39.5 기존 Image Workshop 안정성 유지

Text Workshop 기능 추가를 이유로 기존 이미지 편집 기능을 대규모 리팩터링하지 않는다.

필요한 공통 기능만 점진적으로 분리/재사용.

---

# 40. 미확정 / 개발 전 확인 필요 사항

다음은 현재 기획에서 **의도적으로 확정하지 않았다.**

## QSP 텍스트 언어/로컬라이제이션 구조

확인 중 중단된 질문:

- QSP 내부 텍스트가 한글만 존재하는가?
- 영어 원문도 함께 존재하는가?
- 별도 로컬라이제이션 팩 구조인가?

이 사항은 현재 기획서에서 임의로 가정하지 않는다.

Claude는 구현 전에 실제 `locations/*.qsrc`, `#txt`, `#txt_2`, `#static_txt` 등 텍스트 관련 소스를 샘플 조사하여 구조를 확인해야 한다.

단, **v0.1 설계 원칙 자체는 어느 구조든 동일하다.**

즉:

```text
화면에 보이는 순수 텍스트
→ 실제 사용 위치 추적
→ 사용처 목록
→ 선택 편집
```

구조를 유지한다.

# 41. 최종 구현 목표 문장

> JO9 Text Workshop v0.1은 게임 플레이 중 보이는 대사와 지문을 대상으로,
