# 대사 편집실 단어 일괄 치환

2026-10-18. 변경 식별자 `text-batch-replace-20261018`, `TEXT_BATCH_REPLACE_*`.

사용자는 단어가 들어 있는 대사를 체크하거나 검색 결과 전체를 선택하여 바꿀 말을 일괄 적용할 수 있다. 기존 원문 찾기 아래의 **단어 일괄 치환**을 펼친다.

1. **찾을 단어**, **바꿀 말**을 입력하고 **치환 대상 찾기**를 누른다. 위치 이름을 넣으면 그 위치로 좁힌다. 위의 「게임에 보이는 대사만 / 코드까지 같이」 설정을 따른다.
2. 치환할 결과를 체크하거나 **검색 결과 전체 선택 (모든 페이지)**을 체크한다. 페이지를 이동해도 선택 및 제외 항목은 유지한다. 결과는50개씩 보이지만 전체선택은 검색된 모든 결과에 적용한다.
3. **선택한 항목 치환 미리보기**에서 전·후 문구와 총 대사 수·단어 출현 수를 확인한다. 미리보기도 페이지를 이동해 전부 볼 수 있다.
4. **선택한 항목의 일괄 치환을 승인함**을 체크하고 **선택한 항목 일괄 치환**을 누른다. 한 번의 백업 및 수정 기록으로 저장한다. 변경 기록에서 JSON 내보내기와 되돌리기를 사용한다.

대소문자·띄어쓰기를 구별하며 정규식이 아닌 입력 문자열 그대로 찾는다. 한 대사에 여러 번 나오면 그 대사 안에서는 모두 바꾼다. 바꿀 말을 비우면 찾은 단어를 삭제한다. 같은 문장이 여러 위치에 있어도 체크한 위치만 바꾼다. 검색어나 범위·선택·수정문을 바꾸면 기존 미리보기와 승인 상태는 취소된다.

이 도구 업데이트 자체는 게임 QSP나 세이브를 수정하지 않는다. 사용자가 실제 치환을 반영할 때는 기존 트랜잭션이 현재 QSP 해시를 다시 확인하고 백업·임시 파일 확인 후 저장한다. 이후 게임의 장면을 다시 불러오거나 게임을 다시 실행한다.

## 구성과 입출력

- `batch-replace.cjs`의 `key(entry)`는 필드와 문자열 범위를 ID로 만든다. 문장 자체가 같아도 위치별 ID가 다르다.
- `search(doc, scope, cachedEntries)`는 원래 QSP와 검색어·위치·보기·페이지를 받는다. 파일 지문, 검색된 대사 수·단어 수와 현재50개 결과를 반환하며 파일에 쓰지 않는다.
- `prepare(doc, input, cachedEntries)`는 검색 지문, 치환 문자열, 선택 ID 또는 전체선택과 제외 ID를 받는다. 변경 QSP 바이트, before/after 지문, 위치별 전·후 목록과 내보낼 변경 조각을 반환한다. 원본 문서와 파일은 바꾸지 않는다. 잘못된 지문·위치·치환문은 기존 검증에 따라 거부한다.
- 대량 처리 시 같은 필드의 문자열을 한 번에 조립한다. 내보내기는 필드별 선택 범위를 덮는 고유한 연속 조각이며, 중간의 선택하지 않은 코드는 전·후가 동일하다. 개별 변경만 가리키는 UI 목록 및 선택 수는 그대로다. 전체 필드를 문자열마다 반복해서 분석하지 않는다.
- `batch-replace.js`의 `createSelection()`은 개별 선택 집합 또는 전체선택의 제외 집합을 관리한다. `replaceLiteral()`은 미리보기용 문자열 치환이다. DOM 이벤트는 검색·선택·미리보기·승인·반영을 기존 API와 연결하며 source text를 HTML로 실행하지 않는다.
- `index.html`의 `JO9BatchEditor`는 기존 편집기 API와 안내, 이전 단일 미리보기 취소, 저장 후 장면·검색 갱신을 연결한다. 기존 단일 수정·복원은 일괄 미리보기를 무효화한다. 초안 보관은 기존 동작을 사용한다.
- 서버 `GET /api/batch/search`, `POST /api/batch/preview`, `GET /api/batch/preview`가 검색·준비·검토 페이지를 제공한다. 저장은 기존 `POST /api/apply`의 batch 분기를 사용한다. 원래 token·origin·최신 해시·승인·백업 검사를 유지한다. 하나의 bulk transaction을 기존 수정 기록과 `/api/export`, `/api/restore`에서 다룬다.

## 의존성 및 복원

기존 `core.cjs`의 QSP 읽기/쓰기, 문자열·형식 검증, 최소 수정 조각 계산과 서버의 `current`, `transact`, history가 필수다. 배포 파일은 `server.cjs`, `index.html`, `batch-replace.cjs`, `batch-replace.js`이며 README도 함께 갱신한다. 원래 설정·키·기록·작업 파일은 덮어쓰지 않는다.

JS를 빼면 패널 조작이 작동하지 않고, 모듈을 빼고 require를 남기면 서버 시작이 실패한다. 일부 구간을 따로 제거하지 말고 동일 작업의 백업으로 관련 도구 파일을 함께 복원한다. 런처는 설치본에 도구 변경을 복사하고 같은 편집기 서버만 확인 후 재시작한다. 브라우저는 새로고침해야 새 화면·세션 토큰을 읽는다. 게임 파일을 복원할 작업은 이 도구 설치에 없다.

## 검증

- 관련 단위·HTTP·기존 편집/추가/장면/복원 회귀42개 통과.
- 실제 Edge 브라우저2개 시나리오 통과. 235결과 중 다음 페이지의1개 제외 →234대사·468단어 치환, 승인 전 무변경, 백업·수정 기록1회, 다운로드 JSON 재적용 및 되돌리기 바이트 일치, 입력 변경 시 승인 무효화와 HTML 비실행을 확인했다.
- 현재47,209,412바이트 플레이 QSP를 읽기 전용으로 분석했다. 검색1,460대사 중1개 제외하여1,459대사·1,802단어의 치환 바이트를 메모리에서 준비하는 데562ms가 걸렸다. 해당 검사는 실제 게임에 쓰지 않았으며 원본 지문 `e49bceb154990f94f582941ad4f7d3aa9c58483e027178586d2e28f0c0b7080a`가 유지됐다. 시간은 이번 실행의 관측값이다.
- 코드 검토에서 남은 중요 결함0. 격리 복사본 전체 테스트의 다른 이미지/패치 자료 누락은 실제 기능 오류와 구분했고 관련42개를 최종 재실행했다.

QSP 구문 전체나 모든 게임 분기를 증명하는 컴파일러를 추가한 것은 아니다. 실제 변경의 범위·문구를 사용자가 미리보기에서 확인한다. 실제 게임 파일에 특정 단어를 치환하는 작업은 이번 요청에 포함하지 않았다.
