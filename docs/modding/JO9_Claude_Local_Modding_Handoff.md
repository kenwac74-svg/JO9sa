# JO9 로컬 모딩 작업 — Claude 핸드오프

## 목적
Jack-O-Nine-Tails(JO9)를 먼저 **완성도 높은 모딩 버전**으로 다듬는다.  
현재 단계의 목표는 웹 포팅이나 AI 런타임 개발이 아니라, 기존 JO9의 버그·UI·이벤트·텍스트·이미지 경로·분기 로직을 실제 플레이 기준으로 정리해 **상용 게임 수준에 가까운 완성본**을 만드는 것이다.

## 핵심 작업 방식
모딩 툴을 별도로 배포하는 것이 목적이 아니다.

사용자가 게임을 플레이하다가 다음처럼 지시하면:

- “이 장면에서 이 이미지를 다른 이미지로 바꿔”
- “이 이벤트에 새 분기를 붙여”
- “이 문장을 다른 이벤트에서 불러오게 해”
- “이 조건에서만 다른 CG를 보여줘”
- “이 UI가 메인 UI와 안 맞는다”
- “이 버그가 왜 생기는지 찾아서 고쳐”

Claude가 직접 로컬 JO9 소스를 검색하고, 관련 QSRC/QSP를 찾아 **최소 변경으로 수정**한다.

기본 루프:

1. 사용자에게 문제 장면 / Show HTML / 이벤트 상황을 받음
2. QSRC/QSP에서 해당 분기 역추적
3. 관련 변수·이미지·텍스트·이벤트 ID 확인
4. 필요한 최소 수정
5. QSP 재빌드
6. 가능하면 게임 실행 후 검증
7. 사용자에게 수정 결과와 확인 포인트 전달

## 중요 원칙

### 1. 전체 QSP 재분석 금지
매 요청마다 전체 프로젝트를 다시 읽지 않는다.

먼저:
- 관련 Location
- 이벤트 ID
- 이미지 파일명
- 텍스트 fingerprint
- 변수명

으로 범위를 좁힌다.

### 2. 최소 변경
전체 파일 재작성보다 **필요한 줄만 수정**한다.

Git diff가 작게 유지되도록 한다.

### 3. 기존 식별자 유지
가능하면 다음은 그대로 유지한다.

- 변수명
- 이벤트 ID
- Location 이름
- 기존 이미지 경로
- 함수명
- 기존 분기 구조

새 기능 추가 시에도 기존 구조와 충돌하지 않게 확장한다.

### 4. 특정 이벤트 전용 이미지
JO9는 공용 이미지를 여러 이벤트에서 재사용하는 경우가 많다.

따라서 사용자가:
> “이 장면만 다른 이미지를 쓰게 해”

라고 하면 공용 이미지를 교체하지 말고,
**해당 이벤트 분기에서만 새 경로를 사용하도록 수정**한다.

예:
```text
기존:
sex_general_milf.png

수정:
SNKmod/events/interaction_city_61121.png
```

다른 이벤트는 기존 이미지를 그대로 사용해야 한다.

### 5. 백업과 복구
QSP/QSRC 수정 전:
- Git 상태 확인
- 변경 대상 파일 확인
- 필요 시 백업 또는 commit/stash 확보

사용자의 기존 작업을 덮어쓰지 않는다.

## UI 작업 역할
UI 수정·분석은 가능하지만, 기존 역할 분담을 따른다.

- UI patch branch: `JO9UIpatch`
- Image Workshop branch: `JO9imgtool`

서로 섞지 않는다.

UI에서 수정할 때는:
- 게임 로직을 임의로 바꾸지 않는다.
- 기존 사용자 UX를 가능한 유지한다.
- 동일 파일명이 여러 폴더에 있을 경우 사용자가 정한 정책을 우선한다.
- 동일 이름의 서로 다른 파일이 있으면 임의 통합하지 않는다.

## Image Workshop 관련
기존 Image Workshop의 핵심 아이디어는 다음과 같다.

- 기존 원본 이미지는 유지
- 특정 이벤트만 새 경로로 분리 가능
- 공용 이미지 재사용 문제 해결
- 새 이미지는 별도 mod 경로 사용
- 백업 유지

하지만 현재 핵심은 **툴 개발이 아니라 직접 QSP를 고치는 것**이다.

## 현재 우선순위
1. 로컬 JO9 직접 수정이 실제로 잘 되는지 검증
2. 버그 수정
3. 이벤트/분기 개선
4. 이미지 경로 분리
5. 텍스트/대사 수정
6. UI 불일치 수정
7. 밸런스 및 게임 흐름 개선

웹 포팅 / AI 실시간 생성은 **후순위**다.

## 장기 방향 — 지금 구현하지 말 것
완성된 모딩 버전을 기준으로 나중에:

- 웹 클라이언트
- 실시간 AI 대사 생성
- Kindroid 또는 기타 AI API 연동
- ComfyUI 기반 장면 이미지 생성
- 동일 이벤트에서도 AI가 다른 배리에이션 출력
- QSP 의존성 축소 또는 웹 런타임 전환

을 검토한다.

그러나 현재는 이 구조를 만들지 않는다.

## 로컬 작업 시 첫 점검
처음 작업할 때 다음을 확인:

1. 현재 repo 경로
2. 현재 branch
3. `jack.qproj`
4. `locations/*.qsrc`
5. 실제 게임 실행 파일 위치
6. QSP 빌드 방식
7. 현재 working tree 변경사항
8. 사용자의 기존 patch가 섞여 있는지 여부

사용자에게 파일 구조를 다시 설계하라고 요구하지 말고, **현재 환경을 직접 확인한 뒤 작업**한다.

## 작업 보고 형식
수정 후 짧게 다음만 보고:

- 수정 파일
- 수정 Location / 이벤트
- 핵심 변경 내용
- 빌드 여부
- 실제 게임 확인 필요 포인트

불필요한 장문의 구조 설명은 피한다.
