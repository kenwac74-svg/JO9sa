### 권장 수정안

1. 현재처럼 체질만 나타내는 아이콘의 이름은 **‘가임기’ 대신 ‘임신 가능한 체질’**로 바꾼다. 배란 시점 안내와 분리한다.
2. 가임성 자체가 아직 밝혀지지 않았다면 **‘가임성 미확인’**으로 표시한다. 숨겨진 불임 정보나 미확인 임신을 아이콘만으로 공개하지 않는다.
3. 임신이 확인된 경우에는 가임기 표시에 우선하여 기존 임신 단계 표시를 사용한다. 미확인 임신은 기존 공개 규칙을 유지한다.
4. 배란 시점 정보를 추가한다면 실제 일일 판정과 같은 상태값을 참조한다. 화면 안에서 별도 주기를 만들어 계산하지 않는다. 정확한 공개 범위는 기존 게임의 정보 공개 의도와 함께 검토한다.
5. ‘안전일’은 임신 불가능을 보장하는 표현이므로, 단지 불임이 미확인되었거나 배란 카운터가 특정 값이라는 이유만으로 사용하지 않는다.
6. 노예·조수·개인실에서 동일한 상태가 서로 다른 문구로 나오지 않도록 공용 표시 함수를 검토한다. 기존 개인실 브리지와 표시 대상 전환을 보존한다.

이번 권장안의 우선 범위는 **표시 수정**이다. 임신 확률·약효·월경 주기·임신 공개 시점은 함께 바꾸지 않는다.

## 2. 쿨라 서비스의 설명 오류

### 확인한 현상과 원인

쿨라 관련 장면은 일반 주기 계산과 별도로 임신 진행 상태를 직접 지정한다. 그러나 안내문은 ‘바로 만삭’과 ‘열흘 정도 뒤 출산’을 약속한다. 지정하는 진행값은 현재 표시 체계의 만삭 기준과 맞지 않는다.

주의: `next_day`의 주석과 임신 단계 UI에는 장기 임신 진행 기준이 보이지만, **실제 출산 이벤트의 존재·발동 조건·잔여 일수까지 이번 조사에서 확정한 것은 아니다.** 따라서 임신 단계 표시 기준을 곧바로 출산 보장일로 해석하면 안 된다.

### 권장 수정안

1. 우선 **검증되지 않은 ‘만삭·열흘 뒤 출산’ 보장 문구를 제거**한다. 성인 대상 서비스에서도 실제 처리 결과와 확인 가능한 상태만 설명한다.
2. 설명을 맞추려고 임신 진행값을 임의로 크게 올리지 않는다. 먼저 출산·납품·임신 단계·공개 상태가 어떤 값을 사용하는지 추적한다.
3. 임신이 불가능한 분류, 미성숙 분류 등 부적격 대상은 메뉴 활성화와 실행 진입 양쪽에서 차단한다. 강제 상태 지정으로 보호 판정을 우회하지 않는다.
4. 적격 성인 대상의 기존 임신·특수 생식 상태에 대한 중복 실행 방지도 함께 확인한다. 이번 문제를 이유로 생식 능력을 강제로 변경하지 않는다.
5. 서비스의 기획이 단순 상태 변경인지, 진행 촉진인지, 실제 출산까지 포함하는지는 별도 결정한다. 출산 기능이 확인되지 않았다면 ‘출산 지원’으로 소개하지 않는다.

대체 안내의 방향은 **‘처치 결과를 확인하고, 이후 진행은 기존 임신 시스템을 따른다’**이다. 구체 문장은 적격 성인 대상의 실제 처리 검증 후 작성한다. 현재 상태에서 새로운 출산 시점이나 결과를 약속하지 않는다.

### 검증

- 부적격 대상은 메뉴와 실행 양쪽에서 거부되고 상태가 바뀌지 않는지 확인한다.
- 적격 성인 대상에서 안내와 실제 상태 변화가 일치하는지 확인한다.
- 미확인 임신을 공개하는지 여부를 서비스 설명과 맞춘다.
- 이미 임신 중인 대상에게 반복 적용하여 상태가 역행하거나 덮어써지지 않는지 확인한다.
- 출산 시점을 안내하려면 실제 이벤트까지 별도로 검증한다. 임신 아이콘 변화만 보고 출산 검증 완료로 기록하지 않는다.

### 활동 단절에 따른 불안 누적 · 사용자 추가 확정

## 5. 반영 범위와 전달 주의

### 보호 분기 270일 엔딩 · 최신 사용자 확정 (이전 240일 안보다 우선)

추가 최신 결정: 사용자는 정상적인 보호·교육 활동을 중심으로 진행하여 절망을 높이는 행동을 사용하지 않을 계획이므로, **초기 절망을 높이고 원작의 자연 회복을 이용하는 방향**을 선택했다. 직전 제안인 각성 절망 4를 기준으로 기록하며 이지는 3으로 제한한다. 새로운 느린 회복 공식과 연속 돌봄 일수에 따른 회복 제한은 채택하지 않는다. 방치 자체의 불안 가중 상승, 응석 상승 차단, 해피엔딩 조건은 유지한다.

따라서 앞 절의 절망 2 출발 계산과 별도 느린 회복 표는 과거 시안이다. 기존 회복과 방치 가중치를 합산하여 30일 방치 목표와 270일 내 달성 가능성을 다시 계산해야 한다. 기본 회복은 성격·태도·주인공 상태 등의 다른 기존 판정도 포함하므로 완성된 게임 검증으로 단정하지 않는다. 성장 보상량·태도 조정·각성 누적값 초기화 등 아직 미승인인 항목을 함께 확정한 것으로 해석하지 않는다.

- 보호 분기는 270일 관리 후 종료 평가한다. 이는 새 보호 분기의 기간 변경이며 원작 스펙터 의뢰의 240일 코드를 전역 변경하라는 뜻은 아니다. 원작 타이머가 새 분기를 241일째 실패시키지 않도록 분리해야 한다.
- 계산 시에는 영입 후 270일에 초기 3일·추가 7일을 포함하여 각성 후 약 260일이 남는 것으로 가정했다. 실제 일일 정산 순서와 시작 기준은 구현 전에 확인한다. 캐릭터 복제·각성 때 전체 기한을 새로 주지 않는다.
- 신체적 위해·성적 행위 등으로 이미 보호 실패한 상태는 아래 성공 엔딩 판정 대상이 아니다. 조건 미달의 정상 종료인 노멀엔딩과 보호 실패 루트를 구분한다.

| 엔딩 | 종료 시점의 조건 | 이야기 |
|---|---|---|

- 해피 조건은 종료 시점의 동시 충족 조건이다. 270일 내내 같은 수치를 유지해야 하는 조건으로 해석하지 않는다.

### 해피엔딩 목표 수치의 달성 가능성 · 정적 계산

각성 직후 누적값을 0으로 놓고, 다른 일일 증가·감소가 없다는 가정에서 필요한 양이다. 누적값 초기화는 아직 사용자에게 확정받지 않은 항목이다.

| 항목 | 각성 → 해피 목표 | 최소 필요한 누적 변화 |
|---|---|---:|
| 헌신 | 1 → 5 | +300 (20+40+80+160) |
| 습관 | 0 → 3 | +70 (10+20+40) |
| 사육 | 0 → 2 | +30 (10+20) |
| 절망 | 2 → 0 | -20 (각 등급 -10씩) |
| 두려움 | 3 → 2 | -20 |

- 수치 조합 자체에는 상호 배타 조건이 없다. 다만 기존 시스템 그대로는 안정적 달성 여부를 확정할 수 없다.
- 헌신은 순증가 +1/일이면 300일로, 각성 후 약 260일 안에 부족하다. 순증가 +2/일인 단순 모델에서는 150일, 습관 +1/유효일은 70일, 사육 +1/유효일은 30일이다. 이는 수치 후보의 산술 예시이며 보상량을 승인·구현한 것이 아니다. 매일 성장하는 것이 아니라면 실제 기간은 더 길다.
- 원본 태도 5에서는 일부 기존 외출의 헌신 상승 조건(태도 4 미만)이 막힌다. 비성적 생활 활동의 분기 전용 성장 보완 없이 목표가 가능하다고 보장하지 않는다.

- 원래 두려움 회복에는 헌신이 두려움보다 높고 기분이 좋으면 등급을 직접 낮추는 처리도 있다. 한 번의 활동으로 즉시 회복되지 않게 하려는 방향과 함께 검토한다.
