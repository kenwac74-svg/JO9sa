## 2. 전체 처리 순서

실행 중 AI가 새 대사를 쓰는 방식이 아니다. QSP에 저장된 완성 문장과 메타데이터를 조건에 따라 선택하고 연결한다.

```text
질문 선택
 → 기존 게임의 답변 성공/거절 및 말할 사실 선택
 → 실제 화자 확인
 → 성격 유형 + 말투 + 현재 관계 모드 + 표현 깊이 계산
 → 그 사실에 맞는 핵심·보충·사건 반응 후보 필터
 → 최근에 쓴 조각을 피하면서 후보 추첨
 → 반말이 활성화된 화자의 알려진 문장만 반말 교정본으로 조회
 → 이름·대상·색상·연결어를 붙이고 페이지 구성
 → 실제 표시를 확정한 대사의 선택 이력 기록
```

내용, 말투, 감정 깊이는 서로 다른 축이다. 반말로 고정해도 반항하는 인물이 갑자기 헌신적인 내용을 말하게 만들지 않는다. 조립기는 헌신·복종·성격·기분 수치를 맞춰 쓰지 않는다. 대화 행동 자체의 효과는 기존 게임 코드가 별도로 처리한다.

## 4. 성격9유형

입력은 현재 화자의 네 값이다.

```text
표현성 E = temper + sensitivity
자기주장 A = ego + pride

낮음: 3 이하 / 중간: 4~6 / 높음: 7 이상
```

| 자기주장 A \ 표현성 E | 낮음 | 중간 | 높음 |
|---|---|---|---|
| 낮음 | `doll` 무표정·수동적 | `meek` 순하고 소극적 | `fragile` 불안·감정 노출 |
| 중간 | `calm` 차분함 | `plain` 중간형 | `frank` 솔직한 감정 표현 |
| 높음 | `ice` 냉담함 | `proud` 자부심 | `flame` 강한 감정·기세 |

한글 설명은 코드 키의 이해를 돕는 요약이다. **성격 키 `plain`은 ‘반말’이라는 뜻이 아니다.** 말투는 다음의 별도 숫자다. 성격값이 바뀌면 유형은 다시 계산될 수 있지만, 지정8명의 반말 고정은 별도로 유지된다.

## 5. 현재 말투 선택 규칙

1. 기본은 말투2.
2. 기존 격식직업은 말투1.
3. 내부 값이-1이면 위 존댓말을 유지하고,1이면 말투3을 사용한다.
4. 내부 값이없거나0이면 지정8명만 말투3이다.

격식직업 목록과 기존 철자는 `maid, valertry, secretary, nun, policewoman, mind_contol, time_plice, jailer, academy, mech`이다. 이전11직업의 말투3 강제는 제거했다. 말투1/2는 존댓말 계열,3은 반말 계열이다. 성격유형 plain은 반말이란 뜻이 아니며 성격9종 계산은 그대로다.

프로필의7번째 인수는 실제 화자의 내부 말투 값이다. 상대를 평가할 때도 말하는 사람의 값으로 선택한다. 새로운 원고를 생성하거나 관계·헌신·사육·인식 수치를 수정하지 않는다.

관계는 현재 `psy_status`를 먼저 사용한다. 헌신이 높다는 이유만으로 적대·공포 모드를 덮어쓰지 않는다.

| 입력 상태 | 조립 모드 | 뜻 |
|---|---|---|
| `reluctant`, `arrogant`, `hateful`, `resistant`, `hysteric` | `hostile` | 반감·적대 |
| `lachrymose`, `frightened` | `fearful` | 두려움 |
| `depresive` | `bleak` | 우울·막막함 |
| `broken` | `broken` | 무너진 상태 |
| `optimistic` | `hopeful` | 기대와 유보 |
| `obedient`, `servile`, `horny`이며 moral<4 | `duty` | 의무·역할 중심 |

예를 들어 적대 상태에서 칭찬을 받았다면, 칭찬받은 사실은 말할 수 있어도 그 사건 하나만으로 감사·사랑을 표현하는 후보를 열지 않는다. 구체적으로 어떤 감정을 허용하는지는 각 원고 행의 관계 태그가 제한한다.

## 7. 감정을 드러내는 깊이

표현 깊이는0·1·2단계다. 말투1·2·3과 별개의 숫자다.

| 감정 분류 | 점수 계산 |
|---|---|
| 취약함 `vulnerable` | `2*moral - pride - 2*(fear>=4)` |
| 적대감 `hostile` | `ego + temper - 2*fear` |
| 긍정감 `positive` | `2*moral + sensitivity - pride` |

| 점수 | 허용 깊이 | 원고 분류상 의미 |
|---:|---:|---|
| 4 미만 | 0 | 감추거나 최소한으로 표현 |
| 4 이상8 미만 | 1 | 암시 |
| 8 이상 | 2 | 분명하게 드러냄 |

원고의 깊이가 허용 깊이보다 높으면 후보에서 빠진다. 공포·헌신 등을 실제로 증가시키는 계산이 아니라, 현재 상태에서 어느 정도 말할 수 있는지를 정하는 출력 계산이다.

## 8. 말할 사실의 선택

`$voice_impression`은 기존 배열에서 사실을 고른 다음 문장 변형을 고른다. 조립에 필요한 수치를 새로 만들어 사실을 바꾸지 않는다.

| 정보 | 선택 기준 |
|---|---|
| 관계 | 현재 `psy_status`에 대응하는 관계 설명 |
| 복종 단계 `obed` | obedience>0/10/20/30/40에서 각각1/2/3/4/5. 그 외0 |
| 낮은 복종의 예외 | stamina·intellect·pride·ego를 포함하는 기존 집안일 수용 식을 만족하면 복종 설명1을 사용 |
| 반항 | 복종 설명을 먼저 고른 뒤 `rebell[psy_status]>0`이면 이후 계산용 `obed=0` |
| 욕구 | `obed>0`이고 경험값 `sex_sum>0`일 때 `min(obed, arousal)` |
| 공포 | QSP 식 그대로 `max(fear ! 0, fear - moral/2)` |
| 합리화 | `min(obed + (daily_reward_count ! 0)*2, rational)` |
| 본능 | `min(obed+2, instinct)` |
| 생활 적응 | `min(obed+2, custom)` |
| 응석 | `obed>0`일 때 spoil |
| 헌신 | `obed>0`일 때 `min(obed, moral)` |

`broken` 상태에서는 관계·복종 설명 뒤의 위 추가 사실 선택을 생략한다. 여기서 `obed=0`으로 만드는 것은 임시 조립 변수 처리이며, 실제 obedience를0으로 쓰는 것이 아니다.

질문마다 같은 핵심 내용을 반복하지 않도록 배치도 나눈다.

| 핵심 내용 | 주된 질문 |
|---|---|
| 관계·복종·공포·합리화·본능·헌신 등 기본값 | 1112 인상 |
| 욕구 `urge_*` | 1113 요구 |
| 응석 `spoil_1` 이상 | 1113 요구 |
| 응석 `spoil_0` | 1112 인상 |

핵심은 지정 질문에서 고르고, 보충 문장도 별도의 질문 메타데이터 제한을 받는다. 이 분배는 해당 주제를 말할 사실 조건을 없애는 처리가 아니다.

## 9. 최근·오늘의 사건 반응

별도의 새 기억 DB를 쓰지 않는다. 기존 최근 행동 횟수와 오늘 보상·처벌 횟수를 읽는다. ‘최근’의 날짜 범위를 이 함수에서 새로 정하지 않는다.

| 기호 | 조건 |
|---|---|
| A | 최근 보상 또는 처벌 합계 중 하나가3 이상이고, 보상 합계가 처벌 합계보다 큼 |
| B | 위 문턱을 넘었고 보상이 처벌보다 크지 않음. 동률도 B |
| D | 오늘 보상 횟수가 오늘 처벌 횟수보다 큼 |
| C | 위 D가 아니면서 오늘 처벌이1회 이상. 동률이며 처벌이 있으면 C |

최근·오늘 양쪽 반응을 무조건 붙이지 않는다. 오늘 반응이 있으면 보통 오늘 반응을 쓴다. **최근 A+오늘 C**, **최근 B+오늘 D**처럼 방향이 반대인 경우에만 최근 반응 다음에 오늘 반응을 이어 붙인다.

사건 감정은 기본 긍정, B/C는 적대 계열에서 출발한다. 현재 모드가 적대이면 적대, 공포·우울이면 취약함으로 해석한다. 의무·헌신 모드에서 B/C를 말할 때도 취약함 깊이를 사용한다. 같은 사건이어도 관계에 따라 표현이 달라지는 이유다.

## 10. 문장 후보 필터와 추첨

현재 `#txt_man`에는 `$voice_fragment_text` 대사 행9,120개가 있고, 데이터 revision은8이다. 이 수는 한 인물이 한 질문에서 선택할 수 있는 후보 수가 아니다.

각 행은 문장 외에 의미 역할, 말투, 성격 유형, 관계, 감정, 깊이, 질문, 필요한 공포값, 좋은 기분 필요 여부 등의 메타데이터를 가진다. 다음 조건을 통과해야 후보가 된다.

1. 지금 필요한 의미 자리와 일치한다.
2. 질문 제한이 있는 호출이면 해당 질문과 일치한다.
3. 현재 말투 숫자와 일치한다.
4. 해당 성격 유형 또는 공통 유형(`*`)이다.
5. 현재 관계 모드를 허용한다.
6. 문장 깊이가 허용 깊이 이하이다.
7. 필요한 공포값을 만족한다.
8. 좋은 기분을 요구하는 문장은 mood>0이다.
9. 드문 칭찬 반응 표식이 있으면 조립기의 보상 합계가3 미만이어야 한다.
10. 본문이 비어 있지 않다. broken의 사건 반응에는 broken 허용 태그도 명시돼야 한다.

`mix`/`native` 방식에서는 성격 전용 후보를 먼저, 공통 후보를 나중에 찾는다. 허용 깊이 안의 후보를 모두 사용할 수 있다. 반면 도입·사건 등 기본 방식은 허용된 후보 중 가장 높은 깊이의 후보를 모은다. 모든 상황에서 가장 깊은 문장만 고르는 것은 아니다.

반복 회피와 전용/공통 우선순위는 아래 순서다.

| 시도 순서 | 반복 제한 | `mix`/`native` 후보 순서 |
|---:|---|---|
| 1 | 최근2회 모두 피함 | 전용 → 공통 |
| 2 | 직전1회만 피함 | 전용 → 공통 |
| 3 | 반복 허용 | 전용 → 공통 |

선택 가능한 풀에서 `rand`로 하나를 고른다. 다양성을 위해 관계·말투·공포 등의 조건을 완화하지 않는다. 후보가 없으면 원문 fallback을 반환하거나, 추가 문장은 생략한다. 후보가 하나뿐이면 반복될 수 있다.

## 11. 핵심·보충 문장과 인물 소개의 차이

일반 대사 `$voice_native`는 원래 게임이 선택한 의미 그룹과 원문을 받는다.

1. 그 그룹의 핵심 `core`를 고른다.
2. 핵심이 있으면 보충 `detail`을 고른다.
3. 과거 소개의 일반 그룹은 세계/가족/직업 범주별 반응 보충을 사용한다.
4. 핵심과 보충을 완성 문장 단위로 연결한다.
5. 나이별 호칭·용기 표현·상대 이름 등 등록된5개 플레이스홀더를 실제 화자 문맥으로 바꾼다.
6. 원문의 이름표·색상·포장을 복원한다. 핵심 후보가 없으면 원문을 유지한다.

세계·가족·직업 소개는 `$voice_native_stored`가 먼저 처리한다. 기존 영문→한국어 표시 조회와 지정 인물의 알려진 옛 소개문 조회를 거친다. 원래 저장 문자열이 일반 배경 사전의 정확한 한 항목과 일치할 때만 일반 소개를 재조립한다. 미등록·직접 편집·중복 일치 소개를 수치로 추측해 새 배경으로 바꾸지 않는다.

따라서 JSON 고유 소개문, 공용 조립 문장, 특성별 직접 작성 희망 대사는 편집 위치가 서로 다르다.

## 12. 반말 전용 문장 교정

`jo9_plain_voice(화자번호, 원문, 내부말투값)`은 최종 반말 활성 여부를 확인하고, 기존 완성문장과 정확히 일치할 때만 교정한다. 내부값을 생략하면0으로 기존 기본8명 정책을 따른다. 명시적으로 켠 다른 인물도 같은 표를 쓸 수 있고,8명이라도-1이면 원문을 반환한다.

기존 대응표와 문장 의미는 유지했다. 임의 어미 치환이나 알려지지 않은 사용자 문장 재작성은 하지 않는다. 속성을 끈다고 이미 작성된 고유 소개 원고 전체를 자동 존댓말로 다시 쓰지는 않는다. 고유 소개 호환 교정 역시 OFF일 때 새 반말을 강제하지 않는다.

`enabled` 모드는 활성 여부0/1을 반환하고 `cache` 모드는 알려진 옛 콜백 조각만 갱신한다. [상세](<G:/somi/JO9sa/docs/modding/CHARACTER_SPEECH_MODE_KO.md>)

## 13. 페이지 구성과 연결어

1112는 다음 세 묶음을 차례로 만든다.

| 묶음 | 내용 순서 |
|---|---|
| 1 | 관계 → 복종 → 최근 사건 → 오늘 사건 |
| 2 | 공포 → 벌·대가에 관한 응석0 → 본능 |
| 3 | 합리화 → 생활 적응 → 헌신 |

빈 항목은 생략한다. 도입은 broken에서 붙이지 않고, 핵심이 이미 등록된 동작 지문으로 시작하는 경우에도 중복을 피한다. 문장을 이어 붙일 때 등록된 선행 지문만 정리하며 모든 괄호 내용을 무조건 지우지 않는다.

연결어는 의미 조건으로 정한다. 두려움이 없는 상태에서 처벌의 대가를 인정하는 내용을 잇는 경우 “다만”, 두려움과 복종 본능을 함께 말하는 특정 경우 “그런데도”, 최근 보상과 오늘 처벌의 대비는 “하지만”, 반대 대비는 “그래도”를 사용한다.

HTML을 제외한 연결 후 길이가230자를 넘을 예정이고 현재 페이지에 이미 문장이 있으면 다음 페이지로 넘긴다. **문장 한가운데를230자에서 자르지 않는다.** 한 문장 자체가 긴 경우에는230자를 넘을 수 있다. 이 값은 화면의 픽셀 높이·글꼴·줄 수를 측정한 결과가 아니다.

각 페이지에 이름표를 한 번 붙여 기존 `$text` 배열에 넣는다. 다음/이전 페이지는 이미 확정한 배열을 읽으며 매번 재추첨하지 않는다.

## 14. 다른 노예·조수에 대한 평가

평가받는 인물이 아니라 **말하는 인물**의 직업·성격·관계·번호로 말투를 정한다. 일반 평가의 원래 의미·고유 관계 사연의 우선권을 유지한다.

`$voice_relation_line`과 `$voice_relation_continue`는 실제 앞선 의미 그룹·본문·말투를 읽어 연결을 정리한다. 외모·성격 같은 평가의 긍정/부정 전환에 “다만/그래도”를 붙일 수 있다. 현재 기분이나 문장의 단어만 보고 상대에 대한 관계 사실을 새로 추정하지 않는다. 일반 후보가 원래 고유 사연에 덮이는 경로는 표시·이력 처리에서 구별한다.

## 15. 이력·세이브·캐시

이력은 최근에 어떤 문장 조각을 골랐는지 기록하는 선택 서명이다. 모든 대화 전문이나 새로운 사건 연대기를 저장하는 기능은 아니다.

| 경로 | 이력 키 |
|---|---|
| 인상/요구/희망/기분의 조합 | `jo9_voice_last1_<질문번호>`, `jo9_voice_last2_<질문번호>` |
| 의미 그룹별 일반 원고 | `jo9_voice_last1_native_<group>`, `jo9_voice_last2_native_<group>` |

노예·조수의 원래 문자열 배열 안에 해당 화자 이력을 기록한다. 실제로 표시하지 않는 “요구 없음” 기본 답변이나 고유 사연에 가려지는 일반 평가를 불필요하게 이력에 남기지 않도록 일부 기록을 임시 보류한 뒤 확정한다. 거절도 실제 거절 분기에서 표시하는 문구의 이력과 일반 수락 조합을 구별한다.

1111~1118 진입 때 함수 마커와 `voice_fragment_revision=8`을 확인한다. 옛 캐시이면 현재 `#dynamic` 함수와 데이터 전용 진입점을 다시 읽는다. 기존 반말 프로필 마커는 유지하며 R05 내부 말투값과 R05a 자동 전환·정확 캐시 갱신을 추가했다. `$ongload`는 `gs 'jo9_plain_voice','cache'`와 `gs 'jo9_plain_voice','load'`를 실행한다. 기존 BGM 로드의 전체 `#dynamic` 재초기화는 유지했다. QSP 교체 후 실행 중인 프로세스가 자동으로 새 파일을 다시 읽는다는 뜻도 아니다.
