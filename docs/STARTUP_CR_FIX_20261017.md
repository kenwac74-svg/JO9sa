# 시작·세이브 불러오기 공백 화면 수정 — 2026-10-17

## 원인

천재·백치 패치 생성기가 기존 CRLF 문장을 다시 LF→CRLF 치환하면서 `$newloc_update_iced_features_list` 안에 `CRCRLF` 두 개를 만들었다. 이 템플릿은 `$newloc`의 보관 인물 18개 순회에서 인물 존재 여부 검사보다 먼저 실행되므로, 보관 인물이 전혀 없는 새 게임도 영향을 받는다. 기존 세이브도 같은 갱신 경로를 지나 오류가 발생한다.

교대 전투 직전 백업에도 같은 잘못된 줄바꿈이 있다. 사용자는 천재·백치 적용 후 실제 실행하지 않았다고 확인했다. 이번 교대 전투의 선택지/순차 교대와 별도로, 이전 표시 캐시 생성 과정에서 도입한 버그다.

## 수정 범위

- 최신 플레이 QSP의 `$newloc`에서 중복 CR 문자 **2개만 제거**했다.
- 기존 `jo9_learning_revision` 문턱과 적용값을 1에서 **2**로 올려 저장된 표시 템플릿도 한 번 다시 정의한다. 기존 캐시 갱신 코드를 그대로 재사용한다.
- 코드의 나머지 조건·수치, 교대 전투, 트레잇 효과, 인물·세이브 파일을 수정하지 않는다. 전체 QSP는 정확히 4바이트 작아졌다.
- 원래 `COG_CACHE` 및 `COG_ICED_DISPLAY` 주석 구간 안의 수정이며, 별도 정확한 old/new 패치 기록을 남겼다.

## 재현·검증

QSP Foundation의 공식 배포 구버전 코어 `qsp.dll` 5.7.0을 별도 작업 폴더에서 화면 없이 호출했다. 플레이 클라이언트를 실행하거나 교체하지 않았다.

| 검사 | 잘못된 원문 | 수정본 |
|---|---|---|
| 실제 표시 템플릿 정의 및 실행 | 오류 119: Unknown action | 오류 0 |
| 실제 `$do_for_each_slave_in_list` + `$iced_slave_characters` 순회 | 오류 119 | 오류 0 |

모든 다른 로케이션 원문 일치, QSP 왕복 바이트 검증, 수정량 4바이트 확인. 기존 교대 전투 제어 흐름 100개 검사도 통과했다. 패치 도구로 재적용한 사본과 후보의 바이트 일치를 확인한다.

앞선 제한 실행기는 줄 단위 `.trim()`을 사용하여 잘못된 CR을 제거해 버렸고, 시작·불러오기를 실제 코어에서 실행하지 않아 이 결함을 놓쳤다. 이번 회귀 검사는 실제 원문 줄바꿈을 유지한 채 네이티브 코어에서 검사한다.

한계: 배포 코어의 사용자 정의 FOR·PLAY 확장이 공식 코어와 달라 게임 전체를 네이티브 검사기로 실행했다고 주장하지 않는다. 실패한 실제 템플릿과 순회 구간은 원문 그대로 실행해 전후 차이를 확인했다. 실제 클라이언트에서 기존 세이브 불러오기와 새 게임 시작은 사용자의 재확인이 필요하다.

## 사용 방법

플레이 클라이언트를 완전히 종료했다가 다시 실행하고 기존 세이브를 불러온다. 처음 불러오면 캐시 버전 2로 한 번 갱신한다. 기존 세이브 자체를 삭제하거나 새로 만들 필요는 없다.

배포 폴더와 순정 원본, 세이브 파일은 변경하지 않는다. 커밋·푸시는 수행하지 않는다.
