# 속성정보 안내와 노예 편집기 수정 — 2026-10-17

대상은 현재 저장된 플레이 폴더의 `game/jack.qsp`, `game/css/base.css`다. 배포 폴더와 보호 원본에는 적용하지 않는다. QSP는 255개 로케이션을 유지하며 `menu_form`, `#help_msg`만 변경한다. 수정 전후 SHA-256은 `review.json`, 설치 결과와 백업은 `installed.json`에 기록한다.

## 속성정보 물음표

`slave_stat`, `assistant_stat`, `teach_screen`의 속성정보 물음표가 `$rank_help` 다음 `$rank_help_2`를 띄운다. 이번 수정은 두 번째 안내창의 제목과 정렬을 바로잡는다. 직전 수정에서 기술 등급표로 잘못 바꾼 내용을 정정하여 원래 안내의 점수 0~5, 단계 최하~최상, 등급 F/D/C/B/A/S를 세 열에 배치한다. 제목 옆의 종합등급 F-~S+는 별도 설명으로 표시한다. 실제 등급값·교육 경험치·승급 계산은 바뀌지 않는다.

변경 표시: `#help_msg`의 `ATTRIBUTE_RANK_HELP`. 이 정의를 제거하면 안내 문자열이 정의되지 않으므로 삭제할 때는 이전 정의를 복원해야 한다. 기존 호출부는 그대로다. 같은 안내 문자열을 쓰던 `master_stat` 링크에도 정돈된 표가 표시된다.

## 편집기 여섯 페이지

`menu_form=2101~2106`에서만 네 출력 문자열에 배치용 래퍼를 추가한다. 두 열은 `jo9-slave-editor`, 하단 이동 버튼은 `jo9-editor-nav` 클래스다. 기존 링크, 항목별 상한·하한, 순서, 페이지 이동값은 유지한다.

`base.css`의 `SLAVE_EDITOR_LAYOUT` 블록에서 각 행 높이/줄높이 40px, 글자 18px, 좌측 여백 16px로 정렬한다. 오른쪽 끝으로부터 − 78px, + 46px, S 10px에 그림 버튼을 고정한다. 기존 인라인 링크의 상대 좌표를 이 편집기 안에서만 해제하여 버튼이 행을 기준으로 배치된다. 배경 PNG의 투명 여백을 감안하여 프레임 그림의 크기를 맞추고, 전체 행 클릭 영역도 실제 행 상단과 맞춘다. CSS에는 문구 생성이나 게임 상태 판정이 없다.

변경 표시: `menu_form`의 `SLAVE_EDITOR_LAYOUT`, CSS의 동일 표시. QSP 래퍼와 CSS는 함께 사용한다. CSS만 제거하면 정렬 개선이 사라지며 게임 값 계산에는 영향을 주지 않는다. 래퍼만 제거해도 다른 편집 동작은 유지되지만 이 CSS가 적용되지 않는다. 원래 편집기 코드 전체를 삭제할 필요가 없다.

## 명기 감소 버튼

기존 버튼은 `slave['virginity']`만 4에서 3으로 낮췄다. `slave['jo9_meiki_known']=1`이 남아 있으므로 화면 갱신에서 `jo9_meiki_state`가 다시 4로 복원했다.

`EDITOR_MEIKI_DECREASE` 블록은 현재 값이 4일 때의 감소 링크에서 `jo9_meiki_known=0`도 함께 저장한다. 그 외 값의 감소 링크는 기존과 같다. 새 함수를 추가하지 않는다. `jo9_meiki_state`, `jo9_meiki_checks`, 기존 발견·효과 판정 조건은 수정하지 않는다.

입력은 편집 대상 노예의 현재 상태값과 발견 기록이다. 클릭 결과는 상태 4→3과 발견 기록 1→0이다. 기존 기술값, 초기화 기록, 과거 발견 판정 완료 기록은 초기화하지 않는다. 따라서 과거에 올라간 기술값까지 되돌리는 기능은 아니다. 기존 + 버튼의 상한 3도 유지한다.

이 블록을 수정 전 링크로 복구하면 재복원 버그가 돌아온다. `if/elseif/end` 일부만 삭제하면 문법 문제가 생길 수 있으므로 이 변경 단위 전체를 이전 한 줄로 복원해야 한다. 기능과 관계없는 다른 제한 코드는 건드릴 필요가 없다.

## 확인 범위

- QSP 읽기/쓰기 바이트 왕복 일치, 선언형 패치 도구 적용본과 후보 바이트 일치, 수정 세 조각의 역치환으로 원본 완전 복원.
- 명기 버튼의 실제 대입문과 기존 상태 함수를 QSP 5.7.0 엔진에서 실행: 수정 전 값 4/기록 1로 복원되는 현상 재현, 수정 후 상태 갱신 두 번을 거쳐도 값 3/기록 0 유지.
- 속성정보 안내 문자열 정의를 같은 엔진에서 실행, 오류 없음.
- 편집기 여섯 페이지의 실제 본문과 배치 래퍼를 QSP 5.7.0 엔진에서 실행하여 HTML을 얻었다. 검사 하네스에서만 화면 전체 재계산 호출을 제외하고 원래 폰트·표시 배열을 초기화했다. 여섯 페이지 모두 오류 0이다.
- 얻은 HTML과 후보 CSS를 Headless Edge에서 렌더링하여 모든 버튼 그림의 로딩·고정 좌표·클릭 영역과 40px 행높이를 검사했다. 최대 16행이 하단 이동 버튼과 겹치지 않으며 안내문도 확인 버튼 위에 끝난다. 실제 게임 클라이언트의 화면 및 저장 후 재실행 검사는 사용자가 한다.
- 플레이 QSP/CSS와 저장소 CSS 원천·매니페스트를 갱신한다. 매니페스트의 과거 대상 적용 이력은 유지하고 이번 플레이 한정 갱신을 추가 기록한다. 배포 폴더는 변경하지 않는다.

재시작 후 속성정보 물음표→확인을 눌러 표를 확인하고, 노예 편집기의 글자/버튼 및 명기 상태에서 −를 누른 뒤 페이지를 나갔다 돌아왔을 때 상태가 유지되는지 확인한다. 게임에서 기존 QSP를 이미 읽은 상태라면 파일 교체만으로 실행 중인 정의가 갱신되지는 않는다.
