## 3. 사용자 확정 정책: 이미지 교체 백업 없음

사용자가 직접 선택하고 원해서 교체하는 이미지에는 불필요한 백업 절차를 두지 않는다.

- 교체 전 이미지의 백업본을 생성하거나 보관하지 않는다.
- 이미지별 자동 백업, 교체 이력용 원본 이미지 사본, 이미지 복원용 ZIP, 이미지 되돌리기 기능을 필수 절차나 요구사항으로 두지 않는다. 선택형 백업 기능을 임의로 추가하지도 않는다.
- 기존 원본 교체 모드는 사용자가 선택한 대상 이미지 파일을 교체하는 방식이다. 이미지 백업 실패 때문에 교체를 막는 절차를 설계하지 않는다.
- 입력 이미지·대상 경로·쓰기 권한 등의 기본 검증은 백업과 별개다. 백업을 없앤다는 이유로 대상 확인이나 오류 처리를 없애지 않는다.
- 완성된 이미지의 PNG/ZIP 내보내기는 결과물 저장이며, 교체 전 원본의 백업과 구분한다.
- 이번 정책 기록만으로 기존 백업 파일을 일괄 삭제하지 않는다. 기존 파일의 정리나 프로그램 코드 변경은 이번 작업에 포함하지 않는다.

## 4. 유일한 백업 지원 범위: 설치·삭제

- 도구/패치의 설치와 삭제 시 원상복구에 필요한 설치 대상 파일의 백업만 지원한다.
- 기존 설치·삭제·설치 원상복구 체계는 유지한다. 설치 이전 실행 파일 등 설치 변경분의 보존은 이미지 교체 백업과 구분한다.
- 설치용 백업에 사용자가 교체한 이미지 전체를 포함하거나, 삭제 시 사용자 이미지 변경까지 되돌리는 기능으로 범위를 확장하지 않는다.
- 다음 업데이트의 QSP 패치에도 복구가 필요하다면 설치·삭제 변경분이라는 범위에서 사전 설계한다. 이를 이유로 이미지별 백업을 재도입하지 않는다. 구체적인 QSP 적용·제거 방식은 아직 미구현이다.

## 5. 현재 도구에서 유지할 UX

- 게임의 Show HTML을 이용한 현재 화면 이미지 자동감지 → 대상 선택 → 새 이미지 편집·조절 → 적용 흐름을 유지한다.
- PIC 폴더 등록 영역을 이미지 목록보다 위에 배치한 수정 HTML을 사용한다.
- 이미 구현된 자동감지를 없는 기능처럼 취급하지 않는다. 사용자에게 이미지 파일명 검색이나 HTML 수동 복사를 정상 사용 절차로 다시 요구하지 않는다.
- 기존 이미지 교체·편집·결과물 출력과 설치·삭제 기능을 구분해서 유지한다. 이미지 백업/복구는 유지 대상에서 제외한다.

현재 배포본에 남아 있을 수 있는 이미지 백업 호출·필수 의존성·버튼·안내·복구 루틴은 실제 코드 변경 시 이 정책과 대조할 항목이다. 이번 문서 변경은 그러한 코드 제거가 완료되었다는 뜻이 아니다.

## 6. 다음 업데이트: 이벤트 컷신 전용 이미지 및 연결 경로 변경

**상태: 개발 전 단계. 이번에는 요구사항과 확인 항목만 기록한다. 구현·게임 적용·배포를 시작하지 않는다.**

이 기능은 기존 이미지 파일 교체와 별개로, 선택한 이벤트 컷신이 다른 이미지 경로를 사용하도록 실행용 QSP를 수정하는 업데이트다.

- 기존 Show HTML 자동감지와 이미지 편집 UX를 재사용한다. 추가하는 핵심은 이미지 감지가 아니라 이벤트 한정 적용 방식이다.
- 새 이미지를 별도 경로에 저장하고, 선택한 이벤트/장면의 연결만 변경한다. 같은 공용 이미지를 사용하는 다른 이벤트는 바꾸지 않는다.
- 저장 설계는 `content/pic_SNmod/events/<override-id>/<원본 pic 아래 상대경로>`로 두고 도구가 경로를 관리한다. 현재 구현되었다는 뜻은 아니다.
- 이 모드에서 기존 공용 이미지가 남는 것은 원래 게임 리소스를 계속 사용하는 것이지, 교체 이미지의 백업본을 만드는 것이 아니다.
- HTML 미리보기의 경로만 바뀌거나 `.qsrc` 수정본만 생성된 상태를 게임 적용 완료라고 표시하지 않는다. 실행용 QSP 반영과 실제 이벤트 재진입 검증을 별도로 구분한다.

### 첫 대상: 부동산 NPC

사용자 설명 기준으로 부동산 상점은 한 곳이며 NPC는 그 상점에만 등장한다. 구매 완료 분기에서 해당 컷신이 발생할 때는 같은 장면을 사용한다. 이는 노예가 아니라 고정 NPC이므로 `slave id`를 요구하거나 노예 데이터 등록을 전제하지 않는다.

대상은 부동산 구매 완료 이벤트의 해당 컷신으로 잡되, 실제 소스에서 호출 범위와 분기를 확인하기 전까지 특정 코드가 이 NPC 전용이라고 단정하지 않는다. Show HTML로 감지한 이미지 경로만으로 이벤트 ID나 QSP 조건문을 모두 알 수 있다고 가정하지 않는다.
