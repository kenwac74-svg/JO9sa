# 개인실의 구 외형 표시 누락 수정 — 2026-10-19

사용자 보고: 새 인디팩으로 교체한 이사벨라 등도 개인실에 가면 옛 전신 이미지가 표시된다. 현재 work QSP와 설치 JSON·이미지·저장 데이터의 외형 필드만 대조해 확인했다. 이번 적용은 work QSP만 대상으로 하며, 배포 동기화·커밋·푸시는 다음 2.4 업데이트 마무리에 진행한다.

## 원인과 수정

- 이전 인디팩 통합은 새 이미지와 indpack_* 등록을 갱신했지만, 개인실에 남아 있던 fullimage 직접 표시 경로를 바꾸지 못했다. 일반 화면은 인물 ID·복장·감정에 따른 indpack 이미지를 선택하는 반면, 개인실은 저장된 옛 기본 이미지 문자열을 직접 표시했다.
- 특히 조수 개인실도 이 경로였다. 조사한 최근 저장 4개에는 조수 ID 2571과 옛 이사벨라 fullimage가 남아 있었다. 해당 옛 파일은 보존한 구 랜덤 이사벨라 2323의 제목 이미지와 같은 바이트이며, 새 2571 팩과는 다르다. 숫자 경로의 얼굴 파일들은 최신 설치 명세와 일치했다.
- 개인실 1~4, 개인실 행동 메뉴, 조수 개인실, 조수 관련 메뉴 3곳, 감방·외양간, 조수 대화 화면의 12개 직접 표시를 공용 display_fullimage에 연결했다. 감방의 특수 비만 장면 등 원래 분기는 유지한다.
- 공용 선택 함수가 room1~room4를 포함한 호출 인물 자신의 ID·복장·충성/흥분 값과 기본 경로를 읽도록 보완했다. 조수의 image_mode 1/2/3, 외양간의 전용 복장, 판매 전시의 제목 이미지 선택도 유지한다. 호출마다 복장 키를 초기화해 앞 인물의 선택이 다음 인물에게 남지 않게 했다.
- 지원하지 않는 복장일 때는 해당 인물의 등록된 indpack_title을 사용한다. 인디팩이 없는 인물은 자신의 원래 fullimage를 사용한다. 등록된 복장 그림이 없을 때의 기존 기본 이미지 대체도 유지한다.
- ID 선택 미리보기·암시장 명단·동면관의 3개 경로는 현재 활성 노예와 섞지 않고 각자 표시하는 ID의 indpack_title을 우선한다. 등록이 없으면 기존 경로를 쓴다. 동면관의 의식/생사 상태에 따른 원래 표시 조건은 유지한다. 원시 DB 값을 확인하는 slavebase_test는 그대로 둔다.
- 기존 div ID, top:3px/left:150px 인라인 위치와 기존 이미지 전환 처리 경로는 유지한다.

기존 이미지 파일을 덮어쓰거나 지우지 않는다. JSON, 인물의 이름·능력치·배경, fullimage/얼굴/신체 문자열, 원본 세이브도 수정하지 않는다. 구 이사벨라 2323은 자기 ID의 구 외형을 계속 사용한다.

## 코드 입출력과 의존성

패치: mods/2026-10-19_room_appearance_routing.json. 본문 14개 로케이션에 선언한 치환 16개를 적용한다. 새 로케이션·함수·저장 변수·리비전 플래그는 추가하지 않는다. 앞서 적용한 지역별 개인실 상한 로케이션과 그 밖의 QSP 필드는 보존한다.

- display_fullimage: 입력은 원래 인물 슬롯 이름($args[0])과 div ID($args[1]), 현재 슬롯의 *_state/*_type, cloth/fullimage, moral/arousal 및 조수 image_mode. 반환 $result는 선택한 경로의 img를 포함한 HTML이다. 기존 임시 선택 변수는 갱신하지만 인물 슬롯이나 저장 파일을 재작성하지 않는다. 일반 인물의 비활동 상태 출력 조건도 기존 함수 그대로다. 안정 표식 ROOM_IMAGE_ACTOR_RESOLVER.
- 각 일반 화면: 기존 fullimage 직접 img 대신 공용 함수 결과를 같은 div/위치에 표시한다. 기존 이미지 전환 wrapper가 있던 곳은 그대로 유지한다. 안정 표식 ROOM_IMAGE_LINK_0~14. 번호와 로케이션의 정확한 대응은 패치 JSON과 원인 조사 목록을 따른다.
- 동면관/정적 ID 미리보기: 자기 dynslave_type/s_type/args[1]의 등록 제목 경로가 있으면 이를 선택하고, 없으면 원래 표시 경로를 사용한다. 일반 노예 슬롯으로 바꿔치기하지 않는다.
- 입력 이미지와 indpack 등록은 설치된 game/json 및 game/content/pic에 의존한다. 기본 이미지 문자열을 지우는 이행 작업은 하지 않는다.

호출부만 되돌리면 해당 화면에서 다시 옛 기본 외형을 쓴다. 공용 함수의 보완만 되돌리면 room1~room4는 ID와 기본 경로를 제대로 읽지 못할 수 있다. 해당 부분은 같은 패치로 보관한다. 다른 이미지·JSON·구 인물 파일을 삭제해 문제를 가리는 방식으로 복원하지 않는다.
