# 1112 대사 페이지 복구 — 2026-10-17

원인: 앞선 재조립에서 답변 전체를 `$text[1]` 하나에 넣었다. 기존 `interaction_screen`은 `$text[txt]` 하나만 표시하고 `$objsel`이 배열 인덱스를 넘기므로, 답변 전체가 같은 화면에 몰려 아래쪽이 잘렸다. 내용 재조립과 한 화면 표시를 잘못 결합한 회귀였다.

## 수정

패치 `2026-10-17_zzzzzzzzzzzzz_voice_pages`, `interaction`의1112 호출부 한 치환이다. `VOICE_COMPOSE_PAGES` 표식 안에 분할 코드를 두었다. 새 함수·로케이션·인물 이력 키는 없다. `#dynamic`, 원문/추가 대사 배열, 관계별 사건 해석과 기존 반복 선택기는 수정하지 않았다.

입력은 위에서 이미 한 번 선택한 `$jo9_voice_impression_line`과 `$slave_name`이다. 출력은 기존 `$text[1..n]` 페이지 배열이다. 이전 페이지 배열을 비우고 이름표를 각 페이지에 한 번만 붙인다. 현재 화면의 `txt` 인덱스와 기존 다음/이전/종료 처리는 그대로 사용한다. 페이지를 넘길 때 답변을 다시 선택하거나 최근ID를 새로 기록하지 않는다.

- 이름표/HTML 포장을 제외한 본문을 페이지당110자 이하로 나눈다.
- 문단 경계는 새 페이지로 넘긴다. 충분히 찬 페이지는 문장 끝에서 끊고, 공간이 부족하면 단어 경계에서 나눈다.
- 띄어쓰기가 없는110자 초과 조각은 길이로 나눈다. 원래 문장의 단어·순서를 지우지 않는다. 표시용 공백/문단 경계는 페이지 경계에 맞춰 정리한다.
- 글자색의 font 포장은 페이지마다 열고 닫아 다음 페이지에 잘못 이어지지 않게 한다.
- 분할 작업용 `jo9_vp_*` 변수8개는 끝에 지운다. 빈 입력은 빈 이름표 한 페이지가 되지만 실제 조립기는 기존 답변 본문을 반환한다.

이 코드는 이미 선택된1112 답변의 알려진 HTML 형식을 대상으로 한다. 모든 게임 대사·임의 HTML에 대한 공용 페이지 편집기는 아니다. CSS, 글자 크기, 화면 높이와 스크롤 설정은 바꾸지 않는다.

## 분리/복원과 기존 세이브

분할 구간을 그냥 지우면 `$text` 페이지를 만드는 코드가 없어지므로 안 된다. 되돌릴 때는 이번 한 치환을 원래 두 줄로 정확히 역치환한다. 그러면 직전 파일과 바이트가 같아짐을 확인했다. 다만 직전의 한 화면 몰림도 되돌아온다. 이번 분할은 원문/추가 대사 내용이나 상태 수치를 삭제·변경하는 코드가 아니다.

세이브는 수정하지 않았다. 게임을 완전히 재실행하고 세이브를 불러온 뒤 인상 묻기를 다시 실행한다. 세이브에 저장된 옛 긴 대사 화면 자체를 자동 변환하지 않는다. 새 질문부터 현재 호출부가 페이지를 만든다.
