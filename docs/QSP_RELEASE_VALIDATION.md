# QSP 출고 전 자동 검사

2026-10-17 사용자 요청으로 추가했다. 이번 빈 화면 회귀처럼 파일로 확인할 수 있는 오류를 먼저 막고, 실제 FastQSP 엔진의 주요 실행 경로까지 확인한다. 게임 전체에 버그가 없다는 인증은 아니다.

## 실행 담당

사용자 추가 지시: 아래 절차는 에이전트가 내부의 격리된 진단 복사본에서 실행한다. 사용자에게 검사 도구를 열거나 실행하도록 요구하지 않는다. 상세 결과는 내부 기록으로 보관하고, 사용자에게는 출고 결과와 실패·미검증 항목만 짧게 알린다. 도구나 보고서를 사이드바에 자동으로 띄우지 않는다.

## 한 번에 실행

저장소 루트에서 Node.js로 실행한다. 경로는 그때의 최신 플레이 파일과 **이번 작업 직전 백업**으로 지정한다. `--mods-dir`에는 그 백업에서 후보까지 적용할 패치만 모은다. 과거 전체 `mods/`를 무조건 지정하지 않는다. 이후 수동 편집 때문에 오래된 기록 전체가 현재 파일에서 재생되지 않을 수 있다.

```powershell
node tools/qa/release-check.cjs `
  --candidate 'G:/somi/Jack O Nine Tails v2.4_work/game/jack.qsp' `
  --baseline '<이번 작업 직전 jack.qsp 백업>' `
  --mods-dir '<이번 작업 패치만 들어 있는 폴더>' `
  --engine 'G:/somi/Jack O Nine Tails v2.4_work/game/engine/jack.exe' `
  --game-dir 'G:/somi/Jack O Nine Tails v2.4_work/game' `
  --state-save '<노예와 조수가 모두 있는 대표 세이브.sav>' `
  --cache-revision 2 `
  --mirror 'G:/somi/Jack O Nine Tails v2.4 Kor_Full/game/jack.qsp' `
  --out '<게임 폴더 밖의 검사 결과 폴더>'
```

`--cache-revision`은 현재 `$newloc`의 `jo9_traits_revision` 목표값이다. 2026-10-17 수정본은 2다. 향후 이 캐시 규약이나 편집기 페이지가 바뀌면 검사 시나리오도 함께 갱신한다. 주인공 직업·모든 캐릭터 조합을 검사하는 설정은 아니다.

배포 폴더를 아직 갱신하지 않는 플레이 단계에는 `--mirror`를 생략할 수 있다. 그러면 보고서에도 배포 사본 미검사로 표시된다. 배포할 때는 실제 배포 QSP를 반드시 지정한다. 실행 자체가 적용·배포·커밋을 수행하지는 않는다.

결과 폴더 아래 매번 새 `run-*` 폴더를 만든다. 콘솔 마지막 줄에 `report.json` 경로가 나온다. 같은 위치에 사람이 읽을 `report.md`도 만든다.

| 결과 | 의미 | 종료 코드 |
|---|---|---|
| PASS | 지정된 출고 검사 전부 통과 | 0 |
| FAIL | 하나 이상 실패. 후보 출고 중단 | 1 |
| INCOMPLETE | 필수 입력이나 검사가 빠짐. 후보 출고 중단 | 2 |
| STATIC_PASS | 명시적으로 정적 검사만 실행. 출고 승인용이 아님 | 0 |

PowerShell에서 다른 명령과 묶을 때는 `$LASTEXITCODE`와 보고서의 `verdict`를 확인한다. `STATIC_PASS`를 출고용 `PASS`로 취급하지 않는다. `--profile`을 생략하면 출고 검사인 `release`다.

## 검사하는 것

1. **파일 구조:** UTF-16 QSP를 끝까지 읽을 수 있는지, 바이트 왕복이 같은지, 로케이션 이름이 중복되는지 검사한다. 본문과 로케이션 기본 행동의 실행 코드에 CRLF가 아닌 단독 CR/LF가 있으면 실패한다. 줄바꿈을 임의 수정하지 않는다.
2. **패치 재생:** 첫 패치의 적용 전 해시와 마지막 패치의 적용 후 해시를 실제 입력과 비교한다. 임시 백업 복사본에 기존 `tools/apply_mods.ps1`을 실행해 후보와 바이트 단위로 같아지는지 확인한다. 한 번 더 적용해 바뀌지 않아야 한다. 빈 검색 문자열 등 위험한 패치 형식도 거부한다.
3. **설치 엔진 실행:** 실제 설치된 `jack.exe`를 사용한다. 진단용 QSP의 `Start`만 검사 진입점으로 바꾸고, 후보의 원래 로케이션 실행 끝에 고유 완료 메시지를 붙인다. 단순히 프로세스가 살아 있는 것으로 통과시키지 않는다. 완료 메시지 전에 다른 메시지·엔진 종료·12초 제한 초과가 발생하면 실패한다.
4. **아홉 실행 경로:** `menu_form → main_screen` 홈 진입, `init_game → start_game` 새 게임 초기화, 편집기 2107의 노예/조수 두 역할, 이전 캐시 버전에서 두 코드 정의 플래그 초기화, `next_day → end_day_screen` 하루 진행을 확인한다. 무기점·미용실의 실제 NPC 대화 화면과 전투 메뉴 초기화 호출도 검사한다. 전투 승패·밸런스 검사는 별도다.
5. **배포 사본/입력 보존:** 지정한 배포 사본은 후보와 바이트가 같아야 한다. 검사 전후 후보·백업·배포 QSP·입력 세이브의 SHA-256을 대조한다.

## 기존 패치 적용기의 쓰기 전 방어

`tools/apply_mods.ps1`에도 완성된 각 로케이션 본문/기본 행동의 줄바꿈 검사와 이름 중복 거부를 추가했다. 모든 조각을 합친 **최종 코드**를 검사하며, 단독 CR/LF가 있으면 QSP와 백업을 쓰기 전에 중단한다. `-DryRun`과 재적용에도 동일하게 적용된다. 자동 정규화로 원문을 바꾸지는 않는다.

기존 파일에 잘못된 줄바꿈이 있다면, 그 부분까지 고치는 검토된 패치를 함께 적용해야 최종 검사를 통과한다. 이 검사는 실제 엔진 실행을 대신하지 않는다.

## 파일과 부작용

| 파일 | 역할과 의존성 |
|---|---|
| `tools/qa/release-check.cjs` | 검사 총괄. Node.js, 기존 QSP 코덱·줄바꿈 검사기·세이브 코덱·패치 적용기를 사용한다. |
| `tools/qa/run-client-smoke.ps1` | Windows PowerShell 5.1에서 진단 프로세스를 숨김 실행하고 완료 로그를 읽는다. 자신이 실행한 PID만 종료한다. |
| `tools/qa/release-check.test.cjs` | 손상 파일·중복 이름·패치 오류·누락 입력 판정·복사본 생성과 쓰기 전 차단 테스트. |
| `tools/qa/save-codec.cjs` | 기존 5.7.0 세이브 읽기/왕복 코덱. 고정 G: 경로 의존성을 상대 경로로 변경했다. |

입력 QSP/세이브는 수정하지 않는다. 출력은 게임 폴더 밖으로 제한하고 기존 심볼릭 링크/정션 경로도 해석해 확인한다. 진단 폴더에는 게임 JSON과 설정의 복사본, 자동 저장을 끈 진단 QSP, 패치 재생본, 로그가 생긴다. 기존 게임 창과 세이브를 덮어쓰지 않는다.

진단 QSP에는 대표 세이브에서 가져온 값이 포함된다. **`run-*` 전체나 진단 QSP·JSON·세이브를 Git에 넣거나 배포하지 않는다.** 공개 기록에는 상태 원문이 없는 보고서만 선별한다. 도구는 출력물을 자동 삭제하지 않는다.

삭제/분리할 경우 검사 도구만 없어지고 게임 실행 코드는 바뀌지 않는다. `run-client-smoke.ps1`을 빼거나 의존 파일/엔진/JSON을 찾지 못하면 출고 검사는 실패/미완료로 끝난다. 적용기의 방어를 제거하면 잘못된 줄바꿈을 저장 단계에서 차단하는 기능도 없어진다.

## 확인 범위의 한계

- 대표 세이브의 숫자와 짧은 문자열을 가져와 게임 상태를 구성한다. 긴 코드 캐시·콜백·치환식 문자열은 가져오지 않고 `refresh_database`로 현재 정의를 읽는다. **실제 세이브 불러오기 버튼, CRC 호환, 저장된 모든 스크립트 복원은 검증하지 않는다.**
- 새 게임 테스트는 대표 상태에서 초기화 로케이션을 호출한다. 캐릭터 선택 화면을 조작하거나 모든 생성 조합을 검사하지 않는다.
- 실행 코드를 건드리는 계측은 진단 복사본에만 있다. 그림·글자 배치·이미지 누락과 실제 플레이 결과는 수동 확인이 필요하다.
- QSP의 동적 코드와 모든 문법을 판정하는 정식 컴파일러는 아니다. 단순 정규식 `if/end` 개수를 근거로 문법 통과를 선언하지 않는다. 기능별 경계값·전투·가격 등은 해당 기능 테스트를 별도로 수행해야 한다.

빠른 정적 점검은 아래처럼 실행한다. 이는 실제 엔진 검사 없이 파일 구조만 확인한 결과다.

```powershell
node tools/qa/release-check.cjs --candidate '<jack.qsp>' --profile static --out '<결과 폴더>'
```
