# 인물 편집기 원본 연결 오류 수정

증상: 서버와 페이지는 열리지만 `상태 툴팁: 연결 누락 또는 여러 연결이 있습니다 (0).` 오류로 원본·입력 항목을 불러오지 못했다.

## 원인과 수정

1. 편집기는 상태표를 조건 1행·HTML 1행씩 고정해서 읽었다. 현재 QSP의 정상 `JO9 MOD START/END` 주석을 HTML로 읽고 실패했다. 전체 행 주석과 빈 행을 건너뛰되, 실제 파일의 문자 위치와 행 번호를 보존하도록 수정했다. 실행문은 건너뛰지 않는다.
2. 교육 XP는 예전 직접 누적 형식만 지원했다. 천재·백치 성장 보정이 통합된 현재 `jo9_learning_gain += 수치` 형식도 읽도록 추가했다. 기존 조건과 계산 순서는 그대로 두고 해당 숫자만 편집 대상으로 연결한다. 두 형식이 중복되거나 연결이 모호하면 계속 오류로 처리한다.

변경 파일은 `tools/state-editor/registry.cjs`와 새 회귀 검사 `registry-comments.test.cjs`다. 플레이 설치본의 같은 도구 파일도 맞춘다. 게임 QSP·CSS·세이브·배포 폴더는 변경하지 않는다.

표식: `STATE_EDITOR_UI_COMMENT_SCAN`, `STATE_EDITOR_LEARNING_XP`.

## 입력·출력과 편집 영향

입력은 현재 QSP 바이트다. 출력은 편집 가능한 값과 각 값의 정확한 소스 위치다. 새 게임 변수·로케이션·상태·조건을 추가하지 않는다. 미리보기와 적용의 기존 해시 검사·백업·복원 동작은 유지한다.

이 수정 부분을 제거하면 주석이 없는 예전 배치 및 예전 교육 누적 형식만 읽을 수 있다. 현재 QSP에서는 다시 로딩 오류가 발생한다. 게임 실행 자체는 이 편집기 모듈에 의존하지 않는다.

## 검증

- 수정 전 같은 주석·빈 행으로 실제 오류를 재현했다.
- LF/CRLF에서 툴팁 읽기·원본 행 번호·값 편집·정확한 역적용을 확인했다.
- 조건과 HTML 사이의 알 수 없는 실행문을 무시하지 않는 것도 확인했다.
- 새 교육 보정 형식의 숫자만 바뀌고 나머지 계산은 보존되는지 확인했다.
- 전체 57개 테스트 통과. 실제 플레이·배포 QSP를 읽은 메모리 후보도 원본 바이트로 역적용되며 실제 게임 파일은 바꾸지 않았다.

서버는 기존 `http://127.0.0.1:5284/`와 기존 작업 기록 폴더를 유지해서 재시작한다. 설치 백업·해시는 같은 작업 폴더의 `installed.json`에 기록한다. 실제 브라우저 로딩 확인은 설치 후 수행한다.
