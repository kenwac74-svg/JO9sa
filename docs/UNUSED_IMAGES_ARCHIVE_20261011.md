# 미사용 이미지 외부 보관 — 2026-10-11

사용자가 현재 플레이 폴더의 미사용 이미지를 JO9 밖으로 옮기고 게임을 실행해 확인하도록 지시했다. JO9main의 과거 결과를 플레이본에 그대로 적용하지 않고 현재 `G:/somi/JO9`를 다시 조사했다.

## 완료한 파일 작업

- QSP 247 location, 런타임 CSS/JSON/설정 1,157개, 현재 저장 파일 33개를 확인했다.
- 미참조 후보 5,331개 중 생성 원본·가공본·마스크 30개(`master/max`)와 제작용 버튼 템플릿 2개만 미사용으로 확정했다. `mob template.png`는 작업필요 체크가 있어 유지했다.
- 32개 / **35,767,380바이트(35.77 MB, 34.11 MiB)**를 `G:/somi/JO9_unused_images/20261011_verified/files/`로 옮겼다. 원래 상대 경로를 유지한다. 나머지 **5,299개는 HOLD**이며 이동·삭제 승인이 된 목록이 아니다.
- 외부 복사본의 SHA256이 모두 일치하고 원래 경로에서 32개가 제거됐음을 확인했다. 그 밖의 이미지 누락·크기/수정 시각 변경은 없다. QSP와 원본 B컷 manifest 해시는 동일하다.
- 장면전환 리소스, 원본 B컷, 체크된 작업 파일, JO9O와 카탈로그 상태는 변경하지 않았다.

## 기록과 복구

- [파일별 해시·근거](resource-audits/2026-10-11/moves.json), [HOLD 목록](resource-audits/2026-10-11/held-candidates.json), [조사 근거](resource-audits/2026-10-11/evidence.json), [검증 결과](resource-audits/2026-10-11/verification.json).
- 외부 폴더에 원본 계획, 실행 journal, 검토 기록과 `RESTORE.ps1`을 보존했다. 이 스크립트는 journal의 파일만 복구하며 충돌하는 다른 파일을 덮어쓰지 않는다.
- [재사용 조사·이동 규칙](../tools/jo9-prune-images/SKILL.md)과 복구 도구를 저장소에 보관한다. Git에는 이미지 본체·세이브·대용량 런타임 덤프를 넣지 않는다.

## 실행 확인의 한계

클라이언트를 실행하여 엔진 창 제목 `Jack-o-nine-tails 2.3.2.5 & Kor Ver`를 확인했다. 조작 도구가 `failed to activate captured window` 오류를 냈고 새 창 선택 후 한 번 재시도해도 같은 오류였다. 캡처에 바탕화면만 표시돼 **게임 화면·세이브 로드·버튼 동작은 확인하지 못했다**. 사용자에게 창을 앞으로 띄워 달라고 요청했다. 플레이 QA는 미완료다.

실행 전 자동 저장 5개를 백업했다. 실행 후 루트 `auto.sav` 1개가 바뀌고 나머지 4개는 동일했다. 열린 게임의 자동 저장을 덮어쓰지 않았다. 실행 전 백업은 외부 보관 폴더의 `pre-test-autosaves/`에도 복사했다. 게임 종료 뒤 사용자 진행과 테스트 변경을 확인하고 필요한 경우에만 복구한다.

## 배포 용량

[이동 전 용량 계산](resource-audits/2026-10-11/distribution-size-before-archive.md)은 이전 시점의 압축 계산이며 완성된 출시 ZIP이 아니다. 후보 제외 시나리오는 삭제 가능 판정이 아니다. 이번 35.77 MB는 파일 합계 절감량으로, ZIP이 같은 만큼 줄었다고 주장하지 않는다. 풀팩·간소화 패치의 실제 빌드 후 용량을 다시 측정한다. JO9 바깥 보관 폴더와 감사/백업 자료는 양쪽 배포물에서 제외한다.
