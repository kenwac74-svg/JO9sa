기존 채팅과 세션을 그대로 쓴다. 일반 Chat으로 자동 지시가 전송되거나 상시 협업하는 구조를 가정하지 않는다. 사용자 또는 명시적으로 승인된 전달자가 [짧은 인계](HANDOFF.md)를 전달한다. 연결 가능한 실행 세션에는 승인된 메시지 기능으로 역할을 알린다. 각 실행 세션과 작업에 참여하는 하위 에이전트는 시작 시 이 문서와 해당 인계를 읽고 자기 역할·기준 SHA를 확인한다. 역할 인지 전달과 새 작업 착수는 구분한다.

## 작업 기준 고정

1. 새 작업 시작 때 GitHub에서 원격 main SHA와 확인 시각을 읽는다. 실패하면 마지막 확인 SHA와 조회 실패를 기록하며 최신이라고 말하지 않는다.
2. 작업 기록에 전체 40자리 SHA를 고정하고, 필요한 지침·코드·입력 목록을 그 SHA로 읽는다. 진행 중 main이 바뀌어도 자동 기준 전환하지 않는다.
3. 다음 작업 시작 때 main을 다시 확인한다. 기준 갱신이 진행 작업에 필요하면 차이와 영향을 적고 작업 범위를 다시 정한다.
4. 다른 브랜치의 최신 커밋은 참고 자료다. main 기준과 섞지 않는다. 채택 변경은 출처 SHA·대상·승인 기록을 별도로 남긴다.
5. 로컬 작업은 원격 기준 + 명시한 local-pending 변경으로 표현한다. 로컬 변경·최신 날짜의 QSP·로컬 세션 완료 보고만으로 원격 반영을 주장하지 않는다.
6. 실제 게임 QSP와 이미지는 Git에 전부 보관되지 않는다. 원격 SHA에 더해 사용자가 지정한 실제 입력 파일 경로·해시·필요한 location을 기록한다. 기준 불일치는 전체 QSP 덮어쓰기나 QSRC 재빌드로 해결하지 않는다.

로컬 상태를 읽을 수 없다면 원격 기준과 미확인 범위를 기록하고, 기존 작업을 변경하는 방식으로 해결하지 않는다.

## 상태와 승인

| 상태 | 기록할 근거 |

보류·취소도 기록한다. 취소 작업을 재개하지 않는다. HTTP 200을 내부 브라우저 실제 열림이나 게임 정상 동작으로 기록하지 않는다. 과거 검사 성공을 이번 입력 검증으로 대신하지 않는다.

이미지는 기존 JO9_IMAGE_JOB의 필드와 생성→사용자 채택→Codex 반영 흐름을 그대로 사용한다. 인계 형식은 그 규약을 감싸는 요약이며 새 이미지 규약을 만들지 않는다. `catalog_work_ids.json`의 기존 번호·상태·원장은 유지한다. 충돌 번호를 자동 재번호하거나 보존 번호를 재사용하지 않는다.

## Codex 실행 범위

Chat에서 목표·대사·이미지를 확정하고 Codex에는 한 작업씩 전달한다. Codex는 대상 파일/location과 직접 연결된 의존성만 읽는다. 반복 전체 스캔·기획 토론·이미지 생성·새 대형 도구 개발을 기본 업무로 시작하지 않는다. 캐시한 조사 결과는 기준 SHA 또는 해당 입력이 바뀔 때 갱신한다.

작업별 필요한 검사만 선택한다. QSP 내용 변경은 원격 지침에 따라 왕복 바이트 검증·대상 백업·선언형 mods와 최소 변경으로 기록한다. 새 QSP 실행 코드는 CRLF를 사용한다. 왕복·정적 검사는 실제 실행 검증을 대체하지 않는다. 게임 플레이 확인은 사용자에게 맡긴다. 빌드와 패키징은 이번 승인된 담당의 업무이나 실제 실행은 해당 작업 인계 범위에 따른다. 공개 게시·업로드는 별도 사용자 지시가 있을 때 실행한다.

순정 `G:\somi\JO9O`는 원격 저장소 지침에 따라 보호한다.
