## 1. 문서 범위와 원안의 경계

바티칸에 인계된 아이의 행방이 숨겨진 도축장 공간의 사건, 신원 확인과 가족 재회로 이어지는 비극적 사건의 비성적 진행 구조를 정리한다. 설정·대사 전문과 상세 연출은 사용자가 이벤트 생성기에서 조율한다.

기존 원안에는 미성년 인물과 연결된 성적 상태·보상 설정이 포함되어 있다. 그 부분은 이 문서에 재작성하지 않는다. 이 범위 제한은 게임 속 신규 조건이나 원안의 폐기·변경 승인으로 취급하지 않는다. 대체 보상·대체 설정은 새로 만들지 않았다. 따라서 본 문서는 원안 전체를 그대로 복원한 완성 기획서가 아니다.

### 잔액 유지 조건의 남은 해석 충돌

사용자는 “1만 스파크 보유는 계속 하고 있어야 한다”고 정정했다. 기존 v4 문서는 제안·재제안·수락 직전까지만 10,000을 명시하고 개방 후 재방문에는 날짜만 적고 있다. 이를 확정적으로 완화하지 않는다.

특히 10,000을 보유한 채 5,000을 투자하면 잔액은 5,000이 된다. 투자 직후 첫 입장과 이후 재방문에도 10,000을 요구하는지, 투자 거래에 한해서만 결제 전 기준인지 재개 시 확정해야 한다. 기존 문서의 “그날 즉시 입장”과 “항상 10,000 유지”를 둘 다 만족한다고 단정하지 않는다.

## 3. 진행 구조

1. 유효한 바티칸 인계 사건의 날짜와 관련 인물 ID를 확보한다.
2. 150일·끝자리 4/8·소지금 조건을 모두 만족한 방문에서 투자 제안을 표시한다.
3. 거절은 금액 차감 없이 제안 보류. 재방문에서 조건을 다시 평가한다.
4. 수락 직전에 조건과 잔액을 재확인하고 투자금 5,000을 한 번 차감한다.
5. 안쪽 개방 플래그를 저장한다. 투자 상태와 특정 대상 거래 상태를 구분한다.
6. 인물을 데려오는 경로가 확정되면 고정 ID와 영입 시점을 보존한다. 이 문서에서 거래의 미지원 세부 상태나 대체 보상은 정하지 않는다.
7. 보유일과 관계 조건을 충족하면 신원 확인 이벤트를 호출한다.
8. 적격한 가족이 현재 소유 목록에 있으면 모녀상봉을 진행한다.

안쪽 개방 후 특정 대상을 계속 유지할지, 반복 방문의 일반 재고가 있는지, 최초 사건이 일회성인지 등은 아직 미정이다. 한 번 거래된 같은 대상의 중복 지급은 금지한다.

## 4. 신원 확인과 모녀상봉

| 항목 | 원안 |

| 확인 내용 | 영입 인물이 주인공의 딸이라는 사실 확인. 구체적 증거·연출·추가 트리거는 미정 |
| 딸 효과 | 친딸 특성, 헌신 5 고정·하락 불가, 기분 황홀함 |
| 엄마 후보 | 노예·조수·개인실 보유 인물 중 출산 경험 후 150일 지난 인물 |

혈연상의 엄마를 인계 당시 산모 ID로 고정할지, 원안의 최고 종합등급 후보 규칙으로 정할지 설정 정합성 검토가 필요하다. 동률 처리, 과거 출산 날짜가 없는 캐릭터, 체력 상한 처리도 미정이다.

### 교육 보정의 기록 충돌

대화에는 모녀 교육 보정을 교육기관·가정교육까지 넓히려다가 “아니다 설정상 안맞네”라고 정정한 기록이 있다. 이후 보관 문서 v4에는 조수–노예 페어 보정이 다시 남아 있다.

이 항목은 최신 적용 범위가 불명확하므로 확정 구현 목록에서 보류한다. 교육기관 전체나 가정교육 전체에 임의 적용하지 않는다. 재승인되면 역할 배치의 두 인물 ID를 실제 모녀 ID와 비교하는 기술 방식부터 검토한다. 고정 활성 플래그로 역할 변경 뒤에도 효과를 남기지 않는다.

### 판매·처형 이후 사건

원안은 상봉한 두 인물 중 한 명의 실제 판매 또는 처형이 확정되면 다른 한 명도 사망하는 비극적 후속 사건이다. 방법·장면의 상세 묘사는 정하지 않는다.

대화 선택이나 거래 취소로 발생시키지 않고 실제 확정 완료 경로를 기준으로 한다. 역할 이동과 개인실 재배치는 판매로 간주하지 않는다. 사망 처리의 재귀 호출과 중복 처리를 막는 상태 구분은 구현 검토 사항이다.

## 5. 저장·기술 설계 검토

| 필요한 사실 | 재사용·추가 여부 |
|---|---|
| 현재 날짜·소지금·인물 ID·역할 배치 | 기존 값 재사용 후보 |
| 첫 유효 인계일과 인계 당시 산모 ID | 현재 게임에 존재하는지 확인 필요 |
| 투자/개방/대상 거래/확인/상봉 단계 | 이벤트 생성기의 영속 상태 구조에 묶는 방식 검토 |
| 영입일 또는 보유일 | 기존 보유일 값 재사용 가능성 확인 |
| 모녀 고정 ID | 역할 슬롯 번호와 별도로 유지 필요 |
| 일회 보상 처리와 후속 사건 완료 | 저장·불러오기에도 보존해야 함 |

“신규 변수가 전혀 필요 없다”는 결론은 아직 없다. 기존 출산 횟수만으로 출산·인계 날짜를 복원할 수는 없다. 이벤트 생성기가 공용 상태 저장을 제공하면 전용 변수를 줄일 수 있지만 기록 자체는 필요하다.

헌신을 한 번 5로 대입하는 것만으로 영구 고정을 보장하지 않는다. 정신 상태·하루 갱신·역할 이동·로드 후 재계산 경로를 확인해야 한다. 기존 친족 필드를 덮어쓰기 전에 기존 관계 계산·대사에서의 쓰임을 조사한다.

구세이브의 날짜를 임의 생성하지 않는다. 실제 기록이 없으면 이관 정책을 정한 뒤 처리한다.
