# Claude 정책준수·정책거부 기술 사유서 (2026-11-12)

`REFUSAL_LOG_KO.md`의 짝이다. 항목마다 **원래 설계대로라면 어떻게 동작했어야 하는가**와 **실제로는 어떻게 구현했는가**를 코드·데이터 위치와 함께 적는다. 버그나 코딩 오류로 오해하지 않게 하는 것이 목적이다. 각 항목에서 Claude가 그렇게 한 이유는 한 줄로만 적는다(판단 근거는 `REFUSAL_LOG_KO.md`, 사용자는 일부를 정책 과대 해석으로 본다).

공통 이유(한 줄): Claude는 미성년 설정 캐릭터에게 성적 내용을 붙이는 결과물과 수간 결과물을 직접 만들지 않는다. 형태(문장·숫자·집계·자동 생성 장치)는 구분하지 않는다.

---

## 1. 과거 경험 공식의 연령 제외 — [클로드 정책 거부]
| 구분 | 내용 |
|---|---|
| 원래 동작 | `pastHistory(stock, formula, seed)`가 모든 연령에 같은 식으로 총횟수를 계산한다. 연령은 곱셈 칸 하나(`× formula.ageFactor[seed_age]`)일 뿐이다. 이어 `pastFacts`가 사실을, `pillowTalk`이 대사 조각을 만든다. |
| 실제 구현 | `dist/past-history.mjs` `pastHistory` 첫 부분에서 `formula.excludedAges.includes(stock.age)`이면 계산하지 않고 `{excluded:true, intimacy:null, pregnancies:null, births:null}`을 바로 돌려준다. 지금 `excludedAges = [1]`(`dist/data/past-history-formula.json`). |
| 연쇄 결과 | `pastFacts`는 `result.excluded`이면 `null`(`dist/past-facts.mjs` 30줄). `pillowTalk`도 `null`(`dist/pillow-talk.mjs` 151줄). 시뮬레이터는 과거 경험·필로우토크 카드 대신 '제외 연령' 안내를 낸다(`dist/character-view.mjs` 155·217줄). 편집기 대사집 '담기'는 배경 분류·원본 DB 연결 코드만 가져온다(`dist/studio-view.mjs`, 판단은 서버 `excluded_ages()`가 같은 `excludedAges`를 읽음). |
| 데이터에 남는 것 | 연령 가중치(편집기에서 넣은 1 → 60)는 공식 데이터에 저장된다. 계산 코드는 모든 연령 공통이며 연령 숫자를 따로 박지 않는다. |
| 되돌리는 지점 | `excludedAges` 값 하나(사용자 직접). 그 밖의 코드 수정은 필요 없다. |
| 함께 거부한 요청 | 값을 `[9]`로 바꾸는 것(결과적으로 같은 계산을 켜는 일). |

## 2. 엔진 표본 생성의 연령 1 제외 — [클로드 정책 거부]
| 구분 | 내용 |
|---|---|
| 원래 동작 | 실제 게임 엔진으로 `generate_stock`을 N번 돌려 모든 연령의 노예 표본을 뽑는다(뽑기 분포·공식 검사의 기준 표본 `dist/data/generated-stock.json`). |
| 실제 구현 | `docs/sim/run-generate-stock.cjs`가 생성 전에 `no_loli = 1`을 넣어, 게임 설정의 '소녀 생성 끔' 옵션으로 연령 1이 표본에 나오지 않게 했다. |
| 결과 | 표본 1만 명에 연령 1이 없다. 뽑기 분포·직업별 특성 빈도·과거 경험 검사도 연령 0·2 기준이다. |
| 되돌리는 지점 | 그 스크립트의 `no_loli = 1` 한 줄(사용자 직접). 표본을 다시 만들어야 반영된다. |

## 3. 대사집 저장 차단 (해제됨) — [클로드 정책 거부]
| 구분 | 내용 |
|---|---|
| 원래 동작 | 대사집 저장(`save_talkbook`)은 사용자가 쓴 값을 연령과 관계없이 그대로 저장한다. |
| 처음 구현(잘못) | 서버가 연령 코드 1이면 대사·과거 경험 항목을 지우고 배경 분류·메모만 저장했다. 사용자의 편집을 막은 것이었다. |
| 지금 구현 | 해제. 사용자가 쓴 칸은 그대로 저장된다(`studio_server.py` `save_talkbook`). 제외는 1번의 자동 생성에만 걸린다. |

## 4. 첫 경험 청소년기(B1) 대사 — [클로드 정책준수]
| 구분 | 내용 |
|---|---|
| 원래 동작 | 첫 경험 나이를 뽑아(세계별 평균, 표준편차 2) 나이와 함께 대사를 조립해 화면에 낸다. |
| 실제 구현 | `dist/past-facts.mjs` 60~69줄: 19세 미만이면 `first_band='teen'`, `blocked.first_band='B1'`, 나이를 저장하지 않고 창작물 인터뷰 번호(`first_age_ref`)만 고른다. 화면은 "[이 대사는 표시 불가합니다.]". 19세 이상만 나이(고유어)와 대사를 낸다. |
| 데이터에 남는 것 | 칸·분류 코드·인터뷰 번호. 사용자가 그 칸에 직접 쓰는 것은 막지 않는다. |

## 6. 인터뷰 DB의 표시불가 원문 — [클로드 정책준수]
| 구분 | 내용 |
|---|---|
| 원래 동작 | 블로그 인터뷰 대답 5,112개를 원문 그대로 DB에 담는다. |
| 실제 구현 | `docs/sextalk-interviews/build-db.py`의 `TEXT_WITHHELD = {'minor', 'bestiality'}`에 해당하는 대답(B1 청소년기·B2 수간)은 `answer`에 자리표시 문구, `text_withheld: true`, 부분 키에 `text` 없이 해시·글자 수만 둔다. 원문 위치는 `withheld-locator.json`(글·질문·순서·주소). 편집기 참조 `dist/data/interview-refs.json`도 같은 847칸이 원문 없음. B3~B9는 원문을 담고 표시만 막는다. |
| 글 단위 원문 DB(예정) | 같은 규칙. B1·B2 대답은 원문 없이 위치·분류 코드만, 편집기에서 블로그의 그 글을 연다. |
| 되돌리는 지점 | 칸 구조는 비어 있다. 사용자가 직접 채우는 것은 도구가 막지 않는다. |

## 7. 외부 AI 자동 창작·번역 파이프라인 (설계 단계) — [클로드 정책준수]
| 구분 | 내용 |
|---|---|
| 원래 동작 | 작업 목록에 DB의 모든 칸을 넣어 외부 AI(OpenRouter·Venice·Gemini·Kindroid)에 보낸다. |
| 실제 설계 | 작업 목록을 만들 때 분류 코드 B1·B2 칸을 넣지 않는다. 결과에 '제외됨(B1/B2)'으로 찍는다. |
| 다른 항목과 다른 점 | 데이터 스위치로 두지 않는다. 값 하나로 켤 수 있게 두면 외부 AI에 미성년·수간 성적 창작을 자동 요청하는 장치를 Claude가 만들어 넘기는 것과 같아서다. |
| 실제 영향 | B1·B2 칸은 원래 원문이 없어 번역 대상에서 빠지는 내용은 없다. 사용자가 편집기에서 직접 쓰는 것은 막지 않는다. |
