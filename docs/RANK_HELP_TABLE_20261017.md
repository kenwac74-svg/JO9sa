# 등급 설명 팝업 정렬 수정

2026-10-17. 최신 플레이 QSP를 읽어 기존 등급 안내문만 수정한다. S++·신규 트레잇 작업은 포함하지 않는다.

## 변경

- `#help_msg`의 `$rank_help_2` 정의 한 블록을 수정한다. 태그: `JO9 MOD START/END RANK_HELP_TABLE`.
- 전각 공백으로 한 줄에 나열했던 내용을 점수·단계·기술 등급의 3열, 6개 데이터 행으로 정렬한다.
- 실제 기술 등급인 F-, D-, C-, B+, A+, S+를 표시한다.
- 개별 기술은 6단계, 종합등급은 11단계이며 일부 주인공 전문기술은 S++가 있다는 설명을 추가한다.
- 능력치·경험치·승급 조건·등급 배열·세이브 파일은 수정하지 않는다. 배포 QSP도 수정하지 않는다.

## 원인과 기존 등급

기존 안내문에는 항목 사이의 줄바꿈과 표 셀이 없었다. 창 폭에서 자동 줄바꿈되면서 열과 행이 섞였다. 기술 등급표가 중간 기호를 건너뛰는 것은 보호 원본 JO9O에도 같은 기존 설계다. 현재 일반·하위 기술 표시배열 63개가 0~5의 여섯 단계를 사용한다. F+는 해당 표시체계에 없다.

## 연결 및 편집

`slave_stat`, `assistant_stat`, `teach_screen`에서 먼저 `$rank_help`, 다음으로 `$rank_help_2`를 표시한다. `master_stat`도 두 번째 설명문을 사용한다. 새 로케이션·변수·저장 상태는 없다. 표 내용만 수정할 수 있으며, 태그 전체를 임의 삭제하면 안내문이 없어질 수 있으므로 원복은 패치 JSON의 old/new를 역적용한다.

기존 세이브를 불러오면 `$ongload` → `$newloc`의 full update → `refresh_database` → `#help_msg` 경로에서 설명문을 다시 읽는다. 현재 열려 있는 게임 메모리에는 디스크 수정이 즉시 적용되지 않으므로 클라이언트를 다시 열고 세이브를 불러와 확인한다.

## 검증

- 수정 전 QSP 바이트 동일 왕복 검증.
- 수정된 로케이션은 `#help_msg` 하나이며 다른 본문과 설명 필드는 동일하다.
- 변경 블록을 역적용하면 원래 본문이 정확히 복구된다.
- CRCRLF가 없는지 확인한다.
- 선언형 JSON을 표준 `tools/apply_mods.ps1`로 작업 사본에 적용한 결과와 후보 파일의 SHA-256이 일치한다.
- QSP 5.7.0 DLL에서 수정한 정의를 실제 실행해 오류 0 및 생성된 HTML을 확인한다. 게임 클라이언트를 실행한 검증은 아니다.
- 실제 메시지 배경 500×375, 텍스트 영역 x=80/y=40/폭370으로 HTML을 렌더링했다. 3열 6개 데이터 행이 정렬되며, 내용 하단 y=274로 확인 버튼 y=340 위에 여백이 있다. 이 미리보기는 게임 클라이언트 렌더링과 동일하다고 보장하지 않는다.
- 화면 확인은 사용자가 기존 ? 버튼 → 확인 순서로 진행한다.
