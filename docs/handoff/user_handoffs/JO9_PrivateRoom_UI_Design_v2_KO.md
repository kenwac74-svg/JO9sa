## 2. 개인실의 의미

개인실은 별도 직업이나 작업 역할이 아니다.

> **개인실 = 노예 또는 조수를 일반 업무·조교 상태에서 빼고 개인 공간과 일부 자유를 제공하는 휴양 / 특별대우 상태**

원칙:

- 메인 UI 캐릭터 카드와 기존 게임 기능을 최대한 재사용한다.
- 정보 조회, 질문, 보상, 씻기 등 특별대우와 충돌하지 않는 기능은 유지한다.
- 업무·압박·처벌·처분 성격의 기능은 개인실에서 숨긴다.
- 개인실 전용 기능은 중앙 전용 영역에만 배치한다.
- generic Actor 구조, slave/assistant/room 전체 리팩터링, EXE/FastQSP 아키텍처 변경은 하지 않는다.

## 4. 개인실 화면 기준은 `_layout`

원본 개인실은 다음처럼 `_layout`을 호출한다.

```qsp
$place = "slave_private_room1"
gs '_layout'
gs '$newloc'
```

따라서 개인실 UI는 `main_layout`이 아니라 `_layout` 기준으로 한다.

### `_layout` 주요 좌표

```text
MAINDESC_X = 1
MAINDESC_Y = 1
MAINDESC_W = 1280
MAINDESC_H = 800

STATDESC_X = 810
STATDESC_Y = 1
STATDESC_W = 450
STATDESC_H = 800

OBJECTS_X = 780
OBJECTS_Y = 660
OBJECTS_W = 50
OBJECTS_H = 100
```

### 원본 장면 영역

```text
#bg
left: 4px
top: 3px
width: 795px
height: 595px
```

### 원본 하단 대사 영역

```text
#text
left: 30px
top: 615px
width: 740px
height: 185px
```

개념 구조:

```text
┌───────────────────────────────────────────────┬─────────────────────────┐
│              장면 / 캐릭터 영역              │       우측 UI 영역      │
│              x≈4~799                          │       x≈810~1260         │
│              y≈3~598                          │                         │
├───────────────────────────────────────────────┤                         │
│         원본 하단 대사창                      │                         │
│         x=30 y=615 w=740 h=185                │                         │
└───────────────────────────────────────────────┴─────────────────────────┘
```

### 금지

- `main_layout`과 `_layout`을 혼합하지 않는다.
- x=960을 개인실의 새로운 전체 경계로 고정하지 않는다.
- 별도 320px 전체 우측 패널 아키텍처를 만들지 않는다.

## 5. 원본 하단 대사창 유지

일반 질문 결과, 보상 결과, 교육 결과, 기타 원작 interaction 결과는 원본 하단 대사 출력 체계를 따른다.

따라서 별도 `#snk_room_message` 같은 커스텀 하단 메시지 박스로 원본 대사창을 대체하지 않는다.

## 6. 식사 설정 팝업은 `msg_bg.png` 기준

`msg_bg.png`는 원본 QSP의 MSG 팝업 배경이다.

```qsp
$MSG_BACKIMAGE = 'content\pic\msg_bg.png'
$MSG_OK_IMAGE = 'content/pic/buttons/ok-icon.png'

MSG_TEXT_X = 80
MSG_TEXT_Y = 40
MSG_TEXT_W = 370
MSG_TEXT_H = 400

MSG_OK_X = 250
MSG_OK_Y = 340
MSG_X = 200
```

원본 이미지 규격:

```text
500 × 375
```

역할 구분:

- **식사 설정 → `msg_bg.png` 기반 팝업**
- **일반 대사/결과 → 원본 하단 대사창**

실제 구현이 QSP `msg()`인지 동일 외형 overlay인지는 최소 수정 원칙에 맞춰 결정하되, 외형과 UX는 원본 `msg_bg.png`를 기준으로 한다.

## 8. 초상화 4귀퉁이 — 확정

| 위치 | 표시 정보 |
|---|---|
| 좌상단 | Ill — 질병 |
| 우상단 | Wound — 상처 |
| 좌하단 | 등급 (`S+`, `A+`, `C+` 등) |
| 우하단 | 문신 / 마법 / 인장 / 없음 등 표식 |

Ill/Wound는 상태가 있을 때만 표시한다.

기존 작은 아이콘을 무리하게 확대하지 않고 표준 버튼 영역 안에 원본 아이콘을 중앙 배치한다.

이 규칙은 메인 UI와 개인실 UI 양쪽에 동일 적용한다.

## 9. 임신/생식상태 통합

생식상태는 기존 정보열의 **한 슬롯**에서 다음 5상태를 교체 표시한다.

| 상태 | 이미지 |
|---|---|
| 평시 | `Fer_Normal.png` |
| 안전일 | `Fer_PregS.png` |
| 배란기 | `Fer_PregO.png` |
| 임신중 | `Preg_s.png` |
| 불임 | `Fer_PregX.png` |

임신은 초상화 귀퉁이에 넣지 않는다.

기존 fertility / ovulation / pregnancy 판정을 재사용하며 신규 생식 시스템은 만들지 않는다.

## 13. 질문 — 원작 메뉴 그대로 연결

원작 메인 UI 빠른 질문 버튼은:

```qsp
menu_form = 111
gt 'menu_form'
```

으로 진입한다.

개인실도 같은 원작 질문 메뉴를 사용한다.

원작 질문 항목:

- 인상 묻기
- 불만 묻기
- 요구 묻기
- 현재 기분 묻기
- 희망사항 묻기
- 과거 묻기
- 조수에 대해 묻기

원작 복귀:

```text
질문 메뉴
뒤로 → menu_form = 11
취소 → menu_form = 0

회화 메뉴
뒤로 → menu_form = 1
취소 → menu_form = 0
```

roomN을 기존 slave 메뉴가 처리할 수 있도록 최소 target bridge만 사용한다.

### TEST6 질문 오류

보고된 오류:

> 질문 버튼 클릭 후 원작 결과와 과거 개인실 방 배정 문구가 같이 표시됨.

정상 동작이 아니다.

가능한 원인:

- 개인실 진입 시 `killvar 'menu_form'`
- `$roomN_info_text` 잔류
- roomN→slave bridge 이후 개인실 location으로 너무 빨리 복귀
- 복귀 과정에서 옛 방 배정 UI 재출력

하지만 **TEST6 실제 bridge/return 코드를 대조하기 전까지 원인은 추측**으로만 기록한다.

## 16. 씻기 — 원작 기능 재사용

기존 메인 UI의 씻기 로직을 재사용한다.

## 20. 안내 레이어

중앙에 별도 텍스트 열을 추가하지 않는다.

중앙 공간 크기의 독립 overlay를 사용한다.

기본:

> **숨김**

열기:

- `i` 버튼
- 기존 `game/content/pic/buttons/debug_button.png` 재사용 가능

닫기:

- 우상단 `X`
- 기존 close 계열 재사용

표시:

- 투명 PNG 한 장에 안내 텍스트 포함
- 다른 UI 레이아웃/스크롤에 영향 금지

우하단:

> **개인실 추가 기능 개발 중 by SAnk**

권장 파일:

```text
game/SNKmod/content/pic/ui/private_room_notice.png
```

```text
개인실 → 개인 침대
```

내부 값은 그대로 유지한다.

설명 의미:

> 그녀만을 위해 배정된 편안하고 부드러운 개인 침대는 노예의 기분을 좋게 만들어준다. 충성스럽고 복종하는 노예에게 어울리는 특별대우이지만, 그렇지 않은 노예는 응석을 부릴 수 있다.

중복 정의가 있으면 모두 동일하게 수정한다.

## 26. 레이어 / z-index 원칙

기본 순서:

```text
1. 원본 _layout / bg
2. 장면
3. 캐릭터
4. 일반 UI 카드 / 버튼
5. 필요할 때만 안내 또는 식사 overlay
6. overlay의 닫기 버튼 / tooltip
```

### 금지

```css
div:hover { z-index: ... }
```

같은 전역 hover z-index 승격은 사용하지 않는다.

z-index는 필요한 특정 버튼, tooltip, overlay에만 scope를 걸어 지정한다.

## 27. 개인실 전용 섹스 텍스트 — 후속 규칙

이번 UI 패치에서는 개인실 전용 섹스 엔진을 만들지 않는다.

후속 개발 시:

- 기존 섹스 엔진 재사용
- 기존 판정 재사용
- 기존 CG/장면 이미지 재사용
- 개인실 문맥에 맞지 않는 대사만 별도 분기

초기 텍스트 작성:

1. 원작에서 가장 상황에 가까운 문장을 복사
2. 별도 개인실 텍스트로 연결
3. 문장 끝에 반드시:

```text
#개인실
```

태그 추가

이후 `#개인실` 검색으로 일괄 수정한다.

## 34. 최종 정의

> **개인실 UI는 원본 `_layout`을 유지하면서 메인 UI의 캐릭터 카드 구조를 재사용한다.**
>
> **질문·보상·씻기·정보조회는 유지하고, 사회화·영향력·처벌·처분·청소·요리 같은 업무/압박 기능은 숨긴다.**
>
> **빠른 동작은 `식사 → 보상 → 씻기` 순서이며, 식사 설정은 `일반식 / 고열량식 / 특별식단` 세 항목을 사용한다.**
>
> **질문·보상·교육은 새 기능을 만들지 않고 원작 메뉴와 복귀 흐름을 그대로 연결한다.**
>
> **원본 하단 대사창은 유지하고, 식사 설정은 `msg_bg.png` 기반 팝업 UI를 사용한다.**
>
> **중앙부는 개인실 전용 기능을 위한 공간으로 확보하며 안내 레이어는 기본 숨김, i/X 토글 방식으로 사용한다.**
