# RM 참조 미해결 안건 핸드오프

2026-10-12 기준. 다음 PC에서 이어 검토할 **버그 후보, 누락 안내·대사, 시스템 수정 후보**만 정리한다. 해결된 항목, 적용 여부 판단이 끝나 현행 유지로 결론 난 항목은 작업 목록에서 제외했다. RM에만 있는 변경을 곧바로 우리 버전의 버그로 취급하지 않는다.

두 파일을 이번 문서 작성 시 읽어 해시 및 바이트 왕복을 확인했다. 예전에 조사한 GitGud master QSP(231 locations)와 오래된 로컬 RM(194 locations)은 이 문서의 최신 기준이 아니다. RM의 `.qsrc`가 컴파일된 QSP와 일치한다고 가정하지 않는다.

이 문서는 코드 비교와 이전 조사 결과에 근거한 인계이며 아래 후보를 새로 적용하지 않았다. [현재 QSP와 RM의 미해결 차이 증거](qa/2026-10-12_rm-open-items-evidence.json)에 위치별 줄·변수·배열 차이를 보존했다. 줄 번호는 각 QSP location 본문 기준이다.

## 먼저 검토할 버그 후보

### 1. 생성 대상의 출신과 고유 ID 초기화

**우선순위 높음. 현재 코드 차이 재확인.** `get_stock_seed`에서 출신 설명은 `stock_type`으로 가져오지만, 세계·국적·가족·직업 인덱스, ID, 친족 ID와 관계 문자열은 `slave_type`으로 기존 `slave`에 기록한다. RM은 같은 필드를 `stock_type`으로 생성 중인 `stock`에 기록한다.

새로 생성할 인물의 메타데이터가 빠지거나 기존 동행 인물의 정보가 바뀔 가능성이 있다. 실제 피해 범위는 호출 흐름을 추적해 확인해야 한다.

- 확인 범위: `generate_stock` → `get_stock_seed` → `stock_to_slave_nogt` 및 상점·경매·고유 인물 생성 경로. `tolerant_world`·`tolerant_nation` 계산도 함께 확인.
- 수정 방향: 생성 단계의 대상과 인덱스를 일치시키되, 일부 호출이 의도적으로 기존 `slave`를 갱신하는지 먼저 검사. 함수 전체를 RM 것으로 교체하지 않는다.
- 완료 기준: 기존 동행의 출신·ID 불변, 신규 인물의 출신·ID·관계 정상, 고유 인물/일반 생성 각각 확인. 기존 세이브의 잘못된 ID를 자동 재작성하는 별도 마이그레이션은 이 수정에 섞지 않는다.

### 2. 친족 ID 0의 잘못된 일치와 관계 대사 분기

**우선순위 높음.** `origins_relations`의 RM에는 `relative_id > 0` 보호가 있지만 우리 코드에는 같은 보호가 없다. 양쪽 ID가 0이면 관계가 있는 것으로 잘못 판정될 수 있다. 우리 코드의 일부 `jump 'bio_override'`와 라벨은 주석 처리돼 있어 조건 한 줄만 복사하면 대사가 일반 계산으로 덮일 수 있다.

1번 생성 ID 문제와 함께 조사한다. 무관계/ID 0, 실제 친족, 일반 같은 출신, 양방향 관계를 각각 시험하고 전용 대사가 끝까지 유지되는지 확인한다.

### 3. 구매자 요구 조건의 공통 판정 누락

**우선순위 중간.** `slave_sell_chek`에 최신 RM만 가진 요구 키 25개가 있다. 숫자는 요구 종류 차이이며 신규 이벤트 수가 아니다. 개별 이벤트가 직접 검사하는 조건도 있으므로 우리 쪽에서 모두 무시된다고 단정하지 않는다.

후속 담당자는 요구 키 → 실제 구매자 등록 → 메뉴 → 공통/개별 검사 → 인수 처리 연결표부터 만든다. 사용되는 요구만 작은 패치로 보완한다. RM에도 다음 오류 후보가 있어 그대로 복사하면 안 된다.

- `min_sensitivity`: 거절 비교 방향과 안내 의미의 일치 여부.
- `anal_pure`: `END` 뒤의 거절·`exit`가 조건과 무관하게 실행되는지.
- `nopreversion`: `preversion`/`perversion` 오타와 실제 요구 사용 여부.
- `fertility`: 값·공개 여부 조합이 실제 거절 사유와 일치하는지.

완료 기준은 각 요구의 충족/미충족/정보 미공개 경계 검사, 거절 시 인물·금액 불변, 인수는 한 번만 실행되는 것이다. 우리 변수 표기와 RM의 구형 표기를 매핑한다.

### 4. 지역 최종 인정 상태의 평판 갱신 경로

**우선순위 중간.** 러시아 구역·배제 구역·후타랜드·홍등가·중앙 구역에서 RM `#options`는 납품 완료와 귀족 상태 등의 조건으로 평판 5를 기록한다. 우리 해당 메뉴에는 같은 대입이 빠져 있다. 공통 납품 결과에서도 평판을 올릴 수 있으므로 현재 진행 불가로 확정하지 않는다.

`npc_progress = 2`, `noble_status`, `faction_fame` 및 공통 판매 결과를 추적한다. 지역별 완료 직전/직후/재방문 세이브로 최종 인정이 남는지 검사하고, 빠지는 경로만 보완한다. 미완료·비귀족 상태에 평판 5를 강제하면 안 된다.

### 5. 적의 피해 0 특수공격 선택

**우선순위 중간, 앞선 비교에서 발견한 후보.** RM에는 해당 특수공격의 기본 피해가 0인 경우를 걸러내는 조건이 있다. 우리 현재 전투 AI에서 실제로 의미 없는 공격을 고르는지와 효과형 공격도 피해 0을 쓰는지 재현해야 한다.

무효 공격만 제외한다. 우리 AI의 정수 오버플로 방지·난수 개선을 RM의 구식 계산으로 되돌리지 않는다. 일반 적/특수공격 없는 적/효과형 공격을 각각 확인한다.

### 6. 오베레그 장착 효과의 하루 종료 유지

**우선순위 낮음.** 최신 RM `next_day`에는 `spell_revelio = obereg_on`이 있고 우리 같은 위치에는 없다. 우리 `$newloc`에는 장착 상태로 효과를 다시 켜는 처리가 이미 있어 전체 효과 누락으로 보지 않는다.

장착·해제 후 하루 종료, 같은 화면 유지, 이동, 저장/불러오기에서 효과 상태를 확인한다. 하루 종료와 다음 이동 사이에 실제 공백이 생길 때만 보완한다.
