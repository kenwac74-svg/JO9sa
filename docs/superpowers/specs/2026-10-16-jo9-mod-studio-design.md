# JO9 Mod Studio 설계안

2026-10-16 · 프로토타입 기반 편집·복제·확장 설계 제안 / 제품 구현 전

## 1. 만들 도구와 완료 기준

도구의 초점은 기존 게임 요소와 개발자가 제공한 기본 프로토타입을 편집·복제·확장·변경하는 데 둔다. 특성뿐 아니라 명기처럼 여러 곳에 연결된 정의, 변수 항목, 수치 보정과 표시도 다룬다. 사용자는 프로토타입을 복사해 여러 정의로 늘리고 각각의 ID·이름·기본값·수치·확률·조건·효과·적용 대상·아이콘·대사를 AI·API 없이 조정한 뒤 현재 QSP에 적용·복원한다. 기능 묶음에 없는 기존 값도 소스 검색으로 편집한다.

첫 완성판은 기존 항목 조정과 함께 ‘복제’와 ‘새로 추가’를 제공한다. 새 항목은 등록된 프로토타입에서 시작하며 그 스키마와 어댑터가 지원하는 저장 형식·조건·효과·대상 범위 안에서 작성한다. 현재 명기 설정의 확률/표시명 편집, 복제 지원 프로토타입의 독립 복제본 두 개 생성·조정·대상 변경, 저장·재개방·미리보기·적용·재적용·복원이 완료 기준이다.

AI/개발자는 최초의 작동하는 프로토타입과 편집용 정의·어댑터·저장/초기화 기능을 만든다. 사용자는 이를 재사용해 항목을 추가·복제하고 내용을 조정한다. 프로토타입이 제공하지 않는 새로운 변수 구조, 시스템/엔진 로직, 발동 지점과 복잡한 계산을 게임에 연결하는 일은 개발 작업이다. 이 역할 구분은 트레잇 시스템 전체 개조뿐 아니라 새로운 정의·변수 계열에도 적용한다.

확정한 사용자 기준:

- 등록된 프로토타입의 복제/추가·항목 편집과 일반 소스 값 검색·수정·적용에는 AI 요청·응답 대기가 없다. 지원 범위 안의 값을 바꾸거나 복제본을 늘릴 때마다 AI나 새 기능 등록을 요구하지 않는다.
- 사용자가 작성한 조건·수치·분기를 임의로 추가·삭제·완화하지 않는다. 자동 수정이 필요하면 변경 내용을 먼저 비교한다.
- 기존 항목 편집은 실제 저장 위치·변수·배열 키·상태 번호·연결을 유지한다. 독립 복제본은 제공된 어댑터가 별도 ID와 충돌 없는 저장 바인딩을 발급한다. 등록된 저장 기능을 넘는 새 구조·연결·엔진 기능은 개발 등록 범위다.
- 게임 내용·표시 문구는 QSP에 둔다. 원본 CSS 역할인 배치·폰트·배경·툴팁 외형은 CSS에 유지한다.
- BG, 캐릭터/CG, 아이콘을 별도 자원 역할로 다룬다. CG 교체로 BG를 자동 변경하지 않는다.
- 실제 게임 실행·화면/플레이 검증은 사용자가 한다. 모형 시험과 엔진 실행 결과를 구별한다.

## 2. 선택할 구조

| 접근 | 장점 | 한계 | 판단 |
|---|---|---|---|
| 기존 변수 목록에 입력란만 추가 | 구현량이 적음 | 같은 값의 여러 대입 위치와 조건, 기능별 연관 변경을 놓침 | 검색·문맥·변경 비교를 갖춰야 사용 가능 |
| 기존 도구 + 일반 값 편집 + 프로토타입/기능 묶음 | 반복 편집과 독립 복제·추가를 기존 자산 위에서 수행 | 소스 값 편집기·프로토타입 등록·저장 바인딩 발급·적용 조정기가 필요 | 권장 |
| 범용 특성/이벤트 제작기와 QSP IDE | 새로운 구조까지 직접 작성 가능 | 새 연결·상태 이관·전체 언어 처리가 필요 | 후속 개발 도구 |

권장: 브라우저 UI + 기존 로컬 Node 서버/모듈 재사용. 편집 경로는 ‘일반 소스 값 검색’과 ‘등록된 프로토타입/기능 묶음’ 두 가지이며 같은 후보 생성·검증·적용 계층을 쓴다. 프로토타입 화면에는 기존 항목 편집·복제·새로 추가가 함께 있다. 실행기는 현재 설정의 플레이/배포 폴더를 명시적으로 표시한다. 서버는 localhost만 사용하고 파일 쓰기는 프로젝트·대상 관리 계층이 수행한다. 제작·편집·적용에 외부 통신은 필요하지 않다.

## 3. 사용자 작업 순서

1. 현재 게임/프로젝트에서 기존 기능 묶음이나 프로토타입을 선택하거나 변수명·키·문구·값으로 소스를 검색한다.
2. 기존 항목을 편집하거나 ‘복제’/‘새로 추가’에서 등록된 프로토타입을 고른다. 복제 지원 여부와 지원 조건·효과·대상을 먼저 표시한다.
3. 새 항목은 별도 ID·이름과 자동 발급된 저장 바인딩을 확인한다. 일반 검색 결과는 location·대입식·조건·여러 발생 위치를 확인하고 수정할 위치를 선택한다.
4. 각 항목의 기본값·수치·확률·등록된 조건/효과·적용 대상·표시명·설명·아이콘·대사·가격을 조정한다. 같은 숫자라는 이유로 무관한 발생 위치까지 바꾸지 않는다.
5. 샘플 전후값과 원문 diff에서 복제본 간 독립성·원본 보존·충돌을 확인한다. 기존 판정 이력·상한·계산 순서에 따른 적용 한계도 본다.
6. 프로젝트를 저장하고 다시 열어 편집을 이어간다. 복제본의 ID와 바인딩은 그대로 유지된다.
7. 적용 대상 선택 → 대상별 후보 생성/검사 → 사용자 적용 → 결과 확인. 재적용·복원과 패키지 내보내기는 같은 기록을 사용한다.

프로젝트 저장과 게임 적용은 별도 버튼이다. 편집 중에는 실제 게임 파일을 바꾸지 않는다.

## 4. 화면 구성

왼쪽은 기존 값 검색과 프로토타입/정의 목록, 가운데는 선택 항목과 관련 분기, 오른쪽은 편집 속성이다. 목록에서 편집·복제·새로 추가를 실행한다. 아래에는 실제 연결 원문·변경 비교·시험 결과를 펼친다. ‘분기 한눈에’는 선택 항목의 문맥을 확인하는 보기로 유지하고, 주 작업은 기존 요소와 프로토타입을 재사용해 확장하는 흐름으로 둔다.

| 화면 | 사용자가 하는 일 |
|---|---|
| 프로젝트 | 현재 게임/기존 모드 열기, 프로토타입에서 새 항목 추가·복제, 저장/열기, 변경 이력, 패키지 내보내기 |
| 기존 값 검색 | 변수·배열 키·문구·수치로 검색, 대입/참조 구분, 여러 위치·주변 조건 비교, 선택한 기존 값 수정 |
| 프로토타입·기능 묶음 | 복제 지원/등록 필요 상태, 원본과 복제본 목록, ID·바인딩·대상, 이름·설명·확률·수치·아이콘·가격 편집 |
| 조건·효과 | 지원 스키마 안에서 조건·효과 추가/제거·값·조합·대상 수정, 실행 시점·순서·일회성 이력 확인 |
| 장면·분기 | 기존 페이지·선택지·이동·대사·단계별 이미지 수정. BG/캐릭터/CG/표시 UI를 별도 항목으로 표시 |
| QSP 원문 | 선택 위치·미인식 원문·어댑터 생성 결과 확인, 고급 편집. 지원 범위를 넘는 새 저장 구조/연결 등록은 개발 작업 |
| 시험·적용 | 샘플 입력/전후값, 미수정 범위 비교, 대상별 적용/백업/복원, 자원 누락 확인 |

수락·진행은 초록 #228B22, 거절·중단은 빨강 #B22222, 질문·다른 제안은 보라 #7B1FA2를 기본으로 제안한다. 사용자의 명시적 변경을 덮어쓰지 않는다. 기존 이미지 선택기와 대사 도구는 이 작업 문맥을 유지하며 열린다.

## 5. 편집 모델

### 변수와 상태

숫자와 문자열은 QSP의 실제 형식으로 구분한다. 참거짓은 숫자 0/1의 UI 표현이고, 열거 상태는 숫자 값과 표시명을 연결한 UI 모델이다. 소수형을 엔진 기능으로 가정하지 않는다. 배수는 정수 비율과 계산 순서/나눗셈 절삭을 명시한다.

저장 범위는 실제 소스에 있는 전역/인물/현재 이벤트를 보여준다. 검색 결과마다 변수·배열 키, location, 대입/비교/참조 종류, 원래 식과 주변 조건을 표시한다. 한 변수가 여러 조건에서 다른 값으로 대입되면 모든 후보를 별도로 보여주고, 특정 대입문을 변수의 유일한 기본값으로 취급하지 않는다. ‘소스 상수/대입 후보’, ‘등록된 초기값’, ‘시험용 값’을 구분하며 현재 세이브의 실제 값인 것처럼 표시하지 않는다.

기능 묶음에 등록되지 않은 기존 숫자·문자열 리터럴도 위치를 선택해 수정할 수 있다. 이 경로에 AI나 항목별 사전 등록은 필요하지 않다. 정적 분석으로 의미를 확정하지 못한 표현식·동적 대상은 원문과 한계를 표시하고, 안전하게 선택한 원문 범위만 바꾼다. 같은 리터럴의 모든 출현을 의미상 같은 설정으로 자동 결합하지 않는다.

변수명·배열 키·호출 이름 같은 저장/코드 식별자는 일반 값과 구분한다. 기존 문구 수정으로 저장 키가 바뀌지 않도록 한다. 독립 복제/추가는 어댑터의 바인딩 발급 절차로 새 이름을 연결하며, 원문에서 변수명만 일괄 치환하는 방식으로 처리하지 않는다.

사용자는 등록된 프로토타입의 숫자/문자열 저장 기능 안에서 새 정의나 변수 항목을 추가할 수 있다. 어댑터가 이미 검증한 저장·초기화·역할 복사 규칙에 따라 실제 바인딩을 발급한다. 새로운 엔진 자료형이나 미등록 저장 구조·상태 체계·표시 위치·발동 연결을 설계하는 일은 AI/개발자 범위다. 값을 추가하는 것만으로 UI나 이벤트가 생기지 않으므로 프로토타입이 제공한 출력·호출 연결도 함께 생성·검증한다.

### 프로토타입과 기능 정의 메타데이터

기능 정의는 편집 항목과 실제 원문을 연결한다. 프로토타입 ID/버전, 허용 스키마·형식·범위·조건/효과·적용 대상, 소스 바인딩과 발동 위치 지도, 표시 연결, 저장/초기화·캐시 갱신 규칙, 복제 지원 여부와 바인딩 발급 규칙을 보관한다. 예를 들어 명기의 발견 확률 입력 하나는 실제 인물별 판정 위치를 모두 나열하며, 기술 등급의 같은 숫자까지 변경하지 않는다.

AI/개발자는 최초 작동 프로토타입과 시스템 개조를 제공할 때 편집/복제용 정의·바인딩·어댑터·초기화/이관 규칙도 함께 제공하고 갱신한다. 이후 사용자는 지원 범위 안에서 AI나 원문 코드 작성 없이 편집·복제·새 항목 추가·대상 변경을 수행한다. 메타데이터와 원문이 다르면 연결 확인 필요로 표시한다. 일반 소스 값 편집은 이 등록 자료가 없는 기존 항목도 다룬다.

### 독립 복제와 적용 대상

각 복제본은 고유 instanceId와 이름, prototypeId/버전, 편집값, 적용 대상, 실제 바인딩 원장을 갖는다. ID와 바인딩은 생성 때 확정해 프로젝트에 저장하며 재개방·후보 재생성 때 다시 발급하지 않는다. 어댑터는 복제본별 저장값·초기화/판정/일회 보상 이력·필요 helper 이름을 분리하고 원본/다른 모드와 충돌을 검사한다. 효과가 의도적으로 같은 기존 게임 수치를 대상으로 삼으면 공통 수정 대상과 적용 순서를 별도로 표시한다.

복제본의 값을 조정해도 원본이나 다른 복제본이 바뀌면 안 된다. 표시명만 새로 만들고 내부 쓰기 상태를 공유하는 복제는 독립 복제로 인정하지 않는다. 복제 자체로 기존 인물의 값·발견/획득 이력을 복사하거나 즉시 특성을 부여하지 않는다. 적용 대상과 초기화/획득 정책은 어댑터의 지원 범위에서 명시적으로 선택한다.

아이콘·CG 같은 자원은 처음에는 원본 경로를 공유할 수 있다. 복제본에서 자원을 변경하면 기본적으로 그 복제본의 독립 경로에 저장하고 참조를 변경한다. 공용 자원 자체를 교체하려면 영향을 받는 원본·복제본 목록을 비교 화면에 표시하고 공용 교체를 명시적으로 선택하게 한다. 대사 등 편집 가능한 내용도 복제본을 조정했을 때 원본을 함께 수정하지 않는다.

‘복제 지원’ 판정에는 어댑터가 상태·이력·helper를 읽고 쓰는 실행 참조까지 분리했는지 검증하는 절차를 포함한다. 미인식 코드에 원본 키나 호출 참조가 남는지 확정하지 못하면 기존 항목 편집만 허용하고 ‘복제 등록 필요’로 표시한다. 미인식 원문 보존만으로 독립 복제가 보장된다고 판단하지 않는다.

현재 명기는 기존 virginity=4와 여러 조건/저장 키에 직접 연결되어 있다. 이 정의를 그대로 복사해 모두 같은 상태 4를 읽고 쓰게 하면서 독립 복제라고 표시할 수 없다. 편집 가능과 복제 가능은 별도 상태이며, 독립 저장·호출·표시 연결을 지원하는 어댑터가 등록되기 전에는 ‘복제 등록 필요’를 표시한다. 첫 완성판에는 게임 연결까지 검증한 복제 지원 프로토타입을 최소 하나 함께 제공한다.

대상 변경은 등록된 인물/역할/변수·출력/효과 바인딩 목록에서 선택한다. 표시 대상만 바뀌고 효과는 원래 대상에 남는 부분 변경을 방지하며, 조건·저장·계산·출력 중 무엇이 함께 바뀌는지 diff로 보여준다. 미지원 대상이나 새 사건 연결은 개발 등록이 필요하다.

### 조건

등록된 조건을 트리와 입력란으로 보여주고, 프로토타입 스키마 안에서 추가/제거·비교값·선택 항목·논리 조합·적용 대상을 편집한다. 미등록 조건은 원문으로 보존한다. 확률에는 분모·분자, 실제 판정 시점·대상·재판정 정책을 표시한다. 확률 편집과 최초 1회 이력 초기화는 별개이며, 확률 편집으로 재추첨을 만들지 않는다. 기존 항목과 복제 원본의 조건·게이트는 사용자가 명시적으로 변경한 항목 외에는 유지한다.

### 효과

등록된 효과의 설정값·증감량·배수·최소/최대 보장·상한·대사/이미지/이동 대상을 편집하고 지원 스키마 안에서 효과를 추가/제거한다. 실제 실행 순서와 일회 지급/매번 계산 구분을 표시한다. 순서·효과 종류와 대상 변경, 복제본별 지급 이력 발급은 어댑터의 지원 범위에서 제공한다. 프로토타입이 제공하지 않는 새 계산 구조·저장 기능은 개발 등록 범위다.

매번 보정은 해당 사건의 원래 계산 결과를 입력으로 사용한다. 재방문마다 저장값에 배수를 누적 적용하지 않는다. 우선순위·중복 모드의 같은 값 수정·상한 적용 순서를 비교 화면에서 확인한다.

### 실제 발동 위치

QSP에는 일반적인 이벤트 버스가 없으므로, 실제 소스의 연결 지점을 AI/개발자가 등록한 어댑터가 필요하다. 각 연결은 location·조건 문맥·전/후 위치·대상 인물·변경 변수·예상 일치 개수·소스 fingerprint를 가진다. 줄 번호만으로 연결하지 않는다. 사용자는 등록된 시점과 의미를 확인하며 편집한다.

첫 기능 묶음은 현재 명기의 상태/발견 확률·표시·교육 보정·가격/거래 연결을 재사용한다. 독립 복제는 별도로 등록한 복제 지원 어댑터를 사용한다. 다른 기존 항목은 일반 검색·선택 편집으로 접근하고 자주 쓰는 정의부터 프로토타입을 추가한다. ‘결과 계산 전’, ‘성공 뒤’, ‘지급 직전’은 다른 시점으로 표시한다.

등록되지 않은 새 시점과 복잡한 동적 연결은 개발 작업이다. 일반 값 검색에서 여러 발생 위치가 나오면 사용자가 수정할 후보를 선택할 수 있지만, 이를 새 발동 연결을 자동 생성한 것으로 취급하지 않는다. 의미를 추측해 모든 호출부를 바꾸지 않으며 미인식 코드는 원문으로 유지한다.

## 6. 기존 모드와 명기 가져오기

mods JSON과 현재 QSP를 함께 읽는다. 최신 소스가 기준이며 오래된 문서의 해시를 현재값으로 가정하지 않는다. 명기처럼 여러 패치에 나뉜 작업은 프로젝트 내 구성 요소로 묶어 보여준다.

1. 원본 QSP/등록된 패치의 관계와 실제 적용 상태를 확인한다.
2. 인식한 변수·상태·확률·효과·표시·발동 위치를 GUI 항목으로 가져온다.
3. 지원하지 못하는 조각은 ‘원문 유지’로 표시하고 원래 코드와 JSON 필드를 보존한다.
4. 편집하지 않고 저장/다시 열기/후보 생성하면 QSP는 바이트까지 같아야 한다. 자동 정리·변수 재명명·조건 이관을 하지 않는다.
5. 사용자가 한 값을 바꾸면 그 값과 필요한 연결 부분만 diff에 나타나야 한다. 기존 저장 키와 상태 번호를 몰래 새 체계로 옮기지 않는다.

가져온 항목에는 ‘GUI 편집 가능 / 원문 유지 / 연결 확인 필요’와 별도의 ‘복제 지원 / 복제 등록 필요’를 표시한다. 부분 인식을 완전 편집·복제 가능으로 표시하지 않는다. 명기 전용 편집기로 한정하지 않고 일반 소스 값 편집과 등록 프로토타입 기반 추가를 함께 제공한다. 등록되지 않은 새로운 계열은 개발자가 최초 프로토타입·바인딩·의미를 제공한다.

## 7. 프로젝트 파일과 코드 생성

프로젝트는 일반 JSON과 로컬 자원 폴더로 저장한다. 필수 항목: schemaVersion, id/revision, 원본/프로토타입 정의 버전, 각 instanceId·편집값·대상·확정된 저장/소스 바인딩 원장, 편집 전후값, 보존할 원문, 캐시 갱신 규칙, 자원 원장, 적용 이력, 대상별 fingerprint. 프로토타입 정의에는 허용 스키마와 조건/효과·발동 위치·초기화/이관·복제 생성 규칙을 보관한다. 자원 원장에는 상대경로·형식·크기·해시를 둔다.

일반 값 편집은 선택한 원문 범위의 최소 치환을 만들고, 기존 기능 묶음은 등록 바인딩을 수정한다. 복제/추가는 제공된 어댑터 템플릿과 확정된 ID/바인딩에서 QSP를 생성한다. 같은 프로젝트 입력은 같은 결과를 내며 미수정 원문은 의미와 순서를 유지한다. 생성물은 기존 mods의 old/new/count와 필요한 add_locations로 내보낸다. 현 적용기의 새 location은 actions가 비어 있어야 한다. 임의의 새 시스템 구현을 추측 생성하지 않으며 게임이 프로젝트 JSON을 직접 읽는다고 가정하지 않는다.

프로젝트에는 원래 저장 위치·발생 위치와 편집 항목, 복제본별 생성 바인딩을 함께 보관한다. QSP 전체를 매번 재해석해야만 이전 편집을 이어갈 수 있는 구조를 피한다. 이름·아이콘은 기존 또는 어댑터가 제공한 QSP 출력 연결에서 처리하고 CSS로 문구를 숨겨 덮지 않는다.

원문에서는 기존 location 본문·설명과 선택한 문맥을 확인하고 고급 편집할 수 있다. 본문 안의 ACT/EXEC와 QSP 컨테이너의 별도 action 레코드를 구분한다. 별도 action 레코드는 현재 적용기가 지원하지 않으므로 첫 완성판의 편집 범위 밖으로 표시하고 자동 삭제하지 않는다. 원본 왕복 보존은 필수다.

모드 패키지는 프로젝트 JSON + mods + 자원 + manifest + 적용/복원 설명을 담은 로컬 ZIP이다. 큰 이미지·게임 전체·세이브·백업·키는 Git 자동 저장 대상이 아니다. Git에는 프로젝트·패치·자원 원장·검증 기록을 저장한다. 이미지 전송은 사용자가 선택한 로컬 패키지/드라이브 절차로 분리한다.

## 8. 기존 세이브

프로젝트/코드 버전과 인물별 초기화·판정·일회성 이력을 분리한다. 소스 편집이나 정의 복제는 현재 세이브의 값을 직접 바꾸지 않는다. 기존 초기값을 수정할 때는 해당 대입문의 실행 시점을 표시한다. 새 복제본의 기본값·초기화/획득 대상도 어댑터가 제공한 정책 안에서 별도로 선택하며, 복제했다는 이유로 기존 인물에게 부여하거나 원본 이력을 복사하지 않는다. 지원 범위를 넘는 이관은 개발자가 등록하고 전후 목록을 제공한다.

기존 항목의 발견·시도 완료·일회 보상 이력과 저장 키는 유지하고, 독립 복제본은 어댑터가 발급한 별도 이력 키를 사용한다. 저장/로드, 개인실↔동행↔조수↔보관, 화면 재진입, 재적용에 따른 재추첨·중복 지급·다른 복제본의 이력 오염을 검사한다. 누락 키의 0과 저장된 0을 구분하는 초기화 버전 표시도 정의별로 관리한다. 어댑터 밖의 임의 저장 키는 생성하지 않는다.

어댑터는 프로젝트 revision 변경에 필요한 동적 정의·화면 캐시의 일회 갱신도 정의한다. 세이브에 저장된 이전 코드가 새 수치를 무시하지 않도록 실제 $newloc 갱신 흐름과 연결하며, 기존 $ongload·$onnewloc를 임의로 덮어쓰지 않는다. 같은 revision의 캐시 갱신/이관은 반복하지 않으며, 갱신이나 단순 화면 재진입 때문에 확률 판정·지급이 추가 실행되지 않게 한다. 실제 사건이 새로 발생할 때의 기존 판정·지급 주기는 유지한다.

세이브는 QSP 변경과 별개다. 후속 저장 편집 기능은 확인된 저장 형식의 사본만 지원하고, 입력값 시험을 실제 세이브 실행 결과로 표시하지 않는다. 초기 완성판은 샘플 값과 실제 사용자 플레이로 검증 가능해야 하며 테스트 세이브 편집기 완성을 선행 조건으로 삼지 않는다.

## 9. 적용·복원

대상은 G:/somi/Jack O Nine Tails v2.4_work/game/jack.qsp와 G:/somi/Jack O Nine Tails v2.4 Kor_Full/game/jack.qsp를 각각 관리한다. 플레이본을 배포본에 통째 복사하지 않는다.

적용 순서:

1. 모드/대상/자원/후속 의존성 확인 → 현재 원본 해시·바이트 왕복 검사.
2. 대상별 별도 후보 생성. 치환 범위·개수·문자열·코드 블록·등록 위치·정의 ID/저장 바인딩 충돌을 검사.
3. 공통 변경과 대상별 차이를 미리보기. 원본/복제본, 새로 생성할 바인딩과 바뀌는 조건·수치·대상을 표시.
4. 모든 대상 후보와 자원을 준비한 뒤 원본을 다시 검사하고 백업 바이트를 검증.
5. journal 준비 기록 확정 → 파일별 임시 후보 교체 → 다시 읽어 해시/참조 검사와 단계 기록.
6. 결과를 대상·파일별로 표시하고 캐시/인덱스를 새로 만든다. 실패시 이미 바뀐 파일은 검증된 백업으로 복구를 시도하고, 복구 실패/부분 적용을 숨기지 않는다.

교체 전에 journal을 디스크에 기록한다. 파일별 생성/교체/유지, 기존 존재 여부, 전후 해시와 백업을 보관한다. 대상 루트를 벗어나는 자원 경로와 기존 파일의 다른 해시 충돌은 차단하고, 교체를 원하면 사용자가 명시적으로 교체 대상으로 지정해 다시 비교한다. 복구는 현재 파일 해시를 확인하고 수행한다. 새 파일은 도구가 생성한 경로와 해시가 journal에 일치할 때만 제거하며, 이후 사용자 작업이 있으면 보존하고 충돌을 보고한다.

여러 폴더의 QSP/이미지를 OS 차원에서 동시에 원자적으로 교체할 수 있다고 주장하지 않는다. 사전 준비와 복구 journal을 사용하는 다중 파일 적용이다. 종료/중단 후 재실행하면 journal과 현재 해시로 완료·복구·사용자 확인 필요 상태를 제시한다.

최근 적용의 복원은 현재 파일이 기록의 적용 후 해시와 같을 때 허용한다. 이후 수정이 있으면 이전 전체 백업을 덮어쓰지 않고 충돌을 표시한다. 모드 비활성화도 의존성 검사를 거치는 새 변경으로 처리한다. 모드를 제거한다고 저장된 세이브를 자동 원상 복구하지 않는다.

## 10. 시험과 품질 기준

첫 수락 시험은 기존 항목 조정과 독립 복제·확장을 모두 확인한다. 현재 명기 바인딩을 불러와 발견 확률 5%→10%와 표시명을 편집하고, 일반 검색에서 기존 중립 가격을 선택해 바꾸는 경로도 시험한다. 별도로 등록 완료된 작동 프로토타입 P를 두 번 복제해 A/B의 ID·저장 바인딩을 분리하고 이름·기본값·수치·지원 조건/효과·적용 대상을 서로 다르게 정한다. A를 다시 조정해도 B와 P의 값·이력·출력은 유지되어야 한다.

기존 항목과 A/B를 저장/닫기/재개방 → 대상별 후보 비교 → 플레이 적용 → 재적용 → 복원까지 AI 요청이나 원문 코드 작성 없이 처리한다. 원본 P와 무관한 소스 보존, 복제본의 독립 동작과 충돌 거부를 확인한다. 현재 명기에 복제 어댑터가 없으면 복제 등록 필요로 표시하고, 복제 시험은 실제 등록 완료된 P로 수행한다. 이 설계 작업에서는 실제 수치를 바꾸거나 프로토타입을 게임에 설치하지 않으며 실제 게임 검증은 사용자가 한다.

명기 확률 변경은 아직 판정되지 않은 대상의 다음 유효한 최초 판정에 적용한다. 이미 판정을 끝낸 대상의 재추첨·발견 이력 초기화·상태 번호 변경을 뜻하지 않는다. 이름 수정은 지정한 출력 위치에 적용하고, 가격 수정은 기존 계산·예산·거절 조건 안에서 작동한다. 화면에는 이러한 기존 의미와 적용 한계를 함께 표시한다.

필수 시험:

- GUI→프로젝트→후보 생성→다시 열기 후 의미/값 유지. 무수정 가져오기는 전체 바이트 불변.
- 기능 정의 없는 기존 값도 검색·위치 선택·수정·적용 가능. 여러 대입 위치와 조건을 표시하고 선택 외 동일 리터럴은 보존.
- 명기 5%→10%는 등록된 확률 판정 위치만 변경하고 같은 숫자의 기술 등급·기존 조건·이력·상태 번호는 보존. 표시명/가격 편집도 선언한 바인딩 외 원문 불변.
- 복제/새로 추가 후 ID·저장값·판정/보상 이력·helper 이름의 독립성과 재개방 후 바인딩 고정. ID/키 충돌은 적용 전 거부.
- A/B의 값·조건/효과·대상 변경은 서로와 원본 P를 오염시키지 않음. 대상 변경 시 저장·조건·효과·출력 연결의 일관성 확인.
- A의 아이콘·대사 변경 후 P/B의 참조와 내용 보존. 공용 자원 교체는 영향 목록과 명시적 선택 확인. 미확정 원본 저장/helper 실행 참조가 있으면 복제 지원 판정 거부.
- 복제 등록 필요 항목은 독립 복제 가능으로 표시하지 않음. 복제/추가만으로 기존 인물·세이브에 획득·재판정·원본 이력 복사 없음.
- 확률 0/100/경계 표본, 성공/실패, 최초 시도와 최초 성공의 구별, 표시 갱신에서 재추첨 없음.
- 숫자/문자열 인자, 기존 범위와 상한, 정수 나눗셈, 효과 순서, 일회 보상, 배수 비누적.
- 기존 세이브 값 보존·초기화 버전·인물 역할 이동·표시 이름/아이콘 연결.
- BG 고정 + 단계별 CG/PNG/GIF, 선택지 의미별 색상, 기존 이미지와 경로 보존.
- 겹치는 패치, 원문 수정 후 적용, 대상별 서로 다른 원본, 자원 누락, 잠긴 파일, 중간 쓰기 실패, 복구 실패를 재현.
- 브라우저 조작 시험과 실제 게임 플레이 시험은 별도 기록. 소스 왕복 검사를 QSP 전체 문법/동작 보증으로 표현하지 않는다.

## 11. 개발 순서와 첫 완성판 범위

1. 기존 소스 값 검색·문맥/여러 대입 위치 표시·선택 값 편집·프로젝트 저장을 만든다. 최소 치환과 대상별 후보/적용/복원을 끝까지 연결한다.
2. 현재 명기의 실제 키/연결을 편집 정의로 등록하고, 별도로 작동하는 복제 지원 프로토타입과 어댑터를 제공한다. 편집·복제·새로 추가·독립 ID/저장 바인딩·조건/효과·대상 변경을 연결하고 캐시·이력 보존을 검사한다.
3. 기존 이미지/대사/분기 탐색 도구를 같은 문맥에 연결해 아이콘·툴팁·대사·선택지·단계별 CG, 미리보기/패키지를 통합한다. 선택지·이동 목적지·조건의 GUI 수정은 기존 탐색 기능 위에 새로 구현한다. 기존 편집과 P→A/B 복제·독립 조정·적용·복원 수락 시험을 완료한다.

이 세 단계를 기존 요소와 제공된 프로토타입을 독립적으로 편집·복제·추가·확장하는 첫 완성판의 목표로 본다. ‘새로 추가’는 첫 범위에 포함하고, 지원되지 않는 저장 구조나 시스템을 자동 창조한다고 보고하지 않는다. 새로운 프로토타입 계열·엔진 연결·복잡한 동적 코드 분석·별도 action 레코드 GUI·테스트 세이브 편집은 이후 개발 등록/확장 작업이다.

## 검토 상태

이 문서는 구현 전 설계 제안이다. 함께 제공하는 화면은 조작 가능한 설계 시안이며 실제 QSP·이미지·세이브를 읽거나 쓰지 않는다. 사용자가 흐름과 범위를 확인한 뒤 구현 계획과 제품 구현을 진행한다.
