# JO9 Mod Studio 설계안

2026-10-16 · 설계 제안 / 제품 구현 전

## 1. 만들 도구와 완료 기준

사용자가 AI·API·코드 생성 서비스 없이, 로컬 GUI에서 새 특성·저장값·조건·효과·아이콘·대사 분기를 만들고 현재 QSP에 반영한다. 명기처럼 여러 부분에 걸친 모드를 하나의 프로젝트로 묶고 나중에 다시 열어 수정할 수 있어야 한다.

단순 변수 조회기나 코드 붙여넣기 창을 완성품으로 간주하지 않는다. 첫 완성판은 GUI에서 특성을 새로 만들고, 조건부 효과와 표시를 연결하고, 플레이본에 적용하고, 되돌리는 작업을 끝까지 수행할 수 있어야 한다. 복잡한 원본 코드를 전부 GUI로 자동 변환한다고 약속하지 않는다. 인식한 부분은 GUI로, 나머지는 보존된 QSP 원문으로 접근한다.

확정한 사용자 기준:

- AI 요청·응답 대기 없이 로컬 기능만으로 제작·적용한다. 선택적 AI 도구는 이 제작 경로의 의존성이 아니다.
- 사용자가 작성한 조건·수치·분기를 임의로 추가·삭제·완화하지 않는다. 자동 수정이 필요하면 변경 내용을 먼저 비교한다.
- 기존 값과 구조를 먼저 재사용한다. 새 QSP 변수/배열 키는 사용자가 이름과 용도를 명시해 만든다. 엔진에 없는 등급·기능이 자동으로 생기는 것으로 취급하지 않는다.
- 게임 내용·표시 문구는 QSP에 둔다. 원본 CSS 역할인 배치·폰트·배경·툴팁 외형은 CSS에 유지한다.
- BG, 캐릭터/CG, 아이콘을 별도 자원 역할로 다룬다. CG 교체로 BG를 자동 변경하지 않는다.
- 실제 게임 실행·화면/플레이 검증은 사용자가 한다. 모형 시험과 엔진 실행 결과를 구별한다.

## 2. 선택할 구조

| 접근 | 장점 | 한계 | 판단 |
|---|---|---|---|
| 기존 대사 편집기에 수치 입력란만 추가 | 구현량이 적음 | 다중 위치 특성·발견·저장·효과 연결을 표현하지 못함 | 핵심 해법으로 부적합 |
| 로컬 Mod Studio + 기존 모듈 재사용 | 기존 QSP·이미지·기록 자산을 살리고 구조 편집 기능을 추가 | 규칙 생성기와 적용 조정기를 새로 만들어야 함 | 권장 |
| QSP 전체 IDE와 엔진을 새로 제작 | 장기적으로 표현 범위가 넓음 | 완전한 언어/엔진 호환에 비용이 집중됨 | 첫 목표에서 제외 |

권장: 브라우저 UI + 로컬 Node 서버. 실행기는 현재 설정의 플레이/배포 폴더를 명시적으로 표시한다. 서버는 localhost만 사용한다. 파일 쓰기는 브라우저에서 임의 경로를 만드는 대신 서버의 프로젝트·대상 관리 계층이 수행한다. 제작과 적용에 외부 통신은 필요하지 않다.

## 3. 사용자 작업 순서

1. 새 모드 만들기 또는 기존 모드 가져오기.
2. 변수/상태 정의: 기존 값 선택 또는 새 키 추가. 이름·설명·범위·기본값을 입력한다.
3. 발동 시점 선택: 실제 게임 코드와 연결된 시점 목록에서 고른다.
4. 조건 조합: 그리고/또는/아님, 값 비교, 상태 변경, 확률, 최초 1회/매회/기간 제한을 조합한다.
5. 효과 추가: 값 설정·증감·배수·하한/상한·상태 전환·경험치·금액·대사/장면 이동 등을 순서대로 배치한다.
6. 표시 연결: 이름·툴팁·아이콘·표시 위치·대사·선택지·단계별 CG를 지정한다.
7. 샘플 값으로 규칙 시험. 생성될 QSP와 실제 바뀔 부분을 비교한다.
8. 적용 대상 선택 → 후보 생성/검사 → 사용자 적용 → 결과 확인. 프로젝트·원문·패치·자원 원장을 함께 저장한다.

프로젝트 저장과 게임 적용은 별도 버튼이다. 편집 중에는 실제 게임 파일을 바꾸지 않는다.

## 4. 화면 구성

이전에 고른 ‘분기 한눈에’ 방향을 계승한다. 왼쪽은 프로젝트 항목, 가운데는 조건과 흐름, 오른쪽은 선택한 항목의 속성이다. 아래에는 생성될 코드/변경 비교/시험 결과를 펼친다. 숫자·변수명·조건은 옆 원문과 대조할 수 있다.

| 화면 | 사용자가 하는 일 |
|---|---|
| 프로젝트 | 새 모드, 기존 모드 가져오기, 저장/열기, 변경 이력, 패키지 내보내기 |
| 변수·상태 | 숫자/문자열/참거짓/열거 상태, 저장 범위, 기본값, 값별 표시명, 기존 참조 검색 |
| 특성 | 저장값 연결, 발견/활성/표시 구분, 아이콘·이름·툴팁, 대상 인물 범위 |
| 조건·효과 | 발동 시점과 실행 순서, 조건 트리, 확률, 일회성 이력, 여러 효과 연결 |
| 장면·분기 | 페이지·선택지·이동·조건 분기·대사·단계별 이미지. BG/캐릭터/CG/표시 UI를 별도 항목으로 표시 |
| QSP 원문 | 생성 코드 확인, 인식하지 못한 조각 보기·직접 편집, 실제 연결 위치 지정 |
| 시험·적용 | 샘플 입력/전후값, 미수정 범위 비교, 대상별 적용/백업/복원, 자원 누락 확인 |

수락·진행은 초록 #228B22, 거절·중단은 빨강 #B22222, 질문·다른 제안은 보라 #7B1FA2를 기본으로 제안한다. 사용자의 명시적 변경을 덮어쓰지 않는다. 기존 이미지 선택기와 대사 도구는 이 작업 문맥을 유지하며 열린다.

## 5. 편집 모델

### 변수와 상태

숫자와 문자열은 QSP의 실제 형식으로 구분한다. 참거짓은 숫자 0/1의 UI 표현이고, 열거 상태는 숫자 값과 표시명을 연결한 UI 모델이다. 소수형을 엔진 기능으로 가정하지 않는다. 배수는 정수 비율과 계산 순서/나눗셈 절삭을 명시한다.

저장 범위는 전역/인물/현재 이벤트로 구분한다. 기존 변수 목록에서는 ‘소스의 대입 후보’, ‘설정한 기본값’, ‘시험용 값’을 구분하며 현재 세이브의 실제 값인 것처럼 표시하지 않는다. 새 영구 키는 모드 ID로 이름 충돌을 검사하고, 인물 슬롯/역할 이동시 보존되는지 점검한다.

값을 추가하는 것만으로 새 UI나 이벤트가 생기지 않는다. 표시 위치와 실행 위치는 별도 연결이 필요하며, 미연결 항목은 목록에서 드러나야 한다.

### 조건

모두 충족/하나 이상/부정, 숫자·문자열 비교, 배열 키 조회, 변경 전/후 값 비교, 프로젝트 규칙 참조를 지원한다. 확률에는 분모·분자, 판정 시점, 대상, 재판정 정책이 있어야 한다. 화면을 다시 그리는 것과 사건이 발생하는 것을 구분한다. ‘최초 1회’는 성공만 1회인지 시도 자체가 1회인지 선택한다.

### 효과

설정, 더하기/빼기, 배수, 최소/최대 보장, 범위 제한, 상태 전환, 저장 이력, 선택 대사/이미지/이동을 지원한다. 여러 효과는 순서가 보이고 재배치할 수 있다. 일회 지급과 매번 계산하는 보정은 별도 효과 유형이다.

매번 보정은 해당 사건의 원래 계산 결과를 입력으로 사용한다. 재방문마다 저장값에 배수를 누적 적용하지 않는다. 우선순위·중복 모드의 같은 값 수정·상한 적용 순서를 비교 화면에서 확인한다.

### 실제 발동 위치

QSP에는 일반적인 이벤트 버스가 없으므로, 실제 소스의 연결 지점을 등록한 어댑터가 필요하다. 각 연결은 location·조건 문맥·전/후 삽입 위치·대상 인물·변경 변수·예상 일치 개수·소스 fingerprint를 가진다. 줄 번호만으로 연결하지 않는다.

첫 연결 목록은 실제 기존 제작 범위에서 시작한다: 인물 생성/기존 세이브 초기화, 상태 전환, 교육 결과/경험치, 보상/가격 계산, HUD/개인실 표시, 대사/선택지 진입. ‘결과 계산 전’, ‘성공 뒤’, ‘지급 직전’은 다른 시점으로 보인다.

등록되지 않은 시점도 원문에서 위치를 선택해 사용자 연결을 만들 수 있다. 모호한 문맥·여러 일치가 있으면 후보를 보여주고 선택하게 한다. 의미를 추측해 모든 호출부를 바꾸지 않는다. 동적으로 만들어지는 대상 등 GUI가 표현하지 못하는 부분은 원문 모드로 유지한다.

## 6. 기존 모드와 명기 가져오기

mods JSON과 현재 QSP를 함께 읽는다. 최신 소스가 기준이며 오래된 문서의 해시를 현재값으로 가정하지 않는다. 명기처럼 여러 패치에 나뉜 작업은 프로젝트 내 구성 요소로 묶어 보여준다.

1. 원본 QSP/등록된 패치의 관계와 실제 적용 상태를 확인한다.
2. 인식한 변수·상태·확률·효과·표시·발동 위치를 GUI 항목으로 가져온다.
3. 지원하지 못하는 조각은 ‘원문 유지’로 표시하고 원래 코드와 JSON 필드를 보존한다.
4. 편집하지 않고 저장/다시 열기/후보 생성하면 QSP는 바이트까지 같아야 한다. 자동 정리·변수 재명명·조건 이관을 하지 않는다.
5. 사용자가 한 값을 바꾸면 그 값과 필요한 연결 부분만 diff에 나타나야 한다. 기존 저장 키와 상태 번호를 몰래 새 체계로 옮기지 않는다.

가져온 프로젝트의 각 항목에는 ‘GUI 편집 가능 / 원문 유지 / 연결 확인 필요’를 표시한다. 부분 인식을 완전 편집 가능으로 표시하지 않는다. 명기 전용 편집기만 만들지 않고, 같은 모델로 새 특성을 빈 화면에서 제작할 수 있어야 한다.

## 7. 프로젝트 파일과 코드 생성

프로젝트는 일반 JSON과 로컬 자원 폴더로 저장한다. 필수 항목: schemaVersion, id/revision, 변수 바인딩, 상태/특성, 규칙, 초기화·이관, 발동 위치 연결, 표시·장면, 자원 원장, 적용 이력, 대상별 fingerprint. 자원 원장에는 상대경로·형식·크기·해시를 둔다.

GUI의 조건/효과 트리에서 QSP를 결정적으로 생성한다. 같은 입력은 같은 결과를 낸다. 사용자 원문 블록은 의미와 순서를 유지한다. 생성물은 기존 mods의 old/new/count 치환과 필요한 helper location으로 내보낸다. 게임이 프로젝트 JSON을 직접 읽는다고 가정하지 않는다.

프로젝트에는 원래 저장 위치와 편집용 논리를 함께 보관한다. QSP에 구현한 내용을 나중에 또 해석해야만 편집할 수 있는 구조를 피한다. 상태별 이름·아이콘 출력은 QSP에 생성하고 CSS로 문구를 숨겨 덮지 않는다.

원문 모드는 location 본문·설명과 본문 내 ACT/EXEC 등을 직접 편집할 수 있어야 한다. QSP 컨테이너의 별도 action 레코드는 현재 적용기가 지원하지 않으므로 첫 완성판의 GUI 작성 범위에서 분리해 명시한다. 자동 삭제하지 않으며 원본 왕복 보존은 필수다.

모드 패키지는 프로젝트 JSON + mods + 자원 + manifest + 적용/복원 설명을 담은 로컬 ZIP이다. 큰 이미지·게임 전체·세이브·백업·키는 Git 자동 저장 대상이 아니다. Git에는 프로젝트·패치·자원 원장·검증 기록을 저장한다. 이미지 전송은 사용자가 선택한 로컬 패키지/드라이브 절차로 분리한다.

## 8. 기존 세이브

프로젝트 전역 버전과 인물별 초기화/일회성 이력을 분리한다. 초기값 변경은 기존 인물 전체 덮어쓰기를 뜻하지 않는다. 새 인물만 / 기존 미초기화 인물 포함 / 명시적 이관 중 선택한다. 기존 값 유지가 기본이며, 이관은 값별 전후 목록으로 확인한다.

발견·시도 완료·일회 보상 지급을 별도 이력으로 저장한다. 저장/로드, 개인실↔동행↔조수↔보관, 화면 재진입, 패치 재적용에 따른 재추첨·중복 지급을 검사한다. 누락 키의 0과 실제 저장된 0을 구분해야 할 때는 별도의 초기화 버전 표시를 사용한다.

어댑터는 프로젝트 revision 변경에 필요한 동적 정의·화면 캐시의 일회 갱신도 정의한다. 세이브에 저장된 이전 코드가 새 수치를 무시하지 않도록 실제 $newloc 갱신 흐름과 연결하며, 기존 $ongload·$onnewloc를 임의로 덮어쓰지 않는다. 같은 revision 재진입에서는 이관·확률 판정·지급을 반복하지 않는다.

세이브는 QSP 변경과 별개다. 후속 저장 편집 기능은 확인된 저장 형식의 사본만 지원하고, 입력값 시험을 실제 세이브 실행 결과로 표시하지 않는다. 초기 완성판은 샘플 값과 실제 사용자 플레이로 검증 가능해야 하며 테스트 세이브 편집기 완성을 선행 조건으로 삼지 않는다.

## 9. 적용·복원

대상은 G:/somi/Jack O Nine Tails v2.4_work/game/jack.qsp와 G:/somi/Jack O Nine Tails v2.4 Kor_Full/game/jack.qsp를 각각 관리한다. 플레이본을 배포본에 통째 복사하지 않는다.

적용 순서:

1. 모드/대상/자원/후속 의존성 확인 → 현재 원본 해시·바이트 왕복 검사.
2. 대상별 별도 후보 생성. 치환 범위·개수·문자열·코드 블록·등록 발동 위치를 검사.
3. 공통 변경과 대상별 차이를 미리보기. 기존 코드에서 바뀌는 조건·수치·이동을 표시.
4. 모든 대상 후보와 자원을 준비한 뒤 원본을 다시 검사하고 백업 바이트를 검증.
5. 파일별 임시 후보 교체와 적용 journal 기록 → 다시 읽어 해시/참조 검사.
6. 결과를 대상·파일별로 표시하고 캐시/인덱스를 새로 만든다. 실패시 이미 바뀐 파일은 검증된 백업으로 복구를 시도하고, 복구 실패/부분 적용을 숨기지 않는다.

교체 전에 journal을 디스크에 기록한다. 파일별 생성/교체/유지, 기존 존재 여부, 전후 해시와 백업을 보관한다. 대상 루트를 벗어나는 자원 경로와 기존 파일의 다른 해시 충돌은 차단하고, 교체를 원하면 사용자가 명시적으로 교체 대상으로 지정해 다시 비교한다. 복구는 현재 파일 해시를 확인하고 수행한다. 새 파일은 도구가 생성한 경로와 해시가 journal에 일치할 때만 제거하며, 이후 사용자 작업이 있으면 보존하고 충돌을 보고한다.

여러 폴더의 QSP/이미지를 OS 차원에서 동시에 원자적으로 교체할 수 있다고 주장하지 않는다. 사전 준비와 복구 journal을 사용하는 다중 파일 적용이다. 종료/중단 후 재실행하면 journal과 현재 해시로 완료·복구·사용자 확인 필요 상태를 제시한다.

최근 적용의 복원은 현재 파일이 기록의 적용 후 해시와 같을 때 허용한다. 이후 수정이 있으면 이전 전체 백업을 덮어쓰지 않고 충돌을 표시한다. 모드 비활성화도 의존성 검사를 거치는 새 변경으로 처리한다. 모드를 제거한다고 저장된 세이브를 자동 원상 복구하지 않는다.

## 10. 시험과 품질 기준

첫 수락 시험은 중립적인 ‘행운’ 특성을 사용자 혼자 만드는 것이다. 저장 키·아이콘·발동 시점·25% 확률·지정 보상×2를 GUI로 정하고, 프로젝트 저장/재개방 → 후보 비교 → 플레이 적용 → 재적용 → 복원까지 끝낸다.

필수 시험:

- GUI→프로젝트→QSP 생성→다시 열기 후 의미/값 유지. 무수정 가져오기는 전체 바이트 불변.
- 확률 0/100/경계 표본, 성공/실패, 최초 시도와 최초 성공의 구별, 표시 갱신에서 재추첨 없음.
- 숫자/문자열 인자, 기존 범위와 상한, 정수 나눗셈, 효과 순서, 일회 보상, 배수 비누적.
- 기존 세이브 값 보존·초기화 버전·인물 역할 이동·표시 이름/아이콘 연결.
- BG 고정 + 단계별 CG/PNG/GIF, 선택지 의미별 색상, 기존 이미지와 경로 보존.
- 겹치는 패치, 원문 수정 후 적용, 대상별 서로 다른 원본, 자원 누락, 잠긴 파일, 중간 쓰기 실패, 복구 실패를 재현.
- 브라우저 조작 시험과 실제 게임 플레이 시험은 별도 기록. 소스 왕복 검사를 QSP 전체 문법/동작 보증으로 표현하지 않는다.

## 11. 개발 순서와 첫 완성판 범위

1. 프로젝트 저장·기존 변수 바인딩·최소 QSP 패치·대상별 후보/적용/복원부터 관통한다.
2. 조건/효과 편집기와 등록 발동 지점, 초기화/일회성 이력을 연결한다. 조건·효과·저장 이력의 부분 시험을 완료한다.
3. 이름·아이콘·HUD·대사·선택지·CG 편집을 같은 프로젝트에 연결하고 명기 프로젝트를 가져와 검증한다. 이 단계까지 통합한 뒤 새 특성 제작 전체 수락 시험을 수행한다.
4. 분기 한눈에 화면·원문 병행·패키지 내보내기까지 통합해 첫 완성판으로 제공한다.

이 네 단계를 첫 완성판의 하나의 목표로 본다. 읽기 전용 시안이나 수치 입력만 되는 중간판을 독립 제작 가능하다고 보고하지 않는다. 후속 확장은 등록 시점 확대, 복잡한 동적 코드 분석, 별도 action 레코드 GUI, 테스트 세이브 편집 등이다. 새 게임 모드 본체는 이 편집기와 구분한다.
