# 인물 상태 편집기 — 분류와 첫 범위

2026-10-16 · 기존 범용 Mod Studio 설계의 범위를 좁히는 제안 / 편집기 구현 전

## 방향

모든 변수와 정의를 하나의 GUI에 넣는 범용 편집기 확장은 보류한다. 먼저 게임의 정의를 종류별로 분류하고, 이번 도구는 **인물에 귀속된 상태 체계**만 편집한다. 명기를 첫 대상으로 삼는다. 개발자가 최초 상태 체계와 게임 연결을 제공하고, 사용자가 그 구조 안의 상태·전환·표시·효과를 편집하는 기존 역할 분담은 유지한다.

## 명기는 무엇인가

**명기는 기존 인물 상태 축에 추가한 특수 상태이며, 발견 이력과 여러 연결 규칙을 함께 가진 기능이다.** 편집기에서는 이를 ‘인물 상태형 기능’으로 분류한다. 이 이름은 편집기의 분류명이며 QSP 엔진의 새 자료형이나 게임에 이미 존재하는 공통 등록 규격을 뜻하지 않는다.

| 관점 | 현재 구현 |
|---|---|
| QSP 저장 형식 | 인물 배열의 숫자 값 |
| 현재 상태 | `인물['virginity']=4` |
| 상태 체계 | 하나의 상태 축에서 코드 0~4 중 현재 코드 하나를 가짐 |
| 발견 이력 | `jo9_meiki_known` — 현재 상태와 별도로 보존 |
| 최초 판정 여부 | `jo9_meiki_checked` — 실패해도 판정 완료 이력을 유지 |
| 이전 상태 | `jo9_meiki_prev` — 상태가 바뀌었는지 검사 |
| 초기화/지급 단계 | `jo9_meiki_initialized` — 0/1/2를 사용하는 처리 버전. 단순 체크박스가 아님 |
| 연결 내용 | 전환 판정, 상태 보존, 표시명·아이콘, 일회 지급, 교육·거래 등의 기존 효과 |

현재 상태와 발견 이력은 다르다. 다른 상태를 거쳐도 발견 이력은 남을 수 있으므로, 현재 코드 하나만 편집하는 방식으로는 전체 규칙을 표현할 수 없다. 현재 생성 JSON에 명기 항목을 추가해 둔 구조나, 공통 trait 테이블에 독립 항목 하나를 등록한 구조도 아니다.

## 다른 종류와 구분

| 정의 종류 | 다루는 내용 | 이번 편집기 |
|---|---|---|
| 인물 상태 체계 | 코드별 상태, 전환, 이력, 표시, 연결 효과 | 대상. 최초 등록 대상은 현재 명기와 그 상태 축 |
| 독립 특성 | 특성별 별도 필드·발견 여부. 여러 특성이 함께 존재 가능 | 별도 유형으로 분류. 이 상태 편집기에 자동 포함하지 않음 |
| 능력치·기술 | 수치, 등급, 경험치 | 상태에 연결된 기존 효과의 수정 대상으로 선택. 전체 능력치 편집기는 아님 |
| 종류·원형 코드 | 생성 템플릿·인물 분류 등 | 별도 유형 |
| 생성 프로필 | 새 인물의 초기값과 생성 데이터 | 별도 유형 |
| 세이브 현재값 | 특정 인물의 현재 상태를 직접 변경 | 별도 기능. 이번 소스 규칙 편집과 구분 |

어떤 기존 정의가 같은 편집기로 처리 가능한지는 이름이 아니라 저장·전환·이력·출력 구조를 보고 판정한다. 이번 조사에서 모든 신체/생리 상태가 같은 구현 구조라고 확인한 것은 아니다. 새 상태 체계를 처음 연결하는 작업은 개발자가 담당한다.

## 편집 화면의 단위

선택 항목은 낱개 변수 하나가 아니라 **상태 체계 하나**다. 그 안의 상태 행을 골라 관련 규칙을 편집한다.

1. **상태표:** 내부 코드, 의미, 표시명, 설명, 아이콘. 표시 수정과 내부 코드 재매핑을 구분한다.
2. **전환:** 현재 상태 → 다음 상태, 실제 발동 지점, 조건, 확률, 판정 횟수와 재판정 규칙.
3. **이력과 유지:** 발견 여부, 최초 판정 완료, 이전 상태, 초기화/지급 버전과 상태 이동 후 유지 규칙.
4. **연결 효과:** 해당 상태/이력을 검사하는 기존 효과, 설정/증감/배수/하한/상한, 적용 순서와 일회/반복 구분. 기술·가격·대사는 연결된 항목만 연다.
5. **검증:** 전환 전후의 상태·이력·표시·효과 비교, 수정 위치와 미수정 범위, 원본/복제본 충돌 검사.

현재 명기는 여러 소스에 분산되어 있으므로, 먼저 관련 위치를 이 상태 체계의 연결 목록으로 묶는다. 항목 수를 임의의 몇 개 숫자로 제한하지 않고, 이 종류의 상태가 가진 편집 가능한 구성 전체를 보여준다. 미연결 항목을 작동하는 편집란으로 표시하지 않는다.

## 대상의 의미

이 편집기는 QSP의 상태 규칙을 바꾼다. 특정 세이브의 인물 한 명이나 전 인물의 현재값을 즉시 바꾼다는 뜻이 아니다.

- **연결 역할:** 현재 명기 helper는 `slave`(현재 동행 역할 슬롯), `assistant`, `room1~4`를 처리한다. `slave`는 ‘전체 노예’가 아니다.
- **효과의 대상:** 그 상태를 가진 인물 자신, 해당 사건의 상대/거래 계산 등 기존 연결이 가리키는 대상이다. 역할 연결과 분리해 표시한다.
- **보유 인물 전체:** 별도 열거·중복 처리·이관 규칙이 필요한 작업이다. 역할 선택 하나로 자동 지원한다고 표시하지 않는다.
- **적용할 게임 설치본:** 플레이/배포 폴더 선택이며 인물 대상과 다른 설정이다.

## 편집·추가·복제의 경계

‘새로 추가’는 유지하되 무엇을 추가하는지 구별한다.

- **같은 상태 체계의 상태 행 추가:** 기존 상태와 같은 저장 축의 새 코드다. 해당 축 안에서 상호 배타적이며, 기존 비교식·전환·표시·이관에 미치는 영향을 검증해야 한다.
- **상태 체계 자체의 독립 복제:** 별도 저장 축과 이력·표시·전환 연결이 필요하다. 복제를 지원하도록 개발자가 등록한 프로토타입에서 제공한다.
- 현재 명기를 복사해 모두 `virginity=4`와 같은 이력 키를 쓰는 방식은 독립 복제가 아니다. 지원 연결이 없는 독립 복제는 구현되어 있다고 표시하지 않는다.

상태 행 추가도 해당 체계의 확장 규칙이 등록된 경우에 제공한다. 새 코드는 기존 범위 비교·정규화·전환·표시·이관 규칙과 함께 생성·검증하며, 표에 행을 추가하는 것만으로 작동한다고 표시하지 않는다.

내부 코드와 저장 키는 고급 구조 편집으로 구분한다. 표시명을 바꾸다 내부 값까지 바뀌지 않게 하며, 실제 재매핑을 요청한 경우 관련 참조·세이브 이관을 비교할 수 있어야 한다.

## 첫 완성판의 기준

현재 명기 상태 체계를 불러와 상태표·전환·이력·연결 효과를 확인하고, 표시명/아이콘·확률·등록된 조건/효과 수치를 편집 → 비교 → 프로젝트 저장/재개방 → 대상별 후보 생성 → 적용/복원까지 연결한다. 이름만 다른 복사본, 예시 값 필터, 게임에 연결되지 않은 입력란을 실제 기능 완성으로 계산하지 않는다.

현재 문서는 분류와 범위 설계다. 실제 편집기 구현, 게임 연결, 게임 플레이 검증은 완료되지 않았다. 범용 도구 전체 구현과 세이브 일괄 편집은 이번 첫 범위가 아니다.
