# 파산 전 자산 처분 구현 계획

> **For agentic workers:** 직접 구현과 모듈 병렬 작성, 독립 검토로 진행한다.

**Goal:** 청구서를 낼 현금이 부족해도 남은 자산을 처분해 같은 턴에 운영을 이어간다.
**Architecture:** 청구 상태 조정자 jo9_liquidation, 자산 조정자 jo9_liquidation_assets, 급매 평가·처분 jo9_liquidation_sale을 추가한다. 기존 결산·하루 진행·불러오기 경계만 연결하고 전역 사망 처리는 유지한다.
**Tech Stack:** 기존 QSP/FastQSP, 선언형 mods JSON, Node 검사 스크립트.
**Spec:** ../specs/2026-10-23-insolvency-liquidation-design.md

## Global Constraints
WORK만 최종 검증 후 적용. 기존 세이브 보존. 중복 환급·청구 방지. 인물이 있는 시설 처분 금지. 새 NPC·상시 UI 버튼·커밋·푸시 없음.

## Review Focus
- 결산 진입·재방문·세이브 재개에서 비용과 축사 수익이 중복되지 않는다.
- 기절·사망 인원도 빈 슬롯이 아니며 시설 처분으로 사라지지 않는다.
- 장식 최소형·재입주·재구입과 철거 재클릭에서 중복 환급이 없다.
- 구매자 조회가 평판과 인물 상태를 바꾸지 않는다.
- 미납 중 강제 하루 이동이 순환 호출이나 기존 인원 삭제를 일으키지 않는다.
