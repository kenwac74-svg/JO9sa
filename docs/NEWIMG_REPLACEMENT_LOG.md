# JO9 신규 이미지 교체 패치 기록

기록 시작일: 2026-09-25 (Asia/Seoul)
작업 브랜치: `newimgadd`

## 작업 범위

- 게임의 기존 이미지를 새로 제작한 이미지로 교체하는 패치를 작성한다.
- 교체 내역과 패치 산출물의 상태를 이 문서에 누적 기록한다.
- 사용자 지시 없이 `main`, `JO9UIpatch`, `JO9imgtool` 등 다른 브랜치를 수정하거나 병합하지 않는다.
- UI 패치(FIX5 기준)와 이미지편집툴 소스 작업은 각 브랜치에서 관리하며 이 브랜치에 포함하지 않는다.

## 독립 정책 (2026-09-25 사용자 확정)

이 브랜치의 산출물은 **원본 이미지를 교체하는 순수 이미지 교체 팩**이다.

- QSP를 전혀 건드리지 않는다. `jack.qsp`, `.qsrc`, 이미지 참조 경로, 이벤트 연결은 변경 대상이 아니다.
- 실행 파일을 건드리지 않는다. `jack.exe`, `Jack-o-nine-tails.exe`, 엔진 파일은 패치에 넣지 않는다.
- 세이브 파일을 추가하거나 바꾸지 않는다.
- `game/content/pic` 아래에 이미 있는 원본 이미지를 같은 경로·같은 파일명으로 교체하는 것만 다룬다. 새 경로나 새 파일을 추가하지 않는다.
- **사이즈 불일치 처리:** 사용자가 준 이미지의 가로·세로가 원본과 다르면 자동으로 늘리거나 자르지 않는다. 원본 크기와 받은 크기를 사용자에게 알리고, 사용자가 조치를 정할 때까지 그 항목은 패치에 넣지 않고 기다린다.

## 기록 원칙

- 교체 대상마다 게임 내 원래 경로를 그대로 쓴다. 경로를 바꾸면 기존 참조가 끊긴다.
- 원본과 신규 이미지의 바이트 수, 가로·세로 크기, SHA-256을 함께 적는다.
- 원본 크기와 신규 크기가 다르면 상태를 `사이즈 확인 대기`로 두고, 사용자가 정한 조치를 비고에 적는다.
- 교체 대상의 원본 백업 여부는 아래 미결 사항에서 확정한다.
- 공용 이미지를 교체하면 그 이미지를 쓰는 다른 화면에도 영향이 간다. 확인한 범위를 비고에 적는다.
- 파일 저장, 패치 설치, 게임 실행 검증은 각각 따로 표시한다. 하나가 끝났다고 다른 단계까지 완료로 적지 않는다.

## 상태 표기

| 표기 | 뜻 |
|---|---|
| 미확보 | 파일을 아직 받지 못함 |
| 확보 | 작업 공간에 파일이 있고 해시를 계산함 |
| 사이즈 확인 대기 | 원본과 가로·세로가 달라 사용자에게 알렸고 조치를 기다림 |
| 저장 | 이 브랜치에 커밋·푸시함 |
| 설치 | 패치를 게임 폴더에 적용함 |
| 검증 | 게임 안에서 표시를 확인함 |

## 참조: 이미지편집툴의 교체 구조

사용자가 제공한 참조본이다. 이 브랜치에 저장하지 않았고 그 소스를 수정하지 않는다.

- 파일: `JO9_ImageWorkshop_v1.1.2_PIC_TOP_R1_INSTALL_20260925.zip`
- ZIP SHA-256: `559ee27d63da285b2d4bf2122c8b78a64b6b5f630b22319c2b8abf393dc39fae`
- 31개 항목, CRC 검사 통과. 버전 `v1.1.2 Patch Manager + PIC_TOP_R1`.

아래는 `payload/modtools/place/JO9_Place_Workshop.html`의 `JO9Core`와 설치 스크립트를 코드로 읽어 확인한 내용이다. 실행해서 검증한 것은 아니다.

### 이미지 교체 규칙

- 교체 범위는 `game/content/pic` 폴더다. 대상 경로는 `pic` 기준 상대 경로이고, `..`·절대 경로·역슬래시는 거부한다.
- 교체는 같은 경로에 덮어쓰는 방식이다. 새 경로를 만들거나 QSP 참조를 바꾸지 않는다.
- PNG만 다룬다. 움직이는 PNG(`acTL`)는 거부한다.
- 새 이미지의 가로·세로는 원본과 정확히 같아야 한다. 원본 크기에 맞춰 캔버스에 다시 그린다(`stretch`/`contain`/`cover`, 확대·이동, 흑백·세피아·밝기).
  - 이 브랜치에서는 이런 자동 맞춤을 하지 않는다. 사이즈가 다르면 위 독립 정책에 따라 사용자에게 알리고 기다린다.
- 용량 상한이 있다. `ui` 80 KB, 초상화 160 KB, NPC 680 KB, 그 밖에는 680 KB 또는 1200 KB 중 선택한다.
- 테두리가 있는 규격은 원본 테두리를 남기고 안쪽만 바꾼다.
  - `ui overhaul/`의 59×66 아이콘: 안쪽 49×51, 모서리 반경 3
  - `girls/face/`와 `mob/*_ava.png`의 150×150: 안쪽 140×140
- 새 파일은 먼저 경로가 맞는지 보고, 없으면 같은 파일명, 그다음 확장자를 뺀 이름으로 대상을 찾는다. `_gray`·`_sepia`·`_ava` 베리에이션은 같은 이름으로 묶는다.

### 쓰기 순서

1. 대상 전체를 읽어 SHA-256을 확인한다. 변환 후 원본이 바뀌었으면 중단한다.
2. `pic/__JO9_ImageBackups/<시각_id>/original/`에 원본을 복사하고, `manifest.json`에 경로와 before·after 해시를 기록한다.
3. 쓰기 직전에 원본 해시를 다시 확인하고, 쓴 뒤에는 다시 읽어 해시를 대조한다.
4. 실패하면 백업본으로 되돌린다. 기록 상태는 `preparing → prepared → applying → applied`, 복구할 때는 `restoring → restored`로 바뀐다.
5. 원본을 찾지 못한 항목은 완성본 ZIP으로만 저장할 수 있다.

### 대상 감지

- `JO9_Detect.ps1`이 게임의 Show HTML을 캡처해 `content/pic/` 참조만 뽑는다. 결과는 `runtime/context.json`에 기록된다.
- 기본으로 숨기는 대상은 `filters.json`에 있다. `pic` 루트, `ui`, `buttons` 폴더와 `money_counter*`, `menu_button*`, `padding*`, `hurt_*`, `A_P1*` 패턴이다.

### 설치 관리자

- `payload/install_manifest.json`에 적힌 파일만 복사하고, 복사한 뒤 SHA-256을 대조한다.
- `game/modtools` 폴더 전체를 지우지 않는다. 비순정 `jack.exe`가 있으면 경고하고, `YES`를 입력해야 진행한다.
- 순정 복구는 `jack.exe`를 2.3 순정으로 되돌리고 도구가 소유한 파일만 지운다. `content/pic`, 세이브, `jack.qsp`는 건드리지 않는다.

### 참조본에 적힌 정책 (2026-09-25)

- 사용자가 이미지를 교체할 때는 원본 백업을 만들지 않는 방향으로 정했다. 코드에는 아직 반영되지 않았다.
- 백업은 도구·패치를 설치하고 삭제할 때 되돌리기 위한 변경분에만 둔다.

## 참조: Individuality Patch Installer (대조용)

사용자가 Google Drive에서 가리킨 참조다. 이 브랜치의 패치와 성격이 다른 예로 기록한다.

- 링크된 파일: `JoNT_IndividualityPatchInstaller.zip` (38,266,440 bytes, Drive 수정 2026-09-19)
  - 연결된 Drive 도구의 다운로드 한도(10 MB)를 넘고, 작업 환경에서 Google 직접 접속은 프록시 403으로 막혀 **ZIP 원본은 열지 못했다.**
- 대신 Drive에 이미 풀려 있는 `JoNT_IndividualityPatchInstaller_3_2_0` 폴더와 `individuality_patch_data` 폴더를 읽었다. 링크된 ZIP과 같은 버전인지는 확인하지 못했다.

확인한 구조는 다음과 같다.

- Qt 기반 `patch_installer.exe`와 `InstallerGuide.pdf`로 구성된다.
- "Apply the patch"로 게임에 패치를 적용하고 "Restore vanilla version"으로 되돌린다. 적용하면 `patched_girls.sav` 세이브가 추가된다.
- 이미지 팩은 노예별 ZIP이고, `pack_info.json`, `face/`, `fullbody/`, `scenes/` 폴더로 되어 있다. `custom_slave_data`가 있는 팩은 게임에 새 노예를 추가한다.
- `individuality_patch_data/<id>/<id>.json`은 노예 ID별로 `girls/full/...`, `girls/face/..._sepia`, `_gray` 같은 이미지 경로와 체형 값을 지정한다.
- 가이드는 "파일 이름과 크기는 신경 쓰지 말라, 설치할 때 이름을 바꾸고 크기를 자동으로 맞춘다"고 설명한다.

이 브랜치와 다른 점은 다음과 같다.

| 항목 | Individuality Patch | 이 브랜치의 이미지 교체 팩 |
|---|---|---|
| 게임 데이터 | 패치 적용, 세이브 추가, 새 노예 추가 | QSP·실행 파일·세이브를 건드리지 않음 |
| 이미지 경로 | 노예별로 새 경로를 지정 | 기존 경로·파일명 그대로 덮어씀 |
| 크기 | 설치할 때 자동 조정 | 자동 조정 없음. 다르면 사용자에게 알리고 대기 |

## 미결 사항

- 교체 대상 이미지 목록과 신규 이미지 파일
- 패치 형식(단순 덮어쓰기 ZIP, 설치/복구 스크립트 포함 여부). 스크립트를 넣더라도 QSP·실행 파일은 건드리지 않는다.
- 원본과 파일 형식이 다른 이미지(JPG 등)를 받았을 때의 처리
- 원본 백업 여부. 참조본의 무백업 정책을 이 패치에도 적용할지, 설치 관리자처럼 패치 삭제용 원본을 둘지 정해야 한다.
- 기준으로 삼을 게임 원본 버전
