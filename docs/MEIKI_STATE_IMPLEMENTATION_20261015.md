# 상태 보존과 발견 판정 적용 기록

2026-10-15 플레이·배포 QSP에 각각 패치를 적용했다. 두 설치본의 기존 차이를 유지했으며 원본 JO9O, 기존 hbe 세이브, CSS 2.4는 수정하지 않았다. 실제 게임 실행 확인은 사용자에게 남아 있다.

## 반영한 동작

- 상태 0에서 지원되는 성인·동의 경로로 최초 전환할 때 1~100 중 1~5만 발견한다. 판정은 한 번이며 실패 후 다시 시도하지 않는다.
- 상태 1 해제에서는 새 발견 판정이 없다. 이전 발견 이력이 있으면 상태 4로 돌아온다.
- 발견 이력을 `jo9_meiki_known` 키에 저장하고, 상태 2·3으로 덮어쓰이면 4로 정규화한다. 알려진 특성이 일일 처리에서 상태 3으로 강제 변경되는 경로도 막았다.
- 기존 세이브의 이미 비처녀인 캐릭터에는 소급 추첨하지 않는다. 기존 상태 4는 발견 이력으로 인식한다.
- 최초 갱신 때 저장된 동적 함수 정의를 갱신한다. 주인공·일반 생성 stock의 상태는 새 helper 대상이 아니다. 역할은 slave·assistant·room1~4다.
- 기존 +1 보정 helper의 숫자 인자를 `$args[1]`로 읽던 오류를 `args[1]`로 고쳤다. 기존 모델 검사는 숫자·문자 슬롯을 구분하지 못했으므로 해당 검증 주장도 이 검사로 보완한다.

지원 경로의 제한과 기술 등급 보정 미구현은 [사례 문서](AI_POLICY_CASE_20261015.md)에 구분했다. 특성의 영구 보존은 동의 여부에 따라 특성이 사라지도록 만드는 설정 변경이 아니다.

## 검증과 한계

각 설치본에서 QSP 250 locations 바이트 왕복, 예상 해시 일치, 상태 소스 모델 630건, 기존 보정 소스 모델 36건 검사를 통과했다. 최초 판정 1~100 전부에 대해 정확히 5개 성공·95개 실패를 확인하고 재판정·복원·기존 세이브·역할 복사 관련 이력을 검사했다. 코드 리뷰에서도 배포 차단 결함은 발견하지 않았다.

검사는 실제 helper를 제한된 JavaScript 모델로 실행한 결과다. QSP 엔진의 문법·콜백·저장·화면 실행 성공을 입증하지 않는다. 진단 세이브는 상태 처리 전용이며 일반 플레이나 결과 +1, 기술 등급을 검증하지 않는다. 기술 S+·S++ 및 단체 하위 기술 +1은 아직 구현하지 않았다.

## 진단 세이브 사용

두 게임의 `game/save/JO9_MEIKI_STATE_TEST_20261015.sav`를 불러온다. 기존 hbe와 다른 이름이며 원본은 수정하지 않았다. 이 파일은 등장인물의 장면을 여는 일반 플레이용이 아니라 숫자 상태를 검사하는 독립 진단 복사본이다. 버튼은 진단 복사본의 배열만 바꾼다.

1. **1 → 2**: 성인 진단 데이터 초기화 후 최초 전환. 대부분 상태 2이며 5%만 4가 된다. 2번을 반복해도 재추첨하지 않는다.
2. **1 → 3 → 4 → 5**: 알려진 상태 4 준비, 복원상태 1, 해제 후 다시 4. 새 판정은 없다.
3. **1 → 4 → 5**: 발견 이력이 없으므로 상태 2. 복원 해제로 새 발견하면 안 된다.
4. **3 → 6**: 상태 3으로 덮어쓰기를 시도해도 4.
5. **3 → 7**: 조수 배열로 복사한 뒤 상태 4·발견 이력 1.
6. 실제 저장 유지 확인은 게임의 별도 새 슬롯에 저장·로드한 뒤 현재 값 확인을 누른다. 기존 사용자 슬롯에는 덮어쓰지 않는다.

진단 종료는 다른 일반 세이브 불러오기다. 일반 플레이 확인은 성인 대상의 지원 경로에서 별도로 해야 한다. 5%는 소수의 수동 클릭으로 성공률을 검증할 수 없으며 자동 경계값 검사를 참고한다.
