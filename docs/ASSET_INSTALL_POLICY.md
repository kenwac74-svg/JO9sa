# 잭오나 모드 — UI/UX와 일반 이미지의 설치·복구 정책

기록일: 2026-09-25 (Asia/Seoul)
작업 브랜치: `JO9UIpatch`
구현 출발점: 사용자가 직접 첨부한 FIX6. 원본 패키지는 변경 없이 보존한다.
상태: 사용자 확정 방침과 설치 안내 문구를 기록한 문서. 설치기·QSP·CSS·이미지 파일 변경 또는 실행 검증 완료를 뜻하지 않는다.

## 1. 사용자 확정: 두 체계로 분류

분류 기준은 현재 폴더 이름이나 파일 크기의 임계값이 아니라 이미지의 용도다. 여러 위치에 흩어진 UI/UX 자산을 모드 전용 위치로 모으되, 일반 이미지를 복제해 보관하는 구조는 만들지 않는다.

| 구분 | UI/UX — 복구형 | 일반 이미지 — 교체형 |
|---|---|---|
| 대상 | 버튼, 패널, 상태 표시, UI 배경 등 UI/UX 자산 및 아래 예외 | UI/UX가 아닌 캐릭터·NPC·일반 배경 등 |
| 설치 | 모드 전용 폴더에 추가하고 QSP의 해당 참조 경로를 변경한다. CSS 등 실제 참조부도 필요한 범위에서 대응한다. | 기존 경로와 파일명을 유지해 선택한 이미지를 덮어쓴다. |
| 원본 | 기존 UI 이미지 파일을 덮어쓰거나 이동·삭제하지 않는다. | 기존 이미지가 교체된다. 설치기가 원본 이미지의 백업·복구용 사본을 만들지 않는다. |
| 복구 | UI/UX 연결 변경을 되돌려 설치 전 UI를 표시할 수 있게 한다. | 패치의 자동 원본 복구 기능을 제공하지 않는다. |
| 선택 사용 | 일반 이미지 교체와 독립적으로 설치·복구할 수 있게 한다. | 일괄 교체는 편의 기능이며 필수가 아니다. 원하는 그림만 골라 수동 교체할 수 있게 한다. |

일반 이미지 교체를 위해 QSP의 해당 이미지 경로를 바꾸지 않는다. 기존 파일 경로와 이름에 의존하는 수동 교체 사용법을 유지한다.

## 2. BG 폴더는 파일별로 분류

`bg`에는 UI/UX 배경과 일반 배경이 섞여 있다. `bg` 안의 모든 그림은 각각 해당하는 정책을 따르며, 폴더 전체에 하나의 설치·복구 정책을 적용하지 않는다.

사용자가 UI/UX로 지정한 예외:

- BG 폴더 내 번역된 이미지.
- 트로피룸 관련 UI/UX 리소스.

위 예외 외에도 UI/UX 용도의 배경이면 UI/UX 정책을 적용한다. 일반 배경이면 기존 경로 덮어쓰기·무백업 정책을 적용한다. 파일이 크더라도 UI/UX 용도를 우선한다.

구현 시 해당 자산의 실제 경로·파일명과 적용 정책을 설치 목록에 명시한다. 아직 확인하지 않은 파일명을 확정 목록처럼 만들지 않는다. UI/UX 목록과 일반 이미지 교체 목록은 중복되지 않아야 한다. 취소된 전체 이미지 참조 카탈로그 작업을 재개하는 것은 아니다.

## 3. 일반 이미지 교체 동의

자동 설치에서 일반 이미지 파일을 덮어쓰기 전에 별도 동의를 받는다. UI 설치 승인이나 통합 패키지 실행 자체를 일반 이미지 교체 동의로 간주하지 않는다.

동의 질문의 핵심 문구:

> 원본이미지 교체에 동의하십니까?

질문과 함께 표시할 안내:

> 캐릭터·NPC·일반 배경 이미지를 기존 파일에 덮어씁니다. 현재 설치된 다른 이미지팩의 그림도 대상 경로가 같으면 교체됩니다. 원본 이미지는 백업하지 않으며, 이 패치로 자동 복구할 수 없습니다. 일괄 교체 대신 제공된 이미지 중 원하는 파일만 골라 수동으로 교체할 수도 있습니다.

명시적으로 승인한 경우에만 일반 이미지 쓰기를 수행한다. 거절·취소·동의가 없는 입력은 교체 허가가 아니다. 일반 이미지 교체를 승인하지 않아도 UI/UX만 설치할 수 있어야 한다. 버튼 형태와 입력 방식 등 구체적인 설치 화면은 후속 구현에서 정한다.

수동 복사는 설치기 밖에서 사용자가 직접 수행하는 작업이므로 설치기 동의창이 표시되지 않는다. 수동 교체 안내문에도 동일한 덮어쓰기·무백업·자동 복구 불가 내용을 표시한다.

## 4. 배포와 수동 교체

한 패키지로 제공하더라도 UI/UX 설치 자료와 일반 이미지 교체 자료를 구분한다. 패키지 전체를 게임 폴더에 무조건 덮어쓰는 절차로 안내하지 않는다.

일반 이미지는 기존 게임의 상대경로와 파일명을 유지해 제공한다. 사용자는 원하는 이미지만 골라 같은 상대경로에 복사할 수 있어야 한다. 선택하지 않은 이미지는 변경하지 않는다. 특정 그림의 수동 교체를 위해 전체 설치기 실행이나 QSP 수정이 필요해서는 안 된다.

UI/UX 원본 무수정 원칙과 일반 이미지 무백업 원칙을 혼용하지 않는다. 일반 이미지용 백업·자동 원본 복구 기능을 필수 요구로 다시 추가하지 않는다.

## 5. 제거와 복구의 의미

UI 복구는 게임 전체 순정화를 뜻하지 않는다. UI/UX 변경을 해제한 뒤에도 사용자가 교체한 캐릭터·NPC·일반 배경 이미지는 그대로 남는다. UI 제거기가 일반 이미지를 삭제하거나 과거 그림으로 되돌려서는 안 된다.

UI 연결 복구에 필요한 작은 QSP/CSS 변경 기록의 보존은 일반 이미지 원본 백업 금지와 별개다. 다른 모드의 변경을 지우는 과거 QSP 전체 덮어쓰기를 무조건적인 제거 절차로 삼지 않는다.

QSP만으로 모드 CSS까지 해제할 수 있는지는 실제 연결 구조를 검증해야 한다. 확인 전에는 'QSP 하나만 원복하면 전체 순정 복구'라고 안내하지 않는다.

기존 FIX6 설치로 이미 교체된 UI 원본의 전환 복구는 별도 확인 대상이다. 새 모드 폴더를 만든 것만으로 이전에 덮어쓴 원본이 복원됐다고 표시하지 않는다. 기존 백업의 일괄 삭제는 이번 지시의 범위에 포함되지 않는다.

## 6. 설치 안내문 반영용 문안

> 이 패키지는 UI/UX 패치와 선택형 이미지 교체팩으로 구성됩니다.
>
> **UI/UX 패치**는 모드 전용 폴더를 사용하며 기존 UI 이미지를 덮어쓰지 않습니다. UI 복구 기능으로 UI/UX 변경을 되돌릴 수 있습니다. BG 폴더의 번역 이미지와 트로피룸도 UI/UX에 포함됩니다.
>
> **캐릭터·NPC·일반 배경 이미지**는 기존 파일을 교체합니다. 원본 이미지를 백업하지 않으며 자동 원본 복구 기능을 제공하지 않습니다. 일괄 교체는 선택 사항이며, 원하는 그림만 골라 기존 경로에 수동으로 교체할 수도 있습니다. 자동 설치에서는 '원본이미지 교체에 동의하십니까?'에 승인한 경우에만 교체합니다.
>
> UI/UX를 제거하거나 복구해도 교체된 캐릭터·NPC·일반 배경 이미지는 그대로 유지됩니다.

위 문안은 새 구조를 구현·검증한 배포본에 사용할 문안이다. 기존 FIX6가 이미 이 구조로 동작한다고 설명하는 문안이 아니다.

## 7. 확정 경로: 기본은 원본 구조 유지, 예외는 사용자 지정

사용자가 만든 UI/UX 루트는 `game/SNKmod/content/pic/`이다. 정확한 폴더명은 `SNKmod`이며, 앞선 `content/JO9UIpatch/` 제안은 사용하지 않는다.

사용자가 보여 준 기본 구조:

```text
game/SNKmod/content/pic/
├─ buttons/
├─ ui/
├─ ui overhaul/
└─ bg/
   ├─ slave_psychology/
   └─ trophy/
```

대부분의 UI/UX는 기존 상대경로와 파일명을 유지한 채 SNKmod 아래의 같은 폴더에 배치한다.

```text
기존 UI 위치: game/content/pic/<기존 상대경로와 파일명>
모드 UI 위치: game/SNKmod/content/pic/<같은 상대경로와 파일명>
```

이 규칙은 UI/UX로 분류한 대상에만 적용한다. 일반 배경이나 캐릭터·NPC까지 SNKmod로 복제하거나 참조 경로를 전환하지 않는다.

엉뚱한 위치에 흩어진 UI의 정리 경로는 사용자가 패키징 시 별도로 지정한다. 사용자 지정 경로가 있으면 기본 경로 규칙보다 우선하고, 지정한 목적지에 맞춰 해당 QSP/CSS 참조를 연결한다. 지정하지 않은 UI는 기본적으로 원본 상대경로를 유지한다.

중복 파일도 이름이나 내용이 같다는 이유만으로 임의 통합·이동·개명하지 않는다. 경로 통합이 필요한 경우 사용자 지정에 따른다. 앞서 제안했던 중복 파일 자동 통합은 승인된 요구로 취급하지 않는다.

패키징 시 대상별로 기존 경로, UI/UX 또는 일반 이미지 정책, 설치 경로를 기록한다. 기본 규칙으로 정해지는 경로를 사용자에게 하나씩 다시 입력하도록 요구하지 않는다. 분류가 불분명하거나 지정 경로가 충돌하는 등 필요한 항목만 확인한다.

## 8. 남은 구현 확인

사용자에게는 미결정 사항만 하나씩 확인받는다. 위에서 이미 확정한 두 체계와 경로 규칙을 다시 승인받지 않는다.

- BG 파일별 정책과 실제 대상 목록: 제공 자료 및 사용자 지정 기준으로 기록한다.
- 산재된 UI의 예외 경로: 패키징 시 사용자가 제공한 경로를 적용한다.
- QSP/CSS 참조 전환과 UI 복구: 실제 코드와 설치 상태 기준으로 구현·검증한다.
- 일반 이미지 자동 교체: 승인 전 파일 쓰기 없음, 승인한 대상만 교체, 원본 백업 생성 없음, UI 제거의 영향 없음 등을 검증한다.

SNmod 이벤트 컷신 고유화와 이미지편집툴 자체의 백업 정책은 별도 채팅의 작업이다. 이번 배포 정책을 이유로 그 도구의 기존 동작이나 문서를 임의로 바꾸지 않는다.
