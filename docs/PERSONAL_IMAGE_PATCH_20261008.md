# 개인 작업 이미지 자동 기록 및 패치

이미지 교체 도구의 성공한 저장과 B/C/D 컷 추가를 자동 기록한다. 완료 체크, 파일 수정시각, 다른 이미지팩 설치만으로는 개인 제작이라고 판단하지 않는다. 워크샵 밖에서 직접 배치하는 작업도 배치 직후 personal-patch.cjs의 record를 호출해야 한다.

기록 위치: 활성 catalog/image_work/personal-patch. settings.json에 추적 시작 UTC 시각, events.jsonl에 작업 UTC와 한국 시각 및 전후 SHA256을 남긴다. objects에는 성공한 결과를 SHA256별 한 번만 보관한다. 복구는 별도 작업으로 기록하여 원본으로 돌아간 파일을 개인 결과로 배포하지 않는다. 이미 기록된 개인 결과로 되돌린 경우 그 결과를 선택한다.

기존 기록 도입: personal-patch.cjs GAME CATALOG RUNTIME. 교체 백업의 applied 기록, 컷 추가 기록, 입력 이미지와 완료시각이 명시된 placed 진행기록 중 현재 파일의 SHA256까지 맞는 것만 도입한다. 불일치 내역은 import-report.json에 남긴다. 과거의 모든 중간 버전을 복원했다고 간주하지 않는다. 기존 done 플래그만 있는 항목은 제외한다.

나중에 사용자 패치 제작 지시가 오면 bundled Python으로 build-personal-patch.py 실행:

```
python build-personal-patch.py --root "CATALOG/image_work/personal-patch" --until "2026-10-08T23:59:59+09:00" --output "개인이미지패치_20261008.zip"
```

기본은 확인된 전체 작업 중 마감시각까지의 파일별 마지막 결과. --since를 주면 기간 추가분. 같은 파일 여러 버전은 최종 한 개만 넣는다. ZIP에 manifest.json(기간, 제작시각, 파일 해시), game/content/pic 경로를 유지한 이미지, catalog/index.html 대조 카탈로그와 설치안내를 포함한다. 기존 ZIP은 덮어쓰지 않는다. 이 기능은 이미지 전용이며 QSP 엔진의 컷 전환 코드 및 JO9O B컷 링크 설정은 별도다.

카탈로그는 WebP 최대 160px, 장당 최대 6,000바이트, 모든 썸네일 합계 최대 12MiB. 대량이면 자동으로 크기/품질을 낮춘다. 동일 썸네일은 해시로 공유하고 HTML에 base64를 넣지 않는다. 검색과 지연 로딩을 제공한다. 결과 썸네일 클릭은 ZIP 안의 실제 결과 파일로 연결한다. 작업 전 이미지는 기존 백업에서 읽어 작은 썸네일만 넣고 큰 원본을 ZIP에 복제하지 않는다. 과거 진행기록은 확인 가능한 JO9O 원본을 대조에 이용하며 비교 이미지가 없으면 명시한다.

기록 및 패치 제작은 게임을 실행하지 않는다. 이미지 저장 파일과 활성 카탈로그 기록을 PC 사이에 함께 가져가야 과거 마감시각을 다시 내보낼 수 있다. API 키와 브라우저 로그인, 다른 이미지팩 전체 및 전체 백업은 패치에 넣지 않는다.

검증: 임시 게임에서 서로 다른 시각의 저장 결과, 마감시각 선택, 복구 제외, ZIP 중복 생성 거부, 카탈로그와 썸네일 제한 시험. 실제 게임/QSP 변경 없음.
