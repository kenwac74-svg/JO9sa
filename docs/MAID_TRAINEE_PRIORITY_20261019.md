# 개인실 공용업무 우선권과 정보창 적용 범위 — 2026-10-19

## 사용자 확정 기획

개인실은 노예를 메이드로 승격해 자동 업무를 맡기는 시설이다. 그러나 공용업무가 현재 육성 중인 노예의 경험치나 일일 효과를 빼앗아서는 안 된다. 같은 업무를 여러 명이 중복 수행해 비용을 쓰지 않도록 한 명만 선정한다.

- 현재 노예 → 조수 → 개인실 순서로 배정한다. 노예·조수의 체크박스는 기존대로 사용할 수 있다.
- 존재하는 노예나 조수에게 해당 업무가 체크돼 있으면 개인실의 해당 업무만 일시 비활성화한다. 상위 담당자가 지쳐 있어도 개인실이 임의로 대신하지 않는다. 상위 역할이 비어 있다면 그 역할에 남은 체크는 배정을 막지 않는다.
- 개인실의 저장된 체크는 지우지 않는다. 상위 담당자의 체크를 해제하면 다시 사용할 수 있다. 두 상위 역할에 모두 체크되어 있으면 노예가 먼저다.
- 개인실까지 순서가 넘어온 경우 식사·청소·괴물 업무는 각각 요리·서비스·촉수 관련 원래 수치가 가장 높은 메이드 한 명을 선정하고, 동점은 무작위다. 목욕·기상 보조는 체크한 수행 가능 메이드 중 매일 무작위 한 명이다.
- 비활성 업무의 팝업과 툴팁: “현재 이 업무를 맡고 있는 사람은 ○○입니다. 교체를 원하시면 기존 담당자의 업무를 먼저 해제하세요.” 기존 안개 괴물 부재 안내와 같은 비활성 이미지 및 `$msg` 팝업을 사용한다.
- 개인실 정보창의 왼쪽 잠자리·식단·식사량·열량 도움말은 모두 비활성화한다. 이 일반 설정은 개인실 입주 중 효과를 적용하지 않는다. 개인실 자체의 식단과 휴식 효과는 유지한다.

## 구현과 의존 관계

`jo9_household_worker`는 기존 location을 확장한다. 새 location이나 새 저장용 변수를 추가하지 않는다. 함수의 선택 변수와 동적 템플릿은 호출 중에만 사용하는 local이다. 인물의 기존 규칙 체크와 속성·일일 기록 필드는 그대로 사용한다.

입력은 첫 인자의 문자열이다. `cook`, `clean`, `tentacle`, `wash`, `wake`는 수행할 역할 이름(`slave`, `assistant`, `room1`~`room4`) 또는 빈 문자열을 반환한다. 두 번째 인자에는 거절 뒤 재선정에서 제외할 역할을 줄 수 있다. `owner`와 `notice`는 두 번째 인자에 아래 규칙 키를 받아, 개인실 정보창에서만 실제 상위 담당자의 이름 또는 안내문을 반환한다. 조회는 값을 바꾸지 않는다.

| 업무 | 규칙 키 | 개인실 내 선정 기준 |
| --- | --- | --- |
| 식사 | `cooks_rule` | `cook` |
| 청소 | `cleans_rule` | `service` |
| 괴물 업무 | `tentacle_rule` | `sub_tentacles` |
| 목욕 | `washes_master_rule` | 무작위 한 명 |
| 기상 보조 | `blowjob_rule` | 무작위 한 명 |

공용 정보창은 원래 `slave_stat` 하나다. 개인실은 기존 `snk_room_bridge`로 대상을 잠시 `slave` 자리에 놓고 원래 노예를 `snk_parked_slave`에 둔다. 따라서 담당자 조회는 `snk_room_target>0`일 때 보관된 원래 노예를 읽는다. 메이드 자신을 상위 노예로 오인하지 않는다. 일반 노예 정보창에서는 새로운 잠금 안내를 생성하지 않는다.

`slave_stat`의 `MAID_DUTY_LOCK_1R/2R/3R/4R/11R`는 다섯 공용업무의 기존 처리만 감싼다. 담당자의 이름은 EXEC 코드에 직접 삽입하지 않고 클릭할 때 조회한다. 툴팁에서는 HTML 문자를 이스케이프한다. `MAID_LEFT_LABELS/INPUTS`는 일반 왼쪽 표시·입력을 개인실에서만 비활성화하며 오래된 일반 식단의 열량을 개인실의 열량처럼 표시하지 않는다.

`#dynamic`의 `MAID_LEFT_PRESET_USE/PURGE`는 개인실에서 프리셋을 적용·해제할 때도 왼쪽 다섯 설정을 덮어쓰지 못하게 한다. 프리셋의 오른쪽 규칙은 기존대로 적용한다. 기존 로드 갱신 경로가 `#dynamic`을 새로 구성한다.

일반 식단·잠자리 효과의 대부분은 원래부터 주 노예 전용이었다. 개인실에도 영향을 주던 네 경로만 추가로 고쳤다. `next_day`의 `MAID_LEFT_FIXED_REST_GUILT/SPOIL`은 개인실 입주자의 옛 수면 설정 때문에 일반적인 기분·죄책감 처리가 달라지지 않게 한다. `MAID_LEFT_ACTUAL_RATION_COLLAPSE`는 영양 부족 판정에 옛 `diet_portion` 대신 실제 `roomN_ration+1`을 읽으며 실제 열량 부족 판정은 유지한다. `#static_base`의 `MAID_LEFT_KEEP_STORED_SLEEP`은 개인실 및 정보창에서 잠시 `slave` 자리에 놓인 메이드의 저장된 수면 설정을 일반 노예용 보정으로 덮어쓰지 않게 한다. 일반 노예·조수의 기존 보정은 유지한다.

`next_day`는 기존 행동 결과 코드를 유지하고 선정한 인물만 실행한다. `MAID_BATH_WAKE_PRIORITY`는 목욕과 기상 보조를 한 명에게 배정한다. 기상 보조는 원래의 수락·거절·능력 변화 코드를 재사용하며 새로운 대사·행동력 비용·성공 컷신을 만들지 않는다. 목욕 거절 후 조수로 넘어갈 수 있고, 상위 체크가 남아 있으면 개인실로는 넘어가지 않는다. 기존 주인공의 비상 식사·청소 보충은 제거하지 않는다.

기상 보조를 맡은 조수·메이드는 그 행동 전에 기존 일일 규칙 위반 횟수·위반 희망 횟수·기상 규칙 위반 여부와 설명 기록을 초기화한다. 새 저장 필드를 만드는 것이 아니라 원래 주 노예용 행동의 일일 초기화를 선택된 인물에게만 적용하는 것이다. 거절과 강제 규칙의 기존 결과도 실제 담당자에게 적용하며, 주 노예 전용 전역 규칙 개수와 알림 플래그는 복사하지 않는다. 기존 죄책감 함수의 주 노예 전용 제한도 변경하지 않는다.

관련 숙련도로 선정하는 것과 해당 행동이 올리는 수치는 다르다. 식사는 요리, 청소는 서비스 경험치를 준다. 기존 괴물 일일 업무는 선정에 촉수 수치를 읽지만, 그 일일 코드에 촉수 숙련도 경험치 증가는 없고 체력·일부 개발 수치 변화가 있다. 목욕에는 기존 행동력 비용이 있고 기상 보조에는 기존 코드상 별도 행동력 비용이 없다. 선택되지 않은 인물에게 이 행동의 비용이나 성장 효과를 중복 적용하지 않는다.

## 분리·제거 시 주의

UI의 잠금만 제거하면 개인실에서 설정은 바꿀 수 있어도 일일 선정에서는 계속 상위 담당자가 우선한다. 선정 함수만 제거하면 UI와 일일 호출이 누락 location을 참조하므로 함께 복원해야 한다. 목욕·기상 보조 템플릿은 선정 변수와 한 묶음으로 복원해야 하며, 블록 일부만 잘라내면 수락과 결과가 다른 인물에 적용될 수 있다. 왼쪽 프리셋 가드와 효과 차단은 화면 비활성화와 함께 유지해야 한다.

이전 `MAID_DUTY_SELECTION_20261019.md`의 전체 여섯 명 중 최고 숙련자 방식과 목욕·기상 보조 확인 대기는 이 후속 기획으로 대체된다. 그 단계에서 고친 개인실 1~4의 실제 유형에 따른 컷신 연결은 보존한다.

## 배포 경계와 검증

Work만 적용한다. CSS·이미지·JSON·개인 세이브와 Full은 변경하지 않는다. Full 동기화, 커밋, 푸시는 아직 수행하지 않는다. 최종 검증 수치와 후보 해시·적용 결과는 같은 기록 폴더의 `RESULT.json`, `release-report.json`, 각 네이티브 결과 파일을 기준으로 한다.

네이티브 검사는 별도 복사본에서 실제 엔진으로 실행한다. 저장 파일은 대표 상태를 읽어 진단 변수로 재구성하며 원래 파일에는 쓰지 않는다. 실제 저장 파일 선택 UI·전체 플레이·전체 화면의 시각적 배치는 이 검사와 별개다. 검사 중 발견된 후보 오류는 적용 전에 고치며 실패한 실행도 진단 기록으로 남긴다.
