# 인물 상태 편집기 0.2 — 사용자 의견 반영

사용자가 편집 위치를 찾기 어렵다고 보고한 뒤, 먼저 의견을 모으고 2026-10-16에 재구현을 요청했다. 이 작업은 기존 상태 축 편집기의 사용성과 생성 초기값 연결을 보완한다. 전체 게임 변수 편집기나 임의 조건식 제작기로 확대하지 않는다.

## 취합한 문제와 수정

| 사용자 의견 | 반영 범위 |
|---|---|
| 편집 가능한 버튼·입력칸을 알아보기 어렵다 | 색상과 '편집 가능' 문구로 표시하고 읽기 전용 정보와 구분 |
| 텍스트에 마우스를 올렸을 때 설명이 필요하다 | 항목별 도움말, hover/focus 설명, 키보드 접근 |
| '크게 늘어난' 검색 후 무엇을 고칠 수 있는지 모르겠다 | 메뉴를 가로지르는 검색 결과, 현재값·항목·소속 메뉴, '편집으로 이동'과 정확한 입력칸 focus |
| 상태표와 전환·이력 중 어디서 편집하는지 모호하다 | 각 메뉴의 편집/조회 범위를 직접 안내 |
| 성숙(MILF) 생성 시 특정 상태를 초기값으로 주고 싶다 | '생성 초기값' 메뉴의 기존 일반 생성기 연결, 초기 선택은 '기존 생성 규칙 유지' |

기존의 표시명·툴팁은 서로 다른 실제 QSP 문자열이다. 툴팁 검색 결과는 해당 입력칸으로 이동하며 상태 코드나 아이콘을 임의로 바꾸지 않는다.

## 생성 초기값의 정확한 범위

기존 `generate_stock`에서 `special_stock = 0`이고 `stock['age'] = CONST_INT['milf_age']`인 일반 생성 인물에 적용한다. 생성기의 무작위·직업·기술 계산 뒤, 특성목록과 가격 계산 전에 기존 `stock['virginity']`만 설정한다. 새 게임 변수·저장 키·이력 초기화·상시 강제 규칙을 추가하지 않는다.

- 일반 생성기를 쓰는 시장·경매·전문가 찾기·무작위 의뢰·일부 보상 인물이 포함될 수 있다. 퀘스트 인물을 전부 제외한다는 의미는 아니다.
- `special_stock > 0` 고유 프리셋과 직접 시드를 읽는 별도 생성 경로는 제외된다.
- 클론이나 개별 사건이 생성 뒤 상태를 별도로 지정하는 동작은 유지된다.
- 이미 세이브에 있는 인물은 소급 변경하지 않는다. 초기값을 설정해도 이후 상태 전환은 기존 규칙을 따른다.
- 선택값은 기존 유지(-1), 상태 0~3이다. 상태 4는 발견·보장 이력 연결이 필요하므로 이번 생성 초기값 메뉴에서 직접 지정하지 않는다. 다른 편집 항목의 기존 상태 4 지원은 유지한다.
- 프로젝트 저장과 후보 미리보기는 실제 QSP를 쓰지 않는다. 사용자가 설치본을 선택하고 후보 적용을 눌러야 변경된다.

## 검증과 배치

새 검색→정확한 입력칸 이동, 설명 연결, 생성 선택값 프로젝트 저장/불러오기, 두 독립 QSP의 후보·적용·원본 바이트 복원을 임시 QSP와 브라우저에서 검증한다. 실제 Work/Full은 읽기 및 메모리 후보 검사만 수행한다. 게임 클라이언트 실행과 플레이 검증은 사용자 담당이다.

실제 실행 주소·테스트 수·배치 결과는 최종 QA JSON에 기록한다. 런타임 프로젝트·후보·백업을 배포 파일로 덮어쓰지 않는다.

## 최종 검증 결과

- 편집기 자체 45개, 기존 대사 편집실을 포함해 113개 중 112개 통과, 실패 0. Windows 파일 심볼릭 링크 생성 불가로 1개 제외.
- 기존 브라우저 회귀와 새 사용성 시나리오 통과. 320/736/1024~1120 폭에서 5개 메뉴 가로 넘침 없음.
- 검색 결과에서 툴팁 입력칸의 정확한 focus·설명, select의 숫자형 프로젝트 저장/불러오기·후보 무효화, 독립 두 사본의 적용/정확 복원 확인.
- Work/Full 실제 QSP의 31개 필드 읽기 및 메모리 후보·역패치 검증. 설치 QSP의 기존 SHA256 불변.
- 저장소와 두 게임의 modtools/state-editor 제품 10개 파일 일치. 사용자 런타임 프로젝트·백업은 덮어쓰지 않음.
- 실제 서버 http://127.0.0.1:5284/ 재시작 뒤 두 대상의 31개 항목, 초기값 '기존 생성 규칙 유지', 대상 초기 미선택, 검색 이동과 pageerror 0 확인.
- 독립 코드 검토에서 추가 조치사항 없음. 게임 클라이언트 실행·플레이 검증은 하지 않음.
