# 노예 대사 1단계 — 보조 계산과 인상 묻기(1112)

설계 기준은 `design/slave-voice`의 `dbdca06`이다. `IMPLEMENTATION_HANDOFF.md` 4절 1단계만 구현한다. 대사는 `lines/1112_impression_v1.md` 원문 108개를 그대로 사용한다. 이번 작업의 수정 전 기준은 최신 플레이 QSP `9c931f755aa3ba87908cad2750883d8f937fc5daf22412d093147df6558c5251`이며, 배포본·보관 원본·CSS는 대상이 아니다. 저장소의 미커밋 작업을 유지하기 위해 현재 main을 전환하거나 정리하지 않고, 지정 설계 커밋을 별도 사본으로 읽었다.

## 게임에서 보이는 변화

질문하기의 인상 묻기(1112)를 받아들였을 때, 기존 대답 끝에 `[이름]` 한 블록이 추가된다. 성격·감수성·자아·태도로 9유형을, 배경 직업으로 3말투를 계산한다. 오늘 또는 요즘의 칭찬·처벌 기록을 읽어 원문을 고른다. 오늘 일이 없고 최근 합도 양쪽 모두 3 미만이면 추가하지 않는다.

오늘 일과 최근 화제가 같으면 오늘 문장만, 반대이면 최근 문장 다음에 오늘 문장을 넣는다. 최근 화제는 3 이상인 쪽 중 횟수가 많은 쪽 하나를 먼저 고른다. 대답 거부 시 기존 거부문만 나오며 새 코드는 실행되지 않는다. 기존 대답·상태값·복종·기분·보상·발견 조건을 수정하지 않는다.

**문서 미정 경계의 구현 기본값**: 오늘 양쪽 일이 모두 있으면 더 많은 횟수 쪽, 동률이면 처벌(C)을 고른다. 최근 합이 동률이며 모두 3 이상이면 처벌(B)을 고른다. 이는 기존 설계의 확정 규칙과 구분되는 기본값이다. 작업 중 사용자에게 선택지를 제시했고 답이 없는 동안 이 기본값으로 후보를 준비했다.

이번 단계에는 다른 질문, 현재 기분 묻기, 포트레이트, 어휘 변형, 수업 반응, 정신분열 전용 대사 덮어쓰기를 넣지 않는다. 정신력 계산 helper는 준비하지만 전용 문장 선택은 인계서의 4단계다.

## 새 구성과 입출력

새 QSP 로케이션은 없고 기존 255개를 유지한다. 다음 네 개는 `#dynamic`에 보관하는 실행 문자열이다.

| 이름 | 입력 | 반환 / 영향 |
|---|---|---|
| `$voice_profile` | 직업 문자열, 성격, 감수성, 자아, 태도 | `$dyneval`로 `plain_2` 같은 유형·말투 키 반환. 전달받은 값은 수정하지 않음 |
| `$voice_mental` | 자아, 성격, 태도 | `dyneval`로 0 보통 / 1 신경쇠약 / 2 정신분열 반환. 기존 sanity 전역을 건드리지 않음 |
| `$voice_index` | 조각 번호 k, 양수 후보 수 n | 기존 day·interaction으로 의사난수 인덱스 0~n−1 반환. rand나 새 기록을 쓰지 않음 |
| `$voice_impression` | 인자 없음. 기존 slave 수치·직업·횟수 읽음 | `$dyneval`로 추가 문장 또는 빈 문자열 반환. 대사 배열과 행동 번호표에 의존 |

`voice_reward_ids` 22개와 `voice_punishment_ids` 52개는 읽기용 고정 행동 번호표다. `$voice_1112`는 원문 108개 고정 문자열 배열이다. 이 정의와 상수는 저장될 수 있지만 새로운 인물 상태·사건 이력·버전 플래그를 만들지 않는다. 계산용 임시 변수 13개는 각 실행 종료 시 `killvar`로 지운다.

호출은 `interaction`의 1112 `$special_part` 끝 한 곳이다. 반환 문자열이 있을 때만 기존 형식 `[이름]<br>&nbsp;…</div>`로 `$text[]`에 붙인다. 이름은 실행 시점에 문자열로 연결하며, 정의 시점의 `<<>>` 조기 평가를 쓰지 않는다.

기존 세이브에 helper가 없으면 기존 `#dynamic`을 읽어 정의를 보충한다. 대사 배열이 없으면 `gs '#txt_man', 'jo9_voice_1112_data'`로 새 데이터 구간만 읽는다. `#txt_man` 맨 앞의 인자 분기는 해당 전용 호출만 맨 끝 데이터 라벨로 보낸다. 따라서 여주인 플레이에서도 남주용 기존 대사 배열을 덮어쓰지 않는다. 보통의 `#txt_man` 호출은 기존 코드를 그대로 지나 새 데이터에 도달한다.

## 표식과 분리·복원

선언형 패치는 `mods/2026-10-17_zzzzzzz_slave_voice_stage1.json`이다. 각 추가분은 다음 `JO9 MOD START/END` 표식으로 묶었다.

| 표식 | 로케이션 | 역할 |
|---|---|---|
| VOICE_STAGE1_HELPERS | #dynamic 끝 | 네 helper와 고정 번호표 |
| VOICE_STAGE1_DATA_ROUTE | #txt_man 처음 | 새 대사 데이터만 읽는 전용 인자 경로 |
| VOICE_STAGE1_DATA | #txt_man 끝 | 데이터 라벨과 원문 108개 |
| VOICE_STAGE1_1112 | interaction 1112 | 초기 정의 보충·문장 선택·한 블록 추가·임시 삭제 |

`VOICE_STAGE1_1112` 구간만 제거하면 추가 대사를 호출하지 않고 원래 1112 대답이 남는다. 코드 후보 검사에서 이 구간을 제거한 interaction 본문이 수정 전과 바이트 단위로 같음을 확인한다. 기능 전체를 제거할 때는 네 구간을 함께 역패치하는 편이 안전하다. helper·데이터·데이터 경로 중 일부만 지우고 호출부를 남기면 정의 누락, 빈 추가문 또는 존재하지 않는 라벨로 이동하는 오류가 생길 수 있다. 원문 및 원래 조건을 지울 필요는 없다.

## 인계서 6절의 7개 확인 결과

줄 번호는 수정 전 최신 Play의 로케이션 본문 기준이다. 세부 근거는 작업 폴더 `audit-route.md`, `audit-recent.md/json`, `source-reference-check.json`에 있다.

1. **블록과 줄 번호**: 최신 Play `interaction` 539~567행, 실제 삽입은 기존 565행 뒤·동적 문자열 닫기 전이다. 저장소 최신 source 파일 `jack_2026-10-01.qsp`는 533행부터이며 1112 본문 자체는 최신 Play와 동일했다. 구현은 source 사본이 아닌 최신 Play에 한다.
2. **조수 직업 변수**: `$assistant_occupation`이 맞다. `$slave_vars`의 `$instance_occupation` 치환 및 인스턴스 교환으로 유지된다. 지정한 직업 코드 21종은 실제 생성 코드에 모두 있다. 철자도 그대로 사용한다.
3. **처벌 전체 목록**: abuse/torture를 기준으로 52개. 인계서 누락은 174, 855, 856, 1473~1475, 5625다. 1451~1453은 메뉴라 제외하고, 14511~14516은 별도 present_torture라 이 집합에 넣지 않는다. 보상 목록은 22개다.
4. **cowSK**: 1226 / 4134 / 1726 / 570이 맞고, 5612는 미술이다. 최신 Play에는 이 번호 중복이 없다. 이번 단계에서 수업 코드는 바꾸지 않는다.
5. **기술 이름표**: 기존 `$atr_name`이 있다. 설계의 운동·체조·화술과 실제 표의 체력·무용술·수사학에는 명칭 차이가 있으므로 3단계에서 확인한다. 1112에는 과목명이 필요 없다.
6. **거부**: `interaction_result` 560~571행. res<0이면 기존 거부문, else에서만 `$special_part`를 실행한다. 별도 거부 차단은 추가하지 않는다.
7. **HTML**: `[<<$slave_name>>]<br>&nbsp;…</div>` 형식을 따른다. 기존 broken 관계 문장 한 줄의 닫는 태그 누락은 이번 범위에서 고치지 않는다.

문서와 다른 기존 횟수 의미도 유지한다. 최근 횟수는 매일이 아니라 **2일마다 각 행동별 최대 2 감소**한다. 오늘 처벌은 기존 결과 helper에서 실패 여부와 무관하게 증가할 수 있고, 오늘 보상에는 최근 22개 목록 외의 선물·말로 칭찬도 포함된다. 동결 인스턴스는 기존 일일 초기화 예외가 있다. 새 코드가 이 값들의 기록·감쇠를 고치거나 새 이력을 만들지는 않는다.

## 검증과 플레이 확인

후보 QSP 왕복, 255개 로케이션 유지, 세 본문 밖 변경 없음, 정확한 역패치, 표준 `apply_mods.ps1` 사본 재생을 확인한다. QSP WASM 5.8에서 성격 조합 1,296개를 포함한 2,042개 검사가 통과했다. 원문 108개·직업 말투·화제 문턱과 조합·임시 삭제·거부·기존 세이브 초기화·원래 답변 유지가 포함된다. QSP 5.7 네이티브 DLL 시험 결과와 설치 해시·백업 경로는 같은 작업 폴더의 `native-qa/result.json`, `installed.json`에 기록한다.

게임 클라이언트 실행과 실제 세이브 화면 확인은 하지 않는다. 재실행 후 인상 묻기에서 기록 없음 / 오늘 칭찬 / 오늘 처벌 / 최근과 오늘 반대의 네 상황을 확인하면 된다. 다른 질문과 포트레이트는 기존과 같아야 한다. 되돌릴 때는 설치 백업 또는 이 패치의 정확한 역적용을 사용한다.
