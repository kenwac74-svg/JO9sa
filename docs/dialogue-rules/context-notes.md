# 말하기 기본 규칙 context notes

## 2026-11-16 기획서 v0
- 사용자 지시: 산출물은 기획서. 섹스토크만이 아니라 캐릭터의 현재 상태, 주인과의 관계, 성격, 배경에 따라 어떤 어투로 어떤 말을 하는지를 정하는 **기본 규칙**이다. 게임 적용 전이다.
- 그래서 문서를 섹스토크 구조서가 아니라 공통 규칙서로 잡고, 섹스토크는 7장에서 "이 규칙을 쓰는 자리 하나"로 다뤘다.
- 뼈대를 "말하는가 / 무엇을 / 얼마나 / 어떻게" 네 물음으로 잡은 이유: 사용자가 든 네 입력(현재 상태·관계·성격·배경)이 각각 어느 물음에 작용하는지 한 표로 보이게 하려고. 기존 문서들은 자리별(필로우토크, 인상 묻기 등)로 흩어져 있어 이 대응이 보이지 않았다.
- 새 규칙은 만들지 않고 기존 확정 사항을 묶었다. 새로 채운 것은 [제안] 표시: 덮어쓰기 우선순위(3장), 현재 상태의 작용 범위(5.2), 구현 단계(9장).
- 기존 문서끼리 어긋난 곳 5개를 찾아 10장에 올렸다. 가장 큰 것은 반말의 범위(2026-10-15 "적대는 비꼬는 존대" / 2026-11-12 "초기·적대는 반말·당신" / 2026-11-13 "반말은 유니크 8명과 공주 계열").
- 깊이 식은 정수판(필로우토크 규칙 3.4)을 본문에 실었다. 반값판과 문턱이 두 배 관계라 결과는 거의 같고, QSP는 정수 연산이 편하다.
- 현재 QSP에서 읽은 것: 대화 메뉴는 `menu_form`의 `menu_talk` 블록(질문한다 / 영향력을 행사한다 / 사회화), 질문은 `interaction` 1111~1118, 벙어리 차단과 대사 캐시 조건이 그 번호 범위로 적혀 있음, `interaction_result`의 talk 유형은 행동력을 깎지 않음, 일일 횟수 초기화는 `next_day`. `jo9_supermacy`는 QSP에 없고 `master_supermacy`만 있음.
- 표시 불가 분류(B1·B2)는 기존 지침대로 키와 자리표시 문구만 두는 구조를 유지했다.
- 브랜치: 이 세션은 `claude/vibrant-turing-ysgmbv`에만 올릴 수 있어 여기에 뒀다. 기획 원본들은 `editor/character-studio-20261112`, `design/slave-voice`에 있다.

## 2026-11-16 호칭 방향 (사용자)
- 사용자: 한국어 존대 어투를 세심하게 다 표현하면 대사 세트가 너무 많아진다. 공주 계열 반말 캐릭터는 어투를 계속 반말로 두고, 사이가 나쁠 때 [너/네놈] → [당신/주인공 이름] → 복종할 때 [주인/마스터]로 **호칭만** 바꾼다.
- 반영: 기획서 4.4를 "관계는 호칭만 바꾼다"로 다시 썼다. 2026-11-12 호칭표의 "초기·적대면 출신 무관 반말" 부분은 이 방향과 부딪히므로 대체로 적었다(존댓말 계열 확장은 Claude 제안, 사용자 확인 전).
- 호칭을 빈칸으로 두려면 조사 붙은 꼴 표가 필요하다. '너'가 "네가"·"네"로 바뀌어 조사 자동 붙이기가 안 되기 때문(Claude 판단).
- 단계 문턱과 칸 안 두 낱말 고르는 기준은 Claude 제안이며 10장 결정 1에 남겼다.

## 2026-11-16 세계관 자료 (사용자 제공)
- 사용자가 나무위키 Jack-o-nine-tails 문서의 세계관·지역·이벤트·팁 부분을 붙여 줬다. 별도 지시는 없었고, 말하기 규칙의 배경 자료로 준 것으로 이해했다(Claude 해석).
- 원문은 저장소에 싣지 않았다(외부 위키 글, 1.7.5·2.2 판 기준). 말하기에 닿는 점만 기획서 2.1에 표로 요약했다.
- 새로 얻은 것: ① 노예는 이세계인이라 관계가 낯섦에서 시작한다는 전제 ② 낱말층 둘(출신 세계 / 로마) ③ 로마 낱말은 겪은 것만 말한다 ④ 헌신 3이 게임의 '스스로 따른다' 선(조수 자격, 챔피언 자유민 잔류) → 호칭 '복종' 단계 문턱 대안 ⑤ 고객 앞에서의 말은 범위 밖.
- 위키의 수치·명칭은 2.4.1과 다를 수 있어 규칙의 수치 근거로 쓰지 않았다. 헌신 3 선은 QSP 확인이 필요하다.

## 2026-11-16 노예 자료 (사용자 제공)
- 사용자가 나무위키 Jack-o-nine-tails/노예 문서(속성, 아우라, 특성, 스킬, 보상과 처벌)를 붙여 줬다. 지시는 없었고 앞 자료와 같은 배경 자료로 이해했다(Claude 해석). 원문은 싣지 않았다.
- 반영: ① 용어 대응표(위키는 기질·본성·프라이드, 이 문서는 성격·자아·태도. 태도는 값이 클수록 오만이고 화면 등급은 반대) ② 현재 상태 입력에 공로·죄책감·보상 약속 추가(QSP에 `virtue`, `guilt`, `promise_reward` 있음) ③ 헌신 3 선을 QSP에서 확인 ④ 섹스토크는 연령 코드 1에게 열지 않는다는 기존 확정 사항을 7장에 명시 ⑤ 특성 화제는 기존 질문 문장이 담당.
- 반영하지 않은 것: 위키의 신경쇠약 계산(성격 + 자아 − 태도 등급)은 QSP의 대사용 판정(`$voice_mental`: 세 값의 합 4 이하 신경쇠약, 2 이하 정신분열)과 다르다. 기획서는 QSP를 따른다. 화면의 특성 판정과 대사용 판정이 같은 식인지는 확인하지 않았다.
- 위키에 "복종도가 낮으면 질문에 욕설을 한다"는 서술이 있다. 기존 거부 대사에 주인을 향한 욕설이 실제로 있는지 확인 항목으로 올렸다.

## 2026-11-16 플레이어 캐릭터 자료 (사용자 제공)
- 사용자가 나무위키 플레이어 캐릭터 문서(속성, 기술, 가문 평판, 작위)를 붙여 줬다. 배경 자료로 이해했고 원문은 싣지 않았다.
- 이 자료를 계기로 QSP를 확인해 앞선 판단을 정정했다: "대상별 장악력이 없다"는 틀렸다. `master_supermacy`는 `$calculate_attributes`에서 dynslave(대상 인물) 값을 빼서 계산한다. 없던 것은 `jo9_supermacy`라는 이름뿐이다.
- 기획서 2.2 추가: 관계를 복종(조교)과 장악력(힘겨루기) 두 축으로 읽는 표. 기존 결정 "장악력 < 0이면 거짓말"을 겉말/속말 구조와 잇기 위한 Claude 제안이다.
- 주인의 작위·평판을 호칭에 쓰지 않는다는 것도 Claude 제안(대사 세트를 늘리지 않으려는 사용자 방향에 맞춤).
- QSP `$refuse_talk` 확인: arrogant·hysteric·hateful·optimistic 대사가 반말이고 hateful은 욕설. 새 원칙과 다르지만 통 대사라 그대로 두는 안을 결정 9로 올렸다.

## 2026-11-16 전면 재검토 (사용자 지시)
- 사용자: 반말 캐릭터는 세계관상 많을 수 없다. 유니크 일부와 공주 출신 랜덤 노예만 반말. "정해 달라고 한 것은 네가 기획해서 제안해라. 노예의 정보를 어떻게 활용해 대사 분기를 판단할지 정해라. 기존에 합의한 기획 정책을 전면 재검토해라." 노예 정보 화면 두 장(속성, 아우라 수치)을 함께 줬다.
- 그래서 질문 목록을 없애고 Claude가 전부 정한 재검토안 v1을 따로 썼다. 이하 판단은 모두 Claude 제안이며 승인 전이다.
- 핵심 판단: 기존 정책은 축이 너무 많고(유형 9 × 관계 7 × 깊이 3 × 말투 3 × 어휘 4), 관계 모드·깊이 식·현재 상태 반영은 게임의 정신 상태(`psy_status`)가 이미 종합한 것을 다시 계산한다. QSP `#static_base` 1087~1143행에서 정신 상태가 기분·헌신·두려움·절망·응석·인식·흥분·복종도·속성 네 개로 정해지는 것을 확인했다.
- 원고 축을 말결 4 × 태도 3으로 줄였다. 말결 4종은 9유형 격자를 '표현 낮음 열'(짧은)과 나머지를 주장 축 세 줄(낮추는·담백한·내세우는)로 묶은 것. 길이와 태도가 함께 갈리는 묶음이라 골랐다.
- 열림을 헌신 등급 하나로 한 이유: 섹스토크 주제가 이미 헌신으로 열리고, 화면에서 바로 보이며, 식 세 개는 예측이 안 된다.
- 기분을 별도 축으로 두지 않은 이유: 정신 상태가 기분을 이미 반영한다(기분 < 2면 우울증·슬퍼함 쪽으로 간다). 대신 움츠림 태도에서 길이 상한을 낮춘다.
- 섹스토크 거부의 인식 ≤ 2 조건을 헌신 0으로 바꾸자고 한 근거: 사용자가 준 화면의 노예가 헌신 5·인식 0이라 기존 규칙으로는 거부 대사가 나온다.
- 존댓말 인물의 중간 단계 호칭을 "주인님"으로 한 근거: 기존 거부 대사에서 obedient·servile이 "주인님"을 쓰고, 두려움 상태는 호칭을 거부할 처지가 아니다. 맞섬일 때만 "당신".
- Wayward식 기억 버퍼·점수 판단·숨긴 이야기는 보류로 판정(1차 범위 밖).

## 2026-11-16 Sixth Sense 비교 (사용자 제공 HTML)
- 사용자가 다른 대사 조립형 게임의 단일 HTML을 주고 비교를 요청했다. 저장소에는 넣지 않았고(외부 게임 소스), 구조만 읽어 재검토안 8장에 정리했다.
- 읽은 범위: 대사 데이터(JSON 묶음), 등록 함수, 데이터의 `_doc` 설명. 고르는 함수 전체와 대체 순서의 정확한 구현은 읽지 못했다(줄여진 코드). 대체 순서는 키 모양과 설명문에서 추정한 것이다.
- 가장 쓸모 있던 확인: 고정 히로인 3명짜리 게임도 원고 칸을 단계 묶음 3 × 결과 4 = 12로 잡는다. 재검토안의 12칸과 같은 크기다.
- 가져오자고 한 것(Claude 제안): 망설임 결과, 계층 키와 `*` 대체, 빈칸 안 조사 표기, 줄 안 속마음, 상태는 필요한 자리에서만.
