# JO9 텍스트 보강 대원칙 (2026-11-17)

- 이 문서는 **어디에 적용할지와 무관한 원칙만** 담는다. 어떤 대사나 커맨드를 고칠지는 아직 정하지 않았다.
- 기존 문서(풍부화 규칙, 시스템 보고서, DB의 `triggers`)에 있는 사건 목록과 넣을 자리는 **적용 후보**이며 결정된 것이 아니다.
- 상태 표시: **확정**은 사용자 결정이 있는 것, **제안**은 Claude가 연구에서 끌어낸 것(사용자 확인 전).

## 4. 어떻게 저장하고 고르는가
| # | 원칙 | 내용 | 근거 | 상태 |

| 20 | 규칙과 문장을 나눈다 | 문장은 데이터(DB), 고르는 규칙은 코드. 규칙을 바꿀 때 문장을 다시 쓰지 않는다 | 사용자 "DB 스키마와 규칙이 먼저" | 확정(방향) |
| 21 | 칸 수에 상한을 둔다 | 한 자리의 원고 칸은 목소리 × 관계 단계로 15칸 안팎 | 다른 게임 비교(12~15칸), 원고를 채울 수 있는 크기 | 제안 |
| 22 | 빈 칸이 있어도 게임은 돈다 | 구체적인 줄이 없으면 공통 줄, 그것도 없으면 원래 글만 | 원고가 다 차기 전에도 넣을 수 있어야 한다 | 제안 |
| 23 | 어미를 자동으로 바꾸지 않는다 | 말투마다 완결 문장을 따로 쓴다. 빈칸은 이름·호칭·조사뿐이고, 조사가 붙은 꼴을 표로 둔다 | Wayward 한국어판과 같은 방식, '너' 같은 꼴 변화 | 제안 |
| 24 | 대사를 세이브에 넣지 않는다 | 원고는 변수에 올리지 않는다. 인물에 저장하는 것은 최소(목소리 번호 등) | 기존 대사 변수 문제(세이브 크기, 옛 원고) | 확정 |
| 25 | 같은 줄을 연달아 내지 않는다 | 변형을 두고 최근에 쓴 줄을 피한다. 조건을 완화해 다양성을 만들지 않는다 | 기존 결정 | 확정 |

## 6. 적용할 때마다 정해야 하는 것
아래는 원칙이 아니라 **적용 대상별 결정**이다. 어떤 대사나 커맨드에 적용하기로 하면 이것을 하나씩 정한다.

| 항목 | 정하는 것 |
|---|---|
| 대상 | 어느 대사·커맨드인가 |
| 무게 | 원칙 5에 따라 얼마나 큰 일인가(덧대는 양과 횟수가 따라 정해진다) |
| 계기 | 사건이 일어났다고 판단하는 게임 값이나 실행 지점 |
| 넣을 자리 | 원래 글이 나오는 줄 |
| 칸 나누기 | 관계 단계를 몇 칸으로 나눌지(태도 3칸, 헌신 2칸, 하나) |
| 작성자 | Claude 초안인가 사용자 작성인가 |
| 화자 | 노예 하나인가, 조수·손님이 함께 나오는가 |

## 7. 이전 문서와의 관계
- 이 문서가 맨 위다. 풍부화 규칙, 시스템 보고서, 인계 문서의 내용 가운데 이 원칙과 어긋나는 것이 있으면 이 문서를 따른다.
- 그 문서들의 사건 목록, 처형 위협 mods 초안, 원고 95블록은 **원칙을 시험한 자료**다. 적용 대상으로 정해진 것이 아니다.
