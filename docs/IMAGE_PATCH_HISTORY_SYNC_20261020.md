## 이후 작업

Workshop에서 성공한 이미지 저장은 기존 events.jsonl과 objects에 계속 자동 기록된다. 그 기록에는 원래 작업 시각과 전후 해시가 남는다. 배포 기준은 이번 스냅샷에 봉인되어 있으므로 다음 동기화에서도 배포된 이미지와 이후 작업을 구별할 수 있다.

다음 패치 준비 시 최신 원장을 새 run으로 동기화한다. 옛 CSV/스냅샷은 덮어쓰지 않는다. 이번 마감 이후 저장은 기존 자동 원장에는 바로 남지만, 이번 불변 CSV와 패치 후보를 소급해서 바꾸지는 않는다. Workshop 밖의 외부 파일 교체는 원장 또는 별도 통합 계획에 근거가 있어야 출처를 확정한다.

기존 2.4 ZIP, Full, 게임 이미지, QSP, CSS, 세이브는 변경하지 않았다. 퇴역한 SNKmod 동기화나 구형 imagepack 빌더는 실행하지 않았다. 새 배포 ZIP 제작과 Work→Full 동기화는 이번 작업 범위에 포함하지 않았다.

## 내부 재현·검증

`records/image-patch-history-sync-20261020/sync-history.py`는 현재 경로/배포 manifest/외부 계획/읽기 전용 inventory를 입력받는다. `--apply`가 없으면 새 후보 스냅샷만 만든다. `--apply` 시 카탈로그 HTML의 목록과 MR, 고정 번호 JSON, 표시 번호 JS, 개인 패치 settings만 갱신하고 release-history 인덱스를 추가한다.

기존 HTML의 본문·행 순서·원본 크기·연결, 코드 JS의 기존 alias와 WORK_UNITS는 보존한다. 현재 파일 해시와 원장, 결과 객체가 일치한 개인 교체만 후보에 넣는다. 출처 미확정 행을 개인 패치로 승격하지 않는다. 원본 관리자료를 먼저 보존하고 쓰기 직전 바이트 변경을 검사한다. 4파일 갱신은 하나의 파일시스템 트랜잭션은 아니므로 중간 실패 시 보존된 스냅샷과 실제 적용 파일을 확인해야 한다. 실패를 성공으로 처리하지 않는다.

출력: 새 run 폴더의 manifest/CSV/전후 메타데이터/이미지 후보와 SYNC_RESULT.json. 입력 원장·체크·progress·게임은 읽기 전용이다. objects와 이미지 후보는 SHA256으로 검증한다. 원장 시각을 동기화 시각으로 대체하지 않는다.

기존 개인 패치 exporter의 dry-run에서 54파일, 19,044,036바이트 이미지와 비교용 썸네일을 정상 선택했다. 신규 공개 ZIP은 만들지 않았다. 게임 실행이나 시각적 인게임 검증은 이번 관리자료 동기화에서 수행하지 않았다.
