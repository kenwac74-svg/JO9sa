# 시설 설명의 단계 배분과 재고 표시 보존

사용자 요청: 크라이오 보관소처럼 한 시설을 여러 화면에서 보여 주는 경우 설명을 단계에 맞게 나누고, 같은 구조의 다른 설명도 정리한다.

## 화면별 배분

| 대상 | 표시 내용 |
|---|---|
| 크라이오 입구 stasis_bank | 검수본 첫 문단인 군대 냉동 보관 시설의 건립 배경 |
| 크라이오 셀 관리 stasis_bank_2 | 검수본 나머지 문단인 개인 임대·노예 보관·유지 비용 |
| 캣파이트 클럽 catfightclub | 기존 관전·베팅 소개 유지 |
| 에게야 결투 egeya_battle | 클럽 주인 에게야와 직접 맞붙는 현재 상황 |
| 식품점 gastronom / 정육 구역 meat | 우측 재고표 유지, 비어 있는 하단 지문 칸에 검수된 시설 설명 표시 |
| 도축장 slaughter | 우측 도축업자 정보 유지, 비어 있는 하단 지문 칸에 검수된 시설 설명 표시 |

크라이오의 두 문단을 원래 경계로 다시 이어 붙이면 승인한 본문과 정확히 같다. 도축장/정육 구역은 노예 동행 여부에 따른 분기다. 에게야 결투는 일반 경기의 다음 페이지가 아니라 별도 결투 상황이다. 이 실제 분기를 기준으로 배분했다.

## 대상 감사

승인 장소 키 87개와 19개 장소군의 실제 호출·전환을 대조했다. 같은 제목이라도 다른 지역의 접견실·농장·빈민가는 별도 시설로 구분했다. 궁전/첨탑/시타델/타워/바티칸의 입구와 내부, 로마 포럼, 검은 숲, 프라이빗 클럽, 사파리/결산, 데티네츠, 겨울 동화 등의 기존 개별 설명은 해당 화면 역할에 맞아 보존했다. 접미사만 보고 설명을 교환하지 않았다.

## 변경 지점·입출력·호출

새 로케이션과 새 영구 변수는 없다. 기존 reference revision의 목표만 4에서 5로 올린다.

| 로케이션 / 안정 식별자 | 동작 |
|---|---|
| jo9_reference_info / PLACE_STAGE_CRYO_CELLS | 기존 전체 크라이오 검수 설명과 예전 보충 설명을 인식해 운영 문단으로 갱신. 기존 별도 수동 설명은 보존. |
| jo9_reference_info / PLACE_STAGE_REFERENCE_V5 | 원래 stasis_bank/egeya_battle 설명 또는 공백일 때 단계별 설명을 적용. 마지막에 jo9_reference_info_revision=5. |
| jo9_reference_info / PLACE_STAGE_LEGACY_GASTRONOM, PLACE_STAGE_LEGACY_MEAT | 기존 세이브에 재고표가 설명으로 저장된 경우 원래 고정 라벨·HTML·숫자 칸 전체가 정확히 일치할 때만 검수된 설명을 복구. 추가 문구·라벨 변경·개행 등은 수동 설명으로 보존. |
| $newloc / PLACE_STAGE_CACHE_V5 | revision<5이면 기존 jo9_reference_info 호출. 기존 세이브의 다음 로케이션 처리에서 갱신. |
| shop_general / PLACE_STAGE_LIVE_* | 원래 재고 계산·문구를 지역 문자열 jo9_place_live_info에 담는다. place_info를 덮어쓰지 않는다. 입력은 기존 fridge/estate_size와 get_fridge_space, 출력은 기존 재고표와 같다. |
| shop_general / PLACE_STAGE_PANEL_SOURCE, PLACE_STAGE_PANEL_RENDER | 지역 문자열 jo9_place_panel_info로 우측의 기존 재고 또는 시설 정보를 선택한다. NPC 우측 분기는 유지한다. |
| shop_general / PLACE_STAGE_EMPTY_NARRATION | 지역 문자열 jo9_shop_narrative로 기존 지문을 읽는다. gastronom/meat/slaughter에서 지문이 빈 경우에만 시설 설명을 출력한다. 기존 sp_text 배열을 바꾸지 않는다. |

함수 반환값을 추가하지 않는다. 세 지역 문자열은 해당 shop_general 실행 범위에서만 쓰며 저장 상태에 새 키를 남기지 않는다. 거래 비용·행동 번호·선택 메뉴·냉장고 계산·전투 규칙은 바꾸지 않는다.

## 의존성과 복구

기존 #place_base/#npc_base와 $newloc가 jo9_reference_info를 호출한다. shop_general은 기존 display_options, place, sp_text, get_fridge_space 및 UI 렌더링을 사용한다. 코드 경계는 위 식별자와 패치 ID 2026-10-18_world_description_stages로 표시했다.

참조 갱신 호출만 제거하면 이전 저장 상태의 설명이 갱신되지 않을 수 있다. 재고 지역 변수 구간과 렌더링 구간은 함께 유지해야 한다. 한쪽만 제거하면 재고가 안 보이거나 설명과 재고를 잘못 선택할 수 있다. 하단 지문 대체 구간만 제거하면 기능·재고는 유지되지만 해당 시설 설명이 다시 숨을 수 있다.

완전 복구는 설치 영수증의 백업 QSP 또는 선언형 패치의 역적용을 사용한다. 이번 변경 이후의 수동 수정이 있으면 복구 전에 별도로 보존한다. 로케이션별 원자적 old/new 기록으로 중첩 주석 구간도 재적용 시 변경되지 않는다.

## 검증과 한계

수정 전 동일 검사로 문제를 재현하고 후보에서 133개 기능 검사를 통과했다. 구재고 문자열 인식은 별도 45개 검사로 검증했다. 패치 재생·재적용·바이트 역적용·QSP 구조와 실제 설치 엔진 9개 경로도 검사한다. 기능 검사의 화면 장식 의존성은 격리하며, 기존 메뉴 및 실제 재고·본문 렌더링 코드는 실행한다.

기존 세이브 UI 선택·CRC 호환 전수 확인과 모든 창 크기의 실제 화면 배치 확인은 별도다. 플레이본만 반영하며 배포본 동기화·커밋·푸시는 이번 작업에 포함하지 않는다.
