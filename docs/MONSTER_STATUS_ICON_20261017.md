# 괴물 상태 아이콘 적용

승인된 갈망·만족 아이콘을 사용해 괴물 정보를 조수 개인 상태 텍스트에서 분리한다. 현재 상태는 아이콘, 성장 이름은 툴팁으로 표시한다.

## 화면에서 달라지는 점

- 집 화면과 도시 화면에서 `레비아탄: 만족` 같은 괴물 문구를 조수 개인 상태칸에 출력하지 않는다.
- 우측 마지막 포트레이트 하단 버튼 줄의 맨 오른쪽에 독립된 32×32 괴물 아이콘을 표시한다.
- `tentacle_state=1`: 붉은 갈망 아이콘. `tentacle_state=2`: 촉수를 안으로 오므린 청록색 만족 아이콘.
- 괴물을 보유하지 않았거나 표시 상태가 0이면 아이콘을 숨긴다. 조수 유무·기절·사망 여부와는 독립적으로 출력한다.
- 툴팁은 `안개 괴물 · 레비아탄 / 현재 상태: 만족` 형식이다. 이름은 기존 성장 이름에서 읽고 색상 HTML을 제거해 표시한다.
- 아이콘을 클릭하면 기존 괴물 성숙도 표를 표시한다. 하단에서 잘리지 않도록 툴팁은 위로 열린다.

집의 청결·음식 표시와 기존 행동 버튼은 이번 변경 대상이 아니다.

## 코드 설명

| 표식 | 로케이션/파일 | 역할 |
|---|---|---|
| `MONSTER_STATUS_MAIN_SCREEN` | `main_screen` | 집 화면의 괴물 텍스트를 독립 아이콘 출력으로 교체 |
| `MONSTER_STATUS_CITY_SCREEN` | `city_screen` | 도시 화면에 같은 표시 적용 |
| `MONSTER_STATUS_LAYOUT` | `base.css` | 아이콘 위치·크기, 툴팁 위치 지정 |

입력은 기존 `pet_tentacle`, `tentacle_state`, `tentacle_size`, `$tentacle_name[]`이다. 출력은 HTML 아이콘 한 개이며 반환값은 없다. 기존 표시용 `$tooltip_text`를 재사용한다. 새로운 함수·로케이션·저장 변수는 추가하지 않는다. 모든 성장·일과·메뉴 판정과 게임 수치는 그대로다.

성장 이름은 그늘진 그리퍼 / 어둠의 유생 / 촉수 짐승 / 크라켄 / 레비아탄의 다섯 종류다. 성숙도를 기분으로 해석하거나 상태를 새로 늘리지 않는다.

## 파일과 분리 시 영향

- 플레이 `game/jack.qsp`: 위 두 로케이션만 수정. `mods/2026-10-17_zzzz_monster_status_icon.json`으로 기록한다.
- 플레이 `game/css/base.css`: 새 ID `jo9_house_monster`에 한정한 CSS를 추가한다.
- 플레이 `game/content/pic/ui/monster_status/craving.png`, `satisfied.png`: 승인된 두 PNG를 새 경로로 추가한다. 원본 이미지 교체 없음.
- 저장소 `assets/css-2.4` 및 `assets/content/pic/ui/monster_status`에 원천을 보관한다. 배포본과 JO9O는 변경하지 않는다.

QSP의 표식 구간 전체를 제거하면 괴물 표시만 사라진다. 성장과 상태 계산은 다른 기존 코드에 있으므로 이 출력 구간에 의존하지 않는다. 기존 조수 상태칸을 닫는 `*p '</div>'`는 표식 바로 앞에 남아 있어 출력 구간을 통째로 제거해도 div 구조를 유지한다. CSS만 제거하면 아이콘 위치가 풀리며, PNG만 제거하면 이미지가 깨진다. 원래 텍스트 배치로 되돌릴 때는 JSON 패치를 역적용한다.

기존 파일은 적용 직전에 해시를 재확인하고 날짜가 붙은 백업을 만든다. 백업 경로와 최종 해시는 작업 폴더의 `installed.json`에 기록한다. 이 문서의 백업을 복원할 때도 이후 수동 변경이 없는지 먼저 확인한다.

## 검증 범위

QSP 왕복·표준 패치 재생·정확한 역적용 검증을 통과했다. 두 로케이션 외의 데이터는 보존했다. QSP 5.7에서 최종 코드 그대로 32개 경우를 실행해 성장명·갈망/만족·미보유·상태 0·조수 없음·일반 이름 문자열을 확인했다. 독립 HTML에서는 5개 성장명×2개 상태의 10개 경우에서 이미지 로딩·버튼 겹침 없음·클릭 대상·툴팁 화면 안 표시·긴 이름 줄 잘림 없음을 확인했다. 구체적인 결과는 같은 작업 폴더의 `qa-agent` 및 `layout-check.json`에 기록했다. 게임 클라이언트 실행과 실제 세이브 플레이 검증은 수행하지 않았다.
