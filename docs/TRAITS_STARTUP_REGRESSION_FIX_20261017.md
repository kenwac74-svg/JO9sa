# 시작·불러오기 공통 경로의 빈 화면 회귀 수정 — 2026-10-17

이번 특성 추가의 부분 치환이 CRLF 두 글자 사이에서 끊어졌다. 치환 조각만 줄바꿈을 변환하고 완성한 로케이션 본문을 검사하지 않아 단독 LF 2곳과 단독 CR 19곳이 남았다.

직접 원인은 menu_form의 TRAITS_EDITOR_NEXT 종료 주석 바로 뒤 단독 LF였다. 다음 end가 주석에 붙으면서 블록 종료로 인식되지 않아, 편집기를 열지 않은 일반 홈 진입도 중단했다. menu_form만 이전 본문으로 되돌리는 대조와 해당 LF 한 곳만 고친 진단본에서 홈·새 게임 시작이 모두 복구되어 원인을 확인했다.

| 위치 | 수정 |
|---|---|
| menu_form | 단독 LF 1곳 |
| main_screen | 단독 LF 1곳 |
| next_day | 단독 CR 17곳 |
| interaction_result | 단독 CR 2곳 |

네 본문은 줄바꿈 외 모든 문자를 보존했고 전체 파일은 42바이트 커졌다. 기존 jo9_traits_revision의 판정·대입 두 숫자를 1에서 2로 올려 잘못된 버전에서 저장된 수행 템플릿도 다음 사용 시 다시 정의하도록 했다. 캐시 플래그를 초기화하는 기존 갱신을 재사용하며 특성 조건·수치·효과, 로케이션 수, 개인 저장 키는 바꾸지 않았다.

설치된 실제 jack.exe로 격리 복사본을 실행했다. 이전 정상본은 홈과 새 게임 완료 지점에 도달했고 오류본은 둘 다 멈췄다. 메뉴 LF 한 곳만 수리한 진단본과 최종 수정본은 모두 통과했다. 최종본에서 홈, 새 게임, 노예/조수 신규 편집 페이지, 캐시 갱신, 하루 마무리 화면 진입을 확인했다. 기존 버전1에서도 캐시 버전2와 두 수행 템플릿의 재생성 예약을 확인했다.

기존 세이브의 수치·짧은 상태 문자열을 진단 QSP에 옮겨 같은 인물 상태를 재현했다. 원본 세이브는 수정하지 않았다. 실제 GUI 불러오기 메뉴를 클릭했다거나 화면 배치를 눈으로 확인했다는 뜻은 아니다. Computer Use 초기화 실패로 입력 조작은 하지 않았으며 실제 클라이언트의 완료 메시지 로그로 대조했다.

tools/qa/check-qsp-line-endings.cjs는 지연 코드 문자열까지 원문 그대로 검사한다. 오류본에서21곳을 검출해 실패하고 수정본에서0곳으로 통과한다. 작업 생성기는 조각 치환을 모두 마친 본문 전체를 마지막에 한 번 정규화하도록 수정했다. 이전 개별 효과 검사는 전체 menu_form 진입을 검사하지 않아 이 결함을 놓쳤다.

Play에 먼저 적용하고, 이미 공개한 잘못된 버전의 수정으로 배포본에도 같은 패치를 적용했다. 각 jack.qsp.bak_날짜 백업을 남겼다. 보호 원본 JO9O·CSS·원본 세이브는 유지한다. 기존에 켜 둔 창은 이전 코드를 메모리에 갖고 있으므로 완전히 종료 후 재실행하여 기존 세이브를 다시 불러온다. 세이브 삭제나 새 게임 재작성은 필요 없다.
