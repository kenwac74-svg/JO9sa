## 1. 확정된 것
### 1.1 과거 경험 공식(통계)
- 코드 `dist/past-history.mjs`, 계수 `dist/data/past-history-formula.json`(승인), 검사 `checks-past-history.mjs`.
- 총횟수 = 기준량(기술 등급) × 직업 × 출신 × 세계 × 연령 × 성욕 특성 × 기본 속성(외모 등, 안개경계 상처 대신 기본값) × 특성 키워드 × 변동(각 /100, 정수). 처녀 고정 배경 0, 비처녀인데 0이면 1~3, 클론 0, 연령 코드 1 제외, 유부녀만 임신·출산.
- 질·구강·애널 배분은 기술 등급²에 성향 특성 배율. **모든 특성 추첨이 끝난 뒤 맨 마지막**에 계산한다.
- 세계·출신·직업 계수는 대분류 범위 → 소분류 값 구조(`categories`). 기본 범위는 결과 불변.

### 1.2 섹스토크 커맨드
- 메뉴: 대화하기 > 질문한다 아래. 하루 1회(한 뒤 메뉴 비활성). 행동력 0.5.
- 거부 순서: 절망 ≥ 3("말씀 드리고 싶어도 기억이 안 납니다") → 응석 ≥ 3("몰라요, 말하기 싫어요, 흥~") → 인식 ≤ 2("그런 은밀한 제 비밀에 대해서 대답할 의무는 없습니다").
- 헌신 1~5로 질문이 열린다(22개, 기획 6.1 표). 화면: 우측 "내 방 / 섹스토크 중" 아래 질문 목록, 다 못 담으면 ◀이전 질문 - 다음 질문▶, 노예 답은 하단 대사창.
- 노예 속성은 말투에만 영향(감수성·성격·자아·태도 = 성격 9유형).
- 숨은 성향: 대화 = 처음 겪기와 같은 효과(발견). 경험치형 성향은 기준의 70% 이상일 때 대화 1회 = 경험 1(하루 1회), 기준값은 게임 값(#static_base 1646~).
- 거짓말: 이 노예에 대한 장악력 < 0이면 사실 대신 기존 오답(다른 노예의 답)으로 답한다(사용자 결정 2026-11-12).
- 반말: 왕족·귀족 출신 노예가 사육·헌신·두려움 등급이 낮은 초기 상태일 때.
- 사실 일관성: 사실은 영입 때 한 번 정해 저장(`dist/past-facts.mjs`, `dist/data/past-facts.json`). 같은 질문에 언제 물어도 같은 사실.
- 첫 경험: 성인은 나이를 고유어로("스물두 살 때였어요.."), 청소년기는 나이를 뽑지 않고 창작물 인터뷰 번호만 연결, 화면에는 "[이 대사는 표시 불가합니다.]". 현대 평균은 러시아 자료 18세.
- 이종 경험: 이터널 로마(잭오나 세계관) 안의 일만. 안개 경계 순찰에서 괴물에게 당하던 중 구출(장면 611xx: 촉수·괴물·와그). **이전 주인 촉수 착정은 이터널 로마 출신 특수 설정 유니크에게만 수동 지정**한다. 다른 세계 출신 노예(직업 '노예' 포함)는 자기 세계에서 노예였으므로 없다(무작위 생성 0%, 사용자 결정 2026-11-12). 안개 경계·경매장·밀수업자·암시장에서 얻는 노예는 모두 다른 세상에서 바로 온 상태이므로 해당하지 않는다. 게임 세계관에 오래 머문 것으로 설정된 유니크만 해당한다(안개 경계 구출의 괴물 경험은 등장 사건이므로 별개로 센다). 살던 세상의 동물 경험은 B2(표시 불가).
- 표시불가 내부 코드: B1 청소년기, B2 수간, B3 근친, B4 금기 목록, B5 SNS, B9 빈 대답. 화면에 코드는 보이지 않고 키로 사유를 찾는다.
- 유니크: 기본 묶음 결과를 추출해 사용자가 각색·수동 지정.

### 1.2a 대화는 영입 뒤 경험도 반영한다 (사용자 결정 2026-11-12)
- 등장 직후에는 영입 전 과거 경험(사실 필드)만 말한다.
- 육성하면서 생기는 경험을 누적해 대화에 반영한다: **주인과의 경험**, **주인 외 사람과의 경험**(창관 모드에서 창관 근무, 개인실·길거리 일 등), 이종 경험(안개 경계 등).
- 따라서 게임 적용 때 사실을 두 층으로 둔다.
  | 층 | 내용 | 변하는가 |
  |---|---|---|
  | 영입 전 과거 | `past-facts`가 영입 때 한 번 정한 값(첫 경험, 과거 상대 수 등) | 고정 |
  | 영입 후 누적 | 주인·주인 외(창관·길거리 등)·이종별 횟수와 상대 수, 하룻밤 최다 등 | 게임 행동마다 증가 |
- 질문의 답은 두 층을 합친 값(예: 상대 수 = 과거 + 영입 후)으로 말하고, 주제에 따라 "주인님을 만나기 전에는…", "여기 와서는…"처럼 구분해 말할 수 있게 한다. 누적 카운터를 올릴 게임 지점(직접 섹스, 창관 근무, 길거리 일 등)은 모드 제작자가 찾아 연결한다.

## 3. 대사를 QSP에 넣을지, 별도 JSON으로 둘지 (중요)
**판단은 로컬에서 게임을 실행할 수 있는 모드 제작자가 한다(사용자 결정 2026-11-12).** 사용자 희망: 로딩에 문제가 없다면 **별도 JSON**(세이브 영향 없음). 아래는 판단 자료다.
- 이 게임(FastQSP)이 JSON을 읽는 방식은 확인된 것이 하나다: **시작할 때 `json` 폴더의 캐릭터 JSON을 `seed_<키>[ID]` 전역 변수로 채운다**(`get_stock_seed`가 이 변수를 읽음). 이 경로로 대사를 넣으면 대사가 전역 변수가 되어 **세이브에 함께 저장될 가능성이 크다**(QSP는 전역 변수를 모두 저장). 그러면 "세이브 영향 없음"이라는 장점이 사라진다.
- 필요할 때만 읽고 버리는 JSON 읽기 함수가 FastQSP에 있는지는 확인하지 못했다(이 세션의 시험 엔진은 FastQSP가 아니다).
- 결정 전에 사용자 PC에서 할 확인(10분):
  1. `game/json` 아래에 큰 시험 JSON(예: 1MB 문자열 하나)을 둔다.
  2. 게임을 켜서 새 게임 → 저장 → 세이브 파일 크기를 시험 전과 비교한다.
  3. 커졌으면 JSON 자동 로드는 세이브에 들어간다.
- 판단:
  | 결과 | 권장 |
  |---|---|
  | 세이브가 커짐 | **방안 A**: 대사 원본은 JSON으로 관리하고, 빌드 때 QSP location 문자열로 넣어 필요할 때 `local`로 읽는다. 세이브 영향 없음, 쓰는 순간에만 읽음. 단 location이 너무 크면 느려지므로 묶음당 조각 수 상한(예: 300)을 둔다 |
  | 세이브가 그대로 | 별도 JSON을 그대로 쓴다. 단 시작 로딩 시간을 확인한다(참고: 비슷한 규모의 대사 변수 9,120행을 이 세션의 시험 엔진에서 읽는 데 약 8초) |
- 어느 쪽이든 원본 형식은 편집기의 JSON 대사집(설계 문서 7장 스키마)으로 유지한다.

## 4. 게임 적용 순서(권장)
1. 3장 확인으로 저장 방식 결정.
2. 과거 경험 공식·사실 생성기를 QSP로 옮긴다(정수 연산, mulberry 대신 게임 `rand` 사용, 시드 고정이 필요하면 영입 때 한 번 계산해 저장). 저장 키는 인물 배열에 문자열 한 줄(사실 약 250바이트), 인물 교체 목록에 등록.
3. 섹스토크 메뉴·거부 조건·헌신별 질문·하루 1회·행동력 0.5.
4. 대사 조립(유형·말투·관계·반말 규칙·표시불가 자리표시).
5. 숨은 성향 발견·경험치 반영.
6. 편집기 시뮬레이터 결과와 엔진 결과를 같은 입력으로 대조한다.
