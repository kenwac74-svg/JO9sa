## 1. 만들어 두신 구조가 앞으로의 UI 관리 기준입니다

```text
game/SNKmod/content/pic/
├─ buttons/
├─ ui/
├─ ui overhaul/
└─ bg/
   ├─ slave_psychology/
   └─ trophy/
```

앞으로 수정하는 UI는 **가능한 한 이 분류 안에 배치**합니다. 기존 파일이 어느 모더의 폴더에 들어 있는지보다는 **버튼인지, 패널인지, 번역 이미지인지, 트로피룸 리소스인지**를 기준으로 목적지를 정하는 것입니다.

예를 들어 말씀하신 `content/pic/ui/grimdark/...`의 엄지 아이콘도, 기존 위치 때문에 우리 모드에 똑같은 `grimdark` 계층을 만들 필요는 없습니다. **모드의 `buttons/` 아래에 정리하고, 그것을 사용하던 UI 참조를 새 위치로 연결하는 방식**으로 처리하면 됩니다. 구체적인 하위경로는 실제 파일을 대조해서 정합니다.

## 2. 따라서 단순한 경로 접두사 변경만으로 처리하지 않습니다

모든 경로 앞에 `SNKmod/`를 붙이는 것만으로는 기존의 산재와 중복이 그대로 남습니다. 필요한 것은 **기존 참조 경로와 정리된 모드 경로 사이의 대응 관계**입니다.

```text
기존 위치 A ─┐
             ├─→ 정리된 모드 이미지 한 곳
기존 위치 B ─┘
```

이렇게 연결하면 나중에는 모드 이미지 한 곳만 수정해도, 그 이미지로 연결한 여러 UI에 반영되도록 만들 수 있습니다. **원본 A·B 파일을 이동하거나 삭제하는 것은 아닙니다.** 원본은 복구용으로 기존 위치에 남기고, 모드가 사용하는 파일과 참조만 정리합니다.

## 3. 중복은 ‘같은 이름’과 ‘같은 용도’를 구분하겠습니다

말씀하신 트로피 이미지처럼 여러 폴더에 중복된 파일이 있어도, **파일명이 같다는 이유만으로 바로 합치지는 않겠습니다.**

그림·규격·투명도와 사용처를 확인하여 **같은 모드 그림을 함께 써도 되는 경우에만 하나로 통합**하는 것이 맞습니다. 이름은 같아도 활성/비활성 상태나 테마별로 달라야 하는 이미지라면 구분해서 보관합니다. 반대로 파일명이 달라도 실제로 같은 그림과 용도라면 통합 후보가 됩니다.

이 정리는 **UI/UX에만 적용**합니다. 캐릭터·NPC·일반 배경은 앞서 확정한 기존 경로 덮어쓰기 방식을 유지합니다.

**다음 한 가지만 확인하겠습니다. 실제 중복이며 같은 그림을 함께 사용해도 되는 UI는, `SNKmod` 안에 파일 하나만 두고 여러 기존 참조를 그 한 파일로 연결하는 방식으로 통합할까요?**

또한 **중복 파일을 제가 임의로 합치거나 경로를 재설계하지 않겠습니다.** 별도 지정이 없는 UI는 기존 구조를 유지하고, 지정해 주신 예외만 정리합니다. 패키징 시에는 각 파일의 **적용 정책·기존 경로·설치 경로**를 구분해서 반영하면 됩니다.

이 기준으로 **`JO9UIpatch`의 `docs/ASSET_INSTALL_POLICY.md`를 갱신했습니다.** 이번에는 정책 문서만 수정했으며, 실제 이미지 이동이나 QSP·설치기 변경은 하지 않았습니다.

### 8. 답변 · 턴 1a806aa4-4c6a-4bdc-a6da-53d160eb8d8b

네. **‘파일명이 같다’, ‘파일 내용이 완전히 같다’, ‘게임에서 사용한다’는 서로 별개로 확인하겠습니다.** 동명 파일을 전부 통합 대상으로 올리는 것이 아니라, 제가 먼저 구분한 뒤 필요한 결정만 질문드리겠습니다.

| 확인 결과 | 처리 방식 |
|---|---|
| **여러 경로에서 사용하며, 파일도 완전히 동일** | 동일한 사본임을 알려드리고 **통합할 경로만 확인**받습니다. 승인 후 모드 파일 하나로 관련 참조를 연결합니다. |
| **여러 경로에서 사용하지만, 이름만 같고 그림은 다름** | 사용처와 그림·규격의 차이를 보여드리고 **사용할 이미지와 통합 경로를 확인**받습니다. |
| **동명 파일 중 일부는 미사용으로 확인됨** | 사용되는 파일과 구분해서 알려드리고, **미사용 사본은 패키징·참조 변경 대상에서 제외**합니다. 원본 폴더의 파일을 삭제하지는 않습니다. |
| **사용 여부가 불확실함** | **‘참조 미확인’으로 보류**합니다. 미사용이라고 단정하거나 임의로 제외하지 않습니다. |

특히 **소스에서 파일명 검색이 안 됐다는 이유만으로 미사용 처리하지 않겠습니다.** 관련 QSP·CSS·HTML의 경로 구성과 조건을 확인하고, 소스 연결을 확인한 것과 실제 게임 표시까지 확인한 것도 구분하겠습니다.

완전히 동일한 사본에는 불필요하게 “어느 그림을 쓸까요?”라고 묻지 않고, **“이 경로들에서 같은 파일을 사용하니, 모드에서는 이 한 경로로 모을까요?”**처럼 질문하겠습니다.
