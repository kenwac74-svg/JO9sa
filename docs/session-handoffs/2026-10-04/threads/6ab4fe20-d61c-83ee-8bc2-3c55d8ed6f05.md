## 2. 참조를 찾아야 하는 대상

후보 이미지가 게임에서 사용되는지를 판단하기 위해 다음을 조사한다.

1. 게임 전체 `jack.qsp`
2. QSP를 텍스트로 추출하거나 디컴파일한 전체 소스가 있다면 그 전체 소스
3. 게임에서 사용되는 CSS 전체
4. QSP 내부 HTML 문자열
5. `<img src=...>` 같은 HTML 이미지 참조
6. CSS `background`, `background-image`, `url(...)` 참조
7. 이미지 경로를 생성하는 QSP 변수 및 문자열 결합
8. 이미지 파일명을 변수, 배열, 조건문 등으로 선택하는 코드
9. 디렉터리 경로만 코드에 있고 파일명이 런타임에 조합되는 경우
10. 공통 함수 또는 UI 출력 함수를 통해 간접적으로 호출되는 이미지

특정 몇 개 location만 검사하지 말고 **QSP 전체를 분석한다.**

## 3. 매우 중요한 판정 규칙

각 후보 이미지를 다음 3가지 중 하나로 분류한다.

### ① CONFIRMED_USED
실제 코드에서 해당 이미지에 대한 직접적인 참조를 찾은 경우.

예:

`content/pic/buttons/teach.png`

또는

`pic/buttons/teach.png`

또는 파일명을 포함하는 명확한 `<img>` / CSS 참조 등.

### ② INDIRECT_OR_DYNAMIC
파일 전체 경로가 문자 그대로 존재하지 않지만, 코드 구조상 해당 이미지가 사용될 수 있음이 확인되는 경우.

예를 들어:

`'content/pic/buttons/' + $button_name + '.png'`

또는

`'content/pic/ui/' + $status_icon`

또는 파일명 배열:

`$icon[0] = 'thumb_up.png'`

같은 구조이다.

이 경우 절대 UNUSED로 분류하지 마라.

어떤 변수, 배열, 함수, 경로 조합 때문에 연결된 것으로 판단했는지 근거를 기록하라.

### ③ NO_REFERENCE_FOUND
QSP 전체 + CSS 전체 + HTML 문자열 + 동적 경로 생성 로직까지 조사했지만 해당 파일에 연결되는 근거를 찾지 못한 경우.

이것만 "미사용 후보"로 분류한다.

중요:
`NO_REFERENCE_FOUND`는 "게임에서 절대로 사용되지 않는다"는 뜻이 아니라

**현재 분석한 QSP/CSS 코드에서는 참조 근거를 찾지 못했다**

라는 의미이다.

## 4. 단순 문자열 검색으로 끝내지 마라

특히 다음 패턴을 반드시 조사한다.

### 파일명만 등장하는 경우

예:

`thumb_up.png`

경로 없이 파일명만 존재해도 찾아야 한다.

### 확장자를 코드에서 추가하는 경우

예:

`$icon + '.png'`

### 폴더와 파일명이 분리된 경우

예:

`$path = 'content/pic/buttons/'`

이후 다른 코드에서

`$path + $icon`

### 조건문으로 이미지가 정해지는 경우

예:

```
if pregnant:
    $icon = 'z_pregnant.png'
end
```

### 배열 / lookup table

예:

```
$status_icon[0] = 'z_ill.png'
$status_icon[1] = 'z_wounds.png'
```

### HTML 조합

예:

```
'<img src="' + $image_path + '">'
```

이 경우 `$image_path`가 어디서 만들어지는지도 역추적한다.

3. 파일명 전체
4. 확장자를 제외한 파일명
