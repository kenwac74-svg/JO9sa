> ### 설치기 안전 정책
> 패키지는 계속 다음 구조 유지:
>
> `CHECK.cmd`
> `APPLY.cmd`
> `RESTORE.cmd`
> `Install.ps1`
> `manifest.json`
> `qsp-patches.json`
> `PanelCodec.cs`
> `payload/`
>
> 원칙:
> - CHECK는 메모리에서만 계획 계산, 게임 파일 쓰기 금지
> - APPLY 전에 package payload 전체 SHA-256 검증
> - 변경 파일만 backup
> - temp 파일 작성 → 교체 → hash 검증
> - 오류 시 rollback
> - restore 전에 backup hash 및 현재 설치 파일 hash 검사
> - 설치 전 존재하지 않던 파일은 restore 시 삭제
> - 같은 경로 manifest 중복 금지
> - 새 리소스는 Files + Payload + Restore allowlist 모두 갱신
>

> `game/_JO9_UI_ALL1914_BACKUPS/`

> 해야 할 방식:
> - 단순히 buttons 폴더 전체를 나열하지 말 것
> - 현재 한국어판 v2.3.2.5 / FIX5 기준 QSP + CSS에서 실제 참조를 추적
> - 실제 사용되는 이미지 파일만 추출
> - HTML에 이미지 미리보기, 파일명, 크기, 참조 location 또는 CSS 위치를 표시
> - 가능하면 사용 화면/용도도 표시
> - 미사용 파일은 별도 섹션으로 분리하거나 기본 목록에서는 제외
> - 이후 사용자가 선택한 이미지들을 수정하고 다음 누적 패치에 반영할 예정
>
> ### 앞으로의 빌드 규칙
> 사용자가 새로운 UI 이미지 ZIP이나 개별 파일을 주면:
> 1. FIX5와 비교
> 2. 정확히 어느 경로를 교체/추가하는지 확인
> 3. 사용자가 파일 교체만 요청했다면 코드 참조를 새로 만들지 말 것
> 4. 기존 누적 리소스가 빠지지 않았는지 반드시 검증
> 5. 새 빌드는 FIX6 또는 다음 적절한 번호로 생성
> 6. ZIP은 Python `zipfile`을 사용하여 한국어/Unicode 파일명 보존
> 7. ZIP CRC + 압축 전후 SHA-256 + manifest integrity 재검증
> 8. Windows PowerShell 5.1 실제 실행 테스트를 하지 못했다면 그렇게 명확히 표시
>
> **가장 중요한 원칙:**  
> 이전처럼 오래된 R1을 기준으로 재구성해서 최신 리소스를 잃어버리지 말 것.  
> 이제부터 모든 작업은 **FIX5를 유일한 누적 기준선**으로 삼는다.

이걸 새 채팅 첫 메시지로 넣으면 된다. 이후 첫 작업은 **`buttons` 실제 사용 이미지 HTML 카탈로그 작성**부터 이어가면 가장 자연스럽다.
