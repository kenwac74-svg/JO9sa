# JO9 창관 경영 모드 (Brothel) — 복원 기준 문서

- 저장 브랜치: `brothel`
- 작성일: 2026-10-06
- 목적: 과거 「재고나 창관모드」 기획 대화와 기존 기획서에서 합의된 내용을 다시 미정으로 되돌리지 않기 위한 기준 문서.
- 원칙: 과거 기록에서 확인되는 사항만 **확정**으로 적는다. 세부 원문을 아직 회수하지 못한 사항은 **복원 필요**로 분리한다.

## 1. 모드의 기본 방향 — 확정

- JO9 안에 별도의 **창관 경영 콘텐츠**를 추가한다.
- 비프로스트식 창관 경영의 핵심 구조를 참고하되 JO9의 기존 시스템과 데이터를 최대한 재사용한다.
- 단순 소모형 콘텐츠가 아니라 **유지·성장형 창관**이다.
- 창관은 지도상의 실제 장소/부동산으로 취급하며, 구매 후 방문·운영한다.
- 방문과 영업에는 JO9의 기존 행동력 체계를 사용한다.
- 새로운 전용 능력치를 무분별하게 추가하지 않고 JO9의 기존 캐릭터 데이터, 상태, 명령 가능 판정 등을 우선 재사용한다.

## 2. 코어 영업 루프 — 확정

기본 루프:

1. 창관 방문
2. 당일 고객/고객 큐 생성
3. 고객의 요구와 상태 확인
4. 접객 가능한 종업원 선택
5. 기존 JO9 능력치/특성 기반으로 매칭 및 접객
6. 고객 상태와 만족도 변화
7. 지불액/수익 산출
8. 누적 만족도와 창관 성장에 반영
9. 고객 큐 소진 또는 강제 폐점 시 영업 종료

### 행동력

- **고객 1명 접객 = 행동력 1 소모**를 기본 단위로 한다.
- 종업원 스태미나가 0인 상태에서 추가 접객 시 **추가 행동력 0.5**가 걸리는 것으로 과거 기록에서 복원된다.
- 종업원 정신력 0은 기분/정신 관련 페널티와 연결한다.
- 기존 JO9의 행동력·피로·기절/위험·기분 시스템을 재사용한다.
- 사용자가 2026-10-06 다시 확인한 과거 합의: **그룹 고객은 약 1.5명 상당의 처리 단위/보정**을 사용했다. 정확히 어떤 항목에 1.5배를 적용했는지는 원 대화 회수 후 문구를 보강한다.

## 3. 종업원 — 확정

- JO9에서 기존 규칙상 **명령 가능한 노예**를 창관 종업원으로 배치한다.
- 창관 레벨에 따른 종업원 **최소 등급 제한은 두지 않는다**.
- 등급과 기존 능력치는 배치 제한이 아니라 매칭/접객 결과와 만족도에 영향을 준다.
- 창관 Lv.1의 기본 종업원 슬롯은 **1명**, 레벨이 오를 때마다 **+1명**으로 복원되어 있다.
- 별도의 창관 전용 캐릭터 스탯을 대량 추가하지 않는다.

## 4. 고객 상태 모델 — 확정된 골격

고객은 JO9의 기존 상태 개념을 활용한 임시 스테이터스를 가진다.

- **HP = 고객 예산/지불 가능한 금액의 기반값**
- 접객 과정의 HP 감소량은 실제 **지불액**과 연결된다.
- **고객 스태미나 0 = 착정/육체적 완료 상태**
- **고객 정신력 0 = 만족도 보너스 상태**
- **스태미나와 정신력이 모두 0 = 최상 결과**

고객 만족도는 단일 수치만이 아니라 **육체 만족 / 정신 만족의 이중 구조**를 사용한다.

## 5. 고객 요구와 매칭 — 확정된 방향

- 비프로스트식 **요구 슬롯 매칭**을 핵심으로 한다.
- 고객 요구를 보고 적합한 종업원을 선택하는 것이 플레이의 중심이다.
- JO9 기존 등급, 성기술, 외모·체형, 취향, Trait 등 기존 데이터를 가능한 범위에서 매칭 판정에 재사용한다.
- 완벽히 맞는 종업원이 없더라도 접객 자체가 불가능해지는 구조로 만들지 않는다.
- 만족도 중심으로 결과와 창관 성장이 이어진다.

## 6. 그룹/다인 고객 — 확정된 골격

- 그룹 고객은 개별 고객 여러 명을 UI에서 따로 굴리는 대신 **하나의 group 객체**로 취급하는 구조가 과거 기록에서 확인된다.
- 그룹의 HP/스태미나/정신력은 **인원수에 따라 증가/배수 처리**한다.
- 그룹 접객 시 종업원 능력치/효율에는 별도 보정이 들어간다.
- 행동력/처리량 측면에서는 사용자가 다시 확인한 **약 1.5명 상당 규칙**이 존재한다.
- 정확한 그룹 인원별 배율표와 1.5 규칙의 적용 대상은 원 대화 추가 복원 대상이다.

## 7. 창관 성장 — 확정

- 고객 만족도를 누적해 창관이 성장한다.
- 창관 레벨은 **Lv.1 ~ Lv.10**.
- 레벨업은 단순 돈 지불이 아니라 **고객 만족도 누적**을 핵심 성장축으로 한다.
- 종업원 슬롯은 Lv.1 1명에서 시작하여 레벨당 +1명으로 복원되어 있다.

## 8. 시설/확장 — 확정된 방향

- 시설 체계를 둔다.
- 시설과 담당자형 애드온을 결합하는 구조를 사용한다.
- **조교실**과 **훈련도구 관리실**은 서로 다른 역할로 분리한다.
- **네크로관**은 일반 창관과 분리된 특수 확장 슬롯이며 **사망자 전용**이다.
- 일반 창관과 네크로관은 같은 코어 엔진을 최대한 재사용하되 특수 조건만 분리한다.

## 9. 마담 — 기존 상세기획에 포함

- 마담 시스템은 2026-09-23 상세기획본까지 포함되어 있던 설계다.
- 마담의 정확한 효과, 슬롯, 능력치 반영식은 원문 재확인이 필요한 항목으로 둔다.

## 10. 임신/기존 JO9 시스템 호환 — 기존 상세기획에 포함

- 임신 시스템과의 호환/연동을 고려하는 것이 기존 상세기획에 포함되어 있다.
- 기존 JO9 시스템을 깨지 않고 접객 결과가 원래 게임의 상태 변화와 연결되도록 하는 방향이다.
- 정확한 임신 판정 시점과 예외 규칙은 원문 재확인 대상이다.

## 11. UI 방향 — 합의된 구조

기존 JO9 UI 리소스를 최대한 재사용한다. 없는 것만 신규 제작한다.

PC 경영 화면의 기본 구조:

- 왼쪽: 종업원 목록(약 6~10명 표시)
- 가운데: 선택 종업원 상세 정보 / 배정
- 오른쪽: 현재 고객 요구, 상태, 만족도
- 하단: 마담/시설/창관 성장 또는 운영 정보
- 기존 JO9 버튼, 프레임, 아이콘, 캐릭터 얼굴, 배경 등 실제 게임 리소스를 우선 재사용한다.
- 신규 UI를 전혀 다른 게임처럼 그리지 않고 **실제 JO9에 이미 구현된 화면처럼 보이게** 한다.

## 13. 복원 작업 규칙

앞으로 창관 기획을 진행할 때:

1. 이 문서에 **확정**으로 적힌 내용은 새로 선택지로 제시하지 않는다.
2. 과거 대화에서 추가 결정이 발견되면 이 문서를 갱신한다.
3. 과거 자료끼리 충돌하면 더 나중 날짜의 사용자 결정이 우선한다.
4. 기억이나 일반 게임 지식으로 빈칸을 임의 확정하지 않는다.
5. 새 결정은 `확정 / 잠정 / 미정` 중 하나로 기록한다.
6. UI/구현 전에 기획 기준 문서를 먼저 갱신한다.
