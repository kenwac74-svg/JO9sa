## 0. 게임에서 바뀌는 것 (요약)
- 질문하기 6종(1111·1112·1113·1114·1115·1117)의 원래 대답 뒤(1113은 앞)에 노예의 `[이름]` 한마디가 붙는다. 현재 기분 묻기(1116)는 바뀌지 않는다.
- 노예 포트레이트 하단 상자: 원래 3인칭 나레이션 뒤에 `[이름]` 1인칭 한 줄이 붙는다.
- 조수 포트레이트 하단 상자: 보고 내용은 같고, 조수 직업이 해요체·투박한 해요체인 경우에만 말투가 바뀐다.
- 원래 게임 문장은 지우거나 고치지 않는다. 예외 하나: 요구 묻기의 `$no_need_gentle`은 조건부로 이음 문장으로 바뀐다 (3.3).

## 1. 원칙
1. **새 상태 변수 0개.** 저장되는 값을 새로 만들지 않는다. 계산은 그때그때 기존 값으로 한다.
   - 계산용 임시 변수는 써도 되지만, 쓰고 나면 `killvar`로 지운다 (세이브에 남지 않게).
   - 대사 문자열 배열과 고정 표(직업→말투 등)는 상태가 아닌 상수이므로 추가해도 된다.
2. **qsp 직접 수정.** `.qsrc` 재빌드 금지. 수정 전 왕복 검증(읽고 다시 쓴 결과가 원본과 바이트 동일)과 백업.
3. **새 location을 만들지 않는 것을 권장.** 보조 코드는 기존 `#dynamic`에 `$voice_*` 동적 문자열로, 대사는 기존 `#txt_man` 끝에 넣는다. location 수가 바뀌지 않아 다른 패치와 충돌이 적다.
4. 수정은 `mods/`에 선언형 JSON(location, old, new, count, 전후 SHA-256)으로 남기고 `tools\apply_mods.ps1`로 적용한다.
5. QSP 주의
   - `$x`와 `x`는 같은 이름 공간이다. 문자열/숫자 변수 이름을 겹치지 않게.
   - 문자열 리터럴 안의 `<<>>`는 대입 시점에 평가된다. 늦게 평가할 자리는 `{과목}`처럼 표식을 두고 `$replace`로 바꾼다.
   - 한 줄 `elseif`를 쓰지 않는다.

### 2.4 어휘 (가족 `$slave_family`)
- 1차 구현은 **보통 어휘만** 쓴다. 어휘 판(궁정·세련·거친)은 검수 뒤 작성하며, 나중에 넣을 수 있게 대사 키에 어휘 자리를 비워 둔다 (3.1).

### 2.5 의사난수 (기존 문법)
```
((48271 * (day + interaction + k)) mod 65537) mod n
```
- 정신분열 대사 고르기, 조각별 어투 고르기에 쓴다. k는 조각 번호 등으로 바꾼다.

### 2.6 "오늘"·"요즘" 판정
| 판정 | 계산 | 근거 |

| 요즘 자주 처벌 | 처벌 계열 행동 번호의 `slave_already_done_recent[...]` 합 ≥ 3 | 같음 |

칭찬·처벌 계열 행동 번호 (코드의 `$interaction_type` 기준, 구현 때 재확인)

- 처벌: abuse 1411~1415, torture 1421~1425·1431~1435·1441~1448·1461~1468·1471~1472·14521~14526·14531~14536 (목록이 길다. `interaction`에서 `$interaction_type = 'torture'`인 번호를 전부 모은다)

## 3. 대사 저장과 출력

### 3.1 저장 형식 (`#txt_man` 끝에 추가)
```
$voice_1112['A_ice_1'] = '요즘 칭찬이 잦으십니다. 이유는 묻지 않겠습니다.'
         자리  화제_유형_말투(1합니다 2해요 3투박)
```
- 자리: 1111, 1112, 1113, 1114, 1115, 1117, ps(노예 포트레이트), pa(조수 포트레이트), sz(정신분열)
- 나중에 어휘 판을 넣을 때는 끝에 `_어휘`(c궁정, r세련, x거친)를 붙인 키를 추가하고, 없으면 기본 키를 쓰게 한다.
- `{과목}`은 출력 직전에 `$replace`로 바꾼다.

### 3.2 출력 형식
원래 대답과 같은 모양의 블록으로 붙인다.
```
$text[] = '[<<$slave_name>>]<br> ' + (고른 대사) + '</div>'
```
- 원래 문장 블록의 실제 머리·꼬리 모양(`[<<$slave_name>>]<br> ` … `</div>`)을 원문에서 확인하고 똑같이 맞춘다.

### 3.3 자리별 처리
| 자리 | 위치 (덤프 기준) | 처리 | 대사 원문 |
|---|---|---|---|
| 1111 과거 | `interaction` 1111 `$special_part`, `$text[3]` 뒤 | 헌신 4 이상 → A / 기분 −2 이하 → B / 기분 +2 이상 → C / 그 밖 없음. `$text[]`로 붙임 | `lines/1111` |
| 1112 인상 | `interaction` 1112 `$special_part` 끝 | 2.6 판정. 오늘 일 있으면 오늘(C·D) 하나. 요즘과 오늘이 반대(A+C, B+D)면 둘 다. 오늘 없으면 요즘 하나 | `lines/1112` |

### 3.4 트레잇 덮어쓰기 (`lines/doll_trait`)
| 조건 | 처리 |
|---|---|
| 정신분열 (모든 유형) | 위 모든 자리(1111~1117 덧붙임, 노예 포트레이트)의 덧붙임을 정신분열 대사로 바꾼다. 12줄(조합형 Z1~Z6, 통 대사 T1~T6) 중 의사난수로 하나. 조합형이면 조각마다 말투 1~3을 따로 의사난수로 |
| 신경쇠약 + 인형 | 1113 요구 묻기에서만 덧붙이지 않는다. 다른 자리는 그대로 |
- 판정 순서: 정신분열 → (자리별 규칙) → 신경쇠약+인형(1113만).

### 3.5 거부
- 노예가 대답을 거부하면 지금의 거부 대사를 그대로 쓴다. 덧붙임을 만들지 않는다. 거부 때 `$special_part`가 실행되지 않는지 확인한다.

### 3.6 조수 쪽
- 1차 범위는 **노예(`slave`) 질문하기와 노예·조수 포트레이트**다. 조수에게 하는 질문하기는 1차 범위 밖이다.

## 4. 단계별 진행 권장
1. **1단계:** 보조 계산(2.1~2.6) + 1112 인상 묻기만. 게임에서 유형·말투·오늘/요즘 판정이 맞는지 확인.
2. **2단계:** 1111·1115·1117·노예 포트레이트.
3. **3단계:** 1113(앞에 붙임, 요구 없음 처리)·1114(기술별, 수업 방식 판정).
4. **4단계:** 조수 포트레이트 말투판, 트레잇 덮어쓰기.
5. 어휘 판은 사용자 검수 뒤 별도 단계.

## 5. 검증
- 각 단계마다 qsp 왕복 검증, 바뀐 location 목록 확인(`#dynamic`, `#txt_man`, `interaction`, `chose_answer`, `slave_stat`, `assistant_stat` 외에는 바뀌지 않아야 함).
- 가능하면 WASM 실행으로 대표 노예(유형 9종 각 1명)의 출력 문장을 뽑아 대사 원문과 대조.
- 게임 안 확인은 사용자가 한다: 질문하기 7종과 포트레이트를 노예 몇 명으로 열어 보고, 어색한 출력을 알려 준다.

## 6. 구현 때 확인할 것 (설계 측에서 확인 못 한 것)
1. 위 줄 번호와 블록 구조가 `source/` 최신 파일과 같은지.
2. 조수 직업 변수 이름.
3. 처벌 계열 행동 번호 전체 목록.
4. cowSK 수업 번호와 5612 중복.
5. 기술 한국어 이름표가 게임에 있는지.
6. 거부 시 `$special_part` 실행 여부.
7. 원래 대답 블록의 정확한 머리·꼬리 HTML.
