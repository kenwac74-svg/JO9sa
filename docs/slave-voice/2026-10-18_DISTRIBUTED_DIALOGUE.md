# 아르곤 대사 플레이 반영과 질문 배분

2026-10-18. 패치 ID `2026-10-18_argon_dialogue_distribution`.

사용자가 테스트한 아르곤 본문 1,395행과 도입·사건 반응 684행을 현재 플레이에 반영한다. 새 대사는 작성하지 않았고, 2,079행의 문구와 기존 guard를 그대로 사용한다. 원본 QSP와 버전 검사 설정은 쓰기 전에 각각 백업한다. 실제 백업 경로와 적용 지문은 내부 `install.json`에 기록한다.

## 실제 배분

| 질문 | 이번 내용 |
|---|---|
| 1112 인상 | 관계15항목과 복종·두려움·합리화·본능·생활 적응·헌신 각6항목, 처벌 때의 대우 인식 `spoil_0`. 총52개 의미 ID. 도입·오늘/최근 사건 반응도 유지 |
| 1113 요구 | 현재 욕구 `urge_0..5`, 관심·보상·대우 기대 `spoil_1..5`. 총11개 의미 ID. 원래 구체적인 요구를 먼저 남기고 이동분을 뒤에 표시 |
| 1111·1114·1115·1117 | 기존 과거·희망·싫어하는 것·조수 평가 원문과 선택식 유지 |
| 1116 기분 | 기존 전체 무드렛 목록·순서·기본값·broken 분기 유지 |

`spoil_0`은 처벌 시 주인의 태도를 설명하는 말이어서 인상에 남겼다. 처벌 사건 반응도 헌신적인 인물에게는 반성이나 관계 설명이므로 불만 질문으로 통째로 이동하지 않았다. 전체 질문의 신규 집필·후보 확충은 후속 아르곤 작업이다.

## 함수와 입력·출력

- 기존 `$voice_profile`: 직업·성격·감수성·자아·태도로 9유형과3말투를 계산한다.
- 기존 `$voice_depth_level`: 취약·적대·긍정 감정과 기존 수치를 읽어 허용 깊이0/1/2를 반환한다.
- 기존 `$voice_pick_fragment`: 역할·유형·말투·관계·깊이·guard·최근 이력을 읽어 적합한 완결 조각을 고른다. 본문은 최근2회 제외→최근1회 제외→반복 허용의 각 단계 안에서 유형 전용→공통 순서다. 사건은 기존 최고 깊이 우선 규칙을 유지한다.
- `$voice_impression`: 인자1112 또는 생략은 인상, 인자1113은 요구의 이동분을 구성한다. 현재 노예의 원래 의미 선택식을 실행한 뒤 질문에 맞는 ID만 고른다. 결과는 임시 `$jo9_vf_pages`이며, 핵심과 보충은 같은 페이지에 이어진다. 현재 관계·기분·교육·헌신 등 게임 수치를 바꾸지 않는다.
- `jo9_vf_has_request`:1113 이동분에 실제 원하는 것(`spoil_1..5` 또는 `urge_1..5`)이 있으면1인 임시 출력값이다. hook이 사용한 뒤 지운다. `urge_0`만 있으면0이며 원래 요구 없음 답변을 보존한다.

1113 hook은 기존 `chose_answer`를 먼저 실행한다. 원래 구체적 요청은 전부 유지한다. 실제 이동 요구가 있으며 원래 결과가 `$no_need` 또는 `$no_need_gentle` 한 개뿐일 때만 그 기본 답변을 빼고 추가 요구를 표시한다. 0번에서 시작하는 기존 배열과 `txt=0`을 유지한다. 1112의 빈0번/1번 시작 규칙을1113에 복사하지 않는다.

## 조건과 저장 영향

이동분의 복종 단계·반항 초기화·broken·경험·욕구 단계 조건은 원래1112 선택식 그대로다. 하녀 업무 복종 예외는 실제 복종 단계를 올리지 않는다. broken이나 반항이 원래1113의 구체적 요청 전체를 차단하는 새 조건도 만들지 않았다. 기존1112 거부값−10과1113 거부값−3은 유지한다. 따라서 이동한 정보는 이제 요구 질문의 기존 응답 허용률을 따른다.

이전1112의 `jo9_voice_last1_1112`, `jo9_voice_last2_1112`를 계속 사용한다. 1113에는 같은 방식의 `jo9_voice_last1_1113`, `jo9_voice_last2_1113` 두 문자열을 사용한다. 실제 답변 확정 때만 갱신하고 거부·화면 재표시에서는 갱신하지 않는다. 새 장기 기억·사건 DB·세이브 마이그레이션·로케이션은 없다.

상수 revision은4, 함수 표식은 `VOICE_ARGON_DISTRIBUTED_V4`다. 오래된 세이브의 정의가 남아 있으면1112/1113 진입 시 현재 함수와 대사 데이터만 보충한다. 데이터 전용 갱신은 현재 남녀 원문 배열을 덮어쓰지 않는다. 게임별 `FastQSP.ini`의 `ignoreCRC=true`도 테스트본과 맞춰 구버전 세이브의 버전 검사 충돌을 피한다. 이미 열린 엔진 창에는 INI가 즉시 반영되지 않으므로 적용 후 원래 플레이 게임을 다시 실행한다. 실행 파일·엔진 라이브러리·세이브 내용은 수정하지 않는다.

## 수정 위치와 의존성

- `#dynamic`: `VOICE_ARGON_DISTRIBUTED_HELPERS`. 깊이·후보 선택기와 질문별 조립 정의.
- `#txt_man`: `VOICE_ARGON_DATA`. 원고2,079행·색인·감정 구분과 revision4. 기존 성별 원문 배열은 보존.
- `interaction`: `VOICE_DISTRIBUTED_IMPRESSION`과 `VOICE_REQUEST_DISTRIBUTION`. 캐시 보충, 실제 질문 호출, 기존 요청과 추가 페이지 연결.

위 코드는 기존 `$voice_profile`, `$slave_*_description`, 원래 상태·행동 횟수, `chose_answer`, `interaction_result`, 기존 화면 출력기에 의존한다. 새 함수나 로케이션을 별도 추가하지 않았다. 함수를 없애고 호출부를 남기면 조립이 실패하고, 데이터만 빼면 후보를 찾지 못할 수 있다. 호출부를 분리하면 해당 질문에서 새 원고가 나오지 않는다. 되돌릴 때는 임의 구간 삭제 대신 이번 패치의 정확한 역적용 또는 적용 전 QSP 백업을 사용한다. INI를 되돌릴 경우 별도 설정 백업을 함께 사용한다.

## 확인한 범위

원고2,079행 바이트 내용 보존, 원래63개 의미의 질문 배분, 대표65상태×2질문, 구체 요청과 기본 답변 처리, 거부·반복 이력·구 캐시·여성 배열·WASM 저장 왕복을 포함한223개 검사를 통과했다. 실제 설치 FastQSP 엔진에서 출고9경로와 인상·요구·구 캐시3경로를 검사했다. 최종 적용 파일의 지문과 직전 백업을 기준으로 출고 검사를 다시 실행한다.

실제 세이브 불러오기 UI·CRC와 저장된 모든 스크립트 복원을 자동 검증한 것은 아니다. 새 게임 검사는 초기화 경로이며 캐릭터 선택 UI 조작이 아니다. 픽셀 단위 글자 배치·모든 원고 조합의 자연스러움·조수 자신의 별도 질문 라우팅도 검증 범위가 아니다. 기존1113의 뒤로 버튼 조건 등 전체 UI를 재설계하지 않았다. 테스트본에 기록한 원고의 일부 유형·깊이 정합성과 후보 부족은 이번에 임의 재집필하지 않았으며 후속 원고 작업에 남는다.
