# JO9 대사 편집실

로컬 HTML 화면에서 현재 `jack.qsp`의 원문을 찾아 선택하고, 사용자가 작성하거나 설리태번에서 받은 수정문을 붙여 넣어 저장합니다. AI 호출과 API 연결은 없습니다.

## 실행

`Open-JO9-Text.cmd`를 더블클릭합니다. 기본 대상은 `G:\somi\JO9\game\jack.qsp`입니다. 다른 PC는 `Start-JO9-Text.ps1`의 `-GameDir`로 게임 폴더를 지정합니다. Node.js가 필요하며 Codex에 포함된 Node.js 또는 설치된 `node`를 사용합니다. 창을 열지 않고 주소만 받으려면 `-NoBrowser`를 지정합니다.

1. 게임에서 본 문장 일부로 검색합니다. 필요하면 Location 이름으로 좁힙니다. **보기** 상자에서 「게임에 보이는 대사만 보기」(기본: 변수 이름·경로·코드 문자열 숨김)와 「코드까지 같이 보기」를 고릅니다.
2. 정확한 위치 하나를 선택합니다. 같은 원문이 여러 번 나와도 선택한 문자열 하나만 바뀝니다.
3. ‘각색 요청 복사’로 설리태번에 요청하고 수정문만 붙여 넣습니다.
4. 미리보기 → 수정문 승인 → 반영을 누릅니다.
5. 게임을 다시 실행하거나 해당 장면을 다시 불러와 확인합니다.

## 게임 화면 미리보기

원문을 고르면 장면 칸 위쪽에 게임 화면처럼 보여 줍니다. 왼쪽은 그 장면 코드가 부르는 그림(``의 `bg\` 배경, ``·``, `<img src>` 등, 게임 폴더의 `content\pic`에서 읽음), 오른쪽은 그 장면의 대사를 원문 순서로 이어 붙인 것입니다(`<br>`은 줄바꿈, 다른 태그는 숨김, `<<변수>>`는 〈변수〉). 대사를 누르면 그 대사를 수정하고, 선택지 버튼은 연결된 장면을 엽니다. 「대사만」 보기에서는 장면 조건·분기 코드·주변 원문을 숨기고, 「코드까지」에서 모두 보입니다. 실제 게임은 조건에 따라 일부만 나오고 인물 장면 그림(`display_pic`)처럼 실행 중에 정해지는 그림은 미리보기에 없을 수 있습니다.

## 장면과 분기 이동

- 원문을 선택하면 해당 장면의 조건과 선택지/호출/이동 경로를 표시합니다.
- **이전 장면**: 편집실에서 방문한 장면으로 돌아갑니다. 방문 기록이 없으면 이 장면으로 들어오는 명시적 진입 경로를 찾아 선택할 수 있습니다.
- **다음 장면**: 연결된 이동 목적지가 하나면 바로 엽니다. 여러 갈래면 분기 목록에서 선택합니다.
- **앞 대사 / 뒤 대사**: 같은 장면 범위의 대사를 원문 순서로 선택합니다.
- **같은 장면의 대사 목록**: 선택한 대사 앞뒤를 함께 살펴보고 바로 선택할 수 있습니다.
- 미반영 수정문은 이동 시 보관하고 다시 선택하면 복원합니다. 반영 후에도 같은 장면을 유지합니다.

분기 표시는 QSP를 실행하지 않는 소스 분석입니다. `if/elseif/else`, 위치명 상태값 비교, `$args[0]` 비교, `act`, HTML `exec:` 링크와 `gt/xgt/gs`의 명시적인 목적지를 읽습니다. 변수/동적 목적지, `jump` 라벨, 실행 시 조립되는 선택지는 목적지가 미확정으로 표시될 수 있습니다. 같은 상태값을 서로 다른 조건에서 사용하는 경우 후보 장면을 함께 표시합니다. 현재 세이브 조건의 참/거짓이나 실제 플레이 순서를 확정하지 않습니다. 게임 상태와 파일은 탐색 버튼으로 바뀌지 않습니다.

현재 QSP를 직접 수정하며 오래된 QSRC를 재빌드하지 않습니다. 원본과 바이트가 같은 왕복 읽기/쓰기 검사, 원문 위치와 현재 파일 해시 검사, 태그/치환문/변수 보존 검사, 따옴표 이스케이프, 임시 파일 검사와 백업 후 저장을 수행합니다. 검색 후 다른 도구가 파일을 바꾸면 다시 검색해야 합니다. 동시에 다른 편집기로 저장하지 마세요.

지원 범위는 Location 설명과 본문 코드의 따옴표 문자열입니다. 행동 목록에 별도로 저장된 문자열은 현재 검색 범위에서 제외됩니다. 실행 시 조립된 문장이나 변수로 들어간 이름은 화면 표시와 원문이 다를 수 있습니다. QSP 문법 전체를 컴파일하는 도구가 아니며 조건·분기·호출 코드를 새로 만드는 용도가 아닙니다.

`runtime/backups/`에 원본 QSP와 수정 기록을 남깁니다. 기록의 ‘되돌리기’는 현재 파일이 그 기록의 반영 결과와 같을 때만 허용되며 복원 전에도 백업합니다. ‘수정 기록 내보내기’는 저장소 `tools/apply_mods.ps1`에서 사용하는 JSON 형식이며, location 전체가 아니라 바뀐 문구와 필드 안에서 한 번만 나오는 최소 맥락만 old/new로 담습니다(2026-10-04 이전 기록은 필드 전체가 들어 있으니 그대로 쓰지 말 것). 같은 필드의 연속 수정은 순서대로 적용해야 합니다. 되돌린 기록을 배포용 mods에 넣지 마세요. 이 도구는 배포용 mods를 자동 등록하지 않습니다.

서버는 `127.0.0.1`에만 연결하며 임의 포트를 사용합니다. 설리태번의 8000 포트와 충돌하지 않습니다. 편집실과 설리태번 사이에는 복사·붙여넣기만 사용합니다. 종료하려면 `runtime/server.json`의 PID에 해당하는 Node 프로세스를 종료합니다.

## 단어 일괄 치환

원문 찾기 아래의 **단어 일괄 치환**을 펼칩니다. **찾을 단어**와 **바꿀 말**을 입력하고 **치환 대상 찾기**를 누릅니다. 위치 이름과 위의 보기 설정으로 범위를 좁힐 수 있습니다.

결과에서 바꿀 대사를 체크하거나 **검색 결과 전체 선택 (모든 페이지)**을 사용합니다. 다음 페이지에서 체크를 해제한 항목도 제외됩니다. **선택한 항목 치환 미리보기**에서 전·후와 총 치환 수를 확인하고, 승인 체크 후 **선택한 항목 일괄 치환**을 누릅니다. 백업과 수정 기록은 한 번에 만들어지며 기존 변경 기록에서 내보내기·되돌리기가 가능합니다.

대소문자·띄어쓰기를 구별하는 일반 문자열 치환입니다. 한 대사 안의 같은 단어는 모두 바뀝니다. 바꿀 말을 비우면 그 단어를 삭제합니다. 검색·선택·범위·수정문을 바꾸면 이전 미리보기의 승인이 취소됩니다. 결과는50개씩 보여도 전체선택은200개 제한 없이 모든 검색 결과에 적용됩니다.

여러 문자열을 바꾼 내보내기는 필드별 선택 범위를 덮는 하나의 고유한 연속 조각을 사용합니다. 중간의 선택하지 않은 코드와 문구는 동일하게 보존됩니다. 서버는 반영 직전 최신 파일 지문을 검사합니다. 기능 설치만으로 실제 단어를 바꾸지는 않습니다.

## 흐름 전체 각본 출력

컷마다 따로 고치면 앞뒤 흐름이 끊기므로, 한 흐름을 처음부터 끝까지 한 문서로 꺼내 AI에게 각색을 맡길 때 씁니다. 대사를 하나 고른 뒤 **3. 장면의 흐름** 아래 **흐름 전체 각본으로 출력**을 펼치고 **각본 만들기**를 누릅니다.

- 시작: 고른 대사를 실제로 보여 주는 장면(공용 대사집 `#npc_base`·`#txt_man`의 대사면 그 배열을 `copyarr`로 부르는 장면)에서 시작합니다. ‘이 위치 전체’는 위치의 모든 장면을 씁니다.
- 선택지·이동으로 이어지는 장면을 ‘따라갈 단계’·‘최대 장면 수’ 한도까지 따라갑니다. 상점·메뉴 같은 허브(위치 전체로 가는 이동)는 이름만 적고 펼치지 않습니다. 호출(gs)은 옵션을 켤 때만 따라갑니다.
- 페이지는 `---- [S1-P3] 3/14 ----`로 나뉩니다. 게임에서 → 버튼으로 넘기는 한 화면입니다. 같은 페이지의 조건부 판본은 `(조건: ...) 대체문`으로 그 아래에 붙습니다.
- 주인공 판본: `#txt_man`/`#txt_woman`, `#npc_base`/`#npc_base_woman`처럼 성별로 나뉜 대사집 중 하나를 고릅니다. 한 판본 안에서는 마지막 무조건 대입을 기본문으로 씁니다.
- 대사는 `이름: 내용` 평문으로 바뀌고, `<<$변수>>`는 〈$변수〉로 표시됩니다.
- **복사**, **txt 저장**(UTF-8, 다운로드 폴더), **각색 요청문과 함께 복사**(페이지 구분·화자·변수 보존 규칙을 붙임)를 쓸 수 있습니다.

각본 출력은 읽기 전용입니다. 분기는 소스 분석 결과라 실제로 어느 쪽이 나오는지는 세이브 상태에 따라 다르고, 실행 중 조립되는 페이지는 `[실행 중 결정]`으로만 표시됩니다.

### 각색본 일괄 반영

1. 각본을 만들면 맨 위에 `# 각본 ID:`가 붙고, 페이지(`[S1-P3]`)·대체문(`S1-P3-V1`)·장면 문구(`[S1-L2]`)마다 원래 대사 위치가 `runtime/script-exports/<ID>.json`에 기록됩니다.
2. **각색 요청문과 함께 복사**로 AI에게 보내고, 돌려받은 각본 전체를 **각색본 반영** 칸에 붙여 넣습니다. 앞뒤 인사말이나 코드 블록 표시는 무시합니다.
3. **반영 미리보기**: 바뀐 페이지만 원문(왼쪽)과 각색본(오른쪽)으로 보여 줍니다. 체크를 끄면 그 페이지는 빼고 다시 계산합니다. 변수 〈$…〉·서식 태그가 빠졌거나 화자가 바뀌었거나 너무 길어지면 ⚠ 경고가 붙습니다.
4. 확인 체크 후 **일괄 반영**: 기존 일괄 치환과 같은 방식으로 백업·수정 기록·mods 내보내기를 남기고 한 번에 저장합니다. ‘변경 기록’에서 되돌릴 수 있습니다.

막는 경우: 각본을 만든 뒤 QSP가 바뀜(각본을 다시 만들 것), 각본 ID 줄이 없음, 없던 번호·중복 번호, 빠진 페이지(‘빠진 번호는 원문 유지’를 켜면 허용), `[그림]`·`[선택지]` 표시가 빠지거나 늘어남, 같은 대사를 두 번호에서 다르게 고침, 되돌린 결과가 각색본과 어긋남. 각본의 `이름: 대사`는 원문의 `[이름]<br>` 형식과 머리말·꼬리말(`&nbsp;`, `</div>` 등)을 되살려 저장하고, 〈식〉은 원문의 `<<식>>`으로, `[그림]`·`[선택지: …]`는 원문의 `<img>`·`<a …>` 태그로 되돌립니다. 2026-11-08 현재 QSP의 대사 48,428개 전부에서 원문 → 각본 → 원문 왕복이 같은 뜻으로 돌아오는 것을 확인했습니다.

구현: `script-export.cjs`(출력, `/api/script`), `script-import.cjs`(각색본 해석·되돌리기, `/api/script/preview`, 반영은 `/api/apply`), `script-export.js`(화면), 테스트 `script-export.test.cjs`.

## 시작·마무리로 각본 파일 만들기 (2026-11-08)

1. 기본 탭 **각본 파일 만들기**에서 대사를 검색하고 결과를 선택한다.
2. **이 대사를 시작으로 지정**을 누른다. 앞에 시작 대사가 있으면 첫 대사로 바꿀지, 선택한 위치를 유지할지 고른다.
3. 같은 이벤트의 다른 대사 목록 또는 새 검색으로 마무리를 고른 뒤 **이 대사를 마무리로 지정**을 누른다. 뒤에 대사가 있으면 예상 끝 대사와 현재 선택 중 하나를 고른다.
4. **각본 파일 저장**을 누른다. 선택지·조건 분기가 나오면 포함할 경로를 고른다. 선택한 양끝과 중간을 포함하는 TXT 하나가 저장된다.

확인에 답하기 전에는 저장이 잠긴다. 마무리 이후, 고르지 않은 분기의 대사는 제외한다. 연결을 확인하지 못했거나 선택한 길이 마무리에 닿지 않으면 안내하며, 미완성 구간을 완성 파일로 저장하지 않는다. 예상 시작·끝은 선택한 이벤트에서 계산한 후보이며, 더 큰 줄거리 전체의 경계를 확정하는 기능은 아니다.

기존 원문 수정·추가·각색본 반영은 **대사 수정·반영** 탭에 있다. 고급 각본 출력은 그 탭의 접힌 메뉴에 유지한다. 구간 TXT도 기존 각본 ID/페이지 번호를 유지하므로 기존 각색본 검토·반영 기능으로 읽을 수 있다. 각본 저장만으로 게임 QSP는 바뀌지 않는다.

## 2026-11-08 편집실 구조
