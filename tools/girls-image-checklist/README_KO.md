# 캐릭터 이미지 보완 목록

B안과 새·옛 등록 병행 조회는 2026-11-05 WORK에 적용했다. 이 도구는 이미지 보유 상태 조사와 사용자 PNG 추가·교체를 제공한다.

## 사용자 기능

- 캐릭터 번호·이름·JSON·경로 검색, 부족한 그림과 숨겨진 복장 선택지 필터, 12명씩 표시
- 기본 전신·컬러/흑백/세피아 초상·하녀/비서/도미나·전체 의상과 상태 변형 목록
- 기존 본문 영역에 표시하며 폴더 패널 접기·펼치기와 너비 변경을 따른다. 폴더 패널의 캐릭터 이미지 세트 버튼으로 돌아올 수 있다.
- 캐릭터 ID마다 완료·원본re·머지re·재활용·보관·작업중·작업필요·삭제 예정 태그를 한 묶음씩 표시한다. 여러 태그를 함께 체크할 수 있다.
- 상태 버튼을 누르면 해당 태그가 있는 캐릭터만 모아 본다. 번호 오름·내림차순과 이름순 정렬도 제공한다.
- 캐릭터 상태는 기존 catalog_status.js의 characterItems에 번호별로 저장한다. 기존 파일별 items 상태와 구분하며, 같은 이미지를 쓰는 캐릭터끼리도 상태를 공유하지 않는다.
- 태그를 체크해도 이미지·JSON·QSP나 기존 파일별 체크 상태를 바꾸지 않는다. 캐릭터의 보관·삭제 예정도 작업 표시만 하며 B컷 연결이나 실제 삭제를 하지 않는다.
- 번호별 행동 컷의 존재 여부와 없는 행동용 PNG 추가
- 옛 이름별 장면 등록을 현재 행동 선택 경로와 구분해 표시
- PNG 경로가 등록돼 있으면 없는 PNG 추가와 기존 그림 교체
- 기존 파일은 기존 치수를 유지하고 새 전신/행동 컷은 795×596, 새 초상은 151×150으로 비율을 유지해 맞춘다
- 저장 전에 경로·크기·공유 대상·변환된 그림을 확인한다
- 기존 PIC 저장기가 원본 백업과 이미지 패치를 기록한다
- 경로 자체가 비어 있는 복장은 캐릭터 이미지추가도구에서 등록해야 한다. 이 화면이 임의로 JSON을 수정하지 않는다.
- 이미지 파일을 직접 넣은 뒤 새로고침하면 파일 상태를 갱신한다. JSON의 등록 경로를 바꿨으면 inventory 재생성이 필요하다.
- 독립 HTML은 로컬 파일과 저장 당시 상태 태그를 확인할 수 있다. PNG·태그 저장은 토큰이 있는 로컬 이미지 체크리스트에서 제공한다.

## 파일과 재생성

build_inventory.py는 WORK JSON과 그림을 읽어 manifest.json을 생성한다. catalog-girls-checklist.js는 HTML에 삽입되는 UI다. build_pages.py는 manifest와 UI로 독립 HTML 및 기존 카탈로그 삽입 후보를 생성한다.

실제 사용본은 WORK/game/modtools/catalog/catalog_merge_vs_original.html이다. 로컬 서버가 이 파일의 내용을 매 요청 읽어 기존 PIC API를 연결한다.

사용자가 새 이미지를 넣으면 PNG와 해당 이미지 패치·백업만 저장한다. 새로운 JSON 필드, 게임 상태, SAV는 변경하지 않는다.

## 검사 범위

브라우저 시험은 합성 PNG와 격리 HTTP 저장기를 사용한다. 게임의 대체 조회는 별도 QSP 패치로 적용했으며, 실제 FastQSP 검사와 한계는 records/work-pending-batch-20261105에 기록했다. HTML 검사 대상과 결과는 browser-test-report.json을 참고한다.
