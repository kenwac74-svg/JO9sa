# JO9 인물 상태 편집기 — 테스트판 0.1

현재 설치된 QSP의 명기 상태 체계를 읽고 등록된 30개 표시/수치를 편집하는 실제 로컬 도구다. 이전 5759의 설계 시안과 다르며 실제 QSP 경로·해시·값을 표시한다. 게임을 열거나 세이브를 자동 조작하지 않는다.

## 실행

PowerShell에서 `Start-StateEditor.ps1`을 실행한다. Node.js 20 이상이 필요하며, PATH의 Node 또는 Codex 번들 Node를 찾는다. 서버는 숨김으로 시작하고 localhost URL을 출력한다. Codex에서는 그 URL을 우측 브라우저에 연다. 저장소의 local.config.json 또는 설치 위치로 플레이/배포 대상을 확인하며, 사용자 지정은 `-Targets <JSON경로>`로 준다.

직접 실행: `node server.cjs --targets targets.json --runtime runtime --port 0`.

targets.json 예:

```json
[{"id":"work","label":"플레이","path":"G:/somi/Jack O Nine Tails v2.4_work/game/jack.qsp"},{"id":"full","label":"배포","path":"G:/somi/Jack O Nine Tails v2.4 Kor_Full/game/jack.qsp"}]
```

## 사용

1. 불러올 설치본을 고른다. 원본은 즉시 읽기만 하며 적용할 설치본은 처음에는 선택하지 않는다.
2. 상태표, 전환·이력, 연결 효과에서 표시/수치를 편집한다. 검색은 이 상태 정의의 실제 30개 항목만 대상으로 한다.
3. 적용할 플레이/배포 설치본을 선택하고 변경 미리보기를 누른다. 수정 위치·원본/후보 해시와 자동 캐시 갱신도 비교한다.
4. 검증한 변경 적용을 누르면 대상별 백업과 journal을 먼저 저장한 뒤 각 QSP를 따로 교체·검증한다.
5. 적용 이력의 복원으로 정확한 이전 QSP 바이트를 되돌린다. 이후 사용자가 수정한 파일은 덮어쓰지 않는다.

프로젝트 저장/불러오기는 runtime/project.json에 편집 내용을 저장하며 게임을 변경하지 않는다. 현재 원본과 해시가 다르면 이전 프로젝트를 자동 적용하지 않는다. 패치 JSON 내보내기는 대상별 `patch.edits`를 포함한 묶음이다. 기존 `tools/apply_mods.ps1`에 넣을 때는 필요한 대상의 `targets[n].patch` 객체를 개별 mods JSON으로 사용한다.

## 실제 지원과 범위

- 상태 코드 0~4: 표시명 5, 툴팁 5, 기본/개인실 아이콘 10.
- 최초 발견 확률 1개: 실제 여섯 역할의 기존 판정을 함께 편집한다.
- 기존 보장 수치 6, 지정 교육 XP 1, 시장/경매 배수 2.
- 내부 상태 코드·저장 키·최초 판정 조건·역할 추가·이력 값·임의 조건식·새 상태 추가·독립 복제는 읽기 전용/미지원이다.
- 아이콘은 선택한 설치본 모두에 이미 존재하는 이미지여야 한다. 새 파일 업로드/그림 제작은 포함하지 않는다.
- 거래 수치의 편집은 기존 대사의 숫자를 자동 각색하지 않는다.

`slave`는 현재 동행 역할 슬롯이다. 전체 노예 집합을 뜻하지 않는다. 이 등록의 연결 역할은 slave, assistant, room1~4이며 세이브의 현재 인물 값을 직접 편집하는 기능은 아니다.

## 저장 캐시와 복원

표시명·교육 XP는 세이브의 저장된 정의에도 남을 수 있다. 해당 편집은 기존 `jo9_meiki_revision` 가드를 갱신하며, 표시명은 필요한 슬롯만 다시 설정한다. 도구는 runtime의 버전 원장과 시간 기반 버전 하한으로 이전 후보 버전을 재사용하지 않는다.

**QSP 복원은 세이브 복원이 아니다.** 변경한 게임을 저장한 뒤 QSP를 복원했다면 저장 캐시 갱신 후보 → 적용 → 게임 재시작/세이브 로드로 현재 QSP의 표시명 5개와 동적 정의를 다시 읽게 할 수 있다. 이 동작도 미리보기·백업·복원을 거친다. 인물의 현재 수치·발견 이력·이미 지급된 보상은 되돌리지 않는다. 테스트 전 세이브는 별도 사본으로 보관한다.

## 기록과 중단 복구

runtime/previews에 후보, backups에 대상별 원본, transactions에 적용 전후 해시·선언형 패치·단계가 남는다. 여러 설치본의 교체를 OS 단위의 한 원자적 작업으로 보장하지 않는다. 일부 쓰기 실패 시 검증된 백업으로 복구하며, 충돌은 이력에 남긴다.

이전 프로세스가 종료된 write.lock은 PID를 확인해 기록으로 옮기고 재시도한다. 실행 중인 프로세스의 잠금이나 확인할 수 없는 잠금은 보존한다. 중단된 작업은 이력에서 복원할 수 있다. runtime에는 로컬 백업/프로젝트가 있으므로 PC 이전 때 필요한 기록을 따로 보관하고, 게임 배포 압축에서는 제외한다.

## 검증

`npm test` 또는 `node --test *.test.cjs`. 브라우저 통합은 Playwright 경로를 `JO9_PLAYWRIGHT`, 브라우저 실행 파일을 `JO9_BROWSER`에 지정하고 `node browser-check.cjs`를 실행한다. 테스트는 임시 QSP 사본만 수정한다. 실제 설치본은 읽기와 메모리 후보/역패치 검사만 한다. 소스 검증과 모델 시험을 실제 QSP 엔진 플레이 성공으로 표현하지 않는다.
