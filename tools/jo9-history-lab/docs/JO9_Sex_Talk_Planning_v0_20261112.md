## 1. 참고 자료: 인터뷰 블로그의 형식
사용자가 준 블로그(kurathekura5.blogspot.com, "음란 인터뷰" 연재)를 2026-11-12에 한 편(s5 #104) 읽고 **형식만** 정리했다.
- 한 사람에게 **고정 질문지 약 32문항**을 똑같이 묻는 연재다. 같은 질문지라 사람끼리 비교가 된다.
- 질문 묶음: 첫 경험 / 기록(최다 횟수·인원·나이 차) / 피니시 선호 / 해 보고 싶은 것·절대 싫은 것 / 오르가즘·분출 / 삼킴 / 자기 취향·장기 / 애널·딥스로트 / 색드립 / 특이한 장소 / 최악·최고의 남자 / 다인 경험(유형 목록 중 고르기) / 고정 상대·스와핑 / SM / 촬영 / 마지막 한마디.
- 질문 방식: 반말·비속어, "노코멘트 해도 좋다" 허용, 보기 목록에서 고르게 하는 문항, "간결한 하드보일드 묘사로" 같은 대답 길이 지시.
- 대답 방식: 1인칭 구어체, 짧은 수치 + 짧은 일화, 망설임·얼버무림("정확하진 않은데…")이 자연스럽게 섞임.

### 1.1 쓰는 방법 (제안)
- **질문지 구조와 대답의 말투만 리소스로 쓴다.** 블로그의 대답 원문은 실제 사람의 이야기이고 저작물이므로 대사집이나 repo에 옮겨 담지 않는다. 대답은 우리 사실 데이터(3장)에서 조립한다.
- 그래서 "인터뷰 형식 리소스 데이터베이스"는 **질문지(주제) × 사실 필드 × 성격별 대답 틀**의 표가 된다(4장).
- 잭오나에 맞게 바꾸는 것: 트위터·촬영 같은 현대 온라인 소재는 세계 설정 소재로 바꾼다(예: 촬영 → 구경꾼 앞).
- **빼는 것**: 미성년 암시(교복 "학생 때", 첫 경험 나이), 근친, 수간. 첫 경험은 나이를 말하지 않고 상황(결혼 첫날밤, 일 시작한 날 등)으로만 말한다. 연령 코드 1은 섹스토크 대상이 아니다.

## 2. 커맨드 구조 (설계 문서 4.6 요약)
- 주인은 말하지 않고 **주제 선택지**를 고른다. 노예가 대답하고, 그 주제의 파생 선택지가 이어진다. 끝내기 선택지가 항상 있다.
- 감정 깊이가 모자라면 파생 선택지가 닫히고 "노코멘트"형 대답 + 숨긴 이야기로 남는다(인터뷰의 "노코멘트 해도 좋다"에 대응).
- 대화로 끝나면 질문하기(111), 취향·활동에 영향을 주면 영향주기(112).

## 3. 사실 저장: 일관성을 위한 필드
같은 질문에 언제 물어도 같은 사실로 답해야 한다(사용자 결정). 그래서 **영입 때 한 번 정해 저장**한다. 값은 기존 데이터에서 고정 시드(인물 id + 필드 id)로 뽑는다.

| 필드(초안) | 내용 | 정하는 근거 |
|---|---|---|
| 총횟수·질/구강/애널·상대 수·임신·출산 | 과거 경험 공식 결과 | `past-history.mjs` (확정된 공식) |
| `first_who` | 첫 상대 유형(남편·약혼자·손님·포주·전 주인·동네 건달·같은 처지 노예·기사 …) | 직업 묶음·출신 묶음·혼인 여부 |
| `first_how` | 첫 경험 성격(원해서·얼떨결·돈·강제) | 직업 묶음·출신·성격 |
| `first_where` | 장소 | 세계·출신 장소 사전 |
| `max_night` | 한 상대와 하룻밤 최다 횟수 | 성욕 특성·체력·총횟수 |
| `max_day_people` | 하루 최다 상대 수(다인 제외) | 성매매 묶음·총횟수·상대 수 |
| `group` | 다인 경험 유형(없음/2:1/1:2/여럿) | 직업 묶음·상대 수·성욕 |
| `finish_pref` | 선호 피니시(질내·입·얼굴·가슴·애널) | 배분 결과·성향 특성(정액중독 등) |
| `swallow` | 삼킴/뱉음 | 정액중독·구강 비율 |
| `orgasm` | 오르가즘 빈도(없음·가끔·자주·매번) | 불감증·색정광·감도 |
| `squirt` | 분출 경험 | 감도 + 시드 |
| `signature` | 자신 있는 기술 | 가장 높은 성 기술 |
| `never` | 절대 싫은 것 | 거부형 특성·가장 낮은 행위 비율 |
| `want` | 해 보고 싶은 것 | **아직 드러나지 않은 성향 특성**(숨은 성향) |
| `odd_place` | 특이한 장소 | 세계·직업 장소 사전 |
| `worst_man` / `best_man` | 최악·최고 상대 일화 코드 | 직업 묶음·첫 경험 성격 + 시드 |

- 저장 형식은 설계 문서의 다른 키처럼 문자열 한 줄(약 60~80바이트)로 압축한다. 키 이름·위치는 통계 구현 때 확정.
- 영입 후 실제 기록이 생기면 덧붙여 말하고(“그 뒤로 주인님이랑 {N}번”), 저장된 과거 사실은 고치지 않는다.

## 5. 호칭 규칙 (사용자 결정 2026-11-12)
인칭 정리 기준은 앞 제안을 수용한다: R1 한 화자 안 호칭 통일, R2 노예의 "당신"은 적대 관계일 때만, R3·R4는 사람이 판단. **추가로 출신 성분·계급에 따라 특수 호칭이 있다.**

| 노예 쪽 조건 | 주인 호칭 초안 |
|---|---|
| 기본(헌신·순응·공포) | 주인님 |
| 적대, 일반 출신 | 당신 / 호칭 생략 |
| 적대, 상류·왕가·귀족·무인 출신(현재 출신 묶음 `sheltered`: 공주·야만족 왕·기사·거부·은행가·시장·금융가·제독·장군·고대 귀족) | 너 / 네놈 |
| 적대, 거리·범죄 출신(`street`) | 너 / 이 새끼 등 비속어 |
| 지정 유니크 반말 8명 | 프리셋 |

- 이 표가 맞으면, 인칭 검사 R1(한 화자가 "당신"과 "너"를 섞음) 중 위 조건에 해당하는 것은 혼재가 아니라 **의도된 특수 호칭**으로 남긴다.
- 출신 묶음은 과거 경험 공식의 묶음을 임시로 썼다. 호칭용 묶음을 따로 둘지 함께 정한다.
