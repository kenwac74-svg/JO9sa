# Wayward식 대화 구조 설계 v1 (2026-11-12)

## 0. 목적과 전제
- 목적: LLM 없이 Wayward처럼 "기억하고, 스스로 말하고, 말한 결과가 남는" 노예 대화를 만든다.
- 범위: 필로우토크(새 질문)와 기존 대화 1111~1118이 **같은 구조**를 쓴다. 조수·개인실 인물도 같은 함수를 쓴다.
- 전제: 게임 성격 차이(여러 인물, 행동 단위 진행)는 감안한다. 그래서 인물마다 기억은 작게, 발화는 계기 단위로 둔다.
- 기존 결정 유지: 성격 9유형, 말투(일반 노예 존댓말, 지정 유니크 8명만 반말), 관계 8모드, 감정 깊이 0~2, 메타데이터 조각 행, 원문 대사 보존(`SLAVE_DIALOGUE_ASSEMBLY_RULES_CURRENT_20261112_KO.md`).
- 근거: Wayward 2026-09-30 한국어판 코드(구조만 참고, 코드·문구는 가져오지 않음), 잭오나 최신 qsp, 기존 역설계 문서(`design/slave-voice` 브랜치 `WAYWARD_REVERSE_DESIGN.md`).

## 1. 전체 흐름
```text
사건 발생 (처벌·칭찬·관계·절정·굴욕·판매 위협 …)
  → [기억] 강한 사건이면 인물의 기억 버퍼에 기록 (종류·날짜·상대·세기)
  → [감정] 기존 무드렛 세기 + 기억 연결
출력 자리 (질문 대답 / 노예 정보 하단 / 하루 끝 보고 / 행동 결과 지문) — 새 행동은 만들지 않는다
  → [대기] 자리별 대기, 하루 상한 확인
  → [판단] 발화 종류·속마음 후보마다 조건 확인 → 점수 → 최고점(동점 무작위)
  → [표현] 유형·말투·관계·깊이로 문장 조각 고르기, 빈칸 치환, 겉말/속말, 이어 붙이기
  → [출력] 이름표·페이지(230자 경계)
  → [기록] 이력, 숨긴 이야기 기록/해제, 숨은 성향 공개. 기분·헌신 등 수치는 바꾸지 않는다
```

## 3. 감정 층
- 감정 종류는 역설계 문서 3장의 대응(두려움·수치·분노·혐오·슬픔·자부심·애정·황홀·죄책)을 쓴다. 세기는 기존 무드렛이다.
- **원인 연결**: 무드렛이 문턱 이상으로 생길 때 같은 사건을 기억 버퍼에 쓴다. 대사는 "가장 큰 감정 → 그 감정과 같은 종류의 가장 최근 기억"으로 원인을 찾는다.
- **상대**: 기억의 상대 칸(m 주인, a 조수, c 손님, o 그 밖). 같은 처벌이어도 상대에 따라 다른 대답 후보가 열린다.
- **시간 표현**: 오늘 날짜 − 기억 날짜 → 0 "아까/오늘", 1 "어젯밤/어제", 2~3 "며칠 전", 4~7 "지난주", 그 이상 "전에". 빈칸 `{그때}`.

## 4. 출력 자리 (스스로 말하기)
잭오나에는 노예가 먼저 말을 거는 행동이 없다. 새 행동을 만들지 않고, **플레이어가 어차피 보는 기존 화면에 한마디를 붙인다.** Wayward의 아침·한가함·손님 상대 후 발화를 잭오나 화면에 옮긴 것이다.

| 자리 | 기존 위치 | 붙이는 말 | 대기 |
|---|---|---|---|
| ask | 질문 1111~1118, 필로우토크 1119 | 질문에 대한 대답 + 덧붙임 | 없음 |
| portrait | 노예 정보 하단 서술(`slave_stat`의 `$info_text`, 지금은 정신 상태 고정 1문장) | 지금 마음에 걸리는 일(가장 큰 감정 + 원인 기억) | 하루 1문장 고정. 다시 열어도 같은 문장 |
| report | 하루 끝 보고(`end_day_screen`) | 오늘 있었던 강한 일에 대한 한마디·속마음 | 하루 1회 |
| result | 행동 결과 지문(`interaction` 결과 `$text`) | 방금 행동에 대한 속마음 한 줄. 관계 행동 뒤면 필로우토크 여운 | 같은 인물 3행동마다 1회, 하루 3회 |

- 하루 전체 상한(초안 5회)을 넘으면 자리 대사를 생략한다. 기존 지문·원문은 지우지 않고 뒤에 붙인다.
- 자리와 빈도는 편집기에서 조정한다.

## 5. 판단 층: 무엇을 말할지 고르기
- 잭오나 대화는 플레이어가 묻고 노예가 말하는 한 방향이다. 노예의 말에 플레이어가 다시 대답하지 않으므로, Wayward의 "대답 → 신뢰·기분 변화" 고리는 두지 않는다. 행동 자체의 효과는 기존 게임 코드가 처리한다.
- 후보는 **발화 종류** 단위다. 예: 자랑·담담·수줍은 고백·숨김·원망·헌신·불안, 속마음 계열 = 여운·걱정·욕구·갈등·발견.
- 후보마다 `조건`(통과/탈락), `점수`(입력의 가중합), `우선순위`가 있다.
  - 점수 = Σ 가중치 × 입력(헌신, 두려움, 기분, 감정 세기, 기억 세기, 꾸밈 경향 등). 예: 원망 = 2·(적대 감정) − 2·moral + (최근 처벌 기억 세기).
  - 자리 대사(속마음 등)는 우선순위가 가장 높은 후보 중 무작위, 질문 대답은 점수가 가장 높은 후보(동점 무작위).
- 후보에 붙는 **기록**(수치는 바꾸지 않음):
  | 기록 | 내용 |
  |---|---|
  | `reveal` | 해당 `*_revealed`를 켠다(숨은 성향을 알게 됨) |
  | `keep` / `release` | 숨긴 이야기에 넣는다 / 숨긴 이야기를 꺼낸다 |
  | `remember` | 이 대화 자체를 기억에 쓴다(고백 등) |

## 6. 표현 층: 어떻게 말할지
1. 고른 대답 종류에 맞는 조각 행을 유형(전용 → 공통)·말투·관계·깊이로 거른다(기존 `$voice_pick_fragment` 규칙).
2. **반복 방지**: `jo9_said`에 있는 조각은 조각별 대기 일수 동안 뺀다 → 그래도 없으면 최근 2회만 뺀다 → 그래도 없으면 허용. 조건을 완화해 다양성을 만들지 않는다.
3. **빈칸 치환**: `{이름}`, `{상대}`(주인님/조수 이름/손님), `{그때}`(3장 시간 표현), `{장소}`·`{예전 일}`(세계·출신·직업 사전), `{N}`·`{X}`(횟수), 조사 `{을}`·`{이나}` 등. 사전은 대사집에 둔다.
4. **겉말과 속말**: 발화 종류가 과장·축소·숨김이면 속말 조각을 붙인다. 속말은 기울임 지문으로 따로 표시한다.
   - **꾸밈 경향**(새 값 없음): 성격 9유형에서 정한다. 불꽃·도도는 부풀림, 여린·순종은 줄임, 얼음·관조는 정확, 인형은 짧게. 필로우토크 규칙 5장의 배율과 같다. 지정 유니크는 말하기 유형 지정으로 바뀐다.
5. **숨긴 이야기**: 깊이가 모자라 말하지 못한 화제는 `keep`. 다음 같은 질문에서 깊이가 충분하면 `release` 종류가 높은 점수를 받는다.
6. 이어 붙이기·페이지 나누기는 기존 `$voice_flow_pack`(연결어, 230자 경계)을 쓴다.

## 7. 대사집 데이터 형식 (원본 JSON)
대사집은 편집기에서 JSON으로 쓰고 관리한다. 게임에 넣는 방식은 8장.
```json
{
 "schema": "jo9-dialogue-book/v1",
 "dictionaries": {"place": {"medieval": ["마구간","영주의 침실"], "space": ["선실"]}, "when": ["아까","어젯밤","며칠 전","지난주","전에"]},
 "candidates": [
  {"id": "ask.pillow.boast", "trigger": "ask", "question": 1119, "kind": "boast",
   "when": [["intimacy", ">", 0]], "score": [["mood", 1], ["pride", 2]], "priority": 0,
   "effects": {"remember": "talk_past"}, "cooldownDays": 3}
 ],
 "fragments": [
  {"id": "f.pillow.boast.01", "kind": "boast", "role": "count", "types": ["flame"], "rels": "*", "emo": "-", "depth": 0,
   "text": {"1": "…", "2": "…", "3": "…"}, "inner": {"2": "실제로는 {X}번 남짓이다."}, "cooldownDays": 2}
 ]
}
```
- 조건(`when`)은 `[값, 비교, 수]` 목록(모두 참이면 통과)과 묶음 OR만 허용한다. 빌드 도구가 QSP 식으로 바꾼다. 임의 코드는 넣지 않는다.
- 기존 9,120행의 메타데이터(의미 역할·말투·유형·관계·감정·깊이·질문·공포·좋은 기분)는 이 형식으로 그대로 옮길 수 있다.

## 8. 세이브 용량: 대사를 변수에 두지 않는다
### 8.1 지금의 문제
- `#txt_man`(약 14.7MB)이 실행되면 `$voice_fragment_text` 9,120행과 메타데이터가 **변수**로 올라간다. QSP는 모든 변수를 세이브에 저장하므로 세이브마다 대사 원고가 통째로 들어간다(QSP 표준 동작. 실제 세이브 파일로는 확인 못 함).
- 옛 세이브에 옛 원고가 남는 문제 때문에 `voice_fragment_revision`으로 캐시를 확인하고 다시 읽는 처리가 필요해졌다.

### 8.2 방안 비교 (사용자 입장: 시작·불러오기·저장 속도, 세이브 크기, 대사 고칠 때의 편의)
| | A. JSON 원본 → QSP 코드 빌드 (권장) | B. json 폴더 자동 로드 | C. 현행(`#txt_man` 변수) |
|---|---|---|---|
| 게임 시작·대사 첫 사용 | 빠름. 미리 읽어 둘 대사가 없음 | 엔진이 시작할 때 JSON 전체를 변수로 올림. 크기에 비례해 느려짐 | 느림. `#txt_man` 실행에 시험 엔진 기준 8,096ms(다른 정적 location 1~10ms) |
| 대사 한 번 고를 때 | 작은 location 하나 실행(수 ms 수준. 묶음당 조각 수 상한으로 유지) | 변수 조회라 빠름 | 변수 조회라 빠름 |
| 세이브 크기 | 대사 0. 상태 인물당 약 250바이트 | 대사가 변수라 **세이브에 들어갈 가능성 큼**(엔진 확인 필요) | 대사 원고 통째로 들어감 |
| 저장·불러오기 속도 | 가장 빠름(세이브가 작음) | C와 비슷할 가능성 | 세이브가 커서 느림 |
| 옛 세이브 문제 | 없음(코드가 곧 최신). 이관 때 옛 대사 변수만 지움 | 옛 세이브에 옛 대사가 남을 수 있음 | revision 캐시 확인·재로드 필요(지금 처리) |
| 대사 고칠 때 | 편집기에서 JSON 수정 → 빌드 → mods 적용(qsp 재적용 필요) | json 파일만 바꾸면 됨(가장 간편) | qsp 수정 |
| 확실성 | 표준 QSP 동작만 씀 | 엔진 동작 3가지 미확인 | 지금 동작 |

**결론**: 플레이어 체감(시작·저장·불러오기 속도, 세이브 크기)은 A가 가장 좋다. B의 유일한 장점은 qsp 없이 json만 바꾸는 편의인데, 편집기와 빌드 도구가 있으면 A도 같은 흐름(편집기에서 고치고 내보내기)으로 쓸 수 있다. B는 엔진 확인 결과 세이브에 남지 않고 불러오기 때 다시 읽는 것이 확인될 때만 다시 검토한다.

### 8.3 방안 A의 구조
```text
편집기 (JSON 대사집, 원본)
  → 빌드 도구
     - jo9_dlg_<계기>_<묶음> location: 후보 조건·점수 식, 조각 선택 코드, 문장 리터럴
     - jo9_dlg_index location: 계기·질문·종류별 후보 id 목록(코드 상수)
  → mods/*.json 선언형 기록 → apply_mods로 qsp 적용
게임 실행
  - 계기 발생 → gs 'jo9_dlg_<계기>_<묶음>' → 결과 문장을 local로 받아 출력
  - 저장되는 것: jo9_mem, jo9_kept, jo9_said, jo9_talk_day (+ 선택 결과의 수치)
```
- location 하나가 너무 크면 엔진 속도가 떨어지므로, 묶음당 조각 수 상한(예: 300)을 둔다.
