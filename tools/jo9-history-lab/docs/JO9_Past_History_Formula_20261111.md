# 랜덤 노예 과거 경험 공식 v1 (계수 승인 2026-11-11)

작성 2026-11-11. 기준 게임 소스는 사용자가 준 최신 jack.qsp(sha256 `4354cf39…`)다.
구현은 `dist/past-history.mjs`, 계수는 `dist/data/past-history-formula.json`, 검사는 `checks-past-history.mjs`에 있다. 게임 생성 흉내는 `docs/simulate-generation.mjs`가 한다.
**계수는 사용자가 2026-11-11 승인했다. 게임 본체에는 아직 넣지 않았다.**

## 1. 대상과 시점
- 이 공식은 존재하지 않는 영입 전 과거를 배경과 생성 값에 근거해 **임의로 설정하는 초기값**이다. 영입한 뒤에는 실제 사건을 따로 기록하며(0에서 시작) 두 값을 섞지 않는다(사용자 결정 2026-11-11).
- 랜덤 노예(`special_stock = 0`)가 대상이다. 고유 노예는 고정 배경 설정을 따르며 이 공식을 쓰지 않는다.
- `generate_stock`이 끝난 직후, 즉 영입 시점에 한 번 계산해 확정한다. 이후 스킬이나 직업이 바뀌어도 다시 계산하지 않는다(핸드오프 4장).
- 연령 코드 1은 통계 대상이 아니라서 계산하지 않는다(결과는 미상).

## 2. 입력 (생성 직후 게임 값)
| 입력 | 게임 값 |
|---|---|
| 세계·출신·직업 | `$stock_world`, `$stock_family`, `$stock_occupation`(최종값. 원숙한 신부는 `*_wife`로 바뀐 뒤) |
| 연령 코드 | `stock['age']`: 0 젊음, 2 원숙 |
| 성 기술 | `sub_hug·sub_hj·sub_fj·sub_paizuri`(애무), `sub_kiss·sub_tongue·sub_bj·sub_dt·sub_asslik`(구강), `sub_vaginal·sub_anal·sub_fisting·anal_stretch`(삽입) |
| 임신 관련 | `fertility`(-1 불임, -2 미성숙), `pregnant` |
| 처녀 여부 | `virginity`(0·1 처녀, 2 비처녀). 지금은 경고 판단에만 쓴다 |

## 3. 성경험 총횟수
```
등급(묶음) = 묶음 안 기술의 최댓값 (0~5로 자름)
기준량     = (B[애무]×1 + B[구강]×2 + B[삽입]×2) / 5        B = [0, 3, 15, 50, 140, 320]
총횟수     = 기준량 × 직업 × 출신 × 세계 × 연령 × 변동 / 100^5   (단계마다 정수 나눗셈)
변동       = rand(85, 115)
```
- 묶음별 **최댓값**을 쓴다. 랜덤 노예 템플릿 1,046개에는 `seed_sub_*`가 하나도 없다. 그래서 기술이 0에서 시작해 몇 개만 오르고, 평균을 내면 거의 0이 된다.
- 직업 계수는 기술 보너스로 이미 반영된 부분을 빼고 "노출 기간·빈도"만 반영하도록 작게 잡았다.

| 직업 묶음 | 계수 | 직업 |
|---|---|---|
| 처녀 고정 | **0 → 성경험 전체 0** | bride, nun, sorceress, poor_bride, noble_bride, rich_bride, barbarian_princess, mprincess |
| 성인 접객업 | 200 | whore, markitane, brothel, courtesan |
| 노예 출신 | 150 | former_slave |
| 유부녀 | 130 | viking_wife, poor_wife, noble_wife, rich_wife |
| 유흥·사교 | 120 | major, model, avanturiste |
| 그 밖 | 100 | |

| 출신 묶음 | 계수 | 출신 |
|---|---|---|
| 보호가 강한 상류·왕가 | 80 | mprincess, barbarian_king, knight, magnat, bankeer, mayor, finance, admiral, general, ancient_noble |
| 거리·빈곤·범죄 | 120 | orphan, workhouse, orpnange, gypsy, bondman, mafiosi, roman_freedslave |
| 그 밖 | 100 | |

- 세계는 100(중립)이다. 핸드오프 8장에서 세계는 초기 능력치 추첨을 맡는다.
- 연령 계수는 젊음 100, 원숙 150이다.
- 클론·기술 주입은 0이다.
- **비처녀 최소 경험**: 생성 값이 비처녀(`virginity` 2)인데 위 계산이 0이면 `rand(1,3)`을 준다. 처녀 고정 배경이 생성 뒤 비처녀가 된 경우와 기술이 낮은 비처녀 모두에 적용한다(사용자 결정 2026-11-11: 생성 값을 따른다).

## 4. 유부녀의 임신·출산
유부녀 직업만 적용한다. 나머지 직업은 미상(null)이며 추정하지 않는다.
```
결혼 연수 = 젊음 rand(1,4) / 원숙 rand(5,12)
해마다    rand(1,100) <= 세계 문화 확률 이면 임신 +1
임신마다  rand(1,100) <= 85 이면 출산 +1        (나머지 15%는 유산·사산. 낙태·자녀 수는 만들지 않는다)
불임(-1)·미성숙(-2)이면 임신·출산 0
```
| 세계 문화 | 해마다 임신 확률 | 세계 |
|---|---|---|
| 전통 | 45% | prehistoric, barbarian, sns, medieval, darkfantasy, highfantasy, earth_rome |
| 산업 | 30% | steampunk, industrial |
| 현대·미래 | 20% | modern, cyberpunk, utopia, darkfuture, space |

- 영입 시점에 이미 임신 중(`pregnant > 0`)이면 직업과 관계없이 임신 +1을 하고, 출산에는 넣지 않는다.
- 출산 횟수와 자녀 수는 서로 대신하지 않는다(핸드오프 4장). 자녀 수는 만들지 않는다.

## 6. 게임 쪽 문제: "처녀 고정" 배경이 실제로는 고정되지 않는다
- 직업 블록(수녀 등 785~888행)이 `virginity = 0`과 성 기술 0을 정한다. 그 **뒤에서** 두 가지가 처녀를 다시 비처녀로 바꾼다.
  - 연령 경험 블록(1189~1222행): 젊음 25%, 원숙 75%
  - 1226행 "virginity chance": 남은 처녀 중 젊음 50%, 원숙 80%
- 결과적으로 처녀로 남는 비율은 젊음 약 38%, 원숙 약 5%다. 비처녀가 된 수녀에게는 비처녀 추가 경험(1237행)과 임신 추첨도 붙는다.
- 공식은 생성 값을 따른다. 처녀로 남으면 0, 비처녀가 되었으면 비처녀 최소 경험(1~3회)을 준다(사용자 결정 2026-11-11).
- 해결하려면 게임 쪽을 고쳐야 한다. 예를 들어 1189~1234행 앞에서 처녀 고정 직업은 건너뛰게 한다. 이 수정은 게임 본체 작업이라 사용자 결정 뒤 `mods/`로 한다.

## 7. QSP로 옮길 때
- 모든 계산은 정수와 `rand`로 되어 있다. 곱셈마다 100으로 나눠 값이 커지지 않게 했다(최대 320×200×120×100×150×115 단계별).
- 계수표는 `#static_base` 등에 상수 배열로 둔다(상태 변수가 아님). 결과는 핸드오프 10장의 `jo9_initial_history` 블록에 해당하는 인물 값으로 저장한다. 저장 키 이름과 저장 위치는 통계 업데이트 때 정한다.
- 상세 분포(상대: 이성·동성·인간 외, 행위: 질·구강·애널)는 편집기 엔진(`engine.mjs` `estimate`)의 분배 규칙을 그대로 쓴다. 이 문서는 총횟수와 임신·출산까지만 정한다.
