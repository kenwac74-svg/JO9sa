# 통합 캐릭터 편집기 계획 (2026-11-12)

## 목표
기존 두 도구를 하나의 브라우저 편집기로 합친다.
- 캐릭터 이미지 추가 도구(`tools/character-image-adder`, 파이썬 Tk 창): 게임 폴더의 캐릭터 JSON·이미지(전신·얼굴·외형 슬롯) 추가·수정·복제·삭제.
- 통계 편집기(`tools/jo9-history-lab`, 브라우저): 캐릭터 시뮬레이터, 배경 대사, 특성, 과거 경험·필로우토크.

한 캐릭터를 골라 **외형, 배경 이야기·설정, 능력치·특성·스킬, 과거 경험·필로우토크 대사, QSP 이벤트 대사**를 한 화면에서 고친다.

## 사용자 결정 (2026-11-12)
- 화면은 브라우저로 통합한다. 파이썬 로컬 서버가 기존 `add_character.py` 기능으로 게임 파일을 읽고 쓴다.
- 편집 범위: 외형 이미지 + 배경 이야기·설정 + 능력치·특성·스킬 + 과거 경험·필로우토크 대사 + QSP 안 이벤트 대사.
- 게임에 아직 없는 항목(필로우토크 대사·과거 경험)은 **별도 대사집 파일**에 저장한다. 게임 캐릭터 JSON은 건드리지 않는다.
- QSP는 규칙상 직접 쓰지 않는다. 이벤트 대사 수정은 `mods/` 선언형 JSON으로 내보낸다.

## 구조
```
브라우저(dist/*.mjs)  ──HTTP──  start-history-lab.py(로컬 서버)
                                   ├─ /api/game, /api/chars, /api/char/<id> …  (add_character.py 함수 호출)
                                   ├─ /game/<경로>  게임 폴더 이미지 읽기 전용 제공
                                   ├─ /api/talkbook/<id>  대사집 파일 읽기·쓰기
                                   └─ /api/qsp/*  qsp 읽기(검색) → mods JSON 초안 만들기
```
- 이미지 정렬(배율·위치)과 얼굴 상자는 브라우저 캔버스에서 하고, 원본 이미지 + 변환값을 서버로 보내 `align_core.apply_transform`으로 만든다(Tk 도구와 같은 결과).
- 서버는 127.0.0.1에서만 듣는다. 게임 폴더 밖 경로 쓰기는 거부한다.

## 단계
| 단계 | 내용 | 확인 |
|---|---|---|
| 1 | 이미지 도구 최신본(업로드본)을 repo에 반영, 서버 API 뼈대(게임 폴더 지정·목록·한 캐릭터 읽기·이미지 제공) | 시험 게임 폴더(`assets` 복사본)로 API 응답 검사 |
| 2 | 화면: '캐릭터 편집' 탭(왼쪽 목록·검색, 가운데 외형 미리보기, 오른쪽 탭) + 설정·배경 이야기·능력치·특성 편집 → JSON 저장(백업 `.bak`) | 저장 전후 JSON 비교, 브라우저 점검 |
| 3 | 외형 편집: 슬롯 이미지 선택, 정렬, 얼굴 상자, 저장(`save_character_slots`) | Tk 도구와 같은 입력에서 같은 PNG |
| 4 | 대사집: 캐릭터별 과거 경험 사실 + 필로우토크 대사(시뮬레이터 재사용), 유니크 수동 각색 | 저장·불러오기 왕복 |
| 5 | QSP 이벤트 대사: 이름·ID로 qsp 검색, 줄 단위 수정 → mods JSON 초안(전·후 SHA-256) | apply_py로 적용·왕복 검증 |
| 6 | 새 캐릭터·복제·삭제(기존 함수), 작업 기록(tool_log) | 시험 폴더에서 각 동작 |
| 7 | 단독 실행기·사용 설명·인계 갱신 | 압축본에서 실행 |
