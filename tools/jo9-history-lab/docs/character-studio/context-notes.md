# 결정 기록

## 2026-11-12
- 사용자 결정: 브라우저 통합, 편집 범위 전부(외형·배경·능력치·대사집·QSP 이벤트 대사), 게임에 없는 대사는 별도 대사집 파일.
- 업로드본(`character-image-adder` 2026-11-10판)은 repo 판보다 새것이다(add_character.py·character_editor_ui.py·tool_log.py 다름, 나머지 같음). 서버는 업로드본 함수를 그대로 부른다.
- 이미지 도구 백엔드는 GUI와 분리돼 있다(`save_character_slots`, `clone_character`, `add_character`, `delete_character`, `align_core.apply_transform`). 서버에서 그대로 호출한다.
- 시험 게임 폴더: repo `assets/`(json/slaves 1,181개, content/pic/girls)를 스크래치 폴더로 복사해 쓴다. repo 원본은 쓰지 않는다.
- 게임 캐릭터 JSON에는 세계·출신·직업 ID가 없다(seed 키 164개 중 world/family/occupation은 description 문장만). 그래서 '배경·설정' 탭은 이름·나이 분류·기본 심리·처녀 여부·배경 이야기 3칸을 고친다. 세계·출신·직업 분류는 대사집 파일에 둔다(4단계).
- 고칠 수 있는 키: 게임이 읽는 seed_ 키(`game-seed-keys.json`)에서 이미지·얼굴 경로를 뺀 것. 키가 없으면 게임이 무작위로 정하므로, ×는 키를 지워 '무작위'로 되돌린다.
- 특성은 traits.json 중 묶인 키가 seed 키이고 setValue가 있는 88개만 JSON으로 고정할 수 있다. 같은 키를 쓰는 특성은 하나만 가진다.
- 저장: 바뀐 키만 반영하고 처음 저장할 때 `.bak`(이미지 도구와 같은 규칙). JSON은 이미지 도구처럼 들여쓰기 4칸으로 다시 쓴다. 안 고친 배경 문단은 원문(`<!-- #nwtx -->` 포함) 그대로 둔다.
- 서버 쓰기 요청은 JSON 형식·같은 출처(127.0.0.1/localhost)만 받는다.
- 사용자 확인(2026-11-12): '시뮬레이션 + 편집기'다. 캐릭터 시뮬레이터는 빼지 않는다. 4단계에서 편집 중인 캐릭터를 시뮬레이터로 보내는 연결을 넣는다.
- 외형 저장: 브라우저는 원본 이미지(data URL) + 변환값만 보내고, 서버가 `align_core.apply_transform`(변환 없으면 795×596 그대로, 아니면 `compose_full`)으로 만들어 `save_character_slots`에 넘긴다. 정렬한 기본·하녀 이미지와 얼굴 3종이 Tk 도구 계산과 바이트 단위로 같음을 확인했다.
- 정렬 기능은 Tk 도구와 같다: 전체 맞춤(contain), 투명 여백 기준(지금 배율 유지, 가로 중심 397.5, 윗끝 Y), 두 점(정수리→하단 컷, 정수리→턱 = 머리 높이 142), 끌기·휠·화살표·숫자. 얼굴 상자 기본 위치는 기본 이미지의 보이는 윗부분 가운데.
- 배경 자동 제거(rembg)는 넣지 않았다(선택 기능, 무거운 의존성). 필요하면 기존 도구를 쓴다.
- 대사집 파일: `<게임 폴더>/jo9_talkbook/<ID>.json`(json 폴더 밖이라 게임이 자동으로 읽지 않음). 형식 `jo9-talkbook` v1: 배경 분류(세계·출신·직업 ID), 시드·영입 정보·직접 지정값, 필로우토크 대사(칸 ID → 문장), 과거 경험 사실·통계, 메모. 다시 저장할 때 처음 한 번 `.bak`.
- 시뮬레이터 연결: '시뮬레이터에서 열기'는 편집 중(저장 전 포함) 게임 JSON + 대사집을 캐릭터 시뮬레이터에 유니크로 연다. 시뮬레이터에서 각색한 뒤 '담기'로 배경·시드·사실·대사를 대사집에 가져온다. 다른 캐릭터가 열려 있으면 담지 않는다.
- 사용자 지시(2026-11-12): 연령 코드 1을 아예 막지 말고 원본 DB 연결 코드는 남긴다. 편집기가 스스로 출력(자동 생성)하는 것만 막고 사용자의 편집권은 막지 않는다. 그래서 연령 코드 1은 시뮬레이터가 대사·과거 경험을 만들지 않고('담기'는 배경 분류·원본 DB 연결 코드만), 사용자가 직접 쓴 칸은 그대로 저장한다.
- 사용자 지시: 수동 편집에는 원본 DB 선택과 참조가 필요하다. 대사집 탭에서 칸 22개마다 원본 DB 후보(시뮬레이터와 같은 주제 묶음)를 고르고(◀▶ 넘기기), 원문(또는 원문 없는 대답의 위치 안내·원본 글 링크)을 옆에 보며 쓴다. 고른 키는 `refs[칸] = {key, blocked}`로 저장(문장 없이 키와 표시불가 코드만).
- QSP 이벤트 대사: 게임 jack.qsp를 읽어(왕복 검사) 이름·장면 태그로 줄을 찾고, 고친 줄을 mods 선언형 JSON 초안으로 만든다. 같은 줄이 여러 번 있으면 앞뒤 줄을 붙여 하나로 특정. 메모리에서 적용해 적용 후 SHA-256을 계산하며, `apply_py` 적용 결과와 해시가 같음을 확인했다. 줄바꿈 금지, 작은따옴표 짝 변화는 경고. 내려받기 또는 repo `mods/`에 저장(같은 이름은 거부). 표시는 따로 넣지 않는다(문자열 안 줄에 주석 줄을 끼우면 깨질 수 있어서).
- 새 캐릭터·복제·삭제: 기존 함수(`add_character`, `clone_character`, `delete_character`)를 그대로 부른다. 새 캐릭터는 기본 전신·얼굴 필수, 고유 캐릭터면 랜덤 풀 미등록. 삭제는 확인 번호 입력이 필요하고, 랜덤 풀 중간 번호면 '번호 유지(safe)/마지막 번호 이동(swap)'을 고른다. 공유 이미지는 보존한다. 대사집 파일은 삭제하지 않는다(남은 파일은 수동 정리).
- 작업 기록: 게임 폴더에 `picture_modding`(기존 이미지 도구 자리)이 있으면 그 `작업기록`에 이어 쓰고, 없으면 `jo9_editor/작업기록`. 필드·외형 저장, 새로 만들기, 복제, 삭제를 남긴다.
- 화면 버그 수정: 글 입력칸의 change 때 화면 전체를 다시 그리면 다음 칸으로 옮긴 포커스와 입력이 사라졌다. 글 입력칸은 다시 그리지 않고 표시만 갱신한다.
- 사용자 지시(2026-11-12): 유니크도 세계·출신·직업을 정하면 그 값이 고정되어야 한다. 그래서 배경 분류 선택을 '배경·설정'과 '대사집' 탭 둘 다에 두고, 고르는 즉시 대사집 파일(`background`)에 저장한다(저장 안 한 대사 편집은 건드리지 않음). 선택지는 시뮬레이터와 같은 연결표로 위에서 아래로 좁힌다. 시뮬레이터 카드는 유니크라도 정한 분류를 보여 준다(정하지 않았으면 '유니크 고정 설정(분류 없음)').
- 사용자 지적(2026-11-12): 머리의 '저장…'이 편집값을 저장하지 않는 것 같다. 원인: 숫자를 고친 직후 버튼을 누르면 입력칸을 벗어날 때 머리 버튼을 다시 만들어 클릭이 사라졌고, 값은 입력칸을 벗어나야 변경으로 잡혔다. 수정: 입력하는 즉시 변경으로 잡고, 머리 버튼은 다시 만들지 않고 상태만 바꾼다. '편집값 저장'(바로 저장)과 '변경 보기'(미리보기)로 나눴다.
- 사용자 지시(2026-11-12): 편집기에서 불러오면 그 값이 시뮬레이터로 바로 넘어가야 하고, 명확한 '보내기' 버튼이 있어야 한다. 캐릭터를 열 때와 편집값을 저장할 때 자동으로 시뮬레이터에 열고(탭은 그대로), 머리의 '▶ 시뮬레이터로 보내기'는 저장 전 값까지 보내고 시뮬레이터 탭으로 간다. 시뮬레이터에서 랜덤 생성한 뒤에도 버튼이나 다시 클릭으로 되돌릴 수 있다.
