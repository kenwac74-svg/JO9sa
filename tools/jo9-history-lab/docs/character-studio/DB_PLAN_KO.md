# 편집기 통합 DB 기획 (2026-11-13, 확인 대기)

## 1. 무엇을, 왜
- 지금 편집기 데이터는 JSON 파일 20여 개로 흩어져 있다. 사용자는 JSON을 직접 고치기 어렵다(사용자 말).
- 목표 1(인계 2번): 이 데이터를 **편집기 'DB' 탭에서 표로 보고 고치고, 엑셀로 내보내 고친 뒤 다시 가져오게** 한다.
- 목표 2(인계 3번): 세계관 자료집(1장~)을 같은 DB에 넣어, AI 프롬프트를 조립할 때 **장·절 단위로 골라 붙이게** 한다.

## 2. 설계 원칙 (제안)
1. **원본 파일이 기준이다.** 게임과 시뮬레이터가 읽는 JSON(캐릭터 `seed_*`, 대사집, `dist/data/*.json`)과 자료집 `.md`는 그대로 두고, DB는 그 파일들을 표로 펼쳐 보여 주고 고친 값을 **원래 파일에 되써 넣는 층**이다. 별도 DB 파일(SQLite 등)은 만들지 않는다. 이유는 두 벌을 맞추는 동기화 문제가 생기지 않고, 게임이 읽는 파일 형식이 바뀌지 않기 때문이다.
2. **표 어댑터 하나에 데이터 하나.** 각 데이터마다 '행 키, 열, 고칠 수 있는 열, 되쓰기 규칙'만 정의하고, 화면·엑셀·검사는 공통 코드 하나로 처리한다.
3. **엑셀은 한 통합 문서, 표마다 시트 하나.** 키 열과 원문 열은 '수정 금지' 표시. 가져올 때 키·행 수·형식을 검사하고, 바뀐 칸만 미리 보여 준 뒤 사용자가 확인하면 반영한다(지금 각색 엑셀과 같은 방식). 처음 반영할 때 원본 `.bak`을 남긴다.
4. **기존 정책 유지.** 표시불가 B1·B2 원문은 DB·엑셀·AI 작업 목록에 넣지 않는다. 연령 코드 1의 자동 생성 제외는 `excludedAges` 데이터 값 하나로 두고, 사용자가 직접 쓰는 칸은 막지 않는다.

## 4. 세계관 자료집 DB (인계 3번)
- 자료집 `.md`를 `##`·`###` 제목 단위 절로 나눠 표의 행으로 만든다. 행 키 = 파일 + 제목 경로(예: `03#3.2/12`). 본문을 고치면 그 절만 `.md`에 되써 넣는다.
- 각 절에 붙이는 조건 열: `항상` / `작업별: 번역·창작·대화` / `캐릭터 조건: 세계·주인공 번호·장소·인물`.
- 프롬프트 조립 함수: 작업 종류와 캐릭터(세계·주인공·장소)를 받아 [항상] 절 + 조건이 맞는 절을 순서대로 붙이고, 모델별 분량 상한을 넘으면 낮은 우선순위부터 뺀다. 'AI 연결' 탭에서 조립 결과를 미리 본다.
- 1a장의 9·10번 카드처럼 Claude가 비워 둔 칸은 빈 칸으로 보이며 사용자가 채울 수 있다.

## 5. 단계
1. 공통 표 엔진(어댑터 형식, 서버 읽기·검사·되쓰기 API, DB 탭 표 화면, 엑셀 다중 시트 왕복) + 표 9(영입 경로)로 시험.
2. 표 3~8, 10 차례로 연결.
3. 표 1·2(게임 캐릭터·대사집, 파일이 많고 기존 편집 탭과 겹치므로 같은 저장 함수를 재사용).
4. 표 11 + 프롬프트 조립.
5. 각 단계마다 검사 스크립트(되쓰기 왕복 = 바꾸지 않으면 파일이 바이트 그대로, 바꾸면 그 칸만 바뀜)와 화면 시험.
