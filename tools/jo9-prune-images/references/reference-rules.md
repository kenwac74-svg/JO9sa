# JO9 참조 판정 규칙

## 조사 범위와 근거

실행 QSP가 기준이며 QSRC는 대조 자료다. QSP 해독 도구는 대상 저장소의 검증된 도구를 찾거나 포맷을 확인해 사용한다. 해독 결과의 location 수·내용이 정상인지 확인한다. 바이너리를 일반 텍스트처럼 검색한 결과는 충분하지 않다.

경로 구분자, Windows 대소문자, HTML escape, URL encoding을 정규화한다. 이미지 참조는 전체 상대 경로와 확장자로 구별한다. 파일명이 다른 폴더에도 있다고 그 그림을 사용 중이라고 단정하지 않는다. 기본명만 일치하는 것은 HOLD 근거다. 주석·문서·테스트의 언급은 실행 참조와 구분하되 아직 만들고 있는 패치의 사용 예정 참조는 보호한다.

## 동적 호출에서 놓치기 쉬운 부분

- QSP `<<표현식>>`, 문자열 더하기, `rand`, 배열, `dyneval`, 함수 인수로 경로를 조립한다. 고정 접두사·접미사만이 아니라 변수의 값과 할당 위치를 역추적한다. 전체 경로가 변수인 경우 모든 그림을 KEEP으로 표시해 조사를 무의미하게 만들지 말고, 해결하지 못한 공급 경로의 범위를 HOLD로 표시한다.
- `display_pic`: 행동명과 폴더, 머리색·머리길이·연령, 캐릭터 특수 태그, 두 인물 조합 `A~B`, 일반 fallback, `any_age`를 확인한다. 함수 인수는 괄호와 따옴표를 인식해 파싱한다. 단순 쉼표 분리는 중첩 호출에서 틀린다. 호출의 행동명·폴더가 변수이면 공급자를 확인하거나 관련 풀을 보류한다.
- `display_fullimage`: 의상과 상태별 `indpack_*` 배열, `_horny`, `_rebel`, 조수·수감자·특수 의상 분기를 확인한다. 배열 바인딩을 못 찾았다고 숫자 폴더의 의상 그림을 미사용으로 판정하지 않는다. 엔진이나 로딩 데이터가 공급할 수 있다.
- JSON: `fullimage`, `seed_ava`, 회색/세피아 변형, 몸 부위와 의상 필드를 확인한다. 확장자를 렌더러가 붙이거나 고정 폴더를 앞에 붙이는 값을 해석한다. JSON 내 HTML/CSS 문자열의 `url(...)`도 조사한다. 스톡·캐릭터 데이터를 실제로 로딩하는 코드를 연결한다.
- 제목 그림처럼 `'title' + rand(1,13)`으로 생성되는 파일은 `title13.png`라는 문자열이 없어도 사용된다. 유한 범위는 직접 전개하고 산술·조건 분기는 분석 가능한 만큼 계산한다.

## 새 장면전환과 원본 B컷

기존 underscore 랜덤 풀과 별개로 새 전환 기능은 `name.png`, `name (2).png`, `name (3).png`를 사용한다. 실행 QSP의 `interior_change`에 있는 `$jo9_base`, `$jo9_path`, `jo9_count`, 저장 선택 `jo9_cut_choice`를 대조한다. 등록된 A컷과 선택 가능한 B/C 이후 컷은 KEEP이다. 현재 선택하지 않았다는 이유로 제외하거나 번호를 당겨 저장 선택을 바꾸지 않는다. 등록이 누락된 새 컷도 카탈로그·컷 추가 기록과 부모 A컷을 확인하기 전에는 HOLD다.

`game/modtools/image-original-cuts.json`의 `originals`는 가상 B컷 별칭(`alias`)과 실제 원본(`source`, `target`, `sourceRoot`)을 연결한다. `content/jo9o_original_cuts` junction의 실제 대상과 일치하는지 읽기 전용으로 확인한다. 원본 B컷은 `content/pic`에 복사본이 없어도 사용된다. 원본·연결·manifest를 외부 정리 대상으로 넣지 않는다. `reservations`의 원본 없는 B번호는 실재하는 이미지로 세지 않지만 C컷 번호와 저장 선택을 보존한다.

보관본 JO9main에서 참조되지 않는 파일도 플레이본의 추가 기능·새 패치에서 사용될 수 있다. 양쪽 실행 QSP와 현재 전환 manifest를 대조한다. 원본 경로가 같다는 사실과 같은 실제 파일이라는 사실은 구별한다. 수정 시각·설치 경로가 다른 조사 결과는 섞지 않는다.

## 랜덤 풀과 엔진의 부수 효과

JO9는 엔진의 디렉터리 탐색과 `picMax`가 선택 범위를 만드는 경우가 있다. 그림이 직접 출력되지 않아도 **파일 개수나 인덱스 상한을 바꾸면 다른 그림의 호출이 깨질 수 있다**.

1. 해당 폴더의 랜덤 선택 방식과 번호 규칙을 확인한다. `base.png`, `base_2.png`가 실제 번호 풀인지, 별도 이야기 단계인지 구별한다. 임의로 `-1`, `file2`까지 같은 규칙으로 묶지 않는다.
2. `picMax` 키가 폴더를 포함하는지 기본명만인지 확인한다. 기본명만이면 다른 폴더의 같은 이름도 검사한다.
3. 엔진이 파일 수를 세는지 최대 번호를 읽는지 확인한다. 코드에서 확인되지 않으면 영향 있는 풀은 HOLD로 유지한다. 중간 번호를 제거하거나 사용 중인 파일의 번호를 바꾸지 않는다.
4. 엔진 바이너리의 문자열 목록은 호출 경로를 찾는 보조 증거이며 실제 제어 흐름의 증명이 아니다.

## 외부 입력과 판정 완료

저장 파일, 추가 QSP, 동적 라이브러리, 플러그인, 새 패치, 사용자 데이터가 경로를 공급하는지 확인한다. 지원할 저장본·패치 범위를 명시한다. 저장본 전체를 해독하지 못한 경우 해당 경로 공급자가 존재하면 보류한다. 단순히 구형 저장본이 있을 가능성만으로 무관한 폴더 전체를 보류할 필요는 없다.

MOVE_READY에는 다섯 근거가 필요하다: (1) 정적 참조 없음, (2) 관련 동적 공급자 분석 완료, (3) 인덱스·랜덤 부수 효과 없음, (4) 지원 범위의 외부 입력에서 필요 없음, (5) 배포 또는 작업 자원으로 보존할 용도 결정. 각 근거는 조사 파일·location·필드나 풀 규칙을 지목한다. `확인 완료` 같은 근거 없는 선언은 충분하지 않다.

조사 결과는 추후 버전에서 달라질 수 있다. 실행 QSP 해시와 조사 범위를 기록하고 이동 전 스냅샷을 대조한다. 과거 JO9main에서 찾은 후보 목록을 현재 플레이 폴더에 적용하지 않는다.
