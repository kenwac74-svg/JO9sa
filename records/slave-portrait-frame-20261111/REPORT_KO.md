# 노예 초상 자동 테두리 — 2026-11-11

사용자 요청: 노예 이미지 목록의 포트레이트에 자동 테두리 만들기 기능을 넣는다. 컬러·흑백·세피아 초상 카드마다 버튼을 추가하고 현재 PNG와 테두리 미리보기를 비교한 뒤 명시적으로 적용한다. 기존 PNG 교체·파일 연결·검색·태그·복장·경로 경고 기능은 유지한다.

## 사용법

1. 모드툴의 이미지 패치리스트에서 **노예 이미지** 탭을 열고 캐릭터를 찾는다.
2. 컬러·흑백·세피아 초상 카드의 **자동 테두리 만들기**를 누른다. 현재 연결된 PNG와 새 테두리 미리보기를 나란히 확인한다.
3. 원하는 결과이면 **테두리 적용**을 누른다. **취소** 또는 ESC로 닫으면 PNG를 저장하지 않는다. 기존 프레임이 확인된 경우 적용 버튼이 비활성화되고 현재 파일을 유지한다.

150×150 또는 151×150 PNG만 지원한다. 크기·경로는 유지하고 바깥 5px만 기존 게임 프레임으로 바꾼다. 그 안쪽 얼굴 픽셀과 알파는 그대로다. 세 종류의 프레임은 WORK의 `girls/face/0001_black_long_loli.png`, `_gray.png`, `_sepia.png`에서 읽는다. 150px 프레임을 151px 초상에 쓸 때는 기존 처리와 같은 LANCZOS 크기 맞춤을 사용한다.

알려진 프레임과 일치하거나 매우 가까운 가장자리는 기존 프레임으로 보존한다. 알려진 프레임과 맞지 않는 불투명한 가장자리는 특수 테두리일 수도 있어 **불확실** 안내를 표시한다. 없는 테두리라고 단정하지 않으며 미리보기를 확인하고 적용해야 한다. 다른 캐릭터 JSON이 같은 물리 PNG 경로를 직접 참조하면 공유 번호도 표시한다. 이 경우 파일을 적용하면 같은 경로를 쓰는 캐릭터의 그림도 함께 바뀐다.

## 입력·반환과 호출 관계

| 구간 | 입력 | 반환·역할 |
|---|---|---|
| 초상 카드 | 캐릭터 ID, `seed_ava_clear`/`seed_ava_gray`/`seed_ava`, 현재 JSON 해시 | 최신 연결을 다시 읽고 미리보기 요청 |
| `/api/catalog/portrait-frame/preview` | 위 ID·필드·JSON 해시 | 실제 경로, 원본/결과/선택 프레임 해시, 150/151×150 크기, 판정, 공유 번호, 원본·후보 PNG 데이터 |
| `/api/catalog/portrait-frame/apply` | 미리보기의 경로·해시들과 확인 선택 | 대상을 다시 계산·검사한 뒤 기존 PIC 저장기의 적용 기록·백업 ID 반환. 이미 테두리가 있으면 `unchanged` |
| `inspectPortraitFrame` | PNG 바이트, 알려진 프레임 바이트 목록, 두께 | `framed`/`unframed`/`uncertain`과 크기·판정 사유. 이미지 파일 쓰기 없음 |
| `composePortraitFrame` | 원본 PNG, 선택 프레임, 참조 목록 | 합성 PNG Buffer와 `changed`, `centerPixelsPreserved`. 알려진 프레임은 원본 바이트를 그대로 반환 |

UI는 `tools/girls-image-checklist/catalog-girls-checklist.js`, API는 `tools/text-workshop/server.cjs`가 호출한다. `character-portrait-frame.cjs`가 현재 캐릭터 JSON·PNG·프레임을 확인하고 `portrait-frame.cjs`와 인접한 `portrait-frame.py`로 미리보기를 만든다. Node 내장 모듈과 Pillow가 설치된 Python이 필요하다. Python은 `JO9_PYTHON`/`PYTHON`, 일반 사용자 설치 위치, PATH에서 찾으며 격리된 LOCALAPPDATA에는 USERPROFILE/홈 경로 탐색을 보완했다. 저장 기능 자체는 JSON·QSP를 편집하지 않는다.

적용 직전에 JSON·연결 경로·PNG·선택 프레임·합성 결과 해시를 다시 비교한다. 다른 창에서 바뀌었으면 예전 미리보기로 저장하지 않고 재확인을 요구한다. 불확실한 프레임은 확인 선택 없이는 적용하지 않는다.

## 저장의 부수 효과와 복구

실제 적용은 `pic-local.cjs`의 기존 `apply(jobs, 'portrait-frame')`를 사용한다. 원본은 WORK의 `content/pic/__JO9_ImageBackups/<백업ID>/original/<원래 경로>`에 보존하고 manifest에 전후 해시·상태를 남긴다. 기존 personal-patch 기록과 카탈로그 용량/해시·이미지 진행 이력도 갱신한다. 패치 또는 카탈로그 기록 실패는 저장 결과의 경고로 구분된다. 미리보기·취소·기존 프레임 유지에서는 이 PNG 저장·백업 작업을 하지 않는다.

사용자가 나중에 PNG를 실제 적용한 뒤 되돌릴 때는 기존 이미지 워크숍의 백업/복구 경로를 사용한다. 현재 파일·백업 해시를 확인하므로 이후 다른 그림으로 바뀐 파일을 무작정 덮어쓰지 않는다. 캐릭터 JSON의 연결 주소와 세이브는 그대로다.

기능 설치 전 소스/설치 서버·체크리스트 JS·카탈로그 백업은 `G:/somi/JO9_work_backups/portrait-frame-tool-20261111`에 있다. 기능을 제거하려면 먼저 서버의 새 require/라우트와 카탈로그의 버튼/처리기를 기존 버전으로 맞춘다. 그 뒤 새 helper를 제거할 수 있다. helper부터 지우면 서버가 시작되지 않는다. 카탈로그는 이후 사용자 변경과 대조해 체크리스트 스크립트만 되돌리며, 전체 HTML을 과거 상태로 덮어쓰지 않는다. 이미 적용한 PNG는 도구 제거만으로 돌아가지 않으므로 별도 백업 복구가 필요하다.

## 설치·검증과 한계

WORK의 도구 설치본에 `server.cjs`, `character-portrait-frame.cjs`, `portrait-frame.cjs`, `portrait-frame.py`를 맞췄다. 추적 소스 UI와 seed/WORK 카탈로그는 체크리스트 JS 부분만 바꿨으며 기존 데이터 배열·태그·분석 표시는 보존한다. 이 작업에서 게임 QSP·캐릭터 JSON·실제 PNG·세이브는 변경하지 않았다. Full·음원·커밋·푸시도 변경하지 않았다.

최종 자동 검사 **19개 통과**를 확인했다. helper8개는 150/151px 중앙/테두리 픽셀 보존·반복 무변경·다른 알려진 프레임 보존·불확실 판정·손상/크기 거부·파일 무쓰기·Python 탐색을, 서비스6개는 버전 충돌·공유·저장기·기존 프레임·확인 조건을 검사한다. UI4개와 격리 HTTP1개도 통과했다. 실제 WORK 브라우저에서는 2574 야즈민의 컬러 초상 원본/미리보기를 나란히 열어 151×150/바깥5px/얼굴 보존을 확인하고 취소했다. 실제 운영 PNG의 테두리를 저장한 검증은 하지 않았다.

취소 뒤 준비 중 문구가 남던 안내도 수정했다. 마지막19번째 VM 검사에서 취소 상태 안내와 PNG 무저장을 확인했으며 WORK/seed 카탈로그에 설치했다. 실제 브라우저에서는 초상3종의 버튼·원본/합성 미리보기·불확실 경고와 취소를 확인했다. 이 UI 확인을 실제 PNG 적용 검증으로 바꾸어 표현하지 않는다. 실제 비교 화면 근거는 [미리보기 캡처](preview-dialog.jpg)다.

도구 재시작 과정에서 기존 `Start-JO9-Tools`가 TIME_WAIT 항목의 PID0을 사용 중 프로세스로 잘못 판단해 시작을 막았다. 실제 LISTEN 프로세스가 없음을 확인한 뒤 숨김 방식으로 서버를 직접 시작해 UI 검증을 진행했다. 실행기 코드는 이번에 수정하지 않았다.

설치 검증에서 보호파일14개(QSP·2574 JSON·체크 상태·설정·야즈민 PNG8개)의 해시 보존과 source/WORK 프로덕션4모듈 일치를 확인했다. 야즈민8PNG는 Pillow 전체 디코딩도 통과했다. 설치 전후 해시와 UI/HTTP 검사 자료는 verification.json 및 설치 증거 JSON에 보존한다. 일반 게임의 실제 초상 표시·사용자 세이브 플레이·모든 프레임 종류의 육안 결과까지 확인한 것으로 표현하지 않는다.
