# 여성 주인공 텍스트 분리 검토: 세이브 영향

분석만 수행했다. WORK QSP, 원본 SAV, Full, 저장소 파일은 변경하지 않았다. 입력은 WORK `jack.qsp` 52,174,068바이트, SHA256 `acd6bc3c868cb8f39e89a261d3733f351c7f4fe21da87f873ab9ba914686885b`, 321개 로케이션이다.

## 실제 감소량

여성 전용 은행 두 개의 소스 삭제와, 이미 SAV에 들어간 공통 데이터 정리는 서로 다르다. QSP의 실행되지 않은 로케이션 전체가 그대로 SAV에 복제되는 구조는 아니다. 실제로 초기화된 전역 변수의 숫자/문자열/배열 인덱스, 현재 화면, 선택지 코드와 콜백 이름 등이 저장된다.

남성 SAV 네 개를 오프라인으로 읽었다. 원본 전후 SHA256·크기·수정시각이 같고 기존 codec의 바이트 왕복 검사도 일치했다. `hero_choice`는 각각 1, 1, 1, 10이다. 실제 여성 주인공 SAV의 동작은 검증하지 않았다.

| SAV | 원본 바이트 | 지정 여성 데이터 문자열만 제외 | 숫자 상태 보존 + 전용 레코드/배열 꼬리 제외 |
| --- | ---: | ---: | ---: |
| 1.sav | 24,536,162 | 88,786 | 91,358 |
| bds.sav | 49,657,046 | 99,650 | 102,222 |
| josu.sav | 55,698,448 | 99,650 | 102,222 |
| 안개순찰대.sav | 57,137,858 | 99,660 | 102,232 |

오른쪽 수치는 가정한 정리 결과의 정확한 직렬화 바이트 차이다. `josu.sav`는 메모리에서만 재직렬화하여 55,698,448→55,596,226바이트, 차이 102,222바이트(99.83KiB, 약0.184%)를 확인했다. 미대상 변수는 같은 객체를 유지하며 남은 모든 인덱스맵은 그대로다. SAV 파일은 만들지 않았다. 이 계산은 삭제 안전성 검증이나 반영 승인이 아니다.

현대 SAV `josu.sav`의 구성은 다음과 같다.

| 대상 | 문자열 페이로드 | 레코드/꼬리 포함 참고 |
| --- | ---: | ---: |
| `#masters_base` 6개 배열의 ID101~124 | 59,380 | 끝24칸 절단 시60,820 |
| `#variative`의 여성 표시표6개 | 830 | 전체 레코드1,532; 숫자 상태를 공유하는2개는 보존 |
| 여성 전용 이름의 동적 코드4개 | 36,204 | 레코드36,648 |
| `$pregnant_female_taken` | 3,236 | 레코드3,468 |

메타배열은 `$master_base_name`, `$hero_description`, `$hero_difficulty`, `$master_version_stats`, `$clear_ava_path`, `$sepia_ava_path`다. 여기에 초기화 코드와 이미지 경로도 포함되므로 전부를 대사 문자량이라고 부르지 않는다. 각 SAV에서 배열 길이125, 문자열키 인덱스0개, 101~124의 숫자0을 확인했다. 끝24칸만 제거하는 가정이며 기존 ID0~100은 그대로다. 그 앞의 빈 구간 정리는 이번 범위에 넣지 않았다.

표시표는 `FEMALE_VIRGINITY`, `FEMALE_VAGINAL_MODIFICATION`, `FEMALE_BOOBS_MODIFICATION`, `FEMALE_AGE_NAME`, `FEMALE_BOOBS`, `FEMALE_ANAL_DESCRIPTION`이다. `FEMALE_VIRGINITY`와 `FEMALE_ANAL_DESCRIPTION`에는 남성 SAV에서도 비0 숫자값이 있으므로 레코드 전체 삭제 대신 문자열만 비우는 계산을 적용했다. 숫자 상태는 보존했다. 나머지4개 표시표와 동적 코드4개, 임신 대사1개를 합친9개 레코드만 전체 제외를 가정했다.

동적 코드4개는 `WOMAN_DOSUG_OPTIONS`, `BLACK_BAZAR_WOMAN_OPTIONS`, `SCROLL_HEROES_WOMAN`, `SCROLL_HEROES_WOMAN_BACK`이다. 사용 중인 선택지로 복사된 데이터는 이 추정에 넣지 않았다.

## 여성 은행과 음성 대사 캐시 구분

`#txt_woman`과 `#txt_2_woman`의 직접 문자열 대입을 제한적으로 추적한 결과 2,861건/654개 변수 이름이었다. 그중560개 이름은 다른 로케이션에서도 직접 문자열을 대입한다. 이 이름들로 저장된 약1.3MB를 여성 데이터라며 삭제하면 남성/공통 대사가 함께 사라진다.

두 은행에서만 직접 문자열 대입이 발견된94개 이름은 측정한 네 SAV에 레코드가 없었다. 따라서 **이 두 은행의 전용 이름 레코드만** 대상으로 확인된 감소량은0바이트다. 이는 위의 공통 초기화 위치에서 준비하는 여성 메타데이터·표시표·동적 코드까지0바이트라는 뜻이 아니다. 현재 은행 밖 모든 동일 리터럴을 제외한 여성 고정문장1,374개와 대조했을 때 현대 `josu`/`안개순찰대`는 일치0건이었다. `bds`의 일치1건은 공통 이름 `JO9_NYMPH_STONE_TEXT`에 저장된130바이트 문장으로, 은행 실행이나 제거 가능성을 증명하지 않는다. 치환문이 있는1,333개 대입은 이 고정문장 비교에서 제외했다.

별도로 `bds`/`josu`/`안개순찰대`의 `VOICE_FRAGMENT_*` 15개 레코드는 각각23,531,038바이트다. 이것은 `#txt_man`에서 준비하는 현재 대사 은행이며 여성 은행 삭제의 이익이 아니다. 과거 클린 세이브 보고서의 약47% 감소를 여성 텍스트 삭제율로 재사용하면 안 된다. 현재 일반 저장/자동저장/일반 로드는 이15개를 유지하고, 명시적 클린 저장에서만 비운다. 다음 대화에서 다시 생성할 수 있으므로, 데이터 유지 방식을 바꾸지 않으면 재생성 후 크기가 돌아온다.

## 로드·호출 호환성

- `#txt`와 `#txt_2`는 `hero_choice > 100`이면 각각 여성 은행을 호출한다. `interaction_city:48~49`에도 직접 호출이 남아 있다. 두 로케이션 이름만 삭제하면 여성 상태가 들어 있는 저장이나 직접 호출에서 대상 없음 오류가 생길 수 있다.
- `refresh_database:38~39`는 남성 은행을 무조건 호출한다. 여성 갱신 코드는 주석이다. 반면 `#masters_base`, `#variative`, `#static_txt`, `#options`, `#dynamic` 등 공통 DB는 갱신된다.
- `$ongload:17`은 `jo9_load_compat242`, 20은 `jo9_save_maintenance,'load'`를 호출하고, 350에서 `saved_game_loaded=1`을 세운다. 이후 `$newloc:160~162 → $addon,'update','full':10` 경로가 DB를 새로 준비한다. 그때마다 모든 오래된 변수·배열칸을 자동 삭제하는 것은 아니다. 지정한 공통 초기화4개에서 해당 여성 변수의 `killvar`/`killall`을 찾지 못했다. 소스의 대입문만 지우면 기존 SAV의 오래된 문자열은 다음 저장에도 남을 수 있다.
- 기존 클린 저장의 삭제 허용 목록은 여성 메타데이터/표시표/선택 코드 정리 목록이 아니다. 현재 화면·선택·지연 코드도 보존한다. 여성 데이터 제외를 실제 적용한다면 대상별 명시적 정리/갱신 조건을 따로 설계해야 한다.
- SAV에는 현재 위치 이름, 렌더링된 화면 문자열, 전역 문자열 속 동적 함수·콜백·선택문도 들어 있다. 화면이나 진행 중 선택을 통째로 비워 절감량을 늘리는 방식은 이번 추정에서 제외했다. 네 SAV의 네이티브 ACT 목록은 모두0개였다.

구형 QSP 저장 구조는 현재 위치를 이름으로 기록하지만, ACT에는 코드와 숫자 로케이션 출처/행 정보도 함께 기록한다. 따라서 "현재 위치가 전부 순번이므로 로케이션 삭제 즉시 모든 SAV가 깨진다"는 설명은 부정확하다. 다만 로케이션 삭제로 뒤 순번이 이동하면 구형 ACT 출처 등 위험이 생기므로 이름·순서를 보존한 빈 로케이션이 호환 검토 비용은 작다. 빈 본문만 두어도 호출 누락 오류는 피하지만, 그 자체로 여성 SAV의 대사나 선택 진행을 보장하지는 않는다. [구형 QSP 코드의 저장/로드 구현](https://gitlab.com/Sonnix1/Qqsp/-/raw/master/qsp/game.c), [ACT 출처 사용 구현](https://gitlab.com/Sonnix1/Qqsp/-/raw/master/qsp/actions.c). 이 코드는 구형 형식의 근거이며 설치된 실행 파일과 동일 빌드라고 주장하지 않는다.

[$ONGLOAD/$ONGSAVE 공식 설명](https://dev.qsp.org/docs/language/qsp-keywords/qsp-keywords-sys-var/)도 각각 로드 후/저장 전에 실행하는 콜백임을 설명한다. 현재 설치 엔진으로 여성 SAV·로케이션 삭제 변형의 GUI 로드는 실행하지 않았다. 위 결론은 현재 QSP 정적 분석, 실제 SAV 바이트 디코드, 메모리 직렬화 크기 검증 범위다. 로드 속도 향상 시간은 측정하지 않았다.

## 재현 자료

- `current-source-evidence.json` / `inspect-current.cjs`: 입력 해시·현재 호출 위치·은행 이름 목록.
- `save-bank-measurements.json` / `measure-saves.cjs`: 두 여성 은행과 공통 이름/고정문장/음성 캐시 구분.
- `additional-female-save-measurements.json` / `measure-additional.cjs`: 지정 여성 메타데이터·표시표·동적 코드의 정확한 바이트.
- `saved-context-evidence.json` / `inspect-save-context.cjs`: 현재 화면·네이티브 ACT 개수·관련 전역 문자열 크기. 여성 은행 이름 언급은 모두 저장된 `CLEAR_SLAVE_INSTANCE` 코드의 주석에만 있었다.

원본 SAV의 내용과 대사는 보고서/JSON에 내보내지 않았다. 이번 작업의 진단 QSP·세이브 사본은 생성하지 않았다.
