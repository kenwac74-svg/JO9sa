# 아그라바 특수 식재료·구매 툴팁 — 2026-10-30

WORK에 반영하고 구조·실제 엔진·분리된 브라우저 표시 검사를 완료했다. 사용자가 확정한 짧은 명칭 `신선한 과일`, `아그라바 와인`을 사용한다. 과일 바구니·와인병만 상시 반복 구매하며, 연회용 대량 주문은 기존 퀘스트 단계와 일회 구매 조건을 유지한다.

## 플레이 동작

| 상품 | 기존 가격·결제 유지 | 신규 보관 수량 |
|---|---|---|
| 신선한 과일 | 금화 25, 금화가 부족하면 스파크 250 | 구매마다 과일 +1 |
| 아그라바 와인 | 금화 25 | 구매마다 와인 +1 |

상점의 보조 툴팁 아이콘에 짧은 상품 설명을 붙였다. 연회 주문이 비활성일 때는 의뢰 필요·이미 주문함·자금 부족을 구분한다. 일반 상품도 자금 부족 사유를 표시한다. 기존 가업·회계 메뉴의 `tooltip_menu`와 같은 기능을 재사용하며 별도 팝업이나 공통 메뉴 함수 수정은 없다.

두 수량은 식품 저장고의 기존 목록 아래 한 줄 띄워 표시한다. 주방이 없어도 특수 재고를 가지고 있으면 두 행을 볼 수 있다. 일반 식량·창고 용량·식사·열량·건강·능력치·양조·자동 구매에 연결하지 않았다. 기존 상점 가격이나 환율은 바꾸지 않았다. 소형 결제는 실행 시에도 잔액을 확인해 오래된 선택지를 재호출했을 때 음수 결제나 무료 재고 증가를 막는다.

기존 `Fruits_minibox`, `vine_butle` 구매 기록은 그대로 유지한다. 미리 구매하면 이후 릴리 선물 조건을 미리 갖추지만 퀘스트 단계를 자동으로 진행하지 않는다. 연회용 구매 처리는 바이트 단위로 유지했다. 연회용 와인이 다른 단계에서 아예 사라지던 비활성 메뉴 조건만 과일과 같은 방식으로 보완하여 툴팁 안내가 가능하게 했다.

## 저장과 호환

신규 지속 데이터는 숫자 배열 `jo9_agraba_stock`의 `fruit`, `wine` 두 값이다. 기존 세이브에 값이 없으면 QSP 기본값 0을 사용한다. 초기화·강제 이관·기존 저장 파일 쓰기는 하지 않는다. 과거 구매 플래그는 실제 남은 수량이나 사용 여부를 기록하지 않으므로 임의 수량으로 환산하지 않았다. **새 보관 수량은 이번 변경 이후 소형 상품을 구입한 분량부터 집계된다.**

이번 범위는 보관 수량 표시뿐이다. 기존 퀘스트는 이전처럼 구매 플래그를 판정한다. 특수 보관 수량을 실제 식사나 퀘스트 전달에서 소비시키는 새 규칙은 추가하지 않았다.

5. 독립 검토는 3개 본문/10개 edit의 정확한 변경 범위, 다른 본문·원래 주석·기존 대량 구매 처리 보존, 별도 재고와 CSS 단일 규칙을 확인했다. 구조·CRLF·주석 경계·바이트 왕복·정확한 패치 재생·멱등성 및 실제 엔진 대표 경로9개 출고 검사가 PASS였다.
6. WORK 반영 후 검사한 후보 QSP/CSS와 해시가 같고 대표 세이브 해시가 그대로임을 확인했다. 전체 클라이언트 입력 계획의 QSP/CSS 행과 총 바이트만 갱신했다.
