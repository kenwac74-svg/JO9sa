## 사용자 확정

QSP 변경 경고만으로 병합하지 않는다. 오래된 씬 조건 분석 표시는 실제 이미지 적용과 별개이므로 유지한다. 동기화 명령이 들어오면 현재 WORK QSP와 저장한 변경 자료를 대조해 어떤 버전으로 통일할지 먼저 설명하고, 그 기준에서 변경 내용을 QSP·이미지 연결에 병합한다. 동기화는 나중에 별도로 처리한다는 표시가 아니다.

사용자는 이전 WORK 체크 백업에 최신9개 항목의 선택을 우선 덮어쓴 복구안을 승인했다. 원본 등록 기록과 다른 characters/bishop_nerilis (2).png는 현 파일을 보존하고 원본 자동 관리에서 제외해 일반 B컷으로 유지하는 것도 승인했다. 대사 편집실 열기도 요청했다.

## 원인

1. 씬 조건은 HTML에 저장된 정적 분석이다. QSP가 바뀌면 오래된 분석 경고가 뜨는 정상 비교다. 분석60f8bc…는 사용자 지시로 유지했다.
2. 원본 등록기는 content/jo9o_original_cuts를 JO9O로 가는 junction으로만 간주했다. WORK에는 기록 해시와 일치하는 실제 사본 폴더가 있었는데, 이를 다른 경로로 오판했다. 원본 사본238개는 수정 전 기록과 일치했다.
3. WORK 체크 상태는9개만 남아 있었고 기존 등록238개·예약282개가 남아 있었다. 이전 WORK 백업에는1,826개가 있었다. 기존 상태가 줄어든 정확한 원인은 확정하지 않았으며, 파일을 근거로 다른 작업자의 의도를 추정하지 않았다.
4. 현재 목록에서 빠진 reserve 기초 이미지24개도 등록되어 있었다. 목록에 없다는 이유로 기존 보관 체크를 해제로 취급하지 않도록, 등록부와 저장 체크가 모두 있는 항목은 보존했다.

## 호출·입출력·복구

original-cuts.cjs.originalStore(game, originalReal, entries)는 junction이면 실제 대상을 대조하고, 실제 사본 폴더이면 등록 경로·원본 해시를 검증한다. 실제 폴더를 junction으로 교체하거나 내용을 지우지 않는다. 새 등록은 두 물리 경로를 생성하며 rollback은 해당 실행에서 새로 만든 동일 해시 파일만 제거한다. register(..., {dryRun:true})는 같은 검사와 후보 구성만 하고 파일·QSP를 쓰지 않는다. 미등록 수동 B컷이 이미 있으면 덮어쓰지 않고 보존하며, 원본으로 보호된 B컷이 다르면 충돌로 중단한다. 이번 네릴리스 충돌은 사용자 승인으로 분류를 바꿨다.

catalog-sync-version.cjs.plan은 QSP/체크 기록의 해시와 추가·해제 대상을 반환한다. /api/catalog/original-sync-plan은 읽기 전용이다. 동기화 UI가 이 버전을 표시하고, /api/catalog/original-sync에 두 해시를 보낸다. 반영 전 또는 등록 직후 입력 버전이 바뀌면 중단·되돌린다. 게임에 새 상태 변수나 세이브 형식은 추가하지 않았다. API 직접 호출도 기준 해시가 필요하다. 입력 판정 모듈을 제거하려면 server와 catalog_cuts.js의 호출도 함께 제거해야 한다.

변경 파일은 install.json, 복구안과 해시는 recovery-plan.json, 실제 복구·충돌 승인 후 계획은 approved-b-and-preflight.json, 추가 파일은 merge-plan.json, 실제 응답은 merge-result.json, 소스 버전 통일은 source-sync.json에 있다. before/<해시>.gz에 도구·상태·원본 등록의 변경 전 작은 자료를 보존했다. 최종 체크 상태는 status-after.js.gz다. 후속 수정이 있으면 백업 전체를 덮어쓰기 전에 현재 자료와 대조한다. 실제 게임 QSP의 이전 버전은 해당 편집실 이력의 qsp 백업을 사용하며 중복 전체 복사본은 만들지 않았다.
