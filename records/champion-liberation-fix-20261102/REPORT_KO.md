# 콜로세움 해방 결과 누락 수정 — 격리 후보 및 검증

최종 WORK는 상위 담당이 기존 적용기로 반영한 `6bb939464a7370526ced33c6b51fcb4f0b5023b94bbe1d1bd78dba6bec44398d`다. 작업 직전 입력은 `15d02a6a1263970a1c0761483c71dbbf923fd7eee6dc92cb9978c637e7cc8d6e`였으며 이전 경매 수정 등 수동 변경을 보존했다. 이 구현 담당은 격리 후보·검증·임시자료 정리만 수행했고 실제 WORK·Full·원본·개인 저장에 쓰지 않았다. 상위 적용 결과는 한 단계 위 `FINAL_RESULT.json`에 있다.

## 원인과 수정 내용

이전 상금 두 배·결과 페이지 통합은 `interaction_city=1294` 일반 승리에만 있었다. 무패 4→5단계 승리의 `1295` 해방 결과에는 원래 상금 산식, 전용 2쪽 그림 없는 상태, 별도 상금 3쪽이 남았다.

변경은 `interaction_city` 한 로케이션의 1295 블록에만 있다. 원래 단계별 상금을 계산한 다음 최소 50을 보장하고 최종 두 배로 만든다. 기존 `sparks += purse`는 같은 위치에서 한 번만 실행한다. 선언 1쪽과 처형/생존에 따른 기존 1쪽 이미지는 그대로다. 원래 귀환·이탈 문구는 글자 그대로 보존하고 2쪽 끝에 `<br>우승 상금: $<<purse>>`만 붙였다. 별도 `$text[3]` 대입은 제거하여 실제 배열을 2쪽으로 만들었다.

- `moral > fear`: 2쪽 `content/pic/scene/champion_return.png`, 원래 귀환 성장 보상 유지.
- `moral <= fear`: 2쪽 `content/pic/scene/champion_departure.png`, 원래 영구 이탈·인물 제거 유지.
- 후보 본문 기준 1부터 센 위치: 귀환 그림 `interaction_city:1963`, 이탈 그림 `interaction_city:1984`. 선언형 패치 ID와 네 변경 블록 마커는 `CHAMPION_LIBERATION_RESULT_20261102`다.

1294 및 1296~1298 본문, 승리·해방 조건, 난도는 바꾸지 않았다. 새 저장 변수·로케이션·helper가 없다. 이미 정산된 저장을 검색하거나 상금을 소급 추가하는 보정 코드도 없다.

## 실제 엔진 집중 검사

`native.cjs`는 원래 전투 종료·보상·결과·화면 본문을 유지한다. 공개 TC 대표 상태를 진단용으로 주입하며, 원래 `$objsel`의 선택값 입력만 진단 변수로 연결했다. 무관한 도시 무작위 조우만 격리했다. 결과 렌더러나 가격·보상 본문을 빈 검사 지점으로 교체하지 않았다. 개인 세이브는 읽지 않았다.

수정 전 실제 엔진은 상금 65와 전용 2쪽 그림 부재, 실제 배열 3쪽을 저장된 관측값으로 재현했다. 정상 완료한 28판정 중 7개 핵심 판정이 실패했다. 수정 후 Qt DOM을 포함한 407판정·실패 0, 실제 화면 관측 131건을 확인했다. 두 결과 PNG 모두 실제 엔진에서 자연 크기 795×596으로 읽혔다. DOM 결과는 native 판정을 포함하므로 별도로 합산하지 않는다.

- 처형/생존 각각 `moral=11,10,9`와 `fear=10`: 귀환, 동률 이탈, 낮은 도덕성 이탈을 확인했다. 실제 원래 전투 종료의 arena_level 4→5를 거쳐 1295에 진입했고 모두 상금 130·실제 2쪽이었다.
- 1쪽 재표시 → 실제 앞으로 가기 → 2쪽 재표시 → 실제 뒤로 가기 → 1쪽 → 2쪽 → 정상 도시 복귀에서 추가 지급이 없고 각 페이지 그림이 유지됐다.
- 같은 상태로 집 → 목욕34·요리·청소36 → 일반 도시 무기점 대화를 이어 실행했다. 새 행동의 현재 그림이 로딩되고 이전 귀환·이탈 컷이 없으며, 장면 레이어 수가 맞았다.
- 산식의 낮은 입력을 직접 1295에 넣은 분리 경계 검사에서 최소 상금 100을 확인했다. 이 직접 진입은 자연적인 해방 조건 재현으로 계산하지 않는다.
- 일반 승리 1294의 레벨3 상금100·기패배이력 있는 레벨5 상금130과 1쪽, 1296~1298 대련의 상금 미지급을 대표 회귀로 확인했다.

집중 검사는 hero_choice=1 표본이다. 수정 1295 본문에는 주인공별 조건이 없고 해당 분기는 변경하지 않았다. 여주인 삭제 콘텐츠는 검사 대상에서 제외했다. GUI 개인 저장 불러오기, CRC와 저장된 모든 스크립트 복원, 육안 픽셀 배치와 모든 무작위 플레이를 검증한 것은 아니다.

## 검사 입력 오류와 보존 기록

초기 red fixture의 매 표본 공개 상태 재주입이 옛 `$game_ver`까지 다시 넣어 버전 이식 알림이 떴다. 현재 버전을 다시 명시했다. 또 fear 입력으로 공개 TC의 용감함이 처음 공개되는 무관한 알림이 떠 `courage_revealed=2`를 검증 인물 입력에 명시했다. 생산 코드와 알림 처리기는 바꾸지 않았다. 최종 성공/실패 판정에는 정상 완료 마커가 나온 실행만 사용했다.

첫 공식 검사는 예시 `--cache-revision 2` 입력 탓에 현재 코드의 목표 revision3과 맞지 않아 캐시 경로가 실패했다. 그 보고서는 `release-first-report.*`에 보존한다. 현재 후보 `$newloc`에서 목표값을 직접 읽도록 재현 스크립트를 고쳤으며, 검사기나 후보는 바꾸지 않았다.

공식 최종 검사는 **PASS**다. 실제 엔진 9경로, 277개 로케이션 구조·바이트 왕복·줄/주석 경계, 인물 JSON 등록, 정확한 패치 재생과 멱등성, 입력 해시 보존이 통과했다. 현재 코드에서 읽은 cache revision3을 사용했다. `release-report.json`과 `release-report.md` 및 `release-location.json`에 기록했다. 배포본 mirror는 지정하지 않았으므로 Full 일치 검증으로 표현하지 않는다.

## 입력·반환·부작용·유지보수

입력은 기존 `interaction_city=1295`, `slave` 능력치·도덕성/공포·단계, day·slave_type, 처형/생존 fate 상태다. 기존 전투 종료 `выход_из_боя`가 승리·무패 단계 조건에 따라 진입한다. 독립 반환값은 없고 기존 `interaction_result_city`와 `interaction_screen_city`로 진행한다. 페이지 이동과 종료 복귀는 기존 `$objsel` 및 `$return_lock='city_menu_form'`을 사용한다.

부작용은 기존 정산의 `purse`·sparks 증가, 기존 귀환 성장 또는 이탈 인물 제거, 기존 배열의 페이지별 이미지와 2쪽 보상 표시다. 새 영구 상태가 없으므로 저장 구조는 같다. 두 PNG 경로가 없으면 새 결과 그림이 로딩되지 않는다. 패치를 제거하면 원래 65 수준 산식·상금 3쪽·2쪽 전용 그림 누락이 돌아온다.

재현은 새 `JO9_CHAMPION_QA_ROOT`를 G:/Codex/tmp의 작업 폴더로 지정한다. `prepare.cjs`는 입력 해시를 고정하며 `JO9_CHAMPION_INPUT`으로 복원한 작업 직전 QSP를 받을 수 있다. `native.cjs prepare red|green <입력 QSP>` 후 `run red|green`을 실행하고, `release.cjs`로 공식 출고 검사를 실행한다. 엔진 진단은 반드시 직렬로 실행한다.

상위 담당의 실제 적용 완료 후 이 작업이 만든 명시적 G:/Codex/tmp 폴더 세 개를 정리했다. 삭제 전 절대 경로·소유 범위·정상 디렉터리를 확인했고 정션 제거가 외부 표적을 보존하는지 센티널로 확인했다. 4,016개 파일과 정션 연결 180개를 제거했으며 정션 외부 대상은 따라가지 않았다. 고유 생성 파일 2,574,582,296바이트(약 2.40GiB)를 정리했다. 원본과 공유하던 하드링크 925,402,452바이트는 연결만 줄어든 것이므로 회수 용량으로 합산하지 않는다. 임시 루트 잔존은 0개다.

`before.qsp.gz`, patch, 재현 스크립트, red/green/공식 최종·첫 실패 보고서와 로그 66개를 보존했다. 공개 TC에서 생성한 red·green native 관측 SAV는 필요한 두 샘플만 `diagnostic-samples/*.sav.gz`로 압축하고 원시 바이트 복원 해시를 확인했다(합계 6,019,036바이트, 약 5.74MiB). 이 진단 샘플은 저장 상태를 포함하므로 저장소·배포물에 넣지 않는다. 원시 관측 SAV와 진단 상태 사본은 중복 정리했다. 개인 저장은 읽거나 쓰지 않았다.

`cleanup.json`에 보존 위치·복원 해시·정리 용량·잔존 확인을 기록했다. 정리 전후 WORK `6bb939...`, Full `f87363...`, 원본 `26e15aaf...`의 전체 SHA256이 모두 일치했다. 정리 중 엔진은 실행하지 않았다. ZIP·커밋·푸시는 하지 않았다.
