# 경로 이관 semantic 경계 추가 감사

결론: 원본 이관에서 확인된 추가 오류는 **bg 디렉터리 접두사 280곳 / 44개 로케이션**이며, 그 외 파일명 접미사 오치환은 0건이다. CSS·jo9_traits_view.js·menu_icon.json의 추가 오치환도 0건이다.

## 원인

`content/pic/bg.png`를 UI 파일로 옮기는 맵에 확장자 없는 `content/pic/bg`도 별칭으로 들어갔다. 정규식은 `대안1|대안2|...|마지막대안 + 경계` 형태여서 경계가 전체 대안에 적용되지 않았다. 따라서 폴더 `content/pic/bg/`와 `content\pic\bg\`도 파일 stem으로 매치되어 실제 존재하지 않는 `content/pic/ui/frames/legacy/bg/`로 바뀌었다.

처음 독립 리뷰는 허용된 경로 치환 및 실행 코드 불변을 검사했지만 같은 파일명 경계 계약을 재현해 파일/폴더 의미 오류를 발견하지 못했다. 이번 semantic 감사 결과가 그 부분을 보완한다.

## 전수 확인 범위

- 원본 1f43 QSP와 역사적 UI 경로 패치 81개 본문을 대조했다.
- 정확 파일 맵 87개와 확장자 없는 stem 모두를 검사했다.
- 수정 정규식은 대안 전체를 `(?:...)`로 묶고, 전체 그룹 뒤에 `(?![\\/])`와 기존 경계를 적용했다.
- 기존 패턴에서 매치되지만 이 전역 경계가 거부하는 경우는 정확히 280곳이다. 모두 bg 폴더 구분자이며 underscore·글자·다른 확장자 등의 추가 접미사 오류는 0건이다.
- 280곳 중 interior_change 전환 registry 관련 219곳이 포함된다. 새 컷 등록이나 저장 선택 번호를 수정하지 않고 원래 폴더 접두사를 복구해야 한다.
- 확장자 없는 `.../ui/frames/legacy/bg` 바로 뒤가 quote/end/HTML 경계인 참조는 0건이다. 후속 코드가 slash를 붙이는 별도 디렉터리 공급자를 놓친 경우도 발견되지 않았다.
- CSS·JS·JSON 세 파일도 원본 전체 문자열을 같은 경계 기준으로 재검사해 추가 오치환 0건을 확인했다.

## 복구 범위와 최종 후보

`content/pic/ui/frames/legacy/bg/` 또는 마지막 구분자가 backslash인 잘못된 **디렉터리 접두사만** `content/pic/bg/`로 복구한다. 실제 UI 파일 `.../frames/legacy/bg.png`와 일반 canonical UI 경로는 바꾸지 않는다. 기존 `content/pic/bg` 폴더와 원본 이미지들이 남아 있어 파일 복제나 새 UI 이미지 폴더 생성은 필요 없다.

최종 후보 `7c366e1ae35a5922e32052847bceb28737ddab32c3861b19bbefd7661b45c2b7`를 직접 읽어 잘못된 bg 디렉터리 접두사 잔존 **0건**을 확인했다. 이는 이 후보의 전체 변경이 bg 복구뿐이라는 뜻은 아니다. 병행된 전투 효과 격리·폰트 작업은 별도 검토와 native 검사의 범위다.

기존에도 없었던 정적 이미지 경로 `content/pic/bg/dungeon.png`는 구분해 기록했다. 이 경로 복구가 새 이미지 파일을 만들어 주지는 않으며 이번 이관이 만든 결함으로 세지 않았다.

## 기록과 재발 방지

- `semantic-path-regression-audit.json/cjs`: 오염된 접두사, 원래 경로, 실제 존재 여부, 복구 목록.
- `prefix-suffix-boundary-audit.json/cjs`: 원본 81개 본문·비QSP 세 파일의 전역 경계 재계산. 280개 이외 오류 0건.
- `prepare-migration-corrected.cjs`: 역사적 스크립트를 보존한 별도 교정 사본. 실행하지 않았다. 기존 입력 해시 assert가 유지된다.
- `migration-corrected-regex-selftest.json`: 정규식 생성 부분만 실행한 회귀 검사 11개 PASS. 폴더·동적 경로·파일 접미사를 보존하고 계획된 실제 UI 파일만 옮기는 조건을 확인했다.

이 감사는 운영 파일·이미지·세이브·배포 폴더를 수정하지 않았다. 보고서/조회 스크립트만 작성했다. 실제 플레이나 엔진 실행을 대신하는 검증이라고 주장하지 않는다.
