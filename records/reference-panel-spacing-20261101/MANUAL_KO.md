# 유지보수·복구

추가 로케이션 jo9_reference_panel은 정보창의 HTML을 반환하는 출력 전용 함수다. 첫 인수는 소개 HTML, 두 번째는 선택적인 태도 HTML, 세 번째는 기존 접두 HTML이다. 호출은31곳이며 coverage.json에 로케이션과 인수를 기록했다. helper 내부 변수4개는 local이고 새 저장 변수·상태판정·보상·행동력 변경은 없다. 기존275개 로케이션 순서는 유지하며 함수1개를 뒤에 추가한다.

소개와 태도의 맨 앞 공백/NBSP/BR만 로컬 사본에서 정리하고 기존 HTML 내용을 반환한다. 태도가 있으면 기존 방식의 줄 구분 뒤에 소개가 이어진다. 문자열 앞의 실제내용을 감싼 font 태그나 본문 중간 BR은 제거하지 않는다. QSP 정의부와 기존 SAV에 저장된 설명은 직접 수정하지 않는다.

CSS는 #side_panel_text.jo9-reference-panel만 top203px/height585px를 적용하고 내부 설명의 기존20px 강제를 유지한다. 일반 #side_panel_main/#side_panel_text나 회계표/소문/인물속성표 CSS는 변경하지 않는다. 배치·폰트는 CSS, 고정 제목 삭제·출력 내용은 QSP에 둔다. 이 QSP와 CSS는 함께 적용해야 한다. 함수만 제거하면31개 호출이 실패하며 CSS만 제거하면 본문은 이전 위치로 돌아간다.

패치는 mods/2026-11-01_reference_panel_spacing.json에 원문/수정문/count/전후SHA 및 추가 함수가 있다. 배포·커밋 없이 tools/apply_mods.ps1로 이번 패치만 WORK에 적용했다. prepared.json의 외부 gzip 백업은 QSP와 기존 CSS를 보존하며 압축 해제 결과의 바이트 일치를 확인했다. 이후 사용자 편집이 있으면 오래된 전체 백업을 덮어쓰지 말고 해당 패치 조각만 역방향 대조한다. 추가 함수는 호출 제거 뒤에만 삭제할 수 있다.

재현 스크립트 build.cjs는 출력 폴더, 기준 QSP, 기준 base.css를 순서대로 선택 인수로 받는다. 생략하면 현재 WORK를 기준으로 하기 때문에 이미 적용된 WORK에는 재적용용으로 사용하지 않는다. 재현 시 외부 gzip을 작업별 임시 폴더에 풀고 세 인수를 명시한다. probe.cjs는 baseline/green, QSP 경로를 받아 실제 설치 엔진의 정보창을 검사한다. green 모드는 복사한 격리 CSS만 사용한다. 공식 출고 검사는 release-report.json의 입력과 도구 인수를 따른다.

사람이 확인할 항목은 게임 재실행 후 엘리자베스·바이너·상류신사 모임을 열어 제목이 사라지고 첫 줄이 같은 높이에 있는지, 이름·부제와 긴 설명의 마지막 줄이 정상인지 보는 것이다. 세이브를 새로 만들거나 이전 설명을 삭제할 필요는 없다.
