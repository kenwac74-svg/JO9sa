# 전투 후 선택 UI 제안

표시용 식별자: `BATTLE_FATE_CHOICE_20261028`.

이 폴더의 세 파일은 통합 전 제안본이다. 게임·WORK·저장소·세이브·기존 그림은 변경하지 않았다. 콜백, 처형 판정, 보상, 이미지 교체, 중복 실행 방지는 구현하지 않는다.

`fate-ui.css`는 최신 `base.css` 뒤에 읽는다. 결과 root에 `jo9-battle-fate-active` 클래스를 붙이는 동안에만 기존 로그 높이를 줄이고 두 행을 예약한다. 클래스가 없으면 기존 로그 규칙을 유지하고 새 선택 영역을 숨긴다. 선택 후 결과 문구와 계속 링크를 보여줄 때도 같은 클래스를 유지하면 패널 높이가 바뀌지 않는다.

| 요소 | 좌표와 크기 | 하단 |
|---|---|---|
| 기존 로그 | left258 / top646 / 763×150 | 796 |
| 선택 중 로그 | left258 / top646 / 763×84 | 730 |
| 빈 간격 | 6px | 736 |
| 선택 영역 | left258 / top736 / 763×60 | 796 |
| 첫째 행 | 영역 내부 top0 / 높이28 | 764 |
| 둘째 행 | 영역 내부 top32 / 높이28 | 796 |

로그는 원래처럼 세로 스크롤한다. 프레임·좌우 초상·중앙 그림·결과 제목·좌우 기존 아이콘의 좌표는 이 CSS에서 바꾸지 않는다. 새 선택 두 행은 중앙 결과 로그의 기존 사각형 안에서만 공간을 나누므로 아래로 화면을 밀지 않는다. 링크 문구는 QSP가 출력하며 CSS로 문구를 만들지 않는다.

통합할 구조의 예시는 다음과 같다. `EXEC`의 구체적인 호출과 대상 판정은 root 구현에서 정한다.

```html
<!-- 기존 결과 root에 jo9-battle-fate-active 추가 -->
<div class="jo9-battle-fate-choices">
  <div class="jo9-battle-fate-row">
    <a class="jo9-battle-fate-execute" href="EXEC: [root가 정한 확정 처리]">처형</a>
  </div>
  <div class="jo9-battle-fate-row">
    <span class="is-disabled" aria-disabled="true">살려주기</span>
  </div>
</div>
```

일반 안개에서는 처형만 활성화하고 살려주기는 링크 없는 `span`으로 출력한다. 일반 투기장 인간 여성은 두 행을 각각 활성 링크로 출력한다. 특수 전투 보존과 대상 판정은 QSP가 담당한다. 이 CSS는 전투 종류를 추정하거나 새 제한을 추가하지 않는다.

확정 뒤에는 첫째 행을 `span.jo9-battle-fate-message` 결과 문구로, 둘째 행을 계속 링크로 바꾸어 같은 두 행을 사용한다. `is-locked`는 확정 처리 중 선택 영역의 마우스 입력을 막는 표시 보조다. 계속 링크를 출력할 때는 선택 링크를 제거하고 `is-locked`도 제거하여 계속 링크가 눌리게 한다. CSS만으로 키보드 호출이나 이미 큐에 들어간 명령까지 막을 수 없으므로 QSP의 확정 상태 guard가 필요하다. 기존 `выход_из_боя` 한 번 호출과 잠금 해제 시점은 root가 처리한다. 이 파일에는 그 콜백이 없다.

`execution.svg`는 기존 코드형 SVG 베기 표현을 참고한 795×596 투명 자산이다. 가느다란 짙은 적색 궤적과 작은 적색 흔적만 사용한다. 별무늬·문자·배경·신체 묘사·애니메이션은 없다. 무기별 판정이나 칼/찌르기/둔기 분기를 담은 자산은 아니며, 통합에서 선택하는 공통 최후 일격 표시다.

```html
<!-- 기존 #jo9_battle_fx_layer의 직접 자식으로 넣는다. -->
<div class="jo9-battle-execution" aria-hidden="true">
  <img src="[통합할 경로]/execution.svg" alt="">
</div>
```

효과 wrapper는 left242 / top0 / 795×596으로 기존 중앙 적 그림과 맞춘다. 기존 1280×800 FX 층 안에서 자신의 사각형 밖을 자르고 클릭을 받지 않는다. 효과와 이미지가 일반 문서 흐름에 들어가지 않으며, 양옆 버튼과 아래 로그 영역을 덮지 않는다.

효과의 기본 상태는 `visibility:hidden`이다. 통합 시 wrapper 자체를 잠깐 `visible`로 바꾸고 정해진 수명 뒤 `hidden`으로 되돌린다. 확대·축소·페이드·opacity 애니메이션·CSS keyframes는 사용하지 않는다. 현재 `jo9_battle_log.js`의 `play()`는 IIFE 내부 함수이며 자동으로 이 새 클래스를 재생하지 않는다. root가 새 wrapper를 재생 대상으로 연결해야 한다. 기존 타이머의 `node.parentNode === layer` 확인과 맞추기 위해 wrapper를 FX 층의 직접 자식으로 유지한다. 이전 root의 타이머가 새 화면을 건드리지 않도록 하는 root 동일성 확인도 유지한다.

이 CSS는 적 그림 자체의 밝기를 바꾸지 않는다. 어둡게 처리하는 추가 표시가 필요하면 root 통합 범위에서 별도로 정한다. CSS를 제거하거나 root 상태 클래스를 붙이지 않으면 두 행 배치가 적용되지 않는다. SVG 경로가 빠지면 효과 그림만 누락되므로 통합 검사에서 실제 경로 로드를 확인해야 한다.

확인 범위는 CSS 좌표 계산, 정적 SVG/XML 구조와 금지한 애니메이션 요소 부재다. 실제 QSP 확정 흐름, 링크 클릭, 로그 스크롤, 표시 수명, 연속 재진입, QtWebKit 재도색과 사용자 화면은 통합 후 검사해야 한다.
