# 대사 편집 섹션 UI 통합 — 2026-11-15

사용자 요청에 따라 대사 편집 섹션만 다듬었다. 화면 상단의 ‘대사 편집’ 제목은 한 번만 표시하고, 단일 도구 선택 버튼과 내부 ‘JO9 대사 편집실’ 제목·소개를 통합 화면에서 숨겼다. 상단 문구는 실제 작업 안내로 바꿨다.

파란 바탕·입력창·버튼·테두리를 기존 클로드 편집기의 회색·금색 팔레트에 맞췄다. 파일 입력 버튼과 포커스 표시도 맞췄다. 바깥 프레임 테두리를 없애고 내용 영역 높이를 화면에 맞춰 조정했다. 대사 편집 중 외부 바닥글을 숨겨 이중 바깥 스크롤을 줄였다. 다른 메뉴로 이동하면 원래 바닥글과 레이아웃으로 돌아간다. 내부 도구의 작업 탭·검색·파일 불러오기·검토·반영·하단 작업 영역은 유지한다.

## 구현·호출

- `tools/modding-hub/integration.mjs`: 대사 도구에만 `?workspace=1`을 전달한다. 중복 도구 버튼 제거, 대사 페이지 클래스·프레임 높이 조정. 별도 창 링크는 원래 주소로 연다.
- `tools/modding-hub/integration.css`: 대사 섹션에만 프레임·바깥 여백·바닥글 표시 변경.
- `tools/text-workshop/index.html`: workspace 질의가 있을 때만 최상위 `workspace-embedded` 클래스를 붙인다.
- `tools/text-workshop/workshop.css`: 기존 색을 동일한 기본값을 가진 CSS 변수로 표현한다. 독립 화면의 기본 색은 그대로다.
- `tools/text-workshop/workshop-shell.css`: 통합 화면 클래스가 있을 때만 호스트 색과 입력·작업 탭 스타일을 적용한다. 실제 게임 UI 미리보기의 전용 규칙은 보존하고 그 영역의 색 변수는 원래 값으로 복구한다.
- `tools/text-workshop/server.cjs`: 새 CSS 파일의 읽기 경로만 추가. 검색·편집·저장 API와 승인 로직은 수정하지 않았다.

기존 실행기로 WORK/modtools의 도구 파일을 동기화했다. 게임 QSP·JSON·이미지·SAV·배포 ZIP은 수정하지 않았다. 열린 앱을 강제로 닫거나 편집 데이터를 새로 불러오지는 않았다. 사용자가 편집 중인 내용을 저장한 뒤 새로고침하거나 앱을 다시 열면 새 UI를 사용한다. 기존 앱의 실행 기록은 디스크에서 제공하는 새 클라이언트 자산 빌드와 맞췄다.

## 확인과 한계

JS 구문 확인. CSS 변수의 기본값을 원래 색으로 되돌린 결과가 이전 CSS와 정확히 같음을 확인했다. 게임 미리보기 전용 CSS 동일, 저장소/설치 도구 3개 파일 동일, WORK QSP는 매력 수정 후 해시 f2bb7224… 그대로다.

첨부와 같은 데스크톱 배치(1664×1050)에서 제목 하나, 안쪽 H1 표시 0, 배경 rgb(19,21,23), 프레임 테두리 0, 하단 1032px/높이 830px을 확인했다. 임시 브라우저 크기는 확인 후 원래대로 복구했다. 원문 입력은 가능했다. 브라우저 자동 제어가 프레임의 클릭·키보드 포커스 대상을 찾지 못해 검색 실행·탭 전환은 이번에 추가 검증하지 못했다. 해당 검색/편집 JS는 변경하지 않았고 게임 반영 버튼도 누르지 않았다. 불필요한 게임 엔진·저장·배포 재검사는 하지 않았다.

`verification.json`, `change.json`, `dialogue-after.jpg`에 근거를 남겼다. 원래 파일은 `*.before.gz`, 재현 스크립트는 `change_ui.py`다. 이후 변경을 덮어쓰지 말고 이 작업 블록만 대조해 복구한다. 재생성 가능한 로컬 편집 사본은 정리했다. 커밋·푸시는 하지 않았다.
