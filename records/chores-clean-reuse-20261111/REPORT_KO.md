# 개인실 집안일 — 기존 ‘청소한다’ 컷신 재사용 확인

2026-11-11 사용자 지시: 집안일 자동 실행에 기존 컷신이 있으므로 ‘청소한다’ 명령과 같은 것을 쓴다.

## 결론

현재 WORK에는 이미 같은 조회와 출력이 연결되어 있다. 앞서 `scene/home/chores*` 신규 파일이 없다는 이유로 집안일 그림을 추가 제작·연결해야 한다고 본 제안은 철회한다. 기존 청소 그림을 유지하며 QSP·이미지는 수정하지 않았다. 신규 이미지 제작이나 추가 연결은 남은 작업이 아니다.

## 현재 코드 근거

행 번호는 현재 QSP의 해당 로케이션 본문을 해독한 뒤의 1부터 시작하는 번호다.

- 수동 노예·조수 ‘청소한다’: `interaction:1577`의 `display_pic('dynslave', 'clean', 'girls/normal_scenes/')`. 1589~1590에서 실제 노예·조수 역할로 치환한다. 주인공 직접 청소(명령36)는 별도 `scene/master_clean`이며 이번 기준이 아니다.
- 개인실 자동 청소: `end_day_screen:683/697/711/725`의 room1~4 자동 청소 분기에서 각각 691/705/719/733행의 같은 `clean` 조회를 호출한다. 요리는 기존 `cook` 조회를 유지한다.
- 개인실 별도 업무 보고: 같은 로케이션 52/61/70/79행도 해당 roomN의 `clean` 조회를 기본 그림으로 사용한다. `jo9_room_duty:705~743`은 별도 외근 결과 그림이 있을 때만 경로를 바꾸며 집안일용 그림을 덮어쓰지 않는다. 일반 집안일은 기존 자동 요리·청소 출력으로 진행하므로 새 일반 보고를 추가하지 않는다.
- `display_pic`은 room1~4를 지원하며 해당 캐릭터 번호의 전용 `<번호>_clean` 풀을 우선 조회하고, 고유 태그·외형·공용 풀의 기존 선택 규칙을 사용한다. 다른 역할의 노예를 덮어쓰지 않는다.
- 자동 출력 `end_day_screen:1753`과 수동 출력 `interaction_screen:19`는 모두 `interior_change('jo9_html', ...)`을 사용한다. `jo9_path`의 현재 이미지 전환·조건 설정도 유지한다.

## 검증과 한계

`audit.cjs`로 현재 WORK와 추적 QSP 해시 일치, 개인실 4개 자동 청소 분기·조회 함수 지원, 기존 보고의 그림 유지, 공용/외형 청소 PNG119개와 번호 전용 PNG149개의 파일 실재를 확인했다. SHA-256은 `7501bc7726ac97837ed1f2c1f19f91d409596a8a6708df1b79abf8c3d3180fce`다. 상세는 `verification.json`.

읽기 전용 코드·경로 확인이다. 이번 작업에서 게임 화면이나 엔진 진단을 실행하지 않았다. 실제 화면 확인은 일반 게임에서 개인실 집안일 지정 후 자동 청소가 발생한 날의 마무리 장면에서 해당 인물의 기존 청소 컷이 나오는지를 보면 된다. 조수 조용히 하기 설정과 실제 청소 발생 여부에 따라 장면이 생략될 수 있다.

게임 QSP·이미지·설정·세이브·Full·음원·커밋·푸시 변경 없음. 작업 파일은 이 보고서·확인 JSON·재현 가능한 읽기 전용 감사 스크립트뿐이며 진단 QSP나 복제 게임은 만들지 않았다.
