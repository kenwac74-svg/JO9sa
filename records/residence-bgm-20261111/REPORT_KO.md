# 거주지·지역 명성 BGM 순차 재생 — 2026-11-11

사용자가 승인한 범위를 WORK와 추적 소스에 반영했다. 방문한 지역 때문에 도시 재생목록을 바꾸지 않고, 기본곡 뒤에 기존 지역 명성 조건을 넘긴 곡을 이어 재생한다. 귀족·평판·집 기분곡·전투·경주·특수 이벤트·게임오버의 우선순위를 보존한다.

## 재생 규칙

1. 귀족 신분 또는 `brand_reputation>=5`이면 기존 귀족곡이 기본이다. 그 외에는 아래 거주지곡을 기본으로 한다.
2. `taurus`, `serpis`, `kamira`, `korvus`, `otchuzhdenie`, `RedLight`, `centralkvartal`의 명성4 이상인 지역곡을 이 순서로 붙인다. 일반 상한5의70%를 **초과**하는 정수값이다. 네 가문에서 쓰는 값6도 조건을 충족하며 상한을6으로 다시 계산하지 않는다.
3. 같은 파일 경로는 한 번만 넣는다. 서로 다른 추가곡3개라면 기본곡1+추가곡3=총4곡이다. 전체 목록이 끝나면 기본곡부터 반복한다. 한 곡뿐이면 그 곡을 계속 반복한다.
4. 빈민가·백색 도시에는 독립 지역 명성값을 만들지 않았다. 거주지 기본곡으로만 쓰고 명성 추가 대상에서는 제외했다. 전역 평판을 두 지역의 독립 명성처럼 사용하지 않는다.
5. 방문·화면 재표시·설정창으로 같은 목록을 다시 읽어도 현재 곡과 마감 시각을 유지한다. 거주지/기본곡/명성 충족 목록이 실제로 바뀌면 기본곡부터 새 목록을 시작한다.
6. 집 기분곡·전투·경주·이벤트곡은 재생목록을 중단한다. 도시로 돌아오면 중단했던 목록 곡을 처음부터 재생한다(네이티브 재생 위치 이동 기능을 추가하지 않았다). 게임오버 곡은 기존처럼 게임오버 화면에서만 재생한다.

## 구조·입출력·부작용

- `jo9_residence_bgm`: 기존 `$city_sounds`가 거주지·신분·평판·지역 명성으로 목록을 구성한다. `$play_music`는 목록/직접 이벤트/기존 곡을 구분한다. 네이티브 PLAY는 그대로 사용하고 이전 BGM 경로만 CLOSE한다. 효과음을 자르는 CLOSE ALL을 추가하지 않았다.
- `city`/`add`/`defs`: 거주지·기존 명성·곡 길이 표를 입력으로 경로와 길이 배열을 만든다. 숫자 반환값은 없으며 게임 능력치를 바꾸지 않는다.
- `play`/`advance`/`token`: 순번·현재 음악·중복 콜백 방지 토큰을 갱신한다. `advance`는 현재 토큰·목록 모드·음량·게임오버 상태가 모두 맞을 때만 작동한다.
- `event`/`eventplay`/`pause`: 기존 이벤트 곡의 경로와 원래 음량 채널을 추적하고 도시 시계를 중단한다. `reset`/`load`는 옛 시계를 무효화하고 현재 동적 함수 정의를 읽는다. D21의 캐릭터/이미지 세이브 이관 도구를 실행하는 기능은 아니다.
- `content/js/jo9_bgm_clock.js`: ES5 코드. Date.now와 브라우저 sessionStorage로 마감 시각을 보존하고, 화면에 남아 있는 여러 seed 중 마지막 것만 사용한다. 검증된 토큰만 EXEC로 전달한다. 메시지창이 열려 있으면 전환을 기다린다.
- `jo9_hotkeys.js`: 기존 키보드 코드를 유지하고 시계 모듈 로더만 뒤에 추가했다. 곡을 다시 선택하지 않는 상태 화면에서도 시계가 이어진다.
- QSP의 일반 저장 상태에 소량의 목록/순번/토큰 변수가 추가되고, 브라우저 세션에 음악 시계가 저장된다. 캐릭터/능력치/거래/이미지 경로와 세이브 파일 형식을 이관하지 않는다. 로드 시 재생 상태를 재구성한다.
- 곡별 길이·해시는 [리소스 명세](../../assets/bgm/residence-playlist-20261111.json)에 있다. 음원을 교체하면 ffprobe로 길이와 해시를 다시 측정하고 QSP 정의·명세를 함께 갱신해야 한다.
- 시계 파일/공통 로더를 제거하면 자동 곡 전환이 멈춰 현재 곡만 반복할 수 있다. 새 location을 지우려면 호출 패치도 함께 되돌려야 한다. 단독 삭제하지 않는다.
