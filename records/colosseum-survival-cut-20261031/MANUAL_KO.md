# 콜로세움 노예 패배 후 생존 컷신

사용자 제공 “콜로세움의 마지막 행진_795x596.png”를 기존 content/pic/scene/coldef3.png에 바이트 그대로 등록했다. 795×596 PNG이며 원본은 WORK/modworkpic에 그대로 보존했다. WORK에는 해당 주소가 없었고 Full은 이전 kikudef 공통 컷의 임시 사본을 사용 중이었다. Full의 옛 그림만 외부 backup에 보존하고 WORK·Full·resources/new를 같은 새 PNG로 맞췄다. 생성형 편집·크롭·재인코딩은 하지 않았다.

기존 QSP는 interaction_city1293에서 이 경로를 이미 사용한다. 정식 경기 패배 후 생존 분기는 돌아가기 Start에서 선택되어 후송 설명과 함께 표시된다. QSP를 수정하지 않았으므로 코드 출고 패치나 세이브 형식 변경이 없다. 세이브7개와 사망/처형/연습 컷·두 QSP 해시를 보존했다. 원본 함수의 효과·확률·생존·후송 대사는 그대로다.

실제 엔진에서 도주·기절·치명상에서 생존한3경로를 기존 전투 복귀부터 실행했다. 충분한 체력/기질을 가진 시험 인물로 분기를 고정했고, 실제1293선택·노예보유·PNG 로딩·자연크기 및 표시크기795×596·하단 설명 범위를 확인했다. 이는 격리 진단 실행이며 사용자의 마우스 수동 플레이나 전체 게임 검증은 아니다. 초기 시나리오 숫자 이름과 연습경기의 역할초기화를 정식경기에도 요구한 검사 오류는 진단에서만 고쳤다. 초기 실패를 성공으로 보고하지 않았고 실제 게임 코드를 바꾸지 않았다.

기존 QSP 바이트가 그대로임을 확인하고 구조 검사·진단 QSP 줄바꿈 검사도 실행했다. 이번에는 QSP 기능 수정이 없으므로 새 코드 출고9경로 검사를 했다고 주장하지 않는다. source/targets/prior의 해시와 복구PNG는 verification.json에 있다. 목록·등장 조건·HTTP 확인은 하위 catalog 기록이다.

Full의 coldef3 임시 원화 항목을 해소하여 남은 대기 그림은 coldef1·coldef2 두 개다. manifest·input-plan·최종 설명·릴리즈 노트·간단 TC도 실제 새 파일에 맞췄다. 제거하면 생존 결과의 그림이 누락되며, 옛 Full 그림 복원은 prior.backup을 이용한다. ZIP·커밋·푸시는 하지 않았다.
