# 마스터 편집 CM 누락 수정 — 2026-11-15

원인: 기존 화면은 마스터별 `$master_version_stats`에 명시된 정수만 표시했다. 실제 WORK의 CM은 `init_game`에서 `jo9_cruel_mercy = 0`, `jo9_cruel_mercy_half = 0`으로 공통 초기화되어 프리셋 목록에 나타나지 않았다.

마스터 편집 → 능력치·특성 첫 부분에 CM(Cruel & Mercy)을 항상 표시한다. 공통 초기값을 읽고 프리셋에 별도 지정된 값이 있으면 우선한다. 노예의 마스터 전환용 능력치에서도 같은 항목을 제공한다. 툴팁에 음수 Cruel/양수 Mercy와 실제 변수 관계를 표시한다.

입력은 0.5 단위다. 기존 표현 `whole + half/2`를 사용하며 −0.5는 0/−1, −3.5는 −3/−1, +3.5는 3/+1로 기록한다. 사용자가 변경했을 때만 해당 마스터의 시작 코드에 두 기존 변수 대입을 추가/수정한다. 다른 명령·주석·장비·시작 조건과 공통 초기화는 보존한다. 새 게임 변수·게임 산식·개인 세이브를 추가/수정하지 않았다.

`master_editor.py.native_defaults`가 공통 초기값을 반환하고 `read`/노예 장식 응답의 `nativeDefaults`로 제공한다. `studio-role.mjs.cmValue/patchCm`이 표시와 정수·반점 변환을 맡고 `studio-view.mjs` 입력 이벤트가 기존 변경 미리보기/저장 흐름에 연결한다. CM 두 필드를 일반 정수 목록에 중복 표시하지 않는다. 원본 코드 직접 편집 후에도 CM 표시를 갱신한다.

표시 누락과 공통값 응답 누락을 먼저 재현했다. JS 7건, Python 12건(기존 마스터 저장·복제 회귀 포함), 수정 JS 구문 통과. 격리 QSP에서 CM 시작 값 저장·다른 마스터와 공통 코드 보존을 확인했다. 실제 브라우저에서 밀로드 CM 0 표시, −0.5 입력 시 0/−1 코드 연결·변경 미리보기를 확인한 후 되돌렸다. 운영 WORK QSP·인물·세이브에는 시험 저장하지 않았다. 전체 게임 출고 검사는 반복하지 않았다.

열려 있던 화면은 편집 내용을 저장한 후 새로고침한다. 사용자 작업 탭은 자동 새로고침하지 않았다. 복구는 `changes.diff`와 수정 전 `*.before.gz`를 대조하여 해당 블록만 되돌린다. 후속 사용자 수정을 통째로 덮어쓰지 않는다. 커밋·푸시·배포 갱신은 하지 않았다.
