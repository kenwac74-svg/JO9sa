신규 특성 편집기 링크 색상 수정 — 2026-10-21

원인: #under_cheats의 금색이 내부 <a>에 상속되지 않아 브라우저 기본 파란색이 표시되었다. 기존 편집기는 글자를 컨테이너에 출력하고 이미지에만 링크를 걸어 이 문제가 덜 드러났다.

적용: Work/game/css/base.css와 저장소 assets/css-2.4/base.css의 SLAVE_EDITOR_LAYOUT 블록에 EDITOR_LINK_COLOR 규칙을 추가했다. 두 선택자는 .jo9-slave-editor #under_cheats > a 및 .jo9-editor-nav #under_cheats > a이며 선언은 color:inherit 하나다. 기존 컨테이너의 #FFD700을 사용한다. CSS 매니페스트의 해시/업데이트 이력도 갱신했다.

입력과 출력: 기존 QSP가 출력한 편집기 HTML과 부모 글자색을 받아 링크 글자색만 금색으로 표시한다. 함수/새 입력/반환값/세이브 키는 없다.
호출·의존: menu_form=2107의 두 열은 jo9-slave-editor, 하단은 jo9-editor-nav를 이미 사용한다. jo9_traits editor가 토글 20개를 출력한다. 2100 진입 링크도 기존 jo9-editor-nav를 통해 적용된다. 기존 2101~2106/2110의 그림 링크는 그림 픽셀/좌표/크기를 바꾸지 않는다.
부수효과: 일반·hover·focus 링크의 글자색을 부모 금색으로 유지한다. 회색 안내/일반 화면 링크/특성 효과/게임 수치/클릭 목적지/배치는 변경하지 않는다. 방문 링크 색도 별도로 지정하지 않고 같은 author 규칙을 사용한다.
제거: EDITOR_LINK_COLOR 시작~끝 주석 사이만 제거하면 이전 CSS 바이트로 복원된다. 이 규칙을 제거해도 기능은 유지되지만 파란 링크 문제가 돌아온다. QSP 래퍼나 특성 코드를 삭제할 필요는 없다.

검증: 현재 Work QSP의 HTML 링크 리터럴을 추출한 격리 Headless Edge 화면에서 20개 토글+선택/이동/진입 5개의 수정 전 파랑을 재현했다. CSS 한 규칙 적용 뒤 25개가 금색이 되었다. 실제 설치 CSS를 다시 읽어 일반/hover/focus 색상, 목적지와 위치·크기 유지, 회색/비편집기 링크 미변경을 확인했다. 수정 규칙은 브라우저 CSSOM에서 정상 파싱되었고 색상 선언만 존재한다. 고정 문구 CSS 검사도 저장소/Work 모두 통과했다.
검증 한계: 격리된 HTML/CSS 검사이며 실제 네이티브 게임 클라이언트를 조작해 확인한 것은 아니다. 방문 기록의 실제 색상은 브라우저 개인정보 보호로 computedStyle에서 구분할 수 없으므로 별도 cascade 확인에 한한다. QSP는 변경하지 않았으며 이번 수정에서 QSP 출고/엔진 검사는 수행 대상이 아니다.
적용 확인: 실행 중인 게임의 CSS 캐시를 갱신하려면 게임을 종료하고 다시 실행한다. 기존 세이브를 수정할 필요는 없다.
