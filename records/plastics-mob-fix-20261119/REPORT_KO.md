# 성형 수술 후보와 조수 ID 수정

WORK의 기존 `slave_index.json`과 4000–4727 모브 번호를 유지했다. 성형 수술은 `jo9_mob_pool`의 기존 범위와 신규 번호를 이용하고, 등록 전신과 `seed_age` 및 파일명 머리색이 일치하는 일반 모브만 보여 준다. 앞·뒤 이동은 현재 ID에서 조건을 만족하는 다음·이전 ID로 이동해 번호 사이의 공백을 건너뛴다. 후보가 없으면 비용을 처리하지 않고 머리색 선택으로 돌아간다.

`jo9_plastics`의 `find`에는 외형 분류, 머리색, 기준 ID, 방향을 전달한다. 방향 0은 기준 ID의 유효성을 검사하며, 맞는 후보가 없으면 0을 반환한다. `jo9_mob_pool`의 선택 인수 −1은 풀 크기 질의다. 기존 무작위 호출과 1부터 시작하는 슬롯 조회는 동일하다.

확정은 유효성을 다시 확인한 뒤 선택한 대상의 전신, 초상화 3개, 외형 번호를 바꾼다. 기존 수술 비용과 행동력·회복 처리는 원래 `plastics_confirm_procedure`를 통해 적용된다. 구세이브 로드에서 저장된 확정 코드를 교체하고, 저장 위치가 시술 미리보기이면 현재 후보를 다시 그린다. 별도 세이브 변환기는 필요 없다. 예전 버그로 이미 바뀐 일반 노예 ID의 원래 값은 이 변경으로 복원하지 않는다.

## 검증

- Windows 게임 엔진에서 9개 머리색과 3개 외형 분류를 순회해 신규 728종의 순서와 필터, 탐색 경계, 조수 확정을 확인했다.
- QSP 5.8 격리 테스트에서 실제 앞·뒤 화살표로 번호 구간을 건너는 동작, 구버전 확인 코드가 든 세이브 로드, 노예와 조수 각각의 확정, 유효하지 않은 후보에 대한 무과금을 확인했다.
- 영입·능력치 여러 항목을 가진 샘플 세이브 3개의 변수 슬롯을 점검했다. `meta_type`은 기존 할당을 사용하는 지역 변수다. 게임의 무작위 생성에 전달되던 바깥 값은 보존된다.
- 신규 모브의 전신과 초상화 참조 2,912건의 대상 파일을 확인했다. 두 QSP에 독립 적용 후 기존 패치 도구의 DryRun 해시를 맞췄고, 역적용은 각 원본과 바이트 단위로 일치했다.

## 적용 및 복구

`plastics`, `$objsel`, `#dynamic`, `jo9_mob_pool`, `$ongload`, 새 `jo9_plastics` 위치가 변경 범위다. 복구 시 `work-patch.json`의 변경을 역적용하고 추가한 `jo9_plastics` 위치를 제거한다. 후속 작업이 있는 경우 전체 QSP를 되돌리는 대신 해당 부분만 대조한다.
