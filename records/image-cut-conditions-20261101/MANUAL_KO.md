# 이미지별 B·C컷 등장조건 편집기

이 문서는 `IMAGE_CUT_CONDITION_EDITOR_API_20261101` 및 `JO9_CUT_CONDITION_CORE_20261101` 기능의 사용·유지보수 안내다. 작업 대상은 WORK와 추적 소스다. 설정 저장이나 도구 갱신으로 `G:/somi/Jack O Nine Tails v2.4 Kor_Full`이 자동 동기화되지는 않는다.

## 사용 방법

1. 편집실 서버의 이미지 패치리스트(`/catalog`)를 다시 연다. 파일을 직접 연 페이지에서는 저장 서버와 인증 정보가 연결되지 않을 수 있다.
2. `bg`, `characters`, `scene` 이미지 카드의 **등장 조건 설정**을 누른다. 하위 폴더의 이미지도 대상이다.
3. 같은 폴더·파일명·확장자의 추가 컷을 고른다. 예를 들어 `room.png`가 A컷이면 `room (2).png`는 B컷, `room (3).png`는 C컷이다. 추가 컷이 없으면 기존 **전환 컷 추가 (B·C…)**로 먼저 저장한다.
4. 해당 컷의 **이 컷의 등장 조건 사용**을 켜고 필요한 조건을 지정한다. 사용하지 않을 조건은 체크를 끄거나 드롭다운에서 **조건 없음**을 고른다.
5. **조건 저장**을 누른다. 저장 성공 문구를 확인한 뒤, 실행 중인 게임을 다시 실행하고 세이브를 불러온다.

설정 창은 현재 이미지 가족 전체의 조건을 저장한다. 다른 기본 이미지의 조건은 보존한다. 컷 사용 체크를 끄거나 모든 조건을 비우면 그 컷의 조건만 삭제한다. 조건 삭제는 그림 파일 삭제가 아니다.

## 조건과 선택 순서

| 조건 | 입력과 실제 비교 대상 |
| --- | --- |
| cruel & mercy | 최솟값과 최댓값을 각각 -10~+10, 0.5 단위로 선택한다. 양 끝값을 포함한다. 실제 비교는 기존 `jo9_cruel_mercy`와 `jo9_cruel_mercy_half`를 합친 값이다. 주인공의 누적값 자체를 이 범위로 제한하지 않는다. |
| 보유금 | 주인공의 `sparks`를 비교한다. 0~2,147,483,647의 정수와 **이상** 또는 **이하**를 지정한다. 경계값을 포함하며 금화 수량과는 별개다. |
| 계급 | 현재 `guild_reputation`과 정확히 같은 단계를 비교한다. 조합 신입(0), 조합 말단(1), 조합 일원(2), 조합 인사(3), 조합 중역(4), 조합 이사(5). |
| 평판 | 현재 `brand_reputation`과 정확히 같은 단계를 비교한다. 알려지지 않음(0), 희미하게 알려짐(1), 입소문이 남(2), 잘 알려짐(3), 유명함(4), 로마의 전설(5). |

한 컷에 지정한 조건은 **모두 충족해야 한다(AND)**. 미사용 조건은 비교하지 않는다. 계급·평판 선택은 ‘이상’ 비교가 아니다.

조건을 만족하는 추가 컷이 여러 장이면 **파일의 컷 번호가 작은 것**을 자동 우선 표시한다. B컷과 C컷이 모두 맞으면 B컷이 우선한다. 일치한 파일이 실제로 있어야 표시 대상으로 채택한다.

조건이 붙은 컷이 현재 조건을 만족하지 않으면 기존 수동 전환 후보에서도 제외된다. 그 컷이 이전 선택이었다면 기존 기본 복귀 규칙에 따라 A컷으로 돌아간다. A 파일이 없으면 기존 방식대로 남아 있는 첫 후보를 사용한다. 조건을 붙이지 않은 컷의 기존 수동 선택·전환 방식은 유지한다. 따라서 조건 없는 수동 선택 컷을 사용 중이면 그 선택은 유지될 수 있다. 조건이 전혀 없는 이미지에는 자동 선택을 새로 강제하지 않는다.

판정은 게임이 해당 이미지를 출력할 때 수행한다. 이미 떠 있는 그림을 별도의 상시 감시 타이머로 바꾸는 기능은 아니다. 조건을 바꾼 QSP는 실행 중인 게임 메모리에 자동으로 다시 읽히지 않는다.

## 저장되는 위치와 복구

조건은 대상 WORK의 `game/jack.qsp` 안 `interior_change`에 JSON 주석과 생성한 판정 코드로 함께 저장된다. 카탈로그 브라우저의 임시 상태나 개인 SAV에만 저장하는 방식이 아니다. 새 영구 저장 변수·로케이션·세이브 이관은 추가하지 않는다. 기존 `jo9_cut_choice` 선택 ID와 기존 이미지 전환 기능을 재사용한다.

저장 전에 현재 QSP 해시와 창을 열었을 때의 해시를 비교한다. 다른 편집으로 QSP가 바뀌었으면 덮어쓰지 않고 중단한다. 입력은 열린 창에 남는다. 다시 열기 전에 필요한 입력을 메모하고, 최신 QSP에서 조건을 다시 확인해 저장한다.

반영은 편집실의 기존 `transact`를 사용한다. 기존 QSP 백업, 변경 기록, 임시 출력 파일 검증, 반영 직전 해시 재확인, 교체 후 해시 검증을 거친다. 백업과 기록은 해당 편집실 실행 설정의 `runtime/backups`에 생긴다. 변경이 없는 저장은 새 반영 기록을 만들지 않는다.

기존 편집 기록의 내보내기 기능은 이 변경의 선언형 패치도 내보낼 수 있다. 패치에는 `interior_change` 본문의 변경 전·후 내용과 해시가 포함된다. 다른 버전 QSP에 무조건 덮어쓰는 파일이 아니므로 기존 패치 반영 절차를 따른다. 과거 QSP 전체 백업으로 복구하면 그 이후의 다른 대사·코드 편집도 함께 돌아갈 수 있다. 특정 조건만 지울 때는 해당 이미지의 조건을 해제하고 저장하는 방법을 사용한다.

## 구성 요소와 호출 관계

| 구성 | 입력·출력·역할 |
| --- | --- |
| `catalog-cut-conditions.js` | 기존 카드 생성 함수 `rowHtml`에 버튼을 덧붙인다. 모달 입력을 조건 자료로 만들고 `info`/`save` API를 호출한다. 기존 카탈로그 HTML이나 이미지 상태 자료를 새로 생성하지 않는다. |
| `server.cjs` | `/catalog`에 추가 스크립트를 삽입한다. 기존 편집실 토큰·출처 확인을 거친 `POST /api/catalog/cut-conditions/info` 및 `/save`를 연결한다. 저장은 기존 `transact`로 전달한다. |
| `image-cut-conditions.cjs` | `info({path})`는 기본 경로, 실제 추가 컷, 저장된 조건, 선택 항목, QSP 해시를 반환한다. `save({base,before,rules})`는 해당 이미지 가족의 조건을 교체하고 새 해시·조건·기록 ID를 반환한다. 그림 파일과 SAV는 쓰지 않는다. |
| `image-cut-condition-rules.cjs` | 입력을 검증·정규화하고 QSP 조건 코드와 JSON 주석을 생성한다. `installBaseBody`는 공통 출력 함수를 설치하며, `buildBody`는 설정에 따른 8개 마커 블록을 재생성하거나 제거한다. |
| QSP `jo9_cut_condition` | 기본 경로와 후보 경로를 받아 조건 없음 `-1`, 조건 불충족 `0`, 충족한 컷의 번호 `2` 이상을 반환한다. |
| QSP 기존 `jo9_path` | 실제 파일 후보를 확인하고 불충족 컷을 걸러낸다. 일반 출력(mode 0)에서 충족 컷을 자동 선택한다. 기존 수동 전환(mode 1)과 이미 출력된 이미지 조회(mode 2)의 역할을 보존한다. |
| QSP `jo9_condition_path` | 기본 이미지 경로를 받아 충족하는 추가 컷의 경로를 반환한다. 해당 조건이 없으면 입력 경로를 그대로 반환한다. 기존 수동 선택값을 변경하지 않는 출력용 경로다. |
| QSP `jo9_condition_html` | HTML의 `<img src="…">` 또는 작은따옴표 `src`에서 조건 대상 경로를 바꿔 HTML을 반환한다. 태그의 기존 스타일·위치·다른 내용은 유지한다. |

기존 `jo9_html`이 집·전투 화면의 수동 전환을 제외하는 분기에서도 조건 전용 HTML 변환을 호출한다. 이 연결은 수동 전환 버튼이나 전투 이펙트 레이어를 새로 넣지 않는다.

직접 출력하던 곳은 `renderer-edits.json`의 정확한 변경 명세로 연결한다. 대상은 `slave_stat` 2곳, `assistant_stat` 2곳, `trophy_room_screen` 1곳, `#options` 4곳, `jo9_liquidation` 1곳이다. 각 변경은 기존 HTML 식을 조건 전용 함수로 감싸며 대사와 기존 배열 조립을 유지한다.

## 의존성과 제거 시 영향

정적 공통 코드는 `JO9_CUT_CONDITION_CORE_20261101` 마커로 식별한다. 조건 설정은 다음 8개 마커로 식별한다.

- `JO9_CUT_CONDITIONS_DATA_20261101`
- `JO9_CUT_CONDITIONS_LOCALS_20261101`
- `JO9_CUT_CONDITIONS_SUPPLEMENT_20261101`
- `JO9_CUT_CONDITIONS_REGISTERED_FILTER_20261101`
- `JO9_CUT_CONDITIONS_REGISTERED_AUTO_20261101`
- `JO9_CUT_CONDITIONS_WINDOWS_FILTER_20261101`
- `JO9_CUT_CONDITIONS_WINDOWS_AUTO_20261101`
- `JO9_CUT_CONDITIONS_SELECT_20261101`

저장 규칙이 모두 없어지면 8개 설정 블록을 제거한다. 공통 함수와 직접 출력 연결은 남아 입력 경로를 그대로 통과시킨다. 공통 함수는 `interior_change`와 기존 이미지 전환 등록 구간에 의존한다. 기존 Windows 이미지 슬롯 등록 구간을 갱신할 때는 그 밖의 조건 마커를 보존해야 한다.

도구 스크립트만 제거해도 이미 QSP에 저장한 조건 판정은 계속 작동한다. 반대로 공통 함수만 지우면 이미 연결한 직접 출력 위치에서 호출 대상이 없어질 수 있다. 기능 전체를 제거하려면 설정 블록, 공통 함수, `jo9_html` 연결 및 `renderer-edits.json`의 직접 출력 연결을 함께 검토해야 한다. 각 블록을 임의로 일부 삭제하거나 JSON 주석만 직접 고치면 다음 저장이 손상된 경계로 판정되어 중단될 수 있다.

## 입력 검증 범위와 확인할 점

- 이미지 범위는 `content/pic/bg`, `characters`, `scene`와 각 하위 폴더다. `mob`, `reserve`, 기타 폴더는 이 편집기의 조건 대상으로 받지 않는다.
- 확장자는 PNG, JPG, JPEG, GIF, WebP, BMP다. 같은 가족의 기본·추가 컷은 폴더, 이름, 확장자가 일치해야 한다. 추가 컷 번호는 2~2,147,473,647의 정수이며 `(02)`처럼 앞에 0이 붙은 형식은 받지 않는다.
- 경로의 빈 구간, `.`·`..`, 외부 경로, 연결 폴더·파일은 거부한다. 대소문자와 `/`·`\`는 실제 Windows 파일을 확인한 후 정규화한다. 같은 이름의 대소문자 변형이 둘 이상이면 모호한 경로로 거부한다.
- 경로에는 제어 문자, DEL, `: * ? " < > |`, 작은따옴표, 역따옴표, `% & ! $ { }`를 사용할 수 없다. 임의 QSP 식이나 코드 문자열을 입력하는 기능은 없다.
- 조건은 허용된 네 종류만 받는다. 잘못된 키, 중복 대상, 소수 보유금, 범위 밖 값, 존재하지 않는 컷, 다른 이미지 가족의 컷은 저장하지 않는다. API 본문 제한은 1,000,000바이트다.
- 서버는 QSP 파싱·직렬화 왕복, 고유 `interior_change`, 생성 위치의 고유 앵커, 8개 마커·JSON 일치, 기존 선택 ID 충돌, 다른 본문 보존, 반영 전·후 해시를 확인한다. 이 저장 절차가 게임의 모든 이야기 분기와 화면을 자동 플레이하는 검사는 아니다.
- 개별 컷의 구도·크기·미술 완성도, 실제 도달한 장면의 표시, 실행 중인 구버전 게임의 상태는 별도 플레이 확인 대상이다. 조건 자체가 없던 장면이나 CSS 전용 이미지 표현을 임의로 새 전환 대상으로 만들지는 않는다.

현재 WORK의 세 대상 폴더에서 확인한 지원 확장자 이미지 2,402개 중 위 금지 문자 때문에 조건 경로 정규화가 거부되는 파일은 0개였다. 이 수치는 경로 문자 조사 결과이며 모든 이미지의 게임 등장 여부나 모든 조건 조합의 실행 결과를 뜻하지 않는다.
