# 하드 기본 AP 변경 — 제한된 실제 엔진 검사

후보 SHA-256: `a34b95fc23d39440204ce2aff3cf56cc1b5b19b450cb84865b4389bc6b2f1565`.
기준 SHA-256: `a58cddda7faf051574173484402fa4804f952612c42c9d3981d1fb4d56c7a3e0`.

| 검사 | 변경 전 RED | 같은 계약의 후보 GREEN |
|---|---:|---:|
| 실제 QSP 5.8.0 WASM | 830개 중 636 통과, 194 예상 실패 | 830/830 통과 |
| 설치된 WORK `engine/jack.exe` | 497개 중 452 통과, 45 예상 실패 | 497/497 통과, 실행기 종료 0 |

RED 실패는 기존 하드의 +1 기본 AP 및 이에 종속된 정규화·회복·전환 기대값이다. 쉬움·보통 수식 결과, 기존 보너스 유지 검사, 실제 주인공 상한 함수 검사는 변경 전에도 통과했다.

`hard-ap-runtime.cjs`는 후보의 실제 17개 수식을 추출해 난도 0/1/2 × 지구력 0~5 × 생성 난도 0/2에서 실행한다. 실제 `AP_CURVE_CAP` 정규화 조각, `$dynamic_energy_drop`, `$next_day_energy_refresh`, `$do_for_each_slave_in_list`도 실행한다. `room1`~`room4`, 조수, 가축 담당, 비동결 목록과 기절 상태, 해동 후 목록 포함, 반 행동 1/-1/-3, 양수 반 행동 소비, 에너지 하한 -5, 부상·의료의 같음/초과 경계, 누적 음수 AP, 난도 전환, 기존 밤샘 보너스 상한, 실제 주인공 5칸 상한을 확인했다.

`hard-ap-native.cjs`는 원본에서 추출한 **전체** 에너지 별 함수와 기존 AP 소비·회복 함수를 1개 location의 작은 진단 QSP에서 실행했다. FastQSP의 `for`와 생성 HTML 이미지 개수도 검사했다. WASM 검사는 해당 `for` 렌더링 구문을 제외하고 실제 상한 조각까지만 실행한다. 성공 표식에 결과 카운터를 덧붙이던 시험 실행기 형식은 기존 실행기의 정확 표식 요구에 맞게 수정했다. 단언 및 기대값은 후보 결과를 보고 변경하지 않았다.

`scope-review.json`은 278개 location과 나머지 컨테이너 필드를 유지하고, 15개 location의 17개 수식 및 새 `HARD_BASIC_AP_20261103` 주석만 되돌리면 변경 전 QSP와 바이트 단위로 일치함을 독립 확인한 결과다.

검사 범위는 합성 상태를 넣은 실제 엔진의 관련 코드이다. 개인 SAV의 GUI 로드, 하루 전체 진행, 실제 생성·복제·취득 경로의 주변 처리, 화면 육안·체감은 검사하지 않았다. 생성·취득·튜토리얼·UI의 AP 계산은 해당 지점의 실제 수식 실행으로 확인했다. HTML 이미지 수는 확인했지만 화면을 렌더링해 보지는 않았다.

WORK·Full·소스 저장소·개인 저장 파일은 이 검사에서 수정하지 않았다. 진단 QSP, 실행 설정, 빈 표준 출력은 실행 후 정리했다. 남은 것은 두 재현 스크립트, RED/GREEN 결과, 작은 표준 오류 로그와 범위 보고서다.

재현은 두 스크립트의 `--qsp`를 검사할 QSP 절대 경로로 지정한다.

```powershell
node .\hard-ap-runtime.cjs --qsp '검사할 QSP의 절대 경로' --report '.\green-runtime.json'
node .\hard-ap-native.cjs --qsp '검사할 QSP의 절대 경로' --out '.\native-green'
```

WASM 패키지의 기본 경로와 기존 엔진/실행기 경로는 스크립트 안에 명시되어 있다. WASM 패키지는 `--vendor`, 네이티브 엔진은 `--engine`으로 지정할 수 있다.
