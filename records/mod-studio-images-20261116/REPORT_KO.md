# 통합 작업실 복장 복사·이미지 메뉴 수정 (2026-11-16)

## 원인과 수정

미라2578과2609는 같은 기본 이미지 파일을 쓰지만2609에는 복장·타이틀 등 이미지 연결5개가 없었다. 공통 이미지 읽기/복제/저장에서 동일한 실제 기본 이미지의 누락 슬롯을 보완한다. 명시된 빈값·다른 복장 선택·충돌 후보는 덮어쓰지 않는다. 기존 미라2609의5개 이미지 연결만 보완했고 배경과 모든 기존 필드/문장은 보존했다. 상세·복구 원본은 ../outfit-copy-fix-20261116/REPORT.md.

통합 메뉴는 종료된 이미지 편집 서버와 폴더 비교 서버의 예전 포트만 저장하고 재사용했다. 이제 해당 메뉴를 누르면 실제 서버 상태를 확인하고 기존 실행기를 이용해 준비한 뒤 주소를 갱신한다. 같은 포트로 재시작해도 프레임을 다시 읽으며, 연속 클릭은 하나의 시작 요청으로 합친다. 실패하면 연결거부 빈 프레임 대신 재시도 안내를 보인다. 다른 도구와 기존 사이드바 구성은 유지한다.

이미지 교체 서버는 이미 설치된 catalog-resource-source.js를 제공하지 않아 게임 이미지 소스 선택 플러그인이404였다. 고정된 해당 파일 한 경로만 제공하도록 소스/WORK 설치본을 함께 맞췄다. 실제404→200과 버튼 모듈 응답을 확인했다.

## 확인

- 복사 기능: 신규7개 회귀의RED/GREEN, backend30개·허브62개 통과 기록 참조.
- 도구 실행: Python6개·Node6개 회귀 통과, JS·PowerShell 구문 검사 통과.
- 서버 재시작 후 미라2609 실제 API에5슬롯/5이미지200 확인.
- 별도 임시 브라우저에서 이미지 교체·편집과 폴더 비교·선택 화면이 통합 프레임 안에 열리는 것을 확인. 실제 사용자 이미지 덮어쓰기나 폴더 비교 프로젝트 생성은 하지 않았다. PIC 파일 접근은 기존 폴더 등록 방식을 유지한다.
- 사용자의 기존 탭과 편집 입력은 새로고침하지 않았다. 저장 후 새로고침하면 새 메뉴 연결 처리가 적용된다.

## 사용·유지보수

POST /workspace/tools/ensure는 workshop/imageReview 두 키만 받는다. 현재 게임과 기존 catalog 설정을 사용하며, 외부 주소·임의 실행 경로는 받지 않는다. 준비된 서버의 로컬 주소를 반환하고 tool-urls.json의 해당 키만 갱신한다. 새 포트는 각 도구의 기존 포트 선택을 따른다. 세션마다 포트가 바뀌면 브라우저의PIC 폴더 접근 재승인이 필요할 수 있다. 원래 도구의 유휴 종료·저장 데이터는 변경하지 않는다.

변경 파일은 deployed.json과 workshop-asset-fix.json, 복사 기능의 source-changes.json에 있다. server.py와 Start-Modding-Hub.ps1의 build 파일 목록은 함께 유지한다. 기능을 제거할 때는 integration.mjs의 호출·tool-runtime.mjs·image_tool_runtime.py·Start-Image-Tool.ps1 및 서버 라우트를 함께 검토한다. 다른 프로그램을 종료하거나 사용자가 고른 이미지를 자동 덮어쓰지 않는다.

QSP·음원·기존 배포ZIP·Full·개인세이브·커밋·푸시 변경 없음. 미라JSON5필드의 WORK·추적 소스는 일치한다. 합성 임시 복제는 정리했고 기존 운영 중인 claude-character-studio 경로는 보존했다.
