# 듀플리카토 선택 링크의 인물 변경 오판정 — 2026-11-17

사용자 화면의 ‘대상 인물이 바뀌었습니다’ 오류를, 실제 게임 엔진 5.7의 Qt 선택 링크를 눌러 재현했다. 이전 검사는 생성한 토큰을 직접 함수에 전달하여 링크 처리 단계를 지나지 않았으므로 이 오류를 잡지 못했다.

## 확인한 원인

조수 미스티·노예 Galateya의 실제 테스트 세이브 값을 사용했다. 함수가 만든 원래 토큰의 `|`가 Qt 링크를 통과하면서 `%7C`로 바뀌었다. 현재 인물의 원래 토큰과 다른 문자열로 비교돼 같은 사람도 바뀐 것으로 처리됐다. 실제 클릭 로그에서 전달값과 비교값의 차이를 확인했다. 한국어 이름 자체는 유지됐다.

수정은 `jo9_duplicato` 한 위치다. 인물 토큰과 상충 특성 확인용 토큰을 링크에 안전한 형태로 손실 없이 변환한다. 이스케이프 표식 자체도 구별하므로 서로 다른 원문이 같은 확인값으로 합쳐지지 않는다. 인물 정보와 상충 조건의 변경 검사는 유지한다. 두 인물 토큰은 선택 화면을 만들 때 한 번씩만 계산한다.

새 세이브 필드·전역 상태·이주 과정은 추가하지 않는다. 비용 300스파크, 마법력 B, 상호 친밀도 각각 40, 참가자별 행동력 1, 하루 1회·노예당 1회, 재능과 상충 규칙은 바꾸지 않았다. 프리실라 대사·그림과 다른 위치도 보존했다.

## 실제 클릭 검증

같은 설치 엔진과 실제 세이브의 인물·초상 경로를 사용한 별도 진단 창에서 다음을 확인했다.

1. 수정 전: ‘예민한 미각’ 링크 클릭 → 실제 입력에 `%7C`가 발생하고 동일한 오류로 메뉴에 돌아감.
2. 수정 후보: 같은 링크 클릭 → 미리보기 진입.
3. 확인 링크 실행 → 복사 완료. 실제 로그 `JO9_GUI_FINAL pass=1;sparks=997187;AP=4,3,4`.

pass=1에는 수혜자의 재능 1·발견 2, 제공자 재능 유지, 수혜/일일 기록 1, 스파크 300 및 세 참가자 행동력 각각 1 차감을 함께 검사했다. 실제 Qt 링크 두 개의 클릭 로그는 native-before-qt.log·native-after-qt.log에 보관했다. 생성 링크·토큰·상충 처리의 별도 native 검사 12개와 문자열 보존 검사 134개도 통과했다. 전체 게임 세이브 로드를 반복한 검증은 아니며, 테스트 세이브 파일 자체를 소비하거나 수정하지 않았다.

## 적용과 복구

WORK·추적 QSP·해시 명세를 맞췄다. 결과 SHA256은 applied.json에 기록했다. 이번에 검사한 함수와 배치 함수가 같고, 변경 범위·바이트 왕복·역패치도 확인했다.

52MB 원본을 또 복사하는 대신 기존 `G:/Codex/tmp/duplicato-native-cost300-20261117/before.qsp`와 기존 누적 수정 명세로 이번 수정 직전 4bb19a… 파일을 정확히 재구성할 수 있음을 검사했다. 이번 mods JSON까지 이어 적용하면 결과를 재현할 수 있고, 이번 수정만 역적용하면 직전 상태로 돌아간다. 복구 경로는 applied.json의 recovery에 있다. Full·배포 ZIP·개인 세이브·이미지는 변경하지 않았고 커밋·푸시하지 않았다.

게임을 완전히 종료하고 WORK를 다시 실행한 뒤 `듀플리카토_친밀도테스트_20261117.sav`를 불러와 같은 재능을 선택한다. 기존 실행 프로세스는 수정 전 QSP를 기억하므로 재실행이 필요하다.
