- 공용 코드를 실제 실행하는 곳은 `interaction:2262`의 `5415`와 `2263`의 `44` 두 곳이다. 전자는 먼저 `$sex_partner = ''`, 후자는 먼저 `$sex_partner = 'assistant'`를 설정한다. 그 밖의 공용 코드 실행 참조는 없으며 `$newloc:18`은 캐시 플래그 초기화뿐이다.
- `sex_initiate:26`이 기존 `sex` 배열을 비우고 `51`이 `$sex['partner']`를 저장한다. 빈 파트너 분기 `57~148`은 노예의 이름(`59,147`), 나이(`78`), `anal_stretch`(`112`)를 복사한다. 조수 분기 `151~242`는 조수 이름(`153,241`), 나이(`172`), `anal_stretch`(`206`)를 복사한다.

- 개인실 `snk_room_bridge:108~116`의 별도 행동은 `1027~1030` 번호로 기존 `interaction`에 복귀한다. 해당 번호는 위 공용 코드의 실행 조건 `5415/44`가 아니므로 별도의 미초기화 미니게임 진입으로 세지 않았다. `sex_*` 위치의 방 가드는 기존 세션을 통과시키는 장치이고 새로운 파트너 초기화 호출이 아니다.

## 스냅샷과 조수/노예 구분

현재 네 결과문은 조수 세션에서도 `slave`의 원자료를 읽는다. 노예와 조수의 나이 또는 `anal_stretch`가 다르면 원래 참조식은 화면 파트너와 다른 자료를 고를 수 있다. 07의 변경은 이미 다른 남성 표시문들이 사용하는 세션 참조 방식과 맞는다. `$slave_noun4`, `$slave_body7_txt`, `$slave_anus_txt`라는 변수명은 공용 표현 사전의 이름이며, 그 이름 자체가 현재 노예 개체를 읽는다는 뜻은 아니다. 교정 대상은 사전 이름이 아니라 첨자이다.

현재 전체 본문에서 `sex['girl_age']`와 `sex['girl_anal_stretch']`에 직접 값을 넣는 곳은 위 노예·조수 초기화 네 곳이다. 해당 필드를 세션 중 변경하는 대입은 발견되지 않았다. 따라서 이 범위에서는 세션 스냅샷이 유지된다. 새 함수, 방어 조건, 세이브 마이그레이션, 새 상태 필드는 필요하다는 근거가 없다.

## 삽입식 계산 시점

QSP의 일반 따옴표 문자열 안 `<<...>>`는 그 문자열 표현식을 계산할 때 확장된다. 이번 사전 대입에서는 `#sex_texts` 실행 시 계산되어 결과 문자열이 저장된다. 후속 `$text[1] = $sex_cum_*`는 이미 계산된 문자열을 복사한다. 뒤늦게 `slave`를 올바르게 바꾸면 자동으로 다시 평가되는 구조로 설명하면 안 된다. 현재 `sex_screen:14`가 매 화면에서 사전을 다시 실행하는 것이 중요하다. 게임 시작/갱신의 `refresh_database:56`에서도 사전을 읽지만, 실제 세션은 위 화면에서 초기화 후 다시 덮어쓴다.

공식 근거: [QSP 문자열 문서의 삽입식 절](https://wiki.qsp.org/help:strings), [QSP 엔진 mathops.c](https://github.com/QSPFoundation/qsp/blob/master/qsp/mathops.c#L713) (`713~725`에서 따옴표 문자열을 포맷 대상 값으로 분류, `1055~1063`에서 값 계산 중 확장). 이는 현재 코드의 실행 순서와 결합한 정적 판단이다. 현재 로컬 플레이어 바이너리의 정확한 QSP 버전은 이번 범위에서 대조하지 않았다.
