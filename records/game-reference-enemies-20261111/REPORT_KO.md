# 적 전투 특성 열람 탭

사용자 요청으로 기존 특성·아이템·마법 DB에 ‘적 전투 특성’ 탭을 추가했다. 현재 WORK 적 70종의 상시 플래그, 속성별 고정 저항·약점, 일반공격 155개와 특수공격 30개를 읽는다. 엘자와 포털 가디언의 승인 변경을 반영한 QSP fef0baedfa22746366fc9ce5acf16e4fa04922fd63e9c5c133c559ecb4265357 기준이다.

## 사용

- 현재 WORK 모드툴 열람표에서 ‘적 전투 특성’을 선택한다. 적 이름·ID·특성·저항·공격 효과를 입력하고 검색 버튼 또는 Enter로 찾는다. 분류 선택도 검색 버튼으로 적용한다.
- 적 카드의 ‘공격 정의 보기’를 펼치면 일반·특수공격의 종류와 상태 효과를 읽을 수 있다. 방어 특성의 뜻과 실제 코드 연결 누락은 위쪽의 설명을 펼쳐 확인한다.
- 새 탭은 처음 선택할 때 한 번 구성한다. 탭 왕복 시 검색과 기존 개인 아이디어 작성 내용이 유지된다. 열람 자체는 게임이나 개인 아이디어 파일을 수정하지 않는다.

## 구현과 유지보수

- reference-template.html은 실제 tab/tabpanel을 하나 추가하며 기존 테이블을 숨기는 CSS 덮어쓰기로 만들지 않았다. enemies-ui.js가 적 전용 카드와 수동 검색·분류를 구성한다.
- enemies-data.cjs의 buildEnemies(doc)는 파싱된 QSP를 받아 기술 필드만 추출한다. 설명·대사·공격 및 사망 서술문은 추출하지 않는다. 면역·저항·부가상태와 연결 문제 설명은 기존 감사 결과를 사용한다.
- assemble.cjs의 일반 생성은 기존 DB 생성 후 적 자료도 같은 QSP에서 추출한다. --enemies-only는 기존 HTML의 특성·아이템·마법 및 메타데이터를 그대로 보존하고 적 자료만 현재 QSP에서 바꾼다. 두 기준 해시가 다르면 하단에 각각 표시한다.
- HTML에 자료·UI를 모두 내장하므로 기존 서버와 단독 파일 열기에서 같은 기능을 사용한다. 서버 라우트와 설치기의 복사 목록을 늘리지 않았다. WORK에는 생성 HTML·README·snapshot만 동기화했다. 개인 runtime 폴더는 복사하지 않았다.
- 감사 기준 해시가 바뀌면 과거 연결 문제를 최신 확인으로 표시하지 않는다. 이번 fef0 갱신에서는 이전 a085와 비교해 승인된 적 정의 2edit/7값 외의 295 location과 전투 로직이 동일함을 확인했다.
- 새 모듈과 템플릿 슬롯은 함께 유지해야 한다. 제거하려면 탭·panel·스크립트 슬롯과 assemble의 해당 추출 호출을 함께 제거한 뒤 HTML을 다시 생성한다. 완성 HTML은 이미 내장되어 있으므로 생성 모듈만 삭제해도 현재 HTML에서 즉시 사라지지는 않는다.

## 검증

- 생성 HTML의 스크립트 구문 검사와 데이터 왕복 대조 통과. 기존 특성128·아이템272·마법11의 행·설명·메타데이터가 이전 HTML과 동일하다.
- 이전 독립 추출 JSON과 적70종의 기본 수치·플래그를 대조했다. 일반155·특수30, 아레나 안개괴물 저항 미정의, 대마법사 AI 누락, 쥐인간 상태 키 오기를 확인했다.
- 기존 개인 아이디어·서버·마법 DB 관련10검사 통과. 격리 임시 폴더를 사용했고 운영 아이디어 파일의 부재 상태를 보존했다.
- 실제 WORK 설치 서버 http://127.0.0.1:9515/ 에서 탭·70종·수동 검색·분류·초기화·공격 상세·아이디어 초안 왕복 보존을 확인했다. 엘자6저항·가디언 사기 피해 차단과 해당 플래그 검색12종도 확인했다. 브라우저 오류0.
- source/설치 HTML·README·snapshot의 해시가 일치한다. 엘자·가디언의 게임 수정 검증은 ../enemy-balance-20261111/REPORT_KO.md에 별도로 기록되어 있다. 전체 게임 GUI 플레이 검증은 하지 않았다.

## 기록과 범위

before/에는 도구 원본의 유일한 복구 사본을 보존했다. 중복 설치 백업·검증용 임시 자료는 해시를 대조한 뒤 정리했다. before.json, validation.json, ui-validation.json, qsp-scope-check.json에 검증 근거가 있다. verify.cjs는 현재 생성본을 대조하는 재현 스크립트이며 변경된 QSP를 허용할 때는 별도로 검증한 해시를 인수로 준다.

새 적 탭에 기획 중 춘향을 실제 구현된 적으로 추가하지 않았다. 최신 춘향 설계는 ../catfight-successor-planning-20261111/CHUNHYANG_DEFENSE_DRAFT_KO.md에 구분해 기록한다. Full·음원·개인 JSON/PNG·커밋·푸시는 이번 도구 작업에서 변경하지 않았다.
