# 1031 복장 연결 경고 판정 수정 · 2026-11-08

사용자 첨부의 비서·도미나 “그림 있음 · 복장 선택 연결 필요”는 체크리스트의 잘못된 판정이었다. 현재 WORK의 조수 메뉴와 그림 조회는 옛 fullsecretary/fullmistress뿐 아니라 indpack_secr/indpack_dom 등록도 인정한다. 체크리스트만 옛 필드가 비면 미연결로 처리하고 있었다.

## 반영 내용

- catalog-girls-checklist.js의 role(c,spec): 추가팩만 등록된 복장도 정상 등록으로 분류한다. 표시 문구는 “전용 그림 있음 · 추가팩 등록”. 실제 파일/상태 변형 누락, 기본 전신과 동일한 경로, 미등록 분류는 유지한다.
- build_inventory.py와 manifest/HTML 내 effectiveRoles: 메뉴 사용 가능 여부는 옛 등록 또는 추가팩 등록 중 하나라도 있으면 참이다. menuIssue는 이중 등록 방식에서 별도 미연결 근거가 없어 거짓으로 기록한다. 실제 파일 누락은 기존 displayIssue/파일 검사에서 표시한다.
- legacyFields에 실제 등록이 없는 캐릭터는 빈 이전 장면 경고를 만들지 않는다. 등록이 있는 경우 “이전 개별 장면 등록 · 참고 경로”로 별도 자료임을 설명한다.
- 적용: canonical JS/생성기/manifest, 소스 catalog seed, WORK 통합 HTML과 독립 체크리스트 HTML. 네 원장의 역할 항목100개씩 총400레코드에서 두 판정 플래그만 수정했다. 이미지 경로/태그/다른 메타데이터와 체크리스트 밖 HTML은 보존했다. 전체 inventory를 재분석한 것은 아니므로 기존 qspSha 등은 그대로다.

## 사용과 영향

이미지 패치리스트를 새로고침한 뒤 캐릭터1031을 검색하면 비서·도미나가 추가팩 등록으로 나온다. 빈 이전 장면 경고는 사라진다. 조수 선택이나 게임 저장에 영향을 주는 변경은 없다. 호출자는 카탈로그의 캐릭터 이미지 탭이며 입력은 기존 캐릭터 refs와 파일 존재 원장, 출력은 역할 상태/안내문이다. 이 수정을 제거하면 옛 필드가 빈 정상 추가팩 복장에 다시 연결 경고가 뜬다.

## 복구와 재현 자료

before.json은 작업 전 경로별 해시, before/<해시>.gz는 QSP를 제외한 변경 대상과 보호 대상의 원본이다. installation.json/verification.json에 설치/최종 해시와 검사 범위를 남겼다. 복구할 때는 변경 대상 여섯 파일의 백업을 경로에 맞춰 복원하며, 보호 대상이나 사용자 후속 변경을 덮어쓰지 않는다. 변경 후보 작성·설치 스크립트는 당시 재현용이며 이미 반영된 파일에 무조건 재실행하지 않는다.
