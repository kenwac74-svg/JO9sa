# MOB 이미지 세트 관리

이미지 체크리스트 `/catalog?mobsets=1`의 `전투 MOB 이미지 세트`에서 관리한다. 이름/파일명 검색, 부족한 세트만, 현재 파일 상태 새로고침을 지원한다. 파일 있음은 실제 파일 존재이며 그림의 품질 검수 완료를 의미하지 않는다.

- 초상화 / 전투 전신 / 패배 컷신을 나란히 표시한다. PNG 추가·교체 → 미리보기 → WORK에 반영. 취소하면 쓰지 않는다.
- 전신 `content/pic/mob/name.png`, 패배 `content/pic/mob/defeated/name.png`. 기존 탈옥수 개별 패배 예외는 유지한다. mistress_morrigan은 원래 characters 폴더 전신을 유지하며 패배만 mob/defeated에서 조회한다.
- 새로운 PNG는 선택 원본 크기로 생성, 기존 파일 교체는 기존 치수와 같아야 한다. 가능하면 4:3 투명 PNG를 사용한다. 게임의 기존 contain 배치가 크기를 맞추며 이 도구는 그림 자체를 재생성하거나 리사이즈하지 않는다.
- 공유 슬롯을 바꾸면 그 파일을 쓰는 모든 적/성장단계에 적용된다. 초상·전신·패배는 별개의 파일이므로 하나를 교체해도 다른 파일은 덮어쓰지 않는다.
- 파일은 기존 `pic-local.cjs` 인증 API가 저장한다. 현재 해시 불일치 시 중단하며 원본 백업, image_work/history, personal-patch/events 원장에 기록한다. 상태·칭호·승패·보상·저장 변수는 변경하지 않는다.
- 패배 파일이 아직 없으면 원래 전신으로 대체 표시한다. 전신도 없으면 그 슬롯에 PNG를 먼저 추가해야 한다. 투기장 무작위 외형도 각각 슬롯이 있다. 경주 전용 ride/chariot 초상은 제외한다.
- 안개 무리는 기존 실제 전투 로스터의 각 패배 이미지를 합성하는 규칙을 유지한다. 파일명 하나로 무리 전체를 덮어쓰지 않는다.

## 구현과 유지보수

`MOB_SET_SLOTS_20261028`: 기존 jo9_battle_fate의 sprite(slot, defeatedFlag) 반환 경로16개를 보완한다. 기존 끝난 전투의 단일/무리 img 태그는 누락 파일 오류시 data-standing으로 되돌린다. 함수의 기존 입력/출력과 기존 특수 탈옥수 매핑을 유지한다. locations 추가 없음, CSS/JS 게임 리소스 변경 없음. 다음 전투/화면 재생성부터 적용되며 이미 저장된 HTML의 즉시 변경은 보장하지 않는다.

`MOB_SET_CATALOG_DATA_20261028` / `MOB_SET_CATALOG_20261028`: 기존 catalog HTML 안의 선언형 목록과 패널. 파일 존재는 API로 새로 읽지만 QSP의 새 MOB 정의를 자동 탐색하는 서버 기능은 아니다. 신규 MOB 코드가 생기면 목록 생성 스크립트를 검토하여 다시 갱신해야 한다. 목록과 실제 QSP의 해시는 manifest.json에 기록했다. build.cjs에는 생성 시점 작업 경로가 포함되며 WORK를 무작정 재패치하지 않는다. 재생은 원래 작업 전 백업을 입력으로 사용한다.

원래 8번째 D 필드는 체크 완료를 자식에게 전파하므로 새 패배 파일에는 이를 사용하지 않는다. 별도 세트 데이터로만 그룹화하여 전신 교체 때문에 미제작 패배 그림까지 완료 처리되지 않도록 했다. 새 슬롯은 일반 목록에도 등록되며 미존재는 todo, 기존 수동 상태는 보존한다.

복구: 이번 작업 직전 QSP 백업 및 catalog/image_work/backups/mob-sets-20261028의 HTML/status를 함께 참조한다. 이후 사용자 교체가 있었다면 전체 복원으로 덮어쓰지 말고 이 블록과 패치만 역적용한다. 패널만 제거해도 게임 연결은 남는다. QSP 연결만 제거하면 새 컷신의 자동 사용은 중단된다. personal-patch 원장은 별개이므로 삭제하지 않는다.
