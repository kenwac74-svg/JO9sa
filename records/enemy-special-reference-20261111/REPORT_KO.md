## 결과와 사용

특성·아이템·마법 열람표의 **적 전투 특성 → 특수공격 기술표**를 펼친다. 특수공격 30개에 16종의 이름을 붙이고 기술명 / 사용하는 적·기술번호 / 공격·기본피해 / 부가효과·지속카운터 / 사용조건을 한 HTML 표에 표시한다. 예를 들어 정신교란은 ‘아레나 안개 괴물 특수1’, 안개적응은 ‘아레나 안개 괴물 특수2’로 표시한다. 정신파쇄는 여러 안개 괴물과 리치가 공유하고 파멸참격은 에게야·엘자 등 다섯 적이 공유한다.

같은 공격 종류·속성·효과 대상/상태 구성이면 공통 이름을 쓰며, 피해량과 지속 카운터는 각 행에 원래 값으로 표시한다. 이름은 열람표에서만 쓰므로 QSP 원래 공격 문장은 바꾸지 않았다. 검색 버튼 또는 Enter로 기술명과 적을 찾는다. 입력 중에는 자동 검색하지 않으며 탭 왕복 시 검색·펼침 상태와 개인 아이디어 초안을 보존한다. 기존 적 카드와 펼친 공격 설명에도 같은 이름을 쓴다.

## 코드와 재생성

- `tools/game-reference/enemy-special-names.cjs`: 기존 적ID:슬롯 → 이름 및 사용자 표시명. 30개 키·24종 사용자·공통 이름16종.
- `enemies-data.cjs`: 현재 QSP 정의·하드 연결과 명명 자료를 조합한다. 안개적응은 시전자 대상으로 표시한다.
- `enemies-ui.js`: 선택 탭 렌더링·실제 HTML 표·수동 검색. 기존 기능을 CSS로 가리는 방식으로 변경하지 않았다.
- `node tools/game-reference/assemble.cjs "<game/jack.qsp>" --enemies-only`: 기존 DB를 보존하고 적 자료만 갱신한다. 생성기는 text-workshop/core.cjs와 이름 사전에 의존한다.
- 생성 HTML/README/snapshot을 WORK의 `game/modtools/game-reference/`에 맞췄다. 서버는 매 요청 때 HTML을 읽으므로 프로세스 재시작은 필요하지 않았다.
- `check-and-install-reference.cjs`는 당시 검증·설치 재현 스크립트다. 읽기 전용 검사가 아니며, 기준 해시가 맞을 때 snapshot/설치 HTML·README·snapshot과 validation.json을 쓴다. 다른 WORK 해시에서 그대로 실행하지 않는다.

이름 사전을 제거하면 생성기가 읽지 못하므로 재생성 전에 의존을 함께 정리해야 한다. 현재 설치 HTML은 자료와 코드를 내장해 독립 열람이 가능하다. 개인 아이디어 파일은 생성·설치 대상에 포함하지 않는다.

## 기존 자료 보존과 검증

기존 특성128·아이템272·마법11 및 메타데이터 등 enemies 외 모든 내장 DB 섹션을 이전 HTML과 깊은 비교해 보존했다. 기본 DB 기준 해시는 그대로이며 적 기준 해시는 별도로 표시한다. 적70종의 원시 수치·공격 정의도 변경 전 자료와 일치한다. 새 하드 연결30개·대마법사 하드 AI 대체 경로·안개적응 시전자 표시와 WORK/소스 HTML·README·snapshot 일치를 확인했다. 개인 아이디어 파일의 기존 부재도 유지했다.

브라우저에서 처음30행, 수동 검색 정신파쇄4행·아레나2행·파멸참격5행, 사용자/번호·효과·하드 사용조건, 탭 왕복과 작성 중 아이디어 보존, 콘솔 오류0을 확인했다. 테스트 초안은 저장하지 않고 지웠다. 기존 저장·동시수정·백업/가져오기·API·마법 회귀검사10/10 통과. 상세는 ui-validation.json과 validation.json에 있다. 첫 제한환경 실행은 G: 임시파일 생성 권한 때문에 실패했고 같은 검사를 승인된 접근으로 통과했다.

별도 게임 구현은 후보/설치본 각각 실제 FastQSP 6흐름·923단언 통과, 공식 패치 재생·멱등성·구조 검사 통과. 새 사용이력 배열은 합성 SAV에 저장됐으며 보조 네이티브 API로 복원·재저장을 확인했다. 실제 GUI에서 기존 사용자 SAV 선택/불러오기·전체 전투 플레이는 확인하지 않았다. 사용자 SAV는 건드리지 않았다.

## 춘향·난이도와 구분

기존 게임 중 하드에는 적 체력/공격/피해 직접 배율이 없었다. 조수 행동력 상한이 쉬움/보통 min(5,stamina+1), 하드 min(5,stamina)라 낮은 등급에서 시작 전투 스태미나가 간접 감소할 수 있었다. 캐릭터 생성 game_difficulty와 게임 중 difficulty_setting은 구분했고 보류된 생성 보너스 불일치는 변경하지 않았다.
