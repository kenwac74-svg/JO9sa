# 콜로세움 연습 결과 컷신 구분

사용자가 제공한 네 PNG를 연습 결과에만 연결했다. 주인공 승리/패배는 practice_master_win.png / practice_master_loss.png, 노예·조수 승리/패배는 practice_slave_win.png / practice_slave_loss.png다. 경로는 content/pic/scene이다. WORK·현재 Full 테스트 빌드·추적 resources/new에 네 적용용 파일을 등록했다.

modworkpic의 원본 네 장은 해시를 대조해 보존했다. 여자노예승리는 원본768×576을 고품질 bicubic 보간과 경계반사로795×596에 맞췄고, 다른 세 장은 이미795×596이어서 바이트 그대로 복사했다. 생성형 재작성·크롭·배경 변경은 하지 않았다. 원본/적용본의 해시·크기·대응 파일명은 verification.json에 남겼다.

수정은 interaction_city의 연습 결과1296·1297·1298 헤더3곳이다. 기존 무작위 arena_end 선택을 제거하고 bg_path를 비운 뒤, 기본 승리 full[1]을 지정하며 기존 패배조건(도주/기절/치명상) 안에서 패배 full[1]로 바꾼다. 판정은 기존 combatant/colosseum_fight/승패값이 지워지기 전에 끝난다. 새 변수·로케이션·세이브 형식은 없다. 최근 사용자 대사·각색 대사·XP·피로·원래 정산·복귀 코드는 바꾸지 않았다.

기존 renderer는 full[1]을 그린 뒤 pic_png의 bg_path도 따로 그린다. bg_path를 비워 옛 랜덤 그림이 뒤에 덮이지 않게 했으며, 그림을 full[1]에 유지해 같은 화면 재표시도 정상이다. 다른 경기에서 공유하는 기존 arena_end 이미지는 지우지 않았다. 정식 아레나·캣파이트·이벤트 전투의 결과 그림과 규칙은 수정하지 않았다.

실제 엔진 진단: 원본에서 주인공 승리도 공용 arena_end.png인 증상을 확인했다. 수정본은 주인공·노예·조수 각 승패6경로를 실제 전투 복귀부터 실행하고 각 화면을 한 번 더 표시했다(12회 렌더). 기대 PNG 경로·로딩완료·자연크기 및 표시크기795×596, 하단 글자 범위, 기존 기본XP·복귀 초기화가 모두PASS다. 도주/기절/치명상 패배도 역할별로 한 경로씩 포함했다. 처음 진단은 중첩 bg 안의 작은 도구 아이콘을 배경으로 잘못 집어 검사기만 보완했다. 실제 게임 코드는 그 때문에 바꾸지 않았다.

출고검사: QSP 구조·줄바꿈/주석경계·패치 재생/재적용·배포 일치·기존 엔진9경로 PASS. 기존SAV7개를 덮어쓰지 않고 해시보존을 확인했다. 이는 격리 엔진의 DOM과 기존 콜백 검사이며 사람의 실제 마우스플레이·모든 기존세이브 불러오기 인증은 아니다.

이미 완료된 결과 페이지에 저장된 세이브는 전투 역할/승패가 초기화되어 당시 그림을 유지할 수 있다. 이를 강제로 고치려고 결과 정산을 다시 실행하면 XP 중복 위험이 있으므로 재실행하지 않는다. 전투 종료 전 저장에서 새 결과 페이지로 진행하면 새 분기가 적용된다. 별도 세이브 호환 도구는 만들지 않았다.

패치는 mods/2026-10-31_colosseum_practice_result_cuts.json과 COLOSSEUM_PRACTICE_CUT / LOSS_CUT1296~1298 마커로 추적한다. 입력은 기존 interaction_city·승패값이고 출력은 기존 full[1] 배열뿐이다. 제거하면 랜덤 공용 종료그림으로 돌아간다. 원본 복구QSP·명세 백업은 verification.json의 외부 backup 경로에 있다. 이미지 목록과 재현조건은 하위catalog 기록에서 관리한다. ZIP·커밋·푸시는 하지 않았다.
