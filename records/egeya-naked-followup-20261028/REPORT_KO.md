# 에게야 기본 이미지 조회: 사용자 승인 후 WORK 반영 완료

현재 JSON과 이미지 파일이 모두 있어도, 조수 외형을 알몸으로 선택한 뒤 팩에 없는 실제 의복이 남아 있으면 옛 기본 그림으로 빠지는 경로를 재현했다. 사용자 승인 후 기본 조회키 한 줄을 WORK에 반영했다.

`display_fullimage`는 조수의 표시 역할 키가 빈 경우에도 빈 키를 resolver에 넘겼다. 이 때문에 현재 기본 주소를 개인팩의 기본 이미지로 해석하는 기존 규칙을 건너뛰었다. 후보는 빈 조수 역할 키를 `fullimage`로 넘기는 한 줄 수정이며, 새로운 기능·저장 변수·로케이션은 없다. 원래 의복 값이나 능력치를 변경하지 않는다.

- 기준 WORK: `e620353d0db6374ae293c6919d511966c31e2bb68ebd1763bb5a956bec069ba0`
- 격리 후보: `f6520ef11a720f6d15127738032be960acc1153eb653e2760495b880e85cef97`
- 패치 식별명: `ASSISTANT_DEFAULT_IMAGE_LOOKUP_20261028`
- 상태: **APPLIED — 사용자 승인 후 WORK 반영 완료**. 확정 JSON은 mods에 등록했다. 설치 결과는 검증 후보와 바이트가 같다. `installation.json`과 `MANUAL_KO.md`에 적용·백업·보존 정보를 기록했다.

현재·후보 각 240개 경로, 실제 알몸 버튼의 대입문 각 5개, 직접 resolver 각 5개, 보존 사례 각 13개를 격리 실제 엔진에서 비교했다. 의도한 기본 fallback 9개만 달라졌고, 다섯 역할의 23개 데이터 묶음 비교 10건은 동일했다. 의복·표시 모드·인물 데이터·사용자 지정 이미지·기존 하녀/비서/도미나 연결을 유지했다. 독립 검토에서 추가 수정 사항은 없었다.

공식 출고 검사도 후보에 대해 PASS다. 파일 구조·줄 경계·바이트 재생·재적용과 설치 엔진의 필수 9경로가 통과했다. 배포본 동기화는 지정하지 않았으며 검사하지 않았다. 동적 코드 전체와 모든 게임 분기의 문법이 증명된 것은 아니다.

옛 `girls/full/maid/kirakira` 캐시는 별도의 legacy 분기에서 정규화되는 기존 제한이 있으며 이번 한 줄은 이를 바꾸지 않는다. 개인 세이브를 GUI로 불러온 검사·전체 로드 갱신·실제 픽셀 확인은 하지 않았다. 현재 캐시 문제를 재현한 결과와 과거 저장 전체에 대한 보장을 구분한다.
