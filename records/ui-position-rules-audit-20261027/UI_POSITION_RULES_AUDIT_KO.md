# UI 위치 규칙 감사 결과

2026-10-27. WORK QSP 273개 로케이션과 CSS 3개를 정적으로 대조하고, 프로필 CSS의 실제 적용 범위를 설치 엔진에서 검사했다. 운영 파일은 수정하지 않았다.

## 결론

공통 배치 함수와 화면 규격은 이미 있다. 그러나 엔진 영역 좌표, CSS, QSP 인라인 스타일에 위치 결정이 분산되어 있고 화면별 초기화 범위도 다르다. 같은 값을 여러 곳에 복제하고 후속 CSS로 덮는 구조이므로, 한 곳만 수정하거나 이전 화면 값을 상속하면 틀어질 여지가 있다. 반복 규칙을 명시하고 소유자를 하나로 정리할 근거가 확인됐다.

이번 게임오버 수리는 해당 전체 화면의 원점을 분리한 국소 수리다. 프로젝트 전체의 좌표 소유권을 통일한 작업은 아니다.

## 확인한 분산과 중복

| 대상 | 확인된 현황 | 의미 |
|---|---|---|
| 엔진 화면 영역 | 좌표 직접 대입 96건이 17개 로케이션에 있음 | 공통 함수 밖의 직접 설정과 화면 진입별 초기화 책임을 함께 봐야 함 |
| 공통 배치 함수 | `_layout`, `main_layout`, `stats_layout`, `demo_layout`, `раскладка_бой` 5개, 직접 호출 52곳 | 공통 틀은 있으나 같은 본문 사각형이 여러 함수에 복제됨 |
| QSP 내부 배치 | 파싱 가능한 인라인 배치 태그 619개, 28개 로케이션 | 아이콘 치수·툴팁 relative·동적 표현도 포함하므로 전부 절대 좌표 중복이라는 뜻은 아님 |
| 개인실 반복 | 개인실 1~4와 신축 개인실의 배치 태그 22개씩, 5곳 모두 구조가 동일 | 역할별 아이콘 치수 class부터 공통화 가능; 인물·방 소유 로직을 합칠 이유는 없음 |
| CSS 중복 | 같은 선택자 반복 347그룹, 정규화 후 서로 다른 배치 값 200그룹 | 의도된 버전 보정·상태별 배치도 포함하며 버그 개수가 아님 |

예를 들어 시설 `#cage`의 현재 배치는 `mainScreen.css`, 원래 `base.css`, V193, V196 보정을 함께 읽어야 한다. 귀가 버튼도 원래 `(915,695;100×100)`에 후속 `(923,716;72×72)` 보정이 있다. 현행 화면이 틀렸다는 뜻은 아니지만, 최종값을 소유하는 위치가 명료하지 않다.

## 확정된 적용 범위 불일치

`jo9_traits_view.css`는 주석상 프로필에서만 로드된다고 되어 있지만 현재 엔진은 프로필이 아닌 장면에서도 이 파일의 규칙을 불러온다.

실제 엔진의 프로필 DOM도 없고 명시 CSS 링크도 없는 장면에서 다음을 확인했다.

- `#jo9_tv_panel` 규칙들이 이미 CSSOM에 존재했다.
- 기본 `body::before`의 `top:45px;height:755px` 뒤에 프로필 파일의 `top:0;height:800px`이 적용됐다.
- 최종 테두리 값도 `top:0;height:800px`이었다.

따라서 파일을 분리한 것만으로 화면 범위가 제한되지는 않는다. 프로필용 테두리 규칙은 실제 프로필 root 아래에서만 성립하도록 정리할 대상이다. 반면 `#__message__`의 최상위 z-index는 네이티브 팝업을 특성창 위에 놓기 위한 의도적 공용 규칙이므로 함께 제거하면 안 된다.

근거: `runtime-stylesheet-scope.json`. 설정의 UTF-16LE BOM과 실제 1280×800 뷰포트까지 확인했다.

## 이전 화면의 값 상속 후보

- 전투 배치 함수는 `MSG_X=350`을 지정하지만 본문 `MAINDESC_X/Y/W/H`는 다시 지정하지 않는다. 전투 root는 absolute이므로 본문 원점을 상속한다. 앞선 실제 엔진 검사에서 전장 설계 `(242,0)`이 `(243,1)`로 측정된 것은 본문 `(1,1)`이 더해진 결과다.
- 전투·경주 뒤에 `main_layout` 또는 `stats_layout`만 부르면 일반 메시지 위치 `MSG_X=200`을 복구하지 않는다. 상속 경로는 있으나 실제 사용자 메시지가 잘못 뜬다는 재현까지 완료한 것은 아니다.
- `_layout`, `$addon`, `$ongload`의 메시지 값 중복에는 기존 세이브의 퇴역한 UI를 복구하는 목적이 있다. 값을 공통화하더라도 로드·업데이트 시 재초기화하는 호출은 유지해야 한다.

## 통일할 규칙 제안

1. **엔진 바깥 영역은 QSP 공통 초기화가 소유한다.** 화면 진입 때 본문·보조정보·팝업 등 그 화면에서 사용하는 값이 이전 화면 상태에 의존하지 않도록 한다. 기존 세이브 복구 진입점도 같은 설정을 호출하도록 정리한다.
2. **영역 안 배치는 화면 root 아래의 CSS가 소유한다.** 일반 컷신·인물 정보·전투·전체 화면·팝업의 원점/크기/레이어 규격을 따로 둔다. 서로 다른 용도의 숫자를 일괄 동일하게 바꾸지 않는다.
3. **각 컴포넌트의 최종 좌표를 한 곳으로 모은다.** 기존 운영 화면의 최종 모양을 기준으로 시설·귀가 버튼·아이콘 등의 누적 보정을 정리한다. QSP는 등장 조건·문구·선택지와 화면 종류를 선택하고, 고정 치수를 매번 복사하지 않는다.
4. **화면 전용 규칙은 선택자로 범위를 제한한다.** CSS 파일명이나 주석에 의존하지 않는다. 의도된 공용 메시지 규칙은 별도 목록으로 유지한다.
5. **규격 위반을 검사한다.** 화면 원점 이동 후의 그림/패널 경계, 화면 밖 넘침, 팝업과 닫기 링크의 클릭 가능성, CSS의 다른 화면 침범을 실제 엔진에서 비교한다. 자동 정규식만으로 모든 동적 배치를 증명하지 않는다.

우선순위는 확인된 프로필 CSS의 전역 영향 제한 → 공통 화면 초기화 책임 정리 → 반복 아이콘 치수와 컴포넌트별 CSS 중복 정리다. 새 UI 전면 개편이나 새 영구 저장 변수 없이 점진적으로 진행할 수 있다. 이번 요청에서는 이 정리를 실행하지 않았다.
