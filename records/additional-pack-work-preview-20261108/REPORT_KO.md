# 추가 이미지팩 미리보기 · WORK 설치 기준

2026-11-08 사용자 지시: 이미지 패치리스트의 추가 이미지팩을 현재 WORK 설치본 기준으로 표시한다.

## 원인과 변경

추가 이미지팩 27명/108개 파일의 렌더러가 `img.src=f.preview`로 과거 HTML 내장 썸네일을 표시하고 있었다. 현재 WORK 파일 108개는 모두 존재하고 각 인물 JSON의 전신·초상 참조와 일치했으나, 이 중71개가 목록에 마지막으로 기록된 WORK 해시와 달랐다. 브라우저에서도108개 이미지가 모두 data URL임을 확인했다. 원본 JO9O 폴더를 읽는 문제라기보다, 팩/과거 시점에 고정된 썸네일을 계속 보여 주던 문제다.

미리보기 src를 기존 `url(MR + runtimePath)` 경로로 바꿨다. 현재 HTTP 카탈로그에서 이는 `original=0`인 WORK 전용 이미지 API로 변환된다. 서버가 이미 `Cache-Control: no-store`로 제공하므로 같은 경로의 파일을 교체한 뒤 목록을 다시 펼치거나 새로고침하면 WORK의 새 파일을 읽는다. 이전 썸네일로 자동 대체하는 코드는 없다. 누락 시 WORK 파일 없음으로 표시한다.

사용하지 않는 내장 미리보기108개를 목록 데이터에서 제거하고 현재 WORK 크기·해시·차원을 갱신했다. 팩 원본의 경로·번호·원본 해시 등 출처 기록은 유지했다. 본래 이미지 파일은 변환·교체·이동하지 않았다.

수정 파일은 두 곳이다.

- WORK: `G:/somi/Jack O Nine Tails v2.4_work/game/modtools/catalog/catalog_merge_vs_original.html`
- 추적 소스: `G:/somi/JO9sa/tools/local-workspace/catalog-seed/catalog_merge_vs_original.html`

추가팩의 데이터와 렌더러 밖 HTML은 동일하다. 일반 이미지 카드의 원본 비교, 체크 상태, 메모, 이미지·인물 JSON·QSP는 그대로다. 서버 코드와 실행 프로세스도 바꾸지 않았다. Full·ZIP·커밋푸시 변경은 없다.

## 사용과 복구

추가 이미지팩을 펼치면 현재 WORK 파일을 읽는다. 같은 경로의 이미지 교체는 목록을 다시 펼치거나 새로고침해 반영한다. 파일명이나 인물 JSON 참조 자체가 변경되면 추가팩 목록의 runtimePath도 별도로 갱신해야 한다. 이번108개 경로는 현재 JSON 참조와 일치한다.

installation.json에 각 HTML의 직전 해시·설치 후 해시와 압축 백업 경로를 기록했다. 복구 전 현재 해시가 설치 후 해시와 같은지 확인한다. 이후 HTML 변경이 있으면 백업 전체를 덮어쓰지 말고 이번 추가팩 데이터/렌더러 변경만 되돌린다. 체크 상태나 게임 이미지를 복구 대상에 포함하지 않는다.

재현·설치 스크립트는 task.cjs, HTTP 대조 결과는 verification.json, 화면 예시는 작업 결과의 work-preview.jpg에 보관했다. task.cjs의 install은 과거 renderer가 있는지 검사하는 일회용 설치이며 이미 적용한 파일에는 중단한다.
