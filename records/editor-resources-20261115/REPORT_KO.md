# 캐릭터 얼굴 테두리·이미지 검색 연결·게임 리소스 입력

사용자 요청: 2026-11-15. 통합 도구와 WORK/modtools 코드만 갱신했다. 게임 QSP, JSON, 이미지, 개인 세이브, Full 배포, 기존 ZIP은 변경하지 않았으며 커밋·푸시하지 않았다.

## 아프리카인 복장 표시

2586/2587/2588의 기존 fullmade/fullsecretary/fullmistress/indpack_title 경로와 12개 파일이 존재했다. 사용자는 이미지 편집 전부터 게임을 켜 두었으며, 재접속 후 정상 표시됨을 확인했다. 이 제보 때문에 게임 코드나 저장 데이터를 수정하지 않았다.

## 사용법

1. 캐릭터 편집 → 외형 → 원하는 옷차림 → 기존 이미지 정렬 → 얼굴 상자로 만들기. 새 얼굴 151×150의 가장자리 5px에 게임 기본 테두리를 합성한다. 얼굴 파일 선택에도 적용한다. 색상·흑백·세피아 저장은 기존 서버 기능을 사용하며, 실제 파일 저장은 외형 저장을 눌렀을 때만 한다. 기존 얼굴 파일을 일괄 덮어쓰지 않는다.
2. 캐릭터 상단의 **이미지 검색어 보내기**를 누르면 이미지 작업 → 체크리스트 → 전체 이미지 검색창에 파일명 계열 키워드를 채운다. 예: african3. 번호가 있는 전용 캐릭터 경로는 번호를 사용한다. 자동 검색이나 입력 이벤트를 발생시키지 않는다. 사용자가 **검색**을 누른다.
3. 체크리스트 교체 창 또는 독립 이미지 교체기에서 **게임 이미지 사용**을 누른다. 현재 연결된 PIC의 파일명/경로 후보를 확인하고 이미지 선택 → **이 이미지를 소스로 넣기**를 누른다. 같은 이름이어도 폴더별로 구분한다. 이 단계는 파일을 읽어 교체기의 입력으로 넣을 뿐이다. 기존 교체기의 같은 이름 매핑·얼굴 영역·베리에이션·규격 맞추기·백업 후 교체 절차는 그대로다. 적용 전 교체 경로와 체크된 베리에이션을 확인한다.

열려 있던 도구는 작성 중 내용을 저장한 뒤 새로고침하거나 전용 앱을 다시 열어 새 코드를 읽는다. 사용자가 작업 중인 탭은 자동 새로고침하지 않았다.

## 구조와 의존성

- `tools/modding-hub/overrides/studio-look.mjs`: `ensurePortraitFrame`이 기존 `/game/content/pic/girls/face/0001_black_long_loli.png`의 외곽 테두리를 읽는다. `framePortrait`가 151×150 얼굴의 외곽만 합성한다. 모든 옷차림의 얼굴을 기존 API의 `face.mode=file` 계약으로 전달하므로 새 JSON 필드·저장 형식은 없다. 기본 이미지가 없으면 안내 오류를 내며 테두리 없는 새 얼굴로 조용히 진행하지 않는다.
- `server.py`: 원본 `studio-view.mjs`의 시뮬레이터 버튼 앞에 검색어 보내기 버튼을 제공 시점에 삽입한다. Claude 원본 파일은 수정하지 않는다. `integration.mjs`는 이미지 파일명에서 키워드를 계산하고 체크리스트의 정확한 loopback origin으로 메시지를 보낸다.
- `tools/text-workshop/catalog-search-bridge.js`: embedding parent의 localhost 메시지만 받아 전체 이미지 탭을 연 뒤 입력값·포커스·안내만 갱신한다. 검색 호출·변경 이벤트는 보내지 않는다. `server.cjs`가 카탈로그 shell에서 로드한다.
- `tools/text-workshop/catalog-resource-source.js`: 기존 `window.JO9Workshop` 공개 인터페이스의 `state.root/index`, `screen.resources`, `add`를 사용한다. 디렉터리 핸들에서 선택 파일을 읽고 기존 입력으로 전달한다. 파일쓰기·서버 API를 새로 만들지 않았다. 선택/닫기 때 object URL을 정리한다. 첫 100개 후보를 표시한다.
- `tools/image-workshop/catalog-resource-source.js`는 동일 플러그인 사본이다. 독립 place HTML은 이 파일을 로드하고 `Open-Modding-Tools.ps1`이 WORK/modtools에 코드만 배치한다. 생성된 `catalog_editor.js`와 기존 변환·백업 코드는 수정하지 않았다.
- 제거 시 해당 플러그인 script와 버튼 주입을 함께 제거하면 새 편의 기능만 사라진다. 원본 도구와 기존 저장자료는 남는다. 백업 `*.before.gz`와 `changes.diff`를 대조하여 블록 단위로 복구한다. 이후 사용자 수동 변경이 있을 수 있으므로 전체 파일을 무조건 덮어쓰지 않는다.

- 관련 자동 검사: 다섯 옷차림에서 151×150 얼굴 출력·테두리 합성 호출·원본 선택 유지, 검색어만 전달/외부 메시지 거부, 동일 파일명 경로 구분, 키워드 추출. `tests.log`를 따른다.
- 실제 브라우저: 2588 하녀 이미지를 얼굴 원본으로 선택하고 자동 금색 테두리 미리보기를 확인한 뒤 변경을 버렸다. 저장하지 않았다.
- 실제 통합 화면: `african3` 입력 및 검색 안내, 아직 필터되지 않은 전체 목록을 확인했다. iframe 내부 클릭 자동화의 target unavailable 오류로 후속 소스 선택은 같은 카탈로그를 독립 탭에서 확인했다.
- 실제 독립 카탈로그: 검색 → legacy_overhaul/african3.png 교체 → 게임 이미지 사용 → 같은 이름 12개 후보 → girls/face/african3.png 미리보기 → 입력 1장/매핑 1장/대상 6개 확인. 시험 입력을 빼고 닫았다. 변환·파일 교체·백업 쓰기는 실행하지 않았다.
- JS/Python/PowerShell 문법 및 실제 제공된 studio-view.mjs 구문 확인. 기본 도구 구동과 플러그인 HTTP 200 확인. 전체 게임 엔진 검사는 게임 동작을 바꾸지 않았으므로 반복하지 않았다. 실제 얼굴 저장 후 게임 표시와 전용 앱 재실행 화면은 이번에 확인하지 않았다.
