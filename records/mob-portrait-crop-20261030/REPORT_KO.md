# MOB 포트레이트 얼굴 선택·자동 프레임 — 2026-10-30

WORK 이미지 리스트에 반영했다. MOB 세트의 초상화 PNG 교체/추가에서 얼굴 영역을 정사각형으로 선택한 뒤, 현재 배정된 프레임이 자동 적용된 150×150 미리보기를 확인하고 저장한다.

## 사용법

이미지 리스트를 새로고침 → MOB 초상화의 PNG 교체 → 원본 PNG 선택 → 얼굴과 머리카락을 포함하도록 범위를 드래그·모서리 조절·슬라이더로 맞춤 → WORK에 반영. 방향키는 미세 이동, Shift+방향키는 큰 이동이다. 취소 또는 ESC는 저장하지 않는다. 편집 중에는 실제 게임 PNG를 바꾸지 않는다.

시작 범위는 상단 중앙을 기준으로 한 추천값이며 얼굴 검출 결과가 아니다. 선택한 이미지의 배경과 투명도는 유지한다. 이 기능에서 배경 분리나 생성형 재작화는 하지 않는다.

## 변경과 보존

- 소스: tools/mob-image-sets/catalog-mob-sets.js, portrait-crop.js, frame-data.json, geometry.test.cjs, build-portrait-assets.cjs, README_KO.md.
- WORK 카탈로그와 tools/local-workspace/catalog-seed의 같은 MOB UI 블록을 갱신했다. 카탈로그 D행·MOB manifest·분류·체크 상태는 그대로다.
- 기본/언데드/중고위급/콜로세움/경주 프레임 5종은 2026-10-29 승인된 원본에서 추출했다. 프레임 PNG의 얼굴 영역 RGBA는 전부 0이며 원래 얼굴이 데이터나 새 결과에 남지 않는다.
- 실제 MOB 목록의 78개 역할·75개 초상 경로는 기존 frameClass로 자동 선택한다. 경주 프레임은 준비되어 있지만 이 전투 전용 목록에 경주 전용 인물을 추가하지 않는다.
- 원본 얼굴 영역을 프레임 구멍에 맞춰 고품질 축소한 뒤 외곽 RGBA를 원본대로 보존한다. 선택 범위 밖 이미지를 프레임 속에 섞거나 옛 얼굴을 합성하지 않는다.
- 기존 전신·패배·단체 컷의 795×596 처리, 서버 PIC writer, 원본 해시 충돌 거부·백업·개인 패치 기록을 재사용한다. 서버 코드나 API·QSP·세이브 구조는 바꾸지 않았다.
- 설치 과정에서는 운영 초상 75개와 QSP, 카탈로그 체크 상태를 바꾸지 않았음을 SHA-256으로 확인했다. 실제 교체는 사용자의 최종 반영 버튼에서 기존 writer가 수행한다. 배포/ZIP·커밋·푸시는 하지 않았다.

## 검사 결과

수정 전 격리 브라우저에서 얼굴 선택 창 부재로 회귀 검사가 실패하는 것을 확인했다. 수정 후 실제 파일 선택기·드래그·슬라이더·초기화·취소·최종 저장을 포함한 브라우저 확인 12개가 통과했다. 5종 프레임 외곽 픽셀 일치, 옛 얼굴 미노출, 동시 수정 거부, 누락 초상 생성, 백업·패치 원장, 전신/패배 기존 처리 유지도 확인했다.

기하 경계 및 기존 PIC writer 테스트 7개 통과. 독립 검토에서 20,000개 유효 크기 조절 조합을 확인했다. 검토 중 PNG 인코딩 대기에서 범위가 바뀔 수 있던 경합을 발견해 반영 직전 선택을 고정하고 편집을 잠갔다. 취소는 계속 허용한다. 지연 인코딩을 넣은 브라우저 재검증을 통과했다.

실제 http://127.0.0.1:3813/catalog?mobsets=1 에서 PNG 선택·기본 프레임 미리보기·슬라이더 조절·취소까지 확인했다. 운영 apply 요청은 0회였으며 운영 PNG를 시험 교체하지 않았다. 운영 페이지의 JS 오류는 0개다. 실제 프레임 출력은 150×150 및 3배 연락표로 육안 확인했다. 모든 사용자 업로드 원화의 시각적 적합성이나 게임 전체 플레이를 검증한 결과는 아니다.

## 유지보수·복구

portrait-crop.js의 open 입력은 PNG File, 대상 path, shared, frameClass이다. 취소 시 null, 승인 시 blob/data와 선택 범위를 돌려준다. 기존 replace 함수가 그 PNG를 PIC apply로 전달한다. 새 저장 변수나 서버 의존성은 없다. Canvas·Image.decode·dialog·Pointer Events·PNG 인코딩을 사용하는 기존 브라우저 환경에 의존한다.

frame-data.json과 helper는 catalog-mob-sets.js 안의 생성 블록에도 포함돼서 기존 카탈로그 재생성 흐름이 소스 JS 하나를 삽입해도 작동한다. helper/프레임을 수정했다면 `node tools/mob-image-sets/build-portrait-assets.cjs --write` 후 `--check`와 테스트로 대조한다. 독립 helper만 지우면 재빌드·기하 테스트가 불가하고, 삽입된 생성 블록까지 지우면 포트레이트 교체가 실패한다. 전신·패배 교체와 PIC writer는 별도다.

설치 백업은 G:/somi/JO9_work_backups/mob-portrait-crop-20261030에 압축 보관했다. 복원 전 installation.json의 현재 해시를 대조해 이후 수동 UI 편집을 보존해야 한다. HTML 전체를 오래된 백업으로 무조건 덮어쓰지 않는다. 새 기능만 해제하려면 해당 생성 블록과 MOB 포트레이트 분기를 함께 기존 코드로 되돌린다. 사용자 원화·게임 이미지·세이브는 삭제 대상이 아니다.
