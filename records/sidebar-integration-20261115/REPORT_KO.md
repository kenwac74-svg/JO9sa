# 사이드바 통합 및 전용 창 실행 기록

2026-11-15 사용자 지시: 클로드 편집기 디자인과 기존 도구 기능을 유지해 사이드바를 통합한다. 기타 산출물은 맨 아래에 놓는다. 미정 기능은 구현하지 않는다. 후속 지시로 주신 ZIP의 별도 앱 창/포트 충돌 처리도 지원한다.

## 반영

새 `tools/modding-hub/` 서버·사이드바·산출물 목록·브라우저/앱 실행기를 추가했다. 기존 `Open-Modding-Tools.ps1`는 실제 준비된 도구 URL을 전달하고 통합 화면을 연다. 전용 창은 `-AppWindow` 또는 `통합작업실_앱창.cmd`로 연다. 원래 서버와 API를 상속하며 원본 UI 파일에 기록하지 않는다. 통합 화면용 프레임 제한만 대사·폴더 비교 서버에 추가했다.

캐릭터·시뮬레이터·대사·이미지·산식·게임 DB·일정·기타툴·기타 산출물의 9개 메뉴를 연결했다. 배경 설정/특성 편집/인터뷰 DB/뽑기 분포는 정한 하위 메뉴에 있다. 산출물 35개가 검색·분류·선택된다. HTML은 원래 파일을 읽고 file URL을 응답에서만 변환한다. 별도 MD/CSV 부속물은 이번 열람 확장 범위 밖이다.

## 실행·확인

- 브라우저 주소 유지: `http://127.0.0.1:7689/`. 기존 브라우저 저장소를 유지했다.
- 앱: 원본의 7719~7729 빈 포트 선택·`.app-data/` 저장·종료 시 앱 서버 종료를 재사용한다. 브라우저 설정은 자동 이관하지 않는다.
- 7719 임시 점유 → 7720 실행 확인(`app-port-check.json`). 이후 7719로 다시 실행했다. 기본 포트의 다른 프로그램은 종료하지 않았다.
- 앱의 첫 WinForms 창까지 숨기는 문제를 피하려고 `pythonw.exe`로 콘솔 없이 실제 앱 창을 표시한다. 셸 실행기는 숨긴다.
- 수정 PowerShell·JS·Python 구문 검사 통과. 기존 단위 검사 4개 통과 기록 재사용(목록·등록 경로·중복·경로 거부·URL 변환).
- 브라우저: 기존 캐릭터 화면, 대사 편집실, 이미지 폴더 비교, 이미지 교체 작업실, 게임 DB, 작업 일정, 기타툴, 산출물 카탈로그 표시 확인. 대표 초상 2개의 naturalWidth 150/151 확인. 게임 반영 버튼은 조작하지 않았다.
- 원본 모듈 8개 및 WORK QSP SHA-256 불변. 신규 원본 JSON·이미지·SAV·배포 ZIP·음원 변경 없음. 커밋/푸시 없음.

## 미확인·사용자 확인

첫 앱 창에서 구형 작업대 초기 `Failed to fetch` 알림을 관찰했다. 연결된 4개 JSON은 HTTP 200/정상 JSON이다. 표시 방식을 수정하고 앱을 재실행한 뒤, 컴퓨터 제어 승인 시간이 만료돼 최종 앱 내부를 확인하지 못했다. 자동 승인 검토의 거절과는 다르다. 재발 여부는 미확정이다. 전용 창에서 배경 설정 목록·대사 편집의 두 화면과 초기 경고만 확인하면 된다. 브라우저에서는 관련 메뉴가 표시됐다.

캐릭터 편집/각 기존 도구의 저장·변환·게임 반영을 다시 실행하지 않았다. 이번 변경은 기존 작업 자료·산식·대사/변수 설계·게임 동작을 고치는 작업이 아니다. 전체 게임 엔진 출고 검사는 해당하지 않는다.

## 변경 지점·복구·자료 정리

구현과 호출 흐름은 `tools/modding-hub/README_KO.md`를 따른다. 통합 코드를 제거하면 새 메뉴가 사라지고 원래 도구 실행기를 사용한다. 진입 실행기와 두 프레임 제한의 이전 파일은 이 폴더의 gzip 3개에 보존했다. 이후 수동 변경을 덮어쓰지 말고 해당 변경 블록만 대조한다. 임시 편집 사본은 정리하고 운영 중인 클로드 원본 사본·기록·원본 ZIP·사용자 설정·스크린샷은 보존한다.
