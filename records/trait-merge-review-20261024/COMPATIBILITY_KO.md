# 완전한 사육·노예근성 통합 호환성 검토

상태: 읽기 전용 조사 완료, 게임·세이브 변경 없음. 아래 명칭과 통합 방안은 제안이며 적용하지 않았다.

원천: 최신 WORK jack.qsp, SHA-256 `afb2b9eccbe02193f77fefea4a990081616a79eb84ed14fe2d8f0bbd3cf2d1fc`. 위치별 줄 번호는 복호화한 location 본문의 1 기준이다.

## 결론

두 항목은 저장 상태와 효과가 다르므로 지금은 분리 유지가 가장 안전하다. 기존 항목을 ‘규율 준수’처럼 지속적인 규율 성향을 나타내는 명칭으로 바꾸는 안을 제안한다. 신규 ‘노예근성’은 영입 당시 적응을 보정하는 1회성 특성이다. 구형 디버그의 servile 상태도 같은 ‘노예근성’이라는 이름을 사용하므로, 이 상태에는 별도의 명칭을 검토할 수 있다. 명칭 변경도 아직 적용하지 않았다.

## 세 개의 개념

| 개념 | 저장 키 | 저장 의미 |
|---|---|---|
| 기존 완전한 사육 | meekness, meekness_revealed | 양수/0/음수인 연속 축. 음수는 자유로운 영혼이며 발견 상태가 따로 있다. |
| 신규 노예근성 | jo9_slave_nature, jo9_slave_nature_initialized | 특성 플래그와 영입 시 1회 초기화 완료 여부. 영구적인 복종 강제가 아니다. |
| 기존 정신 상태 | $역할_psy_status = servile | 현재 정신 상태. 위 신규 플래그와 별개다. |

meekness는 기존 복종 계산에 수치 그대로 더해지고, 발견된 양수는 명망 +1, 마차 조종성 +1 효과도 가진다. 음수는 조종성 -1이다. 근거: #static_base:1315–1345, 1577; $ride_start:11–21. 신규 플래그는 jo9_traits:342–405에서 여러 기초/누적 수치를 영입 시 한 번 조정하고 완료 표식을 남긴다. 이후에는 일반 플레이로 수치가 변할 수 있다.

## 고정 JSON 조사

game/json/slaves의 JSON 1,126개 모두 정상 파싱했다. 아래 수는 서로 다른 NPC 인원수가 아니라 파일 수다. 변형·프리셋 중복을 제거하지 않았다.

| seed_meekness 상태 | JSON 수 |
|---|---:|
| 양수 | 78 |
| 음수 | 8 |
| 명시적 0 | 2 |
| 키 없음 | 1,038 |

양수 값 분포는 1:56개, 3:1개, 4:17개, 5:1개, 6:3개다. 음수는 -1:7개, -5:1개다. 양수 78개 모두 seed_ego와 seed_pride가 명시되어 있으며, 그중 34개는 ego≥4 또는 pride≥4여서 새 노예근성의 부여 조건과 충돌한다. 양수이면서 seed_defiant=1인 JSON은 0개다. 이미 발견 상태가 2인 양수 JSON은 2개이며 두 개 모두 새 자아/태도 제한과 충돌한다.

신규 노예근성 키는 이 JSON에 없고, get_stock_seed:98–101도 새 플래그와 완료 표식을 0으로 초기화한다. 따라서 고정 양수 78개를 신규 플래그로 무조건 치환하면 기존 고정 설정을 바꾸는 작업이 된다. 키 없음은 다른 생성 경로에서도 영원히 없다는 뜻이 아니다.

## 기존 세이브 조사

WORK/save의 .sav 76개를 모두 정상 파싱했다. 이름·인물 ID·대사·세이브 파일명은 결과에 기록하지 않았다. 주 노예·조수·개인실·감옥·외양간·냉동 보관·특수 임시 보관 역할을 검사했다. EGO/RATIONAL/MEEKNESS가 존재하고 역할_state>0인 점유 배열만 집계하여 비활성 잔여 배열 7개를 제외했다. STOCK와 SLAVE1 같은 생성·관계 계산용 사본은 제외했다.

단위는 서로 다른 인물 수가 아니라 세이브별 역할 스냅샷이다. 같은 인물이 여러 파일에 반복되며 생성 테스트도 포함된다.

## 통합 시 주요 위험

1. **기존 조건 충돌**: 고정 JSON 34개와 양수 점유 스냅샷 118건은 신규 부여 제한에 맞지 않는다. 조건을 기존 인물에게 소급하면 기존 특성을 지우거나 자아/태도를 바꾸게 된다. 통합을 별도로 승인한다면 기존 인물은 보존하고 새 부여에만 제한을 적용하는 구분이 필요하다.
2. **초기화 소급과 반복 적용**: 새 플래그=1, 완료=0으로 이전하면 rational/custom/moral/instinct, 감정 수치와 해당 누적값 등이 영입 초기화 루틴에 의해 바뀔 수 있다. 이를 매 갱신 실행하면 현재 존재하지 않는 영구 복종 효과가 생긴다. 이미 완료된 특성은 이후 일반 수치 변화를 허용해야 한다.
3. **수치 손실**: 기존 양수 1·3·4·5·6을 bool 1로 바꾸면 기존 복종 보너스의 강도를 잃는다. 기존 값에 다시 새 보너스를 더하는 방식도 의도하지 않은 중첩을 만들 수 있다. 현재 양수와 신규 특성의 동시 보유 자체는 서로 다른 두 효과가 함께 있는 것이며 곧바로 버그라고 단정할 수 없다.
4. **반대 축 손실**: meekness 음수는 독립적인 자유로운 영혼이다. jo9_traits:81–88의 신규 추첨은 음수 meekness를 제외하지 않으므로 음수+신규 조합도 소스 조건상 가능하다. 표본에서 0건인 것과 생성 불가능은 다르다. bool 통합은 이 음수 상태를 파괴할 수 있다.
5. **표시와 슬롯**: 현재 두 항목은 독립적으로 목록에 붙는다(#static_base:1930, 2102–2106). 이 경로에는 고정 특성 슬롯 상한이 확인되지 않았고, 길이 666을 넘으면 글씨를 줄이는 처리만 있다(2193). vb_cycle_skill의 5는 색상 번호이며 슬롯 수가 아니다(96–98). 병합은 표시 한 줄을 줄이는 효과는 있지만 기능 보존과는 별개다.
6. **원복**: 원래 meekness/revealed/신규 플래그/완료 값과 초기화로 변한 기초·누적값을 보존하지 않으면 정확한 원복이 어렵다. 표시 명칭만 조정하는 안은 저장 수치를 바꾸지 않아 되돌리기 쉽다. 역할 이동은 전체 배열을 복사하므로 기존 키를 유지하는 방식은 저장/교대 경로와 잘 맞는다(#static_base:449–473).

## 제안과 검증 범위

우선은 기능·저장 키를 분리한 채 이름과 설명만 명확히 하는 방안을 권한다. 기능 통합을 선택한다면 기존 양수/음수와 발견 상태를 유지하고, 기존 인물 예외·신규 부여 규칙·중복 시 우선순위·초기화 소급 여부를 별도 승인한 뒤 설계해야 한다.

정적 소스 추적과 세이브 읽기만 수행했다. 빠른 선택 필드 판독기는 기존 save-codec.cjs와 약 49 MB 세이브의 모든 대상 변수를 대조해 일치 확인했다. 76개 세이브 파싱과 1,126개 JSON 파싱이 통과했고 조사 중 세이브 수정 시각은 모두 변하지 않았다. 게임 QSP 해시도 조사 전후 동일하다. 실제 플레이·이전 변환 실행은 하지 않았다. 생성한 게임 시험 사본과 임시 추출본은 없으며 핵심 보고서 두 개만 남겼다.

## 선천·후천 구분에 대한 보완

신규 노예근성은 사용자 기획상 선천적인 성향이다. 현재도 발견/생성 시 플래그를 부여하고 영입 때 1회 보정하는 구조다.

기존 완전한 사육은 현재 코드에서 후천 훈련으로 획득하는 특성으로 확인되지 않았다. 생성 추첨(generate_stock:1319), seed JSON(get_stock_seed:140, get_special_assistant_quest:271), 고정 stock 프리셋(interaction_city:12828, 이벤트 931), 수동 치트(menu_form:4287–4297)가 값 부여 경로다. 원문 코드가 그 기원을 선천/후천이라고 명시한 것은 아니다.

설정상 기존 항목을 ‘후천적으로 몸에 밴 규율’, 신규 항목을 ‘선천적 노예근성’으로 구분하면 분리 유지의 의미는 분명해진다. 다만 이는 설정 제안이다. 기존 항목이 현재 훈련 중 자동 획득된다고 보고하거나, 별도 승인 없이 새로운 획득 코드를 추가해서는 안 된다.
