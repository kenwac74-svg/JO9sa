# 미스티 초상화 구세이브 호환

미스티(1214)의 전신과 하녀복은 이미 파란 세트로 조회되지만, `jasl.sav`와 `dsdfdsfs.sav`의 조수 슬롯에는 분홍 기본 초상화 3종이 저장돼 있었다. 분홍 세트는 현재 4348도 정상적으로 사용한다.

`$ongload`에서 실행되는 `jo9_load_compat242`에 `MISTY_PORTRAIT_LOAD_20261118` 블록을 넣었다. 기존 로더가 방문하는 각 보유 슬롯에서 캐릭터 ID 1214, 현재 파란 기본 전신 계열, 기존 분홍 기본 초상화의 정확한 경로를 확인한다. 일치한 초상화 값만 파란 기본 경로로 갱신하며 현재 QSP UI가 기대하는 확장자 없는 형식으로 저장한다. 경로 구분자와 대소문자, `.png` 유무를 허용한다. 다른 ID, 별도로 선택한 전신 또는 초상화, 이름과 육성 기록은 유지한다. 갱신은 로드 중 메모리에서 일어나며 이후 게임에서 저장하면 해당 값이 함께 기록된다.

## 이후 이미지 패치 점검

저장소에서 Node.js로 실행한다. 두 인자는 이전 배포본과 현재 게임의 루트이며 각각 `json/slaves`를 포함해야 한다.

```powershell
node tools/qa/character-image-migration-audit.cjs 'G:/이전 배포/game' 'G:/현재 WORK/game'
```

JSON 파일명의 캐릭터 번호 기준으로 기본 전신, 직업·임신 복장, 개별 복장, 초상화 3종의 경로를 비교한다. 경로 추가·제거, 미존재 대상, 중복 번호나 읽을 수 없는 정의를 표시한다. 이전 경로를 현재도 쓰는 다른 캐릭터의 번호도 표시한다. 비교 결과는 해당 필드가 보유 캐릭터 데이터에 저장되는지, 기존 세이브에 이전 기본값이 남는지 확인할 후보 목록으로 사용한다. 같은 경로의 그림 교체는 경로 갱신이 필요 없다.

## 검증

- `jasl.sav`의 실제 조수 필드를 추출하여 격리한 QSP 엔진 5.8 저장·로드 테스트에서 패치 전 불일치가 재현됐다.
- 수정 후 WORK와 추적 소스 각각 9건을 통과했다. 조수·개인실·동면 슬롯, 4348과 사용자 지정값 보호, 재로드, 경로 표기 변형을 포함했다. Windows EXE 화면 확인은 별도다.
- 두 QSP를 각 원본에 독립 적용했다. 기존 패치 도구의 DryRun으로 후보 해시를 확인했고 역적용 결과는 원본과 바이트 단위로 일치했다.
- 비교 도구는 이전 1214의 초상화 3종과 대상 파일, 과거 경로를 공유하는 4348을 식별했다. 현재 배포본과 WORK의 미스티 JSON 경로는 이미 일치한다.
