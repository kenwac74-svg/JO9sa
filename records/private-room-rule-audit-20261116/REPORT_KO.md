## 결론

일반 노예 슬롯에는 두 규칙의 수락/거부 검사, 설명 생성, 일일 효과가 있다. 조수와 개인실에는 같은 처리가 연결되어 있지 않다. 따라서 해당 역할에서는 문구가 새로 생성되지 않는 것과 실제 일일 효과 누락이 함께 발생할 수 있다.

## 정확한 범위

- next_day 2414~2446: toilet_rule 수락·거부·rules_explanations. 2448~2480: urinal_rule의 같은 처리.
- next_day 2643~2657: urinal_rule의 기분·습관·위생·경험 등 효과. 2658~2673: toilet_rule의 같은 효과. 모두 slave 배열에 고정되어 있다.
- 규칙값은 인물 배열 속성으로 저장되지만, 저장되어 있다는 것만으로 다른 역할의 일일 처리가 실행되지는 않는다.

- broken 플래그와 일일 위반 카운터 초기화는 이미 전체 인물 목록을 대상으로 한다. 이 누락을 고치기 위해 새 영구 저장값이나 세이브 변환을 만들 필요는 없어 보인다.

## 무드 문구의 조건

무드 목록은 활성화된 기분 효과를 표시한다. 규칙을 켰다는 사실만으로 항상 해당 무드 문구를 넣지는 않는다.
일반 노예에서도 소변기 규칙은 perversion<1일 때 neg_disgust=최소10, 육변기는 perversion<2일 때 최소20이 된다. 해당 성향 조건이 맞지 않으면 이 불쾌 무드는 생기지 않는다. 기분 계산은 #static_base의 공통 목록에서 활성 키를 읽는다.
주인공의 pos_toilet 무드는 각각 sub_piss>2, sub_kopro>3일 때 생성된다. 규칙 설명 rules_explanations와 무드 목록은 별개다. 규칙 효과는 하루 처리 시점에 평가된다.

## 권고와 검증 한계

두 규칙의 수락·거부·설명·효과만 기존 공통 인물 호출 방식으로 연결하는 수정이 적절하다. 일반 노예의 기존 수치·거부/강제 조건과 다른 규칙은 유지한다.
선택된 기상 담당자의 $jo9_wake_accept는 next_day2098~2101에서 설명과 위반 카운터를 따로 초기화한다. 새 처리를 이 초기화보다 먼저 호출하면 결과가 지워질 수 있으므로 순서를 맞춰야 한다. 다른 모든 규칙을 한꺼번에 이식하는 수정은 이번 제보보다 범위가 크다.
이번에는 실제 사용자 세이브나 엔진 실행으로 하루를 넘기지 않았다. 따라서 특정 세이브의 실제 보유값·성향·현재 무드 상태는 확인하지 않았다. 코드상 역할별 처리 누락은 확인했고, 수정은 아직 적용하지 않았다.
