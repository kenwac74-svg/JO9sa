# MOB PNG 교체 표준 크기 — 소스 구현·검사

현재 상태: WORK HTML의 MOB 블록과 기존 이미지 크기 메타데이터86개를 갱신하고, WORK 설치 PIC 모듈을 동기화했다. 3813 서버만 기존 인자 그대로 숨김 재시작(PID32188→8600)하고 라이브 검사를 통과했다. D·상태·원장·QSP·런타임 이미지는 이 하위 작업에서 변경하지 않았다.

## 변경

- `tools/mob-image-sets/catalog-mob-sets.js`: 초상150×150, 전신·개별패배·단체패배795×596. PNG 선택 후 미리보기 전에 비율 유지 contain으로 조절하며 남는 영역은 투명하게 둔다. 이미 정확한 크기는 재인코딩하지 않는다. 저장 기준 크기와 변환 결과를 표시한다.
- 같은 파일을 공유하는 초상/전신(현재 Grinch.png)은 전신 버튼을 비활성화하고 별도 전신 조회 경로가 필요함을 표시한다. 전신 부족 집계에도 포함한다. 초상150×150 교체는 계속 가능하다.
- 프레임 정리 현황94개 확인/92개 교체와5분류·공유spawn 기본프레임 결정을 MOB 창에 표시한다.
- `tools/text-workshop/pic-local.cjs`: MOB 창에서만 보내는 `mobSlot` 요청을 받는다. portrait→150, standing/defeat→795×596이고 MOB 폴더 또는 기존 characters/mistress_ava 초상만 허용한다. 일반 교체는 기존 크기 제한을 유지한다. Grinch 전신 태그는 서버에서도 거부한다. 백업 원본 크기가 달라도 검증된 restore 경로를 통해 원본 bytes로 복구할 수 있다.

## 검사

변경 전 브라우저 RED: 비표준 크기 선택시 미리보기 창이 나오지 않는 현재 제한을 재현했다.

변경 후 실제 PIC 모듈을 쓴 브라우저 검사10개 PASS:
1. 비표준 전신 미리보기795×596 및 취소시 무변경.
2. 기존1600×1200 전신 교체 성공, old before SHA 보존.
3. 원본 비율과 투명 여백 보존.
4. 초상150×150 변환.
5. 누락 단체패배795×596 생성, null-before/createMissing 보존.
6. 미리보기 후 다른 쓰기로 달라진 파일은 충돌 거부, 경쟁 파일 보존.
7. 크기를 바꾼 전신도 기존1600×1200 원본 bytes로 복구.
8. 일반 업로드 크기 규칙 유지, MOB 밖 태그 거부.
9. 공유 초상 전신 버튼 비활성화와 서버 보호.
10. 실제 백업·이미지패치 원장·복구 원장 보존, 브라우저 예외 없음.

기존 PIC/B컷/원본컷 보호 테스트25개 전부 PASS. `node --check` 두 소스 PASS.

## WORK 통합 순서

1. 현재 WORK HTML/설치 모듈을 별도 백업한다.
2. 실제 파일을795×596로 정규화하고, PNG이름에JPEG bytes가 들어있던 goblin.png도 먼저 정상 PNG로 바꾼다. writer는 기존 파일의 PNG 형식 검사를 유지한다.
3. 현재 WORK HTML 안의 `JO9 MOD START MOB_SET_CATALOG_20261028`부터 END까지를 최신 canonical JS 전체로 교체한다. 다른 HTML·사용자 카탈로그 상태는 보존한다. 추가/기존 manifest 슬롯의 표준 크기 필드도 부모 이미지 작업에서 갱신한다.
4. `tools/text-workshop/pic-local.cjs`를 WORK의 `game/modtools/text-workshop/pic-local.cjs`에 동기화한다. 다른 설치 대상은 현재 실제 실행 경로를 확인해 필요한 곳만 맞춘다.
5. 3813 서버를 재시작한다. `server.cjs:37`은 `require('./pic-local.cjs').create(...)`를 시작시 한 번 호출하므로 기존 프로세스는 파일 복사만으로 새 정책을 읽지 않는다.
6. 기존 도구 실행기/설정을 재사용해 다시 띄우고 카탈로그 새로고침 및 실제 업로드 정규화 경로를 확인한다. QSP를 수정할 필요는 없다.

## 호출·분리 영향

MOB 브라우저 `replace(slot, role, kind)` → PNG 정규화 → 기존 preview 확인 → PIC apply의 한 job에 mobSlot/key와 고정 width,height 전달. PIC의 경로 검증·B컷 보호·before SHA·백업·패치 이력은 그대로 거친다.

JS만 반영하고 PIC 모듈을 반영하지 않으면, 이전 크기의 실제 파일을 표준 크기로 교체하는 요청은 서버에서 거부된다. 반대로 PIC만 반영하면 일반 업로드는 바뀌지 않고 MOB의 기존 JS도 현재처럼 비표준 파일 선택을 거부한다. 둘을 함께 통합해야 한다.

후속 통합에서 위1~6을 실행했다. 새 브라우저로 프레임 현황·실제 이미지의 표준 크기·795×596 자동 미리보기와 취소 무변경·Grinch 공유 경로 보호·실제 로드된 PIC 서버의 MOB 밖 요청 거부를 확인했다. 새 그룹 이미지의 완료 여부는 변경하지 않았다. 사용자에게는 기존 탭 새로고침이 필요하다. 서버 재시작 시 bridge 토큰이 재발급되기 때문이다. 토큰 값은 기록·보고에 출력하지 않았다.

## 최종 후속 검증

서버는 등록된 MOB 경로와 슬롯 역할도 대조하도록 보완했다. 초상을 전신으로, 전신/패배를 초상으로 위장한 요청을 거부하고 원본 bytes를 보존한다. 최종 브라우저 검사는11항목이며 기존 회귀25항목도 다시 통과했다. role-guard-integration.json과 final-live-report.json을 참조한다. WORK 모듈 일치 후3813 서버를 재시작했다. 최종 그림 작업·8단체 제작·QSP 전용 배경은 ../mob-battle-assets-20261029/REPORT_KO.md가 최신이다.
