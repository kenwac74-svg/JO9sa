# 잡파 위탁 회수 소실 수정 — 구현·검증·복구

## 적용 범위

사용자가 미수정안을 한 건씩 승인하는 절차에서 첫 번째로 승인한 잡파 위탁 회수만 다룬다. 길드 공개경매나 다른 판매처의 가격·조건은 바꾸지 않는다. WORK QSP에만 적용하며 기존 사용자 세이브, 배포용 게임, 이미지, CSS, JavaScript, 엔진은 수정하지 않는다. 커밋·푸시와 패치 ZIP 제작은 하지 않는다.

기준 QSP는 `efdff96228e6cd77b59808c22b3391947e1682918480aea55c89b0a0bb3adebb`, 승인 후보는 `972d1b7a8719c9b44e6aca4bfaf5a6f73908240762ce65061a7d298d0aa82679`다. 최종 적용 여부·백업 경로는 `installation.json`, 공식 검사는 `official-report.json`을 따른다.

## 원인과 변경 후 동작

기존 위탁은 금액만 별도로 남기고 인물은 공용 임시 인물인 `stock`에 두었다. 다른 후보를 생성하거나 거절해 `stock`이 바뀌면 위탁액과 인물의 관계가 끊겼다. 회수 시에는 인물이 없어도 수수료 차감·위탁 기록 삭제와 인물 초기화가 계속되었다. 보호 원본에서도 재현된 문제이며 천재 특성 자체의 오류는 아니다.

새 위탁은 현재 인물 전체를 전용 보관 역할에 복사하고 공용 임시 인물을 비운다. 반환 시 원래 인물의 이름·ID·특성·장비·교육 경험·대회 이력 등을 보존하며, 반환이 확인된 뒤에만 기존 수수료 $5를 차감한다. 회수할 자리가 없거나 기록이 유효하지 않으면 돈과 위탁 기록을 그대로 둔다. 반환 수수료를 낼 현금이 없다는 이유로 새 제한을 만들지는 않는다.

같은 날 여러 명을 위탁하면 이전 위탁액은 정산 대금으로 넘어가고 가장 최근 한 명만 당일 회수할 수 있는 기존 규칙을 유지한다. 날짜 정산과 대금 수령은 각각 한 번만 지급한다. 예전 대금을 받을 때 새로 맡긴 인물이나 다른 용도의 `stock`을 지우지 않는다. 위탁 후 상세 화면도 공용 후보가 아닌 실제 위탁 인물을 표시한다.

## 저장 호환

새 보관 역할은 `jo9_farid_stored`와 `jo9_farid_stored_valid`를 사용한다. 인물의 저장 묶음은 기존 `$slave_vars` 정의의 23개를 그대로 사용하며, 정상 ID 0도 보관할 수 있다. 전용 보관 역할은 소유 인물·일일 성장·파산 처분 목록에 추가하지 않는다. 표시 전용 `jo9_farid_viewprobe`는 상세 화면을 만들 때만 복사하고 즉시 비운다.

기존 세이브 파일은 변경하지 않는다. 새 위탁 보관 정보가 없는 옛 저장의 위탁액은 기존 방식으로 다음 날 정산된다. 공용 `stock`의 현재 인물이 위탁 당시 인물이라고 증명할 수 없으므로 회수 시 임의로 대체하거나 수수료를 받지 않는다. 이미 소실된 인물을 복구하는 변경은 아니다. 이전 세이브를 새 QSP에서 사용한 뒤 다시 저장하면 새로운 보관 정보도 저장 대상이 된다. 새 저장을 구 QSP로 되돌려 계속하는 역방향 호환은 보장하지 않는다.

## 호출·입출력·부수 효과

추가 로케이션은 `jo9_farid_consignment` 한 곳이다. 내부 복사·정리도 이 로케이션에서 처리해 별도 의존 로케이션은 추가하지 않았다. 변경된 기존 로케이션은 `interaction_city`, `interaction_screen_city`, `next_day`, `stock_to_slave_nogt`, `stock_to_slave` 다섯 곳이다. 정확한 본문과 변경 경계는 선언형 JSON의 `patchId`와 `JO9 MOD START/END`로 찾을 수 있다.

| 모드 / 호출 | 반환 | 주요 효과 |
|---|---|---|
| `deposit` / `interaction_city=119` | 성공 1, 실패 0 | 기존 `$slave_price`로 평가 후 기존 절반 금액을 저장. 전체 인물 복사 성공 후 이전 위탁액 이월·신규 위탁 기록 설정·공용 인물 정리 |
| `return` / `interaction_city=1191` | 성공 1, 위탁 없음 -1, 소유 슬롯 점유 -2, 전용 보관 없음 -3, 기타 실패 0 | 빈 `slave` 슬롯에 보관 인물을 그대로 반환. 성공 후 수수료·위탁액 정리·기존 새 노예 기분 효과 유지 |
| `settle` / `next_day` | 이월한 금액, 재호출 0 | 위탁액을 `farid_debt`로 옮기고 보관 인물 정리 |
| `collect` / `interaction_city=1193` | 지급액, 지급 없음 0 | 대금 지급 후 채권을 비움. 최신 위탁과 다른 후보는 보존 |
| `panel` / 위탁 상세 2페이지 | 성공 1, 실패 0 | 표시용 복사본에서 기존 특성·속성·왕관 등급 표시를 계산. 보관 인물 원본과 공용 후보는 보존 |
| 내부 `copy` / `clear` | 성공 1, 실패 0 | 허용된 역할 사이의 23묶음 복사·정리만 수행. 새 인물 생성 초기화와 특성 수리는 호출하지 않음 |

`stock_to_slave_nogt`에는 기존 초기화보다 먼저 무효 원본을 거절하는 방어문을 두었다. 유효한 일반 신규 획득은 기존 초기화 후 성공값 1을 반환한다. `stock_to_slave`는 이 성공값을 확인한 뒤 기존 후속 복귀를 수행한다. 위탁 회수는 이 신규 획득 초기화를 사용하지 않으므로 예전 대회 기록이나 식단이 초기화되지 않는다.

## 의존성과 제거 시 주의

기존 `$slave_vars`, `CONST_INT`, `$slave_price`, 특성 표시 함수와 이미지 resolver를 사용한다. 표시 본문은 이번 기준 QSP의 `$stock_traits`와 시내 인물 속성 본문을 재사용한 것이다. 향후 원래 특성 표시 규칙이 바뀌면 이 표시용 본문도 함께 확인해야 한다. 왕관 등급 표시에서는 기존 가격 함수의 `stock` 특별 취급과 동일하게 `is_stock=1`을 지정한다.

새 로케이션만 삭제하면 위탁·회수·날짜 정산 호출이 끊긴다. 호출부만 구버전으로 돌리면 전용 보관 인물과 위탁액의 연결이 깨진다. 따라서 제거할 때는 패치 전체를 같은 기준으로 되돌려야 한다. 전용 인물이 맡겨진 새 세이브를 구 QSP로 계속 진행하는 방식은 피해야 한다. `stock_to_slave_nogt`의 조기 방어와 wrapper 성공값 확인도 함께 유지한다.

## 검사와 한계

수정 전 실제 엔진에서 위탁 후 공용 후보를 바꾼 회수 소실과 무효 획득의 파괴적 초기화를 재현했다. 수정 후보의 거래·호출부·무효 상태·ID 0·천재·다수 위탁·중복 정산·표시 화면을 별도 native fixture로 검사했다. 모든 23묶음의 이름 있는 배열 키와 문자열도 비교했다. 실제 가격 함수로 계산한 기존 위탁 금액과 새 위탁 금액도 대표 네 사례에서 같았다. 항목별 정확한 증거는 `tests/REPORT_KO.md`와 각 결과 JSON을 따른다.

공식 검사는 QSP 바이트 왕복, 로케이션·줄 끝·마커 경계, JSON 등록, 패치 재생·재적용과 설치 엔진 공통 9개 경로다. 정적 검사만으로 모든 동적 QSP 분기의 문법을 증명하는 도구는 아니다. 기능 검사는 합성 상태로 실제 로케이션과 관련 본문을 실행했으며 전체 사용자 저장을 GUI에서 불러와 클릭한 검사는 아니다. 실제 `SAVEGAME` 출력과 저장 코덱 검사는 별도로 구분한다. 기존 사용자 저장에 이미 사라진 인물을 되살렸다고 주장하지 않는다.

## 복구와 임시자료

WORK 적용 전 자동 백업 경로는 `installation.json`에 기록한다. 복구가 필요하면 새 게임을 종료하고 해당 백업을 `jack.qsp`로 복원한다. 작업 전후 세이브는 별도 판단 없이 삭제하지 않는다. 선언형 변경 JSON, 재현 스크립트, 보고서, 검사 로그, 백업을 남기고 재생성 가능한 진단 QSP·복제 JSON·후보 사본은 검증 후 정리한다. 정리 내역은 `cleanup.json`에 기록한다.

변경 JSON 재생성 스크립트는 `build.cjs`다. 적용 후에는 첫 인수로 기준 백업 `G:/somi/Jack O Nine Tails v2.4_work/game/jack.qsp.bak_20261028_135301`을 지정한다. 기능 재검사는 `JO9_AUCTION_TEST_BASELINE` 환경변수에 같은 백업 경로를 넣고 `tests`의 해당 스크립트를 실행한다. 검사는 기준 해시를 확인한 별도 진단 사본만 실행한다. 저장된 JSON만 다시 적용하려면 `tools/apply_mods.ps1`에 해당 패치 한 개만 든 폴더를 지정한다. 전체 과거 패치 폴더를 임의 재적용하지 않는다.
