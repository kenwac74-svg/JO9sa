# 에게야 보상·도나 인물 번호 충돌 수정

변경 식별: `SEED_NAMESPACE_FIX_20261020`. 적용일: 2026-10-20.

## 결과와 적용 범위

- Work의 인물 JSON 1,151개를 전수 검사했다. 2577~2601의 25개 번호에서 원작 인물과 구 도나 파일이 충돌했다.
- 구 도나 25개는 이미 설치된 8877~8901 도나 파일과 각각 바이트가 같았다. 구 파일만 게임 밖으로 백업 이동했다. 도나 인물은 유지된다.
- `211.json`의 이미지 경로 끝에서 빠진 닫는 따옴표 1개를 복구했다. 현재 이미지 경로와 모든 설정값은 유지했다.
- 수정 후 1,126개 JSON / 1,126개 고유 번호, 번호 중복·JSON 문법 오류 0건.
- Work에만 적용했다. QSP, 엔진, CSS, 이미지, 세이브, Kor_Full 및 배포 ZIP은 변경하지 않았다. 커밋·푸시 보류 유지.

## 원인과 수정 방식

엔진은 JSON 파일명의 첫 밑줄 앞 숫자를 배열 번호로 사용한다. `2579_egeya.json`과 `2579_kirakira.json`은 파일명이 달라도 같은 2579번 설정을 쓴다. 실제 수정 전 엔진에서 2579번과 8879번 이름이 모두 키라키라로 등록되는 것을 재현했다.

퀘스트의 2579번은 에게야가 맞다. 현재 QSP와 보호 원본의 실행 참조 130줄(원작 번호 105줄, 도나 구매 25줄)을 비교했고, 이번 문제로 바꿀 번호 참조는 없었다. 원작의 별도 인물 슬롯이나 배경을 도나 번호로 재매핑하지 않는다.

| 경로 | 유지한 코드 / 검사 지점 |
|---|---|
| 에게야 포획 보상 | `interaction_city=102017`, `special_stock=2579` → `generate_stock` → `stock_to_slave_nogt` |
| 키라키라 구매 | `interaction_city=6238`, `special_stock=8879` → 생성·슬롯 교환 → `interaction_screen_city` |
| 에게야 후속 퀘스트 | `interaction_city`의 `slave_type=2579 and slave["enchanter"] >= 4` 조건 유지 |

`2580_marselina.json` / `2608_marselina.json`은 원본부터 존재하는 서로 다른 번호의 별칭이므로 보존했다. 같은 `stock_id`를 공유하는 원작 인물 변형도 숫자 파일명 충돌과 구분해 보존했다.

## 기존 세이브

- 게임을 완전히 종료한 뒤 수정된 Work를 다시 실행한다. 실행 중인 세션에는 디스크 변경이 즉시 반영됐다고 보장하지 않는다.
- 기존 로컬 엔진 소스는 `.sav` 로드에서 저장 변수 복원 → `ONGLOAD` → JSON 재등록 순서다. 다만 현재 실행 파일과 소스의 완전한 일치 및 실제 저장 선택 UI를 통한 복원은 이번에 검증하지 않았다.
- 이미 잘못 보상받은 인물 인스턴스는 자동 교체하지 않았다. 이름·능력치·육성·장비를 가진 실제 개체를 일괄 덮어쓰면 정상 키라키라나 플레이 기록까지 바꿀 수 있다. 해당 세이브 복구는 원래 보상과 현재 개체를 확인하는 별도 작업이다.
- 진단의 대표 상태 구성은 실제 `.sav` 불러오기 검증이 아니다. `OPENGAME` 진단 경로가 파일 열기로 잘못 연결되는 별도 문제를 이번 수정의 세이브 실패로 집계하지 않았다.

## 재발 방지 검사기

`tools/qa/check-slave-template-ids.cjs`는 파일을 변경하지 않는 Node.js 검사기다.

| 진입점 | 입력 / 반환 | 부작용·의존성 |
|---|---|---|
| `inspectDirectory(directory)` | 인물 JSON 폴더 → 파일 수, 고유 번호, 충돌, 오류, 파일별 SHA-256 보고서 | 하위 폴더 포함 읽기만 한다. Node 내장 fs/path/crypto 사용 |
| `assertRegistry(directory)` | 같은 입력 → 정상 보고서 또는 오류 예외 | `release-check.cjs`가 호출. 오류 시 출고 판정 FAIL |
| CLI | 폴더 인수 1개 → JSON 결과, 정상 0 / 등록 오류 1 / 실행 오류 2 | 파일 생성·이동·삭제·세이브 수정 없음 |

검사 항목: 숫자 접두사 충돌(앞자리 0 정규화 포함), 32비트 비음수 번호, JSON 파싱, 최상위 객체, `indpack_info.girl_id` 불일치, 검증하지 못하는 연결 경로. 원본 `0_template.json`은 유효하다. 서로 다른 번호의 동일 내용·동일 stock_id는 허용한다. 새 모드를 병합할 때도 번호 충돌을 먼저 해결한다.

```powershell
node tools/qa/check-slave-template-ids.cjs 'G:/somi/Jack O Nine Tails v2.4_work/game/json/slaves'
node --test tools/qa/check-slave-template-ids.test.cjs tools/qa/release-check.test.cjs
```

출고 총괄은 `--game-dir`의 `json/slaves`를 필수 검사한다. release 프로필에서 game-dir가 빠지면 INCOMPLETE이므로 PASS가 될 수 없다. static 프로필에서 game-dir를 생략하면 이 검사를 하지 않는다. JSON만 확인하려면 위 전용 CLI를 쓴다.

검사기를 제거하면 게임 동작은 변하지 않지만 출고 총괄의 require가 실패한다. require와 호출까지 제거하면 이번 충돌 방어도 사라진다. 이 검사는 모든 QSP 문법, 이미지 존재 여부, 모든 퀘스트 결과를 증명하지 않는다.

## 확인 결과

- 수정 전: 실제 엔진에서 `EGEYA2579=키라키라 | KIRA8879=키라키라` 재현.
- 수정 후: 충돌 구간의 원작 25명·도나 25명 및 211번에 대해 이름·이미지·기본값 203개 조건 검사 통과.
- 실제 엔진 에게야 보상: `slave_type=2579`, `$slave_name='Egeya'` 통과.
- 실제 엔진 키라키라 구매: `slave_type=8879`, `$slave_name='키라키라'`, `kirakira=1` 통과.
- 인물 번호 검사 8개 + 기존 출고 검사 회귀 10개 = 18개 통과. 충돌 자료를 넣으면 실제 출고 총괄이 FAIL 하는 음성 테스트 포함.
- 현재 Work QSP 구조·줄바꿈·등록 검사 STATIC_PASS. 이번 수정은 QSP를 바꾸지 않았으므로 새 QSP 패치 재생을 꾸며서 전체 출고 PASS로 기록하지 않는다. 위 기능별 실제 엔진 통과와 정적 검사 결과를 구분한다.
- QSP SHA-256 유지: `20137b7336f2ec27c419605cbd2ada1a6fab459919c6ceaaedad89a9152f40f5`.

## 다음 배포에서 빠뜨리면 안 되는 단계

`records/seed-namespace-fix-20261020/runtime-delta.json`의 삭제 25건과 교체 1건을 함께 반영한다. 단순 파일 복사는 구 중복 JSON을 지우지 못한다.

1. 사용자가 마무리 동기화를 지시하면 Full의 삭제 대상 SHA와 정상 고번호 파일 존재·동일성을 확인하고, 해당 25개 구 파일만 게임 밖으로 보관한다. 해시가 달라졌으면 수동 변경 여부를 먼저 검토한다.
2. 최신 Work의 `211.json`을 동기화하고 양쪽 인물 등록 검사 및 실제 배포 엔진 검사를 한다. 다른 수동 변경을 과거 스냅샷으로 덮지 않는다.
3. 새 풀팩에는 구 파일 25개를 넣지 않는다. 기존 설치에 덮는 ZIP은 파일을 삭제하지 못하므로 **기존 구 도나 파일 25개 제거 안내와 정확한 목록**이 필요하다. 설치기·자동 정리 스크립트는 이번에 추가하지 않았다.
4. 최종 설치 폴더에 구 도나팩을 다시 덮으면 같은 충돌이 재발할 수 있다. 팩 병합 후에도 고번호 8877~8901만 유지하고 검사한다. 다른 번역판 전체의 번호가 같다고 가정하지 않는다.

`runtime-delta.json`은 삭제 파일명·정상 유지 파일명·해시를 기록한다. 백업 위치와 적용 전후 목록은 내부 `transaction-result.json`에 보관하며, 개인 세이브와 큰 진단 QSP는 공개 저장소·배포물에 넣지 않는다.
