## 확인한 사실

레시 $buyer_demand의 demand['min_stamina'] > 3는 비교만 하고 값을 저장하지 않는다. 실제 납품 함수 slave_sell_chek는 고객별 min_stamina를 읽지 않고 공통 체력2미만 거절만 검사한다. 레시 납품은 sell_slave_complex 경로로 이어진다. slave_to_train에서 보이는 비슷한 키는 별도 contractor_demand의 훈련용 인물 생성 조건이므로 고객별 납품 검사를 대신하지 않는다. master_stat_clients는 요구 표시이며 실행 납품 조건이 아니다.

현재 실행 정의 #npc_base와 jo9_chun_club에는 min_stamina 숫자 구문51줄이 있다(대입43,비교식8). 공통 해석기를 일괄 연결하면 다른 고객의 납품 조건까지 달라진다. 따라서 다음 한 항목의 승인 범위는 레시만으로 제한한다. 다른 고객의 기존 동작은 이 승인에 포함하지 않는다.

## 제안

레시의 기존 부등호 >3을 뜻대로 최저4로 저장하고 실제 납품에서도 체력4이상을 검사한다. 기존보다 요구가 엄격해진다. 현재 감수성 상한3·나머지 기술·전체등급·가격과 사용자 편집/진행은 유지한다. 알려진 옛 요구 캐시도 같은 범위만 갱신한다. 다른 고객의 체력 요구 일괄 활성화는 별도 결정 대상이다.

승인 후 레시 체력3/4 경계와 다른 고객 거래·기존 감수성 상한·가격/인물/재산 보존을 실제 엔진으로 검증한다. 새 인물별 영구 필드를 추가하지 않는다. 이번 기록은 조사와 제안이며 WORK에는 아직 반영하지 않았다.
