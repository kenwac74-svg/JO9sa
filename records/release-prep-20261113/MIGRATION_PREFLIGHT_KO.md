# 2.4.2 Full 세이브 마이그레이션 사전 점검

작성일: 2026-11-13. 범위: 현재 문서·기록·기존 코덱의 읽기 전용 대조. 개인 SAV를 읽거나 수정하지 않았고, WORK/Full/엔진/도구/소스/원장은 변경하지 않았다. 이 문서 한 파일만 작성했다. 아래 미체크 항목은 앞으로의 출고 게이트이며 검사 통과 기록이 아니다.

## 1. 작업 시점과 순서

D21의 확정 시점은 **모든 수정사항 완료 후, 2.4.2 Full 배포 직전**이다. Full 배포 결정만으로 그 전제까지 충족했다고 보지 않는다. 지금은 범위·순서·필수 검사를 준비하며 구현과 실제 세이브 변환은 시작하지 않는다. [D21 결정](G:/somi/JO9sa/records/deferred-discussions-20261024/index.json:376) · [인계 결정](G:/somi/JO9sa/docs/SESSION_HANDOFF_INDEX.md:1343)

출고 체크 순서는 다음과 같다. 기존 경로 정리는 검증 뒤에 둔다. 이 순서는 기존 검토 기록을 현재 변경에 맞춰 구체화한 것이다. [기존 순서](G:/somi/JO9sa/records/special-weapon-icons-20261031/SAVE_COMPATIBILITY_DISCUSSION_KO.md:13)

- [ ] 모든 승인 수정·현재 WORK 수동 변경·리소스 교체를 확정하고 최종 QSP/JSON/이미지/음원 및 경로 원장을 동결한다.
- [ ] 지원할 원본 SAV 버전·대상 엔진·게임 버전·배포 설정·변환 허용 범위를 확정한다.
- [ ] 읽기 전용 검사에서 변환 대상 위치/옛값/새값/횟수, 미지원·미매핑 참조, 보존 대상을 보여준다.
- [ ] 합의한 구조적 변환기를 구현하고 원본과 다른 이름의 SAV만 출력한다.
- [ ] 비대상 보존·반복 실행·오류 중단·원복과 실제 UI 전체 로드 왕복을 검증한다.
- [ ] 옛 경로가 현재 코드·JSON/CSS·동적 조회·지원 SAV 화면/콜백에 남지 않는지 재확인한다.
- [ ] 검증된 정리 대상만 원장·배포 명세와 함께 정리한 뒤 최종 Full 사본/ZIP 입력으로 다시 출고 검사를 한다.

## 2. 배포 변환기의 허용 변환과 보존

### 이미지·화면·실행 문자열

기존 `save-codec.cjs`는 `QSPSAVEDGAME`/`5.7.0`만 받으며 변수부를 구조적으로 읽는다. 변수 앞의 화면·선택지·오브젝트는 위치를 건너뛰어 원문 그대로 직렬화한다. 따라서 변수 문자열 치환만으로 전체 저장 화면을 이관할 수 없다. [현재 코덱](G:/somi/JO9sa/tools/qa/save-codec.cjs:5) · [기존 검토](G:/somi/JO9sa/records/special-weapon-icons-20261031/SAVE_COMPATIBILITY_DISCUSSION_KO.md:5)

- [ ] 지원 버전의 저장 화면, 이미지, 선택지의 실행 문자열, 오브젝트, 변수 문자열·코드 캐시를 구조적으로 구분한다. 그 안의 **원장에 있는 이미지 주소만** 바꾼다.
- [ ] 슬래시/역슬래시·대소문자·경로 접두사·HTML/CSS/스크립트 안 문자열·분할 조립 경로의 실제 형태를 조사한다. 미지원 표현을 전체 문자열 치환으로 추정 처리하지 않는다.
- [ ] 숫자·배열 키/인덱스·슬롯·퀘스트·인벤토리·보상·관계·장비·보유 기간·육성/행동 이력·사용자 문구를 보존한다. 이름은 아래 별도 규칙에 맞는 값만 바꾼다.
- [ ] 변환 중 장소·선택지·영입·보상·정산·하루 경과를 실행하지 않는다. 실제 첫 로드의 게임 콜백 효과는 변환 단계와 별도로 기록한다.
- [ ] 미지원 형식·손상·불완전 파싱·중복/충돌 매핑을 명시적으로 보고하고 정상 완료로 표시하지 않는다.

위 A안은 2026-10-31의 **권장 검토안**이며 이미 구현·확정된 도구가 아니다. 엔진 파일 조회 별칭 방식인 B안도 검토 이력이 있으나 현재 엔진 지원이나 전체 조회 접점 검증은 확정되지 않았다. 본 점검은 엔진 교체/수정 지시를 추가하지 않는다. [A/B 검토](G:/somi/JO9sa/records/special-weapon-icons-20261031/SAVE_COMPATIBILITY_DISCUSSION_KO.md:7)

### 기본 이름

확정 조건은 **동일 캐릭터 ID이고 저장된 이름이 그 ID의 옛 기본 이름과 정확히 일치할 때만** 새 기본 이름으로 변경하는 것이다. 플레이어 작명은 보존한다. 이름만 같거나 ID만 같은 경우는 대상이 아니다. [D21 이름 규칙](G:/somi/JO9sa/records/deferred-discussions-20261024/index.json:399)

- [ ] 최종 입력에서 `ID / 옛 기본 이름 / 새 기본 이름 / 근거`의 허용 원장을 확정한다. D21/SESSION에는 조건만 있으므로 그 문서만으로 이름 매핑이 완성된 것으로 보지 않는다.
- [ ] 인물 자체 이름과 저장 화면에 남은 이름 사본의 처리 범위를 구분한다. 일반 대사·플레이어 문장 전체의 이름 문자열을 일괄 치환하지 않는다.
- [ ] 같은 ID+옛 기본 이름, 같은 ID+사용자 작명, 다른 ID+같은 이름, 이미 새 이름, 빈 이름/미지원 상태를 검사한다.

시루1448은 과거 `seed_name='시루'`를 새로 추가한 사례다. 그 전 무작위 이름을 모두 시루로 바꾸는 근거는 없으며, 현재 이름 JSON만으로 옛 기본 이름을 역추정하지 않는다. [당시 이름 추가](G:/somi/JO9sa/docs/modding/GIRLS_DECISIONS_AND_BACKLOG_20261026.md:74) · [기존 SAV 이름 미변경](G:/somi/JO9sa/docs/modding/HOME_HANDOFF_20261027.md:52)

## 5. 필수 검증표

다음은 기존 검토의 필수 조건과 현재 변경의 보존 규칙에서 도출한 **출고용 검사 항목**이다. 합성 SAV를 우선 사용하고, 대표 구세이브는 별도 승인된 복사본으로 검사한다. 이 문서를 위해 개인 SAV에 접근하지 않았다.

| 검사 | 합격 증거 |
|---|---|
| 원본/출력 분리 | 원본 SHA-256이 전후 동일하고 출력은 다른 이름이다. 기존 출력 충돌 시 덮어쓰지 않는다. 변환 전후 해시·도구/매핑 버전·변경 위치·옛값/새값을 남긴다. |
| 무변환 왕복·비대상 보존 | 변경0건 입력의 바이트 왕복 동일. 대상 입력은 허용 변경 외 숫자/문자열/배열 키·인덱스/인물 신원/진행이 동일하고 화면·콜백의 비대상 코드도 보존된다. |
| 재실행 | 같은 변환 결과를 두 번째 처리하면 변경0건이며 바이트가 같다. 이미 새 경로/새 이름/완료 revision의 저장은 변경되지 않는다. |
| 실패와 원복 | 미지원·손상·불완전 입력·충돌 원장에서 정상 성공을 내지 않는다. 실패가 원본을 손상시키지 않고 원본+최소 차이 명세로 복구 가능하다. 기존 정산/보상을 재실행하는 역변환을 만들지 않는다. |
