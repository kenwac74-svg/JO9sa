## 확정 P2 1건: 조건 자동 선택이 실제 수동 전환의 순환을 막음

`toggle-repro.json`과 `toggle-source-evidence.json`에 재현 입력과 현재 WORK 소스 근거를 기록했다. 상위 QA의 `../toggle-native-report.json`은 원래 `jo9_html`을 호출한 뒤 원래 `jo9_toggle`을 네 번 연속 실행한 실제 엔진 결과다. 직접 mode1만 호출한 모의 순환 검사가 아니다.

최소 재현: A·B·C·D 파일을 두고 B에 `보유금 >= 100`을 지정한 뒤 보유금 100으로 최초 장면 출력 및 실제 전환 버튼을 네 번 호출한다. 최초 자동 표시 B 뒤 기대 순환은 C → D → A → B지만 실제로 C → B → C → B가 나온다. 조건을 B 한 개에만 지정해도 발생하며 B와 C 모두에 지정해도 동일하다. 조건을 통과한 수동 전환 후보 A·D에 도달할 수 없다.

| 조건 없음 대조군 | `0 / 10002 / 10003 / 10004 / 0` | 5 / 0 |

원인: `image-cut-condition-rules.cjs:211`의 새 SELECT 훅은 mode0에서 낮은 번호의 조건 컷으로 선택을 강제한다. 기존 WORK `interior_change` 본문 1972행의 실제 toggle은 mode1 전에 mode0을 호출한다. 저장된 C가 B로 바뀌면 1974행의 조건 때문에 mode1을 건너뛴다. 기존 native 검사는 mode1을 직접 호출하여 이 실제 버튼 호출 연쇄를 포함하지 않았다.

수정안만 제안한다: 수동 toggle 안에서 현재 선택의 유효성·조건만 재검사할 때는 자동 우선 선택을 적용하지 않고, 남은 유효 경로를 순환하도록 한다. 장면 최초 출력의 자동 우선 선택, mode2의 이미 출력된 그림 경로 조회, 기존 저장 ID는 보존한다. 3개 이상 유효 컷, 조건 1개·여러 개, 조건 변경을 포함하여 실제 toggle을 연속 실행하는 회귀 검사가 필요하다. 생산 코드는 수정하지 않았다.

별도 요청에 따라 `fix-proposal.json`에 정확히 한 줄의 미적용 수정안을 준비했다. toggle의 현재 선택 검증 호출에 명시적 mode3을 전달한다. 전체 `jo9_path` 흐름을 확인했으며 mode3은 후보 존재·조건 검사와 기존 복귀 처리를 통과하고, mode0 자동 우선 선택·mode1 증가·mode2 조기 반환은 건너뛴다. 조건이 없는 경우 mode0과 mode3의 실행 분기는 같다. 새 변수·로케이션·저장 이관은 없다. `prepare-fix-proposal.cjs`로 정적 문법·QSP 왕복·한 본문 한 호출만 변경·조건 생성 코드 불변을 확인했고, 원본 QSP는 `78835089…`, 메모리에서 계산한 후보 QSP는 `05f5726d…`다. 후보 QSP 파일을 추가로 만들거나 생산 파일에 적용하지 않았다. 엔진 통과 여부는 상위 QA의 후보 검사로 별도 확인해야 한다.
