## 바뀌는 동작과 원인

기존 `menu_form`은 `$newloc`로 장비 효과를 재계산한 뒤에야 `$return_lock`을 `menu_form`으로 바꿨다. 재계산 도중 금장 목줄 거부 질문으로 이동하면 뒤쪽 대입이 실행되지 않아, 질문에 남아 있던 복귀 주소를 사용할 수 있었다.

현재 후보는 `menu_form:45-50`에서 복귀 주소를 먼저 정하고, 필요하면 구형 금장 목줄 정의를 갱신한 뒤 `$newloc`를 호출한다. 기존 위치의 대입은 설명 주석으로 대체했다(`menu_form:91-93`). 질문 문구는 아이템 이름과 같은 “금장 목줄”로 정정했다(`#item_base:1222`). 원래의 착용 효과와 거부 조건은 유지한다.

질문 버튼은 질문 당시의 역할, 인물 ID, 유형, 질문 순번을 숫자 또는 역할 문자열로 보관한 호출문을 실행한다. 응답 처리기는 현재 질문과 대상이 맞는지 확인하고, 사용한 양쪽 콜백을 먼저 비운 뒤 원래의 강제 착용·반격 또는 목줄 반환 처리를 수행한다.

## 진입점과 인수

새 로케이션은 추가하지 않았다. 기존 `#item_base` 맨 앞의 모드 분기를 사용한다(`#item_base:1-53`).

### 응답 처리

호출 형식:

```qsp
gs '#item_base', 'golden_collar_choice', '역할', 인물ID, 유형, 질문순번, 응답
```

| 인수 | 의미 |
| --- | --- |
| `$args[0]` | `golden_collar_choice` |
| `$args[1]` | 질문 당시 역할 |
| `args[2]` | 질문 당시 해당 역할 배열의 `['id']` |
| `args[3]` | 질문 당시 해당 역할의 `_type` |
| `args[4]` | 질문 당시 `jo9_gc_seq` |
| `args[5]` | 승인 `1`, 취소 `0` |

실제 허용 대상은 `slave`, `assistant`, `prisoner`, `cow`, `room1`, `room2`, `room3`, `room4`의 8개 역할이다. 이들은 `#static_base:335-343`의 `$main_screen_slave_characters`와 일치한다. `farmhand`, `harpy`, `pig`, 냉동 보관 인물은 이 처리기의 대상에 포함하지 않는다. 공통 아이템 속성이 이외 역할로 치환될 때는 `GOLDEN_COLLAR_OTHER_ROLES_PRESERVED_20261025` 후속 블록이 원본 Y/X 콜백을 그대로 만든다. `2026-10-25_golden_collar_scope_preserve` 패치가 이 보존을 담당하며 기본 A안 패치 다음에 적용한다.

역할이 허용 목록에 없거나, 현재 로케이션이 `choice_screen`이 아니거나, 순번이 현재 `jo9_gc_seq`와 다르거나, 양쪽 콜백에 `GC_CHOICE_20261025` 마커가 없으면 즉시 `exit`한다(`#item_base:3-5`). 이 경우 수치 반환이나 화면 이동은 하지 않는다.

유효한 호출은 지역 코드 `$gc_resolve`에서 역할 치환 후 실행한다. 안쪽 `dynamic`의 `args[0]`, `args[1]`, `args[2]`는 각각 예상 ID, 예상 유형, 응답이다(`#item_base:27`). 대상의 현재 ID·유형이 일치하고, 의식이 있는 존재 상태이며, 여전히 `golden_collar`를 착용하고 있을 때만 다음 조건을 검사한다.

```text
passion_luxury = 0
rebell[해당 역할의 psy_status] > 0
obedience < 0
beaten_ever = 0
domini_dictum = 0
```

위 조건까지 맞으면 승인 시 원래의 반격 또는 강제 착용 코드를 실행한다. 취소 시 목줄 슬롯을 `пусто`로 바꾸고 해당 역할의 인벤토리에 `golden_collar` 1개를 돌려준다. 조건이 달라졌으면 피해나 환급을 추가하지 않는다(`#item_base:9-23`).

수치 반환값은 없다. 응답을 소비한 뒤 해당 역할의 `_stat_screen`을 2, `menu_form`을 0으로 정한다. `slave`·`assistant`는 원래 규칙대로 해당 역할의 통계 화면으로 `GT`한다. 나머지 6개 역할은 검증한 복귀 로케이션으로 `GT`한다. 복귀 주소가 비었거나 `choice_screen`, `next_day`, `end_day_screen`이거나 존재하지 않는 로케이션이면 지역 복귀 주소로 `menu_form`을 사용한다(`#item_base:7-8,24-25`). 반격 코드가 전투로 `GT`하면 그 전투 경로를 따른다.

### 로드 시 캐시 갱신과 구형 질문 복구

호출 형식:

```qsp
gs '#item_base', 'golden_collar_load'
```

추가 인수나 수치 반환값은 없다. `$ongload:79-81`에서 기존 `saved_game_loaded = 1` 설정 뒤 호출한다.

현재 `$item_property['golden_collar']`에 새 마커가 없으면 인수 없는 `gs '#item_base'`로 장비 정의를 다시 만든다(`#item_base:39`). 일반적인 인수 없는 `#item_base` 호출은 기존 아이템 데이터베이스 초기화 경로를 그대로 실행한다.

구형 질문 복구는 다음 조건을 함께 만족할 때만 역할을 인식한다(`#item_base:32-37`).

- 현재 로케이션이 `choice_screen`이고 `$yes`에 새 마커가 없다.
- 같은 허용 역할에 대해 `$no` 안에 목줄 슬롯을 `пусто`로 바꾸는 코드와 `golden_collar` 1개를 반환하는 코드가 있다.
- `$yes` 안에 기존 `$dyn_slave_forced` 참조와 같은 역할의 `_stat_screen = 2`가 있다.

인식한 경우 구형 `$yes`·`$no`를 비우고 `$return_lock`을 `menu_form`으로 정한다. 현재 대상이 여전히 금장 목줄을 착용하고 원래 거부 조건도 만족하면 갱신된 아이템 정의로 질문을 재발행한다. 그렇지 않으면 `menu_form`으로 이동한다(`#item_base:40-49`). 원래 승인 처리는 `beaten_ever`를 1로 만들고, 취소 처리는 목줄 슬롯을 비우므로 해당 완료 상태에서는 같은 질문의 피해나 환급을 반복하지 않는다. 다른 아이템의 질문이나 이미 새 마커가 있는 질문은 이 구형 복구로 재발행하지 않는다.

이 경로는 저장 파일을 직접 고치지 않는다. 로드된 실행 상태의 정의와 확인된 구형 질문만 갱신한다. `next_day`나 청구 절차를 재시작하는 호출은 추가하지 않는다. 메뉴 복귀 후에는 기존 `$newloc`의 로드 후 갱신 경로가 이어진다.

## 상태와 부수 효과

새로 추가하는 영구 전역 값은 질문 순번 `jo9_gc_seq` 한 개이다. 질문을 만들 때마다 1씩 증가하고, 생성한 두 콜백 문자열에 당시 값을 넣는다(`#item_base:1224-1226`). 일반 저장 과정에서는 다른 전역 값과 함께 저장될 수 있다. 새 인물 배열 필드나 인물별 완료 플래그는 추가하지 않는다. `$gc_role`, `$gc_resolve`, `$gc_resume`, `$gc_return`, `gc_i`, `$gc_candidate`는 지역 작업 값이다.

기존 전역 `$yes`·`$no`는 응답 처리 전 함께 비운다. 따라서 사용한 버튼의 `dynamic $yes` 또는 `dynamic $no` 재실행은 이전 효과를 다시 실행하지 않는다. 순번 확인은 이전 질문에서 남은 호출이 새 질문의 응답으로 적용되는 것도 막는다. 대상 ID와 유형 확인은 그 역할을 다른 인물이 차지했을 때 잘못 적용되는 것을 막는다.

이 패치가 직접 사용하는 기존 상태는 역할별 ID·유형·존재 상태·목줄 슬롯·인벤토리·거부 조건, `$return_lock`, `$curloc`, `menu_form`, 역할별 `_stat_screen`, 질문 표시 변수이다. 승인 경로에서는 아래 원래 동적 코드가 가진 능력치·기분·피해·전투 등의 부수 효과도 발생한다.

## 분리하거나 제거할 때의 영향

- 응답 모드만 제거하고 새 콜백을 남기면 새 버튼이 의도한 응답 처리를 수행할 수 없다. 콜백 생성부와 응답 모드는 함께 유지해야 한다.
- 콜백 생성부만 구형으로 되돌리면 대상·순번 검사와 사용 후 콜백 제거를 거치지 않는다. 메뉴 복귀 주소 선설정만으로 이 검증들을 대신할 수 없다.
- `menu_form` 선설정을 제거하면 장비 재계산이 질문으로 이동할 때 이전 복귀 주소가 다시 남을 수 있다. 응답 처리기의 위험 주소 보정은 별도로 남지만, 메뉴 진입 시점의 선설정과 같은 역할은 아니다.
- `$ongload` 호출이나 로드 모드를 제거하면 이미 저장된 구형 질문은 갱신된 아이템 정의만으로 교체되지 않는다. 일반 메뉴 진입이나 기존 `refresh_database`만으로 현재 저장 화면의 구형 콜백이 반드시 재발행되는 것은 아니다.
- 원래 강제 착용·반격 코드를 제거하거나 이름을 바꾸면 승인 경로의 원래 상태 변경 또는 전투 진입이 빠진다. 이 패치와 별개로 그 호출부와 의존성을 함께 검토해야 한다.
- 이전 런타임으로 되돌릴 때 새 마커가 있는 질문 화면을 저장한 파일은 현재 처리기 호출을 담고 있을 수 있다. 질문을 해결해 일반 화면으로 돌아온 상태에서 저장한 복구 지점을 보관하면 진행 중 콜백 의존성을 줄일 수 있다. 이 설명서는 저장 파일의 역방향 변환을 제공하지 않는다.

## 검증 기록과 한계

이 설명서 작성자는 위 SHA-256 후보를 파서로 읽고, 선언형 패치와 실제 `#item_base`, `menu_form`, `$ongload` 본문을 대조했다. 최종 후보의 콜백은 한 줄 `GS` 호출 뒤 `&! GC_CHOICE_20261025` 주석을 붙이는 형태이며 `CHR` 호출을 사용하지 않는다. 정적 검토에서 인수 매핑이나 원래 반격 분기의 변경 오류는 발견하지 못했다.
