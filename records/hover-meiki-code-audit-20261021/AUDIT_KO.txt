1. 장비 목록의 마우스 오버 설명

보관된 JO9O/game/jack.qsp와 source/jack_2026-10-01.qsp의 #dynamic에는 tooltip-data384개가 있고 장비 관련380발생을 확인했다(주석 예시 포함). 0.14 사용 확인 기록의 기준 파일 SHA8d963ae88dcea0db9500b29bcd5112933abd81042d5be8516113840094e607c6도 같은 상태다.
현재 Work 및 r3의 #dynamic에는 tooltip-data4개만 남아 있으며 그4개는 장비 목록 설명이 아니다. 전투 장비 선택 링크와 공통 비전투 목록 헬퍼의 툴팁 속성이 없어졌다.

예: 현재 #dynamic:2220의 아라미드 전투복 선택 링크에는 href와 이름만 있다. 보관본의 같은 링크(:2132)에는 class=tooltip-left와 tooltip-data 설명이 있었다. 공통 $get_non_combat_equipment 헬퍼도 보관본:2420의 설명 정리·툴팁 연결이 현재:2508에는 없다.

현재 CSS의 [tooltip-data]:after, [tooltip-data]:hover:after와 tooltip-left 규칙은 남아 있다. base.css는 r3와 같은 해시다. 즉 CSS를 다시 켜는 것으로 해결할 수 없고, QSP 장비 링크에 설명 연결을 복구해야 한다.

과거 대화의 시험 패치 v0.2는 마스터·노예·조수 장비 선택379링크와 공용 비전투 헬퍼를 지원했고 사용자 동작 확인이 있다. 해당 대화 뒤 작업 취소 발언은 있으나 이후0.14 인계·2.4계획에도 통합 대상으로 명시돼 있다. 다만 10월3일 확인본에는 있고 Git에 보존된10월14일 QSP에는 이미 빠져 있다. 10월14일 파일은 커밋151a728의 source/jack_release_2026-10-14_2.4.0.0.qsp, blob ae9d97d868fcfe9ccf251ef6a0b0f8290b77d279이며 SHA256 bb9bb38387fc97b7b41ccf366ad448fba419f44b71f6286198be92e8c6d2c2d0다. 직접 파싱해 tooltip-data4/장비 연결0을 재확인했다. 이 범위 안의 정확한 삭제 작업은 확정하지 못했다. 현재 mods의 #dynamic 편집에서 해당 속성을 제거한 직접 diff는 찾지 못했고, 10/16 전체 본문 편집의 old부터 이미 감소해 있다.

직전 VARBASE_STRUCTURE_INDEX_20261021은 #var_base만 바꿨고 #dynamic/CSS는 보존했다. 현재 확인은 기존에 작동했던 기능이 최신 QSP에 유지되지 않은 누락을 뜻하며 삭제 의도를 단정하지 않는다.

복구 시 현재 $item_description의 최신 설명·수치와 연결해야 한다. 예전 tooltip-data에는 고정 문안도 있으므로 과거 본문 전체를 되돌리면 이후 승인한 설명 교정이 사라질 수 있다. 장비 클릭·착용 처리와 최근 수리를 보존한 최소 복구가 필요하다. 이번에는 복구 코드를 적용하지 않았다.

2. 명기 확률

생성 단계에 잠재 특성을 미리5% 배정하는 코드가 아니라, 연결된 최초 상태 전환에서 발견 여부를 결정한다.
jo9_meiki_state:18~24는 이전상태0, 현재상태2이상, checked0이면 checked를1로 기록하고, 호출 args[1]=1일 때 rand(1,100)<=5를 실행한다. 성공값1~5이므로 코드상5%다. 같은 난수는 slave/assistant/room1~4의21/59/97/135/173/211행에 있다.

실패 또는 args[1]=0이어도 최초 기회는 소비된다. 반복 행동으로 재추첨하지 않는다. 처음부터 상태1이상인 기존 미발견 인물에게는 소급 추첨하지 않고, 기존 상태4는 발견 이력으로 인식한다. 복원상태 해제도 새 추첨을 만들지 않는다. 기술 보장·교육XP보정은 별도 처리이며 발견 확률을 높이지 않는다.

일반 연결:
- #dynamic의 $vaginally_penetrated:4866~4895는 전환 전 이력 기록, 상태 변경, 허용값에 따른 helper 호출을 한다. 실제 템플릿 실행은 interaction37발생, next_day6발생, interaction_city1발생에서 확인했다.
- sex_initiate:41~42는 특정 진입번호의 자격을 저장하고 sex_end:30~35/72~77이 이를 사용한다.

확인된 개인실 경로 차이:
jo9_meiki_willing은 slave/assistant만 처리해 roomN 직접 요청에서는0을 반환한다. 현재 slave_private_room1~4:312의 기본 링크는 interaction1027~1030을 직접 호출하며, 예를 들어 interaction:8340~8384는 room1 고정 대상으로 전환 템플릿을 실행한다. next_day:857/893/929/965의 roomN 직접 처리도 같다. 이 흐름에서는 첫 전환이 생겨도5% 추첨 없이 checked가 기록된다.

반면 개인실 교육은 snk_room_bridge.enter가 대상을 slave로 교환하므로 같은 문제로 묶으면 안 된다. 개인실 전체가 발견 불가능하다는 결론은 아니다. 직접 경로의 역할 제한이 의도인지 누락인지는 코드만으로 확정할 수 없지만, 현행 인터페이스가 역할별로 다르게 동작한다는 사실은 확인된다.

과거10/15~16 문서의 조건은 현행 코드와 다르다. 현재 actor 검사는 state=slave_exist를, transition 검사는 비어 있지 않은 상호작용 문자열과 대상 검사 결과1을 확인한다. 오래된 문서의 전제를 현재 사실로 보고하지 않는다.

후속 검토 대상은 장비 툴팁 연결 복구와 개인실 직접 경로의 발견 인수 처리다. 현재 수치·역할 조건·추첨 방식은 수정하지 않았다. 커밋·푸시/Full동기화/패키징도 하지 않았다.
