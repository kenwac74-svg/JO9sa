# 타격 이펙트 점검

## 확인한 원인

현재 WORK(a6e32f71...)의 `боевой_интерфейс`, `конец_боя`는 직전 대상의 **HP 감소**만 검사하고, 별무늬가 들어간 `slash.svg` 하나를 출력한다. 원본 전투 규칙에서 일반 둔기는 대체로 행동 체력·정신을, 정신 공격은 정신을 소모시키므로 두 계열은 HP가 변하지 않아 효과가 나오지 않는다. 새 전투용 전신 이미지가 미적용인 문제와는 별개다.

WORK·저장소 battle 기록·workspace output/visualizations에서 독립된 네 종류의 이전 효과 파일을 찾지 못했다. 기존 `slash.svg`는 보존하고 새 repo-native SVG 네 종류를 workspace `fx/`에 준비했다. 500×460, 투명한 배경, 별·별빛·만화 폭발 없이 검흔·충격 흔적·정신 압박으로 구분한다. 제품 적용은 부모 에이전트가 담당한다.

## 원본 타입 규칙

- `колющий`: 단검, 스틸레토, 에페/레이피어, 삼지창, 콘차르, 나기나타 → `pierce.svg`.
- `рубящий`: 글라디우스, 커틀러스, 톱니채찍(`пилохлыст`), 바스타드, 마체테, 카타나, 플랑베르주, 그레이트액스 → `slash.svg`.
- `дробящий`: 맨손, 너클, 곤봉, 철퇴, 의자, 배트 등 → `impact.svg`.
- `психический`: 나가이카, 채찍(`кнут`), 스코토보이 및 포효 기술 → `whip.svg`.

특히 톱니채찍은 외형 이름과 달리 게임상 베기다. 또 정신 공격이 채찍 하나뿐인 것은 아니며 포효 기술도 존재한다. 이펙트는 현재 장비명보다 **실제로 계산된 피해 타입**을 따라야 부무기·특수기술에도 맞는다. 불·번개·냉기·빛은 원본의 다른 타입이며 이번 네 종류에 새 임의 효과를 연결하지 않았다.

## 제안 구현 조각

`hit-snippets.json`은 선언형 anchor edit 7개이며 제품을 수정하지 않는다. `make-hit-snippets.cjs`로 현재 원문에서 유일한 앵커인지 확인해 재생성한다.

1. 전투 초기화에서 명중·타입·적 ID용 UI 임시 배열 세 개를 비운다.
2. 실제 라운드의 피해 반영 직전/직후 HP·체력·정신을 비교한다. 어느 하나 감소하면 현재 슬롯에 실제 피해 타입과 적 ID를 기록한다.
3. 원본 pawn은 수치 감소 없이 `повержен` 상태로 쓰러지므로, 살아 있던 pawn에게 명중해 그 상태가 된 경우도 포착한다.
4. 2인 베기의 부대상 직접 피해 분기에도 같은 포착을 넣는다.
5. 실제 renderer가 현재 표시 대상과 ID가 일치하는 이벤트를 한 번 출력하고 임시 배열을 비운다. 사망 후 다른 생존자로 자동 이동한 화면에 이전 적의 피격 효과를 잘못 씌우지 않는다.

추가 로케이션·외부 의존성·인물 영구 상태는 없다. 전투 중 UI 임시 배열 세 개를 사용하며 기존 세이브는 미존재 값 0/빈 문자열과 초기화로 처리한다. 원본 승패·피해·보상 계산은 변경하지 않는다. 현재 표시되지 않는 부대상의 피격은 장면에 따로 나타내지 않는다.

## 검증 준비와 한계

`hit-native.cjs`: 12개 실제 엔진 fixture. 실제 `конец_раунда`와 원래 renderer를 실행하며, renderer 앞뒤에 관찰/판정만 붙인다. 두 대상 공격은 원래 `атака_игрока,22`도 실행하되 피해 계산 결과를 4로 고정하고 적 AI를 무해하게 만들어 재현성을 확보한다. 원본 수정이나 후보 입력 덮어쓰기는 하지 않는다.

네 종류의 피해, HP 무변화인 둔기·정신 공격, 완전 면역·피해 없음, 모디파이어 0의 정상 명중, 적의 정신 공격과 플레이어 찌르기 타입 공존, 동료 전투, 자동 다음 대상 이동, 두 대상 및 부대상만 피해, pawn 상태 패배를 검사한다. 원본에서 모디파이어 0은 빗나감이 아니라 기본 피해이므로 효과가 있어야 한다.

## 최종 후보 실제 검사

후보 `2f93a1bfbdf26717c04bf7d97cc16266035fb79b57befb00405760991f6300d6`에서 네 종류의 DOM 검사를 실제 엔진으로 완료했다. `hit-dom-v1/report.json`의 네 상황 모두 PASS: SVG가 실제 500×460으로 로드되고 25/200ms에 보이며 750ms에 숨겨진다. 해당 시간축에서 루트·전투 배경·기록·좌우 정보창·FX 레이어 사각형은 변하지 않는다. 중간 EXEC 계측 없이 850ms에 한 번만 terminal callback을 보낸다.

`hit-native-v4/report.json`에서 주요 9개 상황은 통과했다. 상대 정신 공격 사례는 최초 기대값이 원본의 정신 회복을 누락했다. 적은 공격으로 정신을 3 회복하고, 플레이어도 자신의 타격으로 정신을 2 회복한 뒤 7 피해를 받아 최종 995가 정상이다. 제품을 변경하지 않고 이 기대값만 고친 `hit-opponent-v5/report.json`의 별도 재검사도 PASS다. 따라서 주요 10개 상황은 확인했고, 전체 12개가 한 실행에서 PASS했다고 주장하지 않는다. 부분 실패 보고서는 덮어쓰지 않는다.

두 대상 기술은 진단 조건에서 부대상 HP·체력·정신이 모두 100이고 명중 마커가 없다. 수정 전 a6e32... 원본과 이번 후보에서 같은 값이 관찰돼 새 FX가 만든 회귀로 보지 않는다. 이 두 경우는 성공적인 부타격을 증명하지 않으며 원본 분기의 한계로 별도 기록한다. `secondary-parity-observation.json`에 숫자 대조를 남겼다. 진단의 숫자 출력이 완료 marker에 붙어 smoke runner가 완전한 marker와 다르다고 판정한 보고서도 PASS로 바꾸지 않는다. 신규 효과 작업에서 원본의 피해·대상 선택 로직은 고치지 않았다.

최초 두 빠른 검사의 `$MAINTXT` 실패는 진단 tail이 GT로 이동하면서 화면이 지워진 하네스 문제였다. GS로 판정하도록 진단만 고쳤다. 제품 렌더러에 대응 변경은 없었다.

추가 전체 검사 `hit-native-final-v6`은 중복 검사가 불필요하다는 부모 에이전트의 후속 지시로 자기 진단 프로세스와 그 자식만 종료했다. 이 미완료 실행은 통과 결과에 포함하지 않는다. 언어 동작만 따로 보려던 `exit-loop-probe-v1`도 정상 완료가 확인되지 않아 원인 확정 근거로 사용하지 않는다. 본래 두 대상 경로의 의미와 메커닉 수리는 이번 범위에 포함하지 않는다.

이 검사는 네이티브 상태·생성 HTML·실제 SVG 로딩과 시간축의 고정된 사각형을 확인하며, 미술적 품질·모든 해상도·모든 실제 세이브 GUI 로드까지 판정하지 않는다.
