# 리벨리스·오베레그 신규 숨은 특성 표시

## 승인 내용과 변경

사용자는 신규 특성 전체에서도 리벨리스·오베레그 활성 중 보유한 숨은 특성이 보이도록 승인했다. 신규 표시 경로를 전수 대조했고, 누락은 야심가·끈기·산만함·옹졸함·너그러움 5종과 옛 저장의 비표준 활동 조합에 쓰이는 일벌레·안분지족 2개 표시 조건이었다. 다른 신규 특성은 이미 보유 시 표시하거나 리벨리스 표시 조건을 지원한다. 자세한 분류·호출 근거는 `AUDIT_KO.md`를 따른다.

`jo9_traits` 로케이션의 목록 반환 부분 7곳만 바꾼다. 기존 `실제 보유 AND 발견됨`을 `실제 보유 AND (발견됨 OR spell_revelio=1)`으로 바꾼다. 실제 보유 조건을 괄호 밖에 유지하므로 주문을 켰다고 미보유 특성이나 반대 특성을 표시하지 않는다. 통합 활동적·휴식 선호는 이미 같은 규칙이므로 변경하지 않는다.

새 로케이션·저장 키·UI·함수·의존 호출은 추가하지 않는다. 효과, 확률, 자연 발견·강제 발견 API, 실제 보유값과 known/revealed 기록은 변경하지 않는다. 명기의 known은 실제 상태 부여·유지에도 쓰이는 별도 값이며, 숨은 보유 특성의 표시 조건이 아니므로 주문으로 추첨·부여·변환하지 않는다. 이미 보유한 명기는 기존 표시 규칙을 유지한다.

## 입력·출력과 부수 효과

기존 `$func('jo9_traits', 'list', 역할)`을 사용한다. 역할은 기존 호출이 전달하는 `slave`, `assistant`, `room1` 등 인물 접두사다. 반환은 기존 링크와 색상 처리에 사용할 HTML 문자열이다. 변경된 목록 함수는 영구 인물 값을 쓰지 않는다. 리벨리스 활성 중 미발견 보유 특성을 문자열에 포함하는 것이 유일한 동작 변경이다.

`spell_revelio`는 기존 리벨리스 주문과 오베레그 장착/장면 갱신이 설정하는 공통 플래그다. 해제·주문 종료 규칙은 원본 그대로다. 플래그가 꺼지면 자연 발견 전 특성은 다시 숨겨지고, 이미 발견한 특성은 계속 보인다. 주문이 발견 기록을 영구 1로 바꾸지는 않는다. 오베레그의 다른 효과도 바꾸지 않는다.

좌측 특성 목록과 중앙 전체보기는 같은 features_list를 재사용한다. 공통 목록 반환을 수정하므로 화면별 JavaScript나 별도 캐시·레이어 변경은 필요하지 않다. 후보·위탁 상세에서도 기존 공통 목록 호출에 반영된다. 기존 `$slave_traits`의 자연 발견·상태 정리는 그대로며, 이 변경 자체가 자연 발견이나 인물 수리를 추가하는 것은 아니다.

## 코드 위치와 의존성

선언형 명세는 `2026-10-28_revelio_new_traits.json`이다. `REVELIO_NEW_AMBITION_20261028`, `REVELIO_NEW_LEGACY_WORK_ACTIVE_20261028`, `REVELIO_NEW_LEGACY_WORK_PASSIVE_20261028`, `REVELIO_NEW_FOCUS_POSITIVE_20261028`, `REVELIO_NEW_FOCUS_NEGATIVE_20261028`, `REVELIO_NEW_GRUDGE_POSITIVE_20261028`, `REVELIO_NEW_GRUDGE_NEGATIVE_20261028` 마커로 각 변경을 찾을 수 있다.

의존성은 기존 `jo9_traits`의 목록 반환·동적 역할 치환과 `spell_revelio`다. 각 OR 조건을 제거하면 해당 표시 누락만 돌아온다. 목록 함수나 기존 플래그 자체를 삭제하면 다른 특성·주문의 기존 호출에도 영향을 주므로 제거 대상이 아니다. 7개 OR와 새 마커를 역으로 제거하면 기준 본문과 정확히 같다. 다른 로케이션과 수동 변경은 보존한다.

## 저장과 적용

기준 QSP는 `972d1b7a8719c9b44e6aca4bfaf5a6f73908240762ce65061a7d298d0aa82679`, 후보는 `3fbdb2cca0e3eb2d4a70c2f9b442f2fb39bb756f1aefe6217cf8c10668f1106c`다. WORK만 적용하며 기존 세이브 파일을 수정하거나 마이그레이션하지 않는다. 새 저장 값도 추가하지 않는다. 배포용 QSP·엔진·CSS·JavaScript·이미지·ZIP은 수정하지 않으며 커밋·푸시는 하지 않는다. 적용 백업과 최종 해시는 `installation.json`에 기록한다.

재현 스크립트는 `build.cjs`다. WORK 적용 후에는 첫 인수로 적용 직전 백업을 지정한다. 재현 테스트의 기준 경로 지정법과 실제 엔진 검사 조건은 `tests/REPORT_KO.md`에 기록한다. 공식 검사는 해당 패치 한 개만 든 폴더를 `--mods-dir`로 사용한다. 모든 과거 패치를 임의로 다시 적용하지 않는다.

## 검증과 한계

수정 전 actual 목록 함수에서 미발견 산만함이 주문 활성 중에도 숨겨지는 기대 실패를 확인한 뒤 후보를 작성했다. 각 표시는 실제 보유값·미보유값·발견 여부·주문 여부·역할 조합으로 검사하고, 인물 전체 23묶음 보존과 기존 목록 연결·장착/해제 플래그·발견 API 회귀를 구분한다. 구체적인 조건 수와 실행 결과는 `tests/REPORT_KO.md`, 독립 검토는 `REVIEW_KO.md`를 따른다.

공식 출고 결과는 `official-report.json`을 따른다. QSP 구조·줄/주석 경계·바이트 왕복·패치 재생·멱등성과 설치 엔진의 공통 9경로 검사다. 정적 검사만으로 모든 동적 QSP 문법이나 게임 전체 플레이를 증명하지 않는다. 기능 검사는 합성 상태의 실제 엔진 실행이며 개인 세이브의 GUI 불러오기·실제 클릭·시각 배치를 검사한 결과와 다르다.
