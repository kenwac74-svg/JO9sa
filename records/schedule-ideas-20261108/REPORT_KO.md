# 패치 일정의 기획 아이디어 노트

일정 상단에 제목·자유 입력란·노트 저장 버튼·저장 상태를 추가했다. 노트는 작업별 메모와 별도로 저장하며 작성만으로 작업 상태나 진행 차수를 바꾸지 않는다. 저장되지 않은 내용과 저장 실패를 표시하고, 다른 작업 저장으로 화면을 다시 그려도 작성 중 노트를 덮어쓰지 않는다.

공통 저장소는 기존 CatalogDir/patch-schedule.json, schema1의 선택 ideaNotes 문자열이다. 노트가 없던 기존 파일도 기본 빈 노트로 읽는다. 노트만 갱신하는 요청은 changes:[]와 ideaNotes로 처리하고, 작업별 갱신은 노트를 보존한다. 명시적인 빈 문자열로 저장할 때만 노트를 지운다. 노트·일정 변경은 같은 revision 검사와 원자적 파일 교체를 따른다. 최대20,000자와 형식을 확인한 후 전체를 저장한다.

JSON 및 단독 HTML 내보내기와 브라우저 로컬 저장에도 저장된 노트를 포함한다. 노트 없는 옛 JSON은 현재 노트를 지우지 않는다. 생성템플릿·소스/WORK HTML·독립문서를 함께 갱신해 재생성 시에도 기능을 유지한다. 기존 각 HTML의 seed는 보존했다.

검증: 새4개와 기존4개 총8개 통과. 노트 단독 저장/새 인스턴스 조회, 기존 작업 보존, 작업 변경과 옛 JSON 호환, 명시적 삭제, 잘못된 노트/동시 수정의 부분 저장 방지, 실제 HTML 코드의 로컬 저장/재조회와 내보내기 연결을 확인했다. 생성 HTML의 JS 문법도 확인했다. 실제 브라우저에서 노트 입력·미저장 안내·버튼 활성·새로고침 후 공통 기록 조회·50개 작업 유지·콘솔오류0 확인. 운영 파일에는 시험 문구를 저장하지 않았다.

범위: 소스/WORK의 일정 모듈과 HTML/템플릿, 정적 독립문서와 안내만 변경. 운영 일정JSON·QSP는 before.json 해시와 같으며 verification.json에 기록했다. Full·음원·세이브·커밋푸시는 변경하지 않았다. 복구는 before/<sha>.gz와 before.json을 비교하고 이후 사용자 수정을 보존한다. 모듈 복원 시3813 도구서버만 재시작한다. 시험 파일/임시 후보는 정리하고 소스의 schedule-ideas.test.cjs와 복구·핵심 보고서를 유지한다.
