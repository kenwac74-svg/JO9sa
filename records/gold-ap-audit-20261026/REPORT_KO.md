# 조수 질문 행동력·아그라바 금화 점검

게임 파일을 수정하지 않았다.

조수 질문1126·1118은 원본부터 talk_assistant이며 성공 대화 후 주인공·조수 현재 행동력을 각각1 쓴다. 체력 등급을 낮추는 처리는 아니다. 일반 노예 talk만 무료 예외가 있다. 원본 공통 비용 주석은 있으나 조수 정보 대화에 비용을 붙인 개별 이유는 확인되지 않았다. ASSISTANT_AP_KO.md 참조.

금화 누적 실패는 재현되지 않았다. 실제 interaction_city 보상/환전 코드에서 금7·스파크5000으로 시작해 환전5회와 근무 보상2회를 처리했다. 금202에 첫 수입85와 재근무37이 더해져 금324·스파크3050이 저장됐다. 별도 게임의 실제 Game→Load 메뉴로 이 진단 세이브를 불러온 값도 금324·스파크3050이었다. refresh_database 후에도 유지됐으며 전액 역환전 후 금0·스파크6290으로 정확히 정산됐다.

금0/17의 환전 화면은 모두 상단에 스파크1000만 출력한다. 금→스파크 메뉴의 실제 목적지302114는 금이 있을 때만 활성이다. 화면 보유금은 스파크이며 금은 별도 통화다. 원본부터 금 잔액 표시가 없고 금화 변경 계산은 현재와 원본이 동일하다. 금 표시 누락은 UI 보완 대상이다.

제보 세이브 자체는 없으므로 특정 파일의 실제 실패까지 부정하지 않는다. 실제 GUI로 생성 진단 세이브를 불러왔으며 전체 원본 ongload·신고 퀘스트·역할별 근무 장면까지 검증한 것은 아니다. 버그 수정·대화 비용 변경·금화 UI 추가·커밋·푸시는 하지 않았다.

재현: native.cjs가 격리된 economy-write·금0/17 표시 사례를 만든다. economy-write 실행 후 gold-load-ui.qsp에서 Game→Load로 gold-state.sav를 선택한다. 이 엔진에서 OPENGAME은 월드 열기 경로이므로 실제 Save/Load 대신 쓰지 않는다. 초기 진단 가정 실패는 initial-harness-note.txt에 구분했다. 원본 비교는 GOLD_SOURCE_AUDIT.json, 최종 검증값과 한계는 REPORT.json에 있다.
