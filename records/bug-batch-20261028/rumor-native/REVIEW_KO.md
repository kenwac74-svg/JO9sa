## 핵심 구현 검토

변경은 기존3개 로케이션 `jo9_traits_value`, `jo9_rumor_scan`, `jo9_buyer_rumors`의 패치 재생으로 구성된다. 새 로케이션은 없다. 기본 slave 거래의 기존 평가/수수료/매각 처리 흐름을 유지하고, 소문에서만 읽기용 복제 인물을 평가한다.

최종 quote helper의 probe API는 인물 역할 하나만 넘기는 임의 평가 함수가 아니다. scan에서 이미 계산한 `rating`, `slave_base_price`, `slaveprice`를 숫자 인자로 명시 전달해야 한다. quote 본문 전체에서 유효한 고유 local 변수에 이를 보관한다. 기본 slave 호출은 기존 `$slave_price` 실행 뒤 같은 고유 변수에 값을 옮긴다. 이렇게 해야 QSP의 위치 호출/LOCAL 범위에서 원래 전역값을 훼손하거나 엉뚱한 인물의 등급을 읽지 않는다.

이 위험을 겨냥한 시험도 통과했다. 실제 probe는 등급4/길드100, 개인500인 상태에서 일부러 전역 rating0/auction_price0=6000을 남겨도 올바르게 개인을 추천한다. 다른 인물의 오래된 전역 평가값으로 길드 추천이 바뀌지 않는다.

원래98명 전체의 구매조건/지역 roster는 이 fixture에서 새로 전수 증명하지 않았다. 이번 변화가 없는 실제 matcher를 사용하되 시험마다 지역 roster를 합성 고객들로 고정해 가격 비교 분기를 격리했다. 전체 roster의 실제 거래 경로·지급식 감사는 별도 `rumor-price-audit/REPORT_KO.md`의 범위다.

## 검토 중 발견해 수정된 문제

중간 후보는 적용하지 않았다. 실패와 수정 근거는 `review-history.json`과83085단계 개별 결과/계측 로그에 구분해 보관한다.

1. JS String.replace의 `$'` 치환 토큰이 본문을 잘못 삽입했다. root가 callback 치환으로 바꾸고 기준본부터 다시 만들었다.
2. obedience를 기존 평가보다 먼저 읽어 낡은0값으로 감가했다. 실제 첫 견적70/반복354 대 baseline354로 확인했다. 평가 뒤 파생값을 읽도록 수정했다.
3. 새 중첩 GS 가격 평가가 caller LOCAL 밖의 공유 가격 전역29개를 덮었다. 원본104변수는 차이0인데 후보만 변했다. probe의 추가 평가/killvar를 제거했다.
4. QSP 주석에 닫히지 않은 ASCII apostrophe가 들어가 이후 코드를 먹고 실행이 멈췄다. 해당 주석 한 줄을 바꾸자 실행이 다음 명시적 실패까지 진행했다.
5. nested FUNC는 caller local rating을 묵시적으로 읽지 못했다. 작은 엔진 fixture에서 local4/global731일 때 callee가731을 읽음을 확인했다. 숫자 평가 인자를 명시 전달하도록 바꿨다.
6. 그 인자를 inner IF 안의 LOCAL로 선언하면 END에서 범위가 끝났다. 계측 args4/315/212 대 END후rating0으로 확인했다. 최종 후보는 quote 전체 범위의 고유 local 이름으로 해결했다.
