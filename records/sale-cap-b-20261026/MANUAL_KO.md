# 판매 상한 B안 — 동작과 검증 범위

2026-10-26 사용자 선택에 따라 일반 상인·공개경매는 최종 지급액 $6,000, 개인 고객 변동판매는 $8,000으로 제한한다. 이번에는 옵션 난도와 관계없이 같은 상한을 사용한다. 실제 WORK 반영·검사 결과는 `FINAL_RESULT.json`을 따른다.

## 계산과 적용 범위

희귀 특성 평가·배수·기존 난이도 가격식을 먼저 계산한 뒤 `min(기존 최종 금액, 상한)`을 적용한다. 상한 미만 금액은 그대로이며, 기본 가치·등급·특성·구입 이력·고객 취향을 새로 계산하는 기능이 아니다.

- `jo9_traits_value/dealer_quote`: 현재 일반 매입처인 잡파·웡의 공통 견적을 최대 6,000으로 반환한다.
- `slave_auction_sell` 및 `_end`: 잡파의 희귀 재제안 배수 이후 표시·지급을 각각 제한한다. 인물·기본 견적의 기존 확인 가드는 유지한다.
- `$guild_auction`: 기존 특성 보너스까지 계산한 최종 낙찰액을 제한한 뒤 마지막 가격 대사를 만든다. 이전처럼 같은 희귀 배수를 두 번 적용하지 않는다. 기존 중간 입찰 AI·호가 연출은 변경하지 않는다.
- `interaction_city=931`의 남녀 두 지급 분기: 이미 높은 낙찰액이 저장된 이전 세이브도 실지급은 최대 6,000이다. 다른 의뢰도 쓰는 전역 `sparks_get`을 일괄 제한하지 않는다.
- `interaction_city=911/912/913`: 개인 흥정·정가·할인 계산 뒤 각각 최대 8,000으로 견적을 만든다. NPC 현금 보유량이나 할인·흥정 확률은 변경하지 않는다.
- `interaction_result_city`의 `slave_sold_house/slave_sold`: 기존 개인 견적이 높게 저장됐어도 실지급은 8,000 이하로 제한한다. 기존 지급·인물 제거 경로를 사용하며 새로운 재실행이나 별도 지급을 추가하지 않는다.

정액 납품 `sell_slave_simple/complex`, 개별 고정 퀘스트·계약 보상, 파산 급매·주택·시설 정산, 대출·환전에는 적용하지 않는다. 휴면 `slave_sell_done`을 활성화하거나 수정하지 않는다. 새 매입 NPC·메뉴·로케이션·영구 저장키는 없다.

## 기존 저장 화면

웡의 상한 초과 확인 화면은 기존 재견적 복귀 경로를 재사용한다. 잡파는 기존 로드 재표시 처리를 유지한다. 개인·경매의 옛 결과 설명을 표시할 때는 해당 초과 금액에 조회 전용 한도 안내를 붙인다. 표시 중 인물·금액·저장된 대사·콜백을 다시 실행하지 않는다.

옛 `choice_screen` 확인 질문에 이미 박힌 가격 문구 전체를 갱신했다고 보장하지 않는다. 이 경우에도 실제 지급 위치에서 상한을 다시 적용한다. 이미 지급이 끝난 거래를 다시 실행해 새 가격으로 정산하거나 과거 수입을 회수하지 않는다.

## 검증

실제 설치 FastQSP의 격리 진단본에서 기존본의 초과 거래를 재현한 뒤 후보를 비교한다. 개인 3가지 견적·2가지 지급·상한 미만·고정 의뢰 보존, 상인·경매의 경계·난도·희귀 재제안·예전 낙찰액을 검사한다. `private-tests`, `trader-tests`, `view-results.json`에 범위와 결과를 분리한다. 일부 평가·화면 끝점·인물 정리에는 진단용 stub을 쓰므로 모든 원래 UI·모든 세이브 전체 플레이의 증명은 아니다.

공식 출고 검사에는 QSP 구조·바이트 왕복·줄/주석 경계, 정확 패치 재생·재적용과 실제 엔진 9경로가 포함된다. 수동 마우스 플레이는 사용자 담당이다. 기존 금화 확인용 세이브·Full·보호 원본·설정은 해시로 보존한다.

## 재현·의존성·분리

패치 `2026-10-26_sale_cap_b`, `SALE_CAP_B_*_20261026` 표식으로 변경을 찾는다. 견적과 지급을 함께 유지해야 한다. 견적만 남기면 옛 고액 콜백을 통한 초과 지급이 남고, 지급만 남기면 새 거래도 화면 가격과 달라질 수 있다.

최소 복구본은 `before.qsp.gz`와 `patch.json`이다. `node integrate.cjs reproduce`는 이 복구본에 정확 패치를 적용해 G:/Codex/tmp/sale-cap-b-20261026에 검사 후보만 복원하며 WORK를 쓰지 않는다. 준비·검사·적용 때의 상세 경로는 `PLAN_KO.md`와 각 재현 스크립트를 따른다. 롤백으로 기존 사용자 세이브를 덮어쓰지 않는다.

본 작업은 WORK만 반영하며 배포 폴더·ZIP·커밋·푸시는 변경하지 않는다. 이번 진단용 QSP·복제 JSON·파생 저장은 핵심 결과를 보존한 뒤 링크 대상을 따라가지 않고 정리한다.
