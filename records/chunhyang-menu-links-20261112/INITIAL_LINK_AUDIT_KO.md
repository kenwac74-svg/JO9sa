# 춘향 클럽 버튼 링크 오류 — 2026-11-12

상태: 원인 및 수정 후보 검증 완료. 사용자에게 WORK 반영 확인을 요청했으며 아직 답변 대기 중이다. 현재 WORK는 변경하지 않았다.

## 확인된 원인

현재 WORK QSP f3d41973ab1b65e2075c486e9f4b88eb73b0bd3e66165bc2b37386c4506e3672의 `jo9_chun_club` 새 메뉴는 `exec_options`에 `gt 'jo9_chun_club','about'` 같은 명령을 전달한다. 공통 `$menu`의 `exec_options`는 HTML href를 작은따옴표로 감싸므로 안쪽 작은따옴표가 속성을 닫는다. 실제 FastQSP가 생성한 HTML을 표준 HTML 파서로 읽으면 주소가 `EXEC:gt `에서 끝난다.

대화·결투·출전·공급 조건·노예 제안·영입 약속·실제 영입의 7곳이 같은 오류다. ‘시합을 본다’는 기존 interaction_city/get_link가 내부 큰따옴표 명령을 사용하므로 정상이다.

‘클럽을 떠난다’도 원래 get_link 주소는 정상이다. 실제 생성 주소인 `city_form=121 & gt "city_menu_form"`을 엔진에 전달하면 최종 city_screen이 동부 구역(eastkvartal_district)을 표시한다. 현재 진단에서는 이 버튼의 고유 결함은 재현하지 못했다. 사용자 실제 게임 창에서 같은 상태로 클릭했는지는 확인하지 않았다.

캐릭터 그림은 shop_general에서 배경으로 분리되고 pointer-events:none이 적용된다. 그림이 모든 버튼을 가로막는다는 근거는 찾지 못했다.

## 수정 후보

새 메뉴 7곳에만 QSP 명령의 안쪽 따옴표를 큰따옴표로 통일한다. 예: `gt "jo9_chun_club","about"`. 공통 메뉴 함수·CSS·기존 관전/귀환 링크는 변경하지 않는다. 조건·보스·수치·참가 제한·소유권·세이브 상태는 변경하지 않는다.

선언형 후보는 proposed-mod.json, 전후 해시와 7모드는 fix-plan.json에 있다. 승인 전이므로 mods/에는 추가하지 않았다. 후보 적용 후 QSP SHA-256은 621af2dbeb6266de73ed3a21a42922a2525f0d01012764a962b4aabb86e0e363이다.

## 검증

- 실제 엔진이 생성한 open/city/claim HTML을 보관하고 Python 표준 HTMLParser로 분석했다. 수정 전 7명령은 모두 EXEC:gt 에서 끊기고, 수정 후 모두 완전한 GT 명령을 가진다. 관전·귀환 링크는 전후 동일하다.
- 실제 파서가 반환한 href 명령을 격리 FastQSP 진입점에서 실행해 대화·결투 무기 선택·출전 방식·공급 조건·판매 화면·동부 구역 귀환·관전 7경로를 통과했다(after-routes.json). 조건을 충족하는 합성 주 노예와 25만 스파크를 사용했다. 영입 2링크의 실제 주소는 검증했으며 이번에는 영입 전체를 재실행하지 않았다.
- 공식 apply_mods로 후보 재생·재적용 변경 0건을 확인했다. QSP 왕복·구조·CRLF·마커 경계 및 변경 필드가 jo9_chun_club.body 하나뿐인 것을 확인했다(scope-verification.json).
- 이전 귀환 진단 실패는 빈 진단 상태의 버전 업데이트 알림과 완료 마커를 city_menu_form 뒤에 붙인 계측 오류였다. 실제 코드는 city_screen으로 GT한다. 정상 버전과 최종 화면 확인 위치로 고쳐 귀환을 검증했다. 이 때문에 실제 게임 코드를 추가 변경하지 않았다.
- 기존 구현 검사는 메뉴 문구 존재와 함수/분기 직접 호출을 검사했지만 생성 HTML의 실제 href 파싱을 빠뜨렸다. 이번 재현 스크립트는 이 경계를 포함한다.
- 실제 사용자 SAV·실제 게임 창의 마우스 클릭·외형은 미검증이다. 이 결과를 정식 배포 전체 PASS나 모든 세이브 호환 보증으로 확대하지 않는다.

## 보관·다음 적용

baseline.qsp.gz는 이번 작업 직전 WORK의 검증된 압축 복구본, runtime-source.before.json은 당시 원장이다. 세 재현 스크립트와 HTML/파싱 JSON/엔진 로그·선언형 후보를 보관했다. 재생성 가능한 대량 진단 QSP·합성 SAV는 정리한다.

사용자가 반영을 승인하면 당시 WORK 해시가 기준과 같은지 다시 확인하고, 승인된 후보만 공식 적용기로 WORK에 적용한 뒤 추적 QSP·메타를 맞춘다. 게임을 완전히 재실행하고 클럽에 다시 진입해 새 메뉴를 생성해야 한다. Full·음원·실제 SAV·커밋·푸시는 이번 범위에 없다.
