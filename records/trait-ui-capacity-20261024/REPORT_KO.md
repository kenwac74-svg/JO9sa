# 특성 UI 용량 읽기 전용 감사 — 2026-10-24

현재 WORK QSP와 대표 테스트 세이브(01 HOME)를 읽어, 별도의 진단 QSP에서 slave_stat·assistant_stat·teach_screen을 실제 FastQSP 엔진으로 실행하고 SAVEGAME 주 설명을 추출했다. 세 경로 모두 완료 표식을 확인했다. WORK·원본 세이브·Full은 수정하지 않았다.

## 코드에서 확인한 구조

기본 논리 화면은1280×800이다. CSS1392~1411의left_column과left_column_assistant는x11/y0,215×790,경기천년제목 Medium20px이며줄높이normal,overflow visible이다. 최대 개수·스크롤·초과 목록 숨김은 없다. 노예 화면은slave_stat90~126,조수는assistant_stat70~109,교육은teach_screen65~104에서전체속성 뒤에목록을붙인다.

#static_base1919~2196의목록은선천/후천/성취뿐아니라상표없음·정신상태·상처·흉터·멍·기아·회복등도포함한다.2193행은HTML문자열길이666초과시font size2로감쌀뿐,개수나실제높이를계산하지않는다.임신출력은$slave_traits에서이판정뒤붙을수있다.

## 실제 HTML을 사용한 브라우저 실측

SAVEGAME은*nl의줄바꿈을CRLF로저장하므로,Edge대리측정에서는CRLF를br로표시했다.원본태그를자의적으로닫거나고치지않았다.원문은*-native.html,브라우저가파싱한좌측패널은*-column.html이다.최초CRLF를직접삽입한시험은HTML의공백축약때문에잘못된높이를만들어채택하지않았다.

WORK CSS전체와게임의실제경기천년제목 Medium.ttf를로딩한headless Edge에서일반20px/기존size2,분류헤더0/3,목록1~40줄을3종화면에대입해총480표본을측정했다.각특성은한줄에들어가는짧은표본명이다.

| 화면 | 첫 특성 y | 줄 간격 | y790 안 | y800 끝까지 | 분류 헤더3줄 추가 후 y790 안 |
|---|---:|---:|---:|---:|---:|
| 노예 |516|20|13줄|14줄|10줄|
| 조수 |511|20|13줄|14줄|10줄|

큰 '노예의 특성/조수의 특성' 제목은 그대로 둔 상태에서 세 분류 제목3줄을추가한조건이다.기존큰제목을분류제목으로교체하면약1줄을더쓸수있지만아직그배치변경을채택한것은아니다.분류사이여백을넣으면해당공간만큼다시줄어든다.

기존font size2는Edge에서글자가13px로작아져도부모의20pxnormal라인박스가남아줄간격20px가유지되었다.따라서이축소를최대용량확대수단으로간주하지않는다.

## 기획 논의에 쓸 수 있는 범위

현재단일목록의13줄을기준으로분류제목3줄과상태2~4줄을예약하면,실제특성행은8~6줄이다.선천/후천/성취의총합6개를안전논의예산으로삼을수있지만분류별상한을아직강제하지않았다.긴이름·긴특성명·상태가4개보다많은경우는이계산만으로보장할수없다.그경우줄바꿈·상태별도분리·목록상세화면등배치결정을함께해야한다.

## 검증 한계

실제FastQSP의화면출력코드실행과HTML추출은확인했다.픽셀기하측정은headless Edge대리측정이며QtWebKit의normal줄높이를직접측정한것은아니다.사용자가첨부한축소이미지는하단속성부분이Edge보다조금더아래로보여폰트렌더링차이에따른여유가필요하다.따라서14개가모든실제게임상태에서들어간다고단정하지않는다.일반세이브UI로드,전체게임플레이,기존목록의모든명칭폭을검사했다는뜻이아니다.

재현스크립트입력은최신QSP·CSS·대표HOME세이브,반환은격리엔진HTML과480개브라우저배치값이다.새함수·게임상태·세이브필드·게임의존성은추가하지않았다.기록의스크립트를없애도게임에는영향이없고본감사재현만할수없게된다.변경코드가없으므로문법수정검사는해당없으며격리QSP세경로엔진실행결과를보관한다.커밋·푸시하지않았다.
