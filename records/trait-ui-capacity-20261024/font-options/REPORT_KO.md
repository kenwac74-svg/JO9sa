## 긴 명칭과 중첩 font size=2

실제 상태 감사의 exactEightRowFixture를 사용했다. 명칭은 신경 쇠약, 상표 없음, 가벼운 상처, 끔찍한 흉터, 끔찍한 구타 흔적, 고통스러운 허기, 회복 [30], 임신 중기이며 임신 표시의 굵은 글자도 유지했다. 현 등록 특성의 비교적 긴 명칭 12개와 함께 215px 폭에서 측정했다. 검사한 192개 조건 모두 이 표본의 자동 줄바꿈은 없었고, 줄간격이 글자 크기 이상인 경우 글자 행 겹침도 없었다. 향후 더 긴 새 이름이나 사용자가 임의로 편집한 이름까지 보증하지 않는다.

기존 방식처럼 font size=2만 씌우면 Edge에서 글자는 13px이지만 줄간격은 20px으로 남았다. 단순 글자 축소만으로 표시 행수가 늘지 않는다. 18px/18px 블록 안에 기존 size=2가 남아 있어도 중첩 요소를 정리하지 않으면 이 표본에서는 줄간격20px이 관측됐다. 목록 블록과 내부 a/font에 font-size:inherit; line-height:inherit를 함께 적용한 대리 표본은 18px 글자·18px 줄간격이 일치했다. 실제 수정 시에는 기존 중첩 size 속성 제거 또는 목록 안에서만 해당 속성을 덮는 처리가 필요하다. 전체 left_column의 폰트를 줄여 기본 속성 영역을 바꾸는 안은 시험하지 않았다.

## 측정 범위와 한계

- 원래 실제 엔진 캡처는 유지하며 QSP 개행을 기존 재현기와 동일하게 br로 변환했다. 캡처 HTML 내용과 기본 속성 배치는 비교용 목록 아래 부분 외에는 바꾸지 않았다.
- 3화면 × 8글자크기 × 2줄간격 × 4상태예산 = 192개 배치와 중첩 font 9개를 측정했다. 추가로 각 배치에서 특성0~24개를 넣어 용량을 탐색했다.
- 원래 CSS 서체를 직접 로드했으며 font-loaded를 검사했다. 기본 속성 블록의 20px 폰트가 전 조건에서 유지됨을 검사했다.
- 글자/줄간격을 모두 명시한 Edge 실측이다. QtWebKit의 렌더링·사용자 캡처와는 특성 시작 위치가 논리20~30px 다를 수 있으므로 추가 예약 표를 별도로 제시했다.
- comparison.png는 앞선 18/18,16/16,13/13의 12특성+8상태 비교 이력이다. 최종 recommendation-comparison.png는 20/20의12+8,16/16의7+8,13/13의12+8을 나란히 비교한다. 이 그림은 용량 비교용 이름 표본이며 실제 게임 캐릭터를 바꾼 화면이 아니다. 상단 라벨을 위한 표시용24px 이동이 있으므로 숫자 판정은 measurements.json의 원래 y값을 사용한다.
- 기존 실제 HTML을 재사용했으며 실제 QSP를 다시 실행하거나 게임을 수정하지 않았다. 세이브를 변경하지 않았다.

## 제안만 정리

읽기 쉬운 크기를 유지하려면 18px/18px의 목록 국소 변경을 검토할 수 있지만, 상태8행을 항상 예약하면서 특성12개를 전부 보여주는 해법은 아니다. 상태가 적을 때 같은 폰트로 더 많은 특성을 표시하고 상태가 늘면 나머지를 별도 자세히 보기로 넘기는 방법이나, 별도 상세 목록을 두는 방안은 추가 UI 설계 대상으로 남긴다. 이 조사에서 표시 제한·자동 삭제·새 버튼·획득 제한은 구현하지 않았다.

## 추가 확인: 12px와 추천 후보의 구분

12px/12px에서 특성12+상태8은 끝 y756으로 패널790까지34px가 남아, Edge 기준30px 추가 예약도 통과했다. 다만 현재20px에 비해 글자 크기가40% 줄어든다.

16px/16px에서 특성7+상태8도 15행×16px=240px, y516+240=y756으로 같은34px 여유가 남는다. 따라서 16px의 최대9개는 여유 없는 Edge 경계값, 7개는 Qt 차이를 위한30px 예약 후보로 구분해야 한다. 사용자가 아직 선택하지 않았으므로 선천3·후천2·성취2 같은 배분과 표시 UI는 구현하지 않았다.
