# 특성 표시 수 재제안 — 2026-10-24 후속

상태를 필수 표시하고 분류 제목을 추가하지 않는 최신 요청을 반영한 조사·제안이다. 게임 폰트·상한·획득 규칙은 수정하지 않았다. 사용자가 먼저 제시한 선천5/후천4/성취3(총12)을 읽기 쉬운 크기로 수용할 수 있는지 검토한 뒤 수를 다시 제안한다.

## 필수 상태의 상한

일반 노예·조수의 상태 표시 코드는 최대8행이다. 정신 상태, 상표 없음, 상처, 흉터, 멍, 기아, 회복, 임신 단계가 각각1행이다. 정신/기아/임신의 단계는 서로 합산하지 않는다. 질병은 오른쪽 아이콘으로 표시하며 이 목록에 추가 행이 없다. 최대값은 표시 조건상 동시 출력 가능한 분기의 상한이며 전체 게임 진행에서 이 최악 조합을 자연 획득하는 플레이를 재현한 결과는 아니다.

따라서 특성12개와 모든 상태를 보이려면20행이 필요하다. 현재 글자 크기만 작게 만드는 font size2는 줄 간격20px을 유지하여 공간을 확보하지 못한다. 목록을 담는 블록과 내부 링크/글꼴의 크기 및 줄 간격을 함께 지정해야 한다.

## 실제 HTML·게임 CSS/폰트를 사용한 대리 측정

1280×800 기준 패널 높이790, 특성 첫 줄은 y516 부근이다. 기본 속성20px와 기존 목록 제목은 유지하고 분류 제목은 추가하지 않았다. 상태8행과 실제 긴 상태 이름을 사용했다. 아래는 노예 화면 기준이다.

| 목록 글자/줄 간격 | 상태8행을 빼고 패널 경계 안에 들어간 특성 | 렌더러 차이30px 여유를 남긴 특성 |
|---|---:|---:|
|20/20px (현재)|5|4|
|18/18px|7|5|
|17/17px|8|6|
|16/16px|9|7|
|12/12px|12개가 들어감|12개가 들어감|

16/16px에서7특성과8상태의 목록 끝은y756이어서34px 여유가 남는다. 12특성과8상태를 전부 넣으면16px에서는y836,14px에서는y796으로 패널을 넘는다.13px에서는y776으로 들어가지만 여유가14px뿐이다.12px에서야y756으로 같은34px 여유가 남는다.

픽셀 수치는 Edge 대리 실측이다. 이전 실제 게임 첨부와 특성 시작이20~30논리px 다를 가능성이 있어 이 여유를 따로 보았다. 실제 Qt의 모든 상태·창 크기에서 절대 넘치지 않음을 증명한 것은 아니다. 표본의 자동 줄바꿈·행 겹침은 없었지만 향후 긴 새 명칭은 별도 검사해야 한다.

## 추가 검증: 상단 빈 간격 압축

기본 속성 글자는 그대로 두고 실제 빈 간격5곳을 약5px로 압축했다. 분류 제목은 추가하지 않았다. 3개 기존 실제 엔진 HTML을 사용해 Edge에서 각1번씩 해당 국소 배치를 확인했다.

| 화면 | 회수한 높이 | 새 목록 시작 | 12특성+8상태 끝 | 패널 아래 여유 |
|---|---:|---:|---:|---:|
|노예|80px|y436|y756|34px|
|조수|75px|y436|y756|34px|
|교육|75px|y436|y756|34px|

기본 속성의 기존20px 값과 상단 기준 위치를 유지하고 목록만16px/줄 간격16px로 측정했다. 실제 긴 상태 표본의 줄바꿈과 목록 행 겹침은 없었고, 기본 속성의 행 겹침도 없었다. 위의 폰트만 변경한 표는 기존 여백 유지 조건이며 이 추가 배치와 구분한다. 새 QSP 실행·게임 적용·Qt 픽셀 검증을 통과했다는 의미는 아니다.

## 최신 추천

**선천5·후천4·성취3, 총12개를 유지하는 안을 우선 추천한다.** 기본 속성 글자는 그대로 두고, 그룹 사이 빈 간격만 약5px로 줄이며 특성·상태 목록은16px/줄 간격16px로 표시한다. 상태최대8행을 항상 수용하고 분류 제목은 추가하지 않는다.16px는현재20px 대비20% 축소다.

이 배치에서 표본의 하단 여유34px가 남아 이전 대리측정과 실제 게임의20~30논리px 차이를 고려할 공간이 있다. 모든 Qt 창크기·모든 미래명칭을 보증하는 것은 아니므로 실제 게임 화면 확인은 여전히 필요하다. 기존 중첩 font size2가 줄간격20px을 강제하지 않도록 목록 안 글자와 줄간격을 함께 정리해야 한다.

상단 여백을 반드시 유지한다면16px/16px에서 선천3·후천2·성취2, 총7개를 여유 있는 대안으로 둔다. 현재 배치에서12개를 위해12px로 줄이는40% 축소는 권하지 않는다. 이 두 안 중12개+상단여백압축안을 우선 제안하며 실제 게임에는 아직 적용하지 않았다.

인물의 기존 특성을 삭제하거나 숨기거나 효과만 남기는 변경은 하지 않았다. 실제 슬롯 획득 제한을 구현할 때는 특성별 분류와 선천/후천 양쪽 경로로 얻는 특성의 처리, 기존 초과 보유자 보존 방식을 따로 구체화해야 한다.
