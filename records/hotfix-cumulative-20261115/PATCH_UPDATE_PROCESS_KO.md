# 패치 업데이트·검사 재사용 절차

사용자 확정: 2026-11-15. 불필요한 검사를 생략하고 토큰과 시간을 줄인다. 사용자가 작업을 지시하더라도 직접 하는 편이 더 효율적인 부분은 먼저 제안한다.

## 기본 흐름

1. 최신 WORK와 승인 범위를 읽고 수정 파일 목록을 고정한다. 이전 배포물은 보존한다. 기록된 변경 파일과 최근 수동 저장, 크기·시각 차이로 대조 후보를 좁히고 해당 파일의 해시를 확인한다. 기준이 있으면 전체 리소스를 다시 스캔하지 않는다.
2. 수정 내용에 필요한 검사를 **한 번** 수행하고 파일 SHA-256, 검사 범위, 결과를 기록한다.
3. 같은 파일을 풀버전·변경분 패치·누적 패치에 재사용한다. 포장 방식만 달라졌다는 이유로 게임을 다시 검사하지 않는다.
4. 포장에서는 대상 기준과의 파일 합집합/누락, 실제 담긴 변경 파일의 바이트, 안전한 압축 경로, 압축 무결성을 확인한다. 동일한 중간 폴더를 여러 번 전체 복제·재추출하지 않는다.
5. 배포 파일이 검증한 수정본과 달라졌거나 실제 실패/새 우려가 생겼을 때만 관련 검사를 추가한다.

## 변경별 검사

| 변경 | 필요한 검사 | 기본 생략 |
|---|---|---|
| 대사·설명만 수정 | 변경 범위, 문자열/파일 구조, QSP 줄바꿈·패치 재생 | 게임 전체 9경로, 반복 세이브 검사 |
| 같은 경로의 그림 교체 | 파일 열림, 경로, 필요 크기. 이미 확인했다면 결과 재사용 | 엔진 전체, 재생성/재디자인 |
| 조건·계산·상태·콜백·이미지 조회·UI 배치 | 영향받는 경계값/동작만 목표 검사 | 무관한 기능 회귀 |
| 저장 구조·공유 핵심 초기화·광범위 갱신 | 신규/기존 상태 및 관련 통합 경로. 범위상 필요하면 전체 출고 검사 | 검증 후 동일 해시의 다른 포장에 대한 재실행 |
| 검증된 파일의 재압축·풀버전/패치 분리 | 파일 구성/해시, ZIP 무결성 | 게임 기능·세이브·시청각 재검사 |

전체 9경로 검사는 매 패치의 의무가 아니다. 광범위 변경, 검증 가능한 기준 부재, 관련 실패가 있을 때 사용한다. 기존 AGENTS 12·23항과 QSP 출고 문서의 일괄 실행 요구보다 이 최신 범위 기준을 우선한다. 검사하지 않은 항목을 통과했다고 표현하지 않는다. STATIC_PASS와 실제 엔진 PASS도 구분한다.

## 배포 형태

- 풀버전: 검증된 기존 풀버전과 동일한 수정분을 합친다.
- 변경분 패치: 지정한 이전 풀버전에서 바뀌거나 추가된 파일만 넣는다. 그 이전 버전용 전체 리소스를 다시 담지 않는다.
- 누적 패치: 지정된 같은 본편 기준의 승인 수정 합집합을 유지한다. 이미 본편에 들어 있는 동일 파일은 재포장할 필요가 없다. 필수 호환 경로는 본편에 있거나 패치에 포함되어야 하며 설치 결과에서 누락되면 안 된다.
- 별도 승인 없이 Full 원본/이전 ZIP 덮어쓰기, 업로드, 커밋·푸시를 하지 않는다.

## 사용자가 직접 하는 편이 나은 작업

화면/툴팁 육안 확인, 음원 청감, 플레이 감각·대사 자연스러움, 게시글 최종 확인·게시·업로드는 사용자가 더 빠를 수 있다. 그런 경우 이유와 일반 EXE에서 확인할 1~3개 항목을 짧게 먼저 제안한다. 사용자가 빠르게 처리할 수 있는 일을 복잡한 UI 자동화나 긴 에이전트 조사로 확대하지 않는다. 파일 비교·반영·패킹·정확한 해시 확인처럼 자동화가 유리한 작업은 에이전트가 마친다. 이미 주어진 승인에 대해 다시 묻지 않는다.
