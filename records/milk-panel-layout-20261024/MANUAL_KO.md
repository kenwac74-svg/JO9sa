# 우유 협동조합 팻말·보유금 배치 — 2026-10-24

WORK QSP와 base.css, 저장소 CSS 원천에 반영했다. 우유 팻말은 오른쪽 정보 패널 아래 x930/y400, 숫자는 x932/y490으로 함께 이동했다. 원본 200×133 이미지를 그대로 쓰고 두 상자 폭만 200으로 맞췄다. 보유금 CSS의 원래 left700/top10은 바꾸지 않았다.

## 원인과 동작

#options의 $milk_cooperative[1]은 공용 메뉴 BEGIN만 호출하고 END를 누락했다. shop_general이 붙인 바깥 닫힘이 내부 메뉴를 닫아, 뒤에 출력하는 보유금과 팻말이 메뉴 안에 남았다. 기존 공용 $menu의 ===END=== 호출 하나를 추가해 메뉴를 정상 종결했다. 입력은 기존 milk_can/license/stock이고 결과는 동일 선택지 HTML에 정상 닫힘만 추가된 것이다. 가격·스파크·재고·버튼 조건·EXEC·대사·세이브 상태는 변경하지 않았다. CSS 가격판 두 선택자 이외의 전역 UI도 그대로다. 신규 함수·location·상태 변수·세이브 이관은 없다.

## 호출과 분리 시 영향

shop_general → dynamic $display_options[1] → $milk_cooperative[1]이 기존 $menu를 사용한다. QSP 표식 MILK_PANEL_MENU_CLOSE와 CSS MILK_PANEL_LAYOUT_20261024로 찾는다. END만 되돌리면 보유금 등이 메뉴 안에 다시 배치된다. CSS 팻말과 숫자는 같이 이동해야 서로 분리되지 않는다. before.qsp.gz와 before.css는 이번 수정 직전 단일 복구본이며, 패치 JSON이 정확한 원문·변경문·해시를 보관한다. 압축 원본의 해제 바이트 일치를 확인했다.

## 검증과 한계

이전 20261022 검사는 원래 출력에 없는 닫는 태그를 HTML 표본에 직접 추가해 실제 부모 꼬임을 놓쳤다. 이번에는 실제 FastQSP에서 shop_general 원문을 20상태(milk_can 0/1 × license 0/1 × stock 0/1/4/5/6)로 실행한 HTML을 진단 세이브에서 그대로 추출했다. 임의로 닫는 태그를 보완하지 않았다.

수정 전 20실패 → 수정 후 20통과: 보유금 x700/y10, 메뉴 밖 부모, 녹색 지정 범위 안의 팻말·숫자, 참고 정보 본문·메뉴·우유통과 비겹침을 브라우저로 확인했다. 전후 PNG도 시각 확인했다. 독립 검토에서 실제 전후 HTML의 모든 href/src와 메뉴 조건·문구가 보존됐음을 확인했다. ===END===의 정상 메뉴 카운터 초기화는 이후 우유 화면에서 읽지 않는다.

공식 구조·왕복·CRLF/주석 경계·정확 패치 재생/재적용·인물 등록·설치 엔진 9경로 PASS. 실제 GUI 화면, 다른 해상도, GUI 세이브 로드와 게임 전수 플레이 검증은 별도다. 실행 중 게임에는 이미 읽은 QSP가 남고, 옛 세이브의 이미 출력된 메뉴도 남을 수 있으므로 게임을 재실행하고 우유 협동조합에 다시 들어간다. 기존 로드의 refresh_database → #options 재정의를 사용하며 새 캐시 이관은 추가하지 않는다.

이미지·JSON·세이브·Full·배포 ZIP·커밋·푸시는 변경하지 않았다.
