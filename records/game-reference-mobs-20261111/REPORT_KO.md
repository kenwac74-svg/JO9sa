# MOB 정보 탭 (2026-11-11)

사용자 요청에 따라 기존 적 전투 특성 탭을 유지하고 별도 MOB 정보 탭을 추가했다. 현재 WORK 적 정의 70종과 춘향 확정 기획 1종을 표시한다. 게임 QSP는 변경하지 않았다.

## 사용

열람표의 **MOB 정보** 탭을 연다. 이름·ID·방어·기술을 입력하고 검색 버튼 또는 Enter를 누른다. 등록 상태(QSP 정의/미구현 기획), 분류, 이름순·체력/스태미나/사기/기본 피해 높은 순을 선택한 뒤 검색한다. 입력/선택만으로 자동 검색하지 않는다.

표는 이름·등록 상태·분류·체력·스태미나·사기·기본 피해를 비교한다. 이름 버튼을 누르면 위 상세 영역에서 방어 특성·저항·특수능력·공격 정의·작동 주의사항·출처를 읽는다. 필터에서 선택한 MOB이 사라지면 첫 결과로 상세를 바꾸며, 결과가 없으면 상세를 숨긴다. 선택 탭을 처음 열 때 구성하고 이후 탭 왕복 시 검색·상세·펼침 상태와 아이디어 초안을 유지한다.

춘향은 **확정 기획 · 게임 미구현**으로 표/상세에 표시한다. 기존 적70종 수와 미구현1종을 구분한다. 힘5·전투6은 기획 비교 기준이며 실제 적70종에 없는 힘/전투 값을 추정해 채우지 않았다. 체력200·스태미나300·사기200·피해15·사기피해차단·지정6속성·능력비율R·즉사/회피·연고 쉬움/보통3/하드6·30% 조건·CM 정산·6회 일반 참가·클럽 승계/폐쇄·사용자 배경을 두 최신 기획 문서에 대조했다. 홀수 주기 배치·일반 적2배의 세부 밸런스 등 미정 사항도 그대로 구분한다.

## 구현과 의존

- tools/game-reference/mobs-data.cjs: buildMobs(enemies)가 기존 적 자료를 복사해 MOB 표시 자료를 만들고 춘향 기획 한 행을 추가한다. 원본 enemies를 수정하지 않는다. 기획 문서를 기준으로 수동 유지하는 표시 자료이며 게임 패치가 아니다.
- mobs-ui.js: setupMobs(panel,tab,set)가 수동 검색·필터·정렬·선택 상세를 구성한다. textContent로 표시하며 게임/서버 저장 API를 호출하지 않는다.
- reference-template.html: 실제 탭·패널·비교표와 한 번만 실행되는 탭 초기화를 추가했다. 기존 탭을 CSS로 가리거나 교체하지 않았다.
- assemble.cjs: 기존 enemies 데이터로 mobs를 만들고 UI를 HTML에 내장한다. 기존 --enemies-only 재생성으로 갱신할 수 있다. mobs-data/UI 의존을 제거하려면 생성기 슬롯·탭 초기화도 함께 정리해야 한다.
- 현재 HTML/README/snapshot을 WORK game/modtools/game-reference에 설치했다. 실행 서버·시작기는 바꾸지 않았으며 요청마다 HTML을 읽으므로 재시작하지 않았다.

## 검증과 범위

이전 HTML의 traits/items/spells/meta/enemies 다섯 섹션을 전체 깊은 비교해 동일함을 확인했다. 새 MOB70행 각각의 기존 필드도 enemies와 모두 일치한다. 실제70·기획1·춘향200/300/200/15·힘5/전투6·연고3/6·R/CM 경계를 검사했다. 생성기는 내장 모든 JavaScript 구문도 검사한다.

실제 브라우저에서 71행→춘향 검색1행, 입력 중71행 유지, QSP정의 필터70행, 체력 정렬 상위 거대안개괴물/오우거/포탈가디언, 이름 클릭에 따른 실제 상세 전환, 결과 밖 상세 변경과 빈 검색시 상세 숨김, 기획필터1행, 연고규칙, 기존 적카드70종, 탭왕복/아이디어초안 유지와 콘솔오류0을 확인했다. 테스트 초안은 저장하지 않고 지웠다. 기존 저장·동시수정·백업/가져오기·API·마법 회귀검사10/10 통과. 독립 읽기 전용 검토에서도 추가 중요한 문제는 없었다.

QSP WORK/추적본 해시21f41a5203ff 및 개인 아이디어 파일의 기존 부재를 보존했다. 실제 QSP/세이브/전투 동작을 바꾸지 않았으므로 새 게임 엔진 검사를 추가하지 않았다. 일반공격 부가상태의 기존 <br> 키 불일치도 미수정 상태다. 음원·캐릭터JSON/이미지·Full·배포ZIP·커밋·푸시 변경 없음.

## 복구와 기록

before/에 변경 전 template/generator/HTML/README/snapshot이 있다. 복구 시 변경 소스를 복원하고 이번에 추가한 mobs-data/UI 및 생성 의존을 함께 정리한다. 현재 설치 HTML은 자체 내장 자료로 열리며 개인 ideas.json은 복구 대상으로 덮지 않는다. before.json은 보호파일 해시, validation.json은 자료 보존·설치 일치, ui-validation.json은 UI 확인, regression.log는10검사, mob-information.png는 최종 화면이다.

check-and-install-reference.cjs는 당시 재현용 검증·설치 스크립트다. 읽기 전용이 아니며 snapshot/설치HTML·README·snapshot과 validation.json을 쓴다. 이전 snapshot의 설치본 해시와 현재 보호파일을 먼저 검사하며 새 기준에서 무작정 실행하지 않는다. 재생성 가능한 중간 소스 사본·일회성 수정 스크립트·빈 회귀 임시폴더는 정리하고 원본 복구 자료·현재 소스·검증 기록을 남겼다.
