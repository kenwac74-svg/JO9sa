# 결투 패배 기록과 주인공 평판의 생사 판정

사용자 승인 기획: 누적 기절 패배를 판정점수에서 회당1점 감산하도록 바꾸고, 잔혹5 이상이면 살아 있는 패배자를 무조건 처형, 자비5 이상이면 무조건 살려 준다. 기존 단일 저장값 jo9_cruel_mercy는 음수가 잔혹·양수가 자비이므로 각각 <=-5와 >=5로 구현했다. 이는 원본 +100을 실수로 단정한 버그 수정이 아니라 사용자가 의도를 변경한 밸런스 작업이다.

수정 입력/출력: выход_из_боя의 정식경기 Start 및 캣파이트 Start1 패배 블록을 사용한다. 치명상 패배는 원래 rand(1,6)>slave[stamina]이면 즉사 결과1291/103002로 먼저 이동한다. 살아남은 패배만 성향 판정 대상이다. 기존 b=rand(0,3)와 valor=temper-loser_rating는 그대로 계산하고, cruel이면1292/103003, mercy이면1293/103004, 중립이면 기존 b>valor로 결정한다. 단일 predicate는 jo9_cruel_mercy<=-5 or (jo9_cruel_mercy<5 and b>gladiator_valor)다. 기존 난수 호출 순서를 유지했다.

기절 기록은 이번 생사 판정 뒤 증가한다. 정식 경기의 +=100 한 곳을 +=1로 바꿨고 캣파이트는 원래 +=1이라 그대로다. 도주 및 치명상 결과에는 새 기절 기록을 더하지 않는다. 플레이어 평판 때문에 강제 결과가 나와도 jo9_cruel_mercy 자체를 추가 가산·감산하지 않는다. 승리·연습·안개·고유 이벤트·다른 지급/성장/페널티는 바꾸지 않았다.

표시: interaction_city1292/1293과 캣파이트103003/103004의 주인공별 두 복제 경로, 합계6곳에 조건부 평판 대사를 넣었다. 잔혹은 패자를 처형해 온 주인의 소문 때문에 상대도 자비를 거둔 것으로, 자비는 주인의 평판에 상대도 목숨을 살려 준 것으로 서술한다. 임계값·확률을 표시 문구로 쓰지 않는다. 원래 중립 대사와 기존 수치 접미사, 그림 경로를 보존했다. 실제 사망 판정에는 평판 대사를 덮지 않는다.

저장 호환: 새 변수·로케이션·세이브 형식·자동 이관을 추가하지 않았다. 옛 세이브의 loser_rating=100 같은 저장값은 임의 환산하지 않고 유지한다. 따라서 새 기절부터1씩 증가하지만, 옛 큰 누적값은 중립 판정에 계속 영향을 준다. 자비+5는 그 값과 무관하게 살아 있는 패배자를 살린다. 다시 중립이 되면 기존 큰 기록의 영향이 돌아온다. 과거 기록과 캣파이트 패배가 섞인 값을 정확히 구분할 정보가 없으므로 별도의 저장 호환 설계 없이 추정 변환하지 않는다. loser_rating>0의 챔피언 해방 차단도 기존 조건을 유지했다.

검사: 기존 QSP에서 잔혹/자비 강제 결과와 새 KO증가가 성립하지 않는 실제 엔진 Red3을 먼저 기록했다. 최종 엔진 검사에서는 양 무대의 임계 전후, 중립 난수 경계, KO/도주/치명상 생존/즉사 선판정, 옛100기록 및 자비 구원, 주인공별 복제 대사, 승리/연습 회귀를 확인한다. 상세 개수·결과는 green-report.json에 있고 독립 review.json은 정적 검토와 구별한다. 공식 파일 구조·줄바꿈·주석 경계·패치 재생·재적용·설치 엔진9경로·WORK/Full일치도 PASS다. 격리 진단이며 실제 GUI의 모든 기존 SAV 불러오기 검증이라는 뜻은 아니다.

모드 JSON의8개 조각을 apply_mods.ps1로 최신 WORK와 현재 Full 테스트 빌드에 각각 적용했다. 직전 복구본·수정 전후 해시는 verification.json을 따른다. 이미지와 기존TC SAV7개는 보존했다. 이미지 목록 등장조건·Full 명세·릴리즈노트·간단TC도 갱신했다. 제거하면 새 KO가 다시100씩 쌓이고, 평판의 강제 판정과 대사만 사라진다. 이미 저장된 숫자는 제거만으로 복구되지 않는다. ZIP·커밋·푸시는 하지 않았다.
