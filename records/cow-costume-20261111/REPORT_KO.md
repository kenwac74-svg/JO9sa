# 젖소 코스튬 추가 — 2026-11-11

사용자 지시와 고급 훈련 조건 선택에 따라 WORK와 추적 소스에 반영했다. 기존 젖소녀 장비는 그대로 유지한다. Full·음원·사용자 세이브 파일·커밋·푸시는 변경하지 않았다.

## 게임에서 사용

홍등가 → 벼룩시장 → 노예를 꾸민다 → 일상복에서 **젖소 코스튬(25스파크)**을 상시 판매한다. 소지/착용 중인 캐릭터나 공용 보관함에 이미 있으면 해당 구매 항목은 회색이다. 구매한 옷은 기존 의상 변경에서 착용한다. 기존 노예·조수 의상 목록과 개인실 bridge의 같은 목록을 사용한다. 숨겨져 있던 조수 전용 시장 입구를 새로 개방하지 않는다.

| 효과 | 실제 연결 |
|---|---|
| 독특함 +1 | `ex_plus += 1` |
| 사육 상승 | `daily_bonus['instinct'] += 1`, 기존 하루 정산·상한 적용 |
| 젖소녀 교육 상승 | `learn_bonus['cowSK'] += 2`, 기존 교육 산식 적용 |
| 세련됨 −1 | `st_plus -= 1`, 장비 보정점수이며 등급1 직접 감소가 아님 |

지성·태도(pride) 감소, 부정 의상 무들렛, 기분 벌점, 착용 거부는 없다. 추가 긍정 무들렛·특성 부여·수술·외양간 이동도 넣지 않았다. 벗으면 보정은 기존 재계산에 따라 사라진다. 사육·학습의 정상 누적 결과는 일반 성장과 같이 남는다.

기존 `cow` 의상 그림을 공유한다. 등록 그림이 없는 캐릭터의 fallback과 조수의 강제 복장 모드 등 기존 이미지 우선순위는 그대로다. 새 PNG는 만들거나 교체하지 않았다. **고급 젖소녀 훈련의 `cow_gear` 요구는 원래대로**이며 코스튬으로 대체되지 않는다.

일반 EXE 확인 항목: 일상복 구매 목록의25스파크 → 착용 후 등록된 젖소 그림 → 하루 정산 뒤 지성·태도 감소가 추가되지 않는지 확인한다. 실제 사용자 GUI/개인 SAV 플레이는 미검증이다.

현재 벼룩시장 정의에서 노예 복장/노예 튜닉20, 짧은 드레스30, 무희 의상/코르셋40, 기모노/울 튜닉/토가50, 수녀 복장60, 고급 튜닉70, 퍼레이드 복장100이다.

가장 가까운 짧은 드레스30은 일일 사육+1·교육+2·독특함+1에 세련됨+1과 추가 일일 효과가 있다. 새 코스튬은 세련됨−1이고 교육 분야가 젖소녀에 한정되며 고급 훈련 장비로 인정되지 않으므로 저가 의상20~30 사이인25를 유지했다. 기존 젖소녀 장비25의 지성·태도 저하를 제거했지만 고급 훈련 기능도 대체하지 않는다. 다른 아이템의 가격/표기 차이는 이번 변경에 포함하지 않았다.

## 코드·저장 호환·제거

모드: `mods/2026-11-11_cow_costume.json`, 변경7건/기존6로케이션, 신규 `jo9_cow_costume`1개. 주요 표식 `COW_COSTUME_*_20261111`.

신규 helper는 GS 호출의 `$args[0]`으로 `data`, `equipment`, `menus`, `load`를 받는다. `data`는 신규 ID의 이름·가격·설명·데모·효과만 등록한다. `equipment`는 노예/조수의 저장된 의상 목록에 새 항목을 멱등 삽입하며, 옛 cow_gear줄이 달라도 원래 목록 초기화줄이 있으면 이를 기준으로 추가한다. `menus`는 벼룩시장 일상복 두 목록과 시장으로 식별되는 현재 `$display_options[3]`만 보강한다. `load`는 세 작업을 순서대로 실행한다. 전체 아이템/NPC/메뉴 DB를 재설정하지 않는다.

`#item_base`, `#dynamic`, `#options`의 기존 초기화 끝과 `$ongload` 첫머리에 각각 helper를 연결했다. 이후 게임이 해당 캐시를 재생성해도 새 옷이 유지된다. `interaction_city=39934/39834`는 기존 `buy_item/buy_item_assistant`로 연결하며 수량1과 신규 ID를 설정한다. `display_fullimage`는 새 ID를 기존 `cow` 키로 매핑한다. 실제 구매·장착·하루 효과와 이미지 선택의 나머지는 기존 처리다. 고급 훈련을 포함한 `interaction` 본문은 바이트 동일하다.

새 저장 구조·버전 플래그는 없다. 기존 의상 ID 문자열·인벤토리 키를 쓴다. 기존 세이브는 로드 시 신규 데이터/저장 캐시를 보강한다. 재시작 없이 옛 QSP를 이미 메모리에 읽어 실행 중인 게임에는 새 로케이션이 생기지 않으므로 새 QSP로 게임을 다시 열어야 한다. 기능을 제거할 때 이미 착용/보유 중인 `cow_costume`을 기존 의상으로 이행한 후 helper와 호출부를 함께 정리해야 한다. 다음 세이브 마이그레이션 검토에 이 신규 ID를 포함한다.

모드툴의 source/WORK 특성·아이템·마법 DB HTML과 아이템 자료에는 이 신규 행만 추가했다. 이전 전체 DB의 기준 해시는 유지하고 신규 행의 검증 QSP를 따로 기록했다. 개인 아이디어 저장은 건드리지 않았다. 추출기에서도 helper의 실제 정의를 읽도록 보강하여 재추출 때 누락되지 않게 했다.
