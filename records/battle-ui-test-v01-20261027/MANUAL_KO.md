# 전투 UI 테스트 버전 v01

WORK의 기존 세이브로 게임을 다시 실행한 뒤 전투에 들어가면 새 화면이 표시된다. 이미 실행 중인 게임은 QSP와 CSS를 다시 읽도록 재실행한다.

## 화면

- 중앙 전장: 795×596. 보유 중인 원래 적 본체 그림을 표시한다. 본체 그림이 없거나 경로가 유효하지 않으면 기존 전장 배경을 유지한다.
- 중앙 하단: 같은 폭의 기록 패널. 원본의 최근 행동 묶음을 표시하며 긴 내용은 스크롤한다.
- 좌우 상단: 적과 전투 인물의 기존 초상화·수치·상태·도움말·적 전환을 보존한다.
- 좌우 하단: 기존 행동 명령과 동적으로 정해지는 무기 기술을 표시한다. 기술명 뒤의 효과 문구도 원래 순서대로 유지한다.
- 결과: 같은 중앙 하단 패널 안에 기존 특수 상태 그림, 승패 문구·마지막 기록, 기존 thumbs up/down 복귀 선택지를 배치한다.
- 연출: 적 체력 감소 시 SVG 타격 이미지, 아군 체력 감소 시 오른쪽 상태 패널에 짧은 붉은 플래시. 기술별 개별 연출이나 누적 전투 로그는 이번 시험 범위에 없다.

## 변경 구성과 의존성

패치 ID: `BATTLE_UI_TEST_V01`, 선언 파일 `mods/2026-10-27_battle_ui_test_v01.json`.

- `боевой_интерфейс`: 원래 출력 앞뒤에 범위 한정 root를 추가하고 본체 그림과 연출을 출력한다. 기존 href 43개를 보존한다.
- `конец_боя`: 같은 root와 결과 제목을 출력한다. 기존 href 9개 및 전투 종료 처리는 보존한다.
- `раскладка_бой`: 공통 전투 시작에서 화면용 비교값을 초기화한다. 일반 전투·투기장·캣파이트가 모두 이 위치를 거친다.
- `css/base.css`: 파일 끝의 같은 ID 블록만 신규 배치에 사용한다. 원래 규칙은 유지한다. 추적본은 `assets/css-2.4/base.css`다.
- `content/pic/ui/jo9_battle_test_v01/slash.svg`: 코드로 작성한 투명 타격 이미지다. 원래 이미지 파일은 바꾸지 않는다.

화면 입력은 현재 적 문자열 ID `$враг[текущий]`, 본체 `$силуэт_моба`, 기존 HP·행동 문자열·무기 메뉴다. `$jo9_bui_enemy_id`, `jo9_bui_enemy_index`, `jo9_bui_enemy_hp`, `jo9_bui_player_hp`, `jo9_bui_ready`, `$jo9_bui_fx`, `$jo9_bui_result`는 화면 비교와 출력만 맡는다. 전투 수치·보상·소유권을 변경하지 않는다. 오래된 세이브에서 비교값이 없으면 0/빈 값으로 시작하고 공통 진입에서 다시 초기화한다. 세이브 마이그레이션은 없다.

CSS만 제거하면 새 요소에 배치가 없어지고, QSP만 복구하면 새 CSS는 root를 찾지 못해 적용되지 않는다. 정상 롤백은 아래 두 파일을 함께 복구하는 것이다.

## 검증 범위

공식 출고 검사와 추가 native DOM 결과는 같은 기록 폴더의 JSON에 보존한다. 실제 엔진이 원본 전투 출력 코드를 실행하며 배치·이미지·기술 목록·효과·결과 링크를 확인한다. 결과 링크의 출구는 진단 사본에서만 sentinel로 바꾸어 dispatch를 확인하므로 전투별 보상과 게임 전체 플레이를 모두 검사했다는 뜻은 아니다. 모든 적·무기·다중 전투 조합의 시각 품질은 향후 플레이에서 추가 확인한다.
