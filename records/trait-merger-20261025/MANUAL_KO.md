# 특성 통합과 배제 적용 설명

사용자가 승인한 통합2묶음·배제5묶음과 후속 '긍정 부정이 충돌하면 긍정만 남기고 부정은 삭제'를 반영한다. 일반8칸 상한, 칭호 수/세번째 칭호, 다재다능XP와 혀손실은 변경하지 않는다.

## 사용자에게 보이는 변화

연극성 인격장애와 인지욕구는 주목욕구로 통합한다. 기존 별칭과 새 정식값 중 어느 쪽을 보유해도 같은 통합 효과·설명을 사용하며 칭찬 보상을 중복 지급하지 않는다. 심리피학 성향과 비표준값은 그대로이고 주목욕구와 충돌한 은둔형 외톨이는 제거한다.

일벌레/안분지족과 과다행동장애/무기력증은 활동적/휴식 선호로 묶는다. 활동적은 기존 둘째 이후 활동의 기분+2와 기존 활동형 휴식 반응, 휴식 선호는 반복 활동의 기분-2와 기존 편안한 보상 반응을 합친다. 같은 효과를 두 번 적용하거나 XP 배율·행동력·비용을 새로 추가하지 않는다. 구형의 알려진 반대 조합은 활동적으로 정리한다. 구형 comfort=2처럼 통상 범위 밖인 값은 자동 정규화하지 않는다.

무모함과6환경 공포증, 노예근성과 자유로운 영혼/거센 반항심, 강한 복종심과 거센 반항심, 달변가와 선천적 벙어리는 긍정 쪽이 우선한다. 이 조합이 이미 있으면 승인된 부정 특성값과 그 발견값만 제거한다. 체력·기술·경험치·인물·관계·문신·상태·자금을 함께 초기화하지 않는다. 과거 부정 기억을 보상으로 바꾸거나 소급 보상을 지급하지 않는다.

미련한 소와 운동광/활동적은 모두 이점이 있는 조합이다. 기존 동시 보유는 유지하고 앞으로 충돌하는 새 부여는 막는다. 명백한 긍정·부정 충돌에서는 긍정 신규 부여를 허용해 부정을 정리하고 부정 신규 부여를 차단한다. 이미 가진 숫자형 특성의 수동 감소는 허용하여 cow2→1→0 같은 제거가 막히지 않는다.

기존 프로필·전체보기의 한 줄 목록과 하단 설명을 사용한다. 통합 특성은 한 번 표시하고 편집과 카오틱 에센스 삭제도 한 번만 처리한다. 별칭을 함께 정리하여 삭제한 특성이 다시 나타나는 것을 막는다. 카오틱 에센스 가격900/1회분과 대상 없는 경우 무소모 규칙은 그대로다.

## 코드와 저장 호환

패치 경계 TRAIT_MERGE_EXCLUSIONS_20261025, 선언형 패치2026-10-25_trait_merge_exclusions. 기존273개 로케이션을 유지하며 새 로케이션은 없다. QSP의21개 기존 로케이션만 변경한다. JS/CSS/이미지/JSON/설정은 변경하지 않는다.

jo9_traits의 attention_has/value/known은 기존 attention 별칭을 읽는 순수 질의다. attention_edit/opposite/fresh/remove/observe/confirm은 명시적인 부여·삭제·신규 생성·발견 처리이며 attention_repair는 충돌한 fame=-1만 제거한다. 새 인물별 키는 jo9_attention과jo9_attention_known 두 개다. 기존 저장의 누락값은0이며 전체 인물 배열과 함께 보관/교환된다.

activity_value/sign/compatible/known은 순수 질의이며 기존 work_ethic/comfort를 유지한다. activity_repair는 알려진 반대 방향 두 조합만 A1/C-1로 정리하고 activity_set/remove/generate는 명시적 편집·삭제·신규 생성 경로다. 기존 하루 활동 횟수/날짜 버퍼를 재사용하며 호출을 중복 추가하지 않는다.

allow(role,key,value)는 순수 허용 판정, set_guarded는 기존 편집기의 실제 대입과 거부 안내다. repair_exclusions(role)은 승인된 부정값만 정리한다. repair(role)는 세 정리 함수를 순서대로 호출한다. 파생 속성·가격·목록 계산의 역할 치환으로 실제 대상에 적용하며 개인실도 기존 bridge를 사용한다. 조회 함수 자체는 저장값을 변경하지 않는다.

$newloc의 기존 jo9_traits_revision을3으로 높여 구 저장의 동적 정의/설명과 해당 인물 파생값을 갱신한다. 기존 code_defined 무효화 외에 first_visit['interaction_result']를0으로 하여 그곳의 저장된 결과함수도 다시 읽는다. save파일을 일괄 열어 덮어쓰는 변환은 하지 않는다. 다만 불러온 뒤 게임 내 인물의 충돌 부정은 새 규칙에 따라 정리되므로 이후 사용자가 저장하면 정리 결과가 저장된다.

## 의존과 검증

QSP의 읽기/쓰기 모드, 생성/편집/효과/목록/삭제 연결은 함께 필요하다. 모드만 제거하면 FUNC/GS 호출이 잘못된 값을 반환하고, 화면 연결만 제거하면 효과가 있어도 설명이 누락된다. 생성 검사만 제거하면 새 충돌이 다시 생길 수 있다. 부분 삭제보다 이번 패치의 정확한 역적용과 새 저장값 보존 방침을 먼저 정해야 한다.

격리 후보의 실제 엔진 집중 검사와 공식9경로, 구조·줄/주석 경계·정확 패치 재생/재적용, 독립 검토 결과를 함께 보관한다. 대표 저장 상태를 재구성한 엔진 검사이며 모든 세이브의 GUI 로드와 모든 장기 플레이 분기를 증명한 것은 아니다. 실제 저장파일76개와 기존 보호파일은 전후 해시를 확인한다.

최소 복구본은 before.qsp.gz와patch.json이다. 재현 스크립트·설명서·핵심 보고서만 보존하고 복제 JSON/QSP/시험 세이브는 검증 후 정리한다. WORK만 적용하며 Full/ZIP/커밋/푸시는 하지 않는다.

정리 후 재현은 node scripts/build.cjs restore로 격리 후보를 복원하고 node scripts/native.cjs focus로 수행한다. 현재 WORK를 before로 다시 준비하지 않는다. 공식 검사는 복원된 candidate.qsp/before.qsp/patches와 기존 대표 HOME세이브·엔진을 입력하고 cache-revision3, 출력은 별도 jo9-trait-merger-release-20261025로 지정한다. 이 과정은 현재 WORK를 덮어쓰지 않는다. 파일 경로와 로컬 검사도구가 달라지면 스크립트 상수를 먼저 검토한다.
