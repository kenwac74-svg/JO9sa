# 후속 확정: 긍정 우선 배제 구현

사용자 지시 `긍정 부정이 충돌하면 긍정만 남기고 부정은 삭제해`를 반영했다. 파일은 격리된 workspace 구현 모듈이며 런타임이나 세이브 파일은 직접 수정하지 않았다.

## 공통 모드

- `func('jo9_traits','allow',role,key,value)`: 순수 판정. 긍정 부여는 부정 반대값이 있어도 허용하며, 이미 긍정을 보유한 배우의 신규 부정 부여를 막는다. `0` 해제·같은 값은 허용한다.
- `gs 'jo9_traits','repair_exclusions',role`: 해당 배우의 승인된 충돌만 정리한다. 반환 `result`는 지운 필드 수다. 완료표식·XP·발견 상태·무관한 known·기초/누적 능력값은 건드리지 않는다.
- `func('jo9_traits','set_guarded',role,key,value)`: 원래 수치형 편집기 setter. 허용 판정 후 값을 쓰고 위 repair를 실행한다. 이미 보유한 값의 같은 부호 절대크기 감소는 편집기에서 허용한다. 따라서 cow2+sport1에서 소 적성 `2→1→0` 감소/제거가 막히지 않는다. 새 유익 특성 추가에는 이 예외를 적용하지 않는다.

## repair가 지우는 값

| 남기는 긍정 | 정확히 지우는 부정값 |
|---|---|
| courage=2 | 여섯 환경 attitude 중 `=-1`인 필드만 0 |
| jo9_slave_nature=1 | meekness<0을 0; 기존 배제 관계의 defiant=1도 0 |
| meekness>0 | defiant=1을 0 |
| expression_affinity>0, 표시명 달변가 | jo9_voice_trait=1을 0 |

`jo9_voice_trait=2`는 이번 정리 대상이 아니다. 공포 양수 내성/기호값, 통증 공포 등 여섯 환경 밖의 특성도 지우지 않는다.

cowSK 적성은 증산 효과가 있으므로 부정으로 간주하지 않는다. cow와 sport=1 또는 통합 활동 양수가 기존에 같이 있으면 repair는 둘 다 보존한다. 향후 새로 들어오는 쪽은 먼저 가진 유익 특성을 유지하는 기존 허용 판정을 따른다.

## 연결 지점과 루트 dispatcher 계약

원래 편집기31개 링크는 set_guarded를 사용한다. JO9 수동편집은 기존 동적 쓰기 직후 repair를 호출하며 nature 획득 초기화보다 앞이다. 생성/seed의 courage·nature·meekness·expression setter도 랜덤 후보를 한 번 계산하고 허용 판정 후 쓰고 repair한다. 기존 rand 호출 횟수와 순서는 유지한다.

기존 배우 자동 정리는 루트의 공통 dispatcher에서 `gs 'jo9_traits','repair_exclusions',role`를 호출하면 된다. 역할 문자열을 그대로 전달하고 UI/가격/프로필의 별도 역할 추정이나 새로운 영구 이관 상태를 만들지 않는다. dispatcher는 활동 담당 `activity_repair`와 관심/은둔 담당 repair도 같은 배우에 호출할 수 있다. 파생 UI/가격/목록을 만들기 전에 실행하는 편이 표시와 효과를 일치시킨다. 배우 전체 순회는 기존 역할 배열을 사용하고, 개인실은 현재 실제 배열 또는 기존 bridge가 임시로 옮긴 slave 중 실제 호출 배우를 사용한다.

파일을 불러온 뒤 메모리상의 배우 값을 정리하는 것이며 `.sav` 원본 바이트를 직접 편집하지 않는다. 사용자가 이후 게임 저장을 수행하면 정리된 현재 상태가 정상 저장되는 효과는 있다.

## 검증

모듈 JS 문법 검사와 현재 QSP에 메모리로 적용하는 검사를 수행했다. `testCases()`는69개 엔진용 본문을 반환한다. 긍정 우선 허용·신규 부정 거부·정확한 부정 필드 삭제·관련 없는 값 보존·유익 특성 동시 보유·cow 감소/제거·역할별 호출을 포함한다. 실제 엔진 통합 검증 결과는 루트 검사 보고서를 따른다.
