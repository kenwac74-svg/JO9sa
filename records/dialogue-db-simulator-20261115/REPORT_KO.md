# 일반 대사 DB · 캐릭터 시뮬레이터 질문별 메뉴

2026-11-15. 사용자 확정 구조를 통합 모드 작업실에 반영했다.

## 사용 위치

- **게임 DB → 일반 대사 DB**: 현재 WORK의 공통 원문과 메타데이터를 검색·열람·편집한다.
- **캐릭터 시뮬레이터 → 질문하기**: 사이드바와 본문 탭이 같은 상태로 이동한다.
- 질문: **인상, 불만, 요구, 희망사항, 기분, 과거, 조수/노예에 대해, 성경험**.
- 조수/노예 평가는 탭 안에서 방향을 선택하며 질문 번호 1117/1118의 개별 편집을 분리한다.
- 기존 과거 경험·사실·누적 기록은 **경력·기록**에 보존했다.

## 공통 정보와 독립 편집

상단 **01 캐릭터 정보·이름 / 02 배경**은 모든 질문에서 같은 인물을 사용한다. 질문을 바꿔도 캐릭터·배경을 재추첨하지 않는다. 새로 만들기/무작위 생성 등 기존 명령은 유지한다.

일반 질문마다 개별 문장을 브라우저에 보관한다. 캐릭터 편집의 **대사집 → 시뮬레이터 결과를 담기 → 대사집 저장**으로 기존 저장 형식의 `lines['general.1112']` 같은 칸에 보관한다. 원문 후보 ID는 브라우저에서만 보관하고 기존 `refs`의 인터뷰 키 검사는 변경하지 않는다. 기존 섹스토크 칸·참조·경력 저장도 유지한다.

**과거 묻기**는 세계·출신·직업의 기존 배경 DB 또는 유니크 원문을 사용한다. 별도 일반 대사 사본으로 분리하지 않는다. 과거 탭과 02 배경의 저장 전 초안은 서로 연결되고 탭 이동에도 남는다. 명시적 저장이 성공한 뒤 초안을 해제한다. 기존 4,000자 제한과 오류 안내를 적용한다.

**성경험 묻기**는 기존 섹스토크/필로우토크 UI와 인터뷰 DB를 그대로 사용한다. 별도 최상위 시뮬레이터가 아니라 질문하기의 하위 탭이다.

## 일반 대사 DB 범위와 저장

현재 WORK의 `#txt_man`, `#txt_woman`에서 **9,246개**(조립 문구 9,120개 + 기존 기본 원문 126개)를 읽었다. 문장이 아닌 식을 실행하지 않으며 현재 건너뛴 비문자열 항목은 0개다.

질문·성격·말투·관계·종류·검색어로 찾는다. 각 항목은 원문 ID, QSP 위치/행, 의미 자리, 성격·관계 조건, 말투, 표현 단계를 보여준다. 조수/노예 평가는 원본 게임처럼 같은 공통 풀을 공유한다.

DB의 **변경 보기**는 쓰지 않고 차이를 반환한다. **WORK 원문 저장**을 명시적으로 누르면 선택한 한 문장의 문자열 값만 바꾼다. 같은 위치의 다른 문장·메타데이터·다른 QSP 위치는 유지한다. 최초 백업과 위치별 선언형 변경 기록을 `game/jo9_editor/general-dialogue-patches/`에 남기고 묶어서 기록한다. 원문이 바뀌었으면 이전 화면에서 저장을 거부하고 재읽기를 안내한다. 저장 요청 중 선택을 옮기거나 더 입력해도 늦은 응답이 새 선택/초안을 덮지 않는다.

## 구현 파일과 연결

- `tools/modding-hub/general_dialogue.py`: QSP 데이터 추출·후보 검색·개별 원문 저장. `GeneralDialogueDB.search(params)`는 페이지와 건수를, `save({id,text,revision,dryRun})`는 변경/저장 결과를 반환한다.
- `overrides/general-dialogue.mjs`: 일반 DB 화면, 질문 탭, 사이드바 하위 항목, 공통 대사집 슬롯 변환. QSP 텍스트의 이름 자리표시자를 HTML과 구분하여 표시한다.
- `overrides/character-view.mjs`: 기존 01/02와 섹스토크/기록 카드를 보존해 질문별 작업영역에 연결한다. 기존 브라우저 저장 키를 유지한다.
- `overrides/studio-view.mjs`: 일반 질문 칸 표시와 기존 대사집 가져오기/내보내기에 연결한다.
- `integration.mjs`, `integration.css`, `server.py`, `Start-Modding-Hub.ps1`: 기존 UI에 메뉴·정렬·API·소스 갱신 연결을 추가한다.

이 모듈을 제거할 때는 서버의 API/파일 라우트와 빌드 목록, integration import/메뉴, character-view import/연결, studio-view의 질문명 import를 함께 복원해야 한다. 수정 전 소스의 압축 사본과 변경 diff를 이 기록 폴더에 보관했다. 원본 Claude 편집기 디렉터리는 수정하지 않았다.

## 검증과 실제 적용 범위

- Python 3건: 문자열·메타데이터·검색·페이지·따옴표, 무쓰기 미리보기, 한 문장만 저장, 외부 변경 충돌, 잘못된 입력의 무쓰기.
- JavaScript 5건: 8개 독립 메뉴, 일반/섹스토크 대사 슬롯 왕복, QSP 자리표시자 표시, 과거 초안의 검증 실패/탭 보존.
- 격리 HTTP: 일반 DB 읽기·검색·미리보기·저장과 기존 대사집 형식에 일반 질문 칸 저장/재읽기. 기존 마스터 편집 API 검사도 통과했다.
- 실제 UI: 사이드바 질문 이동, 공통 루미너스 ID/배경 유지, 독립 일반 문장, 과거와 02 배경의 원문 일치/초안 유지, 기존 성경험 탭, 게임 DB의 일반 원문 검색·열람을 확인했다. 시험 문장은 제거했고 배경 원문은 보존했다.

**시뮬레이터의 일반 대사는 성격·관계·말투 메타데이터로 찾는 편집 후보**다. 게임의 모든 발동·거절·후속 효과를 실행하는 완전한 QSP 엔진 시뮬레이션으로 표시하지 않는다. 실제 게임 조건 원문과 구분해 안내한다.

이번 작업은 도구 변경이다. 실제 WORK QSP/캐릭터 JSON/세이브에 시험 편집을 저장하지 않았다. Full/배포 ZIP/커밋·푸시는 수행하지 않았다. 게임 EXE 플레이 검증은 하지 않았다.
