# 거주지·지역 명성 BGM 가능성 검토

2026-11-08. 가능성 확인 완료, 본체의 순차 재생 기능은 아직 미반영이다. 별도로 요청한 기존 음원 형식 통일과 게임오버 전용 음향은 적용했다.

## 사용자가 확정한 규칙

- 방문한 구역에 따라 평상시 BGM을 바꾸지 않는다.
- 원본 귀족 신분·평판 우선순위를 먼저 적용한다. 현재 코드의 귀족 신분 또는 최고 평판이면 귀족곡을 기본으로, 그 외에는 거주지곡을 기본으로 삼는다.
- 해당 지역의 최대 명성 70%를 **초과**한 지역곡을 뒤에 붙인다. 정확히 70%는 제외한다.
- 거주지 외에 조건을 넘긴 지역 3곳이면 기본곡 1 + 지역곡 3 = 총 4곡이다. 거주지와 중복되는 곡은 한 번만 넣는다는 질문의 전제를 유지한다.
- 게임오버 음악은 게임오버 화면에서만 재생한다. 이 부분은 별도 모드로 구현·검사했다.

## 현재 엔진에서 확인한 방법

현재 WORK는 `$play_music`의 `only, loop`로 한 곡을 반복한다. `$counter` 등록은 주석 처리되어 있다. 일반 QSP의 [타이머 설명](https://dev.qsp.org/docs/language/qsp-keywords/qsp-keywords-sys-var/)만으로 현재 플레이어의 지원을 가정하지 않았다.

격리 엔진에서 확인한 결과, `ISPLAY`는 재생 전·중·후 모두 1을 반환했다. [기반 플레이어의 공개 콜백 소스](https://github.com/Ivanowich/FastQSP/blob/master/gui/qsp_callback.cpp)에도 항상 true를 돌려주는 구현이 있다. 기본 타이머 방식은 숨김 진단에서 완료되지 않았고, QSP의 `MSECSCOUNT` 역시 해당 진단의 실제 경과 시간과 맞지 않았다. 이 기능의 시계로 사용하지 않는다.

현재 엔진의 HTML 타이머와 EXEC 연결은 동작한다. `Date.now()`와 `sessionStorage`로 곡의 시작 시각·현재 순번을 유지하고, 실제 재생은 기존 네이티브 `PLAY`에 맡기는 진단을 만들었다. 2초·1초·2초·1초 네 곡을 약 6.3초에 걸쳐 재생했고, 첫 곡 도중 화면 이동을 한 번 거쳐도 첫 곡을 다시 틀지 않았다. 로그에는 약 2.075 / 3.149 / 5.223 / 6.301초에 순서대로 전환한 기록이 있다.

따라서 엔진 바이너리를 교체하지 않고 구현할 수 있다. 이는 음량 0·무음 파일로 확인한 순서/시간/화면 유지 검증이며, 실제 긴 곡의 청감·모든 게임 화면·이벤트 우선순위까지 검증한 완성 기능은 아니다. 음악 길이를 알기 때문에 가능한 방식이고, 파일 교체 시 길이 명세를 함께 갱신해야 한다. 오디오 장치의 지연·파일 로딩 지연이 큰 경우에 대한 확인도 구현 단계에 남는다.

## 실제 연결 시 필요한 범위

권장 방식은 위의 네이티브 재생 + HTML 시계다. 엔진 자체의 재생 종료 콜백을 고치는 방식도 가능하지만 엔진 빌드·배포 범위가 커져 이번 요구에 비해 부담이 크다. 완성 음원을 모든 조합으로 이어 붙이는 방식은 파일 중복과 용량 때문에 권장하지 않는다.

구현 시 지역 이동은 재생목록을 다시 시작하지 않고, 곡 경계에서 다음 항목으로 넘어가게 한다. 전체 목록이 끝나면 기본곡부터 반복하는 구성이 적합하다. 원본 집 기분곡·전투·경주·특수 이벤트곡을 어디까지 우선할지는 실제 연결 단계에서 호출 지점에 맞춰 정리한다. 이 항목은 제안이며 사용자가 이미 확정한 것으로 기록하지 않는다.

저장 형식 변경 없이 음악 목록·현재 순번 등 소량의 실행 상태와 브라우저 세션 시계를 추가하는 방법을 검증했다. 타이머는 오래된 화면의 중복 콜백을 현재 순번으로 걸러야 한다. 다음 BGM으로 넘어갈 때 기존 효과음을 자르지 않도록 전용 음악 재생과 화면별 중지 조건을 함께 연결해야 한다. 진단을 그대로 본체에 붙이는 것으로 처리하지 않는다.

## 지역 명성의 실제 데이터

카미라·세르피스·타우루스·코르부스와 홍등가·중앙·배제 구역은 기존 `faction_fame`을 사용할 수 있다. 일반 명성 등급 상한은 5이므로 70% 초과는 4 이상이다. 네 가문의 값 6은 다른 가문 귀족의 최종 결과 분기이고, 설명에는 명성 5로 표시된다. raw 값 6을 별도 최고등급 6으로 오해해 기준을 5로 올리지 않아야 한다.

빈민가·백색 도시에는 같은 형태의 독립적인 0~5 지역 명성 값이 확인되지 않았다. `faction_fame['neutral']`은 일반 지역 명성과 같은 등급표로 취급할 수 없다. 두 곳의 거주지곡 지정은 가능하지만, 명성으로 추가할 조건에는 임의로 전역 평판이나 주택 구매 허가를 끼워 넣지 않는다. 아그라바 등 확장 지역도 곡 파일 존재만으로 다른 지역 명성 값을 연결하지 않는다.

현재 조사 자료: `qsp-evidence.json`, `faction-fame-index.json`, `regional-cap-evidence.json`, `user-audio-metadata.json`. 재현 스크립트는 `native-probe.cjs`, 최종 성공 로그는 `playlist-stderr.log`이다.
