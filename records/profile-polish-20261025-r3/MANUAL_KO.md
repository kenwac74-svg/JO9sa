# 프로필·설명·금액 표시 수정

WORK만 반영한다. 원본 세이브·배포 폴더·배포 ZIP·커밋·푸시는 변경하지 않는다. 최종 실제 적용 여부와 파일 해시는 `FINAL_RESULT.json`을 따른다.

## 표시 결과

- 파산 엔딩과 프로필 하단 설명은 한 어절을 통째로 다음 줄로 넘긴다. 문장 원문과 공백·HTML·문단을 유지한다.
- 숫자와 동적 가격의 접미 `스파크`, `$`를 `$10` 형태로 통일한다. 가격 범위·굵은 글씨·부호도 유지한다. 화폐 이름 자체를 설명하는 추상적인 ‘스파크’는 보존한다. 별도로 쓰던 시작 자금 레이블은 ‘보유금: $금액’이다. 수식과 지급액·조건은 바꾸지 않는다.
- 노예·조수 프로필의 속성 그룹 네 간격은 5px에서 10px. 마지막 속성 그룹과 특성 제목 사이도 같은 10px.
- 좌측 특성 목록은 원래 글자의 80%(20px→16px). 기본 속성·제목·전체보기 링크와 중앙 3열 창은 원래 크기를 유지한다.
- 기존/신규 특성·상태·칭호 설명은 `[제목]<br>설명`. 공유 설명을 쓰는 무용 특성은 실제 선택한 이름으로 하단 표제를 맞춘다. 일반·그랜드 챔피언도 원래 단계 조건에 따라 표제를 고른다.
- 표시명 ‘주목욕구’는 ‘관심종자’. 다른 사람의 관심과 칭찬을 유난히 좋아한다는 설명으로 각색한다. 내부 `attention` 계열 키·부여·삭제·보상·배제 효과는 보존한다.

WORK를 완전히 종료 후 다시 실행한다. 기존 R2의 07번·08번으로 프로필을 바로 확인할 수 있다. 저장된 옛 프로필 HTML도 로드 시 해당 읽기 전용 프로필만 다시 그린다. 다른 이벤트 페이지를 무조건 재실행하지 않는다. 기존 테스트 세이브 파일 자체를 덮어쓰지 않는다.

## 파일·호출·부작용

- `jack.qsp`: 52개 로케이션 필드의 표시 문자열·조회 화면·기존 표시 캐시 후크를 변경한다. `PROFILE_POLISH_20261025_R3` 표식 및 선언형 패치가 경계를 기록한다. 표시만 바꾸며 가격 수식·지급/차감·특성 값은 보존한다.
- `css/jo9_traits_view.css`: `.jo9_profile_group_gap` 10px, `#jo9_tv_root .jo9_tv_list`만 80%. 중앙 팝업은 별도 body 자식으로 원래 column 글꼴을 읽으므로 줄어들지 않는다.
- 새 `content/js/jo9_word_wrap.js`: ES5, QtWebKit에서 `jo9_gameover_message`·`info` 두 컨테이너의 텍스트 노드만 공백 기준으로 감싼다. 각 어절은 `inline-block/nowrap`이며 공백과 기존 태그는 보존한다. 스크립트·스타일·숨김 메타·코드 노드는 처리하지 않는다. 비정상적으로 긴 단일 토큰만 영역을 넘지 않게 분리할 수 있다. QSP 변수·세이브·게임 이벤트를 읽거나 쓰지 않는다.
- `content/js/jo9_traits_view.js` 본문은 변경하지 않는다. 로딩 URL만 r3로 갱신한다. 새 단어 처리 JS는 `exit`, `slave_stat`, `assistant_stat`에서 명시적으로 불러온다.
- 기존 `jo9_profile_text_revision` 목표를 1→2로 올린다. 예전 세이브에서 `#static_base`, `#static_txt`, `#variative`의 원래 표시 정의를 한 번 갱신한다. 저장 파일의 형질 값·소유 인물·돈·날짜를 이관하거나 삭제하지 않는다. 새 캐릭터 상태 키는 추가하지 않는다.
- `jo9_traits_view`의 하단 조회는 이미 출력한 링크의 텍스트에서 태그만 제거해 표제로 쓴다. 조회용 local 값만 사용하며 인물 특성을 부여하거나 지우지 않는다.

새 JS만 빼면 실행 경로는 남지만 어절 분리 방지가 사라진다. CSS만 되돌리면 간격·좌측 크기가 되돌아간다. QSP만 일부 되돌리면 저장된 설명과 UI 리소스 버전이 달라질 수 있으므로 대응 패치·리소스를 함께 복구한다. 작업 직전 세 파일과 QSP의 최소 복구본은 `G:/somi/JO9_work_backups/profile-polish-20261025-r3`에 있다.

## 검사와 한계

공식 출고 검사에서 QSP 구조·개행·주석 경계·정확 패치 재생·재적용·실제 엔진 9경로를 확인한다. 별도 native UI 5건은 양쪽 프로필의 10px/16px/20px, 등급색·전체보기, `[관심종자]` 클릭·설명, 기존 캐시 2경로와 파산 엔딩의 모든 어절 위치 및 원문 텍스트 보존을 검사한다. 통화 3건은 소문 $10/$5, 동적 가격 범위, 파산 정보 금액과 기존 계산을 확인한다.

구형 QtWebKit는 `word-break:keep-all`을 무시했고 vendor 설정도 실제 분리를 막지 못했다. 이 두 진단 실패는 통과로 기록하지 않는다. 최종 후보는 원문을 유지하는 어절 span 방식으로 실제 Range 좌표를 다시 검사했다.

기존 R2 07번의 실제 Game→Load·활동적 클릭·전체보기·관심종자 클릭도 별도 창에서 확인했다. 이 실제 로드는 최종 어절 보완 직전 후보에서 수행했으며, 최종 어절 처리 자체는 실제 엔진 DOM 검사 범위다. 모든 세이브 CRC·전체 게임의 모든 분기/해상도를 수동 재주행했다는 뜻은 아니다.

재현: `prepare.cjs`→`build.cjs`→`compact-patch.cjs`로 후보와 문맥 패치를 만들며 `currency.cjs`·`trait-edits.cjs`를 이용한다. `compact-patch.py`는 최종 양쪽에서 유일한 문맥을 갖는 조각으로 패치 기록만 줄인다. 게임 코드 자체는 이 단계에서 바뀌지 않는다. `native-ui.cjs`, `native-currency.cjs`는 게임 밖 임시 진단을 준비한다. 검사 완료 로그·지표·패치·원본 보호 해시는 보존하고 재생성 가능한 QSP·복제 JSON·시험 저장은 정리한다.
