## 범위·호환 경로 검토

1. 우유 질문은 `내일의 우유 가격을 묻는다`를 그대로 유지하고 ` ($0~5)`만 제거한다. `shop_general`의 구캐시 보정은 `$display_options` 실행 후 출력 직전의 `$text_display`에서, `$place='milk_cooperative'`일 때 정확한 옛 문구만 교체한다. 질문 명령과 가격판·가격 산식은 유지된다.
2. `json/menu_icon.json`의 객체 leaf 차이는 정확히 회색 아이콘 11개다. 전부 `<li id="grey" ="background:`에 빠진 `style` 속성명만 보충하며 이미지 경로·이름·기타 값은 같다. `$menu` 보정도 같은 malformed prefix만 대상으로 하므로 구세이브가 복원한 아이콘 문자열을 표시 시점에 처리한다. 숫자 인자나 일반 클래스 문자열은 이 조건과 일치하지 않는다.
3. `main_screen`은 기존 `menu_potion_S`와 `menu_potion_S_assistant`에서만 클래스를 추가한다. CSS도 그 클래스의 직계 두 열만 `position:absolute;top:63px`로 맞춘다. 다른 메뉴나 물약 효과·재고·비용을 바꾸지 않는다.
4. 우유 재고 CSS는 x좌표를 캔의 x1125에 맞추고 너비85를 부여한다. 기존 y697·폰트·중앙 정렬은 유지된다.
5. 건강체질은 입수처를 직접 밝히던 문장만 힌트로 바뀐다. 명성 TIP은 장소와 개략적인 상승 방식으로 바뀌고 보상 수치가 제거된다. 남아 있는 3승은 출전 제한 안내다. `$ongload`는 기존 `#help_msg` 캐시 갱신 조건의 판별 문자열만 바꾸므로 옛 숫자 TIP도 갱신한다. 건강체질 효과, 명성 지급 실행, 랠리 분기·확률·수치는 바뀌지 않는다.
6. `interaction_city` 변경 블록의 주석을 제외한 차이는 30045의 `$text[2]`에 삽입한 `=` 한 문자뿐이다. 내용·조건·호출·교육·관용값을 바꾸지 않는다. 외곽 `SHOP_TEXT_20261026_008` 표식 안의 기존 J9M 표식도 보존돼 있다.
7. 변경 블록의 JO9 MOD 표식과 대응 END를 확인했다. 새 로케이션과 새 영구 키는 없다. 추가 대입은 기존 표시 문자열 및 함수 인자 보정이며, 별도 세이브 마이그레이션이나 revision 증가는 없다.
8. JS는 `#info`와 `#jo9_gameover_message`의 DOM 텍스트 노드를 span으로 감싼다. 가로 공백은 앞 단어의 `white-space:pre` span 안에 보존한다. 원문 textContent, 기본 폰트, CSS 본문은 유지하며 게임 상태·브리지·파일·네트워크를 쓰는 호출은 없다. 기존 두 번의 타이머 실행에서도 이미 감싼 단어를 재분할하지 않는다.

## 기존 실행 증거 대조

`ui-verification.json`, `ui-native-metrics.json`, `ui-cache-observations.json`, `UI-REPORT.md`를 확인했다. 기존 UI 전용 진단 8건이 PASS이며, 원시 기록에서도 회색 배경 11개가 기존 PNG URL로 표시되고 두 물약 열의 첫 줄 y좌표는 212로 같다. 우유 0/8/250의 숫자 중심은 캔 중심1167.5와 같고, 구캐시 질문도 높이62 한 줄 및 원래 `interaction_city=472` 명령을 유지한다.

`quest-findings.json`의 27회 실행은 원본/기준의 예상 실패 2회를 포함해 기대 결과와 일치한다. 기준·보호 원본의 30045는 실패하고, `=`만 넣은 사본은 통과한 비교가 보존돼 있다. 원본 랠리 라우팅 비교 기록도 현재·보호 원본 간 동일한 조건을 보여준다. 실제 사용자 제보 세이브의 네 관용값을 확인했다는 의미는 아니다.

최종 `spacing-native-results.json`, `SPACING_NATIVE_KO.md`, `word-wrap-manifest.json`에서 최종 JS 해시를 확인했다. 건강체질의 같은 줄 단어 간격은 0→5px, 게임오버는 0→6px이며 textContent·폰트·보통 어절의 분리 없음이 기록돼 있다. 긴 토큰 3개 fixture도 기록된 범위에서는 뷰포트 안에 남는다. 게임오버의 14px 세로 초과는 기준과 후보 모두 존재하며, 최종 기록은 `overflowY='visible'`, `scrollPossible=false`다. 따라서 이를 정상 스크롤 동작으로 설명하지 않는다. 최종 본문 아래472는 메뉴 위506보다 위에 있어 실제 겹침은 관측되지 않았다.

## 한계

- 네이티브 실행은 기존 보고서를 읽어 대조했다. 리뷰 중 실행기를 다시 돌리지 않았다. UI 진단은 UI 전용 후보, 공백 진단은 Start만 계측한 복제본이므로 최종 합본 전체 출고와 동일한 실행 범위라고 부르지 않는다. root가 진행하는 공식 9개 엔진 점검 결과는 이 리뷰의 독립 검증 대상 밖이다.
- GUI 저장·불러오기 호환은 검증되지 않았다. 기존 cache 문자열을 의도적으로 넣은 표시 검증과 정적 호출 경로를 확인한 것이다.
- 후행 공백 없는 긴 단일 토큰은 미검증이다. JS는 방문 전 `clientWidth`를 한도로 사용하고 측정 span이 그보다 클 때 fallback을 적용한다. 방문 전부터 intrinsic 폭이 확장되고 token 폭이 그 한도와 같다면 조건이 발동하지 않을 여지가 있으므로, 현재 결과를 모든 긴 토큰에 대한 보장으로 확대하지 않는다. 이번 승인 범위의 실제 설명에서 이 문제가 발생한다는 근거는 확보되지 않았다.
- 스크린샷 픽셀 비교, 사용자 실제 세이브의 전체 플레이, 모든 설명·해상도·동적 문구 조합은 검증하지 않았다.
- 보호 입력 해시 대조는 지정된 185개 범위다. 전체 이미지 라이브러리 전수 해시 감사라는 의미는 아니다. 변경 스크립트와 고정 조각에는 이미지·폰트 바이트 변경이 없다.

재생성 가능한 진단 사본은 이 리뷰에서 만들지 않았다. 남긴 산출물은 이 문서와 구조화된 리뷰 결과뿐이다.
