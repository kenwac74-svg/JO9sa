## 구세이브 캐시

명성 TIP은 `#help_msg:163`의 `$слава_совет`라는 저장 문자열이다. 현재 `$ongload:11`은 그 문자열에 `랠리: 첫 우승 +10`이 없을 때만 `#help_msg`를 부른다. 따라서 TIP 원문만 바꾸면 기존 숫자 TIP을 가진 세이브는 갱신되지 않는다.

helper의 세 번째 수정은 이 기존 감지 문자열만 `명성을 쌓을 수 있는 곳: 콜로세움의 경주와 투기 대회`로 교체한다. 구 TIP에는 새 문장이 없으므로 로드할 때 기존 `#help_msg` 호출로 갱신되고, 새 TIP에는 문장이 있으므로 이 조건 때문에 매번 다시 초기화하지 않는다. 새 영구변수나 로케이션, revision은 추가하지 않는다. 기존 `jo9_traits_revision=3`, `jo9_profile_text_revision=2`도 그대로 둔다.

건강체질은 저장 설명 변수가 아니다. `jo9_traits_view:53~54`가 현재 `jo9_traits`의 `text` 모드와 key `healthy`를 호출해 새 프로필 메타를 만든다. `$ongload:125~126`이 노예/조수 프로필을 다시 생성하며, 다른 화면에서도 프로필을 새로 열면 현재 문구를 얻는다. 이 설명을 위해 특성 캐시 revision을 올릴 필요는 없다. 프로필 HTML이 이미 만들어진 동안에는 해당 화면의 메타가 남을 수 있어 프로필 재생성이 반영 경계다.

## helper 사용과 검증

`text-edits.cjs`의 `buildTextEdits(doc)`는 `core.parse(raw)` 결과를 받아 `{location, field:'body', old, new, count:1}` 목록을 돌려준다. `jo9_traits` 설명 1개, `#help_msg` TIP 1개, `$ongload`의 기존 TIP 감지 literal 1개다. 입력 파일 쓰기, 세이브 수정, 캐시 실행, 빌드 설치는 하지 않는다. 완전히 적용된 문서에는 빈 목록을 돌려주며, 예상 문구가 달라지거나 중복되면 오류로 멈춘다.

읽기 전용 재현 명령:

```powershell
node 'C:/Users/User/.codex/.chatgpt-projects/g-p-6aad063c991081918e27b6675f290be7/artifacts/shop-text-quest-20261026/verify-text-edits.cjs'
```

메모리 안에서 3건 적용, QSP parse/serialize 왕복, 두 번째 적용 0건, 로케이션 수 동일, 대상 외 인코딩 필드 동일을 확인했다. 변경된 본문의 모든 인용문 내용만 가린 코드가 전후 동일한지도 확인해 조건·변수·연산자·인용문 밖 숫자를 보존했다. 특히 `jo9_traits_combat`, `jo9_contest_fame`, `interaction_city`, `#options` 본문 전체가 바이트 단위로 그대로다. 건강체질 성장/시술 효과와 랠리 우승/보상 산식은 변경하지 않는다.

건강체질 수정만 떼면 입수처 스포일러가 남는다. TIP 수정만 떼면 기존 숫자 안내가 남는다. 감지 literal 수정을 떼면 숫자 TIP을 저장한 구세이브가 계속 옛 안내를 표시한다. 의존성은 기존 `#help_msg` 초기화와 프로필 생성 경로뿐이다. 실제 엔진에서의 구세이브 로드와 보이는 단어 간격은 이 helper의 메모리 검증으로 확인한 범위가 아니며 별도 native 검증 대상이다.

이번 하위 작업은 진단 QSP·세이브·임시 복사본을 만들지 않았다. 남긴 것은 helper, 읽기 전용 검증 스크립트, 보고서와 최소 해시/점검 기록이다.
