## 합본용 수리 조각 사용 설명

`quest-edits.cjs`의 `buildQuestEdits(doc)`는 기존 코덱으로 파싱한 문서를 입력받아 `{location,field,old,new,count:1}` 조각 한 개를 반환한다. 로케이션은 `interaction_city`, 범위는 정확한 30045 블록이다. 기존 `$text[2] '…'`에 `=` 한 문자만 삽입하여 `$text[2]= '…'`로 만든다. 이미 고친 문서에는 빈 배열을 반환한다. 범위·대입문 형태가 어긋나면 중단한다.

이 함수는 제품/세이브를 쓰지 않는다. root의 합본 생성기가 반환 조각을 사용한다. 의존성은 Node.js `assert`와 기존 `tools/text-workshop/core.cjs`뿐이며 새 QSP 로케이션·호출·저장 키·교육 메뉴를 추가하지 않는다. 제거하면 합본에서 이 문법 수리가 빠지고 기존 30045 결함이 남는다. 다른 퀘스트 조건이나 저장값 변환은 없다.

조각 단독 메모리 적용 후 SHA256은 `3830581ba3fbb34cc68b84ed0b376f09f89114205332284071da0f088a03a3e3`이고 구조 파싱·위치 수 보존·멱등성을 확인했다. 최종 합본 SHA와 출고 검사는 root의 후속 결과를 따른다.

재현 스크립트는 `quest-probe.cjs`, `quest-aux-probe.cjs`다. 진단 QSP·설정 복사본·로그는 재생성 가능하며 `G:/Codex/tmp/shop-text-quest-20261026/quest`에서만 만들었다. 상세 합성 입력과 검사 결과 27회는 `quest-findings.json`에 통합했다. 절대 경로·하위 링크 부재·진단 save 폴더가 비었음을 검증한 뒤 재생성 가능한 파일 81개와 진단 폴더를 정리했고, 폴더 부재를 확인했다. 원본·제품·사용자 세이브는 정리 대상이 아니었다.
