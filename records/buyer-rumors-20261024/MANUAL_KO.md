# 지역별 구매자 소문 — WORK 반영

스컵스·작크·아네스의 기존 대화에 구매자 소문 메뉴를 추가했다. 기본 10스파크, 정상 납품 후 5스파크다. 주거지와 상점의 고정 요구사항만 취급하며, 가문 간부·궁정·캣파이트·동부 퀘스트 등 특수 진행에 따른 요구는 제외한다. 최종 목록은 roster.json에 지역·원본 호출 위치와 함께 보존했다.

## 게임에서 사용하는 방법

- 길드의 스컵스: 백색도시·네크로폴리스·황소구역·중앙구역.
- 버진스 힙의 작크: 뱀자리구역·추방자구역·동부구역.
- 카페 신들의 선물의 아네스: 홍등가·도시관문.

보유 인물마다 현재 조건이 맞는 구매처를 살피고, 그 중 요구 등급이 높은 고객부터 이름으로 추천한다. 동률이면 함께 알려 주며 한 페이지에 최대 세 명씩 표시한다. 정확한 가격과 흥정 결과를 예고하지 않는다. 이전·다음 소문과 대화 복귀에는 추가 비용이 없다. 결과가 없더라도 상담을 마치면 소문값을 내며, 살펴볼 소유 인물 자체가 없거나 돈이 부족하면 결제하지 않는다.

스컵스 할인은 길드 납품계약 정상 완료, 작크·아네스는 각 고객의 조건을 만족한 정상 거래 완료가 기준이다. 할인은 인물이 아니라 플레이어의 영구 서비스 이력이다. 기존 코드에 신뢰할 만한 과거 완료 이력이 없어, 이전 세이브의 완료를 추측해 할인을 부여하지 않는다. 업데이트 뒤 정상 납품을 완료하면 기록된다. 새 게임은 기존 Start/start_refresh의 killall을 따른다.

## 입출력·호출과 상태

패치 ID 2026-10-24_buyer_rumors. 입력 파일 해시 5102bad2f3142d064c8927207c90bdae41fe88a77c792ef038c39c2ba0e8b129, 적용 후 f81779df72185ba8afdad6b365a61c1281692fd565080ff94c15840b08c1a74b.

- jo9_buyer_rumors: fee는 제공자 키 skups/barman/anes로 10/5를 반환한다. menu는 한 번 사용할 결제 표식을 발행하고, buy/consult는 표식·장소·금액을 확인한 뒤 조회와 1회 차감을 한다. view/back은 결과 표시와 원래 대화 복귀, refreshmenus는 세 기존 메뉴의 정의를 갱신한다. discount는 해당 제공자의 완료 이력만 1로 설정한다.
- jo9_rumor_scan: 전역 결과 페이지와 조회 인원 수를 만든다. 기존 29개 보유 역할을 복사해 실제 등급·전문화·매력을 평가한다. 원본 인물·이름·기술·명성·역할·거절기록을 변경하지 않는다. 인물창 투영 중 조회는 실행하지 않는다.
- jo9_rumor_match: 구매자 ID, simple/house/full 모드, 매력검사 예외를 입력받아 1/0을 반환한다. 원본 모드마다 실제로 검사하는 항목을 재사용하며, 주거지 입구와 뒤따르는 전체 검사도 함께 반영한다. 요구 및 선호 메타데이터는 임시 배열에서 실행한다.
- jo9_rumor_roster: 제공자별 명단과 실제 구매처의 현재 이용 가능 여부를 반환한다. 일반 상점의 대기 상태·대출금·성별 분기, 주거지 완료 여부를 기존 코드대로 확인한다.

새 영구 상태는 jo9_rumor_discount의 세 제공자 키다. 결제 표식·결과 페이지도 게임 상태에 저장되지만 이 값으로 거래·의뢰를 완료하지 않는다. 임시 인물·요구 배열은 조회 후 지운다. 중첩 평가 함수가 지우는 임시 변수 여섯 개는 조회 전 정확한 배열을 보관하고 복원한다. 기본 평가 함수·정적 인물 목록·구매 메타데이터·기존 메뉴와 그림에 의존한다. 새 이미지·CSS·인물 속성 키는 없다.

기존 #options 끝에서 세 메뉴를 갱신한다. $ongload는 저장된 세 메뉴와 현재 장소의 복사본을 갱신한다. interaction_city의 두 길드 완료 지급 블록과 interaction_result_city의 정상 개인 판매 지급 블록에 할인 호출을 넣었다. 이 연결은 patch.json의 BUYER_RUMOR_* 표식으로 찾을 수 있다. 기능을 분리·제거할 때는 메뉴·로드·납품 호출과 네 helper를 함께 처리해야 한다. helper만 없애면 남은 호출에서 없는 위치 오류가 난다.

## 검증과 한계

실제 FastQSP에서 matcher 105사례, 결제·원본 상태 보존 87검사, 가용성 23검사, 29역할×3안내자 조회, 단일·복수 추천부터 HTML 출력까지, 다른 지역 배제, 정상 개인 납품 할인 12검사, 길드 완료 지급 2블록, 세 곳의 실제 복귀 이동을 확인했다. 할인 세 키의 엔진 SAVEGAME 저장과 세이브 코덱 바이트 왕복도 확인했다. 기존 76세이브·설정·CSS·Full은 해시로 보존을 확인했다. 공식 9경로, 구조·줄바꿈·템플릿 목록·정확한 패치 재생과 재적용 검사가 PASS다.

검사 중 생긴 임시값 유출은 수정 후 재검증했다. 동적 검사 스크립트의 가변 길이 배열 순회가 멈춰 명시적 키 비교로 바꾸었으며, 제품 코드 변경과 구분했다. 납품 검사본은 원본 완료 블록을 실행하되 마지막 공통 화면 이동만 멈춰 상태를 검사했다. 길드는 기존 성공 조건 자체를 새로 전수 증명한 것이 아니라 두 성공 지급 블록의 연결을 확인했다.

전체 동적 QSP 문법과 모든 플레이 분기를 수학적으로 증명한 검사는 아니다. 실제 마우스로 전 화면을 보는 GUI 검사, 사용자 세이브 파일의 GUI 로드와 CRC 호환은 이번에 검증하지 않았다. 숨김 엔진 실행과 HTML 검사는 화면 배치의 육안 검사를 대신하지 않는다.

WORK에만 적용했으며 배포용 Full·ZIP·커밋·푸시는 하지 않았다. 정확한 복구본 before.qsp.gz, 선언형 패치, 소스·재현 스크립트와 검사 결과를 보존한다.

재현할 때는 보존한 scripts/reproduce.cjs를 restore → build 순서로 실행하면 G:/Codex/tmp의 격리본만 재생성한다. 자동 적용은 하지 않는다.
