# 외형 분류 모드 이름·설정 화면 복구

`fresh_mode`를 게임 코드와 집·도시 설정 화면에서 사용한다. 숫자 0·1·2에 연결된 발동 조건과 효과는 기존과 같다. 설정 화면에서 외형 분류는 ‘어림’으로 표시한다.

수동 패치 조각은 도시 메뉴를 가리켰지만, 실제 WORK에는 집 메뉴의 ‘출현중’ 행이 `Fresh`로 바뀌면서 `under`와 `clear` CSS ID가 빠지고 버튼 명령의 `&`가 `&amp;`로 바뀐 상태였다. 도시 메뉴에 남은 유효한 구조를 사용해 복구했다. 배치 ID, 아이콘 경로, 버튼 이동 목적지를 보존했다.

구세이브에서 불러올 때 `fresh_mode`가 아직 없다면 `no_loli`의 값을 그대로 복사한다. 이후 입력은 `fresh_mode`에 저장하며, 과거 저장본의 동적 코드도 같은 값을 읽도록 `no_loli`를 호환용으로 갱신한다. 이미 `fresh_mode`가 기록된 세이브는 새 이름의 값을 기준으로 한다. 개인 세이브 파일을 직접 고칠 필요는 없다. 이전 이름에 대한 호환 쓰기를 제거하면 옛 세이브에 남은 비교식이 다른 상태를 읽을 수 있다.

## 검증

- QSP 엔진의 저장·불러오기 API로 옛 변수만 있는 세이브와 새 변수가 있는 세이브를 0·1·2 각각 검사했다. 로드 콜백이 실제로 실행되고 두 값이 일치했다.
- 집·도시 설정의 네 표시 상태에서 원래 CSS ID와 버튼 명령을 검사하고 클릭 명령을 실행해 원래 목적값으로 전환되는지 확인했다. 초기화까지 총 16건이 통과했다. 게임 EXE에서의 렌더링은 별도 확인하지 않았다.
- WORK와 저장소 소스의 기준본이 달라 각 파일에 같은 변경을 별도 적용했다. WORK에 남은 수동 수정은 그대로 유지했다. 양쪽 패치의 적용 전후 해시와 사용한 테스트는 이 기록 폴더에 있다.
- 원래 QSP로의 역변환은 바이트 단위로 일치했다. WORK 역변환에는 `work-patch.json`, 저장소 소스에는 `mods/2026-11-18_fresh_mode_and_settings_ui.json`의 edit를 역순으로 적용한다.
