# 1031 조수의 의상·전용 장면 확인

현재 WORK QSP 3ed148b3defa43003fe2ec033d15db14dcf817290271bc14079ee763ef0d750a를 읽기 전용으로 조사했다. 원본 QSP·JSON·이미지·사용자 세이브를 수정하지 않았다.

## 확인 결과

1031 전용 장면은 content/pic/girls/sex_scenes/1031의90계열617PNG가 실제 존재하며, 엔진이90계열617개를 모두 picMax에 등록했다. 각 계열의1번(무번호)부터 등록 개수까지 파일명 구멍이 없다. 현재 display_pic 원문에 assistant_type=1031 조건을 주면90개 호출 모두1031 전용 폴더 경로를 선택한다. 공용 그림으로만 고정돼 있거나 팩이 미연결된 상태는 아니다.

display_fullimage의 일반 의상21종×상태3개와 조수 역할모드3개×상태3개, 합계72조건에서 모두 기대 경로를 선택했다. 조수 하녀/비서/도미나 선택 버튼도 기존등록과 indpack 등록을 함께 검사하므로1031의 관련 선택지를 허용한다. 일반 거주지/조수 상태/개인실 화면에서도 같은 표시 함수를 부른다.

의상/기본전신 참조71개와 장면617개, 총688개에 대해 PNG 서명·청크 CRC·압축 해제를 확인했고 실패0이다. 모두795×596이다. 구속복은 상태별 변형2개가 없으므로 기본 구속복으로 대체한다. indpack_old_full은 구 전신 보관 참조이며 현재 의상 메뉴에 대응하는 새 복장이 아니다.

## 실제 플레이에서 구분할 점

조수 이미지 모드가 하녀/비서/도미나로 설정되면 현재 착용 의상보다 역할복이 우선한다. 일반 의상 변화를 확인하려면 기본 표시 모드를 사용한다. display_pic의 ID별 전용팩 우선은 상대 배우가 없는 호출에 적용된다. 두 배우가 함께 나오는 호출은 공용 조합 경로를 고르며, 격리 시험에서도 이 차이를 확인했다.

현재 실행 중인 게임 경로는 WORK로 확인했다. 읽기 전용으로 확인한 auto_day.sav와 kura01.sav의 현재 배치 슬롯에는1031 조수가 없어 사용자가 관찰한 실제 화면 누락은 재현하지 못했다. 따라서 특정 플레이 실패를 수정 완료로 표시하지 않는다. 확인된 결론은 현재 파일·등록·단독 조수 선택 경로가 정상이라는 것이다.

## 검증 범위와 재현

WORK 엔진에 동일 QSP 함수 원문과1031 JSON을 넣은 격리 진단을 실행했다. 원본 장면 미술은 복사하거나 화면에 표시하지 않았고, 유효한 중립 UI 이모지를 동일 파일명으로 배치해 선택 경로만 검사했다. 실제 원본 PNG의 무결성은 별도로 검증했다. 초기화는 원본처럼 killall로 JSON/이미지 목록을 다시 구성한 뒤 수행했다. 사용자 게임 프로세스는 건드리지 않고 진단용으로 시작한 프로세스만 종료했다.

audit-1031.cjs → audit-1031-assistant.cjs → tools/qa/run-client-smoke.ps1(assistant-plan.json) → verify-1031-files.cjs 순으로 재현한다. 생성 진단QSP/세이브/중립 이미지 중복은 정리하고 핵심 결과·스크립트만 보존한다. 기존세이브의 picMax는 저장되지 않는 엔진 자료이므로 저장파일에서 해당 변수가 없다는 사실만으로 등록 실패로 판정하지 않았다.
