# 병행 조회의 예상 문제와 보존 기준

상태: 사용자 전체 범위 승인, WORK 일괄 반영 대기. 후보 구현과 실제 EXE 검사는 아직 하지 않았다.

1. 양쪽 등록이 다른 유효 그림을 가리키면 단순히 처음 발견한 값을 고르는 것만으로 외형이 바뀐다. 이사벨라처럼 구·신 외형이 나뉜 인물은 특히 ID별·화면별 기존 우선순위를 보존한다.
2. 흥분·반항 그림 누락을 즉시 기본 전신으로 보내면 입힌 복장이 벗겨진 것처럼 보인다. 같은 복장의 일반 그림, 반대 등록의 같은 복장, 기본 전신 순서를 확인한다. 현재 흥분·반항 우선순위는 바꾸지 않는다.
3. 오래된 세이브의 외형 캐시나 이벤트 직접 출력이 공통 함수를 우회하면 메뉴만 고쳐도 다른 화면에 문제가 남는다. 표시 시 최신 등록을 조회하고 알려진 옛 별칭만 보정한다. 사용자 지정 외형이나 actor 캐시 전체를 일괄 덮어쓰지 않는다.
4. 옛·새 두 등록에서 같은 파일을 공유하는 인물은 파일명만으로 외형 주인을 추정하면 안 된다. 캐릭터 번호를 조회 기준으로 유지한다.
5. 파일 존재 검사로 메뉴 조건까지 강화하면 기존 선택지가 사라질 수 있다. 기존에 선택 가능했던 등록은 유지하고 파일이 없으면 승인된 B안으로 대체한다. 등록 자체가 모두 없는 복장까지 새로 열지는 않는다.
6. 파일 존재와 이미지 정상 해독은 다르다. 손상된 PNG나 기본 전신까지 모두 없는 경우는 조회만으로 해결되지 않는다. 체크리스트 결손 표시와 PNG 열림 확인이 필요하다.
7. 파일 존재 확인을 지나치게 반복하면 디스크 접근이 늘어난다. 화면에 필요한 소수 후보만 확인하고 전체 girls 폴더를 매번 검색하거나 세이브에 전역 파일목록 캐시를 추가하지 않는다.
8. 현재 파일 검사는 FastQSP 고유 `%경로%` 문법이다. 현재 코드에서 이미 사용하므로 재사용할 수 있으나, 새 후보는 실제 배포 EXE에서 존재·누락 경계 검사를 해야 한다. 표준 QSP/WASM 검사로 대신 통과했다고 보고하지 않는다.

파일명·캐릭터 번호·JSON·SAV 구조의 변경은 이번 안에 포함하지 않는다. 가장 큰 검증 대상은 조회 우선순위와 기존 화면의 그림 유지 여부다.
