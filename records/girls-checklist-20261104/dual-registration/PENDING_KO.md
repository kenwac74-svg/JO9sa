## 확정해 둘 조회 규칙

1. QSP 전체의 메뉴 조건, 클릭 조회, 공통 출력, 이벤트·결과 화면 조회에 새 등록과 옛 등록을 모두 확인한다. 파일명·JSON·SAV는 바꾸지 않는다.
2. **지금 정상적으로 표시되는 화면의 우선순위는 유지한다.** 새 팩이 이기던 화면은 새 팩을 먼저, 직접 옛 그림을 고르던 화면은 그 후보를 먼저 검사한다.
3. 먼저 고른 변형이 없으면 **같은 등록의 일반 그림 → 반대 등록의 해당 일반 그림 → 기본 전신** 순으로 실재 파일을 찾는다. 문자열이 있다는 것과 실물이 있다는 것을 구분한다.
4. 복장 등록과 기본 전신 대체를 구분한다. 등록이 있어 기존에 선택 가능했던 복장은 파일 누락만을 이유로 숨기지 않고 B안으로 표시한다. 두 등록이 모두 비어 있는 복장까지 기본 전신이 있다는 이유만으로 새로 열지 않는다.
5. 기존 resolver를 확장하는 방향으로 후보를 준비하되, 알려진 구형 별칭 보정과 사용자 외형 변경 캐시 보존을 유지한다. 새 영구 캐시나 저장 형식은 만들지 않는다.
6. `resolve`의 조기 반환 경로가 여러 개다. **함수명만 기계적으로 바꾸거나 맨 뒤에 fallback만 붙이는 수정은 금지**하고, 각 후보 반환 경로가 같은 검사를 거치는지 살핀다.

양쪽 기본 전신 파일 자체가 모두 없으면 조회 코드만으로 그림을 만들 수 없다. 그 경우는 체크리스트에 결손으로 남겨 보완해야 한다.

## 사용자 확정 구현 방식

사용자는 추천 설명 후 “그렇게 처리해 줘”라고 승인했다. 기존의 “WORK 반영하라고 할 때 한꺼번에 반영” 지시는 유지한다.

- 기존 공통 이미지 조회 함수를 보강하고 메뉴·클릭·집·이벤트·결과·미리보기의 표시 경로가 그 결과를 사용하게 한다.
- 화면마다 현재 정상 선택하는 후보를 우선한다. 해당 파일이 없을 때 상태별→같은 복장 일반→반대 등록의 같은 복장→기본 전신 순으로 이어진다.
- 메뉴는 구등록 또는 새등록 중 하나가 있으면 선택 가능하게 한다. 기존 선택지를 파일 누락만으로 숨기지 않는다.
- 기존 세이브는 표시 시 최신 등록을 해석한다. 배우 캐시 전체나 사용자 지정 외형을 일괄 덮어쓰지 않는다.
- 파일명·폴더·이미지·JSON·캐릭터 번호·SAV 구조를 유지하고, 캐릭터 생성·머리색 판정·배열 초기화용 코드는 출력 코드처럼 일괄 치환하지 않는다.
- 구·신 등록 혼용 인물과 기존 세이브를 우선 검사한다. 현 단계는 승인 기록이며 실제 코드 수정 완료를 뜻하지 않는다.
