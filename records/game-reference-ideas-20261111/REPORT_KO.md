# 마법 DB와 개인 아이디어 기록 — 2026-11-11

사용자 요청으로 기존 특성·아이템 열람표에 마법과 개인 아이디어 기록을 추가했다. 추적 소스와 WORK 모드툴에 설치했다. 게임 QSP 해시는 `0b08b2c36923fbc9495bf9de467b09feef26c5b0afd2ce0b7bdb286a6182ad3e` 그대로다.

## 사용법

1. 모드툴의 특성·아이템·마법 DB에서 **내 아이디어 → 새 아이디어**를 누른다.
2. 종류(특성/아이템/마법), 이름, 아이디어 내용, 원하는 효과, 획득·사용 조건, 가격·소모량, 추가 메모를 적고 **아이디어 저장**을 누른다.
3. 왼쪽 목록에서 골라 수정한다. 종류별 필터·내용 검색, 수정 취소, 두 번 확인하는 삭제를 제공한다. DB 탭을 오가도 작성 중인 양식은 유지한다.
4. **JSON 백업**은 저장된 전체 기록을 내보낸다. **JSON 가져오기·추가**는 새로운 ID만 추가하고, 이미 있는 ID의 최신 기록은 유지한다. 저장하지 않은 초안은 백업에 포함하지 않는다.

모드툴 서버에서 저장하는 개인 파일은 `G:/somi/Jack O Nine Tails v2.4_work/game/modtools/game-reference/runtime/ideas.json`이다. 첫 저장 때 생성한다. 도구 갱신·동적 포트 변경에도 같은 파일을 읽는다. WORK 실제 파일에는 시험 아이디어를 쓰지 않았다. 단독 HTML을 파일로 열면 해당 브라우저 저장소를 사용하며, 서버 기록과 옮길 때 JSON 백업/가져오기를 사용한다.

개인 기록은 생성 HTML·snapshot·Git에 넣지 않는다. 이 기능은 기획 기록이며 게임에 아이템/특성/마법을 자동 생성하거나 QSP·세이브를 바꾸지 않는다.

## DB와 코드

- WORK에서 특성128개·아이템271개를 유지하고 마법11종을 추출했다. 기존 특성 본문은 모두 같고 아이템 ID도 모두 유지했다. WORK에서 바뀐 두 재료명(다진고기/보통 살코기)과 이를 사용하는 조리 재료 표시는 현재 값으로 갱신했다.
- 마법 이름·설명은 실제 메뉴에서, 소모량은 시전 코드에서 읽는다. 직접 메뉴 조건, 메뉴/시전 위치, 펼쳐 보는 원문 코드를 함께 표시한다. `interaction`의 spell_cast 정의와 메뉴 연결11개를 대조했으며 상위 메뉴의 모든 조건·자동 시전·실제 게임 결과 전부를 검증한 공략이라는 뜻은 아니다.
- `extract-spells.cjs`는 QSP 바이트와 menu_item JSON을 받아 spells JSON을 만든다. `assemble.cjs`는 같은 해시의 traits/items/spells와 템플릿·개인 기록 클라이언트를 합쳐 단독 HTML을 생성한다. 개인 데이터 파일은 읽지 않는다. 기존 core.cjs 의존성은 유지한다.
- `ideas-core.cjs`는 입력 검증·ID·필드·가져오기 규칙, `ideas-store.cjs`는 파일 읽기/저장/삭제/가져오기와 revision 대조, `ideas-client.cjs`는 HTTP/브라우저 저장, `ideas-ui.js`는 작성 양식과 목록을 담당한다. 입력 문장은 textContent/value로 표시하며 HTML로 실행하지 않는다.
- `serve.cjs` API2는 아이디어 파일만 쓴다. GET은 목록/백업, POST는 revision과 아이디어/삭제 ID/가져올 문서를 받는다. 저장 결과는 최신 목록·revision·파일 위치를 반환한다. 충돌은409, 잘못된 형식은400이며 손상 파일을 빈 목록으로 바꾸지 않는다. 기록을 읽지 못하면 양식을 유지하고 오류를 보여 준다.
- `Start-Game-Reference.ps1`은 PID·명령행·root·상태 응답으로 자기 서버를 확인하고 API/백엔드 해시가 다르면 재시작한다. `Open-Modding-Tools.ps1`은 HTML·서버·저장 모듈2개·실행기·README·snapshot만 복사한다. runtime은 복사하지 않는다. backend 모듈을 제거하면 서버 저장 기능이 시작되지 않으므로 실행기와 함께 관리한다.

## 검증과 한계

- 모델/저장/HTTP/단독 브라우저 저장 어댑터/마법 추출의 자동 검사10개 통과. 원문 Unicode·줄바꿈·HTML 문자열, 새 저장소에서 재열기, 편집, 동시 창 revision 충돌, 손상 JSON 원본 보존, 삭제, ID 충돌 가져오기, 외부 Origin 거부, JSON 백업 형식을 검사했다.
- 격리 시험 서버의 브라우저에서 특성·아이템·마법 각각 작성/저장, 편집 후 새로고침, 탭 이동 중 초안 유지, 종류별 검색, JSON 가져오기(기존3개 유지)를 확인했다. JSON 백업 클릭과 완료 안내는 확인했으나 자동화의 download 이벤트가 시간 초과되어 실제 다운로드 파일 저장 위치/내용은 UI 경로로 확인하지 못했다. API의 백업 내용 검사는 통과했다.
- 실행기 연속 호출은 같은 서버를 재사용했고, 백엔드 변경 시 자기 서버만 교체했다. 두 경우 모두 시험 아이디어 파일 해시는 유지했다. JS/PowerShell 구문과 HTML 내 데이터 일치도 확인했다.
- WORK 기존 구 API 서버를 API2로 갱신하고 실제 Chrome의 기존 DB 탭을 새 주소로 이동했다. **내 아이디어** 화면의 파일 위치와 빈 초기 목록을 확인했다. [실제 설치 화면](reference-ideas.png). DB·코드는 WORK/소스 같은 해시다.
- 게임 QSP·게임 능력치·사운드·이미지·세이브·Full·배포 ZIP은 변경하지 않았다. 커밋·푸시 없음. 작은 화면의 실제 반응형 배치는 이번 브라우저 검사 범위 밖이다.
