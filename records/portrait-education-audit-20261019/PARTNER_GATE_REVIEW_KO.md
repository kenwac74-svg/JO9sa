# 조수 대체 참여자 수업 조건 교정

원저자 주석(menu_form2497), 반대편 조건2137, 공통 수업 호출interaction4351/4352가 모두 같은 의도를 가리키므로 기존 조건 오류로 판정했다. no_slave를 제외하던 조건 상수를 slave_exist로 바꿔 기존의 ‘정상 보유 인물이 없을 때 유료 대체 참여자’ 분기를 복원했다. 비용·수업 본문·화자·수치는 그대로다.

후보 SHA256: `20137b7336f2ec27c419605cbd2ada1a6fab459919c6ceaaedad89a9152f40f5`
기준 Work SHA256: `1084c6f39e15c1c66470449b8d748974eb003966db729391d4804e4029d3501a`

| 상태 | 교정 전 대체 활성 | 교정 후 대체 활성 |
| --- | --- | --- |
| no_slave | 0 | 1 |
| faint | 1 | 1 |
| dead | 1 | 1 |
| exist | 0 | 0 |
| no_money | 0 | 0 |

실제 엔진의 관측 state가 요청 state와 일치함을 모두 검사했다. 존재 상태에서는 원래 보유 인물을 쓰는 기본 수업이 활성이고, 돈0에서는 유료 대체 수업이 비활성이다.

추가 실수업: 기존 `$clear_slave_instance, 'slave'`로 슬롯을 비우고 no_slave·빈ID/이름 및 age/obedience/subskill0을 확인한 뒤 실제6999를 실행했다. 원래 결과 본문·조수 역할·다음 콜백5회·뒤로1회·menu0복귀를 통과했다. 비어 있는 노예 슬롯과 조수ID를 유지하며 기존 비용1만 소모했다. 비진단 알림·엔진 오류0건.

프로덕션 변경은 menu_form 조건 상수1개와 provenance 주석 한 쌍뿐이다. 새 함수·지속 상태·수업·조건을 추가하지 않았다. 실제 화면의 저장파일 로드나 모든 상태 조합을 검증한 것은 아니다. 작업영역 후보만 작성했고 게임·G:·git 쓰기는 없다.
