## 3. 실제 엔진에서 측정한 차이

실제 설치 FastQSP에 현재 `jo9_traits`, `jo9_traits_personality`를 그대로 넣은 격리 사본으로22개 단언을 확인했다. 기준 경험치·성과를 각각100으로 두고 같은 활동을2회 실행한 뒤 두 번째 활동의 계산과 누적 기분 변화를 비교했다. 다른 보너스 특성은 주지 않았다.

| 현재 보유 상태 | 현재 경험치 | 현재 성과 | 두 활동 동안의 기분 보정 | 새 기획과의 관계 |
|---|---:|---:|---:|---|
| 없음 | 100 | 100 | 0 | 기준 |
| 끈기만 | 110 | 100 | +2 | 하위 효과 있음 |
| 산만함만 | 90 | 90 | 0 | 하위 효과 있음 |
| 워커홀릭만 | **100** | 100 | **+2** | 새 기획은 경험치110, 반복+활동 기분 합계+4여야 함 |
| 무기력함만 | **100** | **100** | -2 | 새 기획은 경험치90·성과90이어야 함 |
| 끈기+워커홀릭 | 110 | 100 | +4 | 현재 가능. 새 기획에서는 두 특성 동시 보유 금지 |
| 끈기+무기력함 | 110 | 100 | 0 | 현재 가능. 새 기획에서는 반대 계열 동시 보유 금지 |

추가 실행 확인:

- 집중±1을 보유한 상태에서 활동±1을 부여하는4조합 모두 현재 허용됐고 집중값이 그대로 남았다.
- 위 상태에서 반대 집중 성향의 부여 허용 검사도 모두 통과했다. 공통 허용 검사에 새 단계형 제한이 없다.
- 다른 활동을 번갈아 해도 워커홀릭의 두 번째 활동 기분+2는 발생했다.
- 다음 날 첫 활동은 횟수1·활동 기분 추가0으로 초기화됐다.
- 고정 업무에서는 끈기 집중 보정이 발생하지 않았다.
- 정상 관계에서 휴식·마사지의 기준 보상 효력100은 워커홀릭50, 무기력함200으로 계산됐다.

**22개 단언 통과는 현재의 기존 동작을 확인했다는 뜻이다. 새 단계형 기획이 구현·검증됐다는 뜻은 아니다.** 개인 SAV를 불러오거나 수정한 검사는 아니다. 모든 교육·업무·발견·JSON 입력·편집기 버튼을 실제 플레이로 전수 검사한 것도 아니다.

## 5. 구현 작업과 결정 대기를 구분

이미 승인된 구현 잔여:

1. 네 특성의 단일 보유·상위 대체를 모든 부여 경로에 적용.
2. 상위가 하위 효과를 포함하되 한 번만 계산하도록 효과 해석 통합. 기존 두 번째 활동 수치·보상 배율·고정 업무 제외 범위는 유지.
3. 직조공의 최종 끈기20% 적용. 무기력함 직업 추가 추첨은 넣지 않음.
4. 유니크·JSON·게임 내 편집기·발견/표시·설명·툴팁·열람표 연결 정리.
5. 같은 활동/다른 활동/첫 활동/두 번째 이후/날짜 변경/고정 업무/양방향 부여 순서/중복 효과를 나눠 검증.

아직 결정이 필요한 항목:

- 기존에 두 축의 특성을 함께 보유한 인물을 새 규칙으로 바꿀 때 어느 특성을 남길지.
- 기존 저장 필드의 유지·이관과 충돌 정리 시점·방법. 새 필드를 반드시 추가해야 한다고 확정한 것은 아니다.
- 새 단계별 일반 랜덤 추첨 분포. 기존 직업별 승인 확률을 임의로 상위 특성 확률로 치환하지 않는다.

**자동 승급·승급 경험치·승급 확률은 이번 승인 범위에 없으므로 ‘미구현 잔여’에 넣지 않는다.** 기존 저장의 충돌값도 이번 점검으로 자동 삭제하지 않았다.

검증 자료: 같은 폴더의 `verification.json`, `client-results.json`, `trait-stage-audit.cjs`. 임시 진단 QSP·자체 생성 세이브는 기록 확인 후 정리한다. WORK·추적 QSP는 점검 전후 동일하며 Full·음원·커밋·푸시 변경은 없다.
