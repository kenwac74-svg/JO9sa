# JoNT 장면 프롬프트 도구 통합 — 2026-11-15

사용자 제공 `jont-remake-handoff.zip`의 도구를 **이미지 작업 → 장면 프롬프트**에 연결했다. 기존 3개 이미지 탭과 체크리스트 내부 탭은 유지했다. 공통 회색·금색 스타일, 중복 제목 제거, 기존 프레임 보존 방식과 같은 구조를 따른다.

## 반영

- `tools/jont-remake/`: ZIP의 원본 4파일을 그대로 가져왔다. 압축본과 각 파일의 SHA-256은 `source.json`에 기록했다. 함께 제공된 README도 ZIP 안 README와 같았다.
- `hub-server.mjs`, `hub-client.js`, `Start-Jont-Remake.ps1`: 폴더 선택·프로젝트 설정·로컬 작업표 프록시·결과 다시 읽기·소유 서버 재사용·빈 포트 선택을 추가했다. 해석 모델을 입력할 수 있으나 설정 적용 자체는 외부 API를 호출하지 않는다.
- `tools/local-workspace/Open-Modding-Tools.ps1`: 도구를 시작하여 실제 확인된 주소를 `promptWorksheet`로 전달한다. 원래 전용 앱 창 실행 경로도 이 구성을 사용한다.
- `tools/modding-hub/integration.mjs`: 이미지 작업의 네 번째 탭으로 추가했다. 다른 도구 프레임을 재활용하거나 자료를 이동하지 않는다.
- `config.json`, `library.json`, `work/`, `runtime/`는 Git 제외. 설정 변경 시 기존 API 키·상세 옵션은 보존하고 브라우저에는 공개 설정만 전달한다.

새 설치에서는 예제의 실제 원본 폴더·대상 캐릭터를 자동 선택하지 않는다. 사용자가 프로젝트를 지정하기 전에는 원본 작업표 서버를 시작하지 않는다. 기존 해석 결과가 없는 새 이미지 폴더는 원본 CLI의 `describe`가 먼저 필요하다. 이번 통합에서 일괄 해석 GUI를 새로 만들지는 않았다. 원본 도구의 작업표·샘플 라이브러리·CLI 명령은 유지했다.

## 확인한 결과

1. JS와 PowerShell 구문 검사 통과.
2. `tests/hub.test.mjs` 3개 통과: 비밀값 비노출·식별자, 설정 보존·잘못된 경로 거절, 빈 폴더의 설정/작업표/원본 API 프록시/다시 읽기. 실제 이미지나 외부 API를 사용하지 않았다.
3. 통합 실행기에서 8790 점유를 보존하고 **8791**로 실행. 다시 실행했을 때 동일 PID를 재사용했다. 포트 번호는 고정 사용 안내가 아니라 이번 실행의 확인값이다.
4. 통합 브라우저에서 네 번째 탭·설정 입력·폴더 선택 버튼·공통 색상·별도 창 링크가 표시됐다. 1664×1000에서 프레임 상단 약188px, 높이 약800px. 실제 API 해석·샘플 추출·이미지 생성은 실행하지 않았다.
5. 원본 4파일 해시 일치. 원본 README·워크시트·실행 로직을 수정하지 않았다.

화면: [통합 화면](integration.jpg). 결과: `tests.txt`, `verification.json`. 원래 연결 파일의 압축 백업은 `*.before.gz`, 이번 연결 차이는 `change.diff`다. 이전 변경도 있는 작업 폴더이므로 Git 전체 차이와 이번 차이를 혼동하지 않는다.

## 사용 및 남은 범위

[사용법과 구현 설명](../../tools/jont-remake/README_INTEGRATION_KO.md). 기존 전용 앱 창은 작성 내용을 저장한 다음 다시 열어 새 메뉴를 반영한다. API 키는 서버 설정/환경변수에서 설정한다. 서비스 계정·과금·모델의 실제 해석/생성 결과 검증은 이번 범위 밖이다.

게임 QSP·캐릭터 JSON·세이브·이미지·음원·배포 패키지는 수정하지 않았다. 커밋·푸시·업로드는 하지 않았다. 시험 폴더는 결과를 기록한 뒤 이번 작업의 이름 범위 안에서 정리했다. 사용자 제공 ZIP/README와 기존 서버·개인 자료는 보존했다.
