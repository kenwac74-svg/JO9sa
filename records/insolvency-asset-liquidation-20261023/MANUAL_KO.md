# 파산 전 자산 처분 — 동작 설명

사용자 승인 범위는 WORK QSP 반영이며 Full·배포 ZIP·커밋·푸시는 포함하지 않는다. 최종 적용·검사 결과와 정확한 해시는 FINAL_RESULT.json 및 release-validation.json을 기준으로 한다.

## 플레이 흐름
청구서를 낼 현금이 부족하면 즉시 끝내지 않고 자산별 선택지 15페이지를 보여준다. 장식, 연구실/별실/사육장, 개인실4→1, 동면 장치/감옥/축사, 주택, 노예/조수 순이다. 처분액과 부족액을 보여주며 돈이 마련되면 추가 처분 없이 한 번 정산하고 돌아간다. 새 NPC·상시 버튼은 없다. 다른 방법으로 자금을 마련하는 동안 기존 판매·대출·인물 이동을 직접 이용할 수 있고 미납 해결 전 다음 날 진행은 차단된다.

## 가격과 상태
- 장식: 현재 실제 존재하는 방의 카탈로그 정가 50%. 구입가·소유권 추정 이력은 없다. 처분 후7종 상태·일반 그림·확대 그림·설명은 모두 basic. 방별 처분 표시만 남겨 같은 장식 반복 환급을 막는다. 유료/무료 장식 선택으로 실제 새 스타일을 설치하면 해당 표시가 초기화되며, 이사에 의한 무료 초기화는 표시를 지우지 않는다.
- 개인실: 현재 최고 단계의 빈 방부터 공사비50%(4번5000,3번2500,2번1000,1번2500)를 돌려받는다. 인물 슬롯은 건드리지 않고 kulaconstruct만 감소한다.
- 자가: 지역별 정가75×estate_cost_main의50%. 소수점은 게임 정수 계산으로 내림. 임대 주택은 소유 자산 매각대금이 없으며, 계약 해지는 향후 지출을 줄인다. 별도 정액 지원금이나 새 대출은 없다.
- 부속 시설은 기존 후불 임대이므로 미납 경계에서 환급할 선불잔액이 없다. 해지는0스파크이며 다음 결산의 유지비를 줄인다. 이미 청구된 지난 지출은 재계산하지 않는다.
- 노예·조수: 경쟁 노예상이 납품 의뢰에 쓰려고 사가는 급매. 현재 보유 인물의 기존 기본 평가액 slaveprice의50%를 한 번 적용한다. 정상 NPC 구매 제한·의뢰 완료·관계·평판·가문 보상은 처리하지 않는다. 부상·기절·미낙인·낮은 행동력도 살아 있는 본인 소유이면 가능하다. 빈 슬롯·사망·brand4계약 인물은 제외한다. 정상 NPC에게 직접 찾아가는 거래는 원래 규칙을 유지한다.

## 입주자 보존
시설과 개인실은 관련 상태가 정확히 no_slave인 경우에만 처분 가능하다. 기절·사망 상태도 빈 방으로 간주하지 않는다. 감옥·외양간4역할·개인실4역할·안개괴물은 직접 비워야 한다. 가정 동면 장치의 인물 위치 구분 정보가 없어 iced_1..18 중 하나라도 차 있으면 반납하지 않는다. 인물을 자동 이동·해동·해제하지 않는다. 기존 부동산 해지·이사 선택지도 미납 중에는 같은 조건으로 보호한다.

## 저장 및 의존성
추가 지속 상태는 jo9_lq(청구액·날짜·단계·활성/수동·정산)와 jo9_lq_decor_state(방별 처분 여부)다. 예전 세이브에는 기본0으로 비활성이고 기존 인물·관계 키를 이관하지 않는다. 저장된 미납 상태는 현재 코드로 다시 렌더링한다. 개인실 UI가 임시로 교환한 슬롯은 기존 snk_room_bridge leave로 원복한 뒤 조회한다. 실제 시설 입주자를 이동하는 처리는 아니다.

기존 의존성: billing, main_layout, interior_storage/refresh_database/interior_restore, new_estate, snk_room_bridge, $update_slave_price, jo9_traits_value, $sold_clothing/$clear_slave_instance. 장식 basic 이미지14개는 기존 WORK에 존재하며 새 이미지·CSS·JSON은 필요하지 않다. 새 위치3개만 분리 삭제하면 호출 오류가 나므로 관련 후크와 함께 패치를 되돌려야 한다. 이전 백업을 나중 편집 위에 무조건 덮어쓰지 않는다. mods의 해시와 정확한 old/new/count 치환으로 이번 변경을 추적한다.

## 검증 한계
실제 엔진의 상태 검사·출고9경로는 GUI 전수 플레이와 다르다. 기존 세이브 파일57개는 변경하지 않고, 레거시 세이브에서 가져온 상태와 현재 버전 대표 상태를 격리 QSP에 구성해 검사한다. 실제 GUI 로드/CRC와 모든 퀘스트·화면 크기·게임 분기를 증명한 것은 아니다. 일반 도구 회귀는105통과/기존 기준본 필요1건SKIP이며, 상세 네이티브 결과는 NATIVE_VERIFICATION_KO.md를 본다.
