# 파산 위기 급매 모듈 연결 명세

대상 위치는 `jo9_liquidation_sale`이다. 기존 NPC의 매입 의뢰를 완료하는 기능이 아니라, 자금 마련을 위해 다른 노예상에게 현재 평가액의 절반으로 급매하는 기능이다. 원래 NPC를 직접 방문하는 거래는 변경하지 않는다.

`gs 'jo9_liquidation_sale', 'query', 'slave'` 또는 `'assistant'`로 조회한다. 인물의 숫자·문자열·변화량 배열을 임시 전역 복제본에 복사한 뒤, 기존 `$slave_price`와 동일한 특성 갱신 및 `$update_slave_price` 계산을 복제본에 실행한다. 번들 엔진에서 중첩된 GS/FUNC가 호출자 지역 배열을 읽지 못하므로 복제본만 임시 전역을 사용한다. 복제 이후의 모든 반환 경로는 하나의 정리 지점을 거쳐 복제 배열·상태·타입·심리 상태·이름을 제거한다. 평가용 수치 변수는 지역 범위를 사용하며 원래 인물을 변경하지 않는다.

반환 배열은 역할 문자열을 키로 쓴다.

- `jo9_lq_sale_price`: 급매 대금.
- `jo9_lq_sale_type`: 인물의 숫자 타입.
- `$jo9_lq_sale_actor`: 인물 이름.
- `$jo9_lq_sale_id`, `$jo9_lq_sale_scheme`: 모두 `quick_sale`.
- `$jo9_lq_sale_buyer`: `다른 노예상`이라는 일반 표시명.
- `$jo9_lq_sale_reason`: 급매 불가 시 짧은 이유.

`gs 'jo9_liquidation_sale', 'sell', slot, quotedPrice, quotedType, 'quick_sale', actorName`이 실제 급매다. 미납 상태 `jo9_lq['active']=1`일 때만 실행한다. 현재 역할·평가액·타입·이름을 다시 검사하고 일치할 때만, 착용 장비를 함께 넘기고 해당 역할을 `$clear_slave_instance`로 비운 뒤 대금을 한 번 지급한다. 성공 시 `jo9_lq_sale_sold=1`이며 호출 시작마다 0으로 초기화한다. 모듈은 화면을 이동하지 않는다.

가격은 기존 평가 함수의 `slaveprice / 2`이다. 잡파 등의 상인이 주는 금액을 구한 뒤 다시 절반으로 줄이지 않는다. 상인별 흥정·수요·희귀품 매입 배율도 넣지 않는다. 정수 나눗셈으로 소수점은 버린다.

살아 있거나 기절한 인물만 가능하다. 상처·음수 행동력·임신·정신 상태·매력·낙인 없음은 급매를 막지 않는다. 빈 역할, 사망자, 타인 소유로 처리되는 `brand=4`는 불가능하다. 개인실 임시 연결 `snk_room_target>0`일 때는 인물창을 닫도록 안내하여, 노예 칸에 임시 투영된 입주자를 오인해 매각하지 않는다. 인물을 자동으로 다른 시설에 옮기거나 시설에서 해제하지 않는다.

NPC 구매자 목록, 의뢰 조건 판정, NPC 진행·관계·평판·가문 명성·구매 대기·질병 거래 이력·주인공 거래 기분은 변경하지 않는다. 조수와 노예를 임시로 교대하지 않는다. 현재 세이브 인물 구조나 영구 ID를 추가하지 않는다.

의존성은 기존 `$update_slave_price`, `$set_obedience_difficulty`, `$dyn_meat_evaluation`, `jo9_traits_value`, `$sold_clothing`, `$clear_slave_instance`, `$slave_vars`이다. 미납 화면에서 호출을 제거하면 모듈만으로 자동 판매가 일어나지 않는다. 기존 평가 함수의 수식을 변경하면 급매 평가액도 그 변경을 따른다.

UI에는 당시 가격·타입을 상수로 넘겨야 한다. 이름에 따옴표가 있어도 EXEC 문자열에 직접 삽입하지 않고 값으로 넘긴다. 타입·이름 검증은 동일한 타입과 이름을 가진 인물을 구별하는 영구 ID가 아니다. 거래 직전 재조회와 실제 역할의 존재 검사로 잘못된 가격과 반복 지급을 차단한다.

네이티브 검증 범위는 두 역할의 급매·반복 호출·잘못된 가격과 신원·소유권·사망/기절·저장 후 불러오기·NPC 상태 불변 검사를 포함한다. 실제 게임창의 모든 장면 플레이 완료와는 구분해서 기록한다.
