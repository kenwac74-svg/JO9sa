# 편집·유지보수

대사 편집기에서 #긍정적 선택지 / #부정적 선택지를 검색해 버튼 문구를 바꾼다. #긍정적 선택 결과 / #부정적 선택 결과를 검색하면 선택 뒤 한 컷의 내용을 각각 작성할 수 있다. 네 문구는 각각 일반 대사 문자열이므로 HTML 연결 코드를 수정할 필요가 없다.

후속 컷은 WORK/game/content/pic/scene/others/erza_dead_after.png를 교체한다. 크기는795×596이며 두 선택 결과에서 같은 파일을 사용한다. 최초 그림 erza_dead.png는 앞 장면에 그대로 사용한다. 현재 두 파일은 의도된 임시 사본이라 해시가 같다. 이를 나중에 불필요한 중복으로 정리하면 새 후속 컷이 깨지므로 QSP 연결과 함께 확인한다. 새 그림을 넣을 때 임시 사본의 해시 기록을 갱신한다.

interaction_city에서 기존6667792 블록 뒤에 새 결과 분기21/22를 추가하며 $text[1], $special_image[1], $place, $return_lock을 기존 방식으로 설정한다. $interaction_type은 기존 basic을 유지한다. 함수·새 영구 변수는 없다. interaction_screen_city는6667792에서만 출력 사본에 링크를 만들고 페이지 객체를 비우며, 나머지 화면의 이동 코드는 그대로다. 링크 ID는 jo9-erza-positive-choice / jo9-erza-negative-choice다.

전투 종료 자체는 선택 화면 이전에 이미 처리된다. 새 결과에서 выход_из_боя, 전투 종료 함수 또는666779 분기를 호출하면 성장/비용이 중복될 수 있으므로 호출하지 않는다. 선택 결과의 공통 interaction_result_city 기록은 새ID별1회이며 원사망 분기의 기록은 다시 올리지 않는다.

최소 패치는 mods/2026-11-01_erza_death_choices.json이며2개 로케이션의3개 조각만 변경한다. 새 결과 분기를 지울 때는 두 링크와 선택 화면의 페이지 제한을 함께 제거해야 한다. 링크를 남기고 분기만 지우면 빈 장면으로 이동하며, 원사망 장면을 유지하면서 화살표만 막으면 진행이 막힌다. 후속 PNG를 지우면 결과 그림이 누락된다.

build.cjs는 출력 폴더와 기준 QSP를 선택 인수로 받는다. 이미 적용된 WORK 대신 gzip 백업을 임시로 풀어 기준 QSP를 지정하면 재현할 수 있다. probe.cjs는 red/green과 대상 QSP를 받아 격리 네이티브 검사를 실행한다. 추가 PNG의 후보 경로 치환은 진단 복사본에만 하고 실제 설치본에는 상대 경로를 유지한다. 개인 저장·설정·원본은 덮어쓰지 않는다. 이후 편집이 생기면 오래된 전체 QSP 백업을 덮어쓰지 말고 최소 패치 조각을 역방향 대조한다.
