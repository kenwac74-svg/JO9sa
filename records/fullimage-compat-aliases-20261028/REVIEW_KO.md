# 기본 전신 호환사본 — manifest·관리 스크립트 독립 검토

검토 대상은 `2026-10-28_fullimage.json`과 `manage-compat-aliases.cjs`다. 현재 WORK SHA-256은 `e620353d0db6374ae293c6919d511966c31e2bb68ebd1763bb5a956bec069ba0`로 승인 기준과 일치한다.

**검토 범위에서 actionable finding은 없다.** 이번 검토자는 관리 스크립트의 apply/verify 모드를 실행하거나 제품 PNG를 생성하지 않았다.

## manifest와 실제 입력

- 23개 source·compatibility·JSON 참조 조합이 앞선 확정 목록과 정확히 일치한다.
- 실제 원본의 SHA-256/크기와 JSON SHA-256 및 fullimage/indpack_title 값이 manifest와 모두 일치한다.
- 실제 대상 파일은23개 모두 미존재이고, 각 경로를 참조하는 JSON은 해당1개뿐이다.
- 총 추가량4,213,447바이트가 행 합계와 일치한다. 역할/의상 경로, JSON 수정, 이미지 재인코딩은 포함하지 않는다.
- 관련 기존 root 이미지의 경로·해시·크기·원본 동일 여부 기록도 실제 파일과 일치한다. **동일 root 후보가 있는 ID20개/없는 ID3개**다. 후보 파일 기준으로는24개 중 동일20개·상이4개이며, 1205에는 동일 후보와 상이 후보가 각각1개 있다. 개별 manifest 기록은 이 관계를 정확히 담고 있다.
- KEEP·의도적 중복·독립 바이트 사본·기존 기본 주소 호환 용도와 원본/추가 관계, 변경·삭제·패키징·자동 동기화 없음의 유지보수 규칙을 기록했다.

## 쓰기 경계와 실패 처리

스크립트는 승인 상태·작업 ID·23개 범위·KEEP 및 fullimage 필드를 확인하고 대상 중복을 검사한다. image 경로를 girls/full 아래로 제한하며 부모 실제 경로와 기존 이미지 링크를 검사한다.

23개 전부에 대해 원본 해시·크기·PNG 표식/규격, 현재 JSON의 두 소비 경로, 기존 대상 해시를 검사한 후에만 이미지 생성 루프에 들어간다. 기존 대상이 다른 해시이면 생성 전 거부한다. 없는 대상은 `wx`로 배타적으로 생성하므로, 선검사 뒤 같은 경로에 생긴 파일도 덮어쓰지 않는다. 생성 또는 EEXIST 후 대상 해시를 확인한다. 중간 실패는 FAIL 보고서에 이미 만든 항목을 남기며 원본이나 임의 파일을 지우지 않는다.

이후 재실행 시 title 원본의 해시/크기가 승인값과 다르거나 JSON 소비 경로가 달라지면 재검토를 요구하고 복사를 거부한다. 기존 alias의 내용이 달라도 덮어쓰지 않는다. 현재 source/JSON 해시는 독립 확인했으며, 스크립트 자체의 JSON 선검사는 두 소비 경로를 고정하는 방식이다. 관련 없는 JSON 필드 전체나 QSP의 미래 변경을 금지하는 도구는 아니다. 어느 경우에도 QSP/JSON/SAV를 쓰는 코드는 없다.

이 실패 처리와 배타적 생성은 소스를 읽어 확인한 결과다. 이번 독립 검토에서는 Windows 파일 경합이나 apply 실패를 실제 파일 생성으로 시험하지 않았다.

## picMax에 관한 좁은 확인과 한계

현재 `get_stock_seed:294`는 JSON 전역 `$fullimage[stock_type]`를 인물의 fullimage 문자열로 복사한다. 이름이나 ID를 새로 고르는 코드가 아니며, 이 작업은 그 문자열과 JSON 생성 범위를 변경하지 않는다.

현재 `display_pic:75-79`의 fullimage 요청은 기존 resolver를 호출한 뒤 즉시 exit한다. 번호/공용 장면의 `picMax` 선택은 그 뒤의 별도 코드다. `:218-223`은 `main_actor_type + '_' + action` 키를 사용하며, `:244-252`는 action·머리/나이·고유 tag로 장면 풀 키를 조립한다. 이번 추가 경로는 전부 `content/pic/girls/full/`의 이미 JSON이 참조하는 기본 bare basename이며 번호가 붙은 장면 파일이나 scene 폴더·QSP의 장면 키·무작위 범위를 바꾸지 않는다.

따라서 **현재 QSP에서 확인한 fullimage 및 seed 연결을 유지한다**는 것은 확인했다. 다만 실행 엔진이 전체 디렉터리를 어떻게 색인하고 전역 picMax를 구성하는지, 파일 추가 전후 실제 picMax 배열이 완전히 같은지는 이 정적 검토로 증명하지 않았다. 엔진 전수 감사나 native picMax 비교를 수행했다고 주장하지 않는다.

추가 사본은 현재 기본 경로와 구 저장 문자열이 사용할 수 있는 KEEP 자산이다. 동일 해시만으로 정리하면 안 된다. 향후 다른 번호의 scene 파일까지 복제하거나 alias를 scene 디렉터리로 옮기는 작업은 이번 승인 및 확인 범위가 아니다.
