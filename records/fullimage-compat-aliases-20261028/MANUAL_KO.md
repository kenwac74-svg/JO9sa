# 기본 전신 호환 사본 — 적용·검증·복구

## 승인과 변경

사용자가 기본 이미지 경로 문제를 제안한 방식으로 적용하고, 중복 발생과 향후 유지보수 문제를 별도 기록하도록 지시했다. 정상 대표(title) PNG23개를 현재 JSON이 가리키지만 존재하지 않았던 기본 전신 주소에 바이트 그대로 복사한다. 원본을 옮기거나 덮어쓰지 않는다. 기본 의상 fullmade 등 역할 경로와 template 파일은 범위 밖이다.

새 그림0·독립 사본23개·4,213,447bytes다. QSP/JSON/캐릭터번호/배경/머리색 추론/인물 저장값은 유지한다. 같은ID의 다른 root 이미지로 추측 대체하지 않는다.1132/2057/2118의 title은 기존 root 후보와 실제로 달라, JSON에 지정된 title을 그대로 사용했다.

## 파일과 유지보수

`assets/compatibility-aliases/2026-10-28_fullimage.json`이 기준 원장이다. 원본/호환 경로, 인물ID·JSON 소비자, 당시 해시·크기·치수·기존 후보와의 관계, `intentionalDuplicate=true` 및 `KEEP`를 기록한다. `docs/IMAGE_COMPATIBILITY_ALIASES_KO.md`는 중복 정리·원본 교체·경로 이관·패키징 규칙을 설명한다. 프로젝트 AGENTS와 리소스 정책·인계·다음 묶음에서 이 문서를 연결한다.

호환 파일은 원본 변경을 자동으로 따라가지 않는다. 검사는 기록된 해시와 다른 source/target 또는 변경된 JSON 경로를 거부한다. 해시가 같다는 이유만으로 호환 파일을 삭제하지 않는다. 다음 패치는 새 해시 여부와 별개로23개 주소를 모두 포함해야 한다. 새 그림 수와 호환 파일 수는 구분한다.

## 도구 입력·출력·부수 효과

`tools/manage-fullimage-compat-aliases-20261028.cjs`는 Node.js 표준 모듈만 사용한다. `--game`, `--manifest`, `--out`을 받으며 기본은 읽기 검증이다. `--apply`를 주면23개 전체 사전 검사를 마친 후 누락 대상만 `wx`로 배타적 생성한다. 기존 대상이 같은 해시면 그대로 두고, 다른 해시면 작업 전에 거부한다. 입력 PNG를 편집·변환·재인코딩하지 않는다.

출력은 원장 해시·절대 source/target·생성/기존/검증 여부·바이트가 담긴 게임 밖의 JSON이다. 적용 전 계획을 먼저 쓰고 실패 시 가능한 진행 기록도 남긴다. 동시에 다른 파일이 생기면 덮어쓰지 않으며 같음이 확인된 경우만 유지한다. report의created는 실제 추가 수이지 승인 목록 총수가 아니다. 두 번째 적용은 created0이어야 한다.

기존 저장·QSP·JSON·엔진·CSS·JS·배포 폴더를 쓰지 않는다. 원장을 게임의 json/slaves에 넣지 않는다. 이미지 추가·검사에는 QSP 로케이션이나 새 저장 키가 필요 없다. 도구를 제거해도 추가된 파일은 남아 게임에서 사용되지만, 미래 해시·중복 점검 기능이 사라진다. 호환 PNG를 제거하면 기본 주소가 다시 없어진다.

원장 생성 스크립트 `build-manifest.cjs`는 이번 사전 검증 스냅샷과 pinned WORK·JSON·source를 대조하는 재현용이다. 원본이 바뀌면 이를 새 승인으로 재생성하지 않는다. 변화의 원인과 유지보수 결정을 먼저 기록한다.

## 검사 범위

사전 상태에서23개 대상은 모두 없고, 원본은 정상795×596 PNG이며 전체 디코드와 해시 검사를 통과했다. 대상 고유성·JSON/경로ID·다른ID 참조 충돌을 확인했다. 적용 후에는23개 전부 원본과 바이트/해시·치수가 같은지 독립 검사하고 재적용 멱등성·보호 입력 불변을 확인한다. 상세 결과는 `verification/REPORT_KO.md`, 적용 결과는 `installation.json`을 따른다.

이번에는 QSP·문법을 수정하지 않는다. QSP 해시·JSON 스냅샷·기존 파일의 해시가 그대로인지 검사한다. 새 진단 QSP나 전체 게임 복제본은 만들지 않는다. 현재 안개/대회는 resolver 우회가 있어서 제보 화면의 누락 자체를 재현하지 못한 상태다. 이 작업은 확인된 기본 파일 주소의 부재를 해결하며, 제보된 모든 UI 화면·옛 개인 세이브 불러오기 검사를 완료한 것으로 확대하지 않는다.

정적 확인에서 기본 전신은 display_pic의직접fullimage분기에서장면랜덤풀보다먼저종료하고 get_stock_seed는JSON의literal주소를복사한다. 이번에는번호가붙는장면랜덤풀을추가하지않는다. 다만이사실만으로실행엔진의모든picMax구성이나전체장면선택불변을증명하지는않는다.

## 복구

기존 파일을 변경한 작업이 아니어서 복구 대상은 원장의 새23주소뿐이다. 삭제를 검토할 때는 그 주소의 현재 해시가 이번 추가분과 같은지, 현재 JSON·동적 출력·옛 저장의 주소가 여전히 필요한지 먼저 확인한다. 같은 해시라는 사실만으로 삭제하지 않는다. 이 문서는 자동 삭제를 승인하지 않으며 도구도 삭제 모드를 제공하지 않는다. 변경된 원본이나 사용자 사본은 보존한다.
