# 명기 최초 발견 알림

이번 변경은 jo9_meiki_state 한 곳의 알림 추가다. 각 지원 역할(slave/assistant/room1..4)의 기존 성공 판정에서 아직 알려지지 않았을 때만 LOCAL 발견표시·이름을 잡고, 원래 특성 상태와 일회 효과 처리가 끝난 뒤 MSG 한 번을 표시한다. 표시 문구는 [명기] 다음 줄에 인물 이름과 효과의 힌트를 적으며 확률·보정률 같은 정확한 수치를 쓰지 않는다.

기존 발견 처리와 같은 엔진 기본 MSG이므로 별도 UI·CSS·닫기 제어가 없다. X만 허용하거나 읽지 않은 알림을 저장·로드 후 유지하는 기능도 없다. 새 로케이션·영구키는0이며 지역변수2개만 쓴다. 이미 알려진 특성, 기존세이브4값 보정, 실패·조회·검사완료·초기화 시에는 팝업을 띄우지 않는다. 개인실 투영은 기존 bridge가 바꾼 현재 이름을 그대로 사용하고 새로운 역할 이동은 하지 않는다.

패치표식 MEIKI_DISCOVERY_POPUP_*와 선언형 patch.json을 사용한다. 추가된8블록을 제거하면 원래 본문과 바이트까지 같음을 독립 확인했다. 원래 확률·발견 조건·기술 보정·나이 판정·가격·생산·난이도·호출 순서는 바꾸지 않는다. 다른 특성의 발견 helper는 습관을 부여하는 효과가 있어 알림 목적으로 호출하지 않는다.

검사: 기존본 알림 누락 RED, 후보 기본6역할+빈이름 발견·반복/6종무알림 조건의7묶음, 실제 MSG2건, 공식 구조/개행/주석경계/정확재생/재적용·엔진9경로 PASS. 실제 MSG 원시로그는CP949이므로 EUC-KR로 읽는다. 최초UTF-8판독 timeout은 reader 문제이며 popup-reader-note.txt에 원시로그와 함께 보존했다. 확률은 진단사본에서 경계5/6으로 제어하고 MSG는 상태검사에서 카운터로 바꾼다. 별도의2건은 원래MSG를 그대로 실행한다. 실제 마우스·키 입력·사용자GUI로드·모든인물 전수플레이 검사는 아니다. 기존 확인용세이브·Full·설정·리소스는 해시로 보존한다.

복구본 before.qsp.gz와patch.json·재현코드를 보존한다. 정리 후 node reproduce.cjs reproduce 및 probes로 격리 후보를 복원할 수 있다. 후보/백업과patches를 release-check.cjs에 지정하고 출력은 별도 임시 경로로 둔다. native/plan.json은 기존 run-client-smoke.ps1로 실행하며 red-plan은 예상누락실패용이다. popup-plan은 기본MSG 문자열을CP949로그에서 확인하는 표본이다.
