# 대사편집기 2-2 조건 결과 연결 수정 — 2026-11-16

사용자 제보: 2번 선택지의 조건형 2-2를 누르면 3번 결과 페이지가 열림. 추가 확정: 2번 기본 결과와 2-2 결과는 달라야 함.

## 원인과 수정

현재 WORK의 `jo9_slave_death`에는 2번(188행), 조건형 22번(192행), 3번(200행) 결과가 별도로 있다. 22번의 대사는 196~198행에 걸친 여러 줄 문자열이다. `page-flow.cjs`가 출력문 시작 행 안에서 끝나는 문자열만 수집해 22번 결과 페이지를 누락했고, 보이는 결과만 검사하는 else 추론이 22번을 3번으로 연결했다.

전체 본문의 문자열 마스크와 실제 출력문 범위를 사용해 여러 줄 대사를 수집하도록 수정했다. 문자열 내부의 가짜 출력문, 인접 명령과 형제 분기의 혼입을 방지한다. else 추론은 실제 if/elseif 체인 전체를 확인하며, 미표시 분기나 판정 불명 조건을 건너뛰어 else로 단정하지 않는다. 기존 UI, 선택지 조건, 수동 원고와 게임 동작은 유지한다.

## 검증

- 신규 중립 회귀 5건에서 변경 전 예상 실패, 변경 후 통과. 기존 scalar-image 6건, flow-scope 2건을 포함해 부모가 13/13 통과를 재확인했다.
- 실제 WORK와 운영 중인 3813 서버의 읽기 전용 context/scene API에서 총 5페이지를 확인했다.
- 2번 → 188행 분기, 190행 원고, 3번째 페이지.
- 2-2 → 192행 분기, 196행 다중행 원고, 4번째 페이지 `2번 조건 선택 결과`.
- 3번 → 200행 분기, 5번째 페이지. 세 결과의 원고와 목적지를 서로 비교해 구분됨을 확인했다.
- 기존 통합 탭을 갱신하고 페이지 선택 드롭다운으로 `2번 조건 선택 결과`가 실제 표시되는 것을 확인했다. IAB의 iframe 클릭/키 입력은 자동화 대상 오류로 실행되지 않았으며, 드롭다운 선택 API로 결과 페이지를 검증했다. 갱신 뒤 작업 탭은 각본 파일 만들기 상태이고, 선택 결과는 2-2로 열려 있다.
- 갱신 전 현재 수정문과 원문이 동일함을 확인했다. 기존 자동 초안 저장과 선택 복원을 재사용했다.
