# 선택지 페이지와 결과 컷신 표시 복구 — 2026-11-15

사용자 확인: 선택지 1·2·3은 한 페이지에 함께 표시하고, 선택하면 해당 결과 페이지와 미리 만들어둔 샘플 이미지를 볼 수 있어야 한다.

## 원인

기존 flow.cjs는 $text[n] 배열만 단계로 묶었다. $text에 여러 문자열 변수를 합치는 페이지는 선택지, 비용 부족 안내, 결과 문구를 모두 별도 단계로 셌다(최대13단계). 선택값을 대입하고 GT $curloc 하는 링크도 같은 위치 전체로 연결해 결과 분기를 놓쳤다. 그림은 $place 이름표 배경을 명시적인 $bg_path 컷신보다 먼저 고르고, 다음 페이지에서도 이전 배경 선택을 유지했다.

## 수정

page-flow.cjs를 추가했다. 여러 HTML 선택지 변수를 한 $text로 조립하는 명확한 호출형 페이지를 정적으로 분석한다. 단일 합성 메뉴와 그 결과를 1개 메뉴+3개 결과로 구분하고 비용 부족 표기는 같은 선택지의 조건별 변형으로 접는다. 고정 문자열 대입 및 단순 변수 별칭으로 결과 IF/ELSEIF/ELSE가 유일하게 확인될 때만 연결한다. QSP·세이브를 실행하거나 비용·CM·아이템을 변경하지 않는다. 복잡하거나 모호한 소스는 기존 탐색으로 남긴다.

선택지 주 버튼은 결과 페이지를 미리 보고, 별도 ‘문구 편집’으로 해당 원문을 수정 대상으로 연다. ‘← 선택지 페이지’로 돌아가고 페이지 선택기로 결과를 바로 볼 수 있다. 기존 장면 UI·원문 편집·조건/반영 승인 절차와 $text[n] 방식은 유지한다. 새 결과 페이지에서는 해당 $bg_path 컷신을 우선 표시한다. 같은 페이지에서 사용자가 후보 이미지를 바꾸는 기능은 유지한다.

## 확인

신규4검사와 기존 장면/배열8검사 통과. 최종 인라인 JS 문법 통과. 실제 WORK 원문에서 첫 페이지에 선택지3개, 결과1·2·3의 정확한 목적지와 이미지 경로를 확인했다. 브라우저에서 3개 버튼, 결과1의 #자살선택지1, 결과2의 #자살선택지2, 결과3의 #자살선택지3+고기 안내, 각 샘플 PNG의 실제 로딩을 확인한다. 통합 프레임의 자동 입력 제한 때문에 직접 클릭 검증은 같은 편집기의 별도 창에서 수행했다. 통합창의 표시/로딩은 별도로 확인했다.

샘플 파일은 기존 scene/others/suicide_after_1.png, suicide_after_2.png, suicide_after_3.png를 그대로 사용한다. 게임 QSP SHA-256은 작업 전후 d9e54998be9b9d2dbb56e69c1d464c582d6e047ea7c44ed9d50c03134b506c33으로 동일하다. 게임 문구·이미지·수치·배포본은 수정하지 않았다. 편집기 소스와 WORK/modtools/text-workshop 5파일만 반영했다. 커밋·푸시는 하지 않았다.

## 유지보수

입력은 QSP 문서/문자열 목록이며 출력은 flow.kind=pages와 페이지별 원문 참조·조건 변형·이미지 후보·목적지이다. 호출자는 flow.cjs이고 scenes.cjs가 링크/분기 해석기를 전달한다. index.html은 새 페이지 흐름일 때만 전용 표시를 사용한다. page-flow.cjs를 제거하려면 flow.cjs의 require/extend 연결도 함께 되돌린다. 그 경우 기존 소스 단위 표시로 돌아간다. before/*.gz와 changes.diff를 기준으로 복원 가능하며 page-flow.cjs는 이번에 추가한 파일이다.

서버3813을 재시작할 때 기존 JO9_MODDING_HUB_ORIGIN=http://127.0.0.1:7689 설정을 유지했다. 프레임 허용 범위는 기존 통합 작업실 한 곳이다. 원래 사용 중인 편집창은 수정문이 원문과 동일함을 확인한 뒤 다시 불러왔다.
