# 초기값 표시·특성 색상·성기술 3열

## 원인과 수정

JSON의 명시적 숫자만 읽어 화면에 출력하면서, 게임이 공용 초기값과 산식으로 만드는 세련됨·인지도·기분·흥분·관계 단계·성교육계·복종도·장악력 영향이 ‘미설정’으로 남았다. 이 값들은 원본 JSON을 고치지 않고 표시 시 계산하도록 연결했다.

- 세련됨: 누적값(0~200)을 게임 임계값 0/10/20/40/80/160으로 변환한다. 우아함·청결·화장·향수·손톱·제모·머리·세련됨 보정 누적치를 반영한다. 일반 새 화면 갱신의 자동 미용 처리도 적용한다.
- 인지도: 기존 fame_rate의 초기 누적값을 동일한 임계값으로 환산한다.
- 기분: 공용 초기값 0과 진행값을 반영한다. 정신 붕괴의 차분함, 절망·성격·기본 복종 상태·두려움에 따른 원본 상한을 적용한다. 음수 기분의 표시 인덱스도 게임처럼 변환한다.
- 기타 관계 등급/단계·흥분은 지정값 또는 기본 0을 사용한다. 성교육계는 9개 성기술 대분류 합계, 복종도는 원본 산식으로 표시한다. 직접 지정한 시뮬레이션 값은 우선한다.
- 계산 결과는 원본 JSON·역할 프로필에 자동 저장하지 않는다. 초기값을 명시적으로 편집·저장하는 기존 동작만 유지한다.

이 화면은 실행 중인 세이브 조회가 아니다. **공용 초기 상태**를 기준으로 하며, 보통 난이도/추가 장비·마법·일시적 기분·개별 영입 이벤트 효과는 별도이다. 실제 획득 경로의 추첨이나 이벤트가 바꾼 수치까지 알고 있다고 표시하지 않는다. 화면과 툴팁에 이 기준을 안내한다. 미지정 일반 캐릭터의 기본 속성은 공용 0을 보여 주며, 생성 경로에서 다시 추첨될 수 있음을 툴팁으로 밝힌다.

## 특성 색상

QSP의 dyneval 색상, `content/js/jo9_traits_view.js`의 특성별 grade, `css/jo9_traits_view.css`의 grade/칭호 우선 규칙을 함께 읽는다. 예: 워커홀릭·끈기·건강체질은 하늘색, 양성애자·강한 복종심은 녹색, 통증 내성은 보라색, 가학성애자는 파란색, 무모함은 분홍색, 칭호는 갈색이다. 기본 검정인 상태·종족은 기본색을 유지한다. 이 규칙을 시뮬레이터의 읽기 전용 태그와 캐릭터 편집기의 수정용 태그에 공통 적용했다. JS/CSS가 바뀌어도 메타데이터 캐시를 새로 읽는다.

## 배치

성기술은 3열이며 좁은 화면에서는 2열로 바뀐다. 화면의 ‘입력평균’ 문구를 제거하고 이름과 등급만 표시한다. 하위값에 따른 계산 설명은 툴팁에 남긴다. 카드 밖 가로 넘침은 실제 브라우저에서 없었다.

## 확인·한계

- 관련 Python 2건, JS 14건 및 수정 모듈 문법 검사 통과. 초기값 계산·지정값 우선·원본 객체 보존·특성 CSS 우선 규칙·캐시 갱신·기존 질문/초안 보존을 확인했다.
- 독립 검토에서 찾은 정신 상태 별칭, 기분 상한, 공용 자동 미용 처리도 수정하고 관련 사례를 추가 확인했다.
- 실제 브라우저에서 기본 속성 12종과 관계 지표에 미설정이 없고, 특성 색상과 성기술 3열/문구 제거가 적용됨을 확인했다. 기존 사용자 탭의 미저장 입력을 보호하고 새 임시 탭에서 확인했다.
- 실제 게임 세이브 실행이나 전체 배포 검사는 UI 표시 수정 범위에서 하지 않았다. WORK 게임 데이터·배포본·커밋·푸시 변경 없음.

함수: `initialPreview(character, overrides, rules)`는 `{attributes,status,skills,trace}`를 반환하는 순수 계산이다. `traitPresentation(row)`는 QSP/프로필 색상표에서 색상을 찾고 실제 게임의 칭호 우선 규칙을 적용한다. 이를 제거하면 초기값 자동 표시/특성 색상이 없어지며 게임 실행 코드에는 영향이 없다. 자세한 출처는 PLAN_KO.md와 changes.diff를 참고한다.
