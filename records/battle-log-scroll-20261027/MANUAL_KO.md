# 전투 기록 스크롤

사용자 선택대로 전투 기록만 세로 스크롤을 허용하고 이전·다음 페이지를 제거했다. 긴 기록 전체를 같은 DOM에 유지하며 중복된 BR만 정리한다. 글꼴·행간·색상·패널 배치·행동/무기 목록·이펙트 분리는 유지한다.

구성: CSS의 BATTLE_LOG_SCROLL_20261027과 content/js/jo9_battle_log.js의 같은 식별자. 기존 2개 QSP 전투 렌더러의 스크립트 호출을 그대로 사용한다. JS 입력은 현재 #fight_txt DOM이며 반환값이나 새 QSP 변수/로케이션/저장 키는 없다. 기존 페이지 API는 진단용이었으며 현재 스크롤 검사로 대체됐다. 페이지 생성·DOM 재구성·타이머는 제거했다.

기존 QSP 7c366e1ae35a5922e32052847bceb28737ddab32c3861b19bbefd7661b45c2b7는 바이트 그대로다. 이번 문법 검사는 JS node --check와 실제 QtWebKit 실행으로 한정하며, 수정하지 않은 QSP의 공식 검사를 다시 실행했다고 표현하지 않는다. 긴 5적 진행/승리와 짧은 진행 3조건의 내용 보존·스크롤 끝·글꼴·명령 적중 검사를 native-scroll-results.json에 남겼다. 실제 Windows 연속 클릭 검사는 아니다.

백업 G:/somi/JO9_work_backups/battle_log_scroll_20261027110728의 CSS와 JS를 WORK/추적 소스에 함께 복구하면 이전 페이지 방식으로 돌아간다. 한 파일만 복구하면 페이지 UI와 overflow 규칙이 맞지 않을 수 있다. 별도 배포 폴더·기존 세이브·엔진·설정·QSP·ZIP·커밋·푸시는 변경하지 않았다. 다음 게임 재실행부터 적용된다.
