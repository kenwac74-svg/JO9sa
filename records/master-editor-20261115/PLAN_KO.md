# 마스터 편집·양방향 복제 구현 계획

사용자 승인: 기존 UI 유지, 노예/마스터 편집, 남녀 목록·검색, 외형 동일 조작, 배경 역할 전환, 양방향 복제.

writing-plans / executing-plans 적용. 현재 운영 원본을 보존하고 이 작업 폴더에서 모듈을 작성·검사한 뒤 통합 허브의 override로 제공한다. 기존 사용자 편집을 보존하며 커밋·푸시·배포는 하지 않는다.

## 구조

- `tools/modding-hub/master_editor.py`: QSP 마스터 배열의 읽기·선택 변경 저장, 편집용 보조 JSON, 외형 저장, 역할 간 복제. 기존 seed/talkbook 계약 유지. 원본 QSP를 바꾸는 경우 요청한 마스터 배열만 바꾸고 mods/백업과 원본 해시를 기록한다.
- `overrides/studio-view.mjs`: 원본 UI 재사용, 역할 옵션으로 두 인스턴스. 기존 탭·검색·외형 조작 유지, 배경 설정 내 역할 전환, 명시적인 양방향 복제 창.
- `server.py` / `integration.mjs`: 원본 API 유지, master 전용 API와 노예 보조 마스터 설정/복제 API, 사이드바 하위 메뉴 연결.
- 실행기 빌드 지문에 신규 모듈 포함. 실제 게임 자료는 사용자가 저장하기 전까지 읽기만 한다.

## 진행

- [ ] 1. 실제 WORK의 남주 18·여주 24 정의와 스키마를 고정해 파서·원본 범위·충돌·복제 검사를 먼저 작성하고 실패 확인.
- [ ] 2. 마스터 원본/편집 보관값/외형/대사집/양방향 복제 API 구현. 복제는 원본을 보존하고 새로운 파일/번호만 생성. 대응되지 않는 역할 값도 보조 JSON에 보존. 새 마스터는 정의를 만들고 시작 메뉴 연결 여부를 명확히 표시.
- [ ] 3. 기존 UI를 역할 매개변수로 재사용하고 배경 전환·게임/보관 구분·수치 대응표·새 인물 열기 연결.
- [ ] 4. 임시 소형 QSP/JSON/도형 이미지에서 실제 저장·복제·기존 자료 보존 검사. 운영 WORK 자료에는 시험 저장하지 않음.
- [ ] 5. 구문/관련 회귀 검사와 브라우저 화면 확인. 원래 작업 탭은 새로고침하지 않고 결과·사용법·한계 기록.

## 주의할 입력

따옴표/중괄호/여러 줄 소개문, 모르는 QSP 명령, 같은 번호의 다른 역할, 저장 중 원본 변경, 복제 대상 번호·파일 충돌, 역할 변경 후 미저장 편집 보존, 공유 이미지 덮어쓰기, 유효한 비번호 파일명.

새 마스터의 시작 메뉴 배치는 기존 게임 화면을 자동 변경하지 않는다. 새 정의 생성 결과에 연결되지 않음을 표시하고 QSP 이벤트 탭에서 연결 코드와 참조 위치를 제공한다. 기존 마스터 편집은 실제 시작 프리셋을 수정하며 이미 시작한 세이브의 주인공 수치를 덮어쓰지 않는다.
