# 경기 우승 명성 — WORK 적용

랠리는 개인 첫 우승 +10, 반복 우승은 현재 명성40 미만 +1 / 40~79 +0.25다. 첫 우승도 포함해 랠리로는 최대80까지만 오른다. 기존 명성이80 이상이면 그대로 보존하며 추가하지 않는다. 캣파이트는 현재 누적 승수1/2/3번째에10/3/3,그 뒤0이다. 기존3승 달성 후 출전 금지는 유지한다. 캣파이트는 유한 보상이므로 랠리의80상한을 적용하지 않고 기존 명성 원천 상한200만 따른다.

## 기존 세이브와 분수

기존 랠리에는 개인 우승 기록이 없다. 공용 결과 방문수를 개인 기록으로 추측하지 않고, 업데이트 후 처음 정상 입장해 우승한 때 첫 보너스를 기록한다. 저장된 결과 화면이나 참가 표식 없는 이전 추첨을 직접 열어도 소급 지급하지 않는다. 캣파이트는 원래 catfight_level을 사용하며 초기화나 역산을 하지 않는다. 기존1승 인물의 다음 승리는+3이고, 이미3승 이상인 진행 중 전투를 마치더라도 추가 명성은 없다. 기존 파일76개는 수정하지 않았다.

명성 원천은 slave_rate['fame']이고 화면의 slave['fame']는 등급이다. 랠리의0.25는 개인 배열 jo9_rally_fame_quarter에0~3사분점으로 보존한다.40점에서4회 반복 우승하면41,79.75에서 한 번 우승하면80이 된다. 첫 우승 표시는 jo9_rally_won이다. 두 키는 인물 배열 전체 교환/보관 규칙을 따르며 종자ID별 전역 이력표를 쓰지 않는다.

## 호출·입출력·부수 효과

패치 2026-10-24_contest_fame. 입력 f81779df72185ba8afdad6b365a61c1281692fd565080ff94c15840b08c1a74b, 적용 후 7ba03d9adb313169c78a26dfad2970fc9f57b11f13aad67da9f768a04bafc113.

- jo9_contest_fame의 begin은 현재 slave의 상태·이름·타입·종자ID를 참가표식에 기록한다. cancel은 표식을 지운다. settle은 결과ID를 받아 표식을 먼저 소비하고, 정상 승리ID4종과 같은 인물인지 확인한 뒤 보상한다. 반환 result는 실제 증가한 사분점 수다(1=0.25,4=1,40=10). 결과 표시·인물 이동·상금 정산은 하지 않는다.
- interaction_city의102102 남녀2곳에서 begin,102103 두 거부 분기에서 cancel,102113~102116 남녀8개 추첨 확정 직후 settle을 호출한다. 성공/실패 결과 페이지에는 명성 지급을 넣지 않았다.
- выход_из_боя의 기존 Start1 토큰 소비 뒤 캣파이트 승리 분기에서 누적승수를1 올린 다음 새 승수가1/2/3일 때만 명성10/3/3을 추가한다. 기존 일반 콜로세움과 안개 명성은 변경하지 않았다.
- #help_msg의 명성 도움말에 두 경기 규칙을 표시하며 $ongload는 이전 도움말 캐시만 갱신한다. 새 게임은 기존 Start/start_refresh의 killall을 따른다.

랠리 참가표식 jo9_rally_ticket은 일시적 전역 배열이며 이름은 문자열 항목에 저장한다. 승패·거부·인물 불일치 때 소비해 같은 시합 정산을 두 번 지급하지 않는다. 부여하는 영구 개인 키는2개, 새 로케이션은1개다. 상금·참가비·행동력·추첨 확률·기술/복종 판정·기존 원고·이미지·JSON은 바꾸지 않았다.

helper만 제거하면 기존 입장/추첨 호출에서 없는 위치 오류가 난다. 기능을 분리할 때는 RALLY_FAME_BEGIN/CANCEL/SETTLE과 helper를 함께 처리해야 한다. 캣파이트 보상은 CATFIGHT_FAME_REWARD이며 기존 CATFIGHT_SINGLE_WIN·Start1 토큰·3승 제한에 의존한다. 이전 승수 가산을 결과 페이지에 복구하면 다시 중복 승수 문제가 생길 수 있다. 위치는 patch.json의 안정적인 패치 표식으로 찾을 수 있다.

## 검사

실제 FastQSP에서 랠리 경계373상황/1467조건, 실제 입장→추첨→결과52상황/298조건, 캣파이트 전체 정산58상황/204조건, 캣파이트 수치 경계104상황/200조건과 역할 교환4조건이 통과했다. 첫승·반복·39→40·사분점4회·79.75→80·기존80/160/200 이상 보존·패배·거부·인물 교체·동일 종자의 독립 기록·새/기존 결과·3연승16·3승 차단·결과/정산 재진입·일반 콜로세움 기존 보상·원본 상금/AP 유지가 포함된다. 엔진 SAVEGAME과 코덱의 바이트 왕복에서 개인 키·분수·진행 표식 저장도 확인했다.

공식9경로, 구조·줄바꿈·인물JSON1126개, 정확 패치 재생/재적용, 독립 코드 검토가 PASS다. WORK 설치 파일이 후보와 바이트까지 동일하고 기존76세이브·Full·설정·CSS의 해시가 보존됨을 확인했다.

진단본은 최종 화면 끝점과 추첨 난수만 필요한 곳에서 제어했다. 캣파이트 수치 전용 검사는 마지막 도시 화면 이동만 종료문으로 바꿔 상태를 읽었다. 전체 흐름 검사는 native 코드를 유지하고 최종 화면4곳만 검사 끝점으로 연결했다. 테스트의 arena_mode 기대값과 초기 버전 제목 오류는 원본 복귀 동작에 맞게 고쳤으며 제품 코드를 바꾸지 않았다. 원래 전체 결과 처리 스크립트를 임의로 재실행하면 상금/AP가 재정산되는 기존 구조는 그대로지만, 이번에 추가한 명성은 반복 지급되지 않는다.

전체 동적 QSP 문법의 정식 증명, 실제 마우스 플레이와 사용자 세이브 GUI로드·CRC호환 전수 검증은 아니다. 기존 캣파이트 사망 결과의 별도 제어흐름 문제 후보는 unrelated-findings.json에 남겼고 이번 변경에 섞지 않았다.

WORK만 반영했다. Full·배포ZIP·커밋·푸시는 하지 않았다. 복구본 before.qsp.gz, 선언형 patch.json, 소스/재현 스크립트와 핵심 검사 기록을 보존한다. 재현은 scripts/reproduce.cjs의 restore → build 순서로 격리본만 만든 뒤 각 검사 단계로 진행한다.
