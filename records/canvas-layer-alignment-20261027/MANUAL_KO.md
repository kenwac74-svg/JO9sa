# 게임오버 레이어 정렬 수정

패치 ID: `FULLSCREEN_LAYER_ORIGIN_20261027`.

사용자가 제보한 전체 화면 그림과 뒤쪽 배경 사이의 틈을 수정한다. WORK와 추적 소스에만 적용하며 이전 전투 UI 시험판·기존 세이브·배포 폴더는 보존한다.

## 원인과 처리

원본 게임오버 `exit`는 공용 `_layout`의 본문 시작점 (1,1) 위에 일반 컷신용 `#bg` (4,3; 795×595)를 사용해 1280×800 그림을 출력했다. 실제 엔진에서 그림은 (5,4)에 놓여 오른쪽·아래가 넘쳤다. 부모 영역의 좌표를 (20,13)으로 바꾸면 그림도 (24,16)으로 밀렸다.

수정은 게임오버에서만 본문 원점을 (0,0)으로 맞추고, 그림·문구·메뉴를 고정 1280×800 `jo9_gameover_stage` 안에 묶는다. 이 전용 영역은 일반 컷신의 위치 규칙을 따르지 않는다. 기존 이미지 선택 도구, 문구, 메뉴 링크와 글자 크기는 유지한다. 일반 컷신의 `#bg` 규칙과 전투 UI 코드는 변경하지 않는다.

## 파일과 의존성

- `mods/2026-10-27_fullscreen_layer_origin.json`: `exit` 본문 변경과 적용 전후 해시.
- `css/base.css`: 파일 끝의 같은 패치 ID 블록. 추적 원본은 `assets/css-2.4/base.css`.
- 사용 그림 `content/pic/bg/game_over.png`: 원본 그대로. 새 그림·엔진 바이너리·설정 파일은 추가하거나 바꾸지 않는다.
- `exit`의 `MAINDESC_X/Y` 두 표시 값만 조정한다. 새 저장 변수·함수·로케이션·세이브 이관은 없다.
- 기존 `interior_change`가 그림과 전환 도구를 만들고, `jo9_word_wrap.js`가 문구 띄어쓰기를 처리한다. 기존 종속성은 유지한다.

QSP만 복구하면 신규 CSS는 해당 root가 없어 적용되지 않는다. CSS만 제거하면 전용 root의 배치가 사라지므로 두 파일을 함께 복구한다. 백업 위치는 같은 폴더 `before.json`에 기록했다. 게임 종료 후 백업의 `jack.qsp`, `css/base.css`를 WORK의 같은 위치로 복원한다.

## 확인

`native-design-canvas-results.json`은 정상 설정에서 실제 QtWebKit의 원본·후보와 부모 위치 변경 4조건을 비교한다. 수정 후 그림과 캔버스는 모두 (0,0,1280,800)이다. 지연된 띄어쓰기 처리 뒤에도 문구·메뉴의 상대 위치가 유지된다. 메뉴 접근성은 별도 hit-test로 확인한다. 공식 9경로와 패치 재생·멱등성·구조·줄바꿈 검사를 함께 실행한다.

초기 진단 복사본에서 UTF-16 설정을 UTF-8로 잘못 읽어 0폭이 측정됐으나, 설정의 BOM과 인코딩을 보존한 최종 검사로 바로잡았다. 원본 게임 설정은 변경하지 않았다.

검증 범위는 게임이 사용하는 1280×800 논리 화면이다. 모든 장면이나 운영체제 화면 배율의 모든 조합을 검사한 결과는 아니다. 앞서 별도로 제보된 클릭 잔상 문제의 엔진 수리를 뜻하지 않는다.
