# 파산 정산 4단계 변경 계획

사용자 지시: 장식 → 빈민가 이주 → 활동 노예 → 조수. 시설 입주자는 이주를 확정할 때 평가 기본가 50%에 급매하며 외부 크라이오 보관소도 포함한다. 쿨라 증축 개인실은 공사비 20%로 일괄 정산한다. 직접 방법을 찾으면 현재 행동력으로 일반 거래를 계속할 수 있고 이주 급매는 실행되지 않는다.

## 구현 범위

- 최신 WORK의 QSP만 후보로 수정한다. Full, 배포 ZIP, 원본 세이브, 원본 소스와 수동 대사는 보존한다. 커밋·푸시하지 않는다.
- `jo9_liquidation`의 기존 청구 스냅숏과 한 번 정산하는 경계를 유지한다. 표시 단계는 현재 자산에서 계산하여 기존 15페이지 세이브도 처리한다.
- `jo9_liquidation_assets`에 `quote_move`와 `move_slums`를 추가한다. 주택 부속 9슬롯과 외부 보관 18슬롯을 평가 후 정리한다. 자가 주택의 기존 지역별 50% 매각은 유지하고 임대시설 해지에는 금액을 지급하지 않는다.
- `jo9_liquidation_sale`의 기존 평가·장비·슬롯 정리 기능을 시설 슬롯에도 재사용한다. 활동 노예와 조수는 이주 때 보존한다. 의뢰 완료/NPC 거래/명성은 변경하지 않는다.
- 죽은 인물은 매각대금 없이 정리한다. 비소유 계약 인물은 소유자로 반환하고 매각대금을 지급하지 않는다. 괴물 사육장 해지 시 괴물은 대금 없이 기존 상실 처리에 맞게 정리한다. 새 가격 규칙을 만들지 않는다.
- 일반 부동산 해지에서 파산 전용 일괄 급매를 실수로 실행하지 않도록 기존 해지 호출을 파산 선택 화면으로 안내한다. 일반 이사의 입주자 보호는 유지한다.

## 검사 계획

1. 수정 전 실제 엔진에서 새 이동 API가 없는 실패를 확인한다.
2. 기존 평가 산식 50%, 쿨라 누적 20%(1~4칸: 1000/1400/2400/4400), 전체 27슬롯 정리, 활동 인물 보존을 실제 엔진에서 검사한다.
3. 장식 재환급, 이주 재환급, 이미 청구된 비용 재계산/중복 차감, 수동 복귀의 조기 급매, 행동력/날짜 변화, 과거 페이지 저장값을 검사한다.
4. 정확 패치 재생·재적용, QSP 구조/개행/표식, 공식 실제 엔진 9경로 검사를 통과한 후보만 WORK에 설치한다.
5. 사용자 세이브/Full/config 보존을 해시로 확인하고 보고서·변경 명세·재현 스크립트·최소 백업을 남긴다. 재생성 가능한 진단 사본은 정리한다.

이 계획은 사용자 요청 기능을 기존 3개 로케이션에서 수정하며 새 로케이션·새 저장 이력은 추가하지 않는다. 현재 자산 상태가 중복 방지의 기준이다.
