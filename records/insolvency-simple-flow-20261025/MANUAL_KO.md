# 파산 정산 단순화 및 특성 표시 보완

WORK만 적용하는 작업이다. 배포 폴더·기존 ZIP·사용자 `.sav`·커밋·푸시는 변경하지 않는다. 실제 적용 여부와 검사 결과는 `FINAL_RESULT.json`을 기준으로 한다.

## 파산 위기에서의 선택

청구 금액보다 현금이 모자라면 기존 파산 위기 이벤트를 사용한다. 현재 남아 있는 자산에서 다음 순서를 계산하므로 과거 15페이지의 저장된 페이지 번호에 의존하지 않는다.

1. 실내장식: 설치된 장식의 정가 50%. 상태·일반/확대 그림·설명은 기존 기본값으로 바뀐다. 기존 처분 표식을 유지하여 같은 장식의 재환급을 막는다.
2. 빈민가 이주: 주거지의 임대시설을 모두 해지하고 외부 크라이오 보관도 끝낸다. 시설 계약 해지 수입은 없다. 본인 소유 입주자는 기존 `slaveprice`의 절반에 경쟁 노예상에게 급매한다. 정상 NPC 납품 보상은 지급하지 않는다. 쿨라 증축 개인실은 정해진 공사비의 20%를 합산한다(1~4칸 누적 1000/1400/2400/4400). 자가 주택은 이전 합의의 지역별 정가 50%, 임대주택은 주택 대금 0을 유지한다. 활동 중인 노예와 조수는 데리고 간다.
3. 현재 활동 노예 급매: 기존 기본 평가액의 50%.
4. 현재 조수 급매: 같은 기준의 50%.

각 결정 후 청구액을 낼 수 있으면 추가 처분을 하지 않고 한 번만 정산한다. 이미 장식을 처분했다면 다음 파산 위기에는 이주 단계부터, 이미 빈민가이고 잔여 시설도 없다면 노예 단계부터 나온다. 예전 세이브가 빈민가에 외부 보관소 등만 남겨 둔 경우에는 이동 없이 해당 잔여 계약·보관 인물을 정리하는 선택을 먼저 제공한다. 자산이 남았는데 엔딩으로 넘어가지 않도록 하는 호환 처리다.

`직접 방법을 찾는다`는 자산을 처분하지 않고 기존 게임으로 돌아간다. 남은 행동력을 사용하는 기존 판매·대출·이동 규칙은 유지한다. 미납 청구가 있는 동안 날짜 진행은 기존 경계에서 차단한다. 집 밖으로 나가는 것으로 청구가 사라지지 않는다.

## 인물 정리와 퀘스트

이주에서 처리하는 역할은 감옥 `prisoner`, 축사 `farmhand/cow/harpy/pig`, 증축 `room1..4`, 외부 동면 `iced_1..18`의 27개다. 역할을 현재 활동 인물로 교환하지 않고 기존 장비 이전·슬롯 초기화 기능으로 정리한 뒤 `new_estate`를 호출한다. 입주자 때문에 감옥·축사가 다시 켜지는 일을 방지한다.

생존·기절한 소유 인물만 매각대금을 지급한다. 사망 인물은 대금 없이 정리한다. 계약 인물은 사용자 결정에 따라 실패 반환하며 매각대금·성공 보상·새 벌금은 없다. 남겨 두는 활동 인물이 길드 교육 대상인 경우에는 그 별도 계약을 보존한다. 괴물 우리는 기존 상실 처리에 맞게 괴물 상태도 대금 없이 정리한다. 외부 보관 공간의 영구 해금 수는 유지하되 보관자는 모두 비우므로 점유 임대료는 발생하지 않는다.

실제로 인물을 처분할 때만 해당 인물 유형에 묶인 미완료 의뢰를 실패로 종료한다. 견적 조회·수동 복귀·실패한 판매 확인에서는 실패시키지 않는다. 이미 완료한 퀘스트, 다른 인물의 퀘스트, 어느 적합한 인물로든 달성 가능한 일반 납품 주문은 보존한다.

- 펠리시티, 베네라, 펠라게야, 코셰이의 공주, 캐롤라인, 엘사·자스민, Tsyuansu·Hotorn 의뢰 인물, 에게야·미라·카리나의 고유 납품을 연결한다.
- 원본에 영구 실패값이 없는 의뢰만 `jo9_lq_failed_quest` 사전으로 기록하고 해당 의뢰 진입·완료 콜백을 차단한다. 성공 진행도로 위장하지 않는다.
- 원본 펠리시티 의뢰 실패의 다음 날 암살 엔딩은 유지된다.
- 아카부르 성공 완료 21은 실패 22로 덮어쓰지 않도록 기존 분실 검사에도 상한을 둔다.

## 호출·입력·반환·저장

- `jo9_liquidation`: 기존 `begin/settle/finish/manual/view/dispose/sell_person` 진입을 유지한다. 첫 미납의 청구액은 `jo9_lq['bill']`에 고정되고 `settle`만 차감한다. 현재 자산을 기준으로 0~3단계를 표시한다. 오래된 개별 시설 처분 콜백은 새 순서를 건너뛰지 못한다.
- `jo9_liquidation_assets`, `quote_move`: 조회만 하며 `jo9_lq_value['relocation']`, `relocation_people/rooms/house`, 가용성·인원 수를 반환한다. `move_slums`는 같은 상태를 다시 평가하고 실제 처분 후 `jo9_lq_sold/paid`를 반환한다. 중간 매각 실패 시 주택·시설을 없애지 않는다.
- `jo9_liquidation_sale`: 기존 역할 복제 평가와 50% 급매를 27개 시설 역할에도 적용한다. `fail_quests,role` 모드는 실제 처분 직전 연결 의뢰만 정리하고 인물·돈은 직접 바꾸지 않는다.
- `interaction_city`: 일반 부동산 해지의 과거 확인 문구에서 일괄 급매를 실행하지 않고 파산 선택창으로 안내한다. 일반 이사의 입주자 보호는 유지한다.
- 새 저장값은 실패 의뢰 사전과 표시 문구 버전이다. 구세이브에 값이 없으면 0으로 해석하며 원본 세이브 파일은 이관·덮어쓰지 않는다. 새 게임은 실패 사전을 초기화한다.

주요 의존성은 기존 `$update_slave_price`, `jo9_traits_value`, `$sold_clothing`, `$clear_slave_instance`, `new_estate`, `snk_room_bridge`와 파산 후크다. 변경 경계는 `INSOLVENCY_FOUR_STEPS_20261025`, `INSOLVENCY_RELOCATION_20261025`, `INSOLVENCY_ACTOR_QUEST_FAILURE_20261025` 표식을 사용한다. 한 부분만 삭제하면 호출·표시·정산이 불일치하므로 정확 패치를 함께 되돌려야 한다.

## 특성 UI와 설명

`ui/MANUAL_KO.md`에 표시 파일과 의존성이 있다. 전체보기 문구를 줄이고 속성 묶음 간격을 5px로 맞췄다. 프로필 전용 CSS에서 왼쪽 위 금속 테두리를 이어 그린다. 특성은 원본 등급 팔레트, 칭호는 짙은 갈색을 사용한다. 일반 특성의 정확한 효과 수치를 힌트 문구로 바꾸며 실제 능력·성장·가격 산식은 변경하지 않는다. 기존 세이브의 설명 정의는 한 번 갱신한다.

## 검사 범위와 한계

공식 출고 검사는 파일 구조·개행·표식·정확 패치 재생·재적용과 실제 설치 엔진의 9경로를 확인한다. 별도 기능 검사는 27슬롯 동시 처분, 20% 누적액, 중복 환급/청구, 수동 복귀, 퀘스트 실패와 완료 보존을 다룬다. 실제 QtWebKit의 원래 선택지와 특성 링크도 클릭하고 가림 여부를 검사한다.

진단은 세이브 상태를 격리 QSP에 구성한다. 모든 사용자 세이브의 실제 불러오기/CRC, 모든 해상도, 모든 퀘스트 전체 플레이를 증명하는 검사는 아니다. 상세 결과에 실패·미검증을 구분한다. 기존 테스트 세이브 11~13번은 파일을 바꾸지 않고 새 정산 순서로 동작한다.
