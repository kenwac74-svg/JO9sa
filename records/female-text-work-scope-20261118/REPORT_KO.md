# 여주인공 대사 작업 제외 · 2026-11-18

요청대로 기존 게임 자료를 보존하고 작업 범위만 제한했다. WORK QSP와 SAV는 수정하지 않았다. 대사편집기는 새 화면에서 「여주인공 전용 제외」를 기본 체크한다. 기존 검색4열과 찾기 버튼 위치를 유지했다.

## 기본 동작

- 남주/공용 문구는 기존대로 검색·편집한다. 확인된 여주 전용 문구는 기본 검색과 장면에서 제외한다.
- 혼합/전이 장면 소유권 미확정 원문은 확인용으로 구분 표시한다. 기본 일괄 치환·각본 출력/수정·AI 각색에서는 변경 대상으로 쓰지 않는다.
- 사용자가 체크를 해제한 요청에서만 여주/검토 문구를 포함한다. 이 포함 상태를 다음 새 화면의 기본값으로 저장하지 않는다.
- 범위를 바꾸면 이전 미리보기·승인을 무효화한다. 본문/추가/각본 초안과 고정 경로는 보존한다. 과거 포함 범위에서 만든 출력이나 오래된 map은 기본 범위를 우회할 권한이 없다.
- 변경 내용을 반영하기 전 현재 범위와 원본 해시를 다시 확인한다. 페이지 추가 등 관련 편집이 보호 문구를 바꾸는 경우도 차단한다. 외부 AI 제공자 호출 전에 같은 범위를 검사한다.

## 구현·의존성

`work-scope.cjs`가 분류·수동/자동 필터·선택/수정 결과 검사를 제공한다. `work-scope-guards.cjs`는 조건의 IF/ELSE 및 현재 번호 모델을 분석한다. 현재 문서와 줄 내용으로 캐시를 관리하므로 과거 행/오프셋에만 의존하지 않는다. 원문 조회에는 읽기 전용 `workScope` 메타데이터를 붙인다.

`core.cjs`, `scenes.cjs`, 서버와 일괄·각본·대사/선택지/이미지 지정에 필요한 호출 모듈에서 이 범위를 전달한다. UI의 중앙 API는 GET과 POST에 `includeFemale`을 명시하며, 저장 중 토글을 잠그고 다른 범위에서 온 늦은 응답을 버린다. 각본 출력 기록의 범위 표시는 도구 메타데이터다. 게임 저장 항목이나 상태 변수를 추가하지 않았다.

실행 코드17개를 저장소와 WORK에 동일하게 설치했다. 테스트4개는 저장소에만 두었으며 WORK의 별도 과거 테스트 파일을 덮어쓰지 않았다. `manifest.json`, `before/`, `after/`가 설치 범위와 복구 자료다. 제거하려면 참조하는 모듈/서버/UI를 함께 이전 파일로 복원하고 서버를 재시작한다. 프로젝트의 사용자 지침과 백업 탐색 경로는 별도 요청 사항이므로 도구 복구와 자동 연동해 지우지 않는다.

## 검증

최근 집중 조건/동작21개와 격리 HTTP12개, UI7개 및 관련 기존UI17개 통과. 최초 넓은 검사69개도 통과했지만 이후 전체 반복의 잘린 출력은 새 전체 통과로 계산하지 않았다. 작업 범위 문서 및 백업의 확정18,994/검토735레코드와 런타임 분류가 정확히 일치했다.

현재 WORK 읽기 측정은 최초 해석147ms, 원문 분류 포함4,869ms, 같은 문서의 캐시 조회0.109ms였다. 실제 서버의 최종 읽기 요청은 이미 준비된 캐시일 수 있으므로 최초 로딩 시간으로 쓰지 않는다.

운영 서버에는 GET만 보냈다. 기본 검색의 `#txt_woman` 문구0개/명시 포함1,644개, 기본 일괄 검색0개, 공용 프리실라 문구1개 유지, UI 기본 체크를 확인했다. 코드38곳의 해시와 운영 QSP 보존을 검사했다. 운영 반영/각본 내보내기/AI 요청은 하지 않았다. 실제 사용자 캐릭터 편집 탭은 새로고침하지 않았다. 대사편집기를 다음 사용할 때 새로고침한다. 상세는 `API_VERIFICATION.json`.

여주 전용 내용의 완전한 전이 경로 증명을 뜻하지 않는다. 현재 알려진 미확정 항구/대출 장면은 검토 범위로 보류한다. 신규 유형은 사용자 지침에 따라 분류를 갱신한다.
