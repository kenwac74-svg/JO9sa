# MOB 무기·결과문 감사 — 결과/상태 담당

대상은 WORK jack.qsp이며 SHA-256은 `f18fcee393330747f693f0388ef5c0364b926a34e64ea25b659e68ca9b6aa652`이다. codec으로 메모리에서 해독해 분기를 추적했다. 게임/QSP 런타임은 실행하지 않았고 런타임 파일은 수정하지 않았다. 아래 줄 번호는 **해당 로케이션 body 내부의 1부터 시작하는 줄**이다.

## 오접속으로 볼 근거가 없는 항목

- 선택 모드가 활성화된 적은 `конец_раунда:197–209`에서 stage 성공 후 loop5로 건너뛴다. 따라서 뒤의 `213–243`에 있는 기존 즉사/기절/도주 문장이 중복 추가되지 않는다. 처형/생존 선택 뒤의 render도 선택 칸만 바꾸며 옛 사망 템플릿을 다시 호출하지 않는다.
- MOB의 실제 전투 자료는 무기 장착 ID가 아니라 **공격별 피해 유형과 문장**이다. `#противники`에는 장착 무기나 `$класс_оружия` 할당이 없고, 결과 로케이션은 무기 클래스 테이블을 조회하지 않는다. 검사한 결과 분기에서 잘못된 MOB 무기 클래스 인덱스는 발견하지 못했다.
- “최후의 일격”, “무기를 거두고”는 특정한 찌르기/베기/타격 방식을 지정하지 않는 범용 결과문이다(`jo9_battle_fate:291–293`). 여교관의 옛 사망/도주문에서 채찍이 떨어지는 묘사는 실제 채찍 공격과 일치한다(`#противники:270–284`).

## 범위 확인 또는 문구 개선 후보

- **가르시드 무리**: 안개 init 화이트리스트 `jo9_battle_fate:129`에 garsid가 없다. 61115는 가르시드 1 + 수인 4의 전투이므로 `133–141`에서 무리 전체가 mode=0이 된다. 이 경우 기존 사망/기절/도주문을 사용하는 것은 현재 코드의 실제 동작이다. 특수 전투 제외가 의도인지 확인해야 하며, 선택 흐름이 켜졌는데 옛 문구가 새는 결함으로 보지는 않았다.
- **성기사 사망문**: `#противники:3604`의 “난도질당한”은 플레이어의 실제 마무리 피해 종류와 무관한 고정 템플릿이다. 찌르기/마법으로 이겨도 동일 문구가 나오지만 결과 분기 오접속은 아니다. 피해별 묘사를 원할 때의 서술 개선 항목이다.

원문 발췌와 분류는 [result-audit.json](./result-audit.json)에 저장했다. 런타임 재현은 하지 않았으며, 구현·밸런스 변경을 승인하거나 실행한 보고서가 아니다. 전체 QSP 덤프/시험 QSP/복제 런타임 파일은 만들지 않았다.
