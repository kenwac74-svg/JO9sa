# MOB 전투 메시지·피해 실행 경로 감사

읽기 전용 정적 검사 결과, 고정 MOB는 아이템 무기 ID로 전투 메시지를 고르지 않는다. MOB ID인 `$враг[i]`에 연결된 공격 문구·피해값을 직접 읽는다. 따라서 그림이나 MOB 이름에서 무기 ID를 역추정하면 현재 실행 구조를 잘못 설명하게 된다.

- 파서: `G:/somi/JO9sa/tools/text-workshop/core.cjs`, 메모리에서 해독.

## 랜덤·변형·예외

`colosseum_fight`의 g 랜덤은 헐벗은 노예·여교관·여닌자·철갑투사 각각 3종, 여전사 2종의 실루엣·아바타만 바꾼다(L6–45). MOB ID와 공격 데이터는 그대로다. 고정 MOB에 무기 아이템을 무작위 배정하는 풀은 확인되지 않았다.

`#static_base` L157–180의 검투 스타일 무기표는 `$gladiator_fight_start` L34–36에서 플레이어가 조종하는 노예 쪽 `$оружие/$вторичный`에 들어간다. 고정 MOB의 공격 데이터와 합치면 안 된다.

훈육 상대 `воспитуемая`는 예외다. `начать_бой` L263–293에서 노예 장비 ID 23종을 차례로 검사해 피해 타입·기본 피해를 정하고, L297–330에서 3개 MOB 공격으로 복사한다. 여러 무기를 들고 있으면 뒤에서 일치한 규칙이 앞 값을 덮는다. `slave_attack=1`이면 마지막에 관통으로 덮는다. 문구는 구체적인 아이템 명칭 없이 일반 공격 문장과 ‘무기로’ 접미사다. 모든 장비가 이 상대의 슬롯에 실제 들어갈 수 있는지까지는 검증하지 않았으므로 미대응 장비를 곧바로 결함으로 분류하지 않았다. 23개 규칙은 JSON에 보존했다.

기본 QSP의 유일한 `inclib`는 커스텀 노예 자료 토글이며, 호출 뒤 즉시 `freelib`한다(`$addon_custom_data` L7–14). 점검한 WORK game 폴더에는 `jack_custom.qsp` 파일이 없다. 별도 라이브러리가 누락 AI를 제공한다는 근거는 확인되지 않았다.

## 제한된 엔진 회귀 검증

부모 에이전트가 전체 WORK의 별도 진단 사본에서 Start만 바꾸고 실제 `рассчет_вреда` 계산기를 1건 실행했다. 기본 피해 20, `модификатор_рубящий=-7`인 동일 입력에서 `рубящий` 결과는 13, `режущий` 결과는 20이었다. 실제 SAVEGAME `damage.sav`에서 두 결과값을 파싱해 확인했으며 PASS였다. 이는 `режущий` 경로가 표준 베기 modifier를 건너뛰는 현상을 뒷받침한다.
