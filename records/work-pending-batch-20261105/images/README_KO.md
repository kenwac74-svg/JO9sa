# 새·옛 이미지 등록 병행 조회 후보

WORK에 직접 쓰지 않은 선언형 후보이다. `mods.json`의 15개 편집이 9개 로케이션을 바꾼다. 현재 WORK 기준 해시는 `verification.json`에 있다. Full·캐릭터 JSON·그림·파일명·ID·세이브는 이 작업에서 쓰지 않았다.

`generate.cjs`는 기준 해시를 확인하고 메모리에서 패치를 적용한다. QSP 구조 왕복과 역순 편집의 원본 바이트 일치를 검사한다. 생성·머리색 추론·배열 초기화·정의 삭제·성형 확정 캐시 대입·개발용 출력·기존 주석은 그대로 둔다. `consumers.test.cjs`가 감사된 비출력 코드 보존을 검사한다.

## 입력·반환·호출

- `func('jo9_seed_role_images','resolve',ID,현재경로,옛키)`는 기존 호출 규약이다. `$result`는 존재하는 그림의 `content/pic/`와 `.png`를 제외한 경로이며, 전부 없으면 빈 문자열이다. 알려진 별칭만 보정하고 유효한 사용자 지정 경로는 유지한다.
- `func('jo9_seed_role_images','select',ID,현재경로,옛키,새키,상태접미사,우선순위)`가 명시적인 출력 규약이다. `pack`은 상태·새 일반 그림을 먼저 확인하고, `legacy`는 직접 출력하던 후보를 먼저 확인한다. 현재 화면이 유지하던 사용자 지정 후보를 보존하며, 같은 복장 반대 등록과 기본 전신을 이어서 검사한다.
- `func('jo9_seed_role_images','registered',ID,옛키,새키)`는 숫자 `result`로 0/1을 반환한다. 문자열 등록만 확인하므로 파일 누락 때문에 기존 선택지를 숨기거나 기본 전신만으로 없는 복장을 열지 않는다.
- 내부 `alias` 모드는 기존 별칭 보정 알고리즘과 조기 종료를 보존한다. 이 모드의 결과를 외부에서 직접 표시하면 파일 검사를 우회하므로 출력 호출은 `resolve` 또는 `select`를 사용한다.
- 기존 인자 없는 `gs 'jo9_seed_role_images'`의 등록 정리는 유지한다. 새 조회 모드에서는 정의와 배우 캐시를 쓰지 않는다. 추가 후보·파일 검사·복장 키 변수는 함수 로컬이다.

기존 43개 resolver 호출 중 `display_fullimage`와 `stasis_cell`의 2곳은 명시적 `select`로 바꾼다. 나머지 41곳은 새 `resolve`를 통해 같은 파일 검사를 받는다. `display_pic` 10곳, 하루 종료 18곳, 이벤트·결과 13곳이다. 별도 미리보기·직접 이벤트·메뉴·클릭·집 선행 조건도 `mods.json`에 포함한다. 성형의 복제 배열은 보존하고 실제 표시 시 새 알몸 등록과 옛 기본 등록을 조회한다.

이사벨라 공유 기본 주소는 알려진 문자열과 ID를 함께 확인한다. 2323은 전용 `2323_full_title`, 2571은 최신 `isabella_black_long`으로 읽는다. 같은 문자열을 쓰는 다른 ID와 임의 외형은 일괄 변환하지 않는다. 2571의 역할 그림은 기존 새 팩 우선순위를 따른다. 2323의 JSON·공유 PNG 반영은 루트 묶음 작업의 별도 편집이다.

## 검사와 한계

`resolver.test.cjs`의 42개와 `consumers.test.cjs`의 25개 검사는 실제 변경 QSP 코드를 WASM에서 실행한다. WASM에서는 진단용으로 FOR를 LOOP로 변환하고 FastQSP 파일 존재 한 문장만 명시적인 fixture 파일 지도 조회로 바꾼다. 따라서 이 결과를 실제 파일 존재 확장의 성공이라고 보고하지 않는다. 기본 회귀는 구현 전 11개 실패를 확인했고, 사용자 지정 외형 우선순위 회귀 2개도 수정 전 실패와 수정 후 통과를 확인했다.

`prepare-native.cjs`는 실제 FastQSP의 `%경로%` 문장을 그대로 둔 22개 격리 검사를 만든다. 진단에서만 콘텐츠 루트를 사례별 상대 폴더로 바꾼다. 최초 네이티브 시도는 진단용 절대 경로가 지원되지 않아 실패했다. 루트가 실행한 경로 진단에서 절대 경로는 0, 상대 경로는 1임을 확인해 fixture를 수정했다. 실제 코드의 상대 `content/pic/` 경로는 그대로이다.

루트가 확보한 순차 실행 구간에서 실제 WORK FastQSP `game/engine/jack.exe`로 resolver 22개와 `prepare-native-consumers.cjs`의 실제 출력·클릭 25개를 실행해 모두 완료 표식을 확인했다. 엔진 SHA-256은 `f75032d79ecb58eeb7b969cd3f774d66b091fca38a360acdabd782e03a46c6e6`이다. `native-verification.json`과 두 stderr 로그가 근거다. 소비 지점 검사는 변경된 `display_fullimage`, 실제 HTML 문자열에서 복원한 클릭 코드, 레지스트리·사용자 외형 불변, 함수 로컬 값 복원을 포함한다. 테스트하지 않은 모든 UI 분기가 자동 검증됐다는 뜻은 아니다.

파일 존재는 PNG 해독이나 화면 품질을 증명하지 않는다. 두 기본 그림까지 모두 없으면 조회 함수는 그림을 만들 수 없다. 기존 UI 세이브 불러오기와 실제 화면은 별도 확인 범위이다. 일반 EXE에서는 조수 외형 메뉴에서 구등록 전용·새등록 전용 복장, 흥분/반항 시 같은 복장 일반 그림 대체, 기존 사용자 외형 보존을 확인한다.

공통 조회를 제거하면 직접 출력 경로의 실재 파일 검사와 병행 등록이 사라진다. 메뉴·클릭만 남기면 새 복장을 선택해도 일부 화면에서 옛 경로를 직접 쓰는 불일치가 생긴다. 되돌리기는 `mods.json` 편집을 역순으로 적용하며 생성기가 원본 바이트 복원을 검증한다.
