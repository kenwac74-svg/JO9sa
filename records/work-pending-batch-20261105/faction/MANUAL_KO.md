## 동작과 부작용

`menu_form=2110`의 다음 페이지가 2111 세력 영향력 편집기로 이어진다. 2111은 네 가문 및 지역 평판을 읽어 화면 문자열을 만들며, 감소·증가·최대 버튼의 EXEC 코드가 평판을 바꾼 뒤 같은 페이지로 돌아온다. 네 가문의 일부 버튼은 `noble_status`도 바꾼다. 이 부작용은 첨부 원문대로 보존했다. 대립 가문 평판과 `npc_progress['pope']`가 증가 버튼 허용 여부에 쓰이며 `no_futa`가 후타랜드 행을 결정한다. 반환값은 없으며 표시용 `$setting_display`, `$setting_display_c`, `$setting_display_c2`와 임시 허용 변수를 갱신한다.

`main_screen`의 가드 세 곳은 설정·치트 범위를 2111까지 확장한다. 이 세 곳을 빼면 새 치트 화면에서 기존 일반 화면 버튼이 보일 수 있다. 2111을 제거하려면 진입 링크와 가드도 함께 검토해야 한다.

`#static_txt`는 기존 `$vb_cycle_skill`을 DYNEVAL로 호출해 평판별 색상과 안내를 만든다. 거주권 안내의 난이도 입력은 원문대로 생성 난이도 `game_difficulty`다. 화면 설정 난이도와 바꿔 쓰지 않는다. 홍등가·중앙 지구의 원문 오타 후보도 고치지 않았다.

`#static_base`의 S− 등급 안내에서 성애기술 합계 부족 기준을 23에서 25로 맞춘다. 실제 등급 판정이나 능력치는 바꾸지 않는다. `#options`의 두 번째 루미너스 구매 블록에서 활성·비활성 표시명만 `루미너스 ($2000)`로 고친다. 가격·구매 조건·호출 대상과 실제 츠키의 `$1250` 표시는 보존한다.

루미너스 이벤트의 `girls/full/Luminous.png`와 설정문은 이번 패치에서 건드리지 않았다. 사용자가 제작 중인 의상 그림은 별도 보류 사항이다.

## 검사와 한계

`prepare.cjs`는 기준 해시, 수정 전후 개수, 수정 범위, QSP 바이트 왕복, 역재생 바이트 일치, 줄·주석 경계를 확인하고 격리 후보와 패치를 만든다. WORK·저장소·Full에 쓰지 않는다. `static-report.json`은 이 정적 결과다.

`check.cjs`는 후보를 읽어 다음을 WASM으로 확인하고 `targeted-test-report.json`을 만든다.

- 2111 화면 224개 조건과 실제 렌더된 EXEC 버튼 456회: 평판·귀족 상태·복귀 페이지.
- 생성 난이도 3종, 평판 배열 192개: 원문 동적 색상 코드와 입주 안내 단계.
- 성애기술 합계 22~26의 S+ 안내, 세 UI 가드의 경계 60개. 총 2,981개 확인.

실제 GT 콜백을 보존한 native 진단은 40개 이하의 묶음으로 나눴다. 긴 GT 연쇄가 진단 엔진 스택 한도에 닿는 것을 피하기 위한 진단 분할이며 게임 코드는 바꾸지 않는다. 18개 진단 파일 모두 WASM에서 정확한 완료 마커까지 확인했다. 실제 FastQSP 실행은 이 하위 작업에서 하지 않았다.

상위 작업자는 `native/plan.json`을 기존 `tools/qa/run-client-smoke.ps1`로 다른 엔진 검사와 직렬로 실행할 수 있다. 이 검사는 해당 동적 코드의 경계 확인이며 전체 게임 문법·실제 세이브 GUI 불러오기·화면 배치의 인증이 아니다. 게임과 세이브는 수정하지 않는다.

일반 EXE 육안 확인 항목은 치트 다음 페이지의 세력 편집기 진입·복귀, 선택한 가문의 버튼/수치, 해당 구매 화면의 활성·비활성 루미너스 이름이다. 아직 실제 화면은 확인하지 않았다.

진단 완료 후 재생성 가능한 `candidate.qsp`와 `native/*.qsp`는 정리할 수 있다. 패치·보고서·두 재현 스크립트를 남기면 후보와 진단을 다시 만들 수 있다. 원본·세이브·직접 제작한 그림은 이 작업의 정리 대상이 아니다.
