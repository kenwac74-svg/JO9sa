## 계산과 입출력

`jo9_traits_value`에 다음 네 모드를 추가했다. 인수는 모드 이름과 최종 거래 총액이다. 모두 함수 로컬 변수로 계산하며 새 영구 세금 캐시를 만들지 않는다.

| 호출 | 반환 | 부작용 |
|---|---|---|
| `func(...,'sale_tax',gross)` | 정수 세액 | 없음 |
| `func(...,'sale_net',gross)` | 총액에서 세액을 뺀 금액 | 없음 |
| `$func(...,'sale_receipt',gross)` | 총액·세율·세금·실수령 HTML | 없음 |
| `$func(...,'sale_pay',gross)` | 같은 영수증 HTML | 지갑에 순액을 한 번 가산 |

`difficulty_setting = 2`일 때만 총액 6,000 이상은 5%, 10,000 이상은 10%를 거래가 전체에 적용한다. 세액은 QSP 정수 나눗셈으로 버린다. `game_difficulty`는 계산에 사용하지 않는다. 판매세가 실제로 0보다 클 때만 사용자가 요청한 악질적인 세금징수원 문구를 영수증 앞에 붙인다. 5,999→5,999 / 6,000→5,700 / 9,999→9,500 / 10,000→9,000의 경계 역전은 승인된 동작이다. 입력을 별도로 상한·하한 보정하지 않는다.

QSP의 `result`와 `$result`는 같은 결과 슬롯을 사용한다. 따라서 영수증 문자열을 만든 뒤 숫자 `result`를 지갑에 더하지 않고, 함수 로컬 총액에서 세액을 뺀 값을 지급한다. 이 동작은 실제 WASM 테스트로 확인했다.

## 위탁금과 기존 세이브

기존 `farid_debt`와 `farid_potential_debt`에는 거래별 총액 내역이 없다. 승인된 처리대로 새 위탁 건의 소유자 몫 `slaveprice / 2`에서 건별 세금을 계산한 순액을 `farid_potential_debt`에 저장한다. 기존 중개 수수료 계산은 보존한다. 위탁 첫 페이지에 그 건의 총액·판매세·예정 실수령과 내일 지급 안내를 함께 표시한다.

기존 미수금·기존 미결 위탁금은 저장된 금액 그대로 정산·회수한다. `collect`에서 합계에 새로 세금을 매기지 않으므로, 여러 거래 합산액에 잘못된 세율을 적용하거나 신구 금액에 이중 과세하지 않는다. 기존 세이브의 거래별 원총액을 복원했다고 주장하지 않는다.

`deposit` 성공 반환은 기존 숫자 1에서 영수증 문자열로 바뀌고, 단 하나의 실제 caller도 `$func`로 함께 바뀐다. 실패의 빈 문자열/문자열 `0`을 모두 거부한다. `copy`·`clear`·`return`·`settle`·`collect` 반환 규약은 유지한다. 새 저장 변수는 없다.
