# scene 등장 조건 메타데이터 갱신 후보

WORK QSP `5cbc0fbf858b8102bdc6afe8cdfeb2b07eacfe9329c3c5b1a7623c14ced4cf2e`를 읽어 scene 이미지 1,127개의 조건을 다시 분석했다. 직접 연결 726, 무작위 258, 동적 4, 전환용 9, 실행 연결 미확인 130개다. 파일목록 밖의 미해결 참조는 24건이다. 미확인은 삭제 가능 판정이 아니다.

`condition-block.html`이 실제 병합 대상이다. 상위 작업자는 최신 두 HTML의 `JO9_SCENE_CONDITIONS_START`부터 `JO9_SCENE_CONDITIONS_END`까지 한 블록만 이 내용으로 교체해야 한다. `conditions-only-catalog-0.html`과 `-1.html`은 스냅샷 대비 범위 증명용 후보이며 통째로 채택하면 안 된다. 캐릭터 체크리스트 블록의 동시 갱신을 덮어쓸 수 있다.

입력은 현재 WORK QSP·JSON·CSS·scene 파일목록과 기존 WORK/seed HTML이다. 분석기와 표시 JS의 정확 사본을 `sourcecopy/`에 보관했다. `prepare.cjs`는 격리 출력만 쓰며 게임 QSP·이미지·세이브·카탈로그 상태·태그·안정 ID·수동 이미지 조건 규칙을 쓰지 않는다. 표시 모듈과 분석기는 기존 `tools/text-workshop/core.cjs`, `scenes.cjs`를 읽는다. 이 결과를 제거하면 이번 조건표시 후보만 없어지며 게임 동작은 바뀌지 않는다.

WORK의 이전 조건 기준은 `c149e6b5…`, seed는 더 오래된 `86ee16ad…`였다. WORK는 정확 직전 QSP를 새로 분석해 작성자가 보완한 문구를 구분했다. seed는 저장된 참조에서 자동 요약을 다시 계산하고 고정 자동 안내문과 비교해 수동 설명을 구분한 뒤, 현재 소스의 참조·조건·행을 확인했다. summary 4개와 note 7개를 보존했다. 챔피언 해방 후 귀환/영구 이탈 안내와 생존 ELSE 분기 안내가 포함된다. 이전 자동 갱신에서 빠졌던 일반 승리 1294의 1·2페이지 동일 그림 안내는 10/31 기록과 현재 복사 대입문을 대조해 summary 2개·note 2개를 되살렸다. 상세 근거는 `manual-annotations.json`에 있다.

검사는 각 스냅샷과 후보의 조건 블록 밖 동일성, D행 리터럴 동일성, UTF-8 왕복과 모든 인라인 JS의 `new Function` 문법 파싱을 포함한다. WORK는 41,256행, seed는 41,255행이며 최종 스냅샷의 인라인은 양쪽 모두 11개다. 현재 서버의 첫 `</body>` 치환과 앞선 bridge 삽입을 재현한 뒤 각각 인라인 12개도 파싱했다. 준비 중 상위 작업의 girls 블록 갱신으로 seed 인라인 수가 9개에서 11개로 바뀌었으며 마지막 후보는 그 최신 스냅샷 기준이다. 두 후보 모두 리터럴 닫는 body 태그는 한 개이며, 다운로드 JS 문자열 안으로 주입되던 문제가 재발하지 않았다. 외부 브라우저 모듈 실행이나 실제 장면 플레이 검사는 아니다.

실제 설치는 하지 않았다. `verification.json`에는 각 후보의 전후 해시·블록 밖 해시·보호 파일 해시·검사 범위가 있다. 병합 뒤 최종 HTML에서 같은 블록과 최신 QSP 해시를 확인하면 이전 분석 경고를 제거할 수 있다. 재생성 가능한 전체 HTML 후보와 중복 metadata JSON은 상위 병합·검증 후 정리할 수 있으며, 재현 스크립트와 검증·수동 설명 기록은 남긴다.
