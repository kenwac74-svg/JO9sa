# 웡 조합 항의 이벤트 실제 엔진 검증

2026-10-30, 현재 WORK FastQSP의 실제 HTML 렌더러에서 두 격리 사례를 실행했다. 제품 QSP·기존 세이브·저장값은 변경하지 않았다.

원본 첫 22줄의 레이아웃 초기화와 `$text` 초기화를 실제로 실행한 뒤, 무관한 앞선 일일 이벤트만 건너뛰고 웡 분기로 진입했다. 웡 분기·공통 `loop`·footer는 원본 흐름으로 실행했다. 후보만 웡 분기의 `jump 'loop'` 직전에 `$text = $text[1] + '<br><br>' + $text[2]` 한 줄을 추가했다. footer 뒤에 추가한 DOM 관찰기가 실제 `#text.textContent`와 정보창·크기를 읽고, native EXEC/msg를 통해 상태를 출력했다. OS 마우스 입력은 사용하지 않았다.

이 후보는 원인 확인용이며 최종 수정 설계나 WORK 적용을 뜻하지 않는다. 일반 질병 1건 사례는 두 문단이 185px에 들어갔지만 유충·중복 감염·재경고 등 더 긴 다른 대사의 여유 공간과 페이지 설계는 검증하지 않았다. 다음 화살표 클릭도 이번 두 사례의 범위에는 없다.

Qt가 EXEC 링크의 `|`를 `%7C`로 바꾸므로 첫 runner 기록은 판정식에서 실패했으나 두 native 완료 메시지를 이미 확보했다. `analyze-results.cjs`가 원시 로그를 URL 디코딩하고 같은 기대값을 재검사한 결과는 둘 다 통과했다. 보존한 runner도 동일하게 디코딩하도록 보정했다. 새 엔진 실행이나 정적 분석으로 결과를 대체하지 않았다.

원본 SHA-256은 `results.json`의 before/after에 기록했다. 생성된 진단 QSP 두 개 합계 165,572,370바이트와 임시 실행 폴더를 정리했다. `content`·`json` 정션은 정확한 대상 확인 후 비재귀 제거했으며, WORK 실물 리소스와 세이브를 보존했다. 엔진이 만든 임시 `save` 디렉터리는 비어 있었다. 재현 스크립트·결과·원시 stderr·정리 로그만 이 폴더에 남겼다.

재현: `node native-audit.cjs --run` (G:/Codex/tmp 생성과 숨김 엔진 실행 권한 필요). 실행 후 `cleanup-diagnostics.ps1`로 전용 임시 폴더를 정리한다.
