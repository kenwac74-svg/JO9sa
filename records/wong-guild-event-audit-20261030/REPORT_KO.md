# 웡 방문·조합 평판 하락·하단 대사 공백 검사

검사일: 2026-10-30. WORK QSP 기준: 1e8e489eb4a2c6412f81af0e50b69d409bc9ffd5d5edb69e2308cd3e9f71bc7c.

## 확인된 원인

제보 화면과 일치하는 것은 하루 종료 시 웡이 감염된 노예의 인도를 항의하는 이벤트다. 조합 의뢰 납품 두 경로 및 웡의 일반 재매입 처리에서 질병·기생체 변수가 양수이면 후속 방문이 예약된다. 보관 JO9O 비교본의 옛 웡 재매입 확인 처리에도 같은 예약 코드가 있으므로, 새 재매입 기능이 추가한 제재라고 판단하지 않는다.

이벤트가 실행되면 평판 제재는 적용되지만 설명은 비어 있는 문제가 있다. `end_day_screen` 진입부가 `$text` 배열을 지우고, 웡은 `$text[1]`과 `[2]`만 채우는 반면 공통 화면은 0번인 `$text`를 출력한다. 이어 화면 끝에서 `$text[2]='   '`로 실제 항의 대사까지 덮어쓴다. NPC 이름·전신·정보는 별도 출력이라 제보처럼 웡과 우측 정보만 보이고 하단만 공백이 된다. 화살표로 재진입해도 배열을 다시 지우고 처리 완료된 웡 이벤트를 건너뛰므로 누락된 설명을 읽을 수 없다.

보관 JO9O 비교본에도 동일한 배열·출력 구조가 있다. 현재의 글꼴·이미지 교체가 만든 문제라는 근거는 없다. 이 비교는 제공된 보관본에 대한 것이며 모든 공식 과거 배포본의 상태를 입증하지는 않는다.

## 평판과 재발 조건

- 진파랑 조합 계급은 평판 원점수 30~59, 보라는 15~29다. 질병 한 건의 제재 10으로 30→20이면 제보한 색상 변화가 그대로 가능하다. 하늘파랑 계급은 60~119이며 유충 제재 등은 더 크다.
- 원본 후속 제재와 현재의 제어·계산은 일치한다. 질병은 건수에 따라 10씩, 기생체만이면 최대 80, 두 카운터가 같은 양수이면 최대 90을 차감하며 현재 원점수보다 더 내려가지 않는다. 방문 뒤 두 감염 카운터는 0, 당일 방문 완료 표시는 1이 된다.
- 평판이 특정 색상이 되었다는 조건만으로 다시 방문하는 코드는 없다. 새 납품·재매입 없이 다음날 자동으로 두 카운터를 다시 세우는 경로도 전수 참조에서 발견되지 않았다. 따라서 거래 없이 매일 반복된다는 별도 문제는 제보 세이브 없이 확정하지 않는다.
- 질병 진행값 `ill`과 기생체 `parasite`는 체력과 별개다. 초기 질병은 진단 능력·도구 조건을 충족하지 않으면 아이콘이 보이지 않을 수 있으므로, 체력이 좋고 질병 표시가 없다는 사실만으로 거래 당시 두 값이 0이었다고 판단할 수 없다.

## 실행 검증

`native/`의 재현 스크립트·결과·원시 로그를 근거로 실제 FastQSP 엔진의 격리 복사본을 비교했다. 앞선 무관한 일일 이벤트는 진단용 시작점에서 건너뛰지만, 웡 이벤트 본문과 공통 출력·마무리 코드는 그대로 실행한다. 질병 카운터 1, 기생체 0, 평판 원점수 50 조건이다.

- 현재 코드: 웡 NPC가 표시되고 하단 DOM 글자 수는 0이다. 제재 뒤 원점수는 40, 두 감염 카운터는 0, 당일 방문 완료 표시는 1이다.
- 임시 비교 후보: 웡 이벤트의 대사만 출력용 0번 문자열로 합친 경우 같은 제재·카운터 결과를 유지하면서 하단 글자 수 129가 나온다. 이 짧은 질병 한 건의 경우 패널 높이 185px 안에 들어간다.

후보는 원인 확인용이며 WORK 수정본이 아니다. 더 긴 기생체 항의, 반복 경고의 게임오버, 바로 뒤 동일 구조인 안젤리카 항의는 최종 수정 전에 별도 범위를 정하고 검증해야 한다. 특히 현재 게임오버 분기는 사유를 3번에 쓰면서 0번을 전달하는 추가 점검 후보가 있다. 전역 CSS나 공통 화살표 동작을 변경할 근거는 찾지 못했다.

## 상태와 남은 작업

확정된 수정 대상은 설명 대사가 사라지는 원본 구조다. 권장 범위는 이 항의 이벤트의 대사를 기존 일일 화면 출력 규칙에 맞게 복구하고 제재 수치·발생 조건은 유지하는 것이다. 거래 없이 매일 재발한다는 주장은 원인 플래그가 다시 세워지는 실제 상태를 추가 확보해야 한다.

이번 작업은 검사와 격리 후보 비교이며 WORK·QSP·기존 세이브·CSS는 수정하지 않았다. 배포 폴더·ZIP·커밋·푸시도 변경하지 않았다. 재생성 가능한 진단 QSP와 임시 리소스 연결은 검사 후 정리하고 재현 스크립트·결과·로그만 보존한다.
