# 캣파이트 패배·관람 컷신 및 치명상 복귀 수정

사용자 제공 PNG 세 장을 content/pic/scene/catfight_loss_death.png, catfight_loss_survive.png, catfight_watch.png로 등록했다. 세 원본 모두 이미 RGB·795×596이므로 재생성·크롭·축소 없이 바이트 그대로 WORK, Full, resources/new에 복사했다. modworkpic의 사용자 원본을 옮기거나 덮어쓰지 않았다.

interaction_city의 양쪽 주인공 분기에서 103002(치명상 사망), 103003(상대의 처형)은 사망 컷신과 공통 사망 대사, 103004(상대의 자비로 생존)는 후송 컷신과 생존 대사로 연결했다. 실제 소비 필드인 $special_image_full[1]도 설정한다. 이름이 지워지는 killslave보다 먼저 대사를 확정한다. 기존 벌금300·사망 제거·생존 효과·결과 복귀는 유지한다. 관람102019는 첨부 대사가 있는 두 번째 페이지의 full[2]에만 관람 컷을 넣고 첫 페이지와 두 페이지 구성을 보존한다.

выход_из_боя의 Start1 패배 조건에 убит를 포함했다. 원래 캣파이트는 치명상을 버틴 노예가 도주/기절 처리에 들어가지 못해 공통 주인공 사망까지 떨어졌다. 같은 파일의 콜로세움과 동일하게 기존 노예 사망·상대 처형·생존 규칙으로 이어지게 했다. 일반 주인공 전투의 사망 처리는 수정하지 않았다. 새 저장 변수·로케이션·세이브 이관은 없다.

WORK와 Full은 기존 jo9_liquidation 내용이 달라 각 파일을 독립 백업하고 같은 수정만 각각 적용했다. 관련 없는 정산 차이는 보존한다. WORK patch는 mods/2026-10-31_catfight_loss_watch_cuts.json, Full의 독립 적용 명세는 이 폴더의 full-install-mod.json이다. 단일 QSP 전체를 서로 덮어쓰지 않았다.

검사: 변경 전 실제 PNG 누락을 세 화면에서 재현했다. 변경 후 WORK 후보10개·Full 후보3개에서 실제 패배 정산을 거쳐 PNG795×596, 대사와 노예 이름, 사망시 제거1회, 생존시 보유, 벌금1회, 관람 두 페이지 및 재표시를 확인했다. 기존 승리의 처형/생존 PNG와100상금도 통과했다. 총29회 화면 렌더링이다. 진단에만 계측을 붙였고 자동 저장은 껐다. 사람의 현재 게임 창이나 기존 개인 SAV를 조작한 검사는 아니다.

최초 진단 스크립트의 문자열 검사에 QSP 치환 시작 기호가 들어가 실행을 막아 이를 문자열 코드값으로 바꿨다. 초기 페이지 검사는 txt_count가 즉시1이라는 잘못된 가정이었다. 기존 결과는 다음 버튼에서 텍스트 배열로 페이지 수를 계산하므로 arrsize($text) 기준으로 검사만 수정했다. 게임 페이지 코드는 바꾸지 않았고 초기 실패 보고서도 보존했다.

공식 출고 검사: 각 빌드에서 구조·줄바꿈·주석 경계·JSON 등록·패치 재생·재적용 및 실제 엔진9경로 PASS. Full은 전용 후보와 실제 배포 QSP 일치도 확인했다. 기존 TC SAV7개 해시 유지. 게임 재실행 후 새로 진입하는 결과에 적용되며, 과거 결과 화면을 통째로 저장한 SAV의 캐시를 재정산하여 강제로 고치지 않는다.

의존성: 기존 interaction_screen_city와 페이지별 그림 배열, killslave, 도시 메뉴 복귀를 재사용한다. 연결을 제거하면 공용 클럽 배경으로 돌아가고, 치명상 조건 보강을 제거하면 주인공 게임오버 버그가 재발한다. 복구는 verification.json의 외부 backup 경로를 사용한다. 이미지 목록과 등장 조건은 별도 catalog 기록에 갱신한다. ZIP·커밋·푸시·세이브 호환툴 제작·UI 폴더 이동은 하지 않았다.
