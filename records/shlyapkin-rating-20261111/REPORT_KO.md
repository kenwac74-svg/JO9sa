# 슐랴프킨 납품 등급 오판 수정 — 2026-11-11

사용자 승인: “버그네, 수정해”. 현재 WORK를 다시 읽고 `interaction_city = 10372`에서 캐롤라인의 납품 등급을 판정 직전에 새로 계산하도록 수정했다. 조수 없는 방문을 새 조건으로 추가하지 않았다. 목표 목록·납품 능력치·낙인·캐롤라인 번호·보상·완료 분기는 유지했다.

## 원인과 수정

`sjm_UI_UIadds`는 동행 노예 등급을 계산한 다음 조수 등급을 계산하며 공용 `rating`을 덮어쓴다. 기존 슐랴프킨 분기는 이를 다시 계산하지 않은 채 `rating > 6`을 검사했다. 이 때문에 낮은 등급 조수를 두면 준비된 캐롤라인도 거절하고, 높은 등급 조수는 캐롤라인의 부족한 종합 등급을 가릴 수 있었다.

`SHLYAPKIN_TARGET_RATING_20261111` 블록을 기존 납품 조건 바로 앞에 추가했다. 캐롤라인(2613)이 정상 동행 중일 때 `gs '$slave_price', 'slave'`를 호출한다. 실제 가격·등급 산식은 변경하지 않았다.

## 검증과 한계

- 수정 전 실제 FastQSP 격리 실행에서 캐롤라인 A/S·낮은 등급 조수의 실패와 캐롤라인 B+·높은 등급 조수의 잘못된 통과를 확인했다.
- 수정 후 468조합 통과: 조수 없음/등급0~10, 캐롤라인 B+/A-/S+, 정상 또는12개 납품 조건 미충족. 원래 판정 블록을 추출해 실행했다. 등급 계산 호출부는 진단용 대역으로 주어진 캐롤라인 등급을 공급하고 호출 대상이 `slave`인지 검사했다. 실제 등급 산식을 이 시험에서 전부 재검증한 것은 아니다.
- 공식 `apply_mods.ps1` 재생 결과와 후보 해시가 동일하며, WORK 적용 뒤 재적용은 무변경이다. QSP 왕복·구조·줄/주석 경계 검사 통과. 바뀐 location은 `interaction_city` 하나이며 납품 직전 호출만 추가했다.
- WORK·추적 QSP·런타임 원장을 맞췄다. 전후 해시는 `verification.json`, 실패/통과 근거는 `native-before.json`/`native-after.json`과 로그에 있다.
- 기존 게임 창을 조작하거나 실제 사용자 세이브로 납품하지 않았다. 게임 재실행 후 기존 세이브에서 조건을 갖춘 캐롤라인과 낮은 등급 조수를 두고 슐랴프킨에게 납품해 확인할 수 있다.

## 사용·입출력·유지보수

별도 사용법이나 세이브 변환은 없다. 입력은 기존 `slave_type`, `slave_state`, `slave` 속성들과 기존 등급 계산 정의다. 캐롤라인 동행 시 현재 캐롤라인의 `rating` 및 기존 가격 계산 관련 파생 값을 갱신한다. 이후 기존 조건이 성공/실패 분기를 결정하며 보상·노예 소유권 처리 자체는 원래 분기를 그대로 사용한다. 새 지속 변수·저장 형식·조건은 추가하지 않았다.

의존성은 기존 `$slave_price`, `$update_slave_price`, `jo9_traits_value`다. 패치 제거 시 다시 직전 화면이 남긴 공용 등급에 의존하게 된다. 삭제하려면 mods 기록의 새 블록만 역치환하고 현재 WORK의 이후 변경과 대조해야 한다. 전체 QSP를 옛 백업으로 덮어쓰면 이후 편집을 잃으므로 피한다.

변경 전 압축 QSP와 원장은 `prepared.json`의 `backup`에 보존했다. `task.cjs`는 이번 변경의 준비·격리 검사 생성·설치·검증 재현 기록이며 재설치는 입력/기설치 확인에서 멈춘다. 재생성 가능한 격리 QSP·설정·중복 백업은 검사 후 정리했다. Full·음원·세이브·커밋·푸시는 변경하지 않았다.
