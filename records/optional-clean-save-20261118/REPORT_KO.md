# 선택형 클린 세이브 — 2026-11-18

일반 저장과 자동저장은 대사 캐시를 유지한다. 버전 이동 전후에는 **설정 → 자동 저장 설정 → 클린 세이브 만들기**를 사용하여 정리된 상태를 새 이름으로 저장한다. 집 설정은 `menu_form=2000`, 도시 설정은 `city_form=1000`이며 실제 렌더러 `main_screen`/`city_screen`에서도 조건을 확인했다.

클린 버튼은 메모리의 재생성 가능한 조회 캐시를 제외하고 기존 `SAVEGAME` 파일 선택창을 연다. 사용자가 새 이름을 지정한다. 기존 파일을 자동 덮어쓰지 않는다. 취소하면 파일이 만들어지지 않으며 진행은 유지되지만 캐시만 비워져 이후 첫 대화에 재생성 비용이 생길 수 있다.

## 동작과 지원 범위

일반 로드/저장에서는 확인된 오래된 임시 목록만 정리하고 큰 대사 캐시15종은 유지한다. 명시적 클린에서만 조회 캐시와 `voice_fragment_revision`을 비운다. 중앙 선택 함수의 지연 재생성이 확인되지 않는 오래된/사용자 정의 함수이면 큰 캐시를 유지하고 안내한다. 실제 대사 원문·분기 조건·수치는 변경하지 않았다.

클린 파일의 첫 대화는 현재 QSP의 조회 은행을 준비한다. 설치 엔진에서9,120행 재생성은 약4.7초였다(25ms 로그 관측, 시작 로딩 제외). 일반 저장마다 이 지연이 반복되지 않는다. 전투·이벤트의 결과 화면과 미완료 선택 캐시는 삭제하지 않으며 전투/튜토리얼 중에는 클린 저장 진입을 거절한다.

기존 `$ongload → jo9_load_compat242` 자동 보정은 유지한다. 이 기능은 버전별 호환 보정을 위한 작은 저장을 만드는 기능이며 모든 버전의 문제를 일괄 해결하는 기능은 아니다. 현재2.4.1 전투 밖 일반 화면 저장 지원을 유지한다. 이후 버전에서 영구 필드가 바뀌면 해당 이관 코드와 실제 로드 검증을 추가해야 한다. 엔진이 읽을 수 없는 형식이나 손상 파일은 별도 대상이다.

## 입력·저장·의존성

`jo9_save_maintenance`는 `install`(등록), `load`(일반 호환 정리), 기본 호출(저장 콜백), `clean`(명시적 정리), `clean_link`/`can_clean`/`make_clean`(설정 UI)을 제공한다. 정리 버전 정수 `jo9_save_clean_revision` 하나를 추가한다. 기존 저장 콜백은 `$jo9_previous_save_hook`에 보존하며 자기 해제·교체도 존중한다. 작업 배열과 인덱스는 LOCAL이다.

QSP 저장 전 콜백은 실제 파일 생성 전 실행된다. [QSP 공식 문서](https://dev.qsp.org/docs/language/qsp-keywords/qsp-keywords-sys-var/#ongsave)와 현재 설치 엔진의 독립 실험으로 순서를 확인했다.

삭제 허용 목록은 `scope/whitelist.json`에 있다. 인물·육성·재산·장비·관계·진행·전리품·화면·선택지·지연 콜백·배경 분류·seed 등록표는 제외한다. `$meal_id`는 현재76개 ID가 전체에서 정확히 반복되고 숫자 칸이0일 때만 첫76개를 남긴다. 사용자 정의·다른 버전 목록은 유지한다. `$masters_vars` 복수형은 읽는 곳이 없는 누적 목록으로 확인했으며 실제 `$master_vars` 단수형은 유지한다.

`#txt_man` 일반 갱신은 감정63행/분기17+17행만 준비한다. 전용 데이터 진입은 기존 상수 전체를 그대로 준비한다. `#dynamic`의 중앙 picker와 예상 원형이 확인된 기존 저장 picker에 준비 경로를 추가했다. 대사 상수의 값·순서는 보존한다.

제거 시 정적 등록·로드 호출·집/도시 설정 링크·새 로케이션을 함께 제거하고 `$ongsave`를 이전 콜백으로 돌려야 한다. 캐시가 없는 저장을 계속 지원하려면 picker 지연 재생성을 유지해야 한다. 호출이나 로케이션만 단독으로 제거하면 저장/로드 오류가 생길 수 있다.

## 확인 결과

- 원본 bds의 격리 사본49,657,046→26,086,400바이트(47.47% 축소). 허용한 캐시·중복 임시 목록 외의9,832개 변수 레코드와 헤더/행동/오브젝트는 일치한다. 사용자 원본은 변경하지 않았다.
- 네이티브35조건: 실제 일반 저장에는 캐시9,120행/조회69,717행이 남고 클린 저장에는 캐시 값·키가 없다. 나머지38개 진단 변수 레코드는 슬롯·인덱스까지 동일했다(테스트용 콜백 횟수 제외). 첫 대화 재생성, 문장·선택·전리품·육성 보존, 집/도시 설정 허용과 전투 차단을 확인했다.
- 추가 네이티브4조건으로 콜백의1회 실행·자기 해제·교체를 확인했다. 해당 보완만 집중 검사하여 나머지35조건을 반복하지 않았다. WASM 데이터/선택기6조건과 관리 함수7조건도 통과했다.
- 수정 대상의 공식 패치 재생·멱등성·역적용, 기존314개 본문과 모든 설명·기본 행동의 보존을 확인했다. 다른 원고의 기존 lone-LF10건은 유지했으며 전체 출고 PASS를 주장하지 않는다.

실제 GUI 저장 대화상자 조작과 게임 로딩 시간은 미검증이다. OPENGAME 자동 진단은 플레이어가 SAV를 게임 문서로 여는 경로에 걸려 실패했고 그25초를 성능 결과로 쓰지 않았다. 파일 축소율과 은행 재생성 비용만 측정값이다.

일반 EXE 확인: 완전히 종료·재실행한 뒤 설정에 **클린 세이브 만들기**가 보이는지, 새 이름으로 저장한 파일을 다시 불러 첫 대화가 정상인지 확인한다.

WORK·추적 소스만 갱신한다. 작업 중 `interaction_city` 수동 편집은 보존했다. Full·기존 ZIP·이미지·음원·개인 SAV·커밋·푸시는 변경하지 않는다.
