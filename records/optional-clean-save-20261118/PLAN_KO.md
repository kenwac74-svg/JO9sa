# 선택형 클린 세이브 · 호환 갱신과 저장 부하 관리

사용자 최종 결정: 평소 저장은 대사 캐시를 유지하고 버전 이동 때 별도 클린 세이브를 만든다. 기존 세이브·사용자 원고·진행·육성·장비·재산·관계·전투 결과·미완료 선택을 보존한다.

## 확인한 원인과 구현

대표 파일의 23,531,038바이트는 현재 QSP로 재생성 가능한 공용 대사 조회 캐시다. 캐시 행과 중복 인덱스는 실제로 사용하므로 무작정 중복 삭제하지 않는다. 명시적 클린 세이브에서만 이 캐시를 제외하고 첫 대화에서 재생성한다. 일반 저장·자동저장·일반 로드는 큰 캐시를 유지한다. 클린 버튼은 기존 저장 대화상자를 열며 사용자가 새 이름으로 저장한다.

현재 실행 파일에서 `$ONGSAVE`가 저장 직전에 실행됨을 독립 진단과 생성된 임시 세이브로 확인했다. 자동 관리 로케이션 한 개를 추가한다. 직접 파일을 덮어쓰거나 사용자 세이브를 일괄 변환하지 않는다. 정상 저장을 통해 정리된 메모리 상태가 파일에 남는다.

정리 대상은 출처를 확인한 정확한 변수명 15개와 캐시 판본 하나, 참조가 없는 복수형 `$masters_vars`, 현재 식사 ID 76개의 정확한 반복으로 판정된 `$meal_id`뿐이다. 이름의 일부가 같다는 이유로 다른 변수를 삭제하지 않는다. 상세 분류·배경·진행 데이터, 전리품·생사 선택·결과 화면 캐시와 seed 등록표는 제외한다.

중앙 대사 선택 함수에 지연 재생성 경로가 확인된 경우에만 큰 캐시를 제외한다. 저장된 함수가 예상 원형이 아니면 캐시를 유지한다. 기존 저장 콜백이 있으면 보존하고 먼저 실행한다. 추가 영구값은 정리 판본 정수 `jo9_save_clean_revision` 하나이며, 기존 별도 저장 콜백이 있을 때에만 그 주소 문자열을 보관한다.

기존 이름·이미지 경로·특성 등 호환 갱신 함수는 그대로 호출한다. 큰 캐시가 구버전 저장에서 왔더라도 새 판본의 대사 원문으로 다시 준비한다. 캐시를 삭제한 뒤에도 현재 표시 문장·이미지·선택지는 그대로다.

## 작업

- [x] 대표 세이브 3개를 읽기 전용으로 측정하고 중복/캐시/진행 데이터를 분리한다.
- [x] 저장 직전 콜백의 실제 엔진 동작을 확인한다.
- [x] 원본 bds 사본의 캐시 제외 실험과 나머지 상태의 엄격 동일 비교를 한다.
- [x] 일반 텍스트 갱신과 중앙 대사 선택의 지연 로딩 후보를 검사한다.
- [x] 자동 관리 함수의 보존·미지 지원·중복 임시 목록 정리를 검사한다.
- [x] 합친 QSP의 실제 엔진 저장·대화 복원·중복 호출 및 설정 화면 조건35건과 콜백 보존4건을 확인한다.
- [x] 저장 파일 분량을 비교하고 실제 플레이어 로딩 시간 미검증을 구분한다. 재생성 비용 약4.7초 때문에 기본 저장 캐시는 유지한다.
- [x] 최신 WORK 재대조 후 WORK·추적 소스만 적용하고 인계·재현·복구 기록을 남긴다.
- [x] 검증을 끝낸 임시 QSP·SAVE 사본을 정리한다. 사용자 원본은 유지한다.

## 현재 측정의 한계

Node 읽기/파싱 시간은 실제 플레이어 로딩 시간이 아니다. 현재 플레이어의 `OPENGAME`을 통한 자동 진단은 SAV를 게임 문서로 여는 경로에 걸려 실패했으므로 그 시간을 로딩 결과로 쓰지 않는다. 별도 GUI 확인이 없으면 실제 플레이어 로드 속도는 미검증으로 남긴다. 첫 구버전 파일의 읽기 단계는 이미 큰 파일을 읽은 뒤에 정리하므로 단축을 보장하지 않는다. 다음 저장부터 파일 분량과 처리할 데이터가 줄어드는 방식이다.
