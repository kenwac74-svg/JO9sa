# 안개 괴물 성장단계 이미지 경로 감사

성장기·보통·거대는 서로 다른 MOB ID와 능력치이지만, 실제 전신과 아바타 경로가 모두 같다. 현재 외형 동일 현상의 직접 원인은 이 공용 경로다. 캐시나 단계 선택 오류를 추측하지 않아도 코드로 확인된다.

읽은 WORK 스냅샷 SHA-256: `a5f9dcb31acac6160836d0f420a1ef0d697bf1e259619be4187ef8e5b1a829cc`. 아래 줄은 해독한 로케이션 본문 내부 번호다. 게임/소스/이미지는 수정하지 않았다.

| 단계 | MOB ID | #противники 전신/아바타 줄 | 체력/지구력/정신력/피해 | 실제 전신·아바타 |
|---|---|---|---|---|
| 성장기 | исчадие_молодь | 984/983 | 70/60/90/9 | spawn.png / spawn_ava.png |
| 보통/성숙 | исчадие | 1051/1050 | 120/120/160/15 | spawn.png / spawn_ava.png |
| 거대 | чудовщиное_исчадие | 1136/1135 | 200/300/300/20 | spawn.png / spawn_ava.png |

전투 진입은 `interaction_city` 61101/61102/61103에서 각 ID를 정확히 배정한다(L10937/10947/10967). `начать_бой` L121이 `#противники`를 새로 읽는다. 전투 전신은 `боевой_интерфейс` L126, 아바타는 L237이 각 MOB 사전값을 그대로 출력한다.

승리 결과는 `конец_боя` L80–99에서 `jo9_battle_fate sprite`를 호출한다. 그 함수 L67은 공용 spawn.png를 defeated/spawn.png로 보낸다. 따라서 패배 그림도 세 단계가 같다. 새로운 전신 경로만 추가하고 패배 매핑을 안 넣으면 L36 기본값에 따라 결과에도 전신이 그대로 나온다. 파일 로드 오류 때는 결과 img의 data-standing 경로로 되돌아간다.

아레나 `исчадие_арены`는 전신 gladiator_spawn.png(L3215), 패배 defeated/gladiator_spawn.png(sprite L75)로 이미 독립이다. 다만 아바타(L3214)는 spawn_ava.png를 공유한다. `trophy_room`도 거대 L12, 성숙 L14, 어린 L22, 아레나 L36에서 모두 spawn_ava.png를 직접 쓴다. 사전 경로 수정은 이 전리품실의 직접 파일명에 반영되지 않는다.

최소 수정은 성장기·거대의 고유 전신/아바타를 배정하고 대응 패배 매핑을 추가하는 것이다. 보통의 기존 spawn.png/spawn_ava.png와 아레나 전신/패배는 유지할 수 있다. 전리품실도 단계별로 보이게 할 범위라면 성장기·거대 두 직접 경로를 같이 바꾼다. 신규 MOB ID·성장 상태 변수·능력치 변경은 이 문제에 필요하지 않다. 최종 파일명·원화는 루트 구현 담당이 결정한다.

저장에는 사전 배열과 이미 그려진 HTML이 남을 수 있다. `$ongload` L115의 saved_game_loaded=1 → 다음 `$newloc` L111–113 → `$addon` L7–11 → `refresh_database` L46 → `#противники` 순서로 정의가 갱신된다. 새 전투도 별도로 다시 읽는다. 하지만 $ongload에는 일반 전투/결과 페이지 즉시 재렌더가 없어, 로드 직후 정지 화면의 옛 HTML은 별도 확인 대상이다.

이미지 갱신을 위해 무조건 `gt 'конец_боя'`를 호출하면 안 된다. 이 위치는 L2 결과 처리, L11 안개 핸드오프, L15 아레나 초기화, L18 갑옷 해제를 다시 실행한다. 전투 UI도 다중 상대의 로그를 자르는 등 순수한 무상태 출력 함수가 아니다. 즉시 저장 화면 갱신까지 구현할 경우 전투 진행/보상/장비 처리를 재실행하지 않는 좁은 변경과 검증이 필요하다.

권장 검증은 다음과 같다.

1. 3단계의 전신/아바타 경로와 실파일 존재를 확인한다.
2. 격리 엔진에서 `gs '#противники'` 후 3단계+아레나 ID 각각에 대해 `$func('jo9_battle_fate','sprite',1,0)` 및 마지막 인자 1의 반환값 8개를 비교한다.
3. 전투 전신·아바타·전리품실 HTML src와 패배 이미지 fallback 경로를 확인한다.
4. 구 경로를 캐시한 격리 세이브를 로드해 갱신 뒤 경로를 확인하고, HP/지구력/정신력·현재 적·턴·승패/보상/장비 상태가 보존되는지 비교한다.
5. 루트 구현 후 구조·주석 경계·mods 재생·출고 검사를 실행한다. 실제 플레이 화면 검증과 도우미 경로 검증은 구분한다.

이 감사는 정적 코드 조사이며 엔진/세이브/화면 검증을 실행하지 않았다. 세부 근거와 테스트 입력은 code-audit.json에 있다.
