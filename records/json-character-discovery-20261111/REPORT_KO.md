# 캐릭터 JSON 전체 감지와 사운드 목록 제공 (2026-11-11)

사용자 요청: 사운드 목록은 파일을 자동으로 열지 않고 목록만 제공한다. 신규 캐릭터는 번호와 상관없이 JSON을 감지하면 리스트에 표시한다. 번호 없는 캐릭터도 지원한다.

## 원인과 수정 결과

기존 노예 이미지 목록은 2026-11-05 스냅샷의 1,155명 ID만 서버에 요청했고, 응답도 기존 ID가 있을 때만 갱신했다. WORK의 3040_chunhyang.json과 PNG 8개는 존재했지만 목록에 추가되지 않았다. 상태 서버도 HTML에 등록된 숫자 ID만 허용했다.

목록을 열거나 **WORK 이미지 상태 새로고침**을 누르면 현재 game/json/slaves의 정상 객체 JSON 전체를 읽는다. 파일명 번호·번호 범위 제한은 없으며 .JSON도 포함한다. 고유 숫자 접두는 기존 숫자 식별자를 유지하고 번호가 없거나 숫자 접두가 겹치면 json:<실제 파일명.json>으로 구분한다. 화면은 번호가 없으면 '번호 없음 · 이름'과 JSON 경로를 표시한다. seed_name이 없으면 파일명을 사용한다. 잘못된 JSON은 오류 건수로 알리고 나머지를 계속 읽는다. 외부 링크는 따라 편집하지 않는다.

검색은 기존처럼 **검색 버튼**을 눌러 실행한다. 이름·파일명·등록 경로로 찾을 수 있다. 신규/번호 없는 항목도 태그·파일 선택 연결·초상 테두리를 사용한다. 기존 메모·이름별 장면·호환 사본 기록은 유지한다. 숫자가 없는 항목에 가짜 번호 폴더나 행동 컷 경로를 만들지 않는다.

숫자 접두가 중복되는 파일이 나중에 추가되면 같은 JSON의 기존 카드를 파일 식별자로 갱신하여 유령 카드가 남지 않는다. 이전 숫자 태그는 원본 상태 데이터에서 보존하며 원래 JSON을 확인할 수 있는 카드에 '이전 번호 상태(보관)'으로 안내한다. 새 파일에 자동 배정하거나 삭제하지 않는다. 오래된 원장에도 대응 JSON이 없는 신규 번호가 이후 중복이 되고 페이지를 완전히 다시 열면, 이전 숫자 태그의 출처를 확정할 수 없어 원본 데이터에만 남긴다. 해당 상태를 임의로 한 파일에 붙이는 자동 마이그레이션은 추가하지 않았다. 현재 세션과 HTML 내보내기는 대응 이력을 보존한다.

**현재 목록 HTML 저장**은 그 시점의 현재 목록과 상태를 저장한다. 예전에 저장한 단독 HTML은 저장 시점 자료이며 스스로 로컬 폴더를 감시하지 않는다. 온라인 목록에서 다시 읽고 내보내면 신규 항목을 포함한다. 오프라인 생성기 build_inventory.py도 같은 JSON 탐지/식별 기준으로 수정했다. 기존 WORK 카탈로그의 조건 분석·사용자 상태·원장 스냅샷은 덮어 재분석하지 않았고 UI 스크립트 블록만 교체했다.
