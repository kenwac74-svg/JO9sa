# 이미지 공유·분리 — 2026-11-17

통합 캐릭터 편집기의 외형 탭과 이미지 패치리스트의 노예 이미지 카드가 같은 이미지 연결 판정을 사용한다. 2608 마르셀리나에는 2580이 사용하는 알몸 고정·타이틀·하녀·비서·도미나 경로 5개를 보완했다. 원래 능력치·배경·대사·PNG는 그대로다.

## 조작

1. 캐릭터의 **이미지 공유·분리**에서 함께 쓸 다른 번호를 체크한다. 체크만으로 저장되지 않는다.
2. **미리보기**에서 영향 번호, 변경 JSON 항목, 복사할 PNG 수·용량을 확인한다.
3. **공유·분리 적용**을 누른다. 체크한 번호는 현재 캐릭터의 이미지 구성을 기준으로 공유한다. 해제한 번호와는 현재 외형을 유지하면서 분리한다.

공유 해제는 서로 쓰던 PNG만 번호가 붙은 독립 경로로 복사하고 JSON을 연결한다. 원본 PNG는 지우거나 덮어쓰지 않는다. 따라서 분리 후 한쪽 그림을 교체해도 다른 쪽 그림은 바뀌지 않는다. 같은 기본 PNG를 쓰는 번호와 이전 공유 가족이 후보로 표시되어 다시 묶을 수 있다.

명시적인 공유 적용은 미리보기에 표시된 연결을 바꾼다. 일반 파일 연결·누락 경로 보완에서는 다른 번호가 별도로 지정한 경로나 빈 값으로 해제한 항목을 덮어쓰지 않는다. 일반 연결은 공유 그룹의 일치하는 슬롯과 아직 지정되지 않은 슬롯에 반영된다. 공유 편집은 어느 번호에서 해도 같은 그룹 기준을 사용한다.

편집 중인 능력치·외형·대사·QSP 초안이 있으면 공유 적용 전에 먼저 저장하거나 되돌려야 한다. 도구가 초안을 자동 저장하거나 폐기하지 않는다. 기존 브라우저 탭은 자동 새로고침하지 않았다. 저장한 뒤 새로고침해야 새 UI를 받는다.

## 파일과 의존성

- `tools/text-workshop/appearance-sharing.cjs`: 공통 JSON/PNG 조회, 공유 계획·적용·누락 보완. `create(game)`의 `resolve`, `describe`, `targets`, `preview`, `apply`, `materialize` 사용. 입력은 캐릭터 ID 또는 번호 없는 `json:파일명`, 선택 peerIds와 버전 토큰이다.
- `tools/modding-hub/appearance-sharing.cjs`: 같은 코어의 동일 바이트 배치본. `appearance_sharing.py`가 Node 하위 프로세스로 호출한다. 통합 서버의 기존 이미지 조회 함수를 실행 중에 이 공통 조회로 연결한다.
- `character-image-links.cjs`와 통합 서버가 동일한 판정을 사용한다. `/api/catalog/character-images/sharing`, `/api/char/<번호>/sharing`의 read/preview/apply가 두 UI를 연결한다.
- 정책은 WORK `modtools/character-image-sharing.json`에 저장한다. `groups`는 현재 그룹, `families`는 분리 후 다시 선택할 수 있는 후보다. 단독 그룹도 의도된 분리 상태이므로 지우면 자동 공유 판정으로 돌아갈 수 있다.
- 원래 같은 기본 PNG를 쓰는 그룹과 기존 펠라게야 그룹은 별도 정책 없이 인식한다. 임의로 전체 캐릭터 JSON을 다시 쓰지 않는다.
- `modtools/character-image-sharing-history/`에는 적용 전 JSON·정책 및 변경 기록이 남는다. 현재 파일이 외부에서 바뀌었으면 덮어쓰지 않고 충돌을 알린다.

미리보기는 읽기만 한다. 적용에는 JSON·정책·계획 해시가 필요하며, 미리보기 뒤 원본이 바뀌면 재검토한다. JSON·정책은 임시 파일 저장 후 교체하고, 새 PNG는 기존 파일을 덮어쓰지 않는 방식으로 설치한다. 오류 시 이번 작업이 쓴 파일만 확인해서 복구하며 다른 편집이 끼었으면 충돌로 남긴다.

도구 설정과 게임 JSON 경로를 사용한다. 게임 세이브 변수는 추가하지 않는다. 공유 모듈을 제거하면 새 공유 API와 통합 서버가 작동하지 않으므로 코어·브리지·서버·UI를 함께 되돌려야 한다. 이미 보완된 JSON 경로와 분리 PNG는 일반 게임 리소스로 계속 유효하다.

## 검증 범위

공통 코어·체크리스트 연결·기존 파일 연결·펠라게야 공유·UI 상태 검사를 격리 자료로 수행했다. 실제 브라우저에서는 두 화면의 2608 복장 경로와 2580 공유 체크 상태, 분리 미리보기의 PNG 8개를 확인했다. 실제 마르셀리나 그룹의 공유 해제를 시험 목적으로 적용하지 않았다. 상세 결과와 바이트 해시는 INSTALL.json, MATERIALIZE.json 및 검증 기록에 남긴다.

게임에서는 재시작 후 2608의 타이틀·하녀·비서·도미나를 확인할 수 있다. 실행 중인 게임이 이전 JSON 등록을 기억할 수 있다. 실제 게임의 모든 복장 전환과 기존 세이브의 외형 갱신은 이번 도구 화면 검사로 대신하지 않는다. Full·배포 ZIP은 수정하지 않았고 커밋·푸시는 하지 않았다.
