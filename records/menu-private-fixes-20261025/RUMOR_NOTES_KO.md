# 구매자 소문 메뉴 연결 결함

현재 WORK `38aaaaa5…`에서 확인했다. 화면·엔진을 실행하지 않고 원래 메뉴 조립기와 호출 코드를 추적했다.

`$menu`의 `exec_options`는 작은따옴표 HTML 속성 `href='EXEC:…'`를 만든다. 소문 서비스가 넘기는 QSP 명령은 `gt 'jo9_buyer_rumors', 'consult', 'skups', 토큰`처럼 작은따옴표를 포함하므로 브라우저가 `href`를 `EXEC:gt `에서 닫는다. 표시 금액과 글자는 정상이어도 원래 링크를 클릭하면 정상 명령이 전달되지 않는 구조다. 이전 금액 표시 검사만으로 이 결함을 잡을 수 없었던 이유다.

최소 수정은 소문 전용 consult·이전·다음·복귀 4개 호출을 기존 `exec` 조립기로 바꾸는 것이다. 이 조립기는 큰따옴표 HTML 속성을 사용하므로 기존 QSP 명령을 그대로 보존할 수 있다. 공통 `$menu` 자체는 바꾸지 않는다.

스컵스·버진스힙·카페의 세 메뉴 템플릿에서는 기존 소문 블록을 종료 선택지 바로 위로 옮긴다. `#options`와 `$ongload`가 이미 `refreshmenus`를 호출하므로 새 영구 캐시 키가 필요하지 않다.

새 로케이션·영구 상태를 추가하지 않는다. 요금 $10/$5, 기존 할인 조건, 지역별 고정 구매처만 평가하는 범위, 특수 의뢰 제외, 1회 토큰 소비와 중복 청구 방지를 유지한다. 원래 흐름은 소문 선택지를 누르면 전체 보유자의 소문을 만들고 결과 페이지를 넘기는 구조다. 새 인물 선택 단계를 추가하지 않는다.

`rumor-edits.cjs`는 읽은 QSP 문서에서 적용할 편집 조각만 돌려준다. 파일을 쓰거나 게임·세이브를 실행하지 않는다. 네이티브 회귀는 실제 메뉴 앵커 클릭에서 시작하고 결과·페이지 넘김·복귀·옛 링크 재클릭을 검사해야 한다. 돈 부족의 원래 모달 메시지는 진단에서 완료 메시지로 잠시 포착하므로 별도 한계로 기록한다.
