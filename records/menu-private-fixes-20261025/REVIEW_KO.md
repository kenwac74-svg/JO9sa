# 독립 검토: 소문·보관함·보고 링크·공유 고갈·개인실 이동

검토한 수정은 필요한 연결과 표시 간격·고갈 검사에 한정되어 있다. 새 location은 없고 원래 273개를 유지한다. 새 영구 저장 키도 없다. `jo9_household_worker`에 두 조기 모드를 추가해 기존 공유 카운터와 상태를 사용한다. `review-scope.cjs`는 후보 해시, 변경 location, 기존 지급식, 보고의 선행 플래그 해제, 결과 계산 입구 검사, 개인실 whitelist 1행만 바뀐 점을 별도로 검사한다. 결과와 helper 해시는 `INDEPENDENT_REVIEW.json`에 남긴다. 이는 최종 후보의 실제 엔진 실행 통과를 대신하지 않는다.

## 세 가지 기존 수리

- 소문: 메뉴의 소문 항목을 종료 항목 바로 앞으로 이동하고, 소문 동작 네 종류의 `$menu` 호출을 `exec_options`에서 `exec`로 바꾼다. 기존 provider·가격·할인·비용 차감·추천 판정·일회용 접수 값은 변경하지 않는다. 메뉴 원래 항목과 대사도 유지한다. 제거하면 기존 링크 인자 해석 문제와 종료 항목 아래의 소문 배치가 돌아온다.
- 보관함: `master_stat`의 연구실 있음/없음 분기에서 망각의 정수 뒤 `<br><br>`를 `<br>`로 바꾼다. 빈 행 하나만 사라지며 글자·폰트·수량·목록 순서는 같다. 제거하면 마지막 항목이 다시 아래로 밀릴 수 있다. 원래 CSS `#middle_text`의 font26·line-height110%는 변경하지 않는다.
- 우유량 보고: 활동 노예, 개인실1~4, 방 인물 임시 화면의 활성 보고 요소 6곳을 `DIV`에서 `A`로 바꾼다. 원래 `#var_base` 재계산과 수량 메시지 명령·스타일·툴팁·이미지·조건은 같다. 비활성 표시는 건드리지 않는다. 제거하면 `href`가 있는 DIV가 다시 실행 가능한 링크가 되지 못한다. 배우의 소유·역할 배열·보유량·행동력 보존은 실제 보고 클릭 전후 검사로 확인해야 한다.

## 공유 고갈 검사와 소모

ready는 `pet_tentacle>0`, `tentacle_state!=2`, `spawn_milked<=tentacle_size` 세 조건이다. `<=`는 원래의 `>` 고갈 경계를 보존한다. 사용량이 크기를 넘어도 기본 지급 배열의 0번 값이 양수로 남는 원본 조건을, 새 보상식으로 고치지 않고 작업 가능 검사로 막는다.

spent는 `max(기존 숙련 소모량, gain>0이면1 아니면0)`을 기존 사용량에 더하고, 크기를 넘으면 기존 상태를 2로 만든다. 숙련0·gain0은 소모0, 숙련0·양수gain은 소모1, 양수 숙련의 기존 소모량은 유지된다. 수동 세 경로는 새 지역 변수 `jo9_tentacle_before`로 가산 직전·직후 차이를 전달한다. 자동 보고 여섯 경로는 기존 성공 분기에서 캡처한 gain을 전달한다. 실패 분기는 바꾸지 않는다. 양수 gain은 즉시 가산/보고 값이며, 이후 `$newloc`의 기존 저장 상한까지 차감한 순보유량이라는 뜻은 아니다.

메뉴 네 곳, 새 작업 설정 네 곳, 효과 계산 location의 최초 입구에서 검사한다. 같은 이미지 경로를 쓰는 별도 교육 분기나 기존 지급식·배수·행동력 공식·다음 날 회복 주기는 바꾸지 않는다. 고갈 상태2가 언제 회복되는지도 원래 `next_day` 조건 그대로다. 새 before 변수는 지역 변수이고 새 영구 키·인물 필드·location은 만들지 않는다.

원래 WORK 복호화 본문 기준 `interaction_result` 665행(make 계열), 877행(self 계열)에서 `$special_part`를 실제로 실행한다. 따라서 초기 설정 입구만 막으면 직접 캐시된 `gt interaction_result`로 계산에 재진입하는 경우를 막지 못한다. 독립 검토에서 이 점을 지적했고, 최종 helper는 대상 4개 ID만 `interaction_result` 최초 입구에서 ready를 확인하도록 보완했다. `menu_Milk_A/S>0` 검사도 있어 초기값0을 다른 interaction0과 혼동하지 않는다. guard는 원래 actor·AP·counter 처리를 시작하기 전이다.

### 메시지 닫기 층 가설 기각: 진단 상태 재초기화 오류

이후 수량 메시지80을 여는 진단에서 닫기 검사 실패 문구가 `(1243,699,29,29)`와 `DIV#asinfo_block`을 보고했다. 앞선 진단 구문 오류와 구분하되, 이 좌표가 실제 닫기 이미지인지 확인하기 전 제품 결함으로 단정하지 않는다. 기존 CSS의 조수 정보 열은 x1243·y583·높이155여서 실패 문구의 좌표와 일치한다.

프로필의 `jo9_traits_view.css` 26행에 있는 `#__message__{z-index:2147483647!important}`를 공통 CSS 끝에 추가하는 최소 가설을 격리 복사본에서만 검사했다. 프로필 레이아웃 전체 로드나 UI 위치·크기·클릭 방식·게임 상태 변경은 하지 않았다.

`modal-layer-css.cjs`는 순수 빌더이고 준비 실행은 원래 CSS를 작업 백업에 보존한 뒤 `base.candidate.css`와 `modal-layer-css.json`만 만든다. 원본 해시 `eebc8375…`, 후보 `7f94ad5f…`; 원래 파일의 모든 바이트가 prefix로 남아 있고 추가량은146바이트다. 새 runtime 파일·새 dependency·영구 키는0개이며 이 후보는 기존 `css/base.css` 한 파일에만 추가하는 가설이다. 실제 원인이 입증되지 않아 제거 여부의 제품 효과도 단정하지 않는다.
