# 판타지 안개괴물 공유 고갈 검사

`buildTentacleEdits(doc)`는 기존 QSP 문서에서 편집 조각만 반환한다. WORK·후보·세이브를 직접 쓰거나 분기를 실행하지 않는다.

## 입력·반환과 호출

기존 `jo9_household_worker`에 두 조기 모드만 넣는다. 새 로케이션과 영구 키는 없다.

- `func('jo9_household_worker','tentacle_ready')`: 장치 >0, 상태 !=2, 공유 사용량 <= 크기를 모두 만족하면 1, 아니면 0. 게임 상태를 변경하지 않는다.
- `gs 'jo9_household_worker','tentacle_spent',기존숙련소모량,실제보상증가량`: 기존 숙련 소모량을 유지하며, 실제 양수 보상이 있을 때만 최소 소모량을 1로 한다. 사용량이 크기를 넘으면 기존 상태 키를 2로 만든다.

조수·노예의 전용 작업 메뉴, 두 교육 메뉴의 판타지 항목, 실제 신규 작업 설정 1354/7022 및 menu_Milk_A/S에서 같은 ready 검사를 이용한다. 이미 고갈된 옛 메뉴 링크를 눌러도 결과 계산·행동력 차감 전에 기존 디스패치가 정한 menu_form 화면으로 돌아간다. 네이티브 검사에서는 기존 디스패치가 menu_form을 0으로 정리하는 동작을 확인했다.

신규 작업을 설정하는 네 분기와 효과 계산용 `interaction_result`의 최초 입구에서 재검사한다. 후자는 저장된 옛 결과 계산 명령을 직접 재호출해 `$special_part`를 반복 실행하는 우회를 막는다. 계산 시작 때 한 번만 검사하며, 실행 중 정상 성공으로 공유 사용량이 초과되어도 이미 만들어진 결과·다음·복귀 페이지는 `interaction_screen`에서 계속 진행한다. 표시용 `interaction_screen`은 수정하지 않는다.

## 실제 보상과 소모량

판타지 수동 `$special_part` 3개에 `local jo9_tentacle_before`로 직전 자원 수치를 보관한다. 기존 지급식과 기존 보너스를 그대로 실행한 뒤 실제 증가량을 shared consume에 전달한다. 이 지역 변수는 호출 종료 때 사라진다.

따라서 숙련 0이고 실제 보상을 받은 경우에만 공유 사용량 1을 쓴다. 보상을 얻지 못한 숙련 0 훈련에 새 소모를 추가하지 않는다. 숙련이 양수인 훈련의 원래 사용량은 그대로다. 자동 업무 보고 6곳도 기존 성공 분기 안의 기존 소모 지점을 같은 consume로 바꾼다. 실패 분기는 수정하지 않는다.

자동 업무 담당자 선택은 기존의 더 엄격한 상태 검사도 유지한 채 shared ready 조건을 추가한다. 기존 주택 보관 상한, 하루 회복 주기, 다음 날 계산, 지급식·배수·성공 조건·행동력 규칙은 바꾸지 않는다.

## 의존성과 분리 영향

메뉴와 수동·자동 소모 호출은 `jo9_household_worker`의 두 모드에 의존하므로 해당 모드만 제거하면 버튼이 비활성화되거나 소모 처리가 생략될 수 있다. 제거 시 호출부도 함께 이전해야 한다. 기본 담당자 선택 모드와 기존 역할 우선순위는 유지한다.

실제 동물 항목·분기는 수정하거나 실행하지 않는다. 교육 메뉴 전체 접근 문제는 별도 작업이며, 이 helper는 그 접근 조건을 변경하지 않는다.

## 네이티브 검증 결과

`quota-native-report.json`의 최종 네이티브 11건은 전부 PASS다. 공유 ready 경계(장치 없음·상태2·counter초과·마지막 사용 가능), 수정 전 교육 우회 실제 재현, 네 진입 ID의 고갈 차단, 정상 지급/행동력 이전 대비 동일, 숙련0 양수보상 최소1과 무보상0 유지, 원래 결과·다음·복귀 완료와 소진 후 캐시 결과/설정 재호출 방어를 확인했다. 자동 개인실1은 실제 날짜 진행과 보고·복귀까지 지급201·기간합산201이 한 번씩만 반영됐다. 기존 노예→조수→개인실 선택 우선순위도 실제 엔진 숫자 검사를 통과했다.

자동 성공 보고 6곳의 치환과 실패 분기 불변은 정적 검사이며, 실제 자동 흐름은 개인실1 대표 경로다. 원래 FastQSP의 DOM 링크에 합성 클릭 이벤트를 보냈고 물리 마우스 검증은 아니다. 새 로케이션/영구키는 없고 WORK·원본·기존 세이브는 쓰지 않았다. 재현 스크립트 `native-quota.cjs`는 현재 WORK를 baseline으로 읽지 않고 해시38aaaa의 백업 경로를 기본값으로 고정한다.
