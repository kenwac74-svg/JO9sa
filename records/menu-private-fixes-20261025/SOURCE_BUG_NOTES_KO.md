원본 지급은 `semen_gain[max(0, tentacle_size - spawn_milked)]`다. 원본과 WORK의 기준 배열은 `[12,18,24,64,126]`이다. 따라서 공유 사용량이 크기를 넘어도 배열 인덱스는 0에서 멈추고 기준 획득량 12가 남는다. 버튼은 꺼지지만 교육 경로는 계속 열리는 것이 핵심 결함이다.

예를 들어 크기 4·숙련 5라면 정상 지급 뒤 사용량이 5가 되어 고갈 상태가 된다. 기존 교육 경로는 그 상태를 검사하지 않으므로 이후에도 기준 인덱스 0의 양수 획득 경로가 남는다. 이는 고갈 제한 우회가 가능한 코드 근거다. 주택 상한과 일반 행동·거절 조건까지 없어지는 것은 아니므로 문자 그대로 무제한 저장·무소모 행동이라고 표현하면 안 된다.

최근 WORK는 원래 성공 조건에 최상 특성 조건을 추가하고 크기별 보너스 배수를 적용했다. 고갈 검사 누락과 양수인 최소 배열값은 그보다 앞선 원본에서 확인된다. 보너스 지급식 자체를 이번 수정에서 줄이거나 바꾸지 않는다.

## 유지하는 회복 규칙

다음 날 `counter>=size`이면 `max(1,size-1)`로 보정한 뒤, 양수이면 다시 1을 뺀다. `counter>size`일 때 상태 2, `counter=0`일 때 상태 1로 만든다. 장치가 없으면 상태 0이다. 중간 사용량에서 무조건 상태 1로 바꾸는 새 규칙은 넣지 않는다. 고갈 상태가 이미 2라면 원래 회복 조건에 의해 상태가 풀릴 때까지 ready는 0이다.

## 승인된 공유 판정과 소모 예외

ready는 **장치 >0 · 상태 !=2 · 공유 사용량 <= 크기**를 모두 만족해야 한다. 마지막 동등 경계 `counter=size`는 원래 `>` 고갈 규칙과 같게 유지한다. 이를 `<`로 줄여 횟수 밸런스를 바꾸지 않는다.

기존 `jo9_household_worker`에 ready/spent 조기 모드를 추가한다. 새 로케이션과 영구 키는 없다. 메뉴와 새 작업 설정 4경로, 효과 계산용 `interaction_result` 최초 입구에서 ready를 확인한다. 계산 결과를 표시하는 `interaction_screen`에는 검사를 넣지 않아서 정상 성공 직후 고갈 상태가 되어도 기존 보고·다음·복귀 과정을 끝낼 수 있다. 옛 결과 계산 명령을 직접 재호출하는 우회는 `interaction_result` 입구가 막는다.

소모량은 `max(기존 숙련 소모량, 실제 양수 보상이 있으면 1 아니면 0)`이다. 최상 특성으로 숙련 0에서도 보상이 생긴 상황에 기존 `counter+=0`을 그대로 두면 같은 상태가 끝없이 유지되므로, 그 경우에만 최소 1을 소비한다. 수동 작업은 지역 변수로 지급 전후 실제 자원 차이를 비교한다. 숙련 0이고 보상을 못 얻은 훈련에 새 소모를 붙이지 않는다. 양수 숙련의 기존 소모량도 보존한다.

자동 업무 보고 6경로는 원래 성공 분기 내 소모 지점에서 동일 spent를 호출한다. 실패 분기는 수정하지 않는다. 원래 지급식·특성 보너스·회복 주기·행동력·주택 상한·인물 속성을 변경하지 않는다. 실제 동물 분기는 수정·활성화·실행하지 않는다.

## 검증 상태와 한계

`tentacle-static.json`은 helper만 메모리에 적용한 구조·바이트 왕복·변경 범위 검사다. 기존 지급식과 `next_day`, `$newloc`, `interaction_screen` 본문 불변을 확인했고, 이미지 경로를 공유하는 별도 교육 템플릿도 바이트 동일함을 확인했다. `interaction_result`는 위 최초 입구 검사만 추가한다. 상태는 `STATIC_PASS`이며 실제 플레이 완료를 의미하지 않는다.
