# 임신 상태 아이콘 후보 독립 확인

수정 필요 사항을 발견하지 못했다. 첨부 `Temp/z_pregnant.png`와 기존 `content/pic/ui/z_pregnant.png`의 SHA-256은 모두 `9544a8bdc718d90bd9e9b12e768bd2a17a2e7be791487c189b42edb34dacfc24`다. 새 이미지를 추가할 필요가 없다.

원본과 후보의 실제 CSS, 실제 상태·임신 HTML 리터럴을 headless Edge로 렌더링했다. 표시 경로 4개를 각각 확인했으며 원본은 경로·정렬·크기 검사에서 실패하고 후보는 4×8=32개 검사를 모두 통과했다. 결과는 `before-fixture-result.json`, `candidate-fixture-result.json`에 있다.

| 요소 | 실제 후보 범위 |
|---|---|
| 메인 상태 5행 | x1243, y333/362/391/420/449, 각 29×29 |
| 메인 임신 | x1243, y478–507, 29×29 상자 |
| 조수 상태 5행 | x1243, y583/612/641/670/699, 각 29×29 |
| 조수 임신 | x1243, y728–757, 29×29 상자 |
| 하단 괴물 | x1241.5, y757–789, 기존 32×32 유지 |

임신 그림 자체는 약 27.08×29로 원래 1212:1298 비율을 유지한다. 조수 임신 하단과 괴물 상단은 757px에서 맞닿으며 겹치지 않고, 괴물 하단은 사용 가능 하단 793px 안쪽에 4px 여유를 남긴다. 기존 의료 표시와 임신 아이콘의 교차도 없으며 `#active_spell`의 2.5px 간격은 그대로다.

QSP는 `sjm_UI_UIadds.body`만 달라진다. 네 이미지 경로와 새 MOD 주석을 복원하면 원문과 완전히 같다. 조건·레이블·진료 링크·기능 상태는 유지된다. CSS는 기존 바이트 뒤에 새 규칙만 추가하며 두 상태열의 직접 자식 행만 압축한다. 새 클래스·함수·저장 상태는 없다. 공식 정적 구조 검사도 통과했다.

이 fixture는 실제 QSP 조건문을 실행하는 검사가 아니며, 기존 네 표시 분기를 별도로 렌더링했다. 실제 임신 표시 조건과 진료 대상 검사는 root의 별도 native 검사 결과와 함께 판단해야 한다. 게임·CSS·이미지는 읽기만 했다.
