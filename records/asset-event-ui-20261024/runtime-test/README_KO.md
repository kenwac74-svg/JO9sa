# 자산 처분 실제 GUI 검증

WORK 동일 QSP에서 7~10번 시험 세이브 복사본을 실제 클라이언트로 불러오고 클릭했다. 15개 페이지 표시, 장식460 환급과 기본 배경, 빈 시설과 방 철거, 주택7500 환급 및 빈민가 이전, 인물202/204 급매, 미납 중 날짜 차단, 실제 저장·불러오기 왕복을 확인했다. 8번은 100 청구를 1회 차감하여360 유지, 9번 개인실/냉동 인물 보호, 10번 NPC 의뢰·평판 보존을 확인했다.

원본7의 자산을 모두 처분하면 빈 화면이 재현되었다. 시험 세이브 생성기 primeState가 여러 줄 종료 매크로 DEATH[0]를 생략하고 EGEYA 이름 인덱스를0에 배치한 것이 원인이다. 정상 auto_day_end 세이브에는 매크로0/이름1이 있다. WORK 코드를 바꾸지 않고 실패 상태의 진단 세이브에서 DEATH 한 변수만 복원하자 실제 GAME OVER 그림과 채무 매각 문구, day0이 확인되었다. 원래 실패도 증거에 유지했다.

교정ZIP에는 7~10 시험 세이브만 있다. 기존 이름/진행 상태/금액/인물/헤더/CRC는 유지하고 DEATH 배열 한 곳의 함수와 인덱스만 복원했다. 원본 WORK 세이브는 덮어쓰지 않았다. 원본79파일 해시 보존. 테스트 생성기 자체의 범용 수정은 이번 검사에 포함하지 않았다.

화면은 evidence/의 실제 Qt 게임 캡처다. 재현 함수와 결과 세이브는 scripts/와 압축 증거로 보관한다. 전체 게임의 모든 문법·분기를 증명하는 검사는 아니다. 커밋·푸시·배포 반영 없음.
