# 구버전 세이브의 전투 BGM 미출력 제보 확인 — 2026-11-03

## 결론

현재 설치본에서 전투 음원 누락이나 이번 UI 패치의 음악 코드 변경은 발견되지 않았다. **구버전 세이브에만 발생하는 호환 버그라고 확정할 증거는 아직 없다.** 제보 당시 세이브·구버전 번호·오디오 설정이 제공되지 않아 실제 제보 상황은 재현하지 못했다.

## 확인된 사실

- 대상: `C:\MOVE\Jack O Nine Tails v2.4.1_Kor_Full\game\jack.qsp`, SHA-256 `38ec5afcc0c26650491551cf56e93f1fc4cb11f8f93c8c1acf605e79a0935a9c`.
- 일반 전투 진입 `начать_бой:29`가 `$toplay='fight'`를 지정한다. 전투 화면 `боевой_интерфейс:252`가 `$play_music`를 실행한다.
- `#static_base:11–13`의 세 전투 음원 `fight_arena.wav`, `fight_girl.wav`, `fight_master.wav`가 모두 실제 경로에 있다. 셋 모두 RIFF/WAVE PCM 스테레오44.1kHz·16bit이며 파일 길이도 일치한다.
- 현재 `$play_music` 본문과 전투 음원 경로는 2026-10-08 백업 두 개와 같다. 최근 보관함·연금술 UI 수정에서 이 코드는 바뀌지 않았다.
- 음악은 `sound_on=1`, 유효한 `$music[$toplay]`, 양수 `music_volume`이 갖춰져야 들린다. 시작 화면에서는 볼륨100으로 초기화하지만, 세이브 로드 처리에는 음악 볼륨을 무조건100으로 되돌리는 코드가 없다. 저장된 음소거·볼륨0은 가능한 원인이며 그 자체는 설정 유지 동작이다.
- 소스 `#dynamic:1488–1491`에는 빠른 음악 전환·음소거 반복 시 엔진이 무음 또는 이전 음악 유지 상태에 빠질 수 있다는 기존 주석이 있다. 구버전 세이브 전용으로 기록된 문제는 아니다.
- 현재 로컬 `FastQSP.ini`의 플레이어 음소거는 `false`. 제보자 PC의 설정은 확인하지 못했다.

## 격리 진단

현재 음악 재생 함수에서 마지막 미디어 재생 명령만 기록으로 대체한 진단을 실제 엔진에서 실행했다. **13개 조건 통과**: 정상 전투 경로 선택, 같은 곡 재진입 시 재생 명령 재호출, 볼륨0 상태의 무음 재생 요청, 사운드 끔 상태의 미호출, 음악 매핑이 비어 있을 때 미호출을 확인했다.

이것은 재생 분기 검증이다. **실제 소리가 들리는지 확인한 시험도, 제보자의 구버전 세이브 재현 시험도 아니다.** 개인 세이브와 게임 파일은 변경하지 않았다.

## 제보 확인에 필요한 비교

1. 문제 세이브를 불러와 게임의 사운드를 켜고 배경음악 볼륨을100%로 설정한다. 플레이어 자체 음소거도 확인한다.
2. 같은 전투를 새 게임/최근 세이브에서도 비교한다. 효과음·도시 음악까지 안 나오는지, 전투 음악만 안 나오는지 구분한다.
3. 문제가 지속되면 해당 세이브와 원래 사용 버전으로 음악 변수·저장된 함수·화면 복귀 상태를 확인한다. 현재 근거로 모든 구버전 세이브가 잘못됐다고 안내할 수는 없다.

## 별도 발견

현재 목록에 지정된 **도시 BGM `content/snd/city.wav`가 없다.** 이는 전투 세 곡의 누락과 다른 건이며 이번 조사에서는 수정하지 않았다. 전투 화면의 사운드 버튼에는 `gt curloc`($ 없는 변수명)이 있어 별도 버튼 동작 점검 대상으로 남긴다. 이 역시 제보의 원인으로 확정하지 않았다.
