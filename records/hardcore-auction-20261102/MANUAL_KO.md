# 공개경매 난이도별 정산

2026-11-02 사용자 지시. 이번 변경은 공개경매의 낙찰가와 실제 지급액을 구분한다.

| 게임 설정 | 최종 낙찰가 | 지급액 | 세금 문구 |
|---|---:|---:|---|
| 쉬움 / 클래식·보통 | 제한하지 않음 | 낙찰가 전액 | 없음 |
| 어려움·하드코어 | 제한하지 않음 | 낙찰가와 $6,000 중 작은 금액 | 낙찰가가 $6,000을 초과할 때만 |

세금 문구: “악질적인 세금징수원이 낙찰가에서 이런저런 핑계로 스파크를 뜯어 가고, 내 손에는 $6,000만 쥐어졌다.”

## 입력·출력·호출

- `$guild_auction`은 기존 평가·입찰·희귀 특성 계산으로 `bank_size`와 `$auction_flow`를 만든다. 생성 단계에서 $6,000으로 잘라 내지 않고 총 낙찰액을 `sparks_get`으로 넘긴다.
- `interaction_city = 931`은 게임 설정 `difficulty_setting`과 미지급 `sparks_get`을 읽는다. 설정 2이며 $6,000을 초과할 때만 기존 경매 마지막 `$text`에 문구를 붙이고 `sparks_get`을 6000으로 만든 다음 `sparks`에 더한다.
- `$text` 배열 길이를 늘리지 않는다. 기존 낙찰 페이지의 사운드, 이후 NPC 제안과 선택지 인덱스는 그대로다.
- `interaction_screen_city`의 옛 “공개경매 최대 $6,000” 출력은 제거한다. 정산이 끝난 결과를 다시 표시할 때 추가 정산하지 않는다.
- 설정 메뉴의 0=보통 / 1=쉬움 / 2=하드코어를 사용한다. 주인공 생성 시의 `game_difficulty`와 별개다.

## 저장·범위·제거 시 영향

새 저장 변수나 로케이션을 추가하지 않는다. 기존 저장의 아직 정산하지 않은 경매는 정산 시의 설정을 따른다. 과거에 이미 지급된 금액은 소급 환급하거나 다시 공제하지 않는다. 현재 남아 있는 옛 성별 정산 코드도 동일한 규칙으로 보존하지만 삭제된 여주인 콘텐츠의 접근을 복구하거나 번역하지 않는다.

일반 상인 매입 상한, 개인 고객 상한, 고정 의뢰 보수, 파산 정산은 수정하지 않는다. 앞서 확인한 크레딧의 단독 LF 한 곳만 CRLF로 교정하여 문법 검증의 형식 조건을 맞춘다. 문장 자체는 동일하다.

이번 패치를 제거하면 이전의 난이도 공통 $6,000 상한과 안내가 복원된다. 정산 변경·낙찰 총액 변경·화면 안내 변경은 함께 되돌려야 한다. 문자열만 교체하거나 지급 줄만 되돌리면 금액 표시와 지급액이 다시 달라질 수 있다.

## 검증·수동 확인

정확한 검사 결과와 대상 SHA는 `FINAL_RESULT.json`과 `release-report.json`을 따른다. 자동 검증은 격리된 실제 FastQSP 엔진에서 실행하며 원본·개인 세이브·사용자 실행 창을 수정하지 않는다. GUI로 개인 저장 파일을 직접 불러온 플레이 검증은 별도다.

수동 확인은 현재 주인공으로 낙찰가가 $6,000을 넘는 인물을 공개경매에 출품하면 된다. 쉬움·보통에서는 낙찰가만큼 잔액이 늘고 세금 문구가 없어야 한다. 하드코어에서는 잔액이 $6,000 늘며 마지막 낙찰 메시지에 위 문구가 한 번 표시되어야 한다. $6,000 이하이면 어느 설정에서도 세금 문구가 없어야 한다. 결과를 다시 표시하거나 다음 페이지로 넘겨도 잔액이 다시 늘지 않아야 한다.

배포 최종점검은 현재 보류 중이다. 이번 결과의 배포 동기화 여부는 `FINAL_RESULT.json`의 `fullWritten`을 따른다. ZIP·커밋·푸시는 이 작업에 포함하지 않는다.
