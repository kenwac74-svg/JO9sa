# 하드코어 경매 정산 변경 계획

사용자 확정: 2026-11-02. 쉬움·보통은 공개경매 지급 상한을 없애고 하드코어만 $6,000을 적용한다. 기존 경매 대사를 일괄 개작하지 않고 초과분 공제 사유만 추가한다. 여주인 콘텐츠는 삭제된 콘텐츠이므로 번역·복구 대상으로 다루지 않는다.

## 범위와 구현

- 게임 설정 `difficulty_setting`: 1=쉬움, 0=클래식/보통, 2=어려움/하드코어. 캐릭터 생성 `game_difficulty`와 혼동하지 않는다.
- `$guild_auction`: 낙찰 총액을 $6,000으로 잘라 내던 줄을 제거한다. 특성 프리미엄 계산과 기존 경매 문구는 보존한다.
- `interaction_city`의 931 정산: 하드코어이면서 미지급 낙찰액이 $6,000 초과일 때 기존 경매 마지막 페이지에 세금징수원 문구를 붙이고 지급액을 $6,000으로 제한한다. 다른 경우 전액을 지급한다.
- 문구: `악질적인 세금징수원이 낙찰가에서 이런저런 핑계로 스파크를 뜯어 가고, 내 손에는 $6,000만 쥐어졌다.`
- `interaction_screen_city`: 쉬움·보통에서 거짓으로 표시될 수 있는 옛 공개경매 최대 $6,000 안내를 제거한다.
- 현재 파일에 남아 있는 동일 정산의 성별 분기는 동일한 규칙을 사용하되 여주인 접근 경로를 추가·복구하지 않는다. 실제 기능 검증의 주 대상은 현행 주인공이다.
- 상인 매입·개인 고객·고정 의뢰 보상·파산 정산은 변경하지 않는다. 신규 저장 변수나 신규 QSP 로케이션을 추가하지 않는다.
- 알려진 기존 `credits`의 단독 LF 한 곳은 앞서 승인된 최종검증의 형식 교정만 함께 사용한다. 크레딧 원문을 바꾸지 않는다.

## 실행과 검증

1. 최신 WORK를 다시 읽고 SHA·바이트 왕복·로케이션 순서를 기록한다. 패치와 진단 후보는 게임 밖에 만든다.
2. 현행 코드가 쉬움·보통 6,001/12,000 전액 지급 요구를 실패하는지 확인한다.
3. 최소 선언형 패치를 작성하고 후보에서 정확 재생·멱등성·범위 보존을 검사한다.
4. 실제 FastQSP로 설정 0/1/2 × 금액 5,999/6,000/6,001/12,000을 검사한다. 낙찰 총액, 실제 잔액 증가, 세금 문구 수와 위치, 배열 길이·사운드·후속 제안 인덱스를 확인한다.
5. 실제 화면 로케이션을 유지한 결과 재표시에서 재지급·문구 중복이 없는지 확인한다. 경매 프리미엄 총액 보존도 검사한다.
6. 공식 출고 검사로 구조·줄바꿈·패치 적용기 재생·멱등성·실제 엔진 대표 경로를 검사한다. 개인 세이브/사용자 실행 프로세스는 보존한다.
7. 후보 검증이 통과하면 WORK SHA가 시작값과 같은지 다시 검사한 뒤 WORK와 추적 패치·기록에 반영한다. 배포본은 보류 중인 최종 동기화 단계에서 처리한다.
8. 재생성 가능한 진단 QSP·JSON 사본은 정리하고 최소 보고서·재현 스크립트·압축 복구본만 보존한다. ZIP·커밋·푸시는 하지 않는다.

## 한계

구버전에서 이미 지급 완료된 금액은 소급 복원하지 않는다. GUI의 실제 개인 세이브 로드는 자동 엔진 진단과 구분한다. 여주인 잔여 데이터 번역이나 접근 복구는 하지 않는다.
