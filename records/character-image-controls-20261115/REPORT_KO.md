# 캐릭터 이미지 편집 조작 개선 — 2026-11-15

사용자 요청: 얼굴 상자 드래그 확대·축소, 얇은 실선 가이드 추가, 상하좌우 X/Y 이동, 이미지 하단 맞춤·공백 표시.

## 원인과 변경

기존 `studio-look.mjs`는 얼굴 모드의 모든 드래그를 이동으로 처리했다. 휠만 크기를 바꿀 수 있었고 모서리 손잡이는 없었다. pointerup에서 화면 전체를 다시 만들면서 캔버스 포커스가 없어졌으며, 화살표 키 처리는 캔버스 포커스가 있을 때만 작동했다. 키보드 이동 시 저장 버튼의 변경 상태도 바로 갱신되지 않았다.

통합 서버가 `overrides/studio-look.mjs`와 `studio-look-geometry.mjs`를 제공하도록 연결했다. 클로드 원본 파일은 수정하지 않았다. 서버/실행기의 빌드 해시에 두 파일을 포함했다. 원래 캐릭터 API와 저장 payload 형식은 유지한다.

- 얼굴 상자의 네 모서리 손잡이를 드래그해 확대·축소한다. 반대 모서리를 고정하고 기존 151:150 비율을 유지한다. 상자는 캔버스 안으로 제한한다. 내부 드래그는 이동, 휠 크기 변경도 유지한다.
- 화면의 ↑/←/↓/→ 버튼과 키보드 방향키는 1px, Shift를 누르면 10px 이동한다. 얼굴 편집 중이면 얼굴 상자, 그 외에는 이미지를 이동한다. 다시 그린 후에도 캔버스 포커스를 유지한다. 숫자 입력란의 방향키 동작은 가로채지 않는다.
- 가로선·세로선을 추가하고, 선 드래그 또는 X/Y 숫자로 위치를 조절한다. 개별 삭제·전체 지우기를 지원한다. 기존 정수리/중앙 기준선도 얇은 실선으로 표시한다.
- 투명 여백을 제외한 이미지 하단을 계산해 캔버스 아래 표시선을 녹색(맞춤, 0.5px 허용), 빨강(공백), 금색(아래로 잘림)으로 표시한다. 공백/잘림 길이도 표시한다. 보이는 부분의 경계는 이미지 로드 시 한 번 계산해 보관한다.
- 가이드·손잡이·색 표시선은 화면 표시 전용이다. 얼굴 미리보기는 기존처럼 가이드 없는 원본 그림만 자르고, 실제 저장에도 가이드 데이터나 선을 추가하지 않는다.

## 확인

- JS/Python/PowerShell 구문 및 HTTP 자산 제공 확인.
- `tests/look-geometry.test.mjs` 3개 통과: 네 모서리 양방향 크기 변경/반대 점·비율, 캔버스 경계·축소 화면 hit 영역, 하단 공백·맞춤·잘림·빈 이미지.
- 별도 브라우저의 저장하지 않는 새 캐릭터 화면에서 단순 도형 PNG로 조작 확인. 모서리 드래그로 너비 120→193, 얼굴 키보드 오른쪽 1px·Shift 아래 10px, 왼쪽 버튼 1px, 가로·세로 가이드 2개 추가 확인. 이미지 위쪽 이동 시 ‘하단 공백 1.0px’ 빨강, 아래쪽 복귀 시 ‘하단 맞춤’ 녹색 확인.
- 시험 변경은 버리고 시험 탭을 닫았다. 실제 캐릭터·이미지·JSON·QSP·세이브를 저장하지 않았다. 기존 사용자 편집 탭은 재로딩하지 않았다.
- 실제 모서리 드래그 확대는 UI에서, 축소와 다른 세 모서리 경계는 단위 검사로 확인했다. 사용자 이미지의 육안 품질은 별개다. 게임 전체 검사나 외부 API 검사는 하지 않았다.

## 사용과 구현

현재 편집 내용을 저장한 뒤 브라우저를 새로고침한다. 전용 앱은 저장 후 닫았다 다시 연다. 캐릭터의 **외형 → 기존 이미지 정렬/이미지 선택 → 얼굴 상자로 만들기**에서 손잡이가 나타난다. 캔버스를 클릭한 뒤 방향키를 사용하거나 화면 좌표 버튼을 누른다. 가이드는 캐릭터를 새로 열면 초기화되며 게임에는 저장하지 않는다.

`createLookEditor`의 입력(캐릭터·toast·call·onSaved)과 반환(reset/html/draw/bind/dirty)은 같다. 새 기하 함수는 canvas 좌표를 받고 얼굴 상자 또는 하단 표시 상태를 반환한다. 이미지/얼굴 변경은 기존 changed 표시에 연결되고 저장 전 미리보기는 무효화한다. 가이드 조작 자체는 이미지 변경으로 기록하지 않는다. 원래 slot/face API·151×150 얼굴 출력은 그대로다.

제거하려면 서버의 두 자산 override 분기와 빌드 목록에서 두 파일을 함께 제외하면 원본 편집 모듈로 돌아간다. 사용자 설정/게임 파일의 별도 복구나 마이그레이션은 없다. 이후 다른 변경을 덮어쓰지 않도록 `change.diff`의 해당 블록만 되돌린다. 커밋·푸시·배포 ZIP 갱신은 하지 않았다.
